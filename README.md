**Fusion360と同等以上にモダンでシンプルなUIに、自分が実際に使う手動操作と強力なAI操作を載せ、
両者が同じ選択集合を交互に触れるようにしたモデリングツール。**
差別化はUIでも機能数でもなく **交互操作**（AIが集合を提案 → 人が過不足を直す → AIが操作を適用）にある。

**状態: v1の完成条件を満たした（2026-08-14）** — 19操作すべてが人間（UI）とAI（MCP）の両側から使える。
このREADMEは**その手動検証をする人のための入口**である。

## 1. 起動（開発サーバー）

前提はどちらも導入済みなので、**通常は起動コマンド1本だけでよい**。作り直しが要るときだけ:

```powershell
cd C:\Users\tm976\mf\duocad\web; npm install; npm run build
```

> **`web/dist` を作り直さないとUIの変更は画面に出ない。** Pythonサーバが配信するのは
> `web/src` ではなく `web/dist`（ビルド成果物）。`web/src` を触ったら `npm run build`。
> 現在の `dist` は `src` より新しい（2026-08-15ビルド）ので、**そのまま起動してよい**。

**起動コマンドは `duocad.mcp_server` の1本しかない。** MCPとWebSocketと静的配信を1プロセスで
兼ねるので、**手だけで触るときも同じもので立てて、AIに何も頼まなければよい**。

> **起動時に決めることは何も無い（2026-08-15）。** 起動オプション `--step` / `--no-step` は廃止し、
> **サーバは常に空の文書で立つ**。読みたいSTEPは画面の「STEP読み込み」かMCPの `import_step_editable` で
> あとから読む —— **読んだ時点でソリッドごとに編集可能なボディができる**ので、起動時に読んだのと
> 同じ状態になる（以前は画面から読むと参照ボディだけが増え、編集するには `make_editable_copy` が
> 1ボディずつ、27部品なら27回要った。この非対称のせいで起動オプションが消せなかった）。

### 1.1 通常 — MCPクライアントに起動させる

一度だけ登録する（Claude Desktop への登録・`.mcp.json` の書式は [MCP.md](MCP.md)）:

```powershell
claude mcp add duocad -- C:\Users\tm976\mf\duocad\.venv\Scripts\python.exe -m duocad.mcp_server
```

以後は**Claude Codeを起動するとプロセスが立つ**ので、自分でサーバのコマンドを打つ必要はない。
人は `http://127.0.0.1:8766/` をブラウザで開いて手で触り、**AIに頼んだときだけAIが同じ文書を触る**。
終了はセッションを閉じるだけ。

### 1.2 Claude Codeを使わないとき — 自分で立てる

```powershell
cd C:\Users\tm976\mf\duocad; .\.venv\Scripts\python.exe -m duocad.mcp_server --open
```

`--open` でブラウザが開く（省略時は開かない）。**ターミナルのstdinが開いている限り生きる**（`Ctrl+C` で終了）。

> **この立て方だと、あとからAIは繋がらない。** MCPのstdioは**クライアントがプロセスを所有する**
> 仕組みなので、Claude Codeは繋ぎに行かず**別プロセスを立てる** → WebSocket(8765)の bind に失敗して
> **そちらが落ちる**（静的配信の方は「MCPだけで続行」の警告を出して続く）。
> AIも使う日は 1.1 で立て、この立て方は使わない。

### 1.3 frontendを直しながら見る（Vite dev server）

```powershell
cd C:\Users\tm976\mf\duocad; .\.venv\Scripts\python.exe -m duocad.mcp_server   # コア側(WS 8765)
cd C:\Users\tm976\mf\duocad\web; npm run dev                                              # 画面(5173)
```

`http://127.0.0.1:5173/` を開く。devサーバは `/duocad-config.json` を返さないので、
画面は既定の `ws://127.0.0.1:8765` へ落ちて繋がる（Pythonサーバは立てておくこと）。
このときだけは `web/dist` の作り直しが要らない（Viteが `web/src` を直に配る）。
型検査は `npm run check`（`tsc --noEmit` ＋ `svelte-check`）。**`.svelte` の中も見る**
（2026-08-15に `svelte-check` を追加するまでは `.ts` だけで、画面側の未使用変数や
サーバ応答の型の食い違いが素通りしていた）。

## 2. UIチートシート（手動検証用）

### 画面の構成

```
┌ ヘッダ: 接続状態 / 部品数 / 操作数 / プレビュー中の表示 ──────────┐
├ パーツ一覧 │ ビューポート(three.js。Svelteは中身を触らない)     ─┤
├ 選択パネル: いま選んでいるもの・提案/確定の別・除去/クリア/確定  ─┤
├ パラメータ一覧 │ 操作履歴(undo/redoの位置)                      ─┤
├ スケッチ: XY/XZ/YZ・選択中の面に貼る・再開・図形と領域の一覧    ─┤
└ コマンド行: コマンドのボタン / 何を待っているかの1行 / 入力欄   ─┘
```

### 操作の型（**全コマンドで同じ**）

**コマンドのボタンを押す → 引数を集める（クリック・数値・選択肢）→ プレビュー → Enterで確定 / Escで中断。**
verbごとに別のダイアログを作っていないので、1つ覚えれば全部同じ。

| キー / 操作 | 意味 |
|---|---|
| クリック | 選択を**置き換え**（1つだけ選んでいるものを再クリックすると外れる） |
| **Shift+クリック** | 選択に**追加**（フィレット・面取りの複数辺はこれ） |
| **Ctrl+クリック** | 選択から**除去** |
| **Enter** | 確定（引数が揃っているとき）。選択中のコマンドのボタンをもう一度押しても同じ |
| **Esc** | 中断（**操作ログ・体積・入力欄が1つも動かずに戻る**のが正しい挙動） |
| **Tab** | 次の数値引数へ |
| **Ctrl+Z / Ctrl+Y（Ctrl+Shift+Z）** | undo / redo（画面右下のボタンと同じ） |
| 「全体」ボタン | 視点を全体に戻す（スケッチに寄ったあとに使う） |

### コマンド一覧（画面のボタン名）

| モード | ボタン |
|---|---|
| 通常 | 押し出す／領域を押し出す／丸める／面取り／矩形反復／円形反復／保存／開く／STEP読み込み／STEP書き出し／STL書き出し／編集用に複製 |
| スケッチ中 | 選ぶ／線分／円／長方形／円弧／（領域を押し出す・反復） |

スケッチは **XY / XZ / YZ ボタン**か「**選択中の面に貼る**」で入り、「**抜ける**」で出る。
「正面から見る」でスケッチ平面へ正対する。

### 覚えておくと迷わない挙動

- **辺は、辺を要求しているコマンドを起動している間だけ画面に出る**（常時出すと面のクリックが辺に取られる）。
  フィレット／面取りを起動してから辺をクリックする。
- **見えていないボディは選べない**（述語による提案も、画面から指せるのは見えているものだけ）。
  奥の面を触りたいときはパーツ一覧で手前を隠す。
- **読み込んだSTEPはそのまま編集できる**（2026-08-15）。ソリッドごとに編集用ボディができ、
  面をクリックして押し出せる（原本の参照ボディは隠したまま文書に残り、パーツ一覧には出ない）。
  「編集用に複製」（`make_editable_copy`）は、選んだ面のボディをもう1つ作るコマンドである
  （参照ボディを起点にすれば「編集可能にする」、編集用ボディを起点にすれば複製。**どちらも同じverb**）。
- **数値は名前つきの値（`d1` `d2` …）として保持される。** パラメータ一覧で打ち直すと形が追随する。
- **保存形式は操作ログのJSON**。したがって「開く」は再生であり、開くたびに再生経路が検査される。
- **形を変える操作(押し出し・丸め・面取り・反復・図形追加・パラメータ変更)の確定後、
  undo/redoの後は選択が常に空になる**（2026-08-20）。添字は形状変更で壊れるので、後継を
  当てにいくのではなく選び直させる。可視性の切替（手前を隠す）では選択は飛ばない。

## 3. 手動検証の道筋

### 3.1 あなたにしか判定できないもの（ここが本題）

機械検査は599件が通っている（実ブラウザは5本中3本。§7の留保3）。**手で見る価値があるのは、機械が代われない2つ**:

1. **速度の体感** — 「面を選ぶ → 距離を打つ → Enter」がFusion360と同等に速いか。
   これは企画の唯一の前提であり、2026-08-12に計測の器を撤去して**体感が正**と決めてある。
   特に**PCケース（27部品・2835面）を読んだ状態**での、ピックの狙いやすさと再描画の反応。
2. **UIの様式** — Fusion360と同等以上にモダンでシンプルか。
   **FreeCADはここで却下された**ので、様式は足切り条件として実在する。

数値・回帰・失敗の返り方は既に機械が見ているので、手で追う必要はない（§3.5）。

### 3.2 手だけで一巡（空の文書から）

ACCEPTANCE.md §1 の19操作を、人間側だけでなぞる順序:

1. `XY` でスケッチへ入る → **長方形**（左下をクリック → 幅60・高さ40 → Enter）
2. 「領域を押し出す」→ 領域をクリック → 距離10 → **結合** → Enter（最初の板が生まれる）
3. 「抜ける」→ 面をクリック →「押し出す」→ 距離2 → **プレビューが出てから** Enter
4. 面に**円**を描いて「領域を押し出す」→ **切り取り** → 穴が開く
5. 「丸める」→ 辺をShift+クリックで複数選ぶ → 半径2 →（**失敗する半径では理由が画面に出て、選択が保持されたまま戻る**）
6. 「面取り」→ 長さ1（円錐面ができる）
7. **矩形反復・円形反復**（反復は1行の操作。個数と間隔を後から変えられる）
8. パラメータ一覧で `d?` を打ち直す → **全部の穴が追随する**
9. 「保存」→ 「開く」で同じ形に戻る／「STEP書き出し」「STL書き出し」（偏差0.05）
10. 各コマンドで **Esc** と **Ctrl+Z** が効くこと

### 3.3 大きいモデルでの体感（起動してからPCケースを読み込む）

「STEP読み込み」に `3d-models\mATX_PC_case_20251122\PC_case_20251122.step`（27部品・2835面）を
打ってから、パーツ一覧の表示切替 → 奥の面をクリック → 押し出し。
参考値（2026-08-14実測）: 初期配信 2,074ms／押し出し1回の往復 **1,250ms**／undo 578ms。

AI側に「`parallel_to Y` の辺を提案して」と頼む → **選択パネルに提案として出る（3Dの色も確定の橙と別の水色）** →

## 5. アーキテクチャ

```
┌── AI（MCPクライアント）──┐        ┌── 人間（アプリ層 / ブラウザ）──┐
│  述語で引数を作る          │        │  ポインティングで引数を作る      │
└───────────┬──────────────┘        └──────────────┬─────────────────┘
            │ stdio(JSON-RPC)                        │ WebSocket
            │                                        │ コマンド↓ ／ イベント↑
            └────────────────┬───────────────────────┘
                             ▼
        ┌──────────── コア（Python・唯一の真実源）────────────┐
        │  文書（ボディ・スケッチ）／ 選択集合 ／ 操作ログ ／ undo │
        │  ── verb層（純関数） f(文書, 選択, 引数) → 新しい文書 ──  │
        │      問い合わせ : build123d ラッパ（差し替え可能）         │
        │      操作      : OCP（OCCT）＋ 由来マップ回収            │
        └────────────────────────────────────────────────────┘
```

### 外してはいけない3つ

1. **AIの経路はアプリ層を通らない。** コアはUIが無くても機能的に完全であること。
   アプリ層にしか無い機能を作った瞬間、AIから使えなくなる。**層分けの唯一かつ最大の存在理由。**
2. **コマンドは下り、イベントは上り。** AIが選択や可視性を変えるとコアがイベントを発火し、
   ブラウザが描き直す。**この上り方向が無いと交互操作が成立しない。**
3. **アプリ層が落ちて失われてよいのは、途中まで入力していたコマンドだけ。**
   文書・選択・操作ログ・undo履歴はすべてコア側にある。

### 中核の4つの決めごと

- **操作ログが唯一の正で、形状はそこから導出されるキャッシュ。** 保存形式はJSON（SQLiteは使わない）。
  開くときはログから再生する。undo・再生・AIの履歴読み・git差分が全部これに乗る。
- **選択集合はアプリ層ではなくコアにある。** 永続／双方向（AIが書ける）／種別を保持／差分編集可能／
  **提案（`proposed`）と確定（`user`）を区別**。ここをUIの状態にすると交互操作が原理的に不可能になる。
  **verbが食う面・辺・領域は、MCPからもWebSocketからも引数で渡さない**（2026-08-20）——
  どちらもこの集合から取るので、「対象集合の指定方法」は1つしかない。
- **verbのメタ情報は1箇所にしか書かない**（2026-08-20）。名前・引数・カテゴリ・プレビュー可否・
  MCPのスキーマは `duocad/catalog.py` の `COMMANDS` が唯一の宣言で、WebSocketの許可リストも
  MCPのツール定義も導出である。**verbを1つ足すときメタ情報を書くのは宣言1エントリだけ**
  （以前は4ファイル9箇所を手で同期しており、`fillet` は同じタプルが2つの表に、`extrude` は
  `body_id` の有無が表ごとに食い違ったまま残っていた）。**ただし実行の薄いラッパ2本
  （`Session` と `DocumentTools`）は依然verbごとに要る** —— 手順の正は `catalog.py`

### 実測で判明している技術的な地雷（コード側は対処済み。数値を疑うとき用）

- **OCCTのフィレットは例外を投げずに失敗する**（20mm立方体・全辺で r=10.0 は失敗、**r=10.5 は成功**、r=30.0 は失敗。
  **半径に対して単調ですらない**）→ verbのラッパで毎回 `IsDone()` を確認する。
- **面の添字は形状変更で壊れる**（同じ面がフィレットで i=5→9。ただし穴の径変更等では動かない＝**散発的に静かに間違う**）
  → 生の添字を保存・再利用しない。由来スロットを day1 から用意してある。
- **STEP往復の体積は bit-exact ではない**（相対 約8e-16 の1ULP級）→ 比較は `math.isclose(rel_tol=1e-6)`。
- **STLの偏差は絶対値（`isRelative=False`）で渡す** → 相対にすると偏差を1/20にしてもメッシュが1バイトも変わらない。
- **STEP読み込みは `ReadFile()` の戻り値を検査してから `TransferRoots()`** → 怠るとPython例外ではなく
  **プロセスごと落ちる**（0xC0000005）。
- **OCCTのSTEP書き出しはC++からstdoutへ統計を吐く** → MCPのJSON-RPCへ割り込んで接続が死ぬので、
  起動時に fd 1 を fd 2 へ振り替えてある（`_claim_stdout`）。

### 現行verbの制約（v1の範囲として既知）

  非対称な面取りなので、**面の種類は作れても寸法までは再現できない**。

- 操作履歴の「AIがやった／人がやった」の区別は、**その画面が出した操作にだけ**印が付く
  （操作ログに主体が入っていないため。本物にするならコアの永続形式の変更）。
