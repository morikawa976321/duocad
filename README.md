## 0. 設計原則（2026-08-22決定）

UIとAI操作の両方に共通する設計原則。verbを足す・直すときはここへ立ち返る（本人決定。
背景は engine `duocad-ui-interaction-principles` / `duocad-errors-shown-via-toast` /
`duocad-sketch-start-is-two-steps-by-pointing`）。

1. **viewport上で実物をクリックして選択できるものは、別途ボタンを用意しない。**
   基準平面(XY/XZ/YZ)を指す手段が「サイドバーのボタン」と「面を選んでからボタン」の
   2つあったのをポインティング1つに統一した実例が§2「スケッチを始めるのは2手」。
2. **すべての操作を verb→target→how の順序に統一する。**
   コマンドを起動し(verb)、対象を指し(target。クリックまたは共有選択集合から)、
   どうするかを打つ(how。数値・選択肢・パス)。全コマンドで同じ型（§2「操作の型」）。
   **対象を指すID・点の座標・貼る先の平面名は、文字列や列挙に見えても target 側であり
   how ではない**（`MCP.md`「AIはどこまで自分でやるか」と揃える。「名前はすべて対象」
   という言い方はしない — 新規ボディへの命名のような**省略できる付帯入力**は target でも
   how でもない第三分類で、`make_editable_copy` の `name` がその実例）。
   **適用範囲はコマンド行を通るverbに限る**（2026-08-23追記）。値の打ち直し
   (`set_parameter`)・可視性の切替(`set_visible`)・選択集合の編集は直接操作であり、
   この型の対象外である。
3. **省けるクリックは徹底的に省く。** Enterが要るのは次のいずれかに当てはまる操作だけで、
   どちらでもなければ最後のクリックで即適用される（実装は `web/src/commands/command.ts`
   の `needsEnter`、表は `tests/test_ui_command_wiring.py` の `ENTER_REQUIRED`）:
   - (1) **対象を複数選べる**（辺を何本でも・図形を何個でも）
   - (2) **howの入力がある**（数値・選択肢・パス）

   現行で即適用になるのは **`add_line`・`make_editable_copy`・`sketch_create`** の3つ
   （詳細は§2「操作の型」）。
4. **エラーはすべてトーストで見せる**（`web/src/Toast.svelte`）。**いったんエラーのみ**を
   寄せてあり、情報（読み込んだ部品数・書き出したパス等）は`note()`が内部状態として
   保持するだけで画面には出さない（2026-08-23、下段バー削除の本人裁定。実機検査は
   `window.__duocad.messages` で読む）。情報まで画面に出すかは後日判断。
5. **コメントは、コードに現れない制約だけを書く。** 経緯はgitが、決定の理由はengineが持つ。
   書いてよいのは**外部の罠・実測事実・層をまたぐ契約・意図的な変則**の4種だけである。
   「以前は〜だった」「〜から変えた」の語り、次の行が何をするかの言い直し、レビュアーへ向けた
   設計エッセイ、複数ファイルへ同じ理屈を書く重複、テストが既に固定している事柄の再説明は
   書かない（tests の docstring は「落ちたとき何を意味するか」の1〜2行だけ）。

**8bの中心機構の変化**: 実装計画書§8bが中心に据えていた「AIが選択を提案→人が承認して
verb起動」という手順は、原則3（省けるクリックは省く）の結果、verbによって承認が要らない
場合ができたことで中心性を失った。当時の設計判断の記録は書き換えず、§8bに日付つきで
追記してある。AI側の対応する新規則は [MCP.md](MCP.md)「AIはどこまで自分でやるか」が正。

> `web/src` ではなく `web/dist`（ビルド成果物）。`web/src` を触ったら `npm run build`。
> 現在の `dist` は `src` より新しい（2026-08-20ビルド。Gのコミットで作り直した）ので、**そのまま起動してよい**。

**立て方は1つしかない（2026-08-26）。** MCPとWebSocketと静的配信を1プロセスで兼ねるので、
手で触るだけの日もAIに頼む日も同じもので立てる。**MCPクライアントにduocadを起動させる形は廃止した**

### 画面の構成

配置はFusion 360に寄せてある（2026-08-23）。

```
┌ ヘッダ: 接続状態 / 現在のファイル名 / 部品数 / 操作数 / プレビュー中                  ┐
├ ツールバー: ファイル(名前表示/新規保存/一覧) / コマンドのボタン / 何を待っているか / 入力欄 ┤

│  │ モデル: ボディと可視性 │                                       │  / スケッチ           │
│  │ スケッチ: 一覧・編集中 │                                       │                       │
```

  右サイドバー→左サイドバー(データパネル)を経てここへ統合した）。一覧はツールバーの

### 操作の型（**全コマンドで同じ**）

**コマンドのボタンを押す → 引数を集める（クリック・数値・選択肢）→ プレビュー → Enterで確定 / Escで中断。**
verbごとに別のダイアログを作っていないので、1つ覚えれば全部同じ。

**ただしEnterが要らないコマンドが3つある**（2026-08-22。**線分**・**編集用に複製**・**スケッチ**）。
要否はコマンドごとのフラグではなく**引数から導出**している（`web/src/commands/command.ts` の `needsEnter`）:

- **対象を複数取れる**（辺を何本でも・図形を何個でも）か、**数値・選択肢・パスを打つ**なら → **Enterが要る**
  （「もう選び終わったか」「打ち終わったか」は機械には分からないので、終わりを人が言う）
- **対象が1つに定まり、打つものが無い**なら → **引数が揃ったクリックでそのまま適用**（聞くことが残っていない）

即適用は**あなたがこの画面で指したクリックでだけ**起きる。**起動しただけでは起きない**ので、
面を選んだ状態で「編集用に複製」を押しても何も起きず、そこではEnter（またはボタンの押し直し）が適用の1手になる。
**AIが選択を書き換えても起きない**（`modify_selection` で対象が1つに揃っても、指したのは人ではない）。

| キー / 操作 | 意味 |
|---|---|
| クリック | 選択を**置き換え**（1つだけ選んでいるものを再クリックすると外れる） |
| **Shift+クリック** | 選択に**追加**（フィレット・面取りの複数辺はこれ） |
| **Ctrl+クリック** | 選択から**除去** |
| **Enter** | 確定（引数が揃っているとき）。選択中のコマンドのボタンをもう一度押しても同じ。**線分・編集用に複製・スケッチでは要らない**（上記） |
| **Esc** | 中断（**操作ログ・体積・入力欄が1つも動かずに戻る**のが正しい挙動） |
| **Tab** | 次の数値引数へ |
| **Ctrl+Z / Ctrl+Y（Ctrl+Shift+Z）** | undo / redo（2026-08-23、ボタンを廃してキーボードのみに一本化） |

### コマンド一覧（画面のボタン名）

| モード | ボタン |
|---|---|
| 通常 | 押し出す／領域を押し出す／丸める／面取り／**スケッチ**（★）／矩形反復／円形反復／STEP読み込み／**SVG読み込み**／STEP書き出し／STL書き出し／**編集用に複製**（★） |
| スケッチ中 | 選ぶ／**線分**（★）／円／長方形／円弧／（領域を押し出す・反復） |

**保存／開くはツールバーの「ファイル」パネル（`FilesPanel.svelte`）にある**
（2026-08-22に固定フォルダ化・2026-08-23にツールバーへ統合。
engine `duocad-save-location-fixed-folder`）。`duocad/models/`
（リポジトリ直下・gitignore対象。無ければアプリが作る）の中身を**一覧から選ぶ**形に
なった。パスを手打ちする入力欄はもう無い:

- **新規保存**: 名前欄にファイル名（例 `model.json`）を打って「新規保存」（Enterでも可）
- **開く**: 一覧の行をクリック（**確認ダイアログは無い**。§0「省けるクリックは徹底的に省く」）
- **上書き**: 一覧の行の「上書き」ボタン（今の文書をそのファイルへ書く）
- 一覧の各行は**名前・操作数・サイズ**を出す。ヘッダの `#current-file` に
  **今どのファイルを触っているか**が常に出る（未保存なら「(未保存)」）
- ブラウザのネイティブファイルダイアログ（File System Access API）は使わない ——
  実際に書いているのはサーバ側のPythonなので、ブラウザがファイルハンドルを持っても
  噛み合わない

保存/開くの引数は**ファイル名だけ**（`save_document`/`open_document` の `name`）で、
区切り文字・絶対パス・`..` はサーバ(`Session._resolve_document_name`)が拒否し、
`models_dir` の外には出られない。書き出し系（STEP/STL・STEP読み込み）は従来どおり
任意のパスを打てる（この制約の対象は保存/開くだけ）。

★ = **Enterが要らない**（起動してから、線分は2点目のクリック・編集用に複製とスケッチは1回のクリックで適用される）。
起動中のコマンドのボタンには、Enterが要るものだけ「(Enter)」が付く。

**スケッチを始めるのは2手**（2026-08-22）: ツールバーの「**スケッチ**」を押す → **貼る先をクリック**。
貼る先は **XY / XZ / YZ の基準平面グリッド**か、**ソリッドの面**のどちらでもよく、指し方は同じ1クリックである
（起動している間だけグリッドが明るくなり、指せるようになる）。**平面を選ぶボタンは無い** ——
実物をクリックして指せるものにボタンを作らない、が指針だから（旧: サイドバーの XY/XZ/YZ ボタン）。
スケッチパネルに残るのは「**再開**」「**抜ける**」「**正面から見る**」で、これらはverbではなくモード操作である。

**SVG読み込みも同じ2手 + パス**（2026-08-26）: 「**SVG読み込み**」を押す → **貼る先をクリック**
→ パスを打って Enter。外で描いた輪郭（ロゴ・図面・アウトライン化した文字）が**1枚のスケッチ**
として入り、その時点で領域として使えるので、続けて「領域を押し出す」を打てる（**スケッチモードには
入らない**ので Esc は要らない）。曲線は`bezier`という図形種別で**曲線のまま**入る ——
折れ線に落とすと押し出した側面が線分の数だけ平面に割れる（実測で面数4対130）。
単位はmm固定で、SVGが物理単位（`width="100mm"`）を持てばその寸法、`viewBox`しか無ければ
1ユーザー単位=1mm。**ベジエを1本ずつ描くコマンドは無い**（人もAIも作れるのは取り込み経由だけ。
2026-08-26本人裁定）。

面に貼るときは**クリックした面がそのまま貼る先**になる（選択を置き換えたうえでverbが飛ぶ）。
AIが2枚提案していたり提案のままだったりすると、サーバが断ってトーストに理由が出る
（「ちょうど1枚」「まだ確定していない」）。

### 覚えておくと迷わない挙動

- **線分は2点目のクリックで引かれる**（2026-08-22）。Enterは要らず、確定してもコマンドは構えたままなので
  クリックを続けると線が連なる。抜けるのは **Esc**（「選ぶ」へ戻る）。
- **基準平面のグリッドは、スケッチを起動している間だけ指せる**（2026-08-22。辺と同じ規律）。
  部品の手前に見えているグリッドが取れ、部品に隠れている所は取れない（面と平面は近い方が勝つ）——
  **大きなモデルの中に原点が埋まっているときは、ブラウザの「モデル」で隠してから指す**。
- **「編集用に複製」は、押してから面をクリックすると即座に複製する**（2026-08-22）。
  **押す前から面を選んでいた場合・AIが選択を書き換えた場合は発火しない** —— そこはEnter
  （またはボタンの押し直し）で適用する。「起動しただけで文書が変わる」「人が指していないのに文書が変わる」を
  構造的に起こさないための区別で、**1回の起動につき1回だけ**適用される（続けて複製するならボタンを押し直す）。
- **辺は、辺を要求しているコマンドを起動している間だけ画面に出る**（常時出すと面のクリックが辺に取られる）。
  フィレット／面取りを起動してから辺をクリックする。
- **領域は、通常モードでは「領域を押し出す」を起動している間だけ指せる**（2026-08-23。辺と同じ規律）。
  起動している間は**全スケッチの領域**が3Dクリックで選べ（置換／Shift追加／Ctrl除去は面と同じ）、
  重なっているときは**面より領域が勝つ**（要求しているものが勝つ）。常時指せるようにしないのは、
  スケッチ平面と重なる面（そこから押し出した板の底面など）のクリックが領域に取られるため。
  **スケッチモード中は今のスケッチの領域だけ**が対象で、そこは変わっていない。
- **頂点は、選択に入っているものだけが点で出る**（2026-08-23。辺・領域とは規律が違う）。
  点の大きさは**画面の画素で固定**してあるので、引いても消えず寄っても膨らまない。
  頂点を引数に取るコマンドが1つも無いので「候補を全部見せて選ばせる」場面が存在せず、
  **要るのは「AIが提案した頂点が今どれか」を人が見て、Ctrl+クリックで外せることだけ**である。
  したがって**頂点を選択へ新しく足す経路は画面に無い**（足すのはAIの `propose_selection` だけ）。
  優先順位は 辺 → 領域 → **頂点** → 面／基準平面 —— 頂点は必ず辺の端点に乗っているので、
  辺を要求しているコマンドの最中は辺が勝つ（そうしないと丸めたい辺の端が掴めない）。
- **選択パネルは無い**（2026-08-23に削除。本人裁定）。人が選択を直す手段は3Dクリックに一本化した:
  **外す**＝Ctrl+クリック（面・辺・領域・頂点のすべて）／**全解除**＝何も無い所を素でクリック／
  **承認**＝不要（下記）。AIの提案（水色）と確定（橙）の区別を伝えるのは**3Dのハイライト色だけ**になった。
- **AIの提案は、人がコマンドを実行した時点で自動的に確定する**（2026-08-23。「承認する」ボタンの代替）。
  対象集合を確定選択から取るverb（押し出す・領域を押し出す・丸める・面取り・スケッチ）が
  ブラウザから届くと、サーバが走らせる直前に `commit_selection` する
  （`duocad/server.py` の `_commit_before_verb`。宣言は `catalog.Command.uses_selection`）。
  **人がツールバーからコマンドを実行する行為そのものが承認**である、というのが根拠。
  可視性の切替・undo・選択集合の編集では確定しない。**AI側（MCP）は素通し**で、
  AIは今までどおり自分の提案を `commit_selection` で明示的に確定する。
- **見えていないボディは選べない**（述語による提案も、画面から指せるのは見えているものだけ）。
  奥の面を触りたいときはブラウザの「モデル」で手前を隠す。
- **読み込んだSTEPはそのまま編集できる**（2026-08-15）。ソリッドごとに編集用ボディができ、
  面をクリックして押し出せる（原本の参照ボディは隠したまま文書に残り、ブラウザには出ない）。
  「編集用に複製」（`make_editable_copy`）は、選んだ面のボディをもう1つ作るコマンドである
  （参照ボディを起点にすれば「編集可能にする」、編集用ボディを起点にすれば複製。**どちらも同じverb**）。
- **数値は名前つきの値（`d1` `d2` …）として保持される。** パラメータ一覧で打ち直すと形が追随する。
- **保存形式は操作ログのJSON**。したがって「開く」は再生であり、開くたびに再生経路が検査される。
- **保存ファイルは自己完結している**（2026-08-23）。読み込んだSTEPは**本文がそのまま操作ログへ
  取り込まれる**ので、元のSTEPを移動・改名・削除しても、別PCへ持っていっても開ける。
  取り込みなので元のSTEPを後から更新しても追随しない（Fusionの「挿入」と同じ）。
  代償はファイルサイズで、4.6MBのSTEPを読むと `model.json` は約4.8MBになる
  （実測。開くのに約1.6秒）。保存形式の版は `OpLog.FORMAT_VERSION = 2`。
- **形を変える操作(押し出し・丸め・面取り・反復・図形追加・パラメータ変更)の確定後、
  undo/redoの後は選択が常に空になる**（2026-08-20）。添字は形状変更で壊れるので、後継を
  当てにいくのではなく選び直させる。可視性の切替（手前を隠す）では選択は飛ばない。

## 5. アーキテクチャ

```
┌── AI（MCPクライアント）──┐        ┌── 人間（アプリ層 / ブラウザ）──┐
│  述語で引数を作る          │        │  ポインティングで引数を作る      │
└───────────┬──────────────┘        └──────────────┬─────────────────┘
            │ stdio(JSON-RPC)                        │ WebSocket
            │                                        │ コマンド↓ ／ イベント↑
            └────────────────┬───────────────────────┘
                             ▼
        ┌──────────── コア（Python・唯一の真実源）────────────┐
        │  文書（ボディ・スケッチ）／ 選択集合 ／ 操作ログ ／ undo │
        │  ── verb層（純関数） f(文書, 選択, 引数) → 新しい文書 ──  │
        │      問い合わせ : build123d ラッパ（差し替え可能）         │
        │      操作      : OCP（OCCT）＋ 由来マップ回収            │
        └────────────────────────────────────────────────────┘
```

### 外してはいけない3つ

1. **AIの経路はアプリ層を通らない。** コアはUIが無くても機能的に完全であること。
   アプリ層にしか無い機能を作った瞬間、AIから使えなくなる。**層分けの唯一かつ最大の存在理由。**
2. **コマンドは下り、イベントは上り。** AIが選択や可視性を変えるとコアがイベントを発火し、
   ブラウザが描き直す。**この上り方向が無いと交互操作が成立しない。**
3. **アプリ層が落ちて失われてよいのは、途中まで入力していたコマンドだけ。**
   文書・選択・操作ログ・undo履歴はすべてコア側にある。

### 中核の4つの決めごと

- **操作ログが唯一の正で、形状はそこから導出されるキャッシュ。** 保存形式はJSON（SQLiteは使わない）。
  開くときはログから再生する。undo・再生・AIの履歴読み・git差分が全部これに乗る。
- **選択集合はアプリ層ではなくコアにある。** 永続／双方向（AIが書ける）／種別を保持／差分編集可能／
  **提案（`proposed`）と確定（`user`）を区別**。ここをUIの状態にすると交互操作が原理的に不可能になる。
  **verbが食う面・辺・領域は、MCPからもWebSocketからも引数で渡さない**（2026-08-20）——
  どちらもこの集合から取るので、「対象集合の指定方法」は1つしかない。
- **verbのメタ情報は1箇所にしか書かない**（2026-08-20）。名前・引数・カテゴリ・プレビュー可否・
  MCPのスキーマは `duocad/catalog.py` の `COMMANDS` が唯一の宣言で、WebSocketの許可リストも
  MCPのツール定義も導出である。**verbを1つ足すときメタ情報を書くのは宣言1エントリだけ**
  （以前は4ファイル9箇所を手で同期しており、`fillet` は同じタプルが2つの表に、`extrude` は
  `body_id` の有無が表ごとに食い違ったまま残っていた）。**ただし実行の薄いラッパ2本
  （`Session` と `DocumentTools`）は依然verbごとに要る** —— 手順の正は `catalog.py`
  冒頭docstringの5ステップ。ここを1本化するには汎用ディスパッチャが要る（未着手）。frontendだけは別に持つ ——
  TS側が持つのは**引数の集め方**（どのクリックを待つか・入力欄のid）で、宣言には無い情報だから。
  名前と分類が一致することは `tests/test_ui_command_wiring.py` が機械で見る。
- **verb ＝ ①undo1回で消える単位 ②操作ログ1行 ③MCP1呼び出し が一致する単位。**
  UIの操作手順（面を選ぶ→距離→Enter）は**1つのverbを組み立てる漏斗**であって、3つのverbではない。

> **かつてここに書いてあった非対称は解消した**（2026-08-26）。MCPがstdioしか持たなかった間は

- **システムプロンプトも二重に持たない** —— `catalog.agent_instructions()` の1本をMCPの

   スクリプトの脆さかは未判定** —— カメラの余白を広げるのか、スクリプトの座標を寄せるのかが
   判断の分かれ目で、**本人判断待ち**。**`acceptance.mjs` の4件は2026-08-23の実測では緑だった**
   （着手前・完了後の2回とも人間側19操作すべてOK。実行タイミング依存の疑いがあり、赤の記述は残す）。
   他の6本（`smoke` / `smoke-files` / `smoke-mcp` / `smoke-toast` / `smoke-regions` / `smoke-vertex`）は緑。

### 実測で判明している技術的な地雷（コード側は対処済み。数値を疑うとき用）

- **OCCTのフィレットは例外を投げずに失敗する**（20mm立方体・全辺で r=10.0 は失敗、**r=10.5 は成功**、r=30.0 は失敗。
  **半径に対して単調ですらない**）→ verbのラッパで毎回 `IsDone()` を確認する。
- **面の添字は形状変更で壊れる**（同じ面がフィレットで i=5→9。ただし穴の径変更等では動かない＝**散発的に静かに間違う**）
  → 生の添字を保存・再利用しない。由来スロットを day1 から用意してある。
- **STEP往復の体積は bit-exact ではない**（相対 約8e-16 の1ULP級）→ 比較は `math.isclose(rel_tol=1e-6)`。
- **STLの偏差は絶対値（`isRelative=False`）で渡す** → 相対にすると偏差を1/20にしてもメッシュが1バイトも変わらない。
- **STEP読み込みは `ReadFile()` の戻り値を検査してから `TransferRoots()`** → 怠るとPython例外ではなく
  **プロセスごと落ちる**（0xC0000005）。
- **OCCTのSTEP書き出しはC++からstdoutへ統計を吐く** → MCPのJSON-RPCへ割り込んで接続が死ぬので、
  起動時に fd 1 を fd 2 へ振り替えてある（`_claim_stdout`）。

### 現行verbの制約（v1の範囲として既知）

- **面取りは距離1つ（＝45度）しか取れない。** PCケースの脚の円錐は半径方向4mm・軸方向22mmの
  非対称な面取りなので、**面の種類は作れても寸法までは再現できない**。
- 拘束ソルバは持たない（各図形が自分の数値を持つパラメトリック・プリミティブで足りている）。
  次に足すなら `python-solvespace`（実測済み・GPLv3+）。
