# duocad — AI統合（アプリ内AI・MCP・ローカルLLM）

**読むとき**: アプリ内 AI パネル・`duocad/agent/`・MCP 経路の方向を変えるとき、ローカル LLM の
能力や待ち時間を見積もるとき。仕組みの正は README §1・§4 と [../MCP.md](../MCP.md)、契約は
`tests/test_agent_*.py` / `tests/test_mcp*.py`。

## 方向と未決

- **AI は Claude もローカル LLM も「作業しているマシン」で実行する**（本人 2026-08-22）。web デプロイしても
  サーバ機に置いた AI を全端末で共用する形は採らない。帰結: サーバと AI が別マシンになるので **LLM 呼び出しの
  接続の向きを反転させる必要がある**（`AgentLoop` は今は Python サーバ側で LLM を叩く）。借り物の PC では
  ローカル LLM 経路は成立せず Claude 側の経路だけが残る。
- **アプリ内 AI パネルから Claude を API キーで使う経路は廃止**（本人 2026-08-27「不要」）。残るのは llama-server
  （`openai_compat`）だけで、Claude を使う道は MCP（サブスク認証の Claude Code が `/mcp` へ繋ぐ）。
  プロバイダ選択の仕組み（`Provider` / `build_provider` / `ai_configure(provider=…)` / `ai_status.providers`）は
  次の差込口として残し、**画面のプロバイダ選択は `providers` が2つ以上のときだけ出る**（`AiPanel.svelte`）。
- **`claude` CLI をサブプロセス起動して AI パネルから使う案（3段構成の段2+3）は未決のまま**。段1（MCP の HTTP
  トランスポート）だけが実装済み。「web アプリであることが邪魔をしているのでは。ネイティブに移植すべきか」という
  問いも未決。復活の芽があるとすれば段2+3（サブスク認証）であって API キー経路ではない。
- **MCP 登録は `.mcp.json`（project スコープ）だけ**（本人 2026-08-26）。user スコープに足せばどこからでも
  繋がるが本人はそれを選ばなかった —— 登録がリポジトリに載る（クローンすればそのまま繋がる）、リポジトリを
  読んだ人に接続方法が見える。コンテキスト消費は判断材料として小さかった（実測: 遅延読み込みが既定なので
  セッション開始時に載るのはツール名29個 731文字＋instructions 836文字。全スキーマ 10,169文字が載るのは
  `alwaysLoad` か `ENABLE_TOOL_SEARCH=false` のときだけ）。

## ローカル LLM の実測（duocad の実ツールで）

- **Qwen3.8-27B-Q3_K_M**（llama-server・`-c 16384`、2026-08-20）: `PC_case_feet.step`（5面6辺）で
  `import_step` → `describe_predicates` を教えずに自発的に呼ぶ → 「全部の辺」を選ぶ述語が無い問題を
  `length_gt: 0` で回避し `describe_shape` の `edge_count=6` と突き合わせて自分で検算 → `propose_selection` →
  `commit_selection` → `fillet(radius=1)`。全7ターン 170秒、プロンプト 4,005→5,789 トークン。
  **ツール定義29個だけで 3,626 トークン（10,716文字）を毎ターン占める。**
- **Ornith-1.5-9B**（Q4_K_M・RTX 5060 Ti・67 tok/s、2026-08-22）: 「XY にスケッチ→原点に直径8mmの円→
  X20mm×4・Y15mm×3 で配列」を5手で完走（直径→半径の変換も正しく、エラーゼロ・ID の捏造ゼロ）。
  40ボディ＋8スケッチ＋24パラメータ（約7,800字）から「kind=solid のうち体積最大」も正答。
  **9B でもエージェントの土台に足りる**（dGPU 無しのラップトップへの移行余地）。
  当初「6手を超えると破綻する」と見えたのは模擬バックエンドの産物で、実物では再現しなかった。
- **待ち時間の分散はほぼ全部が思考**（Ornith-9B・同一の4手目を seed 違いで8回ずつ、2026-08-23）:

  | 条件 | 中央値 | 最悪 | 生成トークン | 誤り |
  |---|---|---|---|---|
  | 思考ON（現状） | 3.25s | 8.09s | 86〜518 | 1/8 |
  | 思考OFF | 1.56s | 1.66s | 98〜105 | 1/8 |
  | 思考OFF + `tool_choice:required` | 1.53s | 1.64s | 98〜105 | 1/8 |

  思考を切ると出力長がほぼ決定的になる（8回中7回が98トークンぴったり）。精度は3条件で差が出ず、
  **思考OFFに判断品質の代償があるとは言えない**（このタスクでは）。
  事故時の 7,468 トークン（1リクエスト120秒超）は観測レンジの14倍で、通常のばらつきの裾ではなく
  **縮退ループ**。サンプラは `repeat_penalty=1.0` `dry_multiplier=0.0`（llama-server 既定）で
  反復抑制が1つも入っていない。矛盾した指示で思考が膨らみ600秒返らなかった実測もある（README §4）。

## 「止まる」規律はプロンプトではなく実装で守る

- `agent_instructions()` は「曖昧・探索的な依頼なら `propose_selection` で止めて尋ねる」「迷ったら止める側に倒す」
  と明記しているが、**Ornith-9B は守れない**（2026-08-22）。「角が尖ってて危ないから、いい感じに処理しといて」に対し
  R1.5mm を自分で決めて `fillet` まで適用した。**このモデルは「能力の限界」（述語が無くて選べない）では止まれるが
  「権限の限界」（やっていいか分からない）では止まれない** —— 「進める」方向への一貫した偏りで、9B クラスに
  「やらない判断」を期待するのは分が悪い。
- 線引き: **プロンプトで頼んでよいのは「間違えても直せること」だけ。undo でしか戻せない副作用が絡む規律は
  実装で止める。** 文章は守られたか後から検証できないが、コードは検査で固定できる。
- 実装は `Param.dimension`（`catalog.py`）＋ `AgentLoop._dimensions_nobody_asked_for`（`agent/loop.py`）。
  実機（2026-08-23）: 曖昧な依頼3回は適用 **0/3**（1回はガードが fillet を阻止、2回は打ち切り）、
  寸法を明示した依頼は **3/3** 完走で誤発火なし。
- 散文の規範（`agent_instructions()`）が骨抜きにされていないことを文字列検査で守る試みは、QA が2ラウンド続けて
  素通り経路を見つけて打ち切った（列挙していない言い回しの矛盾は常に書き足せる）。原本の docstring の
  「この文を書き換える人へ」が最後の防波堤。散文を検査から外すときは**外した先に別の防具（コア側の門
  `selection_not_committed`）があること**を確かめる。

## 落とし穴（実装・検査で踏んだもの）

- **未知の引数はプロトコルエラー**: `McpServer._call_tool` はツール本体を呼ぶ前に `_check_arguments` で
  スキーマ突合し、未知キーは JSON-RPC のトップレベル `error`（-32602）で返す。`tests/test_mcp_verbs.py` の
  `call_error()`（`isError` 封筒を期待）では拾えず、`request()` を直接呼んで `response["error"]["code"]` を見る。
- **MCP 起点の変更は `applied` を付けずに全接続へ配信される**（`duocad/net/ws.py` `_on_core_change`）。
  `applied.verb` で分岐する画面の挙動を実機で検査するときは、MCP からではなく本物の DOM 操作で起こす
  （[SMOKE_TESTING.md](SMOKE_TESTING.md)）。
- **操作ログから外した状態は、楽観ロックの版にも自分の指紋を足さないと黙って検出されなくなる。** 可視性を
  ログから外した時点で「AI が考えている間に人がボディを隠した」が版に一切現れなくなり、可視性の指紋を足して塞いだ
  （`DocumentTools.current_seq` は3つ組）。状態から導いている版（`body_revision`）は壊れず、経路（ログ）から
  導いている版だけが壊れる。
- **`run_coroutine_threadsafe(...).result()` をイベントループ自身のスレッドから呼ぶと必ず固まる。**
  `ToolsOnLoop._run_on_loop` は同じスレッドなら直接呼ぶ（`net/tools_on_loop.py`）。楽観ロックで毎ターン
  `current_seq()` を呼ぶようにした瞬間に `tests/test_agent_ws.py` の1本で顕在化し、pytest が CPU ほぼ0のまま
  数分止まった —— **プロセスが生きているのに CPU が動かないなら「遅い」ではなくデッドロックを疑う**。
- **AI パネルの条件付きレンダリングは DOM を消すが状態は消さない。** エンドポイント欄を `{#if}` で隠しても
  `baseUrlDraft` は送られ、サーバの正しい防御に当たって画面操作だけでは戻れなくなった。対処は送信時に落とすの
  ではなく**プロバイダを切り替えた時点で打ちかけを捨てる**（`AiPanel.svelte`）。
