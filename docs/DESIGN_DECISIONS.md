# duocad — 設計判断と実測（コア・全体）

**読むとき**: verb・データモデル・保存形式・テスト方針・プロジェクトの方向を変えるとき。
「なぜこの形か」の根拠がここにある。**いまの挙動の正はコードとテスト**（`tests/README.md`）。
画面まわりは [UI.md](UI.md) / [VIEWPORT.md](VIEWPORT.md)、AI統合は [AI_INTEGRATION.md](AI_INTEGRATION.md)、
形状最適化は `TOPOPT*.md`。

## 技術選定の根拠（[INITIAL_PLAN.md](INITIAL_PLAN.md) §4 の補足）

- **Svelte 5 を選び React を撤回した根拠は、自分たちのアーキテクチャ側にある。** 状態を全部コアに
  置いたので、frontend に残る状態はコマンドの途中状態だけで、画面部品も10個前後。フレームワークが
  元を取るのはクライアント状態管理であり、その理由を設計時点で消していた。決め手は技術的優劣ではなく
  「2年後に自分が読み返して分かるか」（10年使う道具）。
- **依存の危険度の順位**（churn を心配する順）: ① three.js（semver を持たず r 番号で毎月リリース・
  非推奨APIを定期削除）② 言語バインディング（OCP。維持者が少ない）③ 小規模ライブラリ ④ フレームワーク。
  フレームワークは最下位。Svelte コアの大きな書き換えは約5年間隔（3→4→5）で、年1回壊すのは SvelteKit 側。
- **ローカル専用ツールは上げなければ壊れない。** 実コストは「壊れる」ではなく**イディオムのずれ**
  （次の大きな版が出た後にAIが書く「今風の書き方」が手元と噛み合わず、AI支援の質が落ちる）。
  対処は「書き換えが1日で済む規模に surface を保つ」——部品10個以下ならこれで足りる。
  churn の激しい依存は狭いインタフェースに閉じ、バージョンは固定する（`pyproject.toml`・`package.json`）。

## 既成CADへ転換する場合の候補（再検討材料）

方針は「自作（Pythonコア＋ブラウザ）」で決定済みだが、将来転換する可能性は低くない。評価軸は
**直接操作の質 × Linuxネイティブ × 軽さ**であって機能の多さではない。**UIの様式そのものが足切り条件**
（FreeCAD はクラシカルすぎて却下済み。再提案しない）。候補を出すときは機能表ではなく画面の見た目を先に確かめる。

| 候補 | 要点 |
|---|---|
| SolveSpace | 拘束ベース・数MB。機械部品と治具だけなら最小。機能の少なさが天井 |
| Plasticity | 履歴なしダイレクトモデリング・Parasolid。Ubuntuネイティブ・買い切り。パラメトリック作り直し不可 |
| Blender + CAD Sketcher / Geometry Nodes | 拘束2Dスケッチ＋非破壊。パネル全消しで3Dビューだけにできる |
| Onshape | UIは最上位だが無料版はデータ全公開・クラウド束縛（離脱理由の再来） |
| Antimony / libfive Studio | 3Dビューのドラッグでスクリプトの数値が書き換わる双方向。採用候補というより設計の参考 |

## verb の粒度（INITIAL_PLAN §2 の補足）

- **避ける切り方**: 細かすぎ（UIの1ステップ＝1verb）は、AIがモーダルな状態機械を人の真似で駆動する羽目になり
  ログは再生不能・undo粒度も壊れる —— **MCPをUI手順の写しにするのが最もありがちで最も致命的**。
  粗すぎ（「ブラケットを作って」＝1verb）は途中結果を指せず、交互操作の割り込み点が消える。
- **verb に課す2つの制約**: (1) 純関数 `f(document, selection, params) -> new_document`（undo もプレビューも
  無料になる）(2) 既存の選択を先に消費する（AI→人の受け渡しがこれで成立する）。
- **モード（通常/スケッチ/形状最適化）は verb の上位次元**で、コアにもMCPにも持ち込まない（`Document` に
  フラグを置かない・`enter_sketch` のような verb を作らない・ツール集合をモードで変えない）。モード遷移は
  undo1回/ログ1行/MCP1呼び出しのどれとも一致しないので verb ではない。
- **起動時にしかできない操作を作らない。** 起動オプション `--step` を消せなかった理由は「アプリ内 import が
  半分しかやらない」ことだったので、オプションを消すには機能の非対称を先に消すしかなかった。
  起動オプションの数はこの手の非対称の指標になる。
- **削除 verb のキー割当（Delete/Backspace）は付けていない。** 他の verb にキー割当が無い中で delete だけが
  持つのは一貫性を欠くため、**全 verb が揃ってからまとめて決める**（本人判断 2026-09-03）。
- **ソリッドブーリアン**（2026-09-11 本人判断。演算の意味は `kernel.boolean_bodies` の docstring が正）:
  選択UIは「ターゲットを1つピック（`PickArgSpec`）→ツールを複数確定選択」で、役割の違う2つの選択グループを
  持つ初めての verb。確定前にツール構成を変えるたびライブ再計算する。

## 図形（スケッチ）の表現

- **拘束ソルバは持たない**（`duocad/parameters.py`）。ただし「書かなくてよい」の根拠は実測済み:
  `python-solvespace` 3.0.8 で雑に置いた4点の矩形に horizontal×2 / vertical×2 / distance×2 を与えて約20行で
  厳密収束し、寸法を変えて再解決もできた（2026-08-07）。**ライセンスは GPLv3+**（配布・販売時に効く。代替の
  FreeCAD `planegcs` も GPL系）。**`dof()` の値は手計算と合わなかった**（完全定義で0のはずが6）ので、
  「完全定義（青→黒）」表示を作るなら要調査。統合は未着手で、Entity は座標を直接パラメータに持つ ——
  だから `move_sketch_entities` が座標を直接書いてもソルバと衝突しない。
- **長方形は1つの図形のまま据え置く**（4本の線分＋拘束にしない。本人判断 2026-09-06）。辺単位で触りたく
  なったら**分解 verb を足す**（`_rotate_rectangle` 系の分解コードが既にあるので実装は小さい）。
  `angle` を持たせたのは機能追加ではなく「欠けている数値を埋める」もの（拘束が無いから Fusion を真似る理由が無い）。
- **図形の `params` にキーを足すとき**（`angle` で全部踏んだ。2026-09-06）: 旧ログから再生した個体はその
  キーを持たないまま残る。**再生時に既定値で埋めてはいけない** —— `register_value` は空いている最小の
  `d<n>` を振るので、以後の名前が全部ずれて古い `set_parameter` が別の値を指す（`keyboard_36_case.json` は
  `d1`〜`d152`）。読む側が `get` で受けるしかなく、次の3箇所が例外もログも出さずに壊れる:
  (1) 書き戻し（`KeyError`。図形がまだ持たないキーは書き戻す側で `register_value` する）
  (2) 辞書の等値比較（キー数が違うだけで常に不一致。元が持つキーだけで比べる）
  (3) 「新規パラメータは N 個」を固定した実機検査（`smoke-optimize-mode.mjs`。語では検索できない）。
  旧データを再生した状態からの検査を1本ずつ足すこと。
- **スケッチと押し出し済みソリッドは連動しない**（本人が許容。2026-08-30）。`move_sketch_entities` や
  `set_parameter` でスケッチを変えても対応ソリッドは追従しない（パラメトリック履歴ツリーは無い）。
  **寸法（半径・幅高さ・角度）を人が打ち直す口も作っていない** —— 作るなら「押し出し済みソリッドの
  再計算をどうするか」を先に決める。
- **回転の既定中心（重心の軸への直交射影）が意味を持つのは「向きだけ指定」の経路だけ**。3Dの回転は
  軸線上のどの点を基準にしても同じ変換なので、軸の位置が決まっている（辺で指す・点＋向き）なら恒等。

## 保存・文書

- **保存済みモデルは捨ててよい。移行スクリプトは書かない**（本人判断 2026-08-26）。verb を消して
  開けなくなったら、元の STEP（`C:\Users\tm976\mf\3d-models`）から作り直す。保存形式や verb 集合を
  壊す変更を検討するとき、**既存モデルの移行コストを制約に数えなくてよい**（「まだ大したものを作れる状態では
  ない」本人 2026-08-27）。
- **保存先を `models/` に固定した理由**: 引数がパス1つだと相対パスがサーバの CWD 基準になり、
  「その日どこで起動したか」で保存先が変わって実際に保存されたファイルが1つも無かった。
  ブラウザのネイティブファイルダイアログ（File System Access API）は使わない —— 書いているのはサーバ側の
  Python なので、ブラウザがファイルハンドルを持っても噛み合わない。
- **STEP をログへ生テキストで埋め込んだ実測**（2026-08-23）: 4.6MB の STEP（27ソリッド）で `model.json`
  4.83MB（**+4%**。ASCII なので増えるのは改行と引用符のエスケープだけ。base64 なら +33%）、保存 0.02秒、
  開く 1.5〜1.6秒（**ほぼ OCCT のパース**。埋め込み無しの import 1.49秒と同じ）。一覧は 4.8MB 1件あたり約30ms。
  この数値で、保留していた形状キャッシュ（サイドカー BREP）と zip コンテナ化は**どちらも不要**と決着。
  **「1モデル＝1ファイル」「git で差分が読める」「自己完結」は3つ同時に満たせない** —— 保存形式を決めた時点で
  外部 STEP の取り込みが視野に無く、埋め込みで表に出た衝突。duocad 版 / OCCT 版の記録は保留（未決）。
- **ログへ埋め込むと配信も太る。** `state_meta()` はログのエントリを `args` ごと配るので、埋め込み直後は
  1操作あたり 4.83MB が WebSocket に流れていた。配信用の射影で伏せて 10.5KB（`duocad/view.py`）。
  埋め込みを足したら `json.dumps(配信ペイロード)` の長さを実測すること —— テストは通る。
- **複数プロジェクトは「閉じて開く」で切り替える**（本人判断 2026-08-23）。別プロセス（`--port` を変える
  だけで独立プロジェクトになる。コード変更ゼロ）・複数文書対応・アプリ内タブは当面採らない。
  同じ URL を2タブ開いても同じ文書が映るだけ（broadcast は交互操作の核なので消さない）。

## 隠したボディ・選択・可視性

- **非表示のボディは fillet / chamfer / extrude の対象にもできない**（本人承認・現状維持 2026-08-20）。
  「可視性は見た目の設定ではなく、何を指せるかの定義」の延長。手数が1つ増えるだけで理由がエラーで出る ——
  従来は黙って変わっていた。**先に緩めない**（煩わしければ `join` モードだけ後から緩める余地がある）。
- **形状変更後の選択全リセット**の代替案「失効した参照と後継を返す契約」は先取りしない。連続性が本当に
  要る verb が現れてから作る。移動系 verb を例外にする案は本人が却下した（全 verb 統一。2026-08-31）。
- **メッシュボディへの「通す / 断る / 黙って外す」の線は「呼び出し側が何を主張したか」で決める**
  （README §4）。実装は `App.svelte` の `pickedRef` がメッシュをボディ参照へ畳む1本で、ツールバーを
  選択に応じて出し分ける案は採らなかった（コマンド一覧はモードの持ち物で、選択のたびに作り直すと
  集めかけの引数が落ちる）。

## コード調査（2026-08-27）で「積まない」と決めたもの

汎用ディスパッチャ（verb 追加手順の一本化）・`kernel.py` の分割・`_dispatch` の表駆動化は**積まない**。
`server.py` の分割は2段構え（クラス境界→ `DocumentView` の切り出し）で実施済み。
`Applied` 型の同期は**生成ではなく突合の機械検査**（`tests/test_applied_type_sync.py`）。

## テスト方針

- **削減の基準（本人 2026-08-20）**: 存在確認と一目瞭然のロジックは検査しない。複雑なロジックは検査する。
  形が存在確認でも残すのは、事故を検出する別チャネルを持つもの（走査テストの自衛ガード・2つの独立ソース間の
  同期検査・宣言表の記述完備リント・層規律ガード・セキュリティ衛生）。
- **層をまたぐ二重検査は意図して残す**: `tests/test_mcp_verbs.py` が体積・undo を `test_fillet.py` と重ねて
  見るのは通る層が違うため（コア直呼び vs MCP封筒）。QA が「全部緑のまま壊れていた経路」を2度実測しており、
  この重複はその防御。重複整理で消さないこと。
- **622→422件（-32%）・180.6秒→15.8秒**（2026-08-22）。「半分以下」の数値目標は取り下げた ——
  規律の高いスイートで1本ずつ判定しても証明できる冗長は1%台しか出ず、半減には検出力のある層を丸ごと捨てるしかない。
  大きく効いたのは判定ではなく**依存の切断**（私物 STEP 依存 151件の削除だけで -24%）。
  実物モデルで踏む OCCT の癖（円柱が穴とは限らない等）を合成の直方体では踏めないので、この層の検出力は失っている。
- **kernel 時間の回帰を機械で見る手段は現在無い**（性能テストは私物 STEP 依存として削除済み）。
  必要なら合成形状で測り直すところから。環境依存で揺れる閾値テストは、閾値をいじるより「揺れることを失敗の現場に書く」。
