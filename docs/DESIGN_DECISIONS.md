# duocad — 設計判断と実測（コア・全体）

**読むとき**: verb・データモデル・保存形式・テスト方針・プロジェクトの方向を変えるとき。
「なぜこの形か」の根拠がここにある。**いまの挙動の正はコードとテスト**（契約は各モジュールの docstring にある）。
画面まわりは [UI.md](UI.md) / [VIEWPORT.md](VIEWPORT.md)、AI統合は [AI_INTEGRATION.md](AI_INTEGRATION.md)、
形状最適化は `TOPOPT*.md`。

## 技術選定の根拠（[INITIAL_PLAN.md](INITIAL_PLAN.md) §4 の補足）

- **Svelte 5 を選び React を撤回した根拠は自分たちのアーキテクチャ側にある。** 状態を全部コアに置いた
  ので、frontend に残る状態はコマンドの途中状態だけで画面部品も10個前後。フレームワークが元を取るのは
  クライアント状態管理であり、その理由を設計時点で消していた。決め手は技術的優劣ではなく「2年後に自分が
  読み返して分かるか」（10年使う道具）。
- **依存の危険度の順位**（churn を心配する順）: ① three.js（semver を持たず r 番号で毎月リリース・
  非推奨APIを定期削除）② 言語バインディング（OCP。維持者が少ない）③ 小規模ライブラリ ④ フレームワーク。
  フレームワークは最下位 —— Svelte コアの大きな書き換えは約5年間隔（3→4→5）で、年1回壊すのは SvelteKit 側。
- **ローカル専用ツールは上げなければ壊れない。** 実コストは「壊れる」ではなく**イディオムのずれ**
  （次の大きな版が出た後にAIが書く「今風の書き方」が手元と噛み合わず、AI支援の質が落ちる）。対処は
  「書き換えが1日で済む規模に surface を保つ」（部品10個以下）。churn の激しい依存は狭いインタフェースに
  閉じ、バージョンは固定する（`pyproject.toml`・`package.json`）。

## 既成CADへ転換する場合の候補（再検討材料）

方針は「自作（Pythonコア＋ブラウザ）」で決定済みだが、将来転換する可能性は低くない。評価軸は
**直接操作の質 × Linuxネイティブ × 軽さ**であって機能の多さではない。**UIの様式そのものが足切り条件**
（FreeCAD はクラシカルすぎて却下済み。再提案しない）。候補を出すときは機能表ではなく画面の見た目を先に確かめる。

| 候補 | 要点 |
|---|---|
| SolveSpace | 拘束ベース・数MB。機械部品と治具だけなら最小。機能の少なさが天井 |
| Plasticity | 履歴なしダイレクトモデリング・Parasolid。Ubuntuネイティブ・買い切り。パラメトリック作り直し不可 |
| Blender + CAD Sketcher / Geometry Nodes | 拘束2Dスケッチ＋非破壊。パネル全消しで3Dビューだけにできる |
| Onshape | UIは最上位だが無料版はデータ全公開・クラウド束縛（離脱理由の再来） |
| Antimony / libfive Studio | 3Dビューのドラッグでスクリプトの数値が書き換わる双方向。採用候補というより設計の参考 |

## verb の粒度（INITIAL_PLAN §2 の補足）

- **避ける切り方**: 細かすぎ（UIの1ステップ＝1verb）は、AIがモーダルな状態機械を人の真似で駆動する羽目になり
  ログは再生不能・undo粒度も壊れる —— **MCPをUI手順の写しにするのが最もありがちで最も致命的**。
  粗すぎ（「ブラケットを作って」＝1verb）は途中結果を指せず、交互操作の割り込み点が消える。
- **verb に課す2つの制約**: (1) 純関数 `f(document, selection, params) -> new_document`（undo もプレビューも
  無料になる）(2) 既存の選択を先に消費する（AI→人の受け渡しがこれで成立する）。
- **モード（通常/スケッチ/形状最適化）は verb の上位次元**で、コアにもMCPにも持ち込まない（`Document` に
  フラグを置かない・`enter_sketch` のような verb を作らない・ツール集合をモードで変えない）。モード遷移は
  undo1回/ログ1行/MCP1呼び出しのどれとも一致しないので verb ではない。
- **起動時にしかできない操作を作らない。** 起動オプション `--step` を消せなかった理由は「アプリ内 import が
  半分しかやらない」ことだったので、オプションを消すには機能の非対称を先に消すしかなかった。起動オプション
  の数はこの手の非対称の指標になる。
- **削除 verb のキー割当（Delete/Backspace）は付けていない**（本人判断）。他の verb にキー割当が無い中で
  delete だけが持つのは一貫性を欠くため、**全 verb が揃ってからまとめて決める**。
- **ソリッドブーリアン**（演算の意味は `kernel.boolean_bodies` の docstring が正）: 選択UIは「ターゲットを
  1つピック（`PickArgSpec`）→ツールを複数確定選択」で、役割の違う2つの選択グループを持つ初めての verb。
  確定前にツール構成を変えるたびライブ再計算する。

## 押し出しの統一（2026-09-26）

本人の発言:

> verbを統一し「押し出す」だけにする。スケッチ中ならスケッチの閉領域を選び通常モードならソリッドの面を選ぶ。またソリッドの面を選ぶ場合同一平面上ならいくらでも面を取れるようにしたい。面を選んだときにも join/cut/new を出す。内部でのverbを2つ残すか1つに統一するかは任せる

- 内部の verb は `extrude` 1本にまとめる（AIが提案し、本人が任せた）。ログの args は領域なら `regions`、
  面なら `faces`（`{"body","index"}` の並び）で、再生はキーで分ける。`extrude_face` は再生専用として残した(下記)。
- 別のボディにまたがる面は許さず、同一ボディに限る（AIが推奨し、本人が選んだ）。
- 通常モードで領域を押し出す手順が消えることは受け入れる（AIが確認し、本人が「消えてよい」と答えた）。
  MCP は選択の種類で判別するので、今後も領域を押し出せる。
- 実装の決め: 距離の正は面の外向き法線側（面から削る cut は負の距離）。面のときの行き先の既定はその面を
  持つボディ。領域と面が混ざった選択は ValueError。領域の押し出し（`extrude_regions`）は保存済み文書の
  面番号・辺番号を動かさないため変えていない。
- Web UI(3/4): ツールバーの「押し出す」は1つ(`#extrude`)。id は `extrude` のまま、スケッチモードの一覧には
  領域版・通常モードの一覧には面版が入る(`commands/features.ts` の `makeExtrude`)。どちらも距離の入力欄は
  `#distance`、種別は `#extrude-mode-join/cut/new`。旧「押し出す」(`extrude_face`)と「領域を押し出す」の
  ボタンは消えた。通常モードでは領域を要求するコマンドが無いので、3Dで領域を指す道(`wantsRegions`)は
  通常モードでは使われない。
- `extrude_face`(4/4): 公開面(カタログ・Session・MCP・WebSocket)から外し、`register_verb` の登録だけを
  古い保存ログの再生用に残した。リポジトリの外に保存された文書に `extrude_face` の操作が入っているかは確かめようがなく、
  消すと読み込めなくなるため。中身は1面の `extrude`(正の距離は join、負は cut)と同じ処理で、体積・面数は
  従来の実装と一致する(`tests/test_extrude_face_replay.py` が従来の実装で作ったログを固定)。
  ただし新しい操作は `extrude` で記録され、再生した `extrude_face` の `provenance` は保存時のまま(キーが `extrude` と別形)。

## 図形（スケッチ）の表現

- **拘束ソルバは持たない**（`duocad/parameters.py`）。ただし「書かなくてよい」の根拠は実測済み:
  `python-solvespace` 3.0.8 で雑に置いた4点の矩形に horizontal×2 / vertical×2 / distance×2 を与えて約20行で
  厳密収束し、寸法を変えて再解決もできた。**ライセンスは GPLv3+**（配布・販売時に効く。代替の FreeCAD
  `planegcs` も GPL系）。**`dof()` の値は手計算と合わなかった**（完全定義で0のはずが6）ので、「完全定義
  （青→黒）」表示を作るなら要調査。統合は未着手で、Entity は座標を直接パラメータに持つ —— だから
  `move_sketch_entities` が座標を直接書いてもソルバと衝突しない。
- **長方形は1つの図形のまま据え置く**（4本の線分＋拘束にしない。本人判断）。辺単位で触りたくなったら
  **分解 verb を足す**（`_rotate_rectangle` 系の分解コードが既にあるので実装は小さい）。`angle` を持たせた
  のは機能追加ではなく「欠けている数値を埋める」もの（拘束が無いから Fusion を真似る理由が無い）。
- **図形の `params` にキーを足すとき**（`angle` で全部踏んだ）: 旧ログから再生した個体はそのキーを持たない
  まま残る。**再生時に既定値で埋めてはいけない** —— `register_value` は空いている最小の `d<n>` を振るので、
  以後の名前が全部ずれて古い `set_parameter` が別の値を指す（`keyboard_36_case.json` は `d1`〜`d152`）。
  読む側が `get` で受けるしかなく、次の3箇所が例外もログも出さずに壊れる: (1) 書き戻し（`KeyError`。図形が
  まだ持たないキーは書き戻す側で `register_value` する）(2) 辞書の等値比較（キー数が違うだけで常に不一致。
  元が持つキーだけで比べる）(3) 「新規パラメータは N 個」を固定した実機検査（`smoke-optimize-mode.mjs`。
  語では検索できない）。旧データを再生した状態からの検査を1本ずつ足すこと。
- **スケッチと押し出し済みソリッドは連動しない**（本人が許容）。`move_sketch_entities` や `set_parameter`
  でスケッチを変えても対応ソリッドは追従しない（パラメトリック履歴ツリーは無い）。**寸法（半径・幅高さ・
  角度）を人が打ち直す口も作っていない** —— 作るなら「押し出し済みソリッドの再計算をどうするか」を先に決める。
- **回転の既定中心（重心の軸への直交射影）が意味を持つのは「向きだけ指定」の経路だけ**。3Dの回転は軸線上の
  どの点を基準にしても同じ変換なので、軸の位置が決まっている（辺で指す・点＋向き）なら恒等。
- **領域を包む verb `envelope_regions`**（本人と合意、2026-09-26）: 結果 = D(d)( D(−R)( D(R)(選択領域の和集合) ) )
  （D(r) は半径 r の円とのミンコフスキー和）。**R（追従半径）と d（オフセット）の両方を UI に出し、初期値は空白で
  空白は 0 mm**。R = d = 0 なら和集合そのもの。**正確な方式**（OCCT の2Dオフセット＋面の結合。出力は線分と円弧
  だけ）で、ポリライン近似は使わない（押し出し後のフィレット・面選択・STEP 出力が壊れるため）。**結果が単一の領域
  でなければ確定をはじいてトースト**（`<n> 個に分かれます。R か d を大きくしてください`。トーストは確定時だけ）。
  **必要な R・d の最小値は計算しない**（本人が案 B を選択）。
  **本人未確認の既定**: (1) 内側に穴を持つ1枚は単一領域として通す (2) 結果は選択領域と**同じスケッチ**に追加し
  元の領域の線は残す。選択が複数スケッチにまたがるとはじく。
  **確定前の幽霊を出す**（本人の依頼、2026-09-26）。投機実行ではなく、文書を変えずに結果の線だけを計算する
  `Session.preview_envelope_regions`（`catalog.Command.preview_session`）で出す。投機実行は verb が失敗すると
  何も返せないので、分裂した形を見せられない。分裂している間は幽霊を警告色で描き、トーストは出さない。

## 保存・文書

- **保存済みモデルは捨ててよい。移行スクリプトは書かない**（本人判断）。verb を消して開けなくなったら、
  元の STEP（`C:\Users\tm976\mf\3d-models`）から作り直す。保存形式や verb 集合を壊す変更を検討するとき、
  既存モデルの移行コストを制約に数えなくてよい。
- **保存先を `models/` に固定した理由**: 引数がパス1つだと相対パスがサーバの CWD 基準になり、「その日
  どこで起動したか」で保存先が変わって実際に保存されたファイルが1つも無かった。ブラウザのネイティブ
  ファイルダイアログ（File System Access API）は使わない —— 書いているのはサーバ側の Python なので、
  ブラウザがファイルハンドルを持っても噛み合わない。
- **STEP をログへ生テキストで埋め込んだ実測**: 4.6MB の STEP（27ソリッド）で `model.json` 4.83MB
  （+4%。ASCII なので増えるのは改行と引用符のエスケープだけ。base64 なら +33%）、保存 0.02秒、開く
  1.5〜1.6秒（ほぼ OCCT のパース。埋め込み無しの import 1.49秒と同じ）。一覧は 4.8MB 1件あたり約30ms。
  この数値で、保留していた形状キャッシュ（サイドカー BREP）と zip コンテナ化は**どちらも不要**と決着。
  **「1モデル＝1ファイル」「git で差分が読める」「自己完結」は3つ同時に満たせない** —— 保存形式を決めた
  時点で外部 STEP の取り込みが視野に無く、埋め込みで表に出た衝突。
- **ログへ埋め込むと配信も太る。** `state_meta()` はログのエントリを `args` ごと配るので、埋め込み直後は
  1操作あたり 4.83MB が WebSocket に流れていた。配信用の射影で伏せて 10.5KB（`duocad/view.py`）。埋め込みを
  足したら `json.dumps(配信ペイロード)` の長さを実測すること —— テストは通る。
- **複数プロジェクトは「閉じて開く」で切り替える**（本人判断）。別プロセス（`--port` を変えるだけで独立
  プロジェクトになる。コード変更ゼロ）・複数文書対応・アプリ内タブは当面採らない。同じ URL を2タブ開いても
  同じ文書が映るだけ（broadcast は交互操作の核なので消さない）。

## STL書き出しの粗さ

**線形偏差 0.01mm 固定**（`duocad/io_step.py` の `STL_DEVIATION`）。**粗さを選ぶ入力は画面にもプロトコルにも
MCPにも無い**（人ができることとAIができることを一致させる方針なので、人の画面から欄を消す以上AIの引数も
消す）。**角度偏差は `kernel.DEFAULT_ANGULAR_DEFLECTION`（0.35rad）のまま**。

実測1（`models/hanger_test.json` = B-rep 11ボディ。書き出し時間は `.venv` のPython・Windows）:

| 線形偏差 | 三角形 | STL | 書き出し |
|---|---:|---:|---:|
| 0.2mm（変更前の既定） | 13,496 | 0.67MB | 0.10s |
| 0.05mm | 20,412 | 1.02MB | 0.13s |
| 0.02mm | 33,668 | 1.68MB | 0.20s |
| **0.01mm** | **52,358** | **2.62MB** | **0.32s** |
| 0.005mm | 80,900 | 4.05MB | 0.49s |
| 0.002mm | 185,212 | 9.26MB | 1.19s |

実測2（円筒を半径ごとに測った弦のずれ。角度偏差0.35rad固定、セルは「円周の分割数 / 実測sagitta[mm]」）:

| 半径 | 0.2mm | 0.05mm | 0.02mm | 0.01mm |
|---|---|---|---|---|
| 1.6mm（φ3.2の穴） | 36 / 0.0061 | 36 / 0.0061 | 36 / 0.0061 | 40 / 0.0049 |
| 5mm | 36 / 0.0190 | 36 / 0.0190 | 50 / 0.0099 | 71 / 0.0049 |
| 12.5mm | 36 / 0.0476 | 50 / 0.0247 | 79 / 0.0099 | 112 / 0.0049 |
| 50mm | 50 / 0.0987 | 100 / 0.0247 | 158 / 0.0099 | 223 / 0.0050 |

**0.01mm にした理由**: OCCTは指定値のおよそ半分に収めるので実際の誤差は0.005mmで、しかも**半径によらず**
その値になる。出力は3Dプリント直行が前提（[TOPOPT.md](TOPOPT.md)）で、FDMの位置決め精度0.1mm前後に対して
2桁の余裕がある。0.2mmのままだとφ100の円筒で0.1mm痩せて印刷誤差と同じ桁になり、0.005mm以下は容量と時間が
倍々に増えるだけで印刷結果は変わらない。**三角形は内接する**ので、穴は常にsagittaのぶん小さく出る。

**角度偏差を下げない理由**: OCCTの分割数は `4π/角度偏差`（0.35radで1周36分割）で、角度偏差は**分割数の
下限**としてだけ効く。その下限でのsagittaは `0.0038×r` なので、線形0.01mmとの支配の境目は半径1.5mm付近
（上表のr=1.6で既に40分割＝線形側が支配）。固定後に角度偏差が形を決めるのは半径1.5mm以下の穴・フィレット
だけで、そこでの誤差は0.006mm以下に収まる。画面用の `resolution.angular_for_deviation`（sqrt則）を書き出し
へ流用すると0.01mm→0.078radになり、φ1のピン穴にも160分割を配ることになるので使わない。

**大きな文書は重い**: 目標偏差0.010mmは外接対角600mmのPCケース（27部品）で1,180,763三角形・14.5秒
（[VIEWPORT.md](VIEWPORT.md)「可変解像度と面カリング」の実測）＝ 約59MBのSTLになる。書き出しは表示中の
ボディだけを書くので、**印刷する部品だけ表示して書き出す**のが前提である。

**トポロジー最適化の成果物には効かない**: 最終形は `topopt/finalize.py` の `solid_mesh` が偏差0.2mmで
三角形にしてメッシュボディとして文書へ入るので、STL書き出しはその三角形を素通しする。最適化した部品の
印刷品質を決めているのは書き出し側ではなく finalize 側である（[TOPOPT_ACCEPTANCE.md](TOPOPT_ACCEPTANCE.md)）。

## 隠したボディ・選択・可視性

- **非表示のボディは fillet / chamfer / extrude の対象にもできない**（現状維持。本人承認）。「可視性は
  見た目の設定ではなく、何を指せるかの定義」の延長。手数が1つ増えるだけで理由がエラーで出る —— 従来は
  黙って変わっていた。**先に緩めない**（煩わしければ `join` モードだけ後から緩める余地がある）。
- **形状変更後の選択全リセット**の代替案「失効した参照と後継を返す契約」は先取りしない。連続性が本当に
  要る verb が現れてから作る。移動系 verb を例外にする案は本人が却下した（全 verb 統一）。
- **メッシュボディへの「通す / 断る / 黙って外す」の線は「呼び出し側が何を主張したか」で決める**
  （README §4）。実装は `App.svelte` の `pickedRef` がメッシュをボディ参照へ畳む1本で、ツールバーを選択に
  応じて出し分ける案は採らなかった（コマンド一覧はモードの持ち物で、選択のたびに作り直すと集めかけの
  引数が落ちる）。

## テスト方針

- **削減の基準（本人）**: 存在確認と一目瞭然のロジックは検査しない。複雑なロジックは検査する。形が
  存在確認でも残すのは、事故を検出する別チャネルを持つもの（走査テストの自衛ガード・2つの独立ソース間の
  同期検査・宣言表の記述完備リント・層規律ガード・セキュリティ衛生）。
- **層をまたぐ二重検査は意図して残す**: `tests/test_mcp_verbs.py` が体積・undo を `test_fillet.py` と重ねて
  見るのは通る層が違うため（コア直呼び vs MCP封筒）。QA が「全部緑のまま壊れていた経路」を2度実測しており、
  この重複はその防御。重複整理で消さないこと。
- **622→422件（-32%）・180.6秒→15.8秒**。「半分以下」の数値目標は取り下げた —— 規律の高いスイートで
  1本ずつ判定しても証明できる冗長は1%台しか出ず、半減には検出力のある層を丸ごと捨てるしかない。大きく
  効いたのは判定ではなく**依存の切断**（私物 STEP 依存 151件の削除だけで -24%）。実物モデルで踏む OCCT の
  癖（円柱が穴とは限らない等）を合成の直方体では踏めないので、この層の検出力は失っている。
- **2回目（2026-09-24）: 1466→1331件・114秒→63秒**（同じマシンで順に計測。作業前は私物モデル依存などで3件が
  常に赤）。物差しは1本ずつの判定ではなく、**変異で空振りを実証すること**と **git の同時編集回数**。効いたのは
  (1) 宣言をテストへ書き写した表をやめて実物と照合する（MCP の引数は `inspect.signature`、Enter 要否は Node で
  本物の `needsEnter` を評価。`ARGUMENTS` は21回・`ENTER_REQUIRED` は17回の同時編集を払いながら、TS の判定を
  壊しても緑だった）、(2) 経路の差が分岐1つの重い照合・同じ決定的呼び出しの2ファイル重複、(3) 変異で緑だった
  検査を名前どおりの性質を見る形に直す（約15本）。
- **kernel 時間の回帰を機械で見る手段は現在無い**（性能テストは私物 STEP 依存として削除済み）。必要なら
  合成形状で測り直すところから。環境依存で揺れる閾値テストは、閾値をいじるより「揺れることを失敗の現場に
  書く」。
