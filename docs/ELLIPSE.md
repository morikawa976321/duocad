# 楕円 verb の設計

**状態: 設計だけ。未実装**（2026-10-17）。実装に入るときと、楕円・円の入力の数え方を疑うときに読む。

本人の依頼（原文）:

> スケッチ用の楕円verbを作成する。円の入力が縦横2つになったバージョンというイメージ。

## 決めたこと（2026-10-17 本人）

| 論点 | 決定 |
|---|---|
| 入力の数え方 | **縦横の直径で入れる。円も直径の入力に変える**（本人: 「そういえばFusionもそうだったし」） |
| 回転角 | **`angle` を持つ。既定 0**。度・反時計回り・スケッチの X 軸基準（長方形の `angle` と同じ数え方） |
| 縦と横が等しい楕円 | **許す**（真円になるだけ） |
| 画面の入力 | **3クリック**: 中心 → 1本目の軸の端 → 2本目の軸の長さ。数値欄は 縦・横・角度 |
| 楕円弧 | **作らない** |
| SVG 取り込み | **閉じた `<ellipse>` だけ新しい楕円図形にする**。楕円弧は今のベジエ近似のまま（[svg_import.py](../duocad/svg_import.py) 冒頭） |
| 選択・測定で見せるもの | **中心・縦・横・角度・周長** |

「縦横」は `angle` 方向の軸と、それに直交する軸を指す。どちらが長いかの意味は持たせない（長軸・短軸ではない）。

## カーネルの罠

**OCCT の `gp_Elips` は長半径 ≥ 短半径でないと作れない**（2026-10-17 実測: `(10,5)` と `(5,5)` は通り、`(5,10)` は `Standard_ConstructionError`）。
縦の方が長い楕円は、辺にするところ（`kernel_sketch.py`）で2つを入れ替え、軸を 90° 回して渡す。

## 周長

楕円の周長に閉じた式は無い。測定では OCCT に辺の長さを測らせる（近似式を自前で持たない）。
