# 面の削除(#190)と面のオフセット(#183)— 方式の決定

**状態: 方式の決定と受入条件のテスト化まで。未実装**(2026-10-18)。実装に入るとき、面編集の結果を疑うとき、
OCCT の Defeaturing・MakeOffset の挙動を疑うときに読む。試作と実測の再現は `tools/face_edit_probe/`(末尾「再現」)。

本人の依頼(Issue #190、2026-10-17):

> 欲しいのはより強力な削除機能。フィレットや面取りを削除したりしたい

Issue #183 は「面を法線方向へ動かし、隣の面を自分の面のまま伸縮させる」(本人の意向: 欲しい、2026-10-17)。#183 の本文は
「フィレットを含む形の寸法直しで、面を動かしても丸めが付いてくることを期待する」と書いている。

対象の範囲(本人、2026-10-19。実物の有機的な部品で面の削除が遅く大半が失敗した、という報告への返事):

> 形状最適化関連の有機形状に使うことはないのでそれは考えなくていい

AI はこれを受けて、有機的な部品での低い成功率と長い計算時間(下「実物の STEP」)を、方式を決める材料から外す。実測は記録として残す。

## 結論

- **verb を2つ足す。** `delete_faces`(面の削除)は OCCT の **`BOPAlgo_RemoveFeatures`**(`BRepAlgoAPI_Defeaturing` の中身)、
  `offset_faces`(面のオフセット)は **`BRepOffset_MakeOffset` を全体0・選んだ面だけ距離 d**(Intersection=False)で作る。
  動かす面に接線でつながる一定半径の丸めがあるときは、**丸めを外して(削除と同じ仕組み)、尖った形で面を動かし、同じ半径で丸め直す**(丸めが付いてくる)。
- **OCCT の成功を信じない。** Defeaturing は閉じられない面を警告だけで残し、MakeOffset は接線でつながる面ごとずらした形や面積0の面を残した形を
  有効な形として返す(どれも `BRepCheck` を通る)。**結果は面ごとに対応元と照らし合わせる関門**(下「関門」)を通ったときだけ成功にする。
- **計算は常駐の子プロセスで行う。** `BOPAlgo_RemoveFeatures` は計算中ずっと GIL を握り(3 秒の計算で主スレッドが 3 秒止まった。穴 49 個を一度に消すと 3.5 秒)、
  角ばった実物でも MakeOffset がプロセスごと落ちた例が 1 件あった(fan_120mm_stand)。同じプロセスで計算すると、その間サーバ全体(画面・MCP)が止まる・落ちる。
- 自前の組み直し(C)は採らない: 合成形状で期待と違う形を2件、段の削除2件で上の段ごと消した形を検査を通して返し、実物ではプロセスごと落ちる(丸めの削除 201 件中 156 件)。
- **形状最適化関連の有機形状は対象外**(本人)。角ばった実物では、丸めの削除・穴の削除はほとんど通り、平面の移動は部品によって断る率が高い
  (下「実物の STEP」)。断ったときは例外にして形もログも変えない。
- 共通の仕組みは kernel 層の `duocad/kernel_face_edit.py`(面の解決・構造の検査・曲面の定義の比較・由来の射影)と、
  子プロセスの口 `duocad/kernel_worker.py`。削除とオフセットで意味の検査は別関数にする。
- 本人判断カードは5枚(下)。どれも実装の順番を止めないが、a(「削除」の意味)と d(押し出しとの統合)は画面の配線を決める。

## 何を作るか

| | 判断 | 理由 |
|---|---|---|
| `delete_faces`(#190) | **作る** | 同一ボディの面を1枚以上消し、隣の面を自分の曲面のまま延ばして閉じ直す。履歴を持たない STEP のボディにも効く |
| `offset_faces`(#183) | **作る** | 同一ボディの面を1枚以上、外向き法線へ距離 d だけ動かす(正で太る)。隣の面は自分の曲面のまま伸縮し、接線でつながる丸めは付いてくる |
| 面の平行移動(任意の向き)・指定面まで | 今回は作らない(カード c) | MakeOffset は法線方向の距離しか持たない |
| 丸めの半径を変える | 作らない | 依頼に無い。丸めを消して(`delete_faces`)丸め直す(`fillet`)で済む |

verb の形は `shell_body`(`duocad/verbs/shell_body.py`)にそろえる: 面は選択から取り(`selection.require_faces`、選択順・1ボディ限定)、
ログの args は `{"faces": [添字…], "body_id": …}`(オフセットは `"distance"` を足す)、undo は `_common.SNAPSHOTS` へ前の形を退避する。
**引数で面を受けない**(target set を引数にしない契約。`tests/test_mcp_verbs.py`)。

## 比べた方式

| 記号 | 方式 | 対象 |
|---|---|---|
| **A** | `BOPAlgo_RemoveFeatures`。消す面を渡すと、隣の面を延ばして交わらせ、閉じ直した形と履歴(`History()`)を返す | 削除 |
| **B** | `BRepOffset_MakeOffset` を全体 0・選んだ面だけ `SetOffsetOnFace(d)` で(Skin、Join=Intersection)。B0 は Intersection=False、B1 は True | 移動 |
| **C** | 自前: 選んだ面を外し(移動ならずらした曲面の大きな面を足し)、隣の面を自分の曲面のまま大きく延ばし、`BOPAlgo_MakerVolume` で空間を区画に分けて内側の区画を残す | 両方 |
| **D** | 合成: 動かす面に接線(G1)でつながる丸めを A で外し、尖った形で B で動かし、同じ半径で丸め直す | 移動 |

S を付けたもの(SA・SB・SD)は同じ方式に**厳しい版の関門**(`strict.py`、astra の1回目の指摘を反映)を通したもの。緩い版の関門は `worker.py` の `gate`。

試作しなかったもの: `BRepOffsetAPI_MakeOffsetShape`(B と同じ `BRepOffset_MakeOffset` を包むだけで、面ごとの距離を渡す口が無い)、
`BRepOffset_MakeSimpleOffset`(全面を一様にずらすだけで、隣を交わらせて作り直さない)、`BRepFeat_MakeDPrism` / `LocOpe`(1つの抜き勾配で柱を足し引きする
局所操作。斜めの隣の面ごとに違う延び方を作れず、円筒面の径変更も扱えない。いまの `extrude_faces` の限界と同じ)。

読み取れること:

- A は期待のある全ケースで一致し、閉じない・曖昧な形(段の踏み面・蹴上げ)は断る。C は段の削除で**上の段ごと消した形(12000 mm³)を通す**。
- 連なり4辺のうち1枚だけ消す(`d_fillet_top4_one`)と、残りの丸めが新しい角まで延びた有効な形になる(A・C とも 23668.9 mm³)。意図と異なる場合がある(カード b)。
- 全辺丸めの縦の4枚だけ消す(角の球を残す)は A が断る。球の角は縦の丸めを延ばしても閉じない。
- B は平面・円筒・斜面・面取りの隣・2面同時・STEP 経由で一致。**丸めの隣の面では、接線でつながる面(丸めとその先の面)まで同じ距離ずらした形を返す**
  (上面 +3 で 29810.6 mm³ = 上面・丸め・前面を一緒に +3)。関門で断る。
- D は丸めの隣のケース(半径の違う2つの丸めに挟まれた面を含む)をすべて一致させる(丸めが付いてくる)。C で動かす D(DC)も丸めのケースは一致するが、
  端を越える蹴上げで C と同じ誤った形を通すので表から外した。
- B0 と B1 の判定は同じ(段の踏み面が消えるとき B0 は面積0の面を残し、B1 は面の数を変える。どちらも関門で断る)。

A は一度に消す特徴の数に対して急に遅くなる(1個なら形の大きさに比例する程度)。逐次に消しても合計は大きく変わらない見込みで
(1個 221 ms × 100)、閉じ方・履歴・順序が変わりうるので性能の手当てとして入れない(astra の指摘)。

### 由来と再生の決定性(`provenance.py`・`isolation.py`)

- A の由来は `History()` で完全(消した面は `IsRemoved`、残る面はすべて結果に見つかり、新しい面は0)。
- **B の由来は `Modified` ではなく `Generated` に1対1で入る**(動かさない面も作り直され、`Modified` は全面で空)。
- D の由来: 残る面は「A の `History()` → B の `Generated` → フィレットの `Modified`」の3段を合成する。**旧い丸めは `deleted`、作り直した丸めは
  `new_faces`**(旧い丸めと新しい丸めを対応させる根拠を持たない。astra の指摘)。作り直した丸めは辺の `Generated` に加えて**頂点の `Generated`** にも出る(角の球)。
- 結果の面の並び(種類・重心・面積)は、別プロセス2回・形の複製(`BRepBuilderAPI_Copy`)・並列実行(`SetRunParallel(True)`)のいずれでも一致した(A・B0・D)。
- **BinTools(バイナリ BRep)の往復は厳密**(重心のずれ 0、往復前後で同じ演算の結果もビット一致)。テキスト BRep は面の並びは保つが重心が 7e-15 ずれる。
  費用は書き出し 1〜2 ms、読み込み 7〜56 ms(26〜206 面)。子プロセスの起動と OCP の読み込みは 1.6 秒。

## OCCT の罠(このリポジトリで実測)

1. **`BRepAlgoAPI_Defeaturing` / `BOPAlgo_RemoveFeatures` は、閉じられない面を例外にも `IsDone()=false` にもしない。** 警告
   `BOPAlgo_AlertUnableToRemoveTheFeature` を出して、元の形(または消せた分だけ消した形)を返す。OCP の `BRepAlgoAPI_Defeaturing` は警告の問い合わせ口
   (`HasWarnings` / `GetReport`)を出していないので、`BOPAlgo_RemoveFeatures` を直接使う。**警告を失敗として扱い、さらに選んだ面がすべて `IsRemoved` か見る**(二重の守り。
   片方だけ外しても受入テストは落ちない —— 両方外すと落ちる)。
2. **`BOPAlgo_RemoveFeatures.Perform` は計算中ずっと GIL を握る。** 別スレッドで 3.04 秒回すと、主スレッドは 3.09 秒止まった(0.01 秒ごとに起きるはずが0回)。
   docs/PERFORMANCE.md の実測(950 ms のフィレット中も主スレッドは最大 43 ms 間隔で動けた)とは違い、呼び出しによる。
3. **`BRepOffset_MakeOffset` は接線(G1)でつながる面を1組として同じ距離ずらす。** 選んでいない丸め・その先の面も動く。丸めだらけの実物では
   平面1枚を動かすとほぼ全面(60 面中 58 面)がずれる。選んでいない面が対応元の曲面のままか、面ごとに見ないと気づかない。
4. **`BRepOffset_MakeOffset` は穴や丸めを含む形で SOLID でなく SHELL を返す。** 閉じたシェル1枚を `BRepBuilderAPI_MakeSolid` で包み `BRepLib.OrientClosedSolid` で向きをそろえる。
5. **`BRepOffset_MakeOffset` は、隣の面の幅が0になる移動で、面積0の面を位相に残したまま `BRepCheck` を通る形を返す**(段の蹴上げを端まで動かす。Intersection=False)。
6. **`BRepOffset_MakeOffset` の由来は `Generated` にある**(上「由来」)。`Intersection=True`(B1)は OCCT 7.9.3 の公式説明で未完成とされるので既定にしない(astra の指摘)。B0 が断ったときに B1 で取り直す案は下「推奨する方式」の候補。
7. **履歴の像は、結果のシェルの中での向きを持たないことがある。** 像の面の法線でずらす向きを決めると逆へ動く(D で前面が内へ動いた)。結果の形を走査して同じ面(`IsSame`)の出現を取り直す。
8. **OCP の `Message_ProgressIndicator` は Python から継承できない**(`No constructor defined`)。進捗通知の `UserBreak` で長い計算を止める手は使えない。
9. **BinTools の往復は厳密、テキスト BRep は 1e-14 ずれる**(上「由来」)。プロセス間の受け渡しは BinTools にする。
10. **面の削除で、残した面の反対側がつぶれた形が、警告もなく返る。** フィレット1辺の箱で下面と奥の面を消すと、丸めの外側の隙間だけを閉じた破片
    (23785 → 214.6 mm³)になる。残した面は自分の曲面のまま、BRepCheck も通り、ここまでの関門を全部通った(2026-10-19、`viz.py` で全組み合わせを計算して発見)。
    面取りの箱・段でも同じ型が出る。残した面の元の範囲が結果の表面に残るかを見て断る(下「関門」)。

## 推奨する方式

### kernel(`duocad/kernel_face_edit.py`。試作は `tools/face_edit_probe/strict.py`)

`kernel.py` は 1,681 行で規律の 1,500 行を越えているので、新しいファイルに切る(依存は kernel_face_edit → kernel の一方向。`kernel_shell.py` と同じ形)。

- `delete_faces(shape, face_indices) -> {"shape", "provenance", "volume_before", "volume_after"}`
  1. `BOPAlgo_RemoveFeatures`(`SetToFillHistory(True)`、`SetRunParallel(False)`)。エラーも**警告も**失敗。
  2. 関門(下)。由来は `History()` を `_blend_provenance` と同じ形で射影する(`face_map` / `deleted`(=選んだ面) / `new_faces`(=空))。
- `offset_faces(shape, face_indices, distance) -> {...}`
  1. 選んだ面から接線でたどり、**構造で認識できる丸め**(下「D」)を集める。丸めでない接線の隣があれば断る。
  2. 丸めが無ければ B0、あれば D。どちらも関門を通す。
- 失敗はすべて `ValueError`。断り文は原因(閉じない/接線でつながる面が丸めでない/面が消える/期限切れ…)を名指しする(`shell_body` と同じ方針)。

### 関門(どの結果にも通す。成功として通してよいかの判定)

構造(削除・移動の共通):
- 結果全体がちょうど1ソリッドで、ソリッドの外に面・辺が無い。`BRepCheck` 合格、自由辺0、体積 > 0。
- 面積が `MIN_FACE_AREA` 未満の面が無い(試作は 1e-6 mm²。**置いた値**で、退化直前の細長い面は拾えず、既存の正当な微小面を断りうる。実装で長さ・面積の許容差を分けて校正する)。

削除の意味:
- 選んだ面がすべて `History().IsRemoved`。残る面はすべて結果に像があり、**解析曲面(平面・円筒・円錐・球・トーラス)は像の曲面の定義が元と同じ**。
  結果の面はすべて残る面の像(新しい面は無い)。B-spline の隣は延ばすと曲面そのものが作り直されるので、定義の比較から外す(意味の検証ができていない範囲として明示する)。
- **残した面の元の範囲は、結果の表面に残る**(延びるだけで削られない)。元の面の内側から面全体に散らした点(最大49点)が、どれかの像の面の上にあることを見る。
  これが無いと、残した面の反対側がつぶれた破片を通す(罠の10)。点を格子の先頭から取ると UV の片側に寄り、段で面の上半分が消えたのを見逃した。
  円筒などの周期面では、射影した角度が面の範囲から一周ずれて返ることがあるので、面の UV の範囲へ寄せる(寄せないと実物の STEP の正しい削除を断った)。
  **限界**(astra の3回目の指摘): 確かめているのは標本の最大49点で、面全体が残ることの証明ではない。標本点の間だけが欠ける細い領域・境界の近くの欠け・
  標本を置けない小さな領域は見逃しうる。逆に、細い帯状の面や細かく切り抜かれた面では内側の点を拾えず断りうる。また、残した面を正当に削る閉じ方
  (共有する側面の上部を切り詰めて段を消す、など)は、利用者の意図として正しくても「延びるだけ」の契約に入らないので断る。**初版の面の削除は、
  残した面の元の範囲を保つ削除に限る**。

移動の意味:
- 旧面 → 新面が `Generated` で**1対1に全部を覆う**(面の数が同じでも、別の面が消えて別の面ができる形を通さない)。
- 各新面が対応元の曲面(選んだ面なら解析的にずらした定義: 平面は法線方向へ平行移動、円筒・球・トーラスは半径を ±d。凸か穴かは外向き法線と軸の向きで決める)と**定義が一致**。
  **解析曲面は定義の照合、自由曲面は内部の最大9点の射影という限られた確認**(曲面の同一性の証明ではない)。選んだ自由曲面は比べられないので断る。
- 体積の増減が距離の符号と一致(補助。各面が指定量動いたことは定義の比較が見る)。

### D(丸めが付いてくる)

- **丸めの認識は構造で、半径の大小では決めない**: 円筒またはトーラスで、**長手の辺**(円筒は軸に平行な直線、トーラスは同軸の円)がちょうど2枚の別の面に G1 で接し、
  その2枚(支えの面)が丸めでないこと。丸めに G1 で接し、**その丸めと同じ半径の**球は角として連なりに入れる。これは**操作上の認識規則**で、
  設計者がフィレットとして作ったことの証明ではない(意匠の大きな丸めも丸めとして扱う。astra の指摘)。
- 選んだ面に G1 で接する面が丸めでない(意匠の曲面・B-spline・円錐・可変半径)なら断る。支えの面が丸め(丸めの上の丸め)なら断る。支えの面の分割や
  スプライン表現での取りこぼしも断る。断り文は理由を区別する。**B の接線伝播へは切り替えない。**
- 手順: 丸めの連なりを A で外す → 尖った形で B0 と移動の関門 → 支えの面2枚の像の共有辺がちょうど1本なら元の半径で丸め直す → 検査:
  - 辺ごとに、その辺から作り直した面(`Generated(辺)`)が円筒・トーラスで**その辺の半径**と一致し、長手の辺で**支えの面の像に G1 で接する**こと(両側とも)。
  - 頂点から作り直した角(`Generated(頂点)`)は、その丸めの半径の球であること。
  - それ以外の面は対応元の曲面に乗り、旧面から新面への対応が単射で、作り直した面と重ならず、出どころの無い面が無いこと。

### 子プロセス(`duocad/kernel_worker.py`)

- **常駐の子プロセス1本**を初回の呼び出しで立てる(起動 1.6 秒)。親は形を BinTools のバイト列で、添字・距離を JSON で渡す。子は演算・関門・由来の射影
  (添字の対応表)まで行い、結果のバイト列と JSON を返す。履歴のオブジェクトは渡さない。
- 親は**期限切れ・異常終了・取り消し**を区別し、どれでも結果を採らず、子を止めて次の呼び出しで立て直す。verb は `ValueError` を投げ、文書もログも変えない。
  **親は同期的に待たない**(待つ間もイベントループと「中止」を捌く)。計算と採用を分け、採用の直前に文書の世代・入力の形・選択・引数を照合する。
- 同時に走らせる計算は1本。確定・再生をプレビューより優先し、待っているプレビューは最新の1件だけ残す。**入力のたびに子を殺さない**(起動 1.6 秒を繰り返して結果が出なくなる)。
  走っている計算を止めるのは「中止」と期限切れだけ(GIL を握ったまま返らない計算を止める手段は子を殺すことしかない)。確定は同じ入力なら検証済みのプレビューの結果(形と由来の組)を使う。
- ログの再生(文書を開くとき・redo・寸法の作り直し)も同じ経路を通す(結果が同じであることは BinTools の厳密さと決定性の実測による)。**再生には対話の期限を掛けない**(カード e)。
- 子のメモリは要求ごとの形・履歴を持ち越さない形にし、立て直しの条件は反復の実測で決める。詳しい契約は「実装計画」の段1(astra の2回目の指摘)。
- **既存の verb(フィレット・面取り・ブーリアンなど)は今回は移さない。** 仕組みは汎用に作り、移すのは別 Issue(docs/PERFORMANCE.md「残り」の
  「50 ms 未満にするにはプロセスを分ける必要があり、やっていない」とも同じ道具になる)。

### 候補: B0 が断った平面の移動を B1 で取り直す(推奨にはまだ上げない)

- 実測: アロマディフューザ(316 面の格子)で、B0 が断った平面の移動 48 件のうち 20 件を、B1(`Intersection=True`)で計算すると厳しい版の関門を全部通る。
  別プロセス2回で面の並びまで一致。時間は B1 約 22 ms(B0 が断るまで約 8 ms)。マザーボード(0/48)・hanger_bar(0/8)は B1 でも作れない。
- 推奨に上げる条件(astra の3回目): 救った編集が本人に要る形と合う、別プロセス・BinTools の往復・要求の順の変化でも形と対応表が一致する、B0 と B1 の合計時間が
  期限に収まる、再生で同じ方式と結果を選べる。**B1 を選ぶのは、丸め追従の無い B0 の「通常の拒否」(関門落ち・空の結果)のときだけ**にし、期限切れ・異常終了の
  ときには選ばない(負荷で方式が変わると、保存時と再生時で形が変わりうる)。採った方式は由来に記録する。

## 推奨が覆る条件

- 子プロセスの往復(BinTools と起動)が、実際の画面のプレビューで体感できる遅れになったとき(目安なし。実装で測る) → まず要求の間引き・結果の再利用・受け渡しの改善で詰める。
  プレビューだけ同じプロセスへ戻すことはしない(同じ演算なので、GIL での停止と異常終了の危険が戻る。astra の3回目の指摘)。
- OCP が `BOPAlgo_RemoveFeatures` の間 GIL を手放すようになり、かつ異常終了を防げる別の実装が得られたとき → 子プロセスをやめられる(既知の形の事前検査だけでは覆らない)。
- 丸め追従(D)が、本人の実際の部品で成功条件と由来を検証できないと分かったとき → 初回は丸めの隣を断る(#183 の丸め追従は未達として扱う)。
- B1 が、B0 では失敗する必要なケースを同じ意味の検査・決定性・性能で安定して解けると実証されたとき → 限られた経路で再検討する。
- 有機的な部品で成功率を上げることが本人にとって重要と分かったとき → 方式の追加(例: 丸めを連なりごとに1つずつ外して閉じ直す、許容差の調整)を別 Issue で比べる。

## 本人判断カード

どれも Issue の「未決(本人判断)」か、製品の方針として本人が決めるもの。**推奨は AI の案**で、決まるまで実装は推奨で進めてよい
(a・d は画面の配線だけ、b は補助、c は範囲、e は既定値1つで、kernel と verb の作りは変わらない)。

### a. 面を選んで「削除する」を押したときの意味(#190 の未決)

- **決めてほしいこと**: いまの「削除する」は、面・辺・頂点を選ぶとそのボディごと消える(`selection.require_deletable`)。面を選んだときは面の削除にするか。
- **推奨**: 面を選んだ「削除する」は**面の削除**にする。ボディを消すのはボディを選んだとき(ボディの一覧から)。辺・頂点だけを選んだ「削除する」と、
  面とボディ・図形が混ざった選択は断る(何を消すか曖昧)。スケッチの図形は今のまま。面が消せないときに**ボディの削除へ自動で移らない**。
  MCP では `delete`(ボディ・図形)と `delete_faces`(面)を別の道具のまま残し、画面の「削除する」が選択の種類で呼び分ける。**保存済みのログの `delete` の意味は変えない**
  (面で指してボディを消した記録は、これまでどおりボディの削除として再生する)。Delete キーの割り当ては今回決めない(docs/DESIGN_DECISIONS.md「キー割当は不満駆動」)。
- **理由**: 依頼の言葉「欲しいのはより強力な削除機能」が削除の延長として書かれている。「見えるものはすべてさわれる」(2026-10-18)で面を選ぶ場面が増え、
  面のクリックからボディが丸ごと消えるのは大きすぎる。直接編集の CAD(Fusion など)も面の Delete は面の削除。
- **弱点**: いまの「削除する」の約束が変わる(面を選んでボディを消していた手順が使えず、ボディの一覧から選び直す)。面が消せない形では断るだけ。
  穴の内面を「削除」すると穴が埋まって体積が増え、「削除」の語感とずれる(astra の指摘)。
- **他の選択肢**: 「削除する」は今のまま、面の削除は別のコマンド「面を削除する」— 今の手順は変わらないが、面を消すつもりで「削除する」を押すとボディが丸ごと消える(Ctrl+Z で戻る)。
- **この結果で変わること**: `DELETE_SELECTION`(`web/src/commands/features.ts`)の受ける種類と呼び分け、catalog の `delete` の説明文。kernel と verb は変わらない。

### b. フィレットの面1枚のクリックで、つながった丸めをまとめて選ぶ補助(#190 の未決)

- **決めてほしいこと**: 丸めの面をクリックしたとき、接線でつながる丸めの面(連なり)をまとめて選ぶ補助を付けるか。
- **推奨**: 付ける。ただし**1クリックで黙って広げない**: 丸めの面を選んだときに「連なりを選択」(ボタンかショートカット)を出し、対象の全部を強調表示してから選択に入れる。
  1枚だけの編集もそのままできる。**verb は選ばれた面だけを消す**(自動で広げない。AI からの呼び出しで選んだものと結果が食い違わないように)。
  (AI の最初の案は「クリックで連なり全体、修飾キーで1枚」だったが、astra の指摘で明示の操作に改めた)
- **理由**: 連なりの1枚だけ消すと、残りの丸めが新しい角まで延びた有効な形になる(`d_fillet_top4_one`)。意図と異なる場合がある(頻度は測っていない)。
  全辺丸めの縦の丸めだけを消すと角の球が閉じず断られる(`d_fillet_all12_vertical4`)。
- **弱点**: 面の連なりの計算が新しく要る(今あるのは辺の連なり `kernel_chains.BlendChains`。D の丸めの認識と同じ道具で作れる)。連なりで消すたびに1手増える。
- **他の選択肢**: 付けない(1枚ずつ選ぶ)。verb が自動で連なりへ広げる(選んだものと結果が食い違う)。
- **この結果で変わること**: 画面のピックの補助と、面の連なりを返す問い合わせ(辺の `get_edge_chains` と同じ形)。

### c. 平行移動・指定面までの移動を持つか(#183 の未決)

- **推奨**: 今回は**オフセット(外向き法線へ距離)だけ**。「指定面まで」は、平行な平面どうしなら距離を自動で埋める画面の補助として後から足せる。
  任意の向きの平行移動は作らない(要るなら別 Issue で方式から比べる)。
- **理由**: MakeOffset は法線方向の距離しか持たない。平行移動は隣を延ばして組み直す別の作り方(C の系統)が要り、C は誤った形を通し、実物ではプロセスごと落ちた。
- **他の選択肢**: 平行移動も作る(方式の比較からやり直し)。
- **この結果で変わること**: verb の引数(今は `distance` だけ)。

### d. 押し出しと画面で分けるか(#183 の未決)

- **推奨**: **「押し出す」に統合**し、面を選んだときの選択肢(join / cut / new)に「面をずらす(隣を延ばす)」を足す。verb は別(`offset_faces`)。
- **理由**: 2026-09-26 の本人の決定「verbを統一し『押し出す』だけにする」の方向と整合する(ただしその決定は領域と面の押し出しの統合で、新しいオフセットを同じ入口に
  置くことの承認ではない。astra の指摘)。箱の面なら押し出しと同じ結果で、違いは斜めの隣・曲面・丸めの隣でだけ出るので、同じコマンドの中で選び分けるのが自然。
  **条件: join / cut / new と「面をずらす」の違いがプレビューで見分けられること**。
- **弱点**: 曲面(穴・外周)を選べるのは「面をずらす」のときだけになり、選べる面が選択肢で変わる。押し出しの選択肢が4つに増える。
- **他の選択肢**: 別のコマンド「面を動かす」— 押し出しは今のまま、面の移動は曲面も最初から選べる。コマンドが1つ増える。
- **この結果で変わること**: web の CommandDef(押し出しの面の版か、新しい `OFFSET_FACES`)。catalog・verb・MCP は変わらない。

### e. 長い計算を何秒で打ち切るか

- **決めてほしいこと**: 面の削除・オフセットの計算が長いとき、何秒で打ち切るか。
- **推奨**: 画面からの操作(プレビューと確定)は既定 **30 秒**で打ち切り(「時間がかかりすぎたので止めた」と出して何も変えない)、計算中は「中止」を出す。
  期限に含めるのは子での計算と受け渡しで、前の計算の終わりを待つ時間は含めない。**文書を開くときの再生には打ち切りを掛けず**、進捗と「中止」(開くのをやめて今の文書を残す)を出す
  (再生に期限を掛けると、保存できた文書が負荷しだいで開けなくなる。astra の指摘)。プレビューは、新しい入力が来たら計算の始まっていない要求を差し替える。
- **理由**: **30 秒は置いた値**で、実測の根拠は「合成形状の正当な計算の最長が 18 秒(穴100個を一度に消す)」と「角ばった実物の1件の計算は最長約 1 秒」の2つだけ
  (有機形状の 61 秒の例は対象外なので根拠にしない)。期限に子の起動(1.6 秒)を含めるかは実装で決める。
- **他の選択肢**: 打ち切らず「中止」だけ。60 秒(待つ時間が長い)。10 秒(穴100個の一括削除が通らない)。
- **この結果で変わること**: `kernel_worker` の既定値1つと、画面の「中止」と再生の進捗。

## 実装計画

順番は「守り(子プロセス)→ kernel → verb → 公開面 → 画面」。各段で develop に入れられる大きさに切る(ブランチ運用は CLAUDE.md)。

1. **子プロセスの口 `duocad/kernel_worker.py`**(新規)。astra の2回目の契約を初回から入れる:
   - 常駐の子1本(初回の呼び出しで起動)。形は BinTools のバイト列、添字・距離・結果の対応表は JSON。履歴のオブジェクトは渡さない。
   - **実行は同時に1件**。確定・再生をプレビューより優先し、待っているプレビューは最新の1件だけ残す。新しいプレビューで確定・再生中の子を殺さない。入力のたびに子を殺さない。
   - **親は同期的に待たない**(待ちの間もイベントループと「中止」を捌く)。要求 ID と子の世代で、取り消し・立て直しの後に届いた古い応答を捨てる。同じ失敗を無限に再試行しない。
   - **計算と採用を分ける**: 開始時の文書の世代・入力の形・選択・引数を固定し、採用の直前に照合する。待つ間に undo・別の操作・文書の切り替えがあれば採らない。
     形・由来・ログ・undo の情報は一括で反映する。プレビューの結果(形と由来の組)を確定に使う。同じ計算が走っていれば確定はそれに合流する。
   - 期限は対話だけ(カード e)。再生には期限を掛けず、進捗と中止を出す。失敗した操作を飛ばして続きを再生しない(`open_document` の原子性は保つ)。
     astra は「進捗・中止・期限を延ばした再試行」を挙げたが、AI は期限そのものを掛けない形にした(再生は本人が文書を開くときに走り、中止できれば足りると判断)。
   - メモリの上限は親子の両方(子は要求ごとの形・履歴を持ち越さない。親の結果の覚えは件数と容量で捨てる。子の立て直しの条件は反復の実測で決め、実行中の確定を潰さない)。
   テスト: 子を送信中・演算中・返信中に止める、期限切れ、検査落ち、プレビューの連打→確定、確定中の undo、文書の切り替え、別の接続からの要求を注入し、
   通信が続き、文書・操作ログ・undo/redo の位置・SNAPSHOTS が変わらず、次の正常な要求が通ること。同じ操作列を繰り返して親子のメモリを測る(初期の増加と頭打ちを分ける)。
   `tests/test_boundaries.py` の `OCP_ALLOWED` と README の表に足す。
2. **`duocad/kernel_face_edit.py`**(新規。`tools/face_edit_probe/strict.py` を製品の形に): `delete_faces` / `offset_faces`(D を含む)/ 関門 / 曲面の定義の比較 /

## 再現

```bash
.venv/Scripts/python.exe -m tools.face_edit_probe.run                       # 合成形状 × A/B0/B1/C/DB/DC(約1分)
.venv/Scripts/python.exe -m tools.face_edit_probe.run --strict              # 厳しい版 SA/SB/SD
.venv/Scripts/python.exe -m tools.face_edit_probe.scale                     # 規模
.venv/Scripts/python.exe -m tools.face_edit_probe.provenance                # 由来の取れ方
.venv/Scripts/python.exe -m tools.face_edit_probe.isolation <file.step>     # BRep の往復
.venv/Scripts/python.exe -m tools.face_edit_probe.realworld <file.step> ... # 実物(厳しい版。--methods legacy で緩い版)
.venv/Scripts/python.exe -m pytest -q -p tools.face_edit_probe.verb_shim tests/test_delete_faces_acceptance.py tests/test_offset_faces_acceptance.py
.venv/Scripts/python.exe -m tools.face_edit_probe.viz out.json                 # 触れる模型のデータ(13 場面・1,456 通り。約1分)
```

触れる模型(本人向けの説明ページ、claude.ai の Artifact「面編集の模型」)は、`viz.py` の出力を three.js で表示したもの。ページ本体はリポジトリに置かない。

試作は duocad 本体から import されない(`verb_shim.py` だけが pytest のプラグインとして duocad の verb の作法を借りる)。Windows では子プロセスの出力の
文字コードを `PYTHONIOENCODING=utf-8` にそろえる(`run.py` と `realworld.py` は子に渡している)。
