# 二値探索の初期条件・候補メモリ管理 修正指示書

作成日: 2026-09-17。状態: **修正指示・未実装**。
調査基準: `8c997e9`、原因を記録したコミット: `579bf00`。
根拠: [INITIAL_SPACE_FAILURE_DIAGNOSIS.md](INITIAL_SPACE_FAILURE_DIAGNOSIS.md)。
本書は [PLAN_BINARY_STRESS_SEARCH.md](PLAN_BINARY_STRESS_SEARCH.md) の実装に対する追加修正指示。
今回は設計空間の形状を変更する仕事ではなく、後段との境界条件の接続と探索管理を直す。

## 1. 解消する不具合

1. CAD面から格子へのアンカー生成は材料の有無を見ず、新探索は全アンカー節点の材料被覆を要求する。
   この前提不一致により、hangerの初期材料マスクが `no_component` になる。
2. 全設計空間でも被覆できない固定アンカーを、空間の部分集合の探索で直そうとしている。
3. 候補をyieldする前に全マスクをリストへ生成し、初期探索の上限なしdequeへ積む。
   評価回数上限に達する前にメモリを使い尽くす。

4.8mm要求時の荷重面31は170節点中49、2.4mmでは938節点中108が未被覆。
これらは除外マスクを引く段階で発生し、接続性剪定が削除したセルは両方とも0。
導出は成功している。「導出失敗」「剪定が荷重面を落とした」と再び結論しない。

## 2. 変更してはいけないもの

- 固定凸包・ミンコフスキー距離膨張・余白20%・格子・除外マスク・導出出力。
- 6条件の意味、目標安全率、物性、応力99.5パーセンタイルの規則。
- 探索開始後に固定する荷重・拘束の対応。各候補に都合よく再配分して合格にしない。
- 未被覆節点への荷重を削って総荷重を減らすこと、人工拘束や空セルの弱い剛性でFEMを通すこと。
- 失敗を隠す検査削除・許容差の根拠のない拡大・旧SIMPへのフォールバック。

設計空間は「材料を置ける範囲」であり、その導出合格は6条件合格や安全率合格の証明ではない。
不足していたのは、固定空間に対して実際に作用する初期境界条件を確定する工程。

## 3. 修正A: 初期アンカーを材料に対応付けてから固定する

### 3.1 配線

```text
既存のdesign_space.derive（形状は変更しない）
 → 導出出力に接する節点集合を計算
 → 元のCAD条件面から、その節点集合への荷重・拘束対応を確定
 → 面ごとの対応・荷重保存・作用位置を検証
 → SearchConditionsへ格納し、ハッシュに含めて固定
 → 全空間での前提検査
 → 二値探索
```

主な変更先は `anchor.py`、`optimize_run._build_search_conditions`、
`binary_search.SearchConditions` と条件識別子。`design_space` のマスク修復で対処しない。
導出内部の幾何接続用の表と探索用の確定表を、ログで識別できるようにする。
探索の検査・島処理・FEM・デバッグ表示は、全て同じ確定表を使う。

### 3.2 対応付けの作り方

- `acceptance.active_nodes(space.mask)` によって、許可材料に接する節点を求める。
- `anchor.build_anchors` に節点の許可マスクを渡せるようにするか、同じ標本・重み処理を共用する専用入口を作る。
  既存生成処理をコピーして二重実装にしない。
- CAD面上の標本点から候補節点を集める際、許可節点を選別してから重みを計算する。
  許可節点以外への寄与を後から捨てる実装は禁止。
- 面の取り違え、標本の取りこぼし、所有権競合後の面の消失を検査する。
  現行の「全面から節点所有者を決める」規則を使うなら、その後の最終表で検証する。
- 近傍に適切な節点がない標本を、無制限に遠い節点へ移して通さない。
  支持節点を探す範囲と判定規則を明示し、成立しなければ面・標本位置付きの診断で停止する。
- 保存する値は、面ID、元CAD面積・重心、標本数、対応不能標本数、節点ID、重み、
  対応距離、適用荷重。元の表との差も診断に残す。

初期条件の再構成は「島除去で失われた荷重の配り直し」と区別する。
**確定後は一切再配分しない**。候補の削除で確定節点が材料から離れたら、その候補を不合格にする。

### 3.3 荷重と拘束の検証

- 荷重面ごとに入力ベクトルと節点荷重の合計が一致することを検証する。
  相反する荷重があるため、全荷重を加算した合力だけの検査では不足。
- 作用位置の変化も測る。固定した共通原点について、CAD面への分布荷重のモーメントと
  節点荷重の `Σ(position × force)` を比較する。現行の一定方向の面荷重ではCAD面重心と
  合力から参照モーメントを計算できる。
- 合力の保存だけを見て新しい重みを採用しない。モーメント・重心・対応距離の誤差は
  mm/Nの実単位と、格子サイズ・荷重で正規化した値を記録する。
- 重み補正が必要なら、局所的な支持節点への分配で合力と作用位置を保つ方法を実装する。
  数値許容差と格子近似の許容差を区別し、解析解を持つ面・格子細分で根拠を示して固定する。
  hangerだけを通す目的で閾値を調整しない。対応が成立しなければ成功扱いしない。
- 拘束は対象面に対応する有効節点だけに適用する。全体の剛体運動を止めるための
  無関係な節点追加は禁止。必要な剛体拘束の検査は維持する。
- 評価条件ハッシュに、確定した節点・荷重・拘束と対応付け規則を含める。

## 4. 修正B: 全空間での必要条件を探索前に検査する

`find_initial_feasible` の入口に、保持CADの重なり検査と同様、
**確定済みの全荷重・拘束節点が全設計空間の材料に接するか**の検査を追加する。

- 失敗なら候補生成・FEMを開始しない。失敗した面、節点数、元入力か対応付けかを診断する。
- 状態は `boundary_mapping_failed` 等の専用理由とし、単に「予算を増やせばよい」と案内しない。
  根拠なしにCAD入力矛盾や解像度不足と断定しない。
- 保持との重なりが全空間でない場合、空アンカーの場合など既存の入口診断は維持する。
- 「全材料の安全率が不足」「除外内の空間が不足」「境界が非正常」は、この不可能判定に混ぜない。
  それらは材料の変更で改善する可能性がある。
- APIを直接呼ぶ検査・CLIでも同じ事前検査を通す。製品入口だけの防御にしない。

数学的な根拠: 候補Mが設計空間Dの部分集合なら、Mに接する節点もDに接する節点の部分集合。
Dで未被覆の固定節点は、D内での削除・追加・置換では被覆できない。

## 5. 修正C: 候補を遅延生成し、初期探索から保持量を制限する

対象は `repair_candidates`、`_generate_repairs`、`find_initial_feasible`、`_push_children`、
`_reduce_volume`。初期探索だけ／後半だけの修正にしない。

### 5.1 候補表現

- `deletes/adds/replaces` に全格子コピーを貯めてからyieldする実装を削除する。
- 候補は親の識別子と操作領域の小さな記述で保持し、評価する直前にマスクを作る。
  又は同等に保持上限を保証できる遅延生成を使う。
- 親マスクも無制限に保持しない。参照中の親・frontier・最良合格・作業配列の保持上限を定める。
- 親・最良合格マスクをin-place変更しない。失敗候補の変更がチェックポイントへ漏れないようにする。
- 同一候補の重複を管理し、全サイズ・全操作で一度に配列を確保しない。

### 5.2 上限・中断・公平性

- 初期探索と削減探索に同じfrontier上限の契約を適用する。
- キューへ積んだ後にまとめて切り捨てるのではなく、生成・確保前から上限を効かせる。
- 評価予算とは別に、候補記述の検討数など生成側の予算も設ける。
  無効・重複候補だけで評価数が増えない場合にも、無限に生成し続けない。
- 生成中・評価前に中断を確認する。予算終了・中断で最良合格を破壊しない。
- キューの先頭が削除候補で埋まり、追加・置換が永久に試されない構成にしない。
  操作別の生成器を巡回するなど、決定的で偏りを制御できる順序にする。
- frontierからの除外、生成予算終了、評価予算終了は履歴に区別して記録する。
  キュー打切りを「近傍を全て探索した」と表示しない。

メモリの目標は概ね `O(保持マスク数×格子セル数＋小さな候補記述・履歴)`。
`O(全生成候補数×格子セル数)` を許さない。評価回数を増やしても保持マスク数が比例増加しないことを検査する。

## 6. 必須の回帰検査

| 対象 | 必須ケースと合格条件 |
|---|---|
| CAD面の対応 | 除外境界に沿う平面・曲面で、探索用アンカーが全て許可材料に接する |
| 荷重保存 | 各面の合力、作用位置、モーメントを既知値と照合。複数・相反荷重でも脱落が相殺されない |
| 格子依存 | 平行移動・格子位相の変更・細分でも対応と荷重精度を検査。hanger一例だけで確定しない |
| 対応不能 | 支持節点がない面・標本、所有権競合で空になった面を診断し、遠方節点で穴埋めしない |
| 条件固定 | 初期合格後、確定アンカーの足場を削ると不合格。再正規化で合格へ戻らない |
| 入口停止 | 全空間でも未被覆の節点を持つ直接API入力は、候補生成0回・FEM0回で停止 |
| 遅延生成 | 1候補を要求した時点で全候補が生成されていないことを検査。単なるgenerator型の確認では不足 |
| 保持上限 | 初期・削減の両経路で、実格子相当の大きさでもキューと親マスク数が上限以内 |
| 生成中断 | 評価に到達しない大量の重複・不適合候補でも、生成予算と中断が効く |
| 探索の継続性 | 追加・置換へ順番が回り、既存の削除行き詰まり回避テストも通る |
| 最良候補 | 上限・中断・後続失敗で最良合格のハッシュと体積が変わらない |

大規模メモリ回帰はまずFEM・CAD評価を小さなスタブに置き換えて候補管理だけを検査する。
実際の巨大確保やMemoryErrorを故意に起こすテストにしない。
アンカー・荷重のテストは実CADと実数値を使い、全てmockで済ませない。

## 7. hangerでの実機確認手順

1. 同一の `models/hanger_bar_attachment.json` を用い、内容ハッシュ・コード版を記録する。
   4.8mm要求・2.4mm要求の両方を使い、実spacingと格子を併記する。
2. 導出出力のハッシュ・セル数を修正前と照合する。現在の基準値は47,232／367,390セル。
   合わせるために導出ロジックや基準値を書き換えない。
3. 旧幾何用アンカーと新しい探索用アンカーの診断を分ける。
   旧表の49／108件を消すことではなく、確定した新表が材料に接し荷重条件を保つことを確認する。
4. 初期全材料マスクの6条件を、実FEMを含めて検査する。
   安全率不足など別の不合格が出たら具体値を記録し、6条件合格と報告しない。
5. 小予算で生成・保持上限・中断を確認してから、4.8mmで合格候補探索と削減を通す。
6. 2.4mmでも同じ入口検査と実評価を行い、探索の採用マスクで6条件を再検査する。
   予算不足で未達ならその旨を残し、4.8mmの成功を2.4mmの成功に読み替えない。
7. 候補中メッシュ化0回、固定空間導出1回、評価条件ハッシュ不変を確認する。

初期モデルの安全率合格は事前には保証しない。初期全材料が不合格でも、探索が正しく合格候補を
発見できればよい。ただし、この追加指示の不具合修正と、元計画のhanger全体完成は別々に報告する。
