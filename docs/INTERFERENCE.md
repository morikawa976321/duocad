# 干渉チェック（Issue #186）の方式

**状態: 調査と方針だけ。未実装**（2026-10-18）。実装に入るとき、判定の数字（許容差・厚さ・時間）を疑うときに読む。
試作と計測は `tools/interference_probe/`（再現コマンドは末尾）。生データは `output/interference_probe/`（git 管理外）。

本人の依頼（2026-10-18、要旨）: Issue #186 の調査と方針探し。方式の候補ごとに小さな試作で精度・計算時間・失敗する形を測って
比べ、相談役と意見を交わし、好みが核になる点は推奨付きの本人判断カードにする。本実装はしない。

## 結論（推奨）

- **verb ではなく問い合わせコマンド `check_interference` を1つ足す。** `measure` と同じ `catalog.Command(category="query",
  changes_document=False)` で、`register_verb` も `@entry` も持たない。操作ログ・undo・選択リセット・状態配信を通らないので、
  「文書もログも変えない・Ctrl+Z の対象にならない」はこの形で構造的に満たす。本人の依頼文は「読み取り専用 verb」と書いたが、
  このコードベースの verb は「undo 1回・ログ1行・MCP 1呼び出し」が一致する単位（[DESIGN_DECISIONS.md](DESIGN_DECISIONS.md)「層の分け方」）で、
  ログに載らないものは verb と呼ばない。
- **判定は「境界箱で絞る → 組ごとに2体の General Fuse（GF）→ 触れていない近い組だけ最短距離」。** GF は2つの形の一致する部分
  （重なりの立体・接する面・辺・点）を両方の像で同じ形状として共有するので、像の共有を見るだけで「重なり／面・線・点の接触／離れている」
  が1回で分かり、重なりの体積・形と接触面積も出る。最短距離（`BRepExtrema_DistShapeShape`）は遅い（PC ケースで全体の 97%）ので、
  触れていない組で隙間を問われたときだけ測る。
- **組ごとに2つの欄を返す。** 幾何の関係 `relation`（overlap / tiny_overlap / contact / separated / unknown）と、隙間の要求に対する
  `clearance`（short / at / ok。`clearance > 0` のときだけ）。触れている組は隙間の要求を満たさない（short）が、画面の一覧は関係で
  分けて出す（下の「定義」）。
- **引数は `clearance`（mm、既定 0）だけ。** 3D プリントのはめ合いの隙間検査（例 0.2）を同じコマンドに含める。別コマンドにしない理由は
  「隙間検査」節。
- **文書の形状に触れない。** 写し（`kernel.copy_shape`）の上で、GF は `SetNonDestructive(True)` で走らせる。既定の破壊モードは入力の
  形状許容差を書き換える（実測: PC ケースで 27 体中 11 体）。結果は要求した接続にだけ返す。
- **計算は子プロセスで、組ごとに時間の上限を付ける。** 山形が一致したねじ山（らせんの B-spline 面どうしが重なる）の2体 GF は 240 秒で
  終わらず、OCP からは OCCT の計算を途中で止められない（`Message_ProgressIndicator` を Python で継承できない）。上限を超えた組は子プロセスを
  止めて作り直し、最短距離（同じ組で 0.14 秒）だけ測って「触れているが重なりは未確定（unknown）」か「離れている」にする。子プロセスの代価は
  PC ケースで約 2 秒（起動と import 1.0 秒・形の受け渡し 0.8 秒）。
- **メッシュのボディを含む組は manifold3d で近似する。** B-rep は 0.01 mm（STL と同じ）で三角形分割する。結果に「近似（方式と偏差）」を
  付け、厚さのしきい値はメッシュ用に別に持つ（分割の誤差で偽の薄片が出る）。メッシュを B-rep に直す経路は採らない（136,564 三角形で
  変換だけ 74 秒）。
- **時間（実測）**: 本人の PC ケース（27 部品・2835 面）で clearance 0 なら 3.9 秒、0.2 なら 8.3 秒（子プロセスの約 2 秒を除く）。
  ねじ山のボルトとナット1組で 2体 GF 約 3 秒。いまの `measure` のようにイベントループの中で同期実行すると、その間ほかの要求が止まる。

## 本人判断カード

好みが核になる点。どれも推奨のまま実装しても後から変えやすい（表示と既定値だけで、判定の計算は変わらない）。

### カード1: 結果をどこに見せるか

- **決めてほしいこと**: 干渉チェックの結果を、パネルの一覧・ビューポートの強調・その両方のどれで見せるか。
- **推奨**: 両方。パネルに組の一覧（関係ごとの見出しと件数、行は「部品A × 部品B・体積または距離」）を出し、行を選ぶとその組の
  重なりの立体（半透明の赤）・接触面・最短距離の線と札をビューポートに出す。何も選んでいなければ重なりの立体だけを全部出す。
- **理由**: PC ケースでは関係のある組が 85 組あり、ビューポートだけでは「どれとどれか」が読めない。一覧だけでは場所が分からない
  （Issue の要件「重なっている領域の画面上の強調表示」）。測定の札（`measureAnnotation.ts`）と投機実行の幽霊（`ghostLayer.ts`）の
  描き方が既にある。
- **他の選択肢**: ビューポートだけ（赤い立体と札。件数が多いと重なって読めない）／パネルだけ（場所が分からない。Issue の要件を満たさない）。
- **この答えで変わること**: 画面側の部品（パネルを足すか、ビューポートの層だけか）。サーバの計算と MCP の戻り値は変わらない。

### カード2: 何も選んでいないときと、1つだけ選んだときの対象

- **決めてほしいこと**: 選択が無いときに全ボディを調べるか、見えているボディだけか。ボディを1つだけ選んだときにどうするか。
- **推奨**: 選択が無ければ**見えているボディ**の総当たり。1つだけ選んでいれば**その1つ 対 ほかの見えている全ボディ**。2つ以上なら選んだものどうし。
- **理由**: 本人の決定「見えないものはさわれなくていい」「可視性は何を指せるかの定義」（[DESIGN_DECISIONS.md](DESIGN_DECISIONS.md)
  「隠したボディ・選択・可視性」）に揃える。隠したボディは「いまは考えない」もので、形状最適化の設計空間の箱（hanger の文書の
  `solid`、他の 6 部品すべてと接触）のようなものを毎回一覧に入れない。1つ選ぶ使い方は「このボルトは何かに当たるか」で、断るより役に立つ。
- **他の選択肢**: Issue の原文どおり全ボディ（相談役 astra の推奨。「見えているものだけは仕様変更なので、明示の選択肢にする」）／
  1つだけ選んだら断る（astra:「勝手に全体検査へ広げない」）。
- **この答えで変わること**: 対象の決め方の数行と、画面の文言。

### カード3: 画面での隙間検査の既定値

- **決めてほしいこと**: 画面で干渉チェックを起動したとき、隙間（clearance）の欄を最初から何にしておくか。
- **推奨**: 0（隙間検査なし）で起動し、欄に打った値はそのセッションの間だけ覚える。
- **理由**: 隙間を 0.2 にすると、組み立てで意図して接している組まで全部「隙間不足」になる（PC ケースで short 58 組のうち 53 組は接触・
  重なり）。はめ合いを見たいときは、相手の2部品を選んで値を打つのが速い。
- **他の選択肢**: 最初から 0.2（本人の印刷のはめ合いの値。部品が少ない文書なら便利）／前回の値を文書をまたいで覚える。
- **この答えで変わること**: 画面の初期値だけ。MCP は引数を省けば 0。

### カード4: 接触と微小重なりを一覧に出すか

- **決めてほしいこと**: 面で接しているだけの組と、厚さが許容差程度の微小な重なり（数値誤差の薄片の疑い）を、一覧に出すか。
- **推奨**: 出すが、見出しの件数だけ見せて行は畳む（開けば見える）。干渉（overlap）と隙間不足（離れているが要求未満）だけを開いて出す。
- **理由**: PC ケースでは overlap 2・微小重なり 20・接触 31。全部を開くと本物の2件が埋もれる。一方、微小重なりが全部数値誤差だという
  証明は無い（astra の指摘）ので、隠さない。
- **他の選択肢**: 出さない（Issue の未決の1つ。件数だけも出さないと「調べたのか」が分からない）／全部開いて出す。
- **この答えで変わること**: 画面の一覧の初期状態だけ。MCP は常に全部返す。

## 定義と許容差

| relation | 判定 | PC ケース（clearance 0.2） |
|---|---|---|
| overlap | 2体 GF の像が立体を共有し、下の tiny_overlap に当たらない | 2 |
| tiny_overlap | 共有した立体の厚さの目安 2V/A と、有向境界箱の最小辺が、**どちらも** 1e-3 mm 以下 | 20 |
| contact | 立体は共有せず、面・辺・点のどれかを共有する（GF の許容差の範囲で触れている） | 31 |
| separated | 何も共有しない | 32 |
| unknown | GF がエラー・打ち切り。「干渉なし」と書かない | 0 |

| clearance（`clearance > 0` のときだけ） | 判定 | PC ケース |
|---|---|---|
| short | 触れている（overlap / tiny_overlap / contact）、または最短距離 d < clearance − ε | 58（触れている 53 + 離れている 5） |
| at | \|d − clearance\| ≤ ε（要求値ちょうどで設計した組） | 14 |
| ok | d > clearance + ε | 13 |

- **接触は OCCT の形状許容差で決まる。** GF は各形状の頂点・辺・面の tolerance の範囲を一致とみなす。PC ケースの部品の最大許容差は
  1e-7〜0.0097 mm で、最短距離 0.00999 mm の3組は GF で separated、`clearance` で short になった。
- **重なりの体積だけでは、本物の食い込みと数値誤差の薄片を分けられない。** PC ケースの「重なり」19組（体積の相対しきい値 1e-9 で判定）の
  うち、2組は体積 1270 / 25 mm³・2V/A 1.51 / 0.79 mm・有向境界箱の最小辺 2.41 / 2.3 mm、残り 17 組は体積 0.0001〜0.014 mm³・2V/A
  ≤ 7.2e-6 mm・最小辺 ≤ 8.3e-6 mm。厚さなら5桁離れる。
- **2V/A は平均の厚さで、最大の食い込み深さではない。** 薄く広い一致面と深い食い込みが1つの領域につながると、薄い側へ引っ張られる
  （実測: 100×100 の面が 1e-6 重なり、半径1・深さ5のピンが刺さる形で 2V/A = 0.00157、有向境界箱の最小辺は 5.0）。そのため有向境界箱の
  最小辺と**両方**が薄いときだけ tiny_overlap にする。代わりに、曲面どうしの薄片は有向境界箱では薄く見えず overlap に残る
  （実測: 半径 5 の穴に半径 5.000001 のピン。2V/A = 1e-6、最小辺 10）。見逃しより誤報の側に倒した。
- **2V/A の面積からは内部の面を除く。** GF の分割や第三のボディで重なりが複数の片に割れると、片どうしの境目の面も数えてしまい厚さが下がる
  （実測: 2.22 → 1.67。境目の面を除けば引数の順6通りで 2.22 のまま）。2体 GF なら第三のボディは入らないが、片への分割は起こる。
- **ε（1e-6 mm）は比較の帯で、距離の保証精度ではない。** 隙間 0.2 で設計した組の最短距離は 0.19999999999908〜0.19999999999998863 と測れ、
  ε なしでは14組が「0.2 未満」になる。
- **しきい値（1e-3 mm と 1e-6 mm）は仮置き。** 根拠は上の実測だけで、FDM の精度（0.1 mm 程度）とも、形状許容差とも結び付けていない。
  形状全体の最大許容差に連動させる案は採らない（離れた辺1本の大きな許容差が、正常な箇所の干渉を隠す。astra の指摘）。

## 方式の比較

| 方式 | 結果 | 採否 |
|---|---|---|
| (A) 組ごとに `BRepExtrema_DistShapeShape` → 距離 ≈ 0 の組だけ `BOPAlgo_BOP` の COMMON の体積 | 合成 35 ケースで、しきい値 1e-4 の内側に置いた隙間 1e-5 の1件以外は正しい。PC ケースで 70.5 秒（最短距離が 68.4 秒、遅い組は1組 3 秒） | 不採用（遅い。体積だけでは薄片と食い込みを分けられない） |
| (B) `BOPAlgo_CheckerSI` に2形状の複合 | 内包（箱の中の箱）で干渉 0 件。面接触と食い込みが同じ種類の干渉（FF/EE/VV）になる | 不採用 |
| (C) General Fuse の像の共有 | 合成 35 ケースで関係を全部正しく出す（0.001 / 0.00001 mm の食い込みは設計どおり tiny_overlap）。接触の種類と接触面積も出る。1組 2〜26 ms | **採用（2体ずつ）** |
| (D) 三角形分割して manifold3d の交差体積と `min_gap` | 画面と同じ 0.2 mm 分割で、半径 30 のピンと穴の隙間 0.1 を 0.0129、0.2 を 0.113 と測る（位相をずらしたとき）。0.01 mm 分割でも円筒の側面どうしの線接触を隙間 0.0049 と誤る | B-rep どうしには不採用。メッシュを含む組だけに使う |
| (E) `BRepExtrema_ShapeProximity` | OCP 7.9.3 で戻り値の型が登録されておらず使えない | 不採用 |
| 全体に GF を1回（(C) の変形） | PC ケースで 1.6〜1.7 秒（2体ずつは 3.3〜4.4 秒）、関係の食い違いは 0 件 | 不採用（下） |

- **メッシュ経路は位相が揃うと誤差が打ち消されて正しく見える。** ピンと穴を同じ角度で分割すると多角形どうしの隙間は (R−r)cos(θ/2) に
  なり、最初のケースはこれで見逃した。精度を測るケースは回転して位相をずらす。
- **2体ずつを選んだ理由**（AI の判断。astra は「連結成分ごとに GF」を推した）: 全体1回より2倍遅いが、PC ケースで 4 秒前後に収まる。
  2体ずつなら、組の結果が第三のボディや引数の順に左右されない、1組の失敗（エラー・警告・打ち切り）がその組だけで済む、進み具合を組の数で
  出せる。全体1回は1つの悪い形で全部が落ち、警告がどの組のものか分からない。astra 自身の覆る条件「写し込みの2体 GF が実文書でも十分速ければ
  2体方式の単純さを優先」に当たる。
- **BOP の警告は失敗にしない。** PC ケースで GF は `BOPAlgo_AlertAcquiredSelfIntersection` と `BOPAlgo_AlertBadPositioning` を出し、
  COMMON も 8 組で警告を出したが、体積は2方式で一致した。既存の `kernel_brep._common_with_box` の「警告で例外」の流儀をここへ持ち込むと、
  実物の STEP で検査そのものが動かない。警告は組ごとに記録して返す。

## 絞り込みと計算時間

| 文書 | ボディ | 総当たり | 境界箱で残る組 | 時間（clearance 0 / 0.2） |
|---|---|---|---|---|
| 本人の PC ケースの STEP | 27（2835 面） | 351 | 85（`Add`）/ 82（`AddOptimal`） | 3.9 秒 / 8.3 秒 |
| hanger（形状最適化の結果入り）の B-rep | 12 | 66 | 22 | 0.2 秒（0.2） |
| 合成（箱・円柱・フィレット付きの箱を格子に） | 30 / 100 / 300 | 435 / 4,950 / 44,850 | 16 / 54 / 178 | 0.25 / 0.53 / 1.56 秒（組ごとの (A)） |

- **境界箱は `BRepBndLib.Add`（緩い箱）でよい。** 緩い箱は真の箱を含むので絞り込みで組を落とさない。PC ケースで `Add` 7 ms に対し
  `AddOptimal` 1.7 秒で、残る組は 85 対 82。`kernel.bounding_box`（`AddOptimal`）の「寸法が最大9倍狂う」理由は表示する寸法の話で、
  絞り込みには当たらない。
- **時間を決めるのはボディの数より形の複雑さ。** 単純な形 300 個（44,850 組）は 1.6 秒、PC ケースの 27 部品は 3.9 秒。
- **最短距離は `SetMultiThread(True)` で 5〜8 倍速い**（PC ケースの遅い組 2.87 → 0.34 秒）。それでも PC ケースの clearance 0.2 では
  離れた 32 組で 3.8 秒かかる。
- **総当たりの箱の比較は Python の二重ループで 300 体 0.1 秒。** 千体を超えたら軸で並べて掃く方式にする（今の文書では要らない）。

## ねじ山（らせんの B-spline 面）

ねじ verb の採用方式（`tools/thread_prototype.py` の `threaded_segment`）でボルトとナットを作り、雄と雌の山形を半径方向に ±off ずらした
（60° の山形で斜面どうしの隙間は約 off）。方式ごとに子プロセスで、上限 240 秒。

| 組 | 2体 GF | 最短距離（並列） | メッシュ 0.2 / 0.05 / 0.01 mm |
|---|---|---|---|
| M8×1.25 off +0.10 | separated 2.9 秒 | 0.0999 / 0.32 秒 | 隙間 0.0928 / 0.0928 / 0.0963 |
| M8×1.25 off +0.05 | separated 3.3 秒 | 0.0499 / 0.31 秒 | 隙間 0.0433 / 0.0433 / 0.0460 |
| M8×1.25 off 0（山形が一致） | **240 秒で終わらない** | 0 / 0.14 秒 | 隙間 0、偽の重なり 0.33 / 0.33 / 0.10 mm³ |
| M8×1.25 off −0.05（雄が太い） | overlap 18.19 mm³・厚さ 0.061 / 4.6 秒 | 0 / 0.11 秒 | 重なり 18.12 / 18.12 / 18.13 mm³ |
| M20×2.5 off +0.10 | separated 2.1 秒 | 0.0999 / 0.46 秒 | 隙間 0.0871 / 0.0872 / 0.0958 |
| M20×2.5 off +0.05 | separated 2.6 秒 | 0.0500 / 0.44 秒 | 隙間 0.0374 / 0.0375 / 0.0454 |
| M20×2.5 off 0（山形が一致） | contact（面）4.2 秒 | 5e-15 / 0.39 秒 | 隙間 0、偽の重なり 1.53 / 1.54 / 0.34 mm³ |
| M20×2.5 off −0.05 | overlap 46.44 mm³・厚さ 0.061 / 2.4 秒 | 0 / 0.06 秒 | 重なり 46.42 / 46.38 / 46.45 mm³ |

- **直列の GF はねじ山で 12〜15 秒**（1回目の試作。`SetRunParallel(True)` で 2〜5 秒）。COMMON も直列で 14〜16 秒。
- **山形が一致する組は、GF で答えが出るかどうかが形による**（M20 は 4.2 秒で面の接触、M8 は 240 秒で終わらない）。メッシュでは偽の重なりが
  出る。最短距離だけがどちらでも速く「触れている」と答える。答えが出ない組は「触れているが重なりは未確定（unknown）」にする。
- **メッシュの経路は隙間を小さめに測る**（0.2 mm 分割で隙間 0.05 を 0.037、0.1 を 0.087。0.01 mm でも 0.045 / 0.096）。重なりの体積は
  −0.4% 以内。ねじ verb の既定の隙間（半径方向）を 0 にしない限り、印刷用のねじでは起きにくい
  （[THREAD.md](THREAD.md)「隙間を一級の引数にする」）。

## メッシュのボディが混ざるとき

hanger の文書（B-rep 12 体 + 形状最適化の結果のメッシュ 136,564 三角形）で測った:

- manifold3d への変換 0.76 秒、境界箱の触れる全組の交差と `min_gap` 1.07 秒。
- **メッシュの結果は保持ボディを内側に含む**（形状最適化の最終処理が保持を足すため）。保持の3部品との組は体積 1047（部品の体積と同じ）で
  overlap になる。意図した重なりで、干渉ではない。
- **分割の誤差で偽の薄片が出る。** B-rep どうしを 0.01 mm で分割した組で 2V/A = 0.00035〜0.0008（GF では contact）、メッシュと B-rep の
  組で 0.003〜0.02。B-rep 用の 1e-3 をそのまま使うと誤報になるので、メッシュを含む組のしきい値は分割の偏差に連動させる（仮に 0.05 mm）。
- **「誤差 ±分割の偏差」とは書かない**（astra の指摘）。距離の誤差は両方の近似誤差の上界が保証されるときしか足せず、体積には長さの偏差を
  付けられない。結果には「B-rep を 0.01 mm で三角形分割した近似」とだけ付ける。保存されたメッシュはそれ自体が基準の形。
- **メッシュを B-rep に直して GF に入れる経路は採らない。** `mesh_geometry.make_material`（三角形1枚を1面）で変換だけ 74 秒。

## 隙間（クリアランス）検査

- **同じコマンドの引数にする。** 判定の流れ（境界箱 → 接触の判定 → 最短距離）が同じで、隙間は境界箱を広げる量と最短距離の比較が
  変わるだけ。別コマンドにすると同じ計算を2回呼ぶことになる。
- **最短距離は「最短箇所」1点。** 「隙間が足りない範囲」ではない。ピンと穴が一か所で接していれば距離は 0 になり、別の場所のはめ合いは
  見えない（astra の指摘）。範囲を出すには面ごとの距離か点群が要る（後の段）。
- **同心のピンと穴の最短距離は半径方向の隙間**で、直径の差ではない（ねじ verb の `clearance` も半径方向。[THREAD.md](THREAD.md)）。

## 相談役の意見と食い違い

### astra 1回目（2026-10-18、方式と定義の全体）

astra の意見（要旨）と AI の採否:

- 「全ケース正しく分類」は保存データ（31件・GF の体積が全件 0・隙間 1e-5 が contact）から確かめられない。→ **採る。** 試作の GF の
  結果の読み取りの誤り（形状を辞書のキーにしていた）を直す前の保存だった。35 ケースで測り直し、保存も差し替えた。
- 共有した立体片の表面積をそのまま足すと、片の境目の面を数えて 2V/A が下がる。→ **採る。** 実測で確かめ（2.22 → 1.67）、境目の面を除いた。
- GF の非破壊モードを設定していない（OCCT 7.9.3 の既定は破壊）。問い合わせとして登録しても入力の不変は保証されない。→ **採る。** 実測で
  PC ケースの 27 体中 11 体の最大許容差が変わった（非破壊なら 0 体）。写しと非破壊の両方にする。
- 薄片を自動で contact に回さない。正の体積は残し「微小重なり」と表示し、表示で畳む。→ **採る**（tiny_overlap を別の区分にした）。
- 2V/A は平均で、薄い面と深い食い込みが混ざると埋もれる。→ **採る。** 実測で確かめ（2V/A 0.00157）、有向境界箱の最小辺と両方で判定する。
  曲面の薄片を overlap に残す副作用は実測で確かめて明記した。
- 形状全体の最大許容差に連動させない。→ 採る。
- 隙間は不足／付近／余裕の3段、ε は比較規則で保証精度ではない。`clearance > 0` なら接触も要求未達。→ 採る。
- 連結成分ごとに GF。→ **採らない**（2体ずつ。理由は「方式の比較」）。
- ネイティブの異常終了から戻るなら別プロセス。→ **最初は採らなかったが、ねじ山の実測の後で採った（理由は別）。** 異常終了の危険だけなら
  `boolean_body` も同じ BOP を同じプロセスで呼んでいて干渉チェック固有ではなく、試作で踏んだ異常終了（`BOPAlgo_BOP.PDS()`）は使い方の誤り。
  採った理由は**止められないこと**: 山形が一致したねじ山の GF が 240 秒で終わらず、OCP からは途中で止める口が無い。同じプロセスのスレッドで
  走らせると、終わらない計算がワーカーを掴んだままになる。
- メッシュは manifold3d、失敗した組だけ unknown。「誤差 ±偏差」は撤回。→ 採る。
- MCP に body ID・対象・版・単位・方式・警告・判定規則・unknown の件数を返す。重いメッシュは通常の応答に入れない。→ 採る。
- 選択なしで「見えている全ボディ」は仕様変更。1つだけ選んだときに全体へ広げない。→ **本人判断カード2にした**（AI の推奨は逆）。
- 試作の不備（hash だけで共有を判定・削除された像を元に戻す・エラーの確認が後・clearance 0 でも距離を測る・`min_gap` の探索幅 0）。
  → 全部直した。

## 推奨が覆る条件

- 2体ずつの GF が実文書で 10 秒を大きく超え、全体1回が十分速い → 境界箱の候補のグラフの連結成分ごとに GF（astra の案）へ切り替える。
- 2体 GF が警告つきの形で関係を誤る例が出る → その組だけ COMMON と最短距離で確かめ直す経路を足す。
- 曲面の薄片の誤報（overlap に残る）が実文書で目立つ → 薄片の判定に、片の表面上の点から相手の面までの距離の最大（局所の厚さ）を足す。
- ねじ山（らせんの B-spline 面）で GF か最短距離が実用時間に収まらない → その組は打ち切って unknown にし、時間の上限を引数で持つ。
- 本人がメッシュの組を出さなくてよいと言う → メッシュを含む組は件数だけにする（manifold3d の経路を持たない）。

## 試作で踏んだ落とし穴

- **`TopoDS_Shape` の Python ラッパは `__hash__` が形状の同一性を返すが、`__eq__` は Python の同一性。** 形状を辞書のキーにすると、
  GF が共有した片が別のキーになり、重なりを全部見落とす（試作の最初の版で GF の体積が全件 0 になった）。hash で引いて `IsSame` で確かめる。
- **`BOPAlgo_BOP.PDS()` や `PPaveFiller().DS()` が返す DS に Python から触るとプロセスが落ちる**（終了コード 127。小さな形では終了時に落ちる）。
  ラッパがポインタの持ち主のつもりで解放する。DS を読むなら `BOPAlgo_PaveFiller` を自分で作って `DS()`（参照）を読む。
- **BOP の DS の FF 干渉は接触ではない。** 隙間 0.2 の組でも面の組が 114 件記録される（境界箱が重なる面の組の記録）。
- **`BRepExtrema_DistShapeShape.InnerSolution()` は当てにしない。** 内包で True になる一方、体積 0 の接触の組でも True が出た。
- **manifold3d の `min_gap(other, search)` は [0, search] に丸める。** search を 0 にすると全組 0（接触）になる。
- **ねじの試作を1プロセスで回すと、3組目（山形が一致）の GF で 20 分の打ち切りに掛かった。** OCCT の呼び出しは Python から中断
  できない: `BOPAlgo_Builder.Perform(theRange)` は進捗の範囲を受け取るが、止める側の `Message_ProgressIndicator` は OCP で構築子が無く、
  Python で継承できない（`TypeError: No constructor defined!`）。方式ごとに子プロセスで時間の上限を付ける（`threads.py`）。
