# カーネルの共通幾何機構

## 責務と依存の向き

| 層 | 責務 | 参照してよい共通層 |
|---|---|---|
| `brep_topology` | 列挙・添字・整数だけの由来射影 | なし |
| `brep_geometry` | 積分・法線・境界箱 | topology |
| `brep_checks` | null以外の形状検査・体積・BRepCheck | topology・geometry |
| `brep_history` | ビルダ履歴・IsSame・後継面の添字 | topology |
| `brep_operations` | コピー・結合・統合とその履歴・ブーリアンのビルダ作成 | topology・geometry・checks |
| `brep_planar` | 平面の座標系・補助面・面集合の演算 | topology |
| `mesh_geometry` | メッシュの幾何処理 | topology・checks |
| `kernel`・`kernel_*` | 操作・失敗方針・ブレンドの試行順 | 必要な共通層 |

共通層から個別操作を参照しない。操作間で内部関数を共有せず、共通層を直接参照する。共通関数の参照はモジュール名で修飾し、操作側に同名の別名を作らない。操作間の公開の協力（例: 投影からスケッチの図形変換、特殊フィレットから辺の連鎖）は許す。`kernel_tight` が `kernel_overflow.Unsupported` を参照するのは両操作の例外契約を揃えるため。

## 層をまたぐ契約

`build_boolean` は引数・ツール・許容差を設定して一度だけ `Build` し、履歴を取得できるビルダを返す。完了判定とフィレット固有の `Unsupported` は overflow と tight のそれぞれの `_boolean` が扱う。`outward_normal` は法線未定義なら `None` を返し、例外・文面への変換はそれぞれの `_outward_normal` が担う。失敗の意味と次の試行を決めるのは操作側なので、共通層に操作固有の例外を持ち込まない。両操作の差し替え点も独立している。

`unify_same_domain` はコピーで試し、体積の維持・妥当性・面数の減少を確かめてから元形状で本番を行う。採用しない場合に未処理の元形状を返せるようにするためで、面が減らない統合は利得がなく入力を壊す危険だけが残る。採用する場合もコピーの試行結果を本番結果には使わない。由来の射影は元の部分形状を鍵に履歴を引くため、コピーの履歴では同一性が切れる。本番で試行と異なり不正な形状になった場合は、入力も壊れているため操作ごと失敗にする。

`kernel.copy_shape` は共通層へ委譲する公開の入口。別スレッドで扱う形状は幾何も写し、三角形分割は写さない。コピーの幾何・三角形分割のフラグは用途ごとの契約であり、一律に揃えない。

通常の OCCT → tight → 吸収の試行順と各段の検証は `kernel` が持つ。ビルダの完了だけでは妥当なソリッドを保証できず、各方式の結果を採用するかは操作として判断する必要がある。ブレンドの由来辞書へ verb・edges を付ける処理と、面編集固有の関門も操作側が持つ。

## 意図的に統合しない実装

bbox・積分・許容差・列挙順・計算順が異なる実装は別に保つ。同じ幾何量を求める関数でも、計算法の違いは数値や採否を、列挙順の違いは面・辺の添字と由来の対応を変えるため、名前や見た目の類似だけでは統合しない。

平面集合の `_unified` は同一平面・同一曲線上の面・辺をまとめる処理であり、ソリッドの体積・妥当性・面数による採用判定と履歴を返す `unify_same_domain` とは契約が異なる。

## OCCT の外部の罠

ブーリアンの2引数コンストラクタはその場で演算を実行する。続けて `Build()` を呼ぶと同じ演算が2回走り、後からの `SetFuzzyValue` は2回目にしか効かない。このため `build_boolean` は空のビルダへ引数と許容差を設定してから実行する。

履歴の取得口はビルダごとに異なる。ブーリアンは `History()` が返す履歴、フィレット等の MakeShape 系はビルダ自身の `Modified`・`Generated`・`IsDeleted` を使う。部分形状の同一性は Python の辞書の鍵では引けないため `IsSame` で照合し、コピーを挟む場合は元形状との対応を保つ必要がある。

`ShapeUpgrade_UnifySameDomain` は入力を破壊し得る。妥当な結合結果が `Build()` 後には不正になることが実測されており、失敗後に同じ入力へ戻すだけでは復旧できない。また、OCCT の三角形分割は面に書き込まれる。別スレッドで同じ `TShape` を共有して清掃・再分割すると壊れるため、深いコピーで分離する。

## 前後一致の実測

共通層への分離前後の4群35ケースで、体積・重心・bbox・BRepCheck・列挙順・接続・向き・配置・由来辞書・例外型と文面の差は0（float は丸めず IEEE 754 のビット列で比較）。
由来の未変更・変更・分割・統合・削除・新生の添字を使う後続操作、入力とコピーの各段の再測定、IsSame/IsEqual/IsPartner、失敗後の再実行、Session.preview 後の確定、undo/redo、JSONログ再生を含む範囲で一致した。
