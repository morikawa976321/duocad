# 見えるものはすべてさわれる — 実装方針（2026-10-18、未実装）

本人の決定と答えの正は [DESIGN_DECISIONS.md](DESIGN_DECISIONS.md)「隠したボディ・選択・可視性」。ここは**どう作るか**と、
作る前に分かっている落とし穴。実装が終わったら、規則は VIEWPORT.md・contracts/ui-selection-viewport.md へ移してこの文書を消す。

方針は AI 3者（Claude・Codex consult・fable）で突き合わせた。

## 決まっている規則（要約）

- **通常モード**：コマンドを起動していないときは、見えているものを全部指せる。対象はスケッチの点・線・領域（全可視スケッチ）と、ソリッドの面・辺・頂点。
  ホバー強調は部品ごとに出し、頂点も強調する。
- **スケッチモード**：今と同じく、編集中スケッチの中身だけを指せる。
- **見えないもの**（非表示・立体の裏）は指せない。この遮蔽は人のポインタにだけ掛ける。**AI は ID でどれでも選べる**。
- **コマンド起動中**：そのコマンドが受け付ける種別だけを指せる。
- **重なったときの優先**：まず細かさを見る（頂点・点 ＞ 辺・線 ＞ 面・領域）。同じ細かさならソリッドを優先する。
- **反復の複製**：クリックした複製だけを選ぶ。
- **矩形選択**：一部でも見えていれば入れる。
- **通常モードの押し出し**：領域も受け付ける。
- **原点ギズモ**：対象外。

## 方式

### ピック（`viewport.ts` の `resolveHit`。統合は割らない）

**候補を集める → 隠れたものを捨てる → 優先で勝者を決める**、の3段で処理する。ホバー・クリック・`project*` 検算の3つが同じ経路を通る。

- **候補**：
  - 点・線・辺・頂点は画面距離で集める（`screenPick.ts`）。
  - 面・領域はレイで集める。
  - 各候補は、画面上の最近点と、それに対応する 3D 点を持つ。3D 点は透視投影を補正して戻す。画面上の補間率を、そのまま線分の補間率に使ってはいけない。
- **遮蔽**：候補ごとに、その 3D 点を投影した画素からレイを撃つ。遮蔽物（全可視ボディの面と断面の切り口）に、候補より手前で当たったら捨てる。
  - **カーソル画素1本の深度で比べない。** 輪郭の外側にカーソルがあると隠れた候補が通り、斜面では誤判定する。
  - 遮蔽の問い合わせは、参照の有無やコマンドのゲートと切り離し、深度だけを返す。切り口（`ref:null`）や、面を指せないコマンドの起動中の面も遮蔽物に含める。
  - 幽霊（プレビュー）は遮蔽物に入れない。
  - 許容は max(数画素相当, そのボディの有効テセレーション偏差) とする。深いズームでは偏差が画素より大きく、曲面上の辺が面メッシュより奥に来るため。
- **優先**：残った候補から、細かさ → ソリッド優先 → 画面距離 → 安定キー、の順で選ぶ。
  - 同じ距離のときは、入力順ではなく安定キーで決める。非同期で届いた順に勝敗を左右させないため。
- **頂点が辺より上になる件**：既定の順で「辺→頂点」としていたのは、フィレット中に辺の端を掴めなくするためだった（`viewport.ts` の resolveHit のコメント）。この問題は、起動中に種別を絞る規則で解く。そのため、種別の絞り込みを常時化より先に入れる。
- **GPU による ID ピッキング**（深度・ID バッファの読み戻し）は、予備の方式とする。CPU 方式が内蔵 GPU の実測で基準（p95 16ms）を超え、候補を絞っても直らないときに切り替える。

### 描画

- **辺**：ピック用の折れ線は描かない。見た目は既存の面境界線（`EdgesGeometry`）に任せる。強調描画するのは、ホバー中と選択中の辺だけ。
  - 全ボディの辺を透過で描くと、裏の辺まで全部見える針金図になる。
  - 代償として、接線連続の境目（角度の閾値以下）は境界線に出ない。そこにはホバーすると現れる。
- **頂点**：普段は描かない。描くのはホバー時と選択中だけ。
  - `vertexMarkers` は、描いているマーカーからしか候補を取らない。候補の集合と描画の集合を分ける改修が要る。
- **非編集スケッチの線・点・領域**（**要確認**）：深度検査をあり、深度の書き込みをなしにし、クリップ空間の深度バイアスを掛けて描く（B群の手法。`planeGrid.ts` の `withDepthBias` を線の材質へ移植する）。これで立体の裏に回った部分は隠れ、「見えないものは指せない」と見た目が一致する。
  - 今は A群と同じで、透過で描いている。
  - 編集中スケッチは、作図のため透過のまま残す。
  - 領域は今もコードでは深度検査ありだが、VIEWPORT.md には透過（A群）と書いてある。この食い違いもここで解消する。
- **選択中のもの**は、裏にあっても透かして描く。AI が選んだ裏のものを、人が確かめられるようにするため。ただしピックは遮蔽の規則どおりにする。

### データ

- **辺・頂点**：全可視ボディ分を持つ。今の作りは単一ボディ前提（`edgeBodyId`・`edgeTargetBody`・`edgeChainOf`・`highlightEdges`）なので、ボディごとの Map にする。
  - キャッシュの鍵は「形の版 ＋ 折れ線の精度」にする。形の版だけでは、拡大したときに粗い折れ線が残る。`body.revision` を鍵にすると、視点を止めるたびに全ボディ分を取り寄せ直す。
  - 取り寄せは、カーソルに近いボディを先に行い、残りは空き時間に温めておく。
  - 古い応答は捨てる。undo/redo・文書の切り替え・非表示・MCP からの選択変更と交差しうるため。
  - 走査するボディは、画面上の外接箱で絞る。1ボディ645本で p95 0.7ms なので、全27部品を素直に走査すると約20ms と見積もられる。
- **スケッチ**：全可視スケッチにピック用の取っ手（点・線）を持たせる。今は編集中スケッチだけ。
  - 再構築の鍵の `'edit'` 印は、取っ手の有無ではなく、描き方（透過か深度ありか）の違いだけを表すようにする。
  - 選択を鍵に入れない規則は保つ（smoke が `sketchRebuilds` で見ている）。
- **反復の複製**（**要確認**）：複製は描画用の `drawn` にしか無く、図形 ID を持たない（反復は `sketch.patterns` が元を参照し、展開するときに作る）。「そのコピーだけ」を選べるようにするには、反復を焼き込む（複製を実体の図形にする）か、複製を指す参照の形を作る必要がある。
- **独立した点の図形**：`add_point` は未実装（2026-10-17 決定）。ここでは受け口だけ作り、点の種別が入れば描かれて指せるようにする。verb の本体は別の作業にする。

### 選択の規則

- **起動中の絞り込み**：コマンドが要求する種別（選択の引数と pick 待ちの和）だけを指せるようにする。
  - ゲートは `sketchId===null` ではなく、明示したモードで書く。最適化モードと、スケッチの貼り先待ちにも同じ規則を掛ける。
  - 最適化の body 引数は、面ヒットをボディ参照へ畳むので、「要求種別」と「幾何のヒット種別」を対応表で結ぶ。
- **既存の選択**は勝手に削らない。修飾キー付きクリックで対象集合を編集する今の操作は残す。
- **サーバ `_apply_mode`**（`session.py`）：通常モードへ戻るときは、図形の参照を残す。スケッチ S に入るときは、S 以外の図形参照を落とす（今と同じ）。新しい遷移テストを足す。
- **矩形選択**（`collectInBox`）：クリックと同じ候補・遮蔽の経路を通す。今はゲートを手で写しているので、それをやめる。
  - 辺の連なりへの展開と、取り寄せ待ちは、全ボディに対応させる。
  - 未起動のときにどの種別を集めるかは**要確認**。
- **押し出し**：通常モードの `EXTRUDE_FACES` が領域も受け付けるようにする。
  - 選択に応じて、引数の表示と距離方向の説明を切り替える。
  - 面と領域が混ざったときは、事前に検出して止める。
  - プレビューも対応させる。
- **削除**：面・辺・頂点を選ぶと、ボディが丸ごと消える（今の契約）。指せる種別が増えると誤削除の入口が増えるので、確定前に対象を表示する今の手順が効いているか、段5で確かめる。
