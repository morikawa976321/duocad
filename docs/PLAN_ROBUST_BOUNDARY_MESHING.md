メッシュ化時に欠落する問題を修正する。境界曲線の折れ線近似が自己交差を作るため、
面を三角形分割する前に交差を検出し、問題のCAD辺だけを再分割する。

- リポジトリ：`C:\Users\tm976\mf\duocad`。既存の`develop`で作業する。ワークツリーを作らない。
- 着手時に`CLAUDE.md`、適用される`AGENTS.md`、git差分を確認する。既存の未コミット変更を消さない。
- 保持・除外の形状、フィレット、隙間、booleanの順序・意味は変更しない。この入力は正常な利用条件。
- OCCT本体を改造・再ビルドしない。Python/OCPから処理段階を制御する案Aを実装する。
- 独自の面三角形分割器、メッシュboolean、ボクセル化、穴埋め、頂点の距離による一括統合は導入しない。
- 開発中に新たな制約が判明したら測定結果を記録する。単なるパラメータ調整で直ったことにはしない。

確実性の契約は「未解決の境界交差・不正な最終メッシュを成功として返さない」。

## 4. 目標となる処理と不変条件

```text
以前の三角形キャッシュを破棄
  → OCCT内部モデルを構築
  → 辺を通常精度で離散化
  → 必要な標準の境界整合処理
  → 独立した境界交差検査
  → 問題辺を再分割 → 全隣接面を再検査（解消するまで反復）
  → 面分割前の最終境界検査
  → OCCTの面分割・後処理
  → 出力された境界が検査済みの境界と整合することを確認
  → 面別payload、必要な成果物検査
```

これは概念順序。HealModelとPreProcessModelが境界やdeflectionを更新する箇所を確認し、
**境界を変更する最後の標準処理の後、DiscretizeFacesの前**を独立検査の保証点にする。
検査後に標準処理が境界を変更するなら、もう一度検査する。名称だけから安全な順序を決めない。

不変条件：

1. CADの曲線・曲面・位相接続は変更しない。変更するのは離散化とそのキャッシュだけ。
2. 同じCAD辺の3D点列は一元管理し、全ての利用面・pcurveへ更新を伝播する。
3. 一つの面だけを独立に再メッシュ化して差し戻さない。
4. 交差点を新しいCAD頂点として結合しない。元の曲線に沿って細分化する。
5. 全体の要求精度を緩めない。局所的に細かくすることだけを許す。
6. 汎用メッシュ化では開いた面・シェルも許す。閉鎖性・単一ソリッドはその契約を持つ最終処理で検査する。

## 5. 境界交差検出

入力は、面分割器が実際に使う内部pcurveの離散点列と、元の辺・頂点・wire・向きの識別情報。
全てのwireを扱い、同一wire内、wire間、同じ曲線内の離れた線分の交差を検査する。

### 判定

- 線分の外接矩形で候補を絞り、2Dの向き判定で交差・接触・重なりを分類する。
- 面積や角度が小さいことを理由に候補・交差を捨てない。deflectionを交差判定のepsilonに流用しない。
- 浮動小数点の高速判定には数学的な誤差境界を使い、符号が確定しない場合のみ厳密演算へ進む。
  小規模な実装ならfloatの厳密な有理数表現によるfallbackが候補。固定epsilonによる近似判定は不可。
- 厳密演算が保証するのは「渡された浮動小数点座標の線分」の判定であり、元のCADの厳密性ではない。
- 接続予定の共有端点はCADの接続情報で識別する。隣接線分のペアを丸ごと除外せず、端点以外の重なりを検出する。
- 非隣接の接触、途中での接触、重なりは診断対象。正当な継ぎ目・縮退辺はOCCTの構造と照合して分類する。
- CAD端点とpcurve端点の小さな差がある場合、許される端点接続だけを局所的に照合する。
  近い座標を全て同一視する処理はしない。区別できない場合は成功にせず、曖昧として診断する。

### 周期曲面・特異点

円柱のseamは同じ辺が同じ面に異なるpcurveとして現れる。面ごとの辺だけでなく、
**辺の利用箇所（wire内の位置、向き、pcurve）**を区別する。
UVの周期をまたぐ見かけの飛びや球の極の縮退を、そのまま通常の交差に数えない。
標準の境界整合処理後の表現を利用し、正当な例外は位相情報で限定する。
平面だけで動く実装を汎用経路へ無条件投入しない。

### 戻り値

検出結果は面ID、wire／辺ID、線分番号、分類（交差・接触・重なり・曖昧）、
関係するCAD辺の集合を含む。再分割は辺ID、診断は面IDと線分番号を使う。
本番で全ての点列を常時ログ出力しない。必要時だけ問題部分を保存する。

## 6. 共有辺の再分割

初期実装はOCCTのEdgeAmplifierと同じ方針を使う。
問題辺を重複排除し、deflectionを1/3にして元の曲線から再生成する。

現在のOCPで公開を確認したAPI：

- `IMeshTools_Context`: BuildModel、DiscretizeEdges、HealModel、PreProcessModel、DiscretizeFaces、PostProcessModel。
- `BRepMesh_EdgeDiscret.CreateEdgeTessellator_s`。
- `BRepMesh_EdgeDiscret.Tessellate3d_s`、`Tessellate2d_s`。
- `IMeshData_Edge`: Clear、GetCurve、SetDeflection、GetPCurve、PCurvesNb。

OCCTソースのEdgeAmplifierを参照し、Clearの対象、端点の保持、最小点数、全pcurveの更新を揃える。
点の手動追加を初期案に混ぜない。API単体が呼べても共有境界が更新された証拠にはならないので検査する。

再分割後は関係する全ての面を作業キューへ戻す。影響のない面は反復中に再検査しなくてよいが、
面分割前の保証点では全体を確認する。交差数が一時的に増えるだけで失敗にしない。
細分化しても交差数が単調減少する保証はない。

停止条件は明示的に設ける：

- 全面の境界交差・未分類接触が解消したら次へ進む。
- 問題辺の全点列が変化しない、または同じ状態へ循環したら未解決として停止。
- 許容値の下限、最大反復回数、最大点数・メモリ予算に達したら停止。
- 初期評価では最大12巡を仮置きし、解消回数と点数を測って製品値を決める。
  12巡以内に収束するという保証ではない。座標規模とOCCT公差を無視して精度を下げ続けない。

診断には終了理由、面・辺ID、反復数、各辺のdeflectionと点数、残った問題数を残す。
本当に交差する入力境界も再分割では直らないので、成功扱いせず有界時間で失敗させる。

## 7. 実装工程

### 工程1：処理段階を制御できることの確認

製品経路を変更する前に、既存の最小3面BREPで単独プロセスの実験を作る。
標準の構築・離散化・境界処理・面分割・後処理を明示的に順番に呼び、
独自修復なしで既存の不具合を再現できることを確認する。

パラメータはIncrementalMesh内部の既定値補完を含めて揃える。
未初期化・ゼロの内部パラメータ、CleanModel、所有者寿命、処理後に解放されるデータを確認する。
context、model、各handleを必要期間保持し、解放後に内部モデルを参照しない。
Python例外処理でnative終了を捕捉できるとは考えない。

続いて、同じプロセス内で異なる形状・精度の呼び出しを繰り返し、寿命と残留状態を確認する。
過去の`internal.py`、`intervene.py`は調査資料であり、そのまま安全な雛形として移植しない。

この工程が通らなければ製品統合へ進まない。原因を調査し、案Aの障害と証拠を報告する。
依頼範囲を越えて案BのOCCT再ビルドへ勝手に移行しない。

### 工程2：交差検査の実装

OCPに依存しない判定部分をテストし、内部点列を受け取るアダプターを接続する。
最小例と保存済みの6面で既知の交差を拾えること、共有端点の偽陽性を除けることを確認する。
検出対象を既知の面番号やフィレット形状に限定しない。

### 工程3：共有辺の再分割ループ

最小例で検出辺を再分割し、隣接面への伝播、再検査、停止条件を実装する。
検査直後と面分割直前の点列を確認し、標準処理が検査済み境界を上書きしていないことを確認。
共有辺の離散点・対応順序・向きを確認してから元モデル全体へ適用する。

### 工程4：製品経路と成果物検査への接続

共通ヘルパーから通常・選択的メッシュ化を呼ぶ。面ID、面の向き、返却形式を維持する。
選択的メッシュ化は別compoundで処理するため、同一呼び出し内の共有辺の保証だけでは不十分。
粗密の境界を既存方式がどう扱うか確認し、更新漏れ・古いキャッシュの再利用を防ぐ。
両経路で同じ要求条件のときに出力が一致することを試験する。

最終ソリッドのメッシュでは接続6項目と適切な自己交差検査を実行する。
閉鎖性や成分数の条件を一般の開いた面や複数ボディへ拡張しない。
既存の`make_material`／`inspect_solid`を使う場合は対象が元CADではなく**生成した三角形**であること、
修復操作で不具合を隠していないことを確認する。重い検査は重複実行を避ける。
独立した検査器を追加する場合は正当な共有辺接触の扱いと依存コストを評価する。

STLはfloat32に丸めた実際の座標について再検証する。これは交差修復とは別の出力検証。
元のfloat64が正常でもfloat32で縮退することがある。頂点を動かしたり三角形を消したりして通さない。
丸めで不正になった場合は理由を示して書き出しを止める。検証前に既存の出力ファイルを上書きしない。
一般のSTL出力に新たな単一ソリッド制約を課さない。最適化結果の厳格な契約を保つ。

### 工程5：実モデルの合格と記録

最適化全体を繰り返す必要はない。保存済み最終BREPを直接メッシュ化して評価する。
元モデルが失敗したまま最小例だけの成功で完了扱いにしない。
収束しない場合は残った面・辺と境界を保存し、検出不足、再分割不足、面分割器内部の問題を切り分ける。

## 8. テストと合格条件

| 層 | 必須の試験 |
|---|---|
| 判定 | 通常交差、浅い交差、微小ループ、ほぼ共線、重なり、非隣接接触、正当な共有端点、隣接辺の折り返し |
| 数値 | 平行移動・拡大縮小、floatの符号判定が曖昧になる例、有限値チェック。固定epsilonへの依存を検出 |
| CAD表現 | 円柱のseam、球の極、穴を持つ面、2辺wire、開いた面、共有辺を逆向きに使う面 |
| 再分割 | 共有辺の全pcurve更新、片側だけ更新する実装を検出する試験、変化なし・上限到達の終了 |
| 最小再現 | 元の3面ソリッド、平面位置±0.01 mm、隙間幅の対照例。形状変更なしで検出・修復 |
| 実モデル | 元の112467面をdeflection=0.2で処理し、欠落ゼロ、境界交差ゼロ、完成メッシュ検査に合格 |
| 出力 | float32のSTLを読み戻して検証。同条件の表示／出力経路の三角形一致 |
| 非回帰 | 既存finalization、final_shape、STL、adaptive_resolution、mesh_bodyの関係するテスト |

合格条件：

- 元の問題形状と最小例で、面の欠落がなく、境界辺・非多様体辺・向き不整合・非多様体頂点・縮退・重複がゼロ。
- 最終成果物に不正な三角形自己交差がなく、元の最終ソリッドとして必要な接続条件を満たす。
  空洞を持つ一般ソリッドでは表面成分が複数でも正当なので、成分数1を汎用条件にしない。
- 実際に面分割へ渡す境界の交差がゼロ。GetStatusFlagsや三角形数だけでは合格にしない。
- BREPの曲面・曲線・位相構造を変更していない。メッシュキャッシュが変わるのでファイルのバイト一致は要求しない。
- 正常形状を壊さず、未解決例は有界時間で診断付きの失敗になる。

実測する性能：総時間、検出時間、再分割時間、面分割時間、成果物検証時間、
再分割辺数、反復数、最終点数・三角形数、ピークメモリ。
通常形状と元モデルの両方で既存経路と比較する。未測定の性能保証は付けない。
