# 実装計画：境界交差の検出と共有辺の再分割（案A）

作成日：2026-09-23。状態：**実装済み(2026-09-23)**。実装・実測・未検証事項は
[TOPOPT_GAP_CAUSALITY.md「案Aの実装と実測」](TOPOPT_GAP_CAUSALITY.md#案aの実装と実測2026-09-23)。

## 1. 目的

トポロジー最適化の最終CADで、フィレット付き保持穴と単純な除外円柱の間にある細い領域が、
メッシュ化時に欠落する問題を修正する。境界曲線の折れ線近似が自己交差を作るため、
面を三角形分割する前に交差を検出し、問題のCAD辺だけを再分割する。

OCCT本体は改造・再ビルドせず、Python/OCPから処理段階を制御する案Aを採用した(独自の面三角形
分割器・メッシュboolean・ボクセル化・穴埋め・頂点の距離による一括統合は導入しない)。

確実性の契約は「未解決の境界交差・不正な最終メッシュを成功として返さない」。
任意の入力が有限回で必ずメッシュ化できるという保証ではない。

## 2. 採用理由と残る不確実性

詳細は[TOPOPT_GAP_CAUSALITY.md](TOPOPT_GAP_CAUSALITY.md)。

- OCCTのFaceCheckerは小ループや浅い方向角の交差を無視するため、独立した交差検査が必要
  (正常な閉じた3面ソリッドでも、通常のdeflection=0.2で境界辺6・非多様体辺2・非多様体頂点7を再現する)。
- OCPには内部モデル・辺の離散化・3D/2D境界の再生成APIが公開されているが、過去の内部モデル操作には
  native終了の実績がある。APIが呼べることと、安全に一連の処理を段階制御できることは別。
- ForceFaceDeflection等の設定変更は最小例を改善するが、元モデル全体は修復できない。
- 依存は`pyproject.toml`の`cadquery-ocp-novtk==7.9.3.1.1`。

## 3. (実装した接続箇所は `duocad/kernel_meshing.py`・`duocad/boundary_check.py`・`duocad/mesh_intersections.py`。既存の面ID・返却形式は変えていない。詳細は `TOPOPT_GAP_CAUSALITY.md`「案Aの実装と実測」)

## 4. 目標となる処理と不変条件

```text
以前の三角形キャッシュを破棄
  → OCCT内部モデルを構築
  → 辺を通常精度で離散化
  → 必要な標準の境界整合処理
  → 独立した境界交差検査
  → 問題辺を再分割 → 全隣接面を再検査（解消するまで反復）
  → 面分割前の最終境界検査
  → OCCTの面分割・後処理
  → 出力された境界が検査済みの境界と整合することを確認
  → 面別payload、必要な成果物検査
```

これは概念順序。**境界を変更する最後の標準処理の後、DiscretizeFacesの前**を独立検査の保証点にする
(検査後に標準処理が境界を変更するなら、もう一度検査する)。

不変条件：

1. CADの曲線・曲面・位相接続は変更しない。変更するのは離散化とそのキャッシュだけ。
2. 同じCAD辺の3D点列は一元管理し、全ての利用面・pcurveへ更新を伝播する。
3. 一つの面だけを独立に再メッシュ化して差し戻さない。
4. 交差点を新しいCAD頂点として結合しない。元の曲線に沿って細分化する。
5. 全体の要求精度を緩めない。局所的に細かくすることだけを許す。
6. 汎用メッシュ化では開いた面・シェルも許す。閉鎖性・単一ソリッドはその契約を持つ最終処理で検査する。

## 5. 境界交差検出

入力は、面分割器が実際に使う内部pcurveの離散点列と、元の辺・頂点・wire・向きの識別情報。
全てのwireを扱い、同一wire内、wire間、同じ曲線内の離れた線分の交差を検査する。

- **判定**: 線分の外接矩形で候補を絞り、2Dの向き判定で交差・接触・重なりを分類する。面積や角度が
  小さいことを理由に候補・交差を捨てない。deflectionを交差判定のepsilonに流用しない。浮動小数点の
  高速判定には数学的な誤差境界を使い、符号が確定しない場合だけ厳密演算(floatの厳密な有理数表現)へ
  進む。固定epsilonによる近似判定は不可。接続予定の共有端点はCADの接続情報で識別し、隣接線分の
  ペアを丸ごと除外せず端点以外の重なりを検出する。CAD端点とpcurve端点に小さな差がある場合は
  許される端点接続だけを局所的に照合し、区別できない場合は成功にせず曖昧として診断する。
- **周期曲面・特異点**: 円柱のseamは同じ辺が同じ面に異なるpcurveとして現れるので、辺そのものでなく
  **辺の利用箇所(wire内の位置・向き・pcurve)**を区別する。UVの周期をまたぐ見かけの飛びや球の極の
  縮退は、そのまま通常の交差に数えない。

検出結果は面ID・wire/辺ID・線分番号・分類(交差・接触・重なり・曖昧)・関係するCAD辺の集合を持つ。

## 6. 共有辺の再分割

問題辺を重複排除し、deflectionを1/3にして元の曲線から再生成する(OCCTのEdgeAmplifierと同じ方針)。
再分割後は関係する全ての面を作業キューへ戻す。交差数が一時的に増えても失敗にしない
(細分化しても交差数が単調減少する保証はない)。

停止条件：

- 全面の境界交差・未分類接触が解消したら次へ進む。
- 問題辺の全点列が変化しない、または同じ状態へ循環したら未解決として停止。
- 許容値の下限・最大反復回数(初期評価は12巡を仮置き)・最大点数に達したら停止する。
  12巡以内に収束するという保証ではない。

本当に交差する入力境界は再分割では直らないので、成功扱いにせず有界時間で失敗させる。

## 8. テストと合格条件

必須の試験観点: 判定(通常交差・浅い交差・微小ループ・ほぼ共線・重なり・非隣接接触・正当な共有端点・
隣接辺の折り返し)、数値(平行移動・拡大縮小、floatの符号判定が曖昧になる例)、CAD表現(円柱のseam・
球の極・穴を持つ面・2辺wire・開いた面・共有辺を逆向きに使う面)、再分割(全pcurve更新・片側だけ更新
する実装の検出・変化なし/上限到達の終了)、最小再現(元の3面ソリッド・平面位置±0.01mm)、実モデル
(元の112467面をdeflection=0.2で処理し、欠落ゼロ・境界交差ゼロ)、出力(float32のSTLを読み戻して検証)。

合格条件：

- 元の問題形状と最小例で、面の欠落がなく、境界辺・非多様体辺・向き不整合・非多様体頂点・縮退・重複がゼロ。
- 最終成果物に不正な三角形自己交差がなく、元の最終ソリッドとして必要な接続条件を満たす
  (空洞を持つ一般ソリッドでは表面成分が複数でも正当なので、成分数1を汎用条件にしない)。
- 実際に面分割へ渡す境界の交差がゼロ。GetStatusFlagsや三角形数だけでは合格にしない。
- BREPの曲面・曲線・位相構造を変更しない(メッシュキャッシュは変わるのでファイルのバイト一致は要求しない)。
- 正常形状を壊さず、未解決例は有界時間で診断付きの失敗になる。

実測する性能: 総時間、検出時間、再分割時間、面分割時間、成果物検証時間、再分割辺数、反復数、
最終点数・三角形数、ピークメモリ。未測定の性能保証は付けない。
