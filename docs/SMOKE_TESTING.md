# duocad — 実機検査（puppeteer smoke / acceptance）の書き方

**読むとき**: `web/scripts/smoke-*.mjs` を書く・直す・赤の原因を切り分けるとき。
走らせ方は README §3。共有部品の使い方は各ファイル冒頭 —— 骨格は `harness.mjs`（`runSmoke`）、
画面を開く・エラーの確認・入力・待ちは `browser.mjs`（`openApp` / `assertNoAppErrors` / `typeInto` /
`waitOrFail` / `waitFrames`）、射影してクリックする手と面の名指し（`planarFace`）は `pick.mjs`、
MCP で箱を作る手は `mcp-client.mjs`。
編集中のスケッチは各本で `sketches` から引き直さず、フックの `window.__duocad.sketch` を読む。
ここは**座標・待機・fixture・環境の落とし穴**と、それに対する作法。落とし穴が名指す本の多くは
2026-10-04 に消した（下記）。作法として読み、実物が要るときは git の履歴から引く。

## 何を smoke に書くか（2026-10-04）

**smoke に書くのは、実ブラウザでないと確かめられない結線だけ。** 本物のポインタ・キー入力が
DOM / WebGL のピックを経てサーバへ届き、描画へ戻るまでの繋がり、レイアウト、フォーカス、実際の描画結果。

- **人が使っていてすぐ気づける壊れ方は、smoke で守らない**（本人指示）。

  > 人間が使っていてすぐに気づけるもの（verbが出ていないとか、クリックがずれるとか、カーソルの強調表示が
  > おこなわれないとか）はテストで守らなくていい。そういうものを守っているテストを優先的に削減したい

  smoke に残すのは、**使っていても気づけない壊れ方**だけ: 見た目が同じまま値だけ違う（スナップが効かず
  座標が 0.3mm ずれる・重なった面と基準平面の取り違え）、黙って別のものが変わる（入力欄の Ctrl+Z が文書を
  戻す・AI の選択で即適用が走る・別のスケッチの選択が持ち越される・既存の荷重が黙って書き換わる）、
  タイミングでしか出ない競合、性能と粗さ。
- **サーバ・コアの契約は pytest に書く。** 画面を入力手段に使って同じ契約を確かめ直さない。
- **TS の純関数は `tests/eval_*.mjs` に書く**（`tests/test_ts_evaluators.py` が pytest から走らせる）。
- **verb を足すたびに smoke を足さない。** 足すのは、既存の本が通していない結線（新しい種類のピック・新しい
  引数の集め方・新しい描画）を持つときだけ。
- **同じ結線を2本で通さない。** 足す前に `web/scripts/smoke*.mjs` を語で検索する。

根拠の実測（smoke を触った 140 コミットの分類）: コストの主因は flake ではなく、**書いた量と、仕様変更が
多数本へ波及する結合**（製品の仕様変更への追従 42 件、うち 13 件は1つの変更で 3 本以上を直した。smoke が
赤くなって製品のバグが見つかったのは 2 件）。この基準で 30 本 12,713 行 → 5 本 959 行
（`smoke.mjs` / `smoke-sketch.mjs` / `smoke-mirror.mjs` / `smoke-face-culling.mjs` / `smoke-resolution.mjs`）に削り、
残した検査は製品を1か所ずつ壊して赤になることを確かめた。その過程で素通りが2つ見つかった:

- **吸い付き先が 1mm 格子の上にあると、点へのスナップの検査にならない**（スナップを切っても丸めが同じ座標を
  返す）。吸い付き先は格子から外す。
- 「AI の選択で即適用が走らない」は、`selfSelections` の数え方を壊しただけでは赤にならない（貼り先は人のクリック
  でしか埋まらないという別の守りが残る）。両方が壊れたときに赤になる。

## 大前提

- **配るのは `web/dist`**（ビルド成果物）。`web/src` を触ったら `npm run build` を挟まないと古い束を検査する
  （削除したはずのパネルが束に残ったまま合格した実例がある）。`npm run check` はソースを見るのでこの罠に掛からない。
- **選択の正はコア。クリック直後に `window.__duocad.selection` を読まない** —— `modify_selection` の往復前の値が
  返る。選択に関する判定は必ず `page.waitForFunction` で書く。**Esc・中断・確定でコマンドが終わった直後も同じ**
  （終了で `clear_selection` を送るので往復が挟まる。直後に `look()` で件数を読むと毎回落ちた）。
- **1回の走行で結論を出さない。** 赤が出たら pristine（`git show HEAD:<path>` で戻す。共有インデックスを通る
  `git stash` は避ける）と変更後をそれぞれ**2回以上**走らせる。pristine で安定緑・変更後で安定赤なら本物、
  両方緑なら flake。`smoke-move.mjs` の最初の検査（左ドラッグでカメラが動かないこと）は原因未特定で間欠的に落ちる。
- **検証範囲は「触ったファイル」ではなく「スイート」で選ぶ。** 部分実行にするなら回さなかったスイート名を
  完了報告に書く。壊れているのを見つけた側は二分して犯人のコミットを名指してから次へ渡す。
- **IDクリック方式は到達可能性しか検査しない。** `page.click('#sketch-new-XY')` の緑は「要素が存在して押せる」
  だけ（画面外でも自動スクロールで緑）。**発見可能性（主要な操作面に居るか・ラベルが操作を表すか）は自動検査の
  外側に残る。**

## 座標: 射影は「押す直前」に、「対象を名指しして」

- **画素はコマンドをまたげない。** ツールバーは起動中のコマンドの引数を出すので、コマンドを移るとビューポートの高さが
  変わる（実測 636px→669.5px）。同じコマンドの中でも引数が1つ埋まると文言が変わって寸法が動く。
  **世界座標を持ち越し、押す直前に射影し直す**（`window.__duocad.projectSketchPoint(u, v, sketchId)` /
  `projectFace` / `projectEdge` / `projectPoint`）。`.viewport` の bounding rect も使い回さない
  （起動/中断をまたぐたびに取り直す）。
- **射影 → ボタンを押す → クリック の順で書かない。** 状態を変える操作を全部済ませてから射影する。視点を
  動かした直後はカメラの減衰が数十ms 動き続けるので、**2回続けて同じ画素に射影できるまで待つ**。
- **対象は法線や寸法で名指しする**（例: `normal[1] < -0.9` の手前の壁。`pick.mjs` の `planarFace`）。
  「その視点で最初に射影できた面」を選ぶと検査が視点に暗黙依存し、fixture から穴を外しただけで面の並びが変わって
  基準平面の向こう側の面を掴んだ。名指しした対象が射影できなければ失敗にする —— 「別のものに逃げて緑」が消える。
  述語で集めた辺の先頭を黙って使うのも同種（直前のフィレットが作る長さ 1.57mm の円弧を掴んだ。
  `measure` で一番長い辺を選ぶ）。
- **`projectFace` は「たまたま条件を満たした三角形の重心」を返す。** カメラを動かすと画面座標が数十px 跳ぶ
  （画角 45→60 で 27.3px。重心を射影すれば 3.5px）。**視点・画角の違いを比べる測定点には `projectPoint(face.centroid)`
  を使う。** `projectFace` が要るのは実際にクリックする手だけ。
- **`projectPoint` は z だけを見て x/y はクリップしない。** 非 null でも画面外のことがある。「映ったか」は
  `.viewport` の rect と突き合わせる（`pick.mjs` の `zoomOutUntilVisible`）。画面外へ `page.mouse.move` しても
  例外は出ず、`pointermove` が canvas に届かないだけ。
- **部分的に変形した後のクリック座標は、その時点の実パラメータから計算し直す。** 動かす前の定数と動かした後の値を
  混ぜると傾いた線分の中点から 4.5mm ずれ、当たり半径の外に出てタイムアウトする。
- **ビューポートが狭まると縮むのは u 軸（横）だけ**（垂直 FOV 固定）。座標を勘で詰め直さず
  `projectSketchPoint(u, v)` を候補グリッドで実測して選ぶ。**開いた図形（線分・円弧）は矩形の外に完全に離す**
  —— 矩形の内側を横切ると `regions()` が平面をすべての辺で割り、押し出しが
  `join produced an invalid shape (BRepCheck)` で壊れる。
- **基準平面へ貼る手順はソリッドが1つも無いうちに済ませ、貼れた平面を毎回検算する**（`sketches[i].frame` の
  `origin` / `normal`）。`projectBasePlane` が返す画素は部品の輪郭のすぐ外側になることがあり、1画素ずれると
  側面に貼られ、後続のアサーションはそれで全部通ってしまう。

## 待機

- **`__duocad.stateEpoch`（状態が1通届くたびに増える番号）で待つ。** 「画面に届いた値が変わらなくなったら落ち着き」は
  サーバが単一イベントループなので**重い測り直しの最中は何も届かず「もう何も起きない」と区別が付かない**。
  手を打つ前の番号を控え → 増えるまで待つ（増えなければ**検査側の間違い**として落とす。0秒と記録しない）→
  増えなくなって2秒経ったら完了 → 所要は最後に増えた時刻まで。既知の値を再現できることがベンチの唯一の証拠。
- **「A と B が一致したら準備完了」は初期値が同じなら判定にならない**（ビューポートの目標偏差とサーバのメッシュ
  偏差はどちらも既定 0.2mm なのでズーム前から真）。`worldPerPixel > 0` を足し、**その値が複数回続けて同じ**ことを見る。
- **ズーム直後のホバー読みは時々落ちる**（測り直しでスケッチの折れ線が作り直される最中）。`stateEpoch` が止まるまで
  待ち、ホバーの読みは null なら数フレーム置いて読み直す（最大3回）。**当たり側だけが救われる非対称な待ち**に
  すること —— 外れ側は何度読んでも null なので判定は緩まない。
- **`wantsEdges === true` は辺の実データが届いた印ではない。** 辺のキャッシュの版が違えば `showEdges(null, [])` で
  空にしてから非同期で取り直す。その間 `projectEdge` は全 index に null を返し、ループが `continue` で撃ち切って
  クリックを1回も発生させずに fail する（エラーは出ない）。**`projectEdge` がどれか1本非 null を返すまで待ち、
  ループは最大2周**（`frameAll()` のカメラジャンプが可変解像度を誘発し、配信で `clearEdges()` が走りうる）。
- **再入場直後の `lookAtSketch` は数フレーム遅れる。** `activeSketch === id` が解決した直後の `projectSketchPoint` は
  まれに null。数フレーム待つ（`browser.mjs` の `waitFrames`）。**視野はそのとき存在する図形にしか合わない**ので、
  スケッチへ入った直後に検査で使う図形を全部描く。取り込みで図形が増えても再フレームされないので、取り込み直後に
  `#sketch-look` を押して寄り直す。
- **`page.click()` は disabled ボタンに黙って何もしない。** 非同期で有効化される UI は、クリックの前に
  「クリック可能になったこと」を `waitForFunction` で待つ（15分のタイムアウトいっぱいまでハングした実例）。
- **`page.waitForTimeout` は puppeteer-core 25 に無い。** 固定時間待ちは `browser.mjs` の `sleep(ms)`。
  既存スクリプトは `waitForFunction`（落ちたら中身を添える `waitOrFail`）と `waitFrames(page, 2)` を優先。
- **`__duocad` に Svelte の `$state` オブジェクトをそのまま出すと、`page.evaluate` の戻り値では `{}` になる**
  （`window.__duocad.errors` も同じ。`?? []` で読んで `length > 0` を見ていた本は永久に緑だった）。数値の比較が
  `Math.abs(undefined - x) > tol` だと NaN で**素通り**する。フック側は `$state.snapshot(...)` で素のオブジェクトにして
  出し、検査側の数値比較は「どちらも数値であること」を先に見る。`assertNoAppErrors` はページの中で配列かどうかを
  見てから素の配列にして返す。

## 選択・モード

- **ウィンドウ選択は完全包含された面・辺・頂点・領域・スケッチ図形を全部拾う。** 「長方形1つだけが選ばれた」は
  先に `item.entity !== undefined` で図形だけに絞る。図形まるごとは `point: null` で入る。
- **`modify_selection` は `remove` に隠れた Body の古い参照が1つでも混じると操作ごと弾く**（トーストにしか出ず
  選択は古いまま静かに変わらない）。Body を隠す・削除するなど「以前の選択が指せなくなる」操作の直後は、
  次に選択を変える前に空の場所をクリックして選択を空にする。
- **スケッチモード中は `wantsRegions` / `wantsBasePlanes` が絶対に真にならない**（通常モード限定の定義）。待つと
  必ずタイムアウト。`projectRegion(index)`（第2引数省略で `activeSketch`）を直接呼んでクリックする。
- **確定成功で無起動へ戻る**（[UI.md](UI.md)）。確定後に「構えたまま」を期待する検査は古い。
- **確定前の幽霊は無関係な再配信で消える**（[UI.md](UI.md)）。「幽霊が出ない」の偽の失敗は、実際には出ていて
  直後に消されていた。状態配信が止まるまで待ってから打つ。
- **`applied.verb` / `applied.change` に依存する挙動は、MCP 経由ではなく本物の DOM 操作で起こす。** MCP 起点の
  変更は `applied` を持たずに配信されるので、検査したい分岐を通らないまま別の経路で緑になる。
- **モーダルを開く手を足したら次の手の前に必ず閉じる。** `showModal()` の `::backdrop` は top-layer で全画面を占め、
  `elementFromPoint` が `<dialog>` を返すので `project*` が全部 null になる。

## fixture

- **「空き地」は既存図形の輪郭から余裕を持って離す**（目安 10mm 以上、または `hoveredRef()` で実測）。典型的な
  フレーミングで**輪郭から 4mm は吸い、5mm は吸わない**（閾値はカメラ距離依存）。数mm で設計した fixture は
  当たり判定を伴う機能が入るたびに壊れる。
- **前段の検査が実行時に置いた端点からも離す**（順序型）。前段が置いた線分の端点へスナップし、`Math.round` を
  経由しない射影誤差（`15.000000000000002`）が返って「丸めが効いていない」に見えた。切り分け: entity params を
  ダンプ → クリック前のマウス移動だけで `hoveredRef()` を呼び同じ当たりが出るか。
- **図形の値の個数を固定した検査は語では検索できない。** 図形が持つ値の個数を変える変更は実機 smoke を全部回すのが
  唯一の検出手段。
- **表示先をトーストのような消える UI へ移すと、走行の最後に一度だけ見る検査が黙って弱くなる。** 今出ている札は
  DOM、走行全体の有無は消えない控え（`window.__duocad.errors`）、と読む先を分ける。
- **`look()` / `snapshot()` のような観測ヘルパは返す値の形が変わりやすい。** `.sketches.length` と書いていたが
  実体は件数で、`undefined !== undefined` が常に偽のまま起動時から何も検証せず緑だった。数値を読む検査は
  `Number.isFinite` を条件に入れる（[WEB_PITFALLS.md](WEB_PITFALLS.md)）。
- **検査を足す・直したときは一度わざと壊して赤を見る。終了コードで。** 各セクションが例外を catch して
  「途中で止めない」作りの本は、❌ が何個並んでも `exit 0` になりうる。「止めない」と「合格を出さない」は別の設計判断。
- **「画面に収める」の検査は在否ではなく寸法で書く。** 「対象を1つでも射影できたか」は、画角 90 でシーンが本来の
  0.4倍にしか写らなくても緑。全画角で射影できた面だけで広がりを比べると正常 0.97〜1.10倍・壊れた実装 0.41倍と
  幅ができる（測る対象の集合を揃えないと 0.73倍などになる）。
- **ガードで守られた検査は `ok()` もガードの中に入れ、スキップ時は別の文言を出す。** ガードの直後の無条件 `ok()` は、
  判定対象外の実行でも「検査した・通った」と出す。
- **「合計 > 0」は1つだけ空の部分を隠す。** GPU へ行った三角形数の全面合算では1面が真っ黒でも合格した。面ごと・
  ボディごと・色ごとに数え、1色ずつ隠して落ちることを変異検査で確かめる。比較スクリーンショットは面ごとにレンダラを
  作らず 1枚の canvas に `setScissor` で並べる（カメラ・光源・背景・画角を面ごとに持てなくする）。
- **WebGL 描画が A と B で違うかは PNG のバイト差分で足りる。** 同一入力の連続2枚は差 0 バイト、FOV 違いで
  2995 バイト。`pixelmatch` は要らない（「どれだけ・どこが」は分からない）。
- **「その画素が何色か」は、同じ法線の別の面との比で予想する。** ランバートの色は線形空間で「材質の色 × 光」なので、
  同じ向きの面の画素から光を割り戻せば光源の設定を検査に写さずに済む（切り口: 予想 73,83,95 に対し実測 73,83,94）。
  1×1 のスクリーンショットは左・上の画素が無いのでフィルタ型に関係なく、IDAT を inflate した2〜4バイト目がそのまま RGB。

## 環境

- **手で立てるサーバも `--models-dir` に使い捨てを渡す。** 実機検査は `startServer({modelsDir})` で temp を渡すが、
  手で立てるとリポジトリ直下の実 `models/` に保存され、本人の作業ファイルが 161KB→4.9MB になった。
  `python -m duocad.mcp_server --models-dir $env:TEMP\duocad-scratch`。stdin を閉じない（EOF で即終了）。
  `models/` の差分に「自分が入れた覚えのない操作」が混ざっていたら並行して誰かが触っている印 ——
  `git checkout` を向けない。
- **headless Chrome は実 GPU を掴む。** `--use-angle=swiftshader` が CPU ラスタライズを強制していただけで、
  `--enable-unsafe-swiftshader` は「掴めなかったときソフト GL へ落ちてよい」の許可（残置）。合成負荷では
  SwiftShader が 0.7fps、D3D11 が 36fps だが、**検査の所要時間はほぼ変わらない**（smoke.mjs 163→150秒。律速は
  OCCT/Python 側と WS 往復）。変わるのは CPU 消費だけ。どちらで描いたかは起動時の `GL :` 行に出る
  （黙ってソフト GL へ落ちても検査は通る）。
- **`viewport.ts` の `tick()` は変化が無くても毎フレーム描き**、puppeteer は既定で
  `--disable-background-timer-throttling` を付けるので画面が無くても 60fps で回る。
- **`getBoundingClientRect()` を `page.evaluate` 単体で返すとフィールドが消える**（DOMRect のプロパティはプロトタイプの
  getter で構造化複製に乗らない）。`rect.left` が `undefined` → `page.mouse.click(NaN, NaN)` で落ちる。rect の取得と
  それを使う計算を同じ `page.evaluate` の中で行い、プレーンオブジェクトで返す（`pick.mjs` の `screenOf`）。
- **`typeInto` で数値欄に1文字ずつ打つと、途中の値（「29.999」の「2」）が下限割れになり、通知が `errors` に積まれる。**
  `allow` なしの `assertNoAppErrors` で締めると赤くなる。
