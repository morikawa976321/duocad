# duocad — 実機検査（puppeteer smoke / acceptance）の書き方

**読むとき**: `web/scripts/smoke-*.mjs` / `acceptance.mjs` を書く・直す・赤の原因を切り分けるとき。
走らせ方は README §3。共有部品（`server.mjs` / `browser.mjs` / `mcp-client.mjs`）の使い方は各ファイル冒頭。
ここは**座標・待機・fixture・環境の落とし穴**と、それに対する作法。

## 大前提

- **配るのは `web/dist`**（ビルド成果物）。`web/src` を触ったら `npm run build` を挟まないと古い束を検査する。
  再ビルド無しで3本緑になり、削除したはずのパネルが束に残ったまま「見せかけの合格」を出した実例がある
  （2026-08-27）。`npm run check` はソースを見るのでこの罠に掛からないが、実機検査は独立に掛かる。
- **選択の正はコア。クリック直後に `window.__duocad.selection` を読まない** —— `modify_selection` の往復前の値が返る。
  選択に関する判定は必ず `page.waitForFunction` で書く。
- **1回の走行で結論を出さない。** 赤が出たら pristine（`git show HEAD:<path>` で戻す。共有インデックスを通る
  `git stash` は避ける）と変更後をそれぞれ**2回以上**走らせる。pristine で安定緑・変更後で安定赤なら本物、
  両方緑なら flake。`smoke-move.mjs` の最初の検査（左ドラッグでカメラが動かないこと）は原因未特定で間欠的に落ちる
  （2026-09-06）—— この節だけの赤ならまずもう一度通す。
- **検証範囲は「触ったファイル」ではなく「スイート」で選ぶ。** スケッチのクリック経路を変えたのに `smoke-regions`
  を回さず、翌タスクが踏んで二分から始める羽目になった（2026-09-06）。部分実行にするなら回さなかったスイート名を
  完了報告に書く。壊れているのを見つけた側は二分して犯人のコミットを名指してから次へ渡す。
- **IDクリック方式は到達可能性しか検査しない。** `page.click('#sketch-new-XY')` の緑は「そのIDの要素が存在して押せる」
  だけで、ボタンが主要な操作面に居るか・ラベルが操作を表す語か・初期状態で視線が向くかは見ていない
  （`page.click` は要素を自動スクロールで可視域に入れるので画面外でも緑）。**発見可能性は自動検査の外側に残る**
  —— v1 が 19/19 で満たされたのに本人が「スケッチを開始するUIが無い気がする」と言う状態が両立した。

## 座標: 射影は「押す直前」に、「対象を名指しして」

- **画素はコマンドをまたげない。** ツールバーは起動中のコマンドの引数を出すので、コマンドを移るとビューポートの高さが
  変わる（実測 636px→669.5px）。同じコマンドの中でも引数が1つ埋まると文言が変わって寸法が動く。
  **世界座標を持ち越し、押す直前に射影し直す**（`window.__duocad.projectSketchPoint(u, v, sketchId)` /
  `projectFace` / `projectEdge` / `projectPoint`）。
- **`.viewport` の bounding rect も使い回さない。** 無起動の状態はツールバーが最も短い（引数の行と `#command-abort` が
  DOM から消える）ので、ページ読み込み直後に測った rect をフィレット起動後に足し合わせると別の面を掴む
  （`smoke-hover.mjs` の `viewportBox()` のように、起動/中断をまたぐたびに呼び直す）。
- **射影 → ボタンを押す → クリック の順で書かない。** 起動で「何を待っているか」の1行が入れ替わり、折り返しが変わると
  3Dビューの高さごとずれる。**状態を変える操作を全部済ませてから射影する。** 視点を動かした直後はカメラの減衰が
  数十ms 動き続けるので、**2回続けて同じ画素に射影できるまで待つ**。この時間差は指している面が境界から遠ければ
  隠れる —— 視点を変えた途端、何年も緑だった手が 6回に2回落ちるようになった（2026-08-28）。
- **対象は法線や寸法で名指しする**（例: `normal[1] < -0.9` の手前の壁）。「その視点で最初に射影できた面」を選ぶと
  検査が視点に暗黙依存し、カメラを触った瞬間に別の面が押され、**3セクション先の AI 側の fillet / chamfer が
  `IsDone is false` で落ちる**（押し出した壁の位置が変わって融合の仕方が変わる）。名指しした対象が射影できなければ
  失敗にする —— 「別のものに逃げて緑」が消える。述語で集めた辺の先頭を黙って使うのも同種
  （直前のフィレットが作る長さ 1.57mm の円弧を掴んだ。`measure` で一番長い辺を選ぶ）。
- **`projectFace` は「たまたま条件を満たした三角形の重心」を返す。** カメラを動かすと勝ち残る三角形が入れ替わり、
  同じ面なのに画面座標が数十px 跳ぶ（画角 45→60 で 27.3px。重心を射影すれば 3.5px）。**視点・画角の違いを比べる
  測定点に `projectFace` を使わない** —— `projectPoint(face.centroid)`。`projectFace` が要るのは実際にクリックする手だけ。
- **`projectPoint` は z だけを見て x/y はクリップしない。** 戻り値が非 null でも画面外（NDC 7.5 のような値）のことが
  ある。「映ったか」の判定は `.viewport` の rect と突き合わせる（`smoke-grid-scale.mjs` の `zoomOutUntilVisible`）。
  画面外へ `page.mouse.move` しても例外は出ず、`pointermove` が canvas に届かないだけ。
- **カメラと同じ象限の部品を選ぶ。** 基準平面の当たり範囲がモデルを覆うので、原点をまたいだ反対側（ホームビューが
  −Y 側なら Y>0 側）の面へのレイは先に座標平面をくぐり、基準平面が勝つ（[VIEWPORT.md](VIEWPORT.md)）。
  bbox を見て危険な部品を除外してから候補を探す（`smoke.mjs`）。
- **部分的に変形した後のクリック座標は、その時点の実パラメータから計算し直す。** 線分の片端だけ動かした後に
  `(LINE.x0 + LINE.x1) / 2, moved.params.y0` のように**動かす前の定数と動かした後の値を混ぜる**と傾いた線分の
  中点から 4.5mm ずれ、当たり半径の外に出てタイムアウトする（`smoke-move.mjs` で計4箇所）。
- **ビューポートが狭まると縮むのは u 軸（横）だけ**（垂直 FOV 固定・水平は aspect に比例）。座標を勘で詰め直さず
  `projectSketchPoint(u, v)` を候補グリッドで実測して選ぶ。横が窮屈なら v 軸方向へ逃がす。
  **開いた図形（線分・円弧）は矩形の外に完全に離す** —— 矩形の内側へ動かして内部を横切ると `regions()` が
  平面をすべての辺で割り、押し出しが `join produced an invalid shape (BRepCheck)` で壊れる。閉じた図形（円）は内側でも穴になるだけ。
- **基準平面へ貼る手順はソリッドが1つも無いうちに済ませ、貼れた平面を毎回検算する**（`sketches[i].frame` の
  `origin` / `normal`）。`projectBasePlane` が返す画素は部品の輪郭のすぐ外側になることがあり、1画素ずれると側面に貼られ、
  後続のアサーションはそれで全部通ってしまう（2026-08-23）。

## 待機

- **`__duocad.stateEpoch`（状態が1通届くたびに増える番号）で待つ。** 「画面に届いた値が変わらなくなったら落ち着き」は
  サーバが単一イベントループなので**重い測り直しの最中は何も届かず「もう何も起きない」と区別が付かない**
  （0.45秒の静けさで打ち切ったベンチはカリング入り/切りで同じ数値を返し、待ちを伸ばすと1測定ぶん遅れた値が並んだ）。
  手を打つ前の番号を控え → 増えるまで待つ（増えなければ**検査側の間違い**として落とす。0秒と記録しない）→
  増えなくなって2秒経ったら完了 → 所要は最後に増えた時刻まで。既知の値を再現できることがベンチの唯一の証拠。
- **「A と B が一致したら準備完了」は初期値が同じなら判定にならない。** ビューポートの目標偏差とサーバのメッシュ偏差は
  どちらも既定 0.2mm なのでズーム前から真になり、待機が 0ms で抜けた。`worldPerPixel > 0`（一度は採った）を足し、
  さらに**その値が複数回続けて同じ**であることを見る。
- **ズーム直後のホバー読みは時々落ちる**（測り直しでスケッチの折れ線が作り直される最中に読む）。視点を動かした後は
  `stateEpoch` が止まるまで待ち、ホバーの読みは null なら数フレーム置いて読み直す（最大3回）。
  **当たり側だけが救われる非対称な待ち**にすること —— 外れ側は何度読んでも null なので判定は緩まない。
- **`wantsEdges === true` は辺の実データが届いた印ではない。** `CommandHost` の同期的な `$effect` で即座に立つが、
  辺のキャッシュの版が違えば `showEdges(null, [])` で空にしてから非同期で取り直す。その間 `projectEdge` は全 index に
  即 null を返し、ループが `continue` で撃ち切ってクリックを1回も発生させずに fail する（エラーは1つも出ない）。
  **`projectEdge` がどれか1本非 null を返すまで待ち、ループは最大2周**（`frameAll()` のカメラジャンプが可変解像度を
  誘発し、届いた配信で `clearEdges()` が走ってループの途中で辺が消えうる）。修正後6回連続緑（修正前 5回中2回）。
  製品側の「起動直後は辺が指せない窓がある」は実挙動として残る。
- **再入場直後の `lookAtSketch` は数フレーム遅れる。** `activeSketch === id` が解決した直後に `projectSketchPoint` を
  呼ぶとまれに null。`settle()` を挟む。**視野はそのとき存在する図形にしか合わない**ので、スケッチへ入った直後に
  その検査で使う図形を全部描く（後から離れた場所を足すと視野の外へ出る）。`smoke-svg.mjs` は取り込みで図形が増えても
  再フレームされず、丘の領域の三角形が画面上で数px しかなくて `projectRegion` が恒久的に null だった —— 取り込み直後に
  `#sketch-look` を押して寄り直す（3回連続 PASS）。
- **`page.click()` は disabled ボタンに黙って何もしない。** 非同期で有効化される UI は、クリックの前に
  「クリック可能になったこと」を `waitForFunction` で待つ。15分のタイムアウトいっぱいまでハングしてから失敗した実例。
- **`page.waitForTimeout` は puppeteer-core 25 に無い。** 固定時間待ちは
  `page.evaluate(() => new Promise((r) => setTimeout(r, ms)))`。既存スクリプトは `waitForFunction` と `waitTwoFrames` を優先。
- **`__duocad` に Svelte の `$state` オブジェクトをそのまま出すと、`page.evaluate` の戻り値では `{}` になる**
  （2026-09-16、`smoke-measure.mjs` で実測。プロキシは CDP の値の持ち帰りで中身が落ちる）。数値の比較が
  `Math.abs(undefined - x) > tol` だと NaN で**素通り**するので、二重に気づけない。フック側は
  `$state.snapshot(...)` で素のオブジェクトにして出し、検査側の数値比較は「どちらも数値であること」を先に見る。

## 選択・モード

- **ウィンドウ選択は完全包含された面・辺・頂点・領域・スケッチ図形を全部拾う。** 長方形を囲むとその領域の参照も入るので、
  「長方形1つだけが選ばれた」は先に `item.entity !== undefined` で図形だけに絞る。図形まるごとは `point: null` で入る。
  辺のクリックで長方形を指す道は内側の領域と重なって当たりが不安定 —— 囲むほうが確実。
- **`modify_selection` は `remove` に隠れた Body の古い参照が1つでも混じると操作ごと弾く**（add 側も含めて。
  トーストにしか出ず選択は古いまま静かに変わらない。2026-09-06）。Body を隠す・削除するなど「以前の選択が指せなくなる」
  操作の直後は、次に選択を変える前に空の場所をクリックして選択を空にする。
- **スケッチモード中は `wantsRegions` / `wantsBasePlanes` が絶対に真にならない**（通常モード限定の定義。スケッチモード中の
  領域ピックは `setActiveSketch` 側の規律で常時動く）。待つと必ずタイムアウト。`projectRegion(index)`（第2引数省略で
  `activeSketch`）を直接呼んでクリックする。
- **確定してもコマンドは既定へ戻らない前提のスクリプトは古い。** 2026-08-31 以降、確定成功で無起動へ戻る。
  ツールバーのコマンドを Enter で確定した後に `#distance` が無い、のような落ち方は逆に「構えたまま」を期待している側。
  `smoke-regions.mjs` は「領域を押し出して確定した後も `wantsRegions === true`」という 2026-08-30 時点の仕様を
  期待していた箇所があった —— 直すときは検査側を今の仕様へ書き直す。
- **確定前の幽霊は無関係な再配信で消える**（[UI.md](UI.md)）。「幽霊が出ない」で60秒タイムアウトした偽の失敗は、
  実際には出ていて直後に消されていた —— 時系列で複数回サンプルするまで分からなかった。状態配信が止まるまで待ってから打つ。
- **`applied.verb` / `applied.change` に依存する挙動は、MCP 経由ではなく本物の DOM 操作で起こす**
  （`smoke-files.mjs` の作法）。MCP 起点の変更は `applied` を持たずに配信されるので、検査したい分岐を一度も通らないまま
  別の経路で緑になる（`smoke-reframe-on-import.mjs` を書く過程で実際に踏んだ）。`smoke-mcp.mjs` は逆にこの仕様を
  「AI が操作したら画面が変わる」経路として検査対象にしている。
- **モーダルを開く手を足したら次の手の前に必ず閉じる。** `showModal()` の `::backdrop` は top-layer で全画面を占め、
  `elementFromPoint` がどこを指しても `<dialog>` を返すので `project*` が全部 null になる（設定ダイアログは
  2026-09-04 に非モーダル化して外れたが、他で `showModal()` を足せば同じ）。

## fixture

- **「空き地」は既存図形の輪郭から余裕を持って離す**（目安 10mm 以上、または `hoveredRef()` で実測）。
  スナップ導入後、典型的なフレーミングで**輪郭から 4mm は吸い、5mm は吸わない**（閾値はカメラ距離依存で
  「数mm は危険域」という桁感だけ再利用できる）。ぴったり数mm で設計した fixture は当たり判定を伴う機能が入るたびに壊れる。
- **前段の検査が実行時に置いた端点からも離す**（順序型）。単独では離れているつもりの `(45.4, 15.35)` が、前段が
  `(45,15)` に線分の端点を置いていたため点マーカーへスナップし、`Math.round` を経由しない射影誤差
  （`15.000000000000002`）が返って「丸めが効いていない」に見えた。距離を離しても直らない。
  切り分け: `page.evaluate` で送られた entity params をダンプ → クリック前のマウス移動だけで `hoveredRef()` を呼び
  同じ当たりが出るか → 一致すれば検査の前提にしていた当たり判定が変わったと判断してよい。
- **図形の値の個数を固定した検査は語では検索できない**（`smoke-optimize-mode.mjs` が「新規パラメータは N 個」を
  固定していて、長方形へ `angle` を足したとき落ちた）。図形が持つ値の個数を変える変更は実機 smoke を全部回すのが唯一の検出手段。
- **表示先をトーストのような消える UI へ移すと、走行の最後に一度だけ見る検査が黙って弱くなる。** `smoke-files.mjs` は
  最後に「画面にエラーが出ていないか」を1回見ていた。消えない控え（`window.__duocad.errors`）を検査用に別途残し、
  今まさに出ている札は DOM、走行全体の有無は控え、と読む先を分ける。
- **`look()` / `snapshot()` のような観測ヘルパは返す値の形が変わりやすい。** `sketches` を件数で返しているのに
  `.sketches.length` と書いていて `undefined !== undefined` が常に偽で、起動時から何も検証しないまま緑だった。
  数値を読む検査は `Number.isFinite` を条件に入れておく（Svelte の `$state` プロキシが `{}` で返る潰れも
  「値が無い」として表に出る。[WEB_PITFALLS.md](WEB_PITFALLS.md)）。
- **検査を足す・直したときは一度わざと壊して赤を見る。終了コードで。** `acceptance.mjs` は「途中で止めない」設計で
  各セクションが例外を catch するため、❌ が何個並んでも `exit 0` だった（`fitDistance` を壊しても 0）。
  `failedLabels()` を足して未実行のセクションも失敗に数える。「止めない」と「合格を出さない」は別の設計判断。
- **「画面に収める」の検査は在否ではなく寸法で書く。** 「対象を1つでも射影できたか」は、画角 90 でシーンが本来の
  0.4倍にしか写らなくても緑（中央付近のものはどのみち残る）。3つの画角すべてで射影できた面だけで射影された広がりを
  比べると 0.97〜1.10倍に収まり、壊れた実装の 0.41倍と幅ができる（測る対象の集合を揃えないと 0.73倍などになる）。
- **ガードで守られた検査は `ok()` もガードの中に入れ、スキップ時は別の文言を出す。** `if (nearEdge > 0 && ...) fail()`
  の直後の無条件 `ok('...')` は、判定対象外の実行でも「検査した・通った」と出す（`smoke-clip-planes.mjs`）。
  near/far の外接球 containment は near 側と far 側が鏡像で同じ姿勢では片方しか検査できない。
- **「合計 > 0」は1つだけ空の部分を隠す。** 比較スクリーンショット撮影台で GPU へ行った三角形数を全面合算で見ていたので、
  1面が真っ黒でも合格した。面ごと・ボディごと・色ごとに数え、1色ずつ隠して落ちることを変異検査で確かめる。
  面ごとにレンダラを作らず 1枚の canvas に `setScissor` で並べるのは、カメラ・光源・背景・画角を面ごとに持てなくする
  （比較の土俵をずらせない構造にする）ため。
- **WebGL 描画が A と B で違うかは PNG のバイト差分で足りる。** 同一入力の連続2枚は決定論的に差 0 バイト、
  FOV 違いで 2995 バイト。`pixelmatch` を足さずに済む（「どれだけ・どこが」は分からない）。

## 環境

- **手で立てるサーバも `--models-dir` に使い捨てを渡す。** 実機検査は `startServer({modelsDir})` で必ず temp を渡すが
  手で立てるとリポジトリ直下の実 `models/` に保存され、本人の作業ファイルが 161KB→4.9MB になった（テスト用 STEP の
  `import_step` が1件追記された形。`git diff` で気づくまでコミット対象に紛れていた）。
  `python -m duocad.mcp_server --models-dir $env:TEMP\duocad-scratch`。stdin を閉じない（EOF で即終了）。
  消し忘れたサーバは別セッションや本人のブラウザが繋ぐので、`models/` の差分に「自分が入れた覚えのない操作」が
  混ざっていたら並行して誰かが触っている印 —— `git checkout` を向けない。
- **headless Chrome は実 GPU を掴む。** `--use-angle=swiftshader` が CPU ラスタライズを強制していただけで、
