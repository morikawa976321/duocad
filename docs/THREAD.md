# ねじ verb の設計（3Dプリント前提）

**状態: 実装済み**（2026-10-23。`duocad/kernel_thread.py`・`duocad/verbs/thread.py`）。ねじ山の形・寸法・隙間を疑うときに読む。
山形と隙間の数値の根拠（試し刷り TP1〜TP4 と計算機内の評価）は [THREAD_SIM.md](THREAD_SIM.md) 6.8〜6.10。

本人の依頼（原文）:

> ネジを手早く作成するverbがほしい。3dpすることを前提にしたものであってほしい。

## 結論

- **verb `thread`（画面の名前「ねじ」）を1つ足した。** 選んだ**全周の円筒面1つにねじ山を実体で刻む**。
  外向きの面（軸）なら雄ねじ、内向きの面（穴）なら雌ねじ。どちらになるかは面の向きで決まり、引数は無い。
- 手順は **「ねじ」→ 円筒面を1つクリック → 山形（半円／30°台形／45°台形）を選ぶ → 隙間（空欄なら既定）→ 幽霊を見て Enter**
  （本人の決定 2026-10-23。[decisions.md](decisions.md)「[ねじ] verb の使い方」）。ピッチは径から自動で、入力欄は無い。
- **3Dプリント前提で決めたのは4つ**: 面の直径を呼び径とみなす／隙間を一級の引数にする（上限で断り、推奨の外は警告）／
  相手が入ってくる端だけ自動で面取りする／印刷どうしで組む山形だけを持つ（金属ねじと組む ISO 基準山形は入れていない）。
- **形は集合演算を使わずに面から直接組む**（下の「形の作り方」）。螺旋の歯を芯の円柱に足す素直な作り方は、
  `BRepCheck` が真のまま芯が消える（M5×0.8 で体積 −84%）ので採らない。

## 何を作り、何を作らないか

| | 判断 | 理由 |
|---|---|---|
| 円筒面へのねじ山（雄・雌） | **作る** | 既存の verb（円を描く→押し出し／穴を切る）の続きに1手で載る。ボルト・ナット・ねじ込みの蓋・部品に切ったねじ穴が全部これで済む |
| ボルト・ナットを丸ごと生む verb | 作らない | 粒度が粗すぎる（[DESIGN_DECISIONS.md](DESIGN_DECISIONS.md)「verb ＝ undo1回・ログ1行・MCP1呼び出し」）。AI なら「円→押し出し→ねじ」の3〜4呼び出しで組める |
| 六角の頭・ナットの凹み | このverbでは扱わない | 遅いのはねじ山ではなく六角形を線6本で描くところ。正多角形のスケッチ図形が別に要る |
| 金属ねじ用の穴（下穴・インサート穴・ナット凹み） | このverbでは扱わない | ねじ山を作らない別物。3Dプリントで金属ねじを使う部品では最も頻度が高いかもしれないので、別の verb として検討する |
| 左ねじ・ねじ部の長さ指定・ピッチの入力・ISO 基準山形・複数の面への一括 | 後から足せる | 下の作り方は「軸方向の断面が r=f(z) の折れ線で書ける山形」なら何でも受ける。足すのは引数と山形の表だけ |

## 3Dプリント前提で決めること

### 1. 面の直径を呼び径とみなす（雄も雌も）

**ボルトもナットも「同じ直径の円柱／穴」を描いてねじを掛ける。** 下穴径（タップ径・谷径）を覚えなくてよい。
Fusion360 の「穴は下穴径で描く」流儀は採らない。印刷すると穴が痩せる分は次の隙間が受け持つ。

- 面の直径 D は、雄では山頂の直径、雌では隙間 0 のときの谷の直径（雄の山頂と同じ）。雌は隙間のぶん外へ広がる。
- **ピッチは径から自動**: `max(1.2, 0.25D)`（0.05 刻み。`kernel_thread.default_pitch`）。山の深さはどの山形も 0.4P。
  1.2 の下限は、半円の D3 が細かいピッチでガタ無しに回る隙間を持たないため（THREAD_SIM.md 6.10）。入力欄は置いていない
  （AI の判断。[decisions.md](decisions.md)）。ログには解決後のピッチが残るので、内部の引数としては受け取れる。

### 2. 隙間（クリアランス）を一級の引数にする

- **定義: このねじの山形を片側いくら動かすか**（雄は内へ、雌は外へ）。**台形は半径方向、半円は山形の曲線の法線方向**に動かす
  （試し刷りと同じ付け方。半円を半径方向に動かすと頂の丸みが薄くなるだけで、斜面のすき間が揃わない）。
  スライサーの「X-Y 穴補正」と同じ片側の流儀で、スライサー側でも補正しているなら**二重にかかる**。
- 印刷どうしの組では雄と雌の隙間が足される。**既定は雌（穴）だけに付け、雄（軸）は 0**（計算機内の評価で、ボルトを呼び寸法のまま穴にだけ付けると
  ボルトの芯が太く残って強い。THREAD_SIM.md 5.5。試し刷りもこの付け方。雄の既定を 0 にしたのは AI の判断）。
- 上限・推奨の範囲・既定値（0.12mm Fine。本人の印刷の 99%。本人が案を了承 2026-10-23）:

| 山形 | 下限 | 上限（断る） | 推奨（外れたら警告。穴） | 穴の既定 | 軸の既定 |
|---|---|---|---|---|---|
| 半円（法線方向） | 0 | 0.24P − 0.1 | 0.11〜0.14 | 0.12 | 0 |
| 30°台形（半径方向） | 0 | 0.4P − 0.125 | 0.18〜0.22 | 0.20 | 0 |
| 45°台形（半径方向） | 0 | 0.4P − 0.125 | 0.11〜0.13 | 0.12 | 0 |

- 上限は「誤差 0 でも山の掛かりが 0.1mm を切る隙間」で、山の深さ（0.4P）に比例するのでピッチの式になる。推奨は径によらず一定（評価の結果）。
- 推奨の外（軸に 0 より大きい値を入れたときを含む）は**確定はして警告のトースト**を出す。プレビューのたびには出さない。

### 3. 相手が入ってくる端だけ、自動で面取りする

象の足（1層目のはみ出し）と食いつきのため。**引数にはしない**（印刷物で要らない場面がほぼ無い）。

- **雄**: 隣の面が「軸に直角な円板」（軸の先端）の端。45度、深さ = 山の深さ + 0.1P（0.1P は AI の仮置き）。
- **雌**: 隣の面が「外側へ広がる軸に直角な平面」（部品の表面）の端。45度、深さ = 山の深さ。貫通穴は両端、止まり穴は口だけ。
- 隣がそれ以外（利用者がフィレット済みなど）の端には何もしない。**雄の先が既に面取り済み（円錐）なら断る**（下の「断るもの」）。

### 4. 山形は印刷どうしで組む3つから選ぶ

how の選択肢 `profile`（既定なし、毎回選ぶ）。本人の決定（2026-10-23）:

> ねじverbでは、複数の形状を選択できるようにしてしまっていいと思う。今の3つ(半円・30°台形・45°台形)から選択できるようにしよう。

| `profile` | 山形 | 評価の要点（0.12mm Fine、D6 P1.5。THREAD_SIM.md 6.9） |
|---|---|---|
| `semicircle` | 半円の山（丸みの半径 0.4P）と平らな谷 | 実物でガタ無しに回った隙間が2点（0.11・0.14）。山が浅い |
| `trapezoid30` | 斜面が軸に直角な面から30°の台形（山頂と谷の平坦は半々） | ガタ無しは 0.20 の1点。0.24 でガタ（模型の予測より早い） |
| `trapezoid45` | 同じく45°の台形 | ガタ無しは 0.12 の1点。嵌合の予測が最もよく当たる。軸方向の遊びが出やすい |

- 金属ねじと組む **ISO 基準山形は入れていない**（AI の判断。本人の印刷どうしの用途と試し刷りの範囲に合わせた）。足すときは山形の表に1行と
  上限・推奨の式を足すだけで、作り方は変わらない。下の ISO の段落は調査の記録として残す。

**ISO 基準山形**（調査の記録。未実装）:

- 60度、山頂の平坦 P/8、谷の平坦 P/4（ISO 68-1 の基準山形）。**金属のねじ・ナットとそのまま組める**のが他の山形に勝つ点。
- 山の高さは 0.541P（計算値）: M3 0.27 / M4 0.38 / M5 0.43 / M6 0.54 / M8 0.68 / M10 0.81 / M12 0.95 mm。
  0.4mm ノズルなら M4 以下は山の高さが線幅（0.4mm 以上）を下回る。
- 軸を鉛直にして刷ると、下向きの斜面は水平から30度（計算値）。軸を鉛直にしたボルトは層の向きが引張に弱い
  （FDM の層間は XY の 40〜60%。[TOPOPT.md](TOPOPT.md)）。横置きにして平らに削る作り方はこの verb の外。

### 本人の経験: Fusion360 のねじコマンドとコイルコマンド

> fusion時代はねじコマンドだとネジ径が小さくなるとプリントできなかった。コイルコマンドだとより小さい径までプリントできた。（2026-10-16）

AI が次のように見立て、本人は「それだ。粗くて緩いネジ」と応じた（コイルで使った値そのものはまだ聞いていない）: どちらも螺旋の立体を作るので、差は作り方ではなく
**寸法を規格表が決めるか、自分で決めるか**にある。ねじコマンドは規格の寸法をそのまま作るので、小径では次の3つが同時に印刷の分解能を割る
（計算値。層は0.2mm として）:

| | 山の高さ 0.541P | 1ピッチあたりの層 | 6g の基礎の寸法差 −(15+11P)µm（ISO 965-1、直径） |
|---|---|---|---|
| M3×0.5 | 0.27mm | 2.5 | 約 −0.020mm |
| M4×0.7 | 0.38mm | 3.5 | 約 −0.023mm |
| M5×0.8 | 0.43mm | 4.0 | 約 −0.024mm |
| M6×1 | 0.54mm | 5.0 | 約 −0.026mm |
| M8×1.25 | 0.68mm | 6.25 | 約 −0.028mm |

規格の隙間は FDM の位置決め精度 0.1mm 前後（[DESIGN_DECISIONS.md](DESIGN_DECISIONS.md)「STL書き出しの粗さ」）より小さく、
ねじコマンドにはそれを足す欄が無い。コイルは断面の大きさ・ピッチ・位置を自由に置けるので、小径でも粗いピッチ・深い山・大きな隙間にできる。

続けて本人が足した要因（原文）:

> あと、山と谷ではなくて半円が凹凸していた形状もミスなくプリントできた要因だろう

**この verb への含意**: ピッチと隙間を引数に開けてあるのはこのため。印刷どうしで組む小径を規格の並目で切ると Fusion のねじコマンドと
同じところで詰まるので、4. で相手「印刷」を分け、山形を半円にした。

### 山形の調査（2026-10-17）

本人の依頼（原文）:

> 普通のネジを3dpすると尖った部分の形状再現ができない、オーバーハングが垂れやすい、精度不足の影響を受けやすいといった問題がある。3dpでねじをプリントするのに適したベストなねじ形状について調査して。

AI が論文・メーカーの設計指針・動画・CAD ライブラリを調べた結果。**山形どうしを同じ条件で比べた実測は、論文にもコミュニティにも無かった**
（印刷ねじを測った査読研究はすべて ISO 60° だけを刷っている）。下の序列は計算と実践者の傾向からの推論で、決めるのは試し刷り。

- **ISO 60° は刷れないわけではない。** M10〜M30 の 60° を支持材なしで刷り、組み付け・引張まで測った査読研究がある
  （Sarzyński 2024 DOI 10.3390/ma17215143、Drazan 2025 DOI 10.17973/MMSJ.2025_06_2025063 ほか）。足りないのは余白で、小径・細ピッチは査読の範囲外。
- **下向き斜面が前の層に乗る割合は 1 − h/(w·tanβ)**（計算。β は軸を鉛直にしたときの斜面の水平からの角、h は層高、w は線幅）。
  h=0.2・w=0.45 で ISO（β=30°）は 23%、45° の山は 56%。ISO を h≈0.115 で刷ると、45° の山を 0.2 で刷るのと同じ張り出しになる。
  **山形と層高・線幅・冷却は互いに代わりがきく**ので、最良の山形は機械で変わる。
- **β を立てる代価**（計算）: 半径方向に c ずれると、片側の斜面の軸方向の隙間は c·tanβ 変わる（ISO 0.58c、45° の山 1.0c、軸に直角な面 0）。
  ナットを押し広げる力も軸力の tanβ 倍。山頂・谷の平坦を同じ幅にすると山は浅くなる（45° は ISO の 58%）。自己ロックは斜面を立てるとむしろ強まる。
- **台形・ACME の標準角（30°/29°）は、軸を鉛直にすると β≈15° で ISO より垂れやすい。** 「台形は刷りやすい」とするメーカーのブログに試験の裏付けは無い。
- **瓶・キャップのねじは丸ねじではなく、角を丸めたバットレスか台形**（SPI の M スタイル 45°/10°、PCO 1881 20°/10°。ISBT の図面）。
  射出成形の指針（PlasticsToday, Beall 2006–2007）が勧める改良バットレス・粗いピッチ・大きな半径は、応力集中と型抜きのための知見で、自己支持とは関係ない。
- **半円（コイル）の山**は、張り出しの大きい層が下端の1〜2層だけで、頂が広い（計算）。その代わり浅く、接触が点に近い。
  裏付けは Formlabs（SLA/SLS 向け、データ無し）、フォーラム、Send to Print（YouTube XYC86E5D8rM、瓶と蓋）の定性的な報告だけ。
- 実践者は「斜面を水平から約45°（山の角度90°）にする」方向に集まっている（BOSL2 の例、`dans98/Fusion-360-FDM-threads`、Send to Print の軸方向 √3 倍、
  GoEngineer の2倍）。どれも嵌合・強度の数値は出していない。
- ナットは穴の軸を鉛直に、ボルトは寝かせた方が強い（Made with Layers YouTube eNMAFTeowFs、My Tech Fun YouTube ZiQek0wei1g）。
  印刷ねじの下限は「M6 以上」が多数派で、境界を測った実験は無い。
- 既存実装の隙間を「雌雄の和・半径」に直すと、調整済みの機械で 0.1〜0.3 mm、M6 級や未調整で 0.4〜0.7 mm。
  半径方向だけを動かす実装が多数派（BOSL2・FreeCAD・bd_warehouse）で、軸方向を別にしているのは Onshape の Plastic Threads くらい。

**この設計への含意**（AI の見立て。本人の採否はまだ）:

- 金属相手を ISO 基準山形にする判断は支持される（相手の斜面が決まっているので、他の形を選べない）。
- 印刷どうしの半円は、利点を幾何で説明できるが、45° の丸めた台形と比べた証拠は無い。浅いので荷重を受けるねじには向かない。
- **隙間を半径の1引数で持つと、軸方向の隙間が山形で変わる**（上の c·tanβ）。軸に直角な面を持つ山形（バットレスの棚）を足すと、その面の隙間は 0 のまま残る。
  山形を増やすなら、軸方向の隙間を別に持つか、少なくとも山形ごとの軸方向の隙間を示す。
- 外ねじの設計上の山の高さ h3 = 17/24·H ≈ 0.613P（DIN 13-19）は、基準山形の 0.541P と別物。どちらで切るかは実装のときに決める。

試し刷りの案（AI 案）: 呼び径 12 mm 相当・P 2.4・深さ 0.8・軸鉛直・0.2 mm 層で、60° 台形／45° 台形／40° 台形／半円 ρ0.8／45° の斜面＋軸に直角な棚を、
雌雄の和の半径の隙間 0.2/0.3/0.4 で刷り、**滑らかに回る隙間の幅**を比べる。幅の広い形ほど寸法の狂いに強い。

調査結果への本人の応答（原文、2026-10-17）:

> iso60はネジ直径が小さくなってくるとまともにプリントできない。コイルの方がより小さい直径まで綺麗にプリントして実用できる。スライサー設定を詰めるのもやりたくない。初期設定でプリントできることが重要である。

**だから「層高・線幅・冷却で山形の代わりをする」手は使わない。** 余白は山形・ピッチ・隙間・造形の向きだけで作る。試し刷りもスライサーの初期設定で行う。

## verb の形（verb → target → how）

| | 中身 |
|---|---|
| target | 確定選択の**全周の円筒面（`kernel.classify_face` の `cylinder_full`）ちょうど1つ**（`selection.require_selected(..., exactly_one=True)`）。円錐面（テーパーねじ）は将来の拡張（Issue #210） |
| how | `profile`（選択 `semicircle` / `trapezoid30` / `trapezoid45`、必須・既定なし）、`clearance`（mm、省略可＝山形と雄雌ごとの既定、`dimension=True`） |
| 返り値 | `body_id`・`changed_bodies`。推奨の外の隙間なら `warning` も（`Session` が確定のときだけ警告のトーストへ積む） |
| 宣言 | `category="feature"`・`previewable=True`・`resets_selection=True` |
| 操作ログ | `{face, profile, clearance, pitch, body_id}`。空欄から決まった隙間とピッチも**解決後の数値で残す**（既定の表を直しても古い文書の再生が変わらない） |
| Enter | 要る。隙間の欄は空欄のままでよい（`NumberArgSpec.optional`。欄には「既定」と出る）。幽霊を見てから確定する |
| 画面 | `THREAD`（`web/src/commands/features.ts`、`SOLID_FEATURE_COMMANDS` のシェルの後、`#thread`、山形のボタン `#thread-profile-*`、隙間 `#thread-clearance`）。プレビューはサーバの投機実行 |

**断るもの**（トースト。文書もログも変えない）: 全周の円筒面でない／メッシュボディ／面が2つ以上／`profile` が3つのどれでもない／
隙間が負・上限を超える／山の深さで芯が 0.2mm を切る（ピッチが直径に比べて粗すぎる）／
穴が短すぎる（入口の面取りを除いたねじの長さがピッチに足りない）／
**雄ねじの先が既に面取りされている**（面取り済みの先端の上にねじを切ると、先が山より太い段になってナットに入らない。
面取りはねじが入れるので、面取りの前にねじを切る）。

## 形の作り方（実測で選んだ）

再現は `tools/thread_prototype.py`（採らなかった方式は `--rejected`）。数値はすべて 2026-10-16、OCP 7.9.3、このPC。
期待体積は解析式（折れ線山形の断面積）か、面取りぶんを含めた (θ, z) 格子の数値積分。体積は `VolumeProperties_s` の Eps=1e-7 で測った。

### 採らない: 螺旋の歯 ∪ 芯の円柱

歯（山形を螺旋に掃いた立体）を作って芯の円柱と `BRepAlgoAPI_Fuse` する作り方。3〜4秒かかり、**`BRepCheck` が真のまま結果が壊れる**:

| | 体積の誤差 |
|---|---|
| M3×0.5 | +3.5e-07 |
| M5×0.8 | **−8.4e-01**（芯が消えて歯だけ残る） |
| M8×1.25 | +6.9e-09 |

歯の谷を芯の内側へ食い込ませても、谷を芯の円筒面に一致させても、`SetGlue` / `SetFuzzyValue` を変えても M5 は直らなかった。
寸法によって当たり外れが出るので、検査を付けても「この寸法は作れない」が残る。

### 採る: 面から直接組む

ねじの側面は `r = f((z − kθ) mod P)`（k = P/2π、f は1ピッチ分の折れ線の山形）と書ける。

1. 山形の折れ線の各区間は、**θ を引数とする2本のヘリックスの間の線織面に厳密に一致する**（同じ θ の2点を結ぶ線分がその区間の母線）。
   ヘリックスを θ で補間した3次 B-spline（1周64点）にし、2本の極を並べた (3,1) 次の B-spline 面を作る。
2. 端の平面 z=0 / z=L の切り口は、各帯の (θ, t) 引数空間で**直線**になる。2D直線の pcurve で縁取るので、平面と螺旋面の交線計算が要らない。
3. 帯だけを先に縫い、残った2本の開いた縁から平面の蓋を作って縫い直す（**蓋と帯で辺を共有させて一度に縫うと、縫い合わせが端の辺を縮退扱いにして殻にならない**）。

ボディへ掛けるときに集合演算が触るのは、**同一平面どうし・同軸同径の円筒どうし**と、雄の先端の面取りで**切り離した軸だけ**に掛ける円錐だけになる:

- **雄**: 軸を作る → 先端の面取りの回転体と共通部分（軸だけで）→ ボディから円柱域（半径 R+0.01）を切る → 軸を足す
- **雌**: 穴の入口の円の辺を**先に**面取りする（既存の `kernel.chamfer_edges`）→ 残った円筒面の範囲で穴を埋める円柱を足す → 雌側の寸法の軸を引く

| 場面（M3×0.5 / M5×0.8 / M8×1.25 / M20×2.5 / M60×4 の5寸法） | 時間 | 体積の誤差 | STL（0.01mm）の三角形 |
|---|---|---|---|
| 軸だけ | 0.03〜0.07秒 | 2.4e-07 以下 | 7,758〜35,368 |
| 箱の頭の上面に立てたボルト | 0.03〜0.10秒 | 1.2e-07 以下 | 7,774〜35,384 |
| 板の上の円柱に雄ねじ＋先端の面取り | 0.50〜1.21秒 | 1.7e-07 以下 | 7,406〜34,218 |
| 入口を面取りした穴に雌ねじ | 0.37〜1.42秒 | 3.0e-08 以下 | 8,030〜15,802 |

5寸法×4場面すべて `BRepCheck` 真・1ソリッド・三角形の取れない面なし。

**半円の山も同じ作り方で組める**（半円を折れ線で近似し、平らな谷と組み合わせた山形。3寸法 d3×P1・d5×P1.5・d8×P2 で測った。再現は `tools/thread_prototype.py --round`）:

| 折れ線の本数 | 軸だけ | 板の上の円柱に立てる | 半円の矢高（近似の誤差） |
|---|---|---|---|
| 16 | 0.28〜0.36秒 | 2.5〜3.1秒（2回測った幅） | 0.002〜0.004mm |
| 32（d3 だけ） | 0.80〜0.82秒 | 5.8〜6.1秒 | 0.0005mm |

すべて `BRepCheck` 真・体積の誤差 2.5e-07 以下。矢高は STL の偏差 0.01mm より小さいので16本で足りる。帯が18枚になる分、
ISO（帯4枚）より本体との集合演算が遅く、プレビュー1回に3秒前後かかる。弧を1枚の曲面（t 方向が2次以上の B-spline）にすれば帯は数枚で済む
見込みだが未測定（AI の案）。雌ねじは未測定。

**雌ねじの皿取りを後から円錐で引くと悪くなる**（ねじを切った本体から円錐を引く順）: 1〜7秒・体積の誤差 7.7e-04〜1.5e-03、
M60×4 は STL の三角形分割で2面が取れず13秒かかった。だから**円錐を当てるのは、螺旋の面がまだ無い段（雌）か、切り離した軸（雄）に限る**。

### 体積の既定積分はねじ山で狂う

`kernel.volume`（`VolumeProperties_s` の既定積分。Eps 無し）は、何周も巻いた B-spline の面で誤差が出る:
採らない方式の歯だけで −1.9e-01（M5×0.8）、採る方式の軸だけで最大 1.5e-03、ボルト・ナットの形で最大 3.5e-04。
`describe_document` が AI に見せる体積はこの値なので、AI の指示文の「体積差 0.1% 以内を指示どおりとみなす」（issue #134）に
軸だけのときは掛かりうる。帯を1周ごとの面に割ると直るかは未測定（割ると面の数が周回数倍になり、画面で選ぶ単位も増える）。

## 合否の門と検査

- **kernel の門**（フィレットの4つと同じ考え方。[../README.md](../README.md)「実測で判明している技術的な地雷」）:
  集合演算の `IsDone()` / 空でない / ソリッドの数が変わらない / `BRepCheck` 真 / **体積の増減が期待値と合う**。
  期待値は「単独で組んだねじ部の体積（Eps 付き）− 埋めた・切った円柱の体積」で、`BRepCheck` が真のまま芯が消える壊れ方を弾く。
  許容は「ねじ部の体積の 1%」（AI の仮置き。採らない方式の壊れ方 −84% を確実に弾き、Eps 付きの最悪 2.2e-04（L=60 の軸）で誤って落とさない幅）。
- **pytest**（`tests/test_thread.py`）: 穴（雌）と軸（雄）・3つの山形／既定の隙間とピッチ／断るもの（文書もログも変えない）／
  undo・redo・JSON を通した再生で同じ体積／三角形に分割できない面が無い／雌の山形が雄の山形より常に外にある（同じ位相で重ねて、隙間が正）／
  推奨の外は確定で警告・プレビューでは出さない。
- 幽霊はサーバの投機実行（`preview: 'server'`）で、確定と同じ関数を通るので、`tests/test_ghost_agreement.py` の枠（画面側の幽霊）には載せない。
- **はまるかどうかは試し刷りでしか決まらない。** 既定値と推奨の範囲は TP1〜TP4（D6 P1.5）と計算機内の評価から決めた。D6 以外の径と、
  verb が作った形そのものでの確かめは別（THREAD_SIM.md 6.5・6.10）。
