## これは何か

**3Dの二値形状探索**(初期合格探索と、ひずみエネルギーの順位で削る体積削減)。固定した設計空間の
中で材料あり/なしのboolマスクを操作し、6条件(境界・単一成分・保持/除外・荷重欠落なし・目標安全率)
を満たす最小体積のモデルを探す(計画は [PLAN_BINARY_STRESS_SEARCH.md](PLAN_BINARY_STRESS_SEARCH.md))。
**保持ソリッド由来のセルは探索が空にしない**(2026-09-21 本人決定。[TOPOPT_PRESERVE.md](TOPOPT_PRESERVE.md))
——解く形と納品する形の保持部分が一致する。

出力は、平滑化後の三角形を面として縫合し、保持・除外CADとのブーリアンを適用したソリッド。
三角形から元の設計意図や滑らかな解析曲面を逆推定する処理は行わない。処理順と現在の判定は
[TOPOPT_ACCEPTANCE.md](TOPOPT_ACCEPTANCE.md)。

**範囲はFEA(線形静解析)だけ**(2026-08-29 本人決定)。Fusion 360のGenerative Designが持つ
①線形静解析 ②SIMP密度法 ③製造方法別の幾何制約 ④複数outcomeの同時探索 ⑤結果メッシュ→
T-spline変換のうち、③④⑤は作らない。**出力はメッシュ止まりと最初から決めてある**——有機的な
三角メッシュを編集可能なNURBS B-repへ自動変換する道はOSSに無い(2026-08調査。OCCTのfaceted
B-rep化・`ShapeUpgrade_UnifySameDomain`・`geomdl`の曲面フィッティングはいずれも非構造三角メッシュ
に使えない)。

**結果は編集可能ソリッドとして持たない**(2026-09-23 本人判断)。文書に入るのは`finalize`が
合格させた三角形のメッシュボディで、画面・STLはそれをそのまま使う。理由は費用: 112k面の結果を
`add_solid_body`で入れると操作ログに128MBのB-repテキストが載り、開く・再生のたびにBRepCheckが走り、
画面は面ごとのMeshと境界線を22万個作ってカメラが回らなくなっていた。失うのは結果のSTEP書き出しと
面単位の選択・問い合わせ。

**最終処理はメッシュ集合演算**(2026-09-25 本人判断、#95。`finalize.py`): 平滑化後の表面に、
線形偏差0.01 mm(STL書き出しの`STL_DEVIATION`と同じ値)・角度偏差0.35 radで三角形分割した保持を足し、
除外を引く(manifold3d、倍精度)。結果は入力面の由来を捨てて(`as_original()`)1e-5 mmで簡略化し、
それでも残る「float32で潰れる三角形」(消費側は文書・画面・STLともfloat32)は許容値未満の最短辺を潰して消し、
接続6項目・単一ソリッド・float32の縮退と頂点一致・自己交差で検査する。B-repはどの段階にも無い。
入力(平滑化後の表面、分割した保持・除外)にも接続6項目・向き・自己交差の検査をかける——manifold3dは
交差のある入力を直さず結果に残すので、入力で止める(小さいから通す判定は無い)。
置き換えの根拠は、hangerでOCCTブーリアン由来の失敗が3種続いたこと(除外cutの警告、三角形分割できない
極小面、保持と除外の一致面による不正な形。[TOPOPT_ACCEPTANCE.md](TOPOPT_ACCEPTANCE.md))が、
判断基準「OCCTブーリアンの失敗が頻発するなら最終処理をメッシュに置き換える」(2026-09-23本人判断)に
当たったため。置き換え先の実測(hangerを含む3例での合格、偏差ごとの体積差、円柱の除外へのめり込み)は
[TOPOPT_MESH_BOOLEAN_STUDY.md](TOPOPT_MESH_BOOLEAN_STUDY.md)。保持・除外の形は内接する三角形で
近似されるので、除外の穴の内面は円柱で約0.005 mm(半径によらない)だけ除外の中に残る。

## 塊(設計空間)をB-repから起こす(voxelize.py)

`voxelize.py`がOCCTの形状から格子を起こす(**stage1**。境界条件を面に紐づける「面アンカー」は
stage2=`anchor.py`。下記「CADの面→格子の節点」)。

```python
from duocad.topopt import voxelize
from build123d import Box, Pos

shape = Box(40, 20, 10).wrapped
lo, hi = voxelize._shape_bbox(shape)
grid = voxelize.grid_for_bbox(lo, hi, 40)   # 最長軸方向の要素数 → 要素サイズが決まる
soup = voxelize.triangles_from_shape(shape, deviation=grid.spacing * voxelize.DEFAULT_DEVIATION_RATIO)
design, stats = voxelize.occupancy(soup, grid)
model = voxelize.model_from_design_mask(
    grid, design, anchor_shape=soup,
    keep=Pos(14, 0, 0) * Box(12, 20, 10),   # 保持領域(材料を必ず残す)。省略可。塊からはみ出すと例外
)
model.grid          # Grid(origin, spacing, shape) —— 立方体要素・ワールド軸整列
model.design        # bool (nx,ny,nz)。設計空間の占有
model.keep / model.obstacle   # bool。はみ出しは例外
model.free          # design & ~keep & ~obstacle(最適化が動かしてよい要素)
model.soup          # TriangleSoup。三角形ごとにOCCTの面添字(1始まり)を持つ
```

**セル中心規約**: `mask[i, j, k]`は要素(i,j,k)の**中心**の値(`origin + spacing*(i+0.5, j+0.5, k+0.5)`)。
新しく格子と実座標を対応づけるときは必ず`Grid.centers_1d`/`Grid.centers_of`/`Grid.center_of`を
通すこと——添字に`spacing`を直接掛けると半セルずれる(`mesh.py`が2026-08-30に踏んだ)。

格子の作り方: 要素サイズ=最長辺/`elements_long_axis`、各軸の要素数=`ceil(辺長/要素サイズ)+2`
(周囲に1要素の余白)、形状は格子の中央に置く。

占有判定は`kernel.tessellate`が返す三角形群に+zのレイを飛ばして巻き数で数える(numpyだけ、
新規依存ゼロ)。**`BRepClass3d_SolidClassifier`は本番経路に使わない**——1点ずつしか判定できず
(1点約21ms)、`check_voxelize.py`の神託としてだけ使う。神託も無謬ではない(実物STEP 3,819件で
1件だけ食い違い、誤っていたのは神託のほうだった。落ちたときは`BRepExtrema_DistShapeShape`で
表面までの距離を測り孤立点かを見る)。

守りが3つ要る(どれか1つでは足りないと実測で分かっている):

1. **偶奇(parity)ではなく巻き数(winding)で数える。** レイが三角形の共有辺をちょうど通ると同じzに
   交点が2つ出る。偶奇だとその上の全域で内外が反転する(実測: 40×40×10の箱で15,200mm³/正解
   16,000)。巻き数なら稜線(上向きと下向きの2枚)では相殺して壊れない。
2. **交点が三角形の辺・頂点に乗ったら(重心座標が `RAY_EDGE_TOLERANCE` 以内)縮退として扱う。**
   同じ向きの2枚の共有辺(平らな面の対角線)を両方に数えると、入る面と出る面の両方で二重になった列は
   巻き数が `2, 1, 2, 0` と0へ戻ったまま、間の空洞が材料になる(合成の中空の角柱で空洞3セルが
   埋まった。issue #40)。どちらにも数えなければ材料が抜ける。
3. **レイの(x,y)を列の中心から決定的にずらし、縮退したらずらし幅を変えてやり直す。** 軸整列した
   形状では面や辺が列の中心と厳密に一致する縮退が系統的に起きる(円錐の頂点をレイが貫くと守れない。
   実測: ずらし幅ゼロではn=6〜40の全解像度で縮退)。**ずらし幅を1つの固定値にすると、その値に
   合った格子を作れば必ず縮退させられる**(2026-08-31のQAが再現)。`RAY_JITTER_SEQUENCE`
   (要素サイズの1e-4に素数を掛けた6通り)を順に試し、全部だめなら例外にする。乱数は使わない。

**壊れた入力は黙って通さない。** 次のいずれかで`ValueError`: (a)三角形が取れなかった面がある、
(b)有向辺の対が揃わない(非水密)、(c)符号付き体積が正でない、(d)**殻(連結成分)ごとの向きが
入れ子の深さと合わない**(内部空洞の殻だけ裏返すと総体積は正のまま空洞が材料として埋まるため、
殻ごとの符号付き体積と巻き数で深さを数えて判定する。実測: 健全な中空の箱は殻2個・体積
[+64000, −8000]・深さ [0, 1] で通る)、(e)ずらし幅を6通り試しても巻き数が0に戻らない列がある、
(f)保持/障害物領域が設計空間の格子と1要素も重ならない、(g)保持領域と障害物領域が重なっている。
**SOLID が2つ以上ある形(`make_compound` でまとめた条件のボディ)は(b)〜(d)をソリッドごとに見る** ——
面で接するボディは接した辺が同じ向きで2回現れ、重なる・入れ子のボディは殻の深さが崩れるが、
どちらも組み立てたモデルでは普通の入力(issue #28)。**どの列の中心も形状の xy 投影に入らない
(`NoRayCrossings`)のは縮退ではなく「この格子では0セル」**で、除外と保持は0セルとして受け取り
`unrepresented_regions` で報告する(列の間の薄い壁・格子の縁をかすめる板・要素より小さい保持。
issue #29・#34)。保持の格子への占有はボディごとに取って和にする(まとめた形で数え直さない)。

**stage2への引き渡し**: `model.soup`は面添字と面ごとの面積・重心・法線(`soup.face_props`)を持つ。
`voxelize.closest_triangle(soup, points)`は最近傍三角形とその距離を**7候補(3頂点/3辺への射影/
面への射影)の最小値**で返す——教科書の領域分けを優先順位つきの上書きで書くと、**退化した三角形
(2頂点が重なる)で複数の領域が同時に真になり誤った距離を返す**(2026-08-31のQA指摘。退化三角形は
OCCTの三角形分割に実際に現れる)。stage2は面へ戻る経路をこの関数に頼るので、ここの誤りはそのまま
伝播する。

### OCCT の bbox はトリムを見ない(2026-09-07)

`BRepBndLib::Add`は**面のトリムを見ず、下地のサーフェス全体で囲む**。トリムされたトーラス面は
ドーナツ丸ごとで囲まれ、bboxが実寸から大きく外れる(実測: `models/hanger_bar_attachment.json`の
1ボディで`Add`が482.8×252.1×252.1mmに対し`AddOptimal`と三角形分割はどちらも35.0×36.6×36.6mm、
約14倍)。**全周トーラスでも外れる**(トリムの有無が原因ではなく、r=10の面をR=100の円に沿わせた
ときの極周りのふくらみ。外れ幅9.06mmでほぼ一定)。円柱・平面だけの部品では両者がほぼ一致するので、
bboxの取り方を試す題材にはトーラスを使うこと。

`kernel.bounding_box`と`voxelize._shape_bbox`は**両方とも`AddOptimal_s(shape, box, False, False)`**
(第3引数`useTriangulation`・第4引数`useShapeTolerance`。`useTriangulation=True`だと形状に付いた
三角形分割の有無で結果が変わり非決定的になる)で取る。**`AddOptimal`は繰り返しても速くならない**
(実測: 11ボディで`Add` 0.09ms対`AddOptimal` 178ms、約2000倍)。繰り返し呼ぶ経路は
`kernel.BoundingBoxCache`に載せる(`Document`が1つ持ち、文書差し替えで捨てる。キャッシュ有り
0.50ms・無し145ms)。初回コストは消えない(29%のボディの寸法が最大9倍狂うほうが害が大きいという
判断で受け入れてある。2026-09-07本人決定)。

**`TopoDS_Shape`は`hash`が一致しても`__eq__`がFalseを返す**ので、素の`dict`や`lru_cache`は1回も
当たらない(遅いままメモリだけ増える)。鍵は`IsSame`で引く(`kernel._ShapeKey`)。**`IsSame`は
Orientationを見ない**ため、この同一性をbbox以外へ流用すると静かに壊れる。

## CADの面 → 格子の節点(anchor.py)

`voxelize.py`が起こした格子の上に、「ボディXの面#42」を「これらの格子節点」へ翻訳する対応表を
載せる(**stage2「面アンカー」**)。これが無いと固定面・荷重面を指定できない。

**ボクセルの側から境界を取り直してはいけない。** ボクセルの表面は階段状で真のCAD面から最大半要素
ずれる。「占有ボクセルの最も左の層」のような取り方をすると斜面や曲面で荷重の向きと面積が歪み、
階段の角に偽の応力集中が出る——出てくる形は「少し悪い」のではなく「自信を持って間違っている」。
正解は**両方の表現が手元にある瞬間(=ボクセル化時)に対応を固定し、以後はその表を引く**こと。
`anchor.py`は`TriangleSoup`と`Grid`だけを見て表を作り、**占有マスクを一切見ない**。

### 契約(後続がここに依存する)

| 事項 | 決め |
|---|---|
| 節点 | 要素の**角**。要素格子`(nx,ny,nz)`に対し節点格子は`(nx+1,ny+1,nz+1)` |
| 節点の座標 | `origin + spacing*(i,j,k)`。**要素中心の+0.5は付かない** |
| 節点番号 | `n = i*(ny+1)*(nz+1) + j*(nz+1) + k`、自由度`3n+{0,1,2}`。**`fem._build_edof`と一致** |
| 面と節点 | **1節点は高々1面に属する**(稜線の規則)。面ごとの節点集合は排他 |
| 担当面積 | 節点ごとに`mm^2`を持つ。**荷重はこの面積比で配る**(等分は禁止) |

節点番号の一致は`check_anchor.py`の検査[0]が`fem._build_edof`と全要素×8隅で突き合わせる。
**ここがずれると荷重は別の場所に入り、それでも最適化はもっともらしく収束する**ので、他の検査が
全部緑でも意味が無くなる。

### 表の作り方

1. 面の三角形を、辺長が`sample_ratio * spacing`(既定0.25)以下になるまで細分し、各小三角形の
   重心を標本点にする(平面の面は三角形2枚で返るため、重心だけでは荷重が2点に集中する)。
2. 各標本点から半径`radius_ratio * spacing`(既定**1.0**)の球に入る節点へ、テント重み
   `1 - d/radius`で面積を配る(標本ごとに重みの和で正規化)。既定を範囲(0.5〜1.0倍)の上端に
   してあるのは、`radius >= sqrt(3)/2 * spacing`でないと「どの節点も球に入らない標本点」が
   出るため——そこへ落ちると荷重が特定の節点へ集中する。既定`radius = spacing`では球に入りうる
   節点はその要素の8隅だけになり、重みは三線形形状関数と同じ形になる。
3. 1つの節点が複数の面の球に入りうる(稜線付近)ので、最後に**持ち主**を決める。

### 稜線の規則(明文化。黙って重複させない)

**節点の持ち主は、その節点へ最も多くの面積を配った面。同点なら面添字の小さい面**。したがって
面ごとの節点集合は排他で、他面に取られた節点へ配った面積は捨てる(再正規化しない。捨てた割合は
`FaceAnchor.leak_ratio`)。荷重は「その面の節点の担当面積の比」で配るので、捨てた分があっても
**指定した総荷重は厳密に保存される**(実測の相対誤差2.3e-16)。

重みを割って両方に配る案(節点を共有する)は採らなかった——固定面と荷重面が稜線を共有していると、
同じ節点が「拘束されていて、かつ荷重を受ける」ことになり**その荷重は黙って消える**(拘束DOFの
荷重は解に効かない)。排他ならどちらか一方には必ず効く。

**この規則の帰結として、要素サイズより小さい面(フィレット・面取り・小さな段差)は節点が1つも
付かず空になる**(実測: 231面のSTEPを要素サイズ1.54mmで割ると22面が空、2.567mmでは30面)。
`table.empty_faces()`で見えるようにしてあり、空の面を名指しして荷重・拘束を作ろうとすると
**黙って「荷重0」を返さず落ちる**。

**要素サイズより小さい面にも節点を付けること自体は可能だが、意図的にやっていない**:
(1) 稜線の排他を崩すと、拘束されていて荷重を受ける節点ができ荷重が黙って消える
(2) 節点1つに荷重を載せるのは点荷重=特異点で、そこに応力が集中し安全率が信用できない値になる
(2026-09-04実測)。

**圧力を載せる口(`pressure_vector`)は2026-09-21に削除した**(製品から呼ばれていなかった)。
足し直すときの注意: `p × 面積`が合力そのものなので、担当面積から出すと稜線で捨てたぶんがそのまま
不足する(実測: 要素サイズ2.5mmで11.7%、1.25mmで4.5%)。合力は`FaceAnchor.cad_area`(B-repの真の
面積)から出し、その総量を担当面積の重みで按分すること。

### 使い方

```python
model = voxelize.model_from_design_mask(grid, design, anchor_shape=soup)  # stage1
table = anchor.build_anchors(model.soup, model.grid)      # stage2
fixed_dofs = table.fixed_dofs(face_a)                     # 面 → 拘束する自由度
load = table.load_vector(face_b, (0, 0, -1000))           # 面 → 荷重ベクトル(合計は厳密に一致)
keep = table.element_mask([face_a, face_b])               # 荷重・拘束の近傍(非設計領域)
```

### FEM側の受け口(`fem.Model`)

境界条件を渡さない(`fixed_dofs`/`load`が`None`)ときの挙動は1ビットも変わらない。注意が要るのは
4点:

- **解いたあと`K U = F`を残差で検算し、通らなければ拘束不足を名指しして落とす。** 拘束不足
  (例: `fixed_dofs=[0]`)は「非空で範囲内」の検査を通ってしまい、CGが収束しないまま
  **max\|u\| = 1.2e16の有限値**が返って呼び出し側が原因から遠い場所で落ちる。
- **空要素にしか接していない節点は拘束側へ寄せて系から外す**(`extra_fixed_dofs`)。**追加であって
  置き換えではない**——`fixed_dofs`に混ぜると`active_mask`だけを渡す呼び出しで片持ち梁の拘束が
  黙って消える(2026-08-31の自己レビューで発見)。
- **荷重が全部拘束DOFに落ちていたら`ValueError`。** 固定面と荷重面が節点を共有していると
  「変位ゼロ・コンプライアンスゼロ」で荷重を掛けたつもりで何も掛かっていない計算が通る。
- **`active_mask`で組み立てから外した要素は、目的値の総和からも外す。** 片方だけ絞ると
  `c = F・U + (解いた系に無いemin媒質のひずみエネルギー)`になる。

### 確定表の節点所有権(2026-09-18実測。測定のみ・実装なし)

`optimize_run._map_boundary_conditions`が作る確定表は、条件面を持つボディ自身の占有ではなく
**設計空間全体**に接する節点を拾うため、一部の節点は最適化で消えうる一般材料の節点でありうる。
「その面のボディ由来の材料に限る」制限を入れた場合の影響を測った: **hanger(4本の条件面、2.4mm・
下限1.875mm)ではどちらの解像度でも節点・面積とも100%がそのボディ由来**で、制限を入れても
`condition_mapping`は変わらず全条件pass。**合成題材(cube/cylinder)を1.2mmまで細かくすると所有権が
32〜39%まで下がる**(荷重はテント重みで球の中心に近い節点ほど重みが大きいため、面積・重みの割合は
92〜98%と高いまま)——それでも制限後の`condition_mapping`はpassのままだった。hangerでこの解像度域
を再現できるかは未確認(下限1.875mmより細かい要素サイズを要求すると断られる)。実装はまだ入れて
いない。

## 塊の連結性と境界条件の入口検査

**塊から除外ソリッドを引いた結果、拘束面と荷重面が別々の島に落ちることがある。** 利用者は塊を
見ないので、塊の不備は利用者側からは観測できない。だから`design_space.derive`が**つながりを
確認してから返す**(現在は導出手順5の`connect_seeds`。下記「固定凸包による設計空間」)。

- **連結性の定義は6近傍(面で接する)**(`scipy.ndimage.label` + `generate_binary_structure(3, 1)`)。
  **26近傍にしない**——角1点・稜1本だけで触れている2要素はピン接合(機構)にしかならず、力の道
  として成立しない。
- 拘束側が乗っている連結成分の集合と荷重側のそれに共通のラベルが1つも無ければ
  `DesignSpaceDisconnectedError`(文面に成分数・各成分の要素数・拘束側と荷重側の所属が入る)。
  **`DesignSpaceTooSmallError`とは別の型**——あちらの直し方(`margin_ratio`を上げる)は分断には
  効かない。
- **見るのは拘束↔荷重の道だけ**。道の細さ(幅1要素でも「つながっている」と判定する)は最適化の
  仕事であって塊の妥当性ではない。保持ソリッドの連結性も見ない(浮いていても最適化が材料で
  つなぐのが正しい振る舞いになりうる)。
- **検査が無いと、切れた塊は2通りに壊れる**(2026-09-04実測、`severed_conditions()`題材)。
  (1)**黙って形が出る**——例外も警告も無く体積制約も満たしSTLも出るが、拘束側と荷重側が
  別々に浮いた形になる(コンプライアンスは参照の約40万倍だが利用者はコンプライアンスを見ない)。
  (2)**原因から遠い場所で落ちる**(`ZeroDivisionError`。文面に設計空間も連結性も出てこない)。
  **塊の分断は塊を組み立てる側でしか安く確実に検出できない**——空要素も剛性の下限`emin`を持つため、
  荷重側の島は`emin`の要素越しに固定節点へぶら下がり、Kは特異にならず残差検算も通ってしまう。

**拘束面・荷重面のアンカーが空のときも同じ考え方で入口検査にする**(2026-09-05)。要素サイズより
小さい面(フィレット・面取り)を選ぶと`AnchorTable.empty_faces()`に入り節点が1つも付かない。
`anchor.run_pipeline`は`table.fixed_dofs`/`table.load_vector`を呼ぶ**前**に
`AnchorTable.condition_face_diagnoses(fixed_faces, load_faces)`で診断し、1件でもあれば例外にせず
`{"state", "empty_condition_faces": [...], "warning", ...}`で早期returnする(最後まで走った場合は
常に`[]`)。診断には面添字・CAD面積・要素サイズ・逃げ道2つ(`absorbed_by_faces`=実際に節点を
持っていった面/`suggested_max_spacing_mm`=`√cad_area_mm2`という近似の目安)が入る。
`design_space.run_topopt`はこれをそのまま`space.stats["empty_condition_faces_warning"]`にも書く
(戻り値経由・`stats`経由の2経路)。

## von Mises応力と最小安全率(後処理。2026-09-04)

出てきた形が「保つか」を数字で言える段(`stress.py`)。**最適化そのものには手を入れていない**——
応力を制約に入れて最軽量を解く型(応力制約トポロジー最適化)は**採らない**(2026-09-04本人決定)。
理由: (1)体積制約はスカラー1本のOC更新で成り立つが応力制約は要素数ぶんに増え、MMAかp-norm集約
への刷新が要る (2)ρ→0で応力が0に行かない特異最適で、ε緩和等の研究水準の対処が要る
(3)応力制約は随伴解が1本増え、実行時間の99.5%を占める線形解が実質2倍になる
(4)ボクセルの階段状境界では応力が最も信用できない量で、これを拘束条件にすると離散化が最も
苦手な数字を制約にすることになる。安全率は最適化器の**外側**のループ(材料量を決めて解く→
応力を後処理で計算→不足なら材料を増やして再実行)で実現する。

```python
model = fem.Model(*material.shape, fixed_dofs=fixed, load=load, extra_fixed_dofs=浮いた節点, active_mask=material)
u = stress.solve_displacement(model, density, solver=solver)
scale = stress.UnitScale(grid.spacing, 1.0, youngs_modulus_mpa, solved_load=1.0)
report = stress.evaluate(model, density, scale=scale, allowable_mpa=..., u=u, percentile=...)
report.safety_factor        # 最小安全率 = 許容応力 / 代表応力
report.representative_mpa   # 代表応力[MPa](ρ>=0.5 の 99.5% 点)
report.raw_max_mpa          # 素の max[MPa]。安全率には使わない
```

**応力評価には解いた`Model`そのものを渡す**(後処理側で拘束・荷重・浮いた節点の扱いを組み直すと、
誤っても落ちずに違う応力が出るため)。変位は最終ρでもう一度`Model.solve()`を呼んで得る
(`Result`に`u`を持たせると`rho`を差し替えた瞬間に古くなるため)。

### 応力の実単位への換算則

FEMは**E=1.0/要素サイズ1**で解く。要素サイズL[mm]・実荷重F[N]・ヤング率E[MPa]・解いた系の
荷重の総量F_ndに対して:

```
sigma_real[MPa] = sigma_nd * (F / F_nd) / L^2
u_real[mm]      = u_nd     * (F / F_nd) * (E_nd / E) / L
```

**応力はEに依存しない**(σ = E εでEが落ちる。したがって安全率もEで動かない——
`youngs_modulus_mpa`が効くのは変位の側だけ。検査3が「EとFを同時に10倍→応力はちょうど10倍」で
押さえる)。剛性は要素サイズに比例するので変位はLに反比例する。
**探索(`acceptance.safety_check`)は荷重を実単位[N]のまま解く**ので`F / F_nd = 1`
(`UnitScale(..., load_n=1.0, solved_load=1.0)`)で、要素サイズだけを換算する。無次元の荷重で解いた系に
実荷重を割り当てる`stress.UnitScale.for_model`(`F_nd`を`Model.f`の総量から読む)は検査専用。

### 代表応力の規則

**製品の探索(2026-10-09〜)**: 代表応力 = **部材域の固定物理体積の上位値** Q_V。部材域は材料のうち、保持セル
(利用者が決めた形)と、拘束面・荷重面の節点を角に持つ要素(節点から h 以内の1層)を除いた所。Q_V は「これを超える応力を
持つ部材域の体積が V 以下」になる最小の応力で、V = 最小幅³(`optimize_run._build_search_conditions`)。部材域の体積が V 以下なら
部材域の最大を使う(意図的な変則。`stress.member_volume_stress`)。合格は 安全率 = 許容 ÷ Q_V ≥ 探索の目標(利用者目標 × 2.4)。

下の 99.5% 点は材料全体の割合なので、**遠くの低応力材料を残すほど高応力部が上位に隠れ、探索がそれを「重り」として残した**
(母数依存。[TOPOPT_IDLE_MATERIAL.md](TOPOPT_IDLE_MATERIAL.md))。V を体積で固定すると部材域の外の材料の量に値が依らない。
拘束面の1層は細分で最大が発散する所、保持は探索が変えられない所なので判定から外す(値は完成形検査が参考として返す)。
根拠・比較・限界は [TOPOPT_STRESS_GATE_DILUTION.md](TOPOPT_STRESS_GATE_DILUTION.md)。V より小さい集中は探索の判定に出ないので、
**完成形検査**(`final_check`)が完成メッシュを 1/3 格子で解き、部材域の表面の面中心の最大応力で利用者目標と比べる。

**`member_volume_mm3` を渡さない経路(受入検査・研究のスクリプト)**: 代表応力 = 「ρ >= 0.5 の要素」の von Mises の 99.5 パーセンタイル。 素のmaxを採らない理由は
2つ、どちらも単独では足りない: (1)ρの低い要素を落とす——実測では全要素のmaxが代表値の
9.8〜30.5倍まで跳ね、細分するほど大きくなる (2)残った母集団でも上位パーセンタイルを取る——
ρ>=0.5に絞ってもなおmaxは階段状境界の角で発散し、**maxで安全率を決めると解像度を上げるほど
安全率が下がり続ける**。要素応力は要素中心1点で評価する(8隅で評価すると階段の角がさらに尖る)。
値はSIMPの見かけの剛性ではなく**材料そのものの応力**で、中間密度の要素は安全率を安全側へ倒す。

実測(斜めに切った板、階段状境界。`check_stress.py`[4]。3段の細分):

| 格子 | 素の max | ρ>=0.5 の max | **代表(99.5%)** |
|---|---|---|---|
| 24×16×2 | 12.92x | 1.538x | **1.324x** |
| 48×32×4 | 26.32x | 1.862x | **1.289x** |
| 72×48×6 | 39.72x | 2.089x | **1.304x** |

素のmaxは収束しない(12.9→39.7)。ρで絞ってもmaxは単調に増える(+35.8%)。**代表値は動かない**
(振れ幅2.7%。しかも公称応力より30%高いので、本当の応力集中は捨てていない)。片持ち梁の曲げ
(σ = M·c/I への収束)は`check_stress.py`[2]が別途、2次収束(誤差が細分でおよそ1/4ずつ減る)を
確認している——ただし**測る断面は根元そのものではなく梁せい1つぶん先に取る**(x=0は全自由度
拘束面で梁理論の前提が成り立たず、根元の要素は理論値を8.5%上回る)。

母集団が空(どの要素もρ<閾値)なら例外で落とす(0を返すと「材料が1つも無い形」が最も安全という
判定になる)。**母集団にnan/infが混ざっている場合も同じく落とす**(2026-09-04のQA指摘。nanは
比較が常に偽になり、黙って通すと安全率がnanのまま不合格判定にも引っかからない)。

**留保(消えない問題)**: この応力はボクセルFEAの上の値なので階段の問題は消えない——**同じ
解像度での相対比較**と「明らかに足りない/足りている」の判定に使い、絶対値は信用しない。99.5%と
ρ>=0.5は実測で選んだ値で理論値ではない(母集団の要素数が少ないと99.5%点はmaxに近づく)。点荷重・
点拘束の特異点は代表値に残りうる。疲労・座屈・接触は見ていない。複数荷重ケース(別シナリオ)は
未対応——打ち消し合う荷重を1つの系に合成して代用してはならない。

### 許容応力の導出

**PETGの降伏応力50MPaに、3Dプリントを想定した低減係数0.8を掛けた40MPaを暫定で使う**
(2026-09-04本人決定。`material.PETG_YIELD_MPA=50.0`/`PRINT_DERATE=0.8`/
`DEFAULT_ALLOWABLE_MPA=50*0.8`)。50はデータシート級の公称値で、実際に使う銘柄の値へ差し替えられる。
**留保**: 0.8は積層方向(Z)には楽観的(FDMの層間接着は通常XY方向の40〜60%)。造形姿勢が決まるまで
一つのスカラーでは異方性を代表できない、暫定値。安全率(利用者入力)とは**二重に効く**(0.8は
材料側の低減、安全率は設計側の余裕。片方に畳み込むと造形法を変えたときどちらを動かせばよいか
分からなくなる)。

荷重の大きさの総和は条件に持たない(荷重は面ごとの力ベクトル`forces`としてNのまま節点へ配られる。
`optimize_run.build_conditions`は「全部0」の門にだけ総和を見る)。`fem.reaction_forces`は荷重釣り合いの確認だけに使う——**`fraction`の合計は
1にならない**(取付点どうしが引き合っていれば打ち消し合うぶんが乗る)ことに注意。

## 線形解法とCPU並列化

`fem.Model.solve`の解法は`"cg"`(Jacobi前処理CG。既定)・`"direct"`(`spsolve`)・`"auto"`の3つ。
**`"auto"`はK_ffを縮めてから、自由な自由度≤50,000かつnnz(K_ff)/自由度≤60ならdirect、それ以外は
cg**(`fem.choose_solver`。2026-09-22本人決定。根拠は[TOPOPT_SPEED.md](TOPOPT_SPEED.md)「cgと
直接解法の使い分け条件の材料」——hangerと合成の塊315対で、この範囲ではdirectがcgより速い評価は
0、探索終盤の細い形ではdirectはcgの0.07〜0.20倍の秒)。**探索と6条件の既定はこの`auto`**。実際に
使った解法は6条件の報告`safety.solver`と実行記録`linear-solve`に出る。

**幾何マルチグリッド前処理(`solver="mg"`、2026-09-04導入)は2026-09-21に削除した**(本人判断)。
SIMP時代の連続密度の系ではCG反復/solveが0.07〜0.20倍だったが、現在の探索が解く形(二値マスク・
材料要素だけで組むK)では速いのは太い形だけで、細い採用形状ではcgより遅く、solve中のメモリは
常に多かった(実測は[TOPOPT_SPEED.md](TOPOPT_SPEED.md)「探索が解く形での cg と mg」)。実装と受入
検査はgit履歴に残る。

**CGの許容は`rtol = 1e-9`**(1e-6だと完了条件の対称性チェックに対して余裕が6倍しかなく、1e-9
でも所要は13%しか増えない)。

**費用の伸び**: Jacobi前処理ではCG反復数が線形解像度sに比例し(条件数∝h^-2)、1反復の費用が
要素数∝s^3なので**所要はs^4**(s=2で実測16.2倍。要素数比(s^3)で見積もると外す)。ただし**指数は
形ごとに違う**(4題材でCG反復数はDOF^(0.41〜0.45)だが、`DOF^(1/3)`で割ると汎用ブラケット
8.2〜8.9・薄板19.7〜21.8と2群に割れる)——**条件数は大きさではなく形で決まる**ので、1部品で
測った指数を他部品へ外挿しない。当たり取り(前処理の既定値選び)は本番と同じ条件数の入力でやること
——一様密度`rho=0.5`で測ると教科書どおり効くが、設計反復を回した密度(`emin`と`penal`が作る剛性差)
では順位そのものが入れ替わる。

**CPU並列化(2026-09-04)は「疎行列×密ベクトル」(CGのSpMV)だけを並列化する。** BLASのスレッド数は
効かず、**scipyのCSR行列ベクトル積はGILを解放する**(行ブロック並列で12スレッド3.8倍。これが本命)。
スレッド数は`fem.PARALLEL_THREADS`(既定**総論理コアの半分・下限1**。環境変数`TOPOPT_THREADS`で
上書き可)——**全論理コアを占有すると最適化中にマシンが応答しなくなる**(duocadのフロントエンドが
同じマシンで動く)ため。性能でも損はない(実測 t=4 78.9秒/**t=8 69.9秒**/t=14 73.5秒。半分は
最良の隣)。行数がスレッド数に対して少なすぎるとき(`_MIN_ROWS_PER_THREAD=512`未満/スレッド)は
自動的にスレッド数を絞る。スケーリングは t=1→14で1.57倍(RAP+spluが並列化されないAmdahl分が
頭打ちの主因)。

**行ブロック分割は答えを変えない**(CSRの各行の丸め誤差の発生順序は変わらない)。実測:
`threads=1/2/3/4/8`の変位が全てビット一致。**これは行ブロック分割という実装に紐づく結論**で
あって、将来「複数スレッドの部分和を最後に足し合わせる」形(縮約の並列化)を足すなら改めて選び
直す必要がある(CG本体の縮約は自由度数のオーダーでSpMVより無視できるほど小さいため並列化して
いない)。

## SIMP時代の記録(段階6で削除)

`safety_loop.py`(材料量[mm³]を安全率目標から探すループ)・`simp.py`(連続密度・OC/MMA更新則)・
密度フィルタ半径`rmin`は、段階6(2026-09-17)で二値マスク探索(`binary_search.py`)へ置き換えて
コードごと削除した。今も参照する価値がある実測だけ残す:

- **幅つきの保証は必要条件であって十分条件ではない。** 幅つき回廊を満たす塊でも、反復を回すと
  保持ソリッドが結果メッシュから消えることがあった(反力は立っているのに)。
- **「繋がっているか」は早く決まり、「どれだけ硬いか」は決まらない。** 同じ塊を40/120反復で
  回すとコンプライアンスは120反復でも収束しなかったが、保持ソリッドの生存や拘束面の反力は
  40反復時点から変わらなかった。
- **病理を出せない題材で「直った」と判定しない。** 同じ部品でも箱の空き具合が違うと同じ病理が
  再現しないことがある。
- **背景のコントラストが崖を作る**(2026-09-12実測)。初期の一様密度が低いと背景の実効ヤング率
  (`emin + ρ^3`)が保持ソリッドに対して桁違いに小さくなり(充填率0.77%で2.2e6倍)、
  **`scipy.sparse.linalg.cg`はこれを「収束した」と言って返す**——再帰残差は`rtol`を満たすが
  真の残差はその約3000倍あり、警告は出ない。埋めるなら「真の残差での再スタート/対角スケーリング/
  初期場を一様にしない」のどれか。
- **箱を広げても費用は下がらない**(2026-09-03)。SIMPが下げるのは密度だけで要素は格子に残り、
  毎反復すべての要素が線形方程式に入る——「でかい箱にしても勝手に削れる」は答えについては
  正しいが費用は下がらない。大きい箱を払えるのは要素が粗いときだけ。

## メッシュ化(marching cubes + Taubin平滑化)

`mesh.py`のパイプライン。入口は`build_surface_from_mask`だけで、受け取るのは探索が返す最終確定
マスク(bool、6条件に合格済み・単一連結)。保持/除外の塗り直しや浮島除去はここではしない。

1. **ゼロの縁を1層足す**(`pad_field = np.pad(rho, 1)`)——材料が設計空間の端に接しているとそこ
   だけメッシュが開き水密でないSTLになる。
2. **marching cubes**(`skimage.measure.marching_cubes`)——入力は0/1の場なので辺の内分比は
   常に0.5、面は材料セルと空セルの境界に出る(階段状)。`level`は引数(既定0.5)。
3. **Taubin平滑化**(自前実装。pyvista/vtk/pymeshlabは使わない)——頂点隣接をscipyの疎行列で
   1度作り、離散ラプラシアン`L = D^-1 A - I`をλ→μの2段で適用する(λ=0.5・μ=-0.53・30反復が
   既定)。**`|μ| > λ`が本質的な条件**で、破ると通過帯域周波数が負になり形が縮む。
4. **STL書き出し**——自前のバイナリSTLライタ。

**Taubinの反復数は30**(`mesh.DEFAULT_ITERS`)。片持ち梁35×14×14で振ると、格子ファセットの残り
`f(k=1)^n`は6反復20%→12反復4.0%→**30反復0.03%**→45反復0.001%、体積変化は12反復-0.21%に対し
**30反復-0.003%**(45反復では+0.29%と増えに転じる)。費用はメッシュ化全体で10〜20msなので
無視できる。

### 1×1 の空隙を探索後に埋める(thin_voids.py。2026-10-07 本人判断)

Taubin 30回は1セル幅の構造を消すフィルタとして働くので、四方が材料で閉じた 1×1 の空セル(平滑化の文書でいう
「管」: 2軸以上で両隣が材料の空セル。板を貫く 1×1 の穴・止まり穴・1セルの窪み)は壁の間隔が 0.1 要素未満まで潰れ、
まれに壁どうしが交差する([TOPOPT_SMOOTHING_INTERSECTIONS.md](TOPOPT_SMOOTHING_INTERSECTIONS.md)。64条件で交差4箇所は
すべて管の中)。交差した入力は最終処理(`finalize`)が止めるので、**探索が確定したマスクの管を、メッシュ化の前に埋める**
(`thin_voids.fill_tubes`。設計空間の中だけ。除外ソリッド由来の空隙は埋めない)。1軸だけ挟まれた溝は実測で 0.12 要素以上
残り交差しないので埋めない(空側の opening(2) で埋めると溝1万セル超も埋まり、形の変化が1〜2桁大きい)。

- **埋めた形は探索が合格させた形と違う**ので、埋めたセルがあれば `acceptance.inspect` で6条件(FEM 1回)を取り直し、
  納品するのは最後に検査に通った形にする。結果の `safety_factor` は取り直した値、探索時の値は `search_safety_factor`、
  埋めたセル数は `filled_cells`。不合格なら `state="fill_infeasible"` で文書は変えない。埋めるセルが無ければ検査は増えない。
  最小幅の規則(m 立方の被覆)は6条件に無い。埋めたセルは2軸以上で両隣が材料なので m より細い材料の筋は作らないが、
  対角が空の配置(十字の中心など)では m 立方に覆われない(実測 2026-10-07、実際の設計空間で保持セルを対象外にして:
  探索の確定マスクは4条件とも規則を満たし、埋めると F2000_h2.4_w2 で 53 セル中 5、F2000_h2.2_w2 で 63 中 2、
  F1000_h2.4_w3 で 20 中 2 が覆われない。どれも保持セルに接しない)。覆われることを求めて止めると実データの多くが落ちるので、
  **保持セルと同じく規則の対象外として扱い**、数を `tube-fill` の `min_width.uncovered_filled_cells` に記録して
  `warning` に出す(`keep_cells_without_room` と同じ扱い)。
- 置き場所を探索後の1回(E1)にしたのは本人判断(2026-10-07)。候補評価ごとに埋める案(E2。追加の FEM は無いが、探索が
  掘った管を毎回埋め戻すので探索の挙動が変わる)と、探索規則に空側の幅の規則を入れる案(`peel` は平面の真ん中の1セル
  から抜くので、空側の規則には材料側の `casualties` の双対が要る)は採らなかった。平滑化側で頂点の移動を抑える案は、
  部品の内部に 0.1 要素のスリットを残すので採らない(空隙は残すのではなく無くす)。
- 実測(64条件、製品コード未変更の時点): 平滑化後の交差 21組 → 0、埋めたセル数は条件あたり 最小 0・中央値 7・最大 80
  (材料の 0.03%、最大 0.1%)、平滑化後の体積変化 −0.02%〜+0.06%、埋める反復は最大3回。
- **実測(製品経路、実際の荷重条件。2026-10-07)**: `topopt_checks/verify_tube_fill.py`(保存済みマスクを探索の確定マスクとして
  製品経路に通す。保存済みマスク自体の再検査が不合格・判定不能ならその時点で `not_done`)で、要素サイズ 2.4 mm の16条件
  (荷重 200〜2000 N × 最小幅 2〜5 セル)を回した。**16/16 が `done`、`fill_infeasible` は 0**。
  埋めたセルがあったのは 13 条件(2〜53 セル、中央値 8。合計 186)。埋めた後の安全率は全条件で下がらず、
  探索時の値に対して +0.001%〜+0.904%(中央値 +0.027%。最大は F1000_h2.4_w3 の 20 セル、F2000_h2.4_w2 は 53 セルで +0.548%)。
  目標(4.8)に対する余裕の最小は F1000_h2.4_w4 の 1.0028 倍で、探索時の余裕がそのまま残る。
  m 立方に覆われない埋めセルは 11 条件で計 23(186 中)あり、止めていたら 11/16 が落ちていた。
  1条件 40〜89 秒(6条件の検査 19〜43 秒 × 2 回を含む)、子プロセスのピーク常駐 1.0〜1.9 GB。
  記録は `output/smoothing_corpus/tube_fill_records/`(要素 1.8〜2.2 mm の 48 条件は未実施)。

**密度場側のガウシアン平滑化は既定を切り(2026-09-05)、実装ごと削除した(2026-09-14)。**
marching cubes出力に残る中周波のうねりをTaubinが落とせない帯域があり、ぼかしで隠していたが、
密度フィルタ半径を上げると筋そのものが消え、σを上げると薄板で体積乖離が15%を超えたため、
**「見えなくする」であって「滑らかにする」ではない**という結論で切った。ぼかす場合は保持/除外/
設計空間外を後から塗り直さないと壊れる。

## 設計上の決定(実測に基づく)

- **体積の二分探索は「フィルタ後の密度」の総和で判定する**(設計変数`x`の総和で判定すると境界
  付近で目標からずれる)。
- **カメラは外接球の半径と視野角から距離を出す**(「最大辺×係数」の目分量だと画面の1/6にしか
  映らない例があった)。
- **marching cubesの頂点座標は角(0,0,0)基準のまま書き出す**(STLは角基準のほうがスライサ・
  ビルドプレート原点と相性がよい)。**画面側だけ**中心原点規約に合わせて平行移動する
  (`optimize_run._mesh_to_world`)。
- **`rho[ex]`はセル`ex`の中心の値であり、パディング除去のオフセットは`(pad_width - 0.5) * spacing`
  が正しい**(`pad_width * spacing`を引くと面が設計空間に対して全軸一律に半要素ずれる。
  2026-08-30、QAが`mesh.py`で指摘・検査8を新設)。
- **巻き順は`run_marching_cubes`で`faces[:, (0,2,1)]`へ入れ替える(生成側で直す)**。`skimage`が
  返す巻き順は一般的な規約(STL/OCCT/three.js)に対して逆向き。**書き出しの直前ではなく生成側で
  直す**——巻き順に依存する消費者はSTLだけではなく(現在は`add_mesh_body`→`viewport.ts`)、
  書き出し1箇所で直す形だと消費者が増えるたびに漏れる(2026-09-02、ブラウザ表示だけ内向き法線が
  残る事故で発覚)。
- **最小肉厚は「法線がほぼ逆向きな近傍点との距離」で近似する**(3Dプリントの薄肉検出でよく使われる
  考え方)。marching cubes直後の階段状メッシュでは局所ノイズを厚みとして誤検出し実際より薄く出る
  ため、「平滑化後≥平滑化前」に振れるのが正常(実測比4.27)。
- **要素サイズ=1mmと仮定する**(`mesh.DEFAULT_SPACING=(1,1,1)`)。実寸を変えたいときは`spacing`を
  差し替える。
- **占有はセル中心の1点サンプルで、部分体積(占有率)は持たない**(全要素が同形状であることに
  依存する解法のため)。境界の表現を細かくしたいときは解像度を上げる。
- **符号付き体積は基準点(bboxの中心、殻ごとなら殻自身の点)を引いてから三重積を取る**(絶対座標の
  まま足すと原点から遠いソリッドで桁落ちする。実測: 原点から1e8mmの40×20×10の箱で8,000が
  7,957.33になった)。
- **向きの検査は殻(連結成分)ごとに行う**(総符号付き体積だけを見ると内部空洞の殻だけを裏返した
  入力が正のまま通る)。

### 空要素を組み立てから外す(void除去。2026-09-09)

**`void_mask`のパッシブ要素を剛性行列の組み立てから外す**(`fem.Model(active_mask=...)`。
`_iK`/`_jK`もactive要素ぶんしか確保しない)。4条件の比較(現行/void除去/疎パターン固定/
matrix-free)を受けて**void除去だけをmainへ入れる**(2つは支配関係に無く、メモリならvoid除去・
大きい問題の速度ならパターン固定。最も安く最も確実に効く1つを採った)。

実測(hanger 5.368mm・箱113,400/塊34,910・40反復・7スレッド): 全体159.1→**120.8秒**(75.9%)、
組立40.49→**12.07秒**(29.8%)、ピークRSS+2,590→**+1,287MB**(49.7%)、非零2,814万→**884万**
(31.4%)、ρ>=0.5の一致率100.0000%。**移植が正しいことの一番強い証拠は、mainとブランチの実装で
ρ場のSHA-256がビット一致したこと**。**Kそのものは変わる(emin媒質の寄与が消える)のでCG反復数は
動く**(bracket n=40で+19%、hanger 5.37mmで+4%)——「数値的に無害」は形の話であって費用の話では
ない。**組み立てを絞ったら目的値の総和範囲も解いた系と揃える**——`compliance`を全要素で足した
ままだと`c = F・U + (解いた系に無いemin媒質のひずみエネルギー)`になる(「同じ不変条件を assert
している検査があるか」ではなく「その検査は自分が変えた経路を通るか」を見ること)。

ピークメモリは箱ではなく塊(材料量)に比例する(実測 約13万要素/100万mm³)。疎パターン固定・
matrix-freeの2案はブランチ`topopt-assembly-comparison`にだけ残る(採用せず——疎パターン固定は
組み立てのピークだけなら軽いが実行全体では差が縮み、matrix-freeは粗格子作用素の構築で密ブロックが
かえって重くなる)。

### 中空構造を許容しない(2026-09-19)

**形状最適化は中空構造(閉じた空洞)を一切許容しない**(2026-09-19本人決定)。原文:

> duocadの形状最適化では中空構造を一切許容しない

- **定義**: 材料マスクの補集合(空)を6近傍で連結成分に分け、格子の外へつながらない成分を
  「閉じた空洞」と呼ぶ(`acceptance.void_components`)。貫通穴・格子面に開いた凹みは外へ
  つながるので空洞ではない。
- **検査**: 6条件の`watertight`(`acceptance.boundary_check`)が
  `irregular_vertices == 0 and void_components == 1`を見る。
- **探索の入口**: 設計空間そのものに閉じた空洞があれば`find_initial_feasible`が
  `input_contradiction`で止まる(`diagnostics['closed_voids']`)。
- **候補生成**: 段階3の削除は材料の表面に接するブロックだけ(内部を空にすると必ず空洞ができる)。
  段階4の`peel`は表面のセル(空の6近傍を持つ)しか抜かない。
- **除外領域が塊に完全に包まれている入力は入力矛盾として扱う**(2026-09-19の既定を2026-09-20
  本人承認)。
- **既知の限界**: 細い通路で外へつながる袋は定義上空洞ではないので通る——空の通路の幅の下限は
  未対応(最小幅の保証は材料の幅の規則で、空の側を見ない)。メッシュ化以降での空洞検査もしていない。

### 最小幅の保証(`min_width_mm`。2026-09-20)

**規則は2つ**(m>1のとき両方満たす。m=1は規則を持たない): **R(m)** 全材料セル(保持セルを除く)が、
材料だけのm×m×mのブロックのどれかに属する。**S(m)**(2026-09-21。`min_width.CoreConnectivity`)
侵食した芯(m立方が全部材料であるセルの集合)の連結成分が、保持セルを介したつながりまで含めて
1つにまとまる。**芯の隣接はm≥4で26、m≤3で6**(#122、2026-10-08。根拠と実測は
[TOPOPT_CORE_ADJACENCY_122.md](TOPOPT_CORE_ADJACENCY_122.md))——m≥4なら、保持を介さない芯の経路に沿って
ボクセルの材料の中を直径m×spacingの球が移動できる(十分条件で同値ではない。m≤3は立方そのものが滑る)。**R(m)だけでは、m立方が斜めにずれて1セルだけ重なるつなぎ目(首)を許してしまう**
(詳細は[TOPOPT_THICKNESS.md](TOPOPT_THICKNESS.md)節J3)。S(m)は芯が**全体で**つながるかを見るので、
首が芯のつながりの唯一の経路(橋)のときだけ、その断面が面でm×(m-1)セル以上あることを要求する
(保持セルを介した結びは保持ソリッドが規則の対象外なので細い橋でも通す)。
**輪の中の首は、両側の芯が輪の別の経路でつながるのでR(m)・S(m)を通る**(#120)——
hanger S2(m=6)の採用形では2つの塊が1セル幅の面だけで接する所が5か所あった。これは第3の判定
**局所くびれ判定**(`neck.NeckJudge`、停止理由 `skipped_neck`)が断る: 1手の後、材料の前線をつなぎ直す
最小の窓の中で芯の前線がつなぎ直されなければ却下する(方式・保証の範囲・実測は
[TOPOPT_NECK_RULE_120.md](TOPOPT_NECK_RULE_120.md))。主張できるのは「各手がくびれを新しく作らない」ことだけで、
初期形に既にあるくびれは咎めない。**したがって、表示している最小幅は「全セルがm立方に属する」という意味で
しか保証されておらず、部材の太さとしては保証されていない**(完成形の太さは持続ホモロジーの診断
`neck_persistence` が「幅不足の疑い/未確定/観測されなかった」で報告する)。

`m = ceil(最小幅[mm] / 実spacing)`(切り上げ)。**選べる m は、m × 実spacing ≥ 2mm を満たす最小の m(ただし m ≥ 2)から、
floor(格子の最短の辺のセル数 × 1/4) まで**(`min_width_cell_range`。2026-10-09 本人決定の**根拠の無い暫定値**)。
上限が下限を下回る解像度では選べる段が無く、要素サイズを下げるよう断る。**画面は数値を打たせず、この段から選ぶだけ**。
**指定なしの既定は選べるいちばん細い段**——m=1(制約なし)にはならない。**保持ソリッド由来のセルは
規則の対象から外す**(2026-09-20本人決定)——保持ソリッドは利用者が指定した実形状で、最終形状
ではunionで戻るのでボクセルの厚みは納品物の厚みと一致するとは限らないため。

**実装(`peel`)は「射影つき」**: 選んだセルxを抜くとき、抜いた後にm立方の被覆を失う材料セル
(巻き添え)を同じ一手で一緒に抜く(1セルずつ却下する方式だと、壁がちょうどm厚になった時点で
全部却下され安全率が目標を大きく超えたまま止まった。[TOPOPT_THICKNESS.md](TOPOPT_THICKNESS.md)
節I2・J3)。一口(x+巻き添え)は表面・支え(条件節点の最後のセルを奪わない)・多様体・連結・
**芯の連結S(m)**・**局所くびれ判定**の6条件を全て通るときだけ抜く。段階3は全材料を1回評価するだけで、評価前に大域
判定(`_mask_satisfies_min_width`/`CoreConnectivity.connected`)を通す。

**設計空間はopeningで先に絞る**(`find_initial_feasible`が最初にm立方のopeningで絞り、入口検査も
その空間に対して行う)。規則を満たす形は必ずm立方の和集合で、その立方は全て設計空間に入るので
**絞ることで失われる解は無い**。絞った結果が保持ソリッドや条件面を割ることはあり、そのときは
入口で止まる(`boundary_mapping_failed`/`input_contradiction`)。絞った設計空間の芯が1つにまとまら
ない入力への対処(何を落とすか)は**本人の判断待ち**(`diagnostics['min_width']['design_core_groups']`
に記録するだけ)。

**入口の範囲**: 下限`2 × 実spacing`(実装の登録時に決めた値。実測で決めたものではない)、上限
`格子の最短の辺のセル数 × 実spacing`(これより太い立方は格子に1つも入らない)。**保証できる幅は
段になる**(実spacingの整数倍だけなので、下限のすぐ上を入れるとmが1つ飛び要求より最大50%太い
部品が黙って出る)——`resolution_limits()["steps"][i]["min_width_steps_mm"]`が段の値を配り、画面は
段のボタンと切り上げ先の%を出す。opening自体の費用はm³ではなく**m比例**(3軸の直線erosion→
dilationに分ける。`min_width.cube_opening`)。

**保証されるのはマスクの幅で、書き出すsolidの幅ではない**(平滑化で細くなりうる。合成の角材で
t=2は平滑化後-9%)。既知の限界・保証しないものの詳細と全実測は
[TOPOPT_THICKNESS.md](TOPOPT_THICKNESS.md)(節I〜N)。

## 固定凸包による設計空間(2026-09-16)

**塊(設計空間)は材料量によらず1実行に1回だけ導出する。** 参照SIMP・順位・回廊による切り出し
(連続値保持)とその設定は削除した。

### 導出(`design_space.derive`)

1. 保持ボディと、拘束面・荷重面が属するボディを重複なく集め、ボディごとのB-repの外接箱
   (`useTriangulation=False`)を取る。除外だけのボディ・無関係なボディ・以前の最適化結果は
   入れない。
2. 外接箱の8頂点(重複除去)を`scipy.spatial.ConvexHull`にかけて凸包を起こす。点群の外接箱の
   最長辺Lに対して余白`m = 0.20 × L`(`DEFAULT_MARGIN_RATIO`。0.25から2026-09-16本人判断で
   下げた)。
3. 格子の外枠は点群の外接箱を各軸にm広げた箱。セル中心が外枠に入り、かつ**凸包から距離m以内**
   (凸包と半径mの球のミンコフスキー和。距離は内側0・外側は表面三角形への最短距離)のセルが候補
   (計画時は支持平面のオフセットだったが、2026-09-16本人判断で距離へ変えた——平面オフセットは
   角・稜のぶん多面体が実際より大きくなる)。
4. 除外ソリッドの占有を引く。保持ボディを1つずつ格子に載せ、除外との衝突は
   `DesignSpaceConflictError`、0セルは取りこぼしとして記録する。
5. 保持ボディごと・拘束面ごと・荷重面ごとを種にして6近傍の連結成分を取り、**全条件が共通の
   成分を持つ**ことを確かめる(`connect_seeds`)。無ければ`DesignSpaceDisconnectedError`
   (上「塊の連結性」参照)。
6. 確定マスクで`VoxelModel`を1回組み、`DesignSpace`を返す(`mask`は読み取り専用、
   `stats["mask_hash"]`にハッシュ)。

点群の階数不足・非有限値・箱の裏返り・Qhullの失敗は`DesignSpaceGeometryError`/`ValueError`
(ランダム摂動や黙った退避は無い)。6近傍の接続は「材料を置ける道がある」ことであって、部材幅や
剛性の保証ではない。

**現在の呼び出し経路**(段階5〜6で書き換え):

```text
optimize_run.run
  └─ trace.recording(doc, options) の中で _run(doc, options, ...) を呼ぶ
       ├─ design_space.derive                固定凸包の塊を1回導出(格子・設計マスク・保持マスク・面アンカー表)
       ├─ 条件面・保持/除外の点検              空の条件面 / 表現できていない領域 → 早期return
       ├─ binary_search.find_best_feasible(space.mask, conditions, max_evaluations=..., is_cancelled=...)
       │    ├─ find_initial_feasible          初めての6条件合格を探す(段階3)
       │    │    └─ 候補ごとに: 幾何検査(境界・単一成分・保持/除外/荷重欠落) → fem.Model.solve → stress.evaluate
       │    └─ _reduce_volume                 エネルギーの低い材料を安全率の余裕に応じて削る(段階4)
       │         └─ 各候補: 支えを残して選ぶ → 水密の修復 → 島処理 → 6条件(FEM。要素エネルギーも返す)
       ├─ thin_voids.fill_tubes               平滑化で潰れる 1×1 の空隙(四方が材料で閉じた空セル)を埋める
       │    └─ acceptance.inspect             埋めたセルがあれば6条件(FEM)を取り直す(不合格なら fill_infeasible)
       ├─ mesh.build_surface_from_mask        埋めた後の確定マスクだけをメッシュ化
       ├─ finalize.finalize                   平滑化後の表面を検査 → 0.01 mmで分割した保持を足し除外を引く(manifold3d)
       │                                      → 簡略化 → 接続6項目・単一ソリッド・float32・自己交差で検査
       └─ add_mesh_body                       合格した三角形をメッシュボディとして文書へ追加
```

**候補中はメッシュ化を呼ばない**——後段へ渡るのは`binary_search.find_best_feasible`が返す最終
確定マスクだけ。**探索候補はbool二値マスクの操作(段階4の削減)**で、材料量は結果として出る値
であって探索変数ではない。`rmin`・`MATERIAL_MIN_RATIO`/`MATERIAL_MAX_RATIO`・`estimate_seconds`
は段階6でコードごと削除した(渡すと`OptimizeInputError`)。

### 境界条件の確定(2026-09-17)

導出が条件ごとの接続確認に使う面アンカーの表(`DesignSpace.table`)は**材料の有無を見ない**
(標本点から半径1要素の球内の節点へ面積を配り、節点が格子内かだけを見る)。一方、6条件の
「荷重・拘束が有効」と探索の島処理は**全アンカー節点が材料に接する**ことを要求する。格子面に
乗らない面(hangerの荷重面はトーラス)では面の外側(除外ソリッド側)の節点にも配られ、その節点は
どの設計セルにも接しない——導出は通るが全材料マスクが`no_component`になる。

直し方は境界条件の側: `optimize_run._map_boundary_conditions`が`acceptance.active_nodes(space.mask)`
(導出出力に接する節点)を`anchor.build_anchors(..., allowed_nodes=...)`に渡し、**標本ごとに球内の
許可節点だけへ重みを配った確定表**を作る(球内に許可節点が無い標本は対応不能として面・座標付きで
残し、遠い節点へ移さない)。`anchor.condition_mapping`が面ごとに節点数・対応不能標本・被覆・合力
(数値許容差)・**作用位置**(CAD面の面積重心から節点の担当面積重心まで≤探索半径r、荷重面では
原点まわりのモーメント誤差≤r·\|F\|。`anchor.position_limit`)を検証し、不成立なら
`state="boundary_mapping_failed"`で探索を始めない。探索の入口(`find_initial_feasible`)も表を全
設計空間で検証し直すので、直接APIで不成立の表を渡しても止まる。

許容を探索半径にしたのは、それが対応規則そのもの(各標本の面積を半径r以内の節点へだけ配る)の
分解能だから——稜線の所有権で面積を失わない限り、節点の重心は標本の重心から凸結合で必ずr以内に
収まる。**実測は[FIX_BINARY_SEARCH_INITIALIZATION.md](FIX_BINARY_SEARCH_INITIALIZATION.md)§9**
(hanger 4.8mm/2.4mmの幾何の表・確定表・作用位置の門・6条件の全数値)。確定した節点・荷重・拘束と
対応付け規則は評価条件ハッシュ(`binary_search.evaluation_identifier`)に入る。記録は
`boundary-mapping`([TOPOPT_RECORDING.md](TOPOPT_RECORDING.md))。

`rmin_mm`は現在の探索に存在せず、`Session.run_optimization`/`optimize_resolution`に渡すと
`OptimizeInputError`になる。`resolution_limits`の上限を実格子の要素サイズへ切り下げる処理
(`optimize_run._snap_to_grid`)は、要求値と実際に使う格子の要素サイズを一致させるために現在も
残っている。

## duocad 本体への配線・設計と画面(`duocad/optimize_run.py`)

条件を置く4 verb(`set_preserve_bodies`/`set_exclude_bodies`/`set_fixtures`/`set_loads`)の続きが
`duocad/optimize_run.py`である。verbは1本も足していない——結果を文書へ入れる口は既存の
`add_mesh_body`だけで、**元のボディは1つも消さず・形も差し替えない**(最適化は編集ではなく
「条件から新しい形を1つ作る」操作)。

```
Session.optimize_conditions()     4条件がそろって走らせられるか(足りないものを名指しする)
Session.optimize_resolution(...)  要素サイズの上限・下限・既定(element_size_mm を渡すとその値の段 selected も返す。画面の自由入力)
Session.run_optimization(...)     端から端まで走らせ、結果をメッシュボディとして足す(重い)
Session.cancel_optimization()     走っている最適化に降りるよう伝える(旗を立てるだけ)
```

**`rmin_mm`・`max_iter`・`material_min_mm3`/`material_max_mm3`は段階6で削除した。** 二値探索は
連続密度もSIMP反復も持たないので渡しても意味の翻訳先が無く、渡すと`OptimizeInputError`にする
(`TypeError`ではなく意味を説明した文で断るため)。

**要素サイズの上限＝「これより粗いと間違う」は、固定値 4mm(`MAX_ELEMENT_SIZE_MM`。2026-10-09 本人決定、#130)と
条件面からの要求の細かい方**。条件面からの要求は`sqrt(CAD面積)`の最小値で、
`anchor.empty_face_diagnosis`の`suggested_max_spacing_mm`と同じ式(近似・保証ではない)。固定値は完成形の検査
(`topopt.final_check`)のためにある —— 条件面だけで決めると面の大きな題材で格子が粗くなり、完成形で拘束面を割り当て直せず
安全率が測れなかった(path 題材: 条件面 200mm² で上限 14mm になり測れず、5mm・2.5mm では測れた。
[TOPOPT_NECK_RULE_120.md](TOPOPT_NECK_RULE_120.md)「実装と実測」)。4mm で必ず測れる保証ではない(「受入検査の題材の大きさ」節の「N mm以下なら通る」は書けない、と同じ理由)。
上限は実格子へ切り下げた値(4mm → 3.98mm など)だが、`element_size_mm`は切り下げる前の値まで受け付ける。
部品が大きいと、上限の 4mm が設計空間の要素数から決まる下限を下回り、解像度を作れない(256mm 立方の外接箱で下限は約 3.26mm)。
**密度フィルタ半径(rmin)は上限に効かない**——二値探索は密度フィルタを持たない。

**要素サイズの下限は設計空間の要素数で決める**(`MAX_DESIGN_ELEMENTS` = 1,300,000。2026-09-26 本人判断: 「1.6 mm が通る130万」)。
格子の箱の数は上限に使わない。ピークメモリを決めるのは組み立てに載る要素数(設計空間=塊。空要素は外れる)で、
hanger は箱の約42%しか塊にならないので、箱の数の上限では同じ値でもモデルの形でメモリが約2.4倍振れる。
既定は上限側(条件を満たす最も粗くて安い設定)で、時間は制約にしない。旧`estimate_seconds`は段階6で削除しており
後継の見積もり機構は無い(利用者が見られるのは完了後の経過秒数だけ)。

**二段で判定する。実行前は見積もり、実行時は実数。**

- `resolution_limits`(画面が実行前に呼ぶ): 設計空間の要素数を幾何から見積もる。
  見積もり = 余白付き凸包の連続体積(`design_space.offset_hull_volume`。凸包 + 半径 m の球のシュタイナーの公式
  `V + A·m + m²·Σ(稜長×外角)/2 + 4π/3·m³`)× 除外に食われない割合(`design_space.obstacle_free_fraction`。
  分割数60の粗い格子で数える。除外が無ければ割合は1)を要素サイズ³で割る。下限と目盛りの要素数はこの見積もりで決まる。
  目盛りの要素数は画面で「約N要素(見積もり)」と出す。
- `run()`: `derive` の後、実数 `space.element_count` が上限を超えたら探索の前に `OptimizeInputError` で止める

**1.6 mm(設計空間 1,272,625 要素・箱 2,997,300)の実測**:

  メモリとは無関係)。途中のメモリの推移は `output/limit_run/F2000_h1.6_w2.progress.jsonl`(30秒ごと)。

**保持・除外ソリッドからは上限を厳密に計算できない**ので、ボクセル化したあとに数えて通知する
——保持/除外を1つずつ格子へ載せ、0要素なら最適化を回さず`state == "unrepresented_regions"`で
戻る(合計で見ると大きい保持ソリッド1つで小さいほうの消失が隠れるため)。

**許容応力は固定**(上「許容応力の導出」)。利用者が入れるのは**目標安全率**で、
`binary_search.find_best_feasible`が6条件を満たす最小体積のboolマスクを探す。**探索(と6条件の
`safety`)に渡す目標は実際の目標×2.4**(`optimize_run.SEARCH_TARGET_FACTOR`。探索の格子は細い
部材の曲げ・ねじりの安全率を過大に出すため。最小幅の既定がm≥2になった〈2026-09-22〉ので係数の
根拠は常に成り立つ)。決定・根拠・実測は[TOPOPT_TARGET_FACTOR.md](TOPOPT_TARGET_FACTOR.md)。

**この版の制限**:

- **荷重は「同時にかかる1つの荷重系」だけ**。拘束面・荷重面は何枚でもよく面ごとに大きさ・向きが
  違ってよいが、扱えないのは**別シナリオ＝複数荷重ケース**(合成するとどちらの単独荷重にも
  耐えない形が出るため)。
- **保持ソリッドは1つ以上必須**(塊は保持ソリッドと条件面から起こす)。
- **拘束面・荷重面は保持ソリッドの面に限る**(2026-09-18本人指示)。保持でないボディの面に置くと
  確定表が半径1要素の球で「生きている節点」を拾うため、元のボディが1要素も取れていなくても
  周りの材料の節点へ荷重が載る(実測: 54ケース中13件。[TOPOPT_THICKNESS.md](TOPOPT_THICKNESS.md)
  D節)。
- **メッシュボディは保持・除外に指定できない**(README §4「ボディの種別」)。

**面の対応がこの配線でいちばん壊れやすい。** 条件面が複数のボディに散ると`kernel.make_compound`
でまとめる際に面添字がずれる可能性があり、**ずれても例外は出ない**(荷重が別の面に入り最適化は
もっともらしく収束する)。網を2枚張ってある: `_verify_face_mapping`(まとめた形で測り直した指紋
〈面積・法線・**重心**〉が単体の指紋と一致するか。重心を外すと同形の別ボディの取り違えを見逃す)
と`_check_anchor_centroids`(実際にできた面アンカーの節点の重心が条件面の重心の近くにあるか)。
同じ性格でもう1つ: 結果メッシュの頂点は要素添字空間で返るので`grid.origin + verts * grid.spacing`
でワールド[mm]へ直す必要があり、`_check_mesh_placement`が毎回見る。

### 受入検査 `check_optimize_wiring.py` が見ているもの

**この1本だけが本物を回す**(`tests/test_optimize_backend.py`はFEMを1回も回さない——pytestを
重くしないため)。題材は離れた2つのパッド(拘束側10x40x40/荷重側10x40x10を離して置く。
`element_size_mm=4.0`〈`CHECK_ELEMENT_SIZE_MM`〉を明示している——既定解像度だと
`voxelize.occupancy`のレイキャスト頑健性の既存バグを踏むため)。

0. **端から端まで** — `state == "done"`、ボディが1つだけ増え、それがメッシュボディで、元の
   ボディは1つも消えず・形も差し替わらない。戻り値が素の値だけでできていることも見る。
1. **結果メッシュの位置** — ワールド[mm]で格子の箱の中にあり両パッドに届いている(要素添字空間の
   まま入れると原点付近に縮む)。
2. **荷重・拘束が選んだ面に入っている** — 面アンカーの節点の重心と条件面の重心の距離(面添字の
   取り違えは例外を出さないため、実際に走らせた結果で突き合わせる)。
3. **進捗(パイプラインの段ごと)** — 評価(FEM1回)ごとに`phase="search"`が来る。SIMP時代の
   「設計反復ごと」の段(`phase="optimize"`)はもう無い。
4. **中断** — 進捗の途中で旗を立てると`OptimizeCancelled`になり文書は1ビットも変わらない。
5. **応力を測る経路** — 最終確定マスクで解き直して安全率が出る。許容応力40MPaの導出も見る。
6. **事後検出** — 1要素も掴めない保持ソリッドがあると探索を回さず`state == "unrepresented_regions"`。
7. **条件面からの要求要素サイズ** — `_face_max_spacing_mm`と`anchor.empty_face_diagnosis`の
   `suggested_max_spacing_mm`が同じ値になる。

### 画面から走らせる(`web/src/OptimizePanel.svelte`)

WebSocketに4つの口(`optimize_conditions`/`optimize_resolution`/`optimize_status`/
`optimize_progress`/`optimize_result`/`optimize_error`)。**MCPには開けていない**——数分かかる
同期呼び出しをツールにすると進捗も中断も運べないままタイムアウトする。

**重い処理は`asyncio.to_thread`で回す**(`_dispatch`の中で待つと同じ接続から届く
`cancel_optimization`が読めなくなる)。**中断の旗を畳むのは別スレッドへ投げる前**
(`Session.begin_optimization`。ワーカーの中で畳むと、走り出す前に届いた中断が消える)。
**接続した画面には最初に`optimize_status`を送る**(開始・終了・中断のときにしか配らないので、再読み込み
した画面は中断ボタンを失い、終わる瞬間に切れていた画面は実行中のまま固まっていた)。
**結果を足した(`state == "done"`)ときだけ、足した直後に`save_document()`で
ディスクへ書く**(2026-09-13〜。足さなかった実行で書くと未保存の編集でファイルを上書きする。保存の失敗は
種類を問わず警告に積み、結果と終了の`optimize_status`は必ず配る)——進捗も結果もサーバプロセス1つのメモリにしか無く、プロセスが
入れ替わると実行中/完了直後の結果は跡形もなく消える(2026-09-13実測: 数時間がかりの実行が保存前
のプロセス入れ替えで消失した)。長時間の最適化を回す間に落としていけないのはブラウザタブでは
なく、そのタブが繋いでいるサーバプロセスとPCのスリープである。

**解像度は「既定＝粗い側の端。細かくする方向にだけ動く目盛り」。** 粗い側の端は「正しさ」の境界
(割ると条件面から節点が消え、最小部材幅が表現できない。しかもsilent)、細かい側の端は「都合」の
境界(遅い・落ちる、それだけ)。目盛りは`resolution_limits()["steps"]`(等比。添字0が上限側＝既定)。
各段に予想時間は付けない(段階6で旧SIMP係数モデルを削除したため)。

**通知はトーストとパネルの二重に出す。** トースト(8秒で消える)は「結果が信用できない」という
意味の文には向かないので、パネルの`#optimize-notice`に次に走らせるまで残す。**中断はエラー扱い
にしない**(赤い札を出さず「文書は変わっていない」だけを残す)。**実行中は走らせている文書を変える操作を
すべて断る**(`Session` の `DocumentBusy`。verb・Undo/Redo・パラメータ・読み込み・プレビュー。
選択・表示の切り替え・保存・書き出しは通す)——最適化は開始時の文書を持ったまま走り、終わりにその文書へ
結果を足して保持・除外の形を読み直すので、途中で変えると古い条件の形が足される(issue #26)。
ブラウザ・MCP・アプリ内AIはどれも `Session` を通るので1箇所で止まり、MCPには`busy` で返る。画面も
その文書を開いている間はverbの行・Undo/Redoのキー・スケッチへの出入り・最小部材幅・解像度・「抜ける」を止める。

**走らせたまま別の文書へ移って編集してよい**(2026-10-04 本人指示。目標は「戻ってきたら終わっている、
または実行中である」)。開く・新規は実行中も通し、実行は開始時の`Document`を持ったまま裏で走り続ける。
結果は`Session.deliver_optimization_result`がイベントループのスレッドで届ける: 開いたままならその文書へ、
別の文書を開いていればそのファイルの操作ログへ書く(`add_mesh_body`は頂点を丸ごとログに積むので、
ログを書けば結果は完結する)。書けなかった結果はメモリに残し、次にそのファイルを開くと結果入りで開く。
走らせているファイルを開き直した写しは名前で見分けて編集を断り、終わったら実行の文書へ差し替える。
走らせているファイルの改名・別名保存・削除は断る(結果が元の名前へ書き戻されて復活する)。
**進捗・実行中の表示・結果は、走らせている文書を開いている間だけ出す**(`optimize_status.running`は
「いま開いている文書で走っているか」)。離れている間の最後の進捗と、離れている間に終わった結果/失敗は
控えておき(`Session.unseen_optimize_results`。ファイルを消すと一緒に捨てる)、その文書を開いたときに配る。
離れている間に出た結果の警告と「ファイルへ書けなかった」は、トーストにせず結果の`warning`に載せて
戻ってきたときのパネルの通知で読ませる。同時に走らせられるのは今も1本だけ(1.6 mm の実行は
ピーク24.2 GBで、2本はメモリに収まらない)。計算はサーバと同じプロセスの別スレッドのまま。

**パネルはビューポート左のブラウザと同じ列の下端に出す**(画面に新しい帯を取らないため——右へ
帯を足すと`viewport.project()`の`clickable(x,y)`判定で左のボディの面が1枚も指せなくなった)。
**結果は積み上がる**(名前は`optimized`/`optimized-2`/…、置き換えない)。**メッシュボディのピック
はボディ選択へ畳む**(`App.svelte`の`pickedRef`)——素直に翻訳すると`kind:"face"`参照になりコアの
`select_face`が断るため、この畳み込み1本で「押せるのに断られる」を消している。

## 制限(承知のうえで残しているもの)

- **画面から面を選べない。** 境界条件UIと非同期ジョブ化は本タスクの範囲外(2026-08-29のスコープ
  確定)。面添字を受け取る側の口(`fixed_dofs`/`load_vector`/`element_mask`)は揃っている。
- **要素サイズより小さい面には節点が付かない**(稜線の規則の帰結。実物STEPを1.54mmで割ると231面中
  22面が空)。入口でメッセージが出るようにしてある(上「塊の連結性と境界条件の入口検査」)。
  **多数決の規則を曲げて小さい面にも節点を付ける、という本当の解決はまだしていない**——節点1つへ
  の点荷重は特異点になる。
- **担当面積は真の面積より数%小さい**(稜線で隣の面に取られたぶんを再正規化しない設計)。
  `load_vector`の総和はこの差から独立。面積が要るなら`FaceAnchor.cad_area`を使う。
- **固定凸包は「塊が答えを含む」ことを保証しない。** 幾何の被覆の確認であって構造性能の確認では
  ない。
- **つながり検査(`connect_seeds`)は道の細さを見ない。** 幅1要素の糸でつながっている塊も設計
  空間としては通る。
- **既定の(いちばん粗い)解像度が`voxelize.occupancy`のレイキャスト頑健性の既存バグを踏み、一部の
  条件では`ValueError`のまま失敗しうる**(段階5で発見・本人判断待ちのまま持ち越し。
  `check_optimize_wiring.py`は`element_size_mm`を明示して回避している)。

## 受入検査の題材の大きさ

**方針: 解像度と反復数は検証が速い側に倒す。性能と品質を詰めるのは配線の後**(2026-09-04本人指示)。
**縮めなかったもの**(縮めると検出力が落ちることを実測で確かめた):

| 場所 | 残した大きさ | 縮めたときに壊れるもの(実測) |
|---|---|---|
| `check_mesh.py`の題材 | 35×14×14 / 15反復 | marching cubes直後の体積誤差。20×8×8では**9.19%**まで育つ |
| `check_anchor.py`[5]の円筒面 | `n=32` | 検出力の実測値が閾値の上下で暴れる(n=32で3.53%・n=24で1.03%) |
| `check_stress.py`[4b] | 20×10×10 / 25反復 | 16×8×8だとパーセンタイルが効いている証拠(1.5倍以上)が1.18倍に落ちる |

**実機(hanger)の検証・測定で使う要素サイズは2.4mmと1.2mm**(2026-09-18本人指示)。**4.8mmは以後
使わない**(製品で選ぶ値としては粗すぎ、そこで通ったことが製品の保証にならない)。

**値が単調ではない場所**: `voxelize.occupancy`のレイのずらしは格子が粗くなると飛び飛びの解像度で
縮退する(実測: `CASE1_LONG_AXIS`が**12と16で落ち**、13/14/15/17/18/20/22は通る)。**「小さいほど
危ない」ではない**ので1点で試して通ったら採る、をやらないこと。

**hangerの作業解像度は2.4mm**(2026-09-09実測)。**要素サイズについて「N mm以下なら通る」という
書き方はできない**——格子の原点と刻みが要素サイズごとに引き直されるので、保持/除外が0要素になる
要素サイズが飛び飛びに現れる(hangerでは4.2/4.6/5.333mmは落ちるが4.4/4.8mmは通る)。**安全率は
材料量に対して単調だが傾きが大きく揺れる**(材料を半分にするごとに0.127〜0.669倍)——2点から
外挿して交差点を当てようとすると必ず外す。

## 受入検査が見ているもの

**走らせ方は`readme.md`§3「形状最適化の受入検査」にある。** ここに書くのは各`check_*.py`が何を
守っているか。どれも最後の行が`OK:`で、終了コードが0なら合格。

`check_fem.py`(二値FEM=`fem.py`を検査する)が見ているもの:

1. **要素剛性行列** — 対称/半正定値/剛体モードがちょうど6本/**パッチ試験**(一様ひずみ・せん断の
   ひずみエネルギーが弾性論の値と1e-10相対で一致)。
2. **全体系** — `K U = F`の残差/拘束DOFが0/**コンプライアンス=F・U**/荷重と拘束がz対称。
3. **移設前一致** — 複数の格子・void配置ケースで移設前の計算と数値が一致する。
4. **void要素の除去** — `active_mask`で組み立てから外した要素の扱い(上「void除去」)。
5. **反力と多重右辺** — `fem.reaction_forces`の荷重釣り合い、複数右辺の同時解。

`check_mesh.py`が見ているもの:

1. **水密** — 全ての辺がちょうど2枚の三角形に共有される。孤立頂点・縮退三角形が無い。
2. **体積の一致** — marching cubes直後のメッシュ体積が`sum(rho_clean) × 要素体積`と一定範囲内で
   一致する(閾値と題材の大きさは対で読む。上「受入検査の題材の大きさ」)。
3. **Taubinが体積を保つ** — 平滑化の前後で体積変化が5%以内。
4. **Taubinが素のLaplacianより縮まない** — 「Taubinと名乗っているが実はLaplacian」の検出。
5. **補間が効いている** — marching cubesの頂点の内分比の標準偏差が0でない(二値化した場では
   厳密に0になる)。
6. **最小肉厚** — 平滑化の後も最小肉厚が平滑化前の50%を下回らない。
7. **STLの往復** — 書き出したSTLを読み戻し、三角形数と体積が一致する。
8. **座標系の整合(セル中心規約)** — 既知の位置に置いた合成密度場で、面のバウンディングボックスが
   期待どおりの位置にある(1〜7はどれも並進不変で**全軸を一律に半セルずらす**類のバグを検出
   できない。2026-08-30にQAが実データで発見。上「設計上の決定」参照)。
9. **面の向き(巻き順が外向き)** — 発散定理の符号付き体積が正であることと、共有辺が逆向きに
   たどられることの両方で確定する。**1〜8で巻き順を見るのはこの検査だけ**で、それはSTL経路しか
   通らないため、`mr.faces`を直接使う消費者(`add_mesh_body`→`viewport.ts`)が内向きのまま残る
   事故を捕まえられなかった(2026-09-02発見)。
10. **保持/除外の塗り直し** — 合成密度場に塗り直しを掛け、保持=1・除外=0が厳密に保たれること、
    できたメッシュを焼き直して保持マスクが内側・除外マスクに材料が無いことを見る。

`check_voxelize.py`が見ているもの(合成ソリッドだけ):

1. **OCCTの神託との一致** — `BRepClass3d_SolidClassifier`の判定と高速経路が一致する(要素の中心
   だけを比べる。表面から要素サイズの5%以内の中心は集計から除く)。
2. **既知形状の体積が収束する** — 格子に対する形状の位置を**サブセル単位でずらした10通りの平均
   誤差**が解像度とともに単調に減る(1点の誤差では単調にならない。実測: 円筒の相対誤差はn=16で
   0.4%・n=24で3.5%と増えるが、平均するとn=8→64で3.9%→0.2%)。
3. **貫通穴が埋まらない** — 穴の内側が1要素も占有されず、実体側は隙間なく埋まる。
4. **壊れた入力で黙って通らない** — 開いたシェル/向きを裏返した面/裏返したソリッド/**内部空洞の
   殻だけを裏返した中空の箱**/閉じていない三角形群、の5種で`ValueError`。健全な入力が通ることも
   見る。
5. **保持/障害物マスクが設計空間の内側に収まる** — 外へはみ出した分が捨てられ件数が報告される。
   設計空間とまったく重ならない領域は理由つきで拒否される。
6. **決定性** — 同じ入力で2回呼ぶと格子もマスクも完全に一致する(同じ形状オブジェクトを使い回して
   も。2026-08-31にここで欠陥を発見)。
7. **セル中心規約の整合** — 辺長が要素サイズの整数倍の軸整列の箱は、どの解像度でも体積が厳密に
   一致する。
8. **縮退したレイでも壊れない** — 上面の対角線が列の中心を厳密に通る箱で、既定のずらしでは体積が
   一致し、ずらしを切ると共有辺の交点を縮退として検知して落ちる(検知が空振りでない確認)。
9. **表面までの最短距離(`closest_triangle`)** — 退化した三角形での反例、標本化した参照値との
   突き合わせ、重心から`face_index`で元の面へ戻れること。
10. **トリムされた曲面のソリッドのbboxが実寸を返す** — 題材にトリムされたトーラス片を使う
    (箱・円柱・平面だけでは`Add`と`AddOptimal`が一致して検査が動かない)。

`check_anchor.py`が見ているもの(合成ソリッドだけ):

0. **節点番号と境界条件の口の契約** — `NodeGrid`の通し番号が`fem._build_edof`と一致する(全要素×
   8隅)。`fem.Model(fixed_dofs=None)`の既定が非空であることと、拘束不足が名指しした例外で落ちる
   ことも見る。
1. **総荷重の保存** — 節点荷重の合計が指定値と一致する(相対1e-12。実測2.3e-16)。圧力の合力が
   `p × cad_area`と一致することも見る。
2. **解像度非依存** — 担当面積の相対誤差と重心の誤差が解像度4倍で半分以下になる。
3. **面の取り違えが無い** — 節点集合が排他、全面について自分の面の三角形から殻の半径以内。
4. **法線が合っている** — CAD法線と厳密に一致し、節点の位置だけから主成分分析で出した面の向きとも
   一致する。
5. **偽の集中が出ていない** — どの節点も要素1個ぶんの1.5倍を超えて担当しない。ガウス核で平滑化
   した荷重密度が真の面積分布と1.5%以下でずれる(**面積重みを外した対照は実際に落ちることまで
   確認する**。実測3.4%/3.5%)。
6. **稜線の扱いが宣言どおり** — 全面の節点集合が互いに排他で、競合した節点がすべて「最も多く
   配った面」へ行っている。

## 平滑化の検証材料(smoothing_corpus。2026-09-25〜26)

平滑化ロジックを改良するための使い回す材料。hanger を **荷重 200/500/1000/2000 N × 要素サイズ 1.8/2.0/2.2/2.4 mm ×
最小幅 2/3/4/5 セル = 64 条件**で製品の `optimize_run.run` に通し、`mesh.build_surface_from_mask` に渡る直前の
二値マスクを `output/smoothing_corpus/`(git 管理外)へ保存した。再生成は `topopt_checks/sweep_smoothing_corpus.py --detach`
(再開可。使い方と出力は先頭の docstring)。

- **マスクは製品の実行の中で捕まえる**(`build_surface_from_mask` を差し替えて渡された配列を控え、例外で降りる。探索・島除去は
  製品のもので、平滑化・finalize は回さない)。`voxel/<条件名>.npz`(mask・origin・spacing・shape)と、同じマスクの材料セルの
  境界面を1面2三角形にした `voxel/<条件名>.stl`(ワールド mm・外向き。座標は `optimize_run._mesh_to_world` と同じ規約)。
- **STL と製品の面の突き合わせ(64条件すべて)**: 巻き順は外向き。同じマスクの marching cubes の頂点(平滑化前)はボクセル境界から
  最大 4.4e-6 セル(=境界上。二値の場なので辺の中点がセル面の中心に来る)、Taubin 平滑化後は 0.48〜0.63 セルに離れる
  (`--verify <条件名>`)。
- **64 条件すべてが `converged` で完走した(解なし 0)**。評価回数は 13〜323。安全率の窓(目標×2.4 の +1%)に入るまでの間、
  最小幅が太い(4〜5 セル)・荷重が軽い条件は採用が1手ずつ進んで数時間かかる(最長は F0200_h2.2_w4 の 5.9 時間・323 評価。1.8 mm の最長は F0200_h1.8_w4 の 5.8 時間・203 評価)。
  1条件のピークメモリは 2.4 mm 7.5 GB・2.2 mm 9.4 GB・2.0 mm 12.4 GB・1.8 mm 16.7 GB(上記の表の続き)。
  ピークは探索の最初の評価(全材料)で立ち、その後の削減は 1 GB 未満・1コアなので、起動から10分空けて順に上げれば
  RAM 約32GB で最大10条件を並べられた。子プロセス時間の合計は 約67 時間(全体の経過は約21時間)。
- 完全な実行記録(`output/optimization_runs/`)は条件ごとに一時フォルダへ書いて消したので、64条件分は残していない
  (残したのは `output/smoothing_corpus/` の 143 MB)。
