# 最終形状の合格条件と最終処理の検査

最適化の最終処理(平滑化 → メッシュ集合演算 → 最終メッシュ)で何を合格とし、どう検査するか、その根拠の実測をまとめる。
島除去後・平滑化前の受入検査、平滑化後の自己交差の規則(`thin_voids` の根拠)、メッシュ集合演算の採用根拠もここに持つ。
穴口の微細隙間とメッシュ欠損は [TOPOPT_GAP_CAUSALITY.md](TOPOPT_GAP_CAUSALITY.md)。

現在の合格条件は、`models/hanger_bar_attachment.json` の最終出力の **水密性（自己干渉なし）・単一ソリッド** の2つ。
保持・除外は既定の合否判定から外し、平滑化後のメッシュ集合演算で反映する。

製品経路は `密度 → 島除去 → 1×1 の空隙(四方が材料で閉じた空セル)を埋めて6条件を取り直す(thin_voids) →
表面生成 → Taubin平滑化 → 平滑化後の表面の検査(接続6項目・向き・自己交差) →
保持・除外を線形偏差0.01 mm(`STL_DEVIATION` と同じ値)・角度偏差0.35 radで三角形分割して同じ検査 →
(表面 + 保持) − 除外(manifold3d、倍精度) → 入力面の由来を捨てて 1e-5 mm で簡略化 →
float32 で潰れる三角形の最短辺(1e-5 mm 未満)を潰す →
最終メッシュの検査(接続6項目・単一ソリッド・float32の縮退と頂点一致・自己交差) →
完成形の検査(探索の格子で解き直した安全率、つなぎ目の幅の診断。`duocad/topopt/final_check.py`) → 文書保存`
(`duocad/topopt/finalize.py`)。重複領域は除外が優先する。入力の不合格、空の結果、分断、自己交差を
成功扱いにしない。**小さいから通す判定は無い** —— 平滑化後の表面に自己交差があれば、それが4組でも
最終処理は入力検査で止まる。
結果はメッシュボディとして三角形を操作ログに保存し、表示とSTLはその三角形をそのまま使う。

安全率は2つ返す: 探索時の値(`safety_factor`。平滑化前の形・探索の格子)と、**完成形を間隔 0.67 mm 以下の格子へ占有化して解き直し、部材域の表面の面積 4 mm² の上位値で出した値**(`final_safety_factor`、2026-10-07〜。この物差しは 2026-10-11〜で、要素数の上限で粗くしか測れないときは割り増す。[TOPOPT_PEAK_GATE.md](TOPOPT_PEAK_GATE.md) 6章)。完成形が本来の目標安全率を割ったときは、探索の合格形をさかのぼって完成形検査に通る形を警告付きで足し(`topopt.complete.backtrack`)、どれも通らなければ `final_unsafe` で結果を足さない(#129・さかのぼりとも 2026-10-11 本人決定。測り方の見直しは [TOPOPT_PEAK_GATE.md](TOPOPT_PEAK_GATE.md))。つなぎ目の幅は診断で、「幅不足の疑い / 未確定 / 疑いは観測されなかった」の3値(適合は出さない。[TOPOPT_MIN_WIDTH.md](TOPOPT_MIN_WIDTH.md))。

入力・最終メッシュとも、閉殻の包含深さと面の向きを照合する。交差のない閉殻に対して代表頂点からの
立体角で包含を判定し、深さが偶数なら外向き、奇数なら内向きを要求する。外に離れた内向きの閉殻を
空洞として数えない。空洞内の材料は別ソリッドなので最終の単一ソリッド検査で不合格になる。
保持・除外の形は内接する三角形で近似される: 円柱では半径によらず約0.005 mmだけ除外の中に材料が残る
(下「円柱の除外へのめり込み」。BSpline・トーラス面では指定偏差を超えた標本がある)。

## 判定器と再現

```powershell
.venv/Scripts/python.exe topopt_checks/check_final_shape.py --mesh result.stl --out output/acceptance.json
.venv/Scripts/python.exe topopt_checks/check_final_shape.py --model-dir output/optimization_runs/<run-id> --model document_after.json --mesh-body <body-id> --out output/acceptance.json
.venv/Scripts/python.exe topopt_checks/replay_finalization.py output/optimization_runs/<run-id>
.venv/Scripts/python.exe -m pytest tests/test_final_shape.py -q
```

- `check_final_shape.py` はメッシュをOCCTのソリッドに縫合して `BRepCheck`・自己干渉で2条件だけを判定する(hangerの最終メッシュで約89秒)。
  **製品経路はこの判定を呼ばず**、`finalize.final_mesh_checks`(接続6項目・単一ソリッド・float32・自己交差。OCP非依存)で合否を決める
  (2026-10-06)。判定器はOCCTで独立に裏を取る道として残す。
  `--model`(既定 `hanger_bar_attachment.json`)・`--mesh-body <ボディID>` を指定できる。
  `--check-constraints` で旧保持・除外比較(保持は各CADソリッドから最終出力を引いて残存ソリッドなし、除外は共通部分にソリッドなし。
  水密・島なしも判定。条件は文書の `optimize.preserve_bodies`/`exclude_bodies`)を調査用に出す。
  `--solid-body` は 2026-09-23 より前の記録(`add_solid_body` で B-rep が入る)用。
- 出力は `PASS / FAIL / UNKNOWN`。終了コードは全合格 0、不合格あり 1、不合格が未確定で判定不能 2。水密検査で止まれば他は判定不能。
  最適化は実行せず、入力メッシュも修復しない。
- `replay_finalization.py` はSIMPを再実行せず、保存済み平滑化後表面を製品と同じ最終処理に通し、`output/finalization_checks/` に
  各段階の検査(`smoothed-mesh-checks` / `cad-meshes` / `mesh-boolean` / `final-mesh-checks`)と、成功時の文書(メッシュボディ)/STLを保存する。
  元の実行が finalize 失敗で mesh-world snapshot を残していない場合は finalize-input から読み直すフォールバックになり、
  その回は grid が無いため成功しても最終STL(`final.stl`)は保存しない。
- 検証は `tests/test_finalization.py`、`tests/test_final_shape.py`、`tests/test_optimization_trace.py` と `topopt_checks/check_trace.py`
  (小型モデルで製品経路・文書再生・最終STLを確認)。判定器のテストが通ることと、対象モデルの最適化結果が合格することは別に記録する。
- 「厳密」の範囲: 元CADと最終メッシュ全体の集合演算で、残存体積の割合による許容値は設けない(微小でも残存ソリッドがあれば不合格)。
  ただし有限精度のOCCTで、縫合・包含判定は `Precision.Confusion`(1e-7 mm)、集合演算にはCADのトポロジーごとの公差も作用する。
  JSONの `tolerance_mm` は検査の基準値であり全演算の誤差上限ではない。曲面の保持部を内接三角形だけで表すとCADとの差が残り不合格になりうる。

## 島除去後・平滑化前の受入検査

`rho_clean > level` のセル(閾値上は含めない。既定は製品と同じ0.5)を格子の実寸の閉じた立方体として集めた材料領域を検査する。
密度積算量とこの二値領域の体積は別々に報告する。探索・島除去は変更せず、その出力を検査する(表面抽出・平滑化・最終CADは呼ばない)。

| 項目 | 検査 |
|---|---|
| 水密な正常な境界 | 各格子頂点まわりの境界の交線が単一閉路(頂点を囲む8セルの256通りの配置で見る。角・辺だけの接触も検出)。空(材料の補集合)の6近傍連結成分が1つ。空モデルは不合格 |
| 単一ソリッド | 材料セルの6近傍連結成分が1個 |
| 保持との重なり | 各保持CADと材料の共通体積が許容差より大きい |
| 除外内の空間 | 各除外CADの体積から共通体積を引いた量が許容差より大きい |
| 荷重・拘束が有効 | 元の各面のアンカー節点が全て材料に接する。面別の荷重を欠落・再配分しない |
| 目標安全率 | 残った二値領域だけのFEMを再構築して解き直し、残差検算を通過し、安全率が目標以上 |

- 貫通穴は正常な境界として許可し、**閉じた空洞は許可しない**(中空構造を許容しない製品制約。頂点の検査だけでは空洞を通すので空の連結成分数で別に見る。根拠は `TOPOPT.md`「設計上の決定」)。この合格は後段の平滑化メッシュの合格を保証しない。
- **「元の条件」は探索へ渡した確定表**。`optimize_run._map_boundary_conditions` が、固定した設計空間に接する節点だけへ条件面を対応付けた表
  (`anchor.build_anchors(allowed_nodes=...)`、`stats["mapping"] == "material"`)を1回作り、探索・6条件・FEMの全てがそれを使う。
  導出が接続確認に使う幾何の表(`stats["mapping"] == "geometry"`)を渡してはいけない(面の外側の節点が最初から材料に接せず全材料マスクでも不合格になる)。
  確定後は探索中に再配分しない。過去記録を読む `optimize_acceptance.inspect_document` も、文書から作った格子上の表を材料マスクに対応付けてから検査する。
- CADとの体積比較はセル中心による占有近似ではなく、材料セルを体積を共有しない直方体列にまとめて元のCADとの共通体積をOCCTで計算して合計する(格子外の除外空間も数える)。
  許容差は `max(1e-9 mm³, 条件CADの体積 × 1e-9)`、計算エラー・警告は判定不能。僅かな重なり・空間でも合格し、保持全体の包含や除外全体の空洞化は要求しない。
  保持条件なしは不合格、除外条件なしは合格(空集合)。探索の中では、同じ共通体積を格子ごとに前計算したセルごとの重なり体積の足し算で取る
  (`acceptance.RegionOverlaps`。曲面のソリッドでは体積積分のばらつきだけ旧経路とずれる。[TOPOPT_SPEED.md](TOPOPT_SPEED.md))。
- FEMは材料セルの密度を1、それ以外を剛性行列から外す。材料に接しない自由度だけ追加固定し、浮いた材料に拘束は補わない。
  剛体運動の拘束不足は不合格、ソルバー・残差・非有限値の問題は判定不能(安全率不足と区別)。応力の代表値は99.5パーセンタイル(素の最大も記録)。
  許容応力・ヤング率は `duocad/topopt/material.py` と共用。
- 探索の診断(各候補の体積・安全率・エラー、安全側/不足側の区間幅、単調性の逆転。収束は探索の申告で、回数上限と区別。古い記録で確定できなければ unknown)は
  別判定。失敗した計算は不足側の実測値に使わず、`minimum_proven` は常に false。

```powershell
python topopt_checks/check_pre_smoothing.py --run output/optimization_runs/RUN_ID --out output/pre_smoothing_checks/report.json
python topopt_checks/check_pre_smoothing.py --fields fields.npz --document models/hanger_bar_attachment.json --target 2 --out output/pre_smoothing_checks/report.json
python -m pytest tests/test_pre_smoothing.py -q
```

- **`--run` は旧SIMP記録(2026-09-16 以前の密度場の記録)専用。今の記録には使えない**(今の `selected-result` は `status`・`termination`・`material_mm3`・`safety_factor`・`filled_cells` のスカラーだけで `rho_clean` を持たず、`KeyError` で終了コード2=判定不能になる)。今の記録には `--fields` で NPZ を渡す。旧記録では `selected-result` に記録された採用候補の `rho_clean` を読む(最後に評価した候補ではない)。除去前の場は同候補の密度へ保存済みの保持・除外マスクを
  製品と同じ順序で適用して復元し、目標安全率・閾値・許容応力・ヤング率・パーセンタイルも保存値を使う。採用記録がなければ推測せず判定不能。
- `--fields` の npz は `rho_clean`・`rho_before`(保持・除外の塗り直し後、島除去前)・`origin`・`spacing`(同じ格子上の有限な0〜1の密度)。
  `--level`/`--allowable-mpa`/`--youngs-modulus-mpa`/`--percentile`/`--solver`(`cg` 既定か `direct`)で明示指定もできる。
  Pythonからは `duocad.optimize_acceptance.inspect_document` が入口(文書の条件確定・密度→boolの閾値変換・密度積算量の付記を閉じる)。boolマスクとアンカー表があるときだけ `acceptance.inspect` へ直接渡せる。
- 終了コードは 0=6項目合格、1=不合格あり、2=判定不能(不合格確定なら1が優先)。

## 平滑化(Taubin)後の自己交差

製品の `mesh.build_surface_from_mask`(パディング → marching cubes → Taubin 30回)の自己交差を、検証材料の64条件
(hanger を荷重4 × 要素サイズ4 × 最小幅4で最適化。解なし0件)で全数集めて平滑化前のボクセルの局所形に結びつけた。

**結論**: 64条件で交差箇所4・交差の組21(全て cross。touch/coplanar/fold/duplicate は0。平滑化前の `verts_raw` は0)。**4箇所とも、四方が材料で閉じた 1×1 の管(板を貫く穴)の中**。
溝・空洞に触れた交差はない。頂点の最大移動は 0.49〜0.59 要素。
**対策(2026-10-07 本人判断)**: 探索が確定したマスクの管(2軸以上で挟まれた空セル)をメッシュ化の前に埋め、6条件を取り直す
(`duocad/topopt/thin_voids.py`。[TOPOPT.md](TOPOPT.md)「1×1 の空隙を探索後に埋める」)。64条件で交差 21組 → 0、埋めたセルは条件あたり中央値 7・最大 80。
溝は埋めない。設計空間(除外を引き切った後)の中だけ埋め、除外由来の空隙は埋めず、交差すれば `finalize` が止める。

用語:
- **管**: 挟まれた軸(空セルの両隣±1が材料の軸)がちょうど2つで、残る1軸に沿って連なる空セルの列(断面が四方とも閉じた 1×1 の空隙)。両端の外側が材料なら「止」、空なら「開」。
  板を貫く 1×1 の穴は 開-開で、長さ L が板厚。止まり穴は 止-開。実データの管534列はすべて断面の斜め4セルも材料。止-止は0列。
- **溝**: 挟まれた軸がちょうど1つの空セル(片側が開いた切れ込み・溝・板の縁の細い隙間)。**空洞**: 3軸とも挟まれた1セル(64条件で0)。
- **壁の間隔**: 挟まれた軸方向の、平滑化後の向かい合う壁の頂点の距離[要素](平滑化前は1.0、負なら入れ替わり)。marching cubes は境界面の中心に頂点を1つずつ置くので曖昧さなく取れる。
- 交差の塊のまとめ方の 3.0 要素、壁の間隔の区切り(0.1/0.25/0.5/0.75)は分析者が置いた値で実測値ではない。保持・除外への接触は npz に情報が無く追跡していない。

規則:
- **R1(潰れ)**: 管は長さが一定以上で壁の間隔が大きく縮む。管534列のうち間隔 0.1 未満は83列。止-開は長さ2以上で62列中60列が 0.1 未満(残り2列も 0.124 以下)、
  開-開は長さ4以上の16列すべてが 0.1 未満(最大 0.090)、長さ3は17列中7列。開-開 長さ5以上は 0.035〜0.062。
  溝は実データ13,594セルで最小 0.122(k=0 両側が開いた隙間 0.500、k=1 0.237、k=2 隅の溝 0.122)で、壁が入れ替わった細い空隙は管にも溝にも1件もない。
  **止まり穴は 0.01〜0.12 まで潰れる**(実データ: 長さ2以上の59/62列が 0.1 未満。合成: 深さ2〜8 で 0.013〜0.022)。
- **R2(交差)**: 交差は R1 で潰れた管のうち開-開で長さ3〜4の列でだけ起きた(長さ3: 17列中3、長さ4: 2列中1。長さ5以上・止-開・長さ1〜2では0)。
  潰れた管83列のうち交差は4列(5%)で、間隔が同程度でも交差しない管が多数ある。
  合成マスク(孤立した板・棒)では、開-開 1×1 貫通穴は**板厚4のときだけ**、平板・225通りの棒・面を15%乱した100通りの全てで交差し、板厚3・5〜12は0。
  **実データの長さ3の交差3箇所は合成で再現できない**(周りの材料の厚さ2〜7・端の外への溝の延び・端の周りの材料の量を表にしても、交差した3列と交差しなかった14列を分ける特徴は見つからない)。
  管から半径4セル以内を切り出して単独でメッシュ化すると、開-開 長さ3以上の33列すべてで交差の有無が一致した(局所性)。長さ3で交差する配置は脆く、周囲のセルを1個反転すると 2〜6% で消える。
  板厚1の合成(棒2/225本)の交差の原因は未調査。
- 2×2 の貫通穴・1×2 の貫通穴・片側が開いた溝(貫通)は合成で交差せず細い空隙の間隔も 0.448 以上。管の規則の分かっていない部分(長さ3の周囲の形、三角形の並びの細部と Taubin の頂点数依存)は、
  規則に依らず管を全部埋める方針にしたので追わない。

再現(分析は製品の関数を既定値のまま呼ぶ。64条件で約16秒。入力は `output/smoothing_corpus/voxel/<条件名>.npz` の `mask`、出力は gitignore 済みの `output/smoothing_corpus/` 以下):

## メッシュ集合演算

曲面を含む最終B-repを作ってから三角形化する代わりに、保持・除外CADを先に三角形化して平滑化後のメッシュと集合演算する案(2026-09-22 実測)を、
2026-10-06(#95)に製品の最終処理として採用した(採用の判断は [TOPOPT.md](TOPOPT.md)「最終処理はメッシュ集合演算」)。

**結論**: hangerの問題run `20260921T185659-b6799e00457d`(121,412三角形・保持4・除外8)で、保存したバイナリSTLが既存の水密・単一ソリッド判定に合格した
(接続6項目0、OCCTの自己干渉0・ソリッド1、CGALの自己交差0。判定 89.28秒)。小型run 2件(4,848→4,860、4,004→4,004三角形)も合格したが、3例での実測で任意モデルへの保証ではない。
**元CADの保持・除外形状を厳密に再現する案ではない**: 最終境界の標本点が元の除外CAD内部に入る例を検出した(各除外の bbox 内の重心300点から `BRepClass3d_SolidClassifier` 1e-7 mm で、除外0〜6でそれぞれ83〜119点が `IN`)。
最終ボディをメッシュとして持ち、STEP書き出し・面単位の選択・CAD編集を持たないことは製品仕様(本人判断 2026-09-23、2026-10-10 再確認。[TOPOPT.md](TOPOPT.md)「結果は編集可能ソリッドとして持たない」)。
体積が小さいこと(結果とメッシュ化済み保持・除外を再演算した残りは約1e-12 mm³だが `is_empty()` は false で残存三角形あり)を理由に保持・除外の厳密合格とはしていない。

他の外部実装として CGAL autorefinement・CGAL Alpha Wrap も確認したが、汎用の壊れた入力の修復器ではなく、採用するなら実物の独立検査が要るので採らなかった(Manifold を採用)。

追加依存(Windows wheel): Manifold 3.5.3、CGAL Python bindings 6.0.1.post202410241521、PyMeshLab 2025.7.post1。

```powershell
uv pip install --no-deps --only-binary :all: manifold3d==3.5.3 cgal==6.0.1.post202410241521 pymeshlab==2025.7.post1
```

中核処理(入力は倍精度の `Mesh64`、`M` は平滑化済みメッシュ、`P`・`E` は三角形化した保持・除外の和集合。保持・除外の分割偏差 0.01 mm、角度偏差 0.35 rad):

```python
result = (M + P) - E
result = result.as_original().simplify(1e-5)
```

結果の配列は座標完全一致で溶接して検査・保存する(近接頂点の溶接も不良面の削除もしない)。`simplify(1e-5)` は形状変化の許容値で、欠陥を合格扱いにするしきい値ではない
(その値が全ケースで幾何誤差の上限になることは独立に証明していない)。

### 集合演算のみの結果

簡略化前・倍精度。全4条件で接続6項目0、境界成分1、Manifold の status は NoError。

| CAD分割偏差 mm | 出力三角形 | 集合演算 秒 | CGAL自己交差ペア | バイナリSTL化後の縮退三角形 |
|---|---:|---:|---:|---:|
| 0.2 | 127,114 | 0.065 | 0 | 45 |
| 0.05 | 128,722 | 0.072 | 0 | 45 |
| 0.01 | 143,412 | 0.093 | 0 | 62 |
| 0.002 | 213,698 | 0.181 | 142 | 150 |

- 0.002 は入力のCGAL交差が180ペアあり不採用(入力の接続検査は合格していたので接続検査では除けない。0.2・0.05・0.01の入力12ボディには交差なし)。
  **「Manifold に渡せば直る」処理ではなく**、不良を小さいから通す判定は導入せず、不合格なら原因を示して停止する。
- **検出器間で不一致がある**: PyMeshLab の自己交差フィルタは 0.01 の出力で200面を選んだがCGALでは0ペア(縮退三角形を自分自身とのペアと報告するため)。PyMeshLab の面数を実交差の確定件数に使わない。

### 保存精度と簡略化

- `meshbody.write_stl` は座標を float32 で書き、ビューアの position も `Float32Array`(`web/src/viewport.ts`)。倍精度の配列が正常でも細い三角形が単精度では潰れる。
  0.01 の生出力は、倍精度配列を既存判定器にかけると `RuntimeError: OCCTがソリッドを不正と判定した` で UNKNOWN(約48秒)、バイナリSTLは縮退62枚で FAIL。
  17桁ASCII STL(既存 `trace.final_mesh` と同じ表現)で書いて再読込すると座標・添字は完全一致で接続6項目0・CGAL交差0だが、ビューアの単精度化やOCCT判定は解決しない。
- 簡略化: 集合演算結果に直接 `simplify(1e-5)` すると 142,182 三角形でSTLに縮退28枚が残るが、**`as_original()` で入力面の由来情報をリセットしてから簡略化すると 140,610 三角形で合格**
  (保存配列から新しい Manifold を作って簡略化した結果と一致)。元の面境界が簡略化を制限することは Manifold のAPI説明にある。入力CADの面へ戻る用途にこのリセットはそのまま使えない。
  再読込後に 1e-4・1e-3 でも接続とCGAL検査は合格したが、OCCT判定は実行していない。最終候補は 1e-5 mm(許容値の掃引は下の製品経路での実測)。
- 時間(hanger): 保持・除外の三角形化と取込 0.269秒、集合演算 0.096秒、リセットと簡略化 0.047秒、CGAL検査 約0.50秒(段階ごとの1回の実測)。

### 寸法と保持・除外への影響

比較対象のネイティブB-repの体積は 3,169,813.784 mm³。簡略化前のメッシュ−CAD の体積差は、偏差 0.2 / 0.05 / 0.01 / 0.002 mm で +97.35 / +88.21 / +19.05 / +3.60 mm³
(0.002 は自己交差があり不採用)。最終候補は 3,169,832.837 mm³、差 +19.053 mm³(約 +0.0006%)。体積差が小さくても局所のはめ合い精度は保証しない。

各入力CAD面の三角形を最大64枚選び、重心と3辺の中点から元のCAD面までの最短距離を `BRepExtrema_DistShapeShape` で測った標本の最大値(最終形状全体のHausdorff距離や誤差上限ではない)は、
偏差 0.2 / 0.05 / 0.01 mm で保持 0.071 / 0.164 / 0.019 mm、除外 0.052 / 0.024 / 0.005 mm。偏差 0.05・0.01 の保持で指定偏差を超える距離が出たので、パラメータ値をそのまま寸法保証に使えない。

### 円柱の除外へのめり込み

`kernel.tessellate` の既定(線形 0.2 mm・角度 0.35 rad)で単独の円柱(長さ40 mm)を分割し、側面三角形の内部を細かく標本して真の円柱面から内側へ入る最大距離を測った(2026-09-25)。
頂点は円柱面上で弦が内側を通るので、`M − 三角形化した除外` はこの距離だけ除外の中に材料を残す。

| 半径 mm | 周方向の分割数 | 最大弦角 | めり込み mm |
|---:|---:|---:|---:|
| 1 | 36 | 10.00° | 0.0038 |
| 4.35 | 36 | 10.00° | 0.0166 |
| 13.288 | 36 | 10.00° | 0.0506 |
| 30 | 39 | 9.23° | 0.0973 |
| 340 | 130 | 2.77° | 0.0993 |

OCCT は角度 0.35 rad(20°)に対して弦角を 10° に取り、線形 0.2 mm に対して弦の垂れを最大 約0.1 mm に抑える(どちらも指定値の半分)。半径約26 mm より小さい円柱は角度、大きい円柱は線形が決める
(めり込み ≒ r(1−cos 5°) = 0.0038 r、上限 約0.1 mm)。単独の解析円柱での値で、BSpline・トーラス面では指定偏差を超えた例がある。

### float32 で裏返る針状の三角形(#133、2026-10-11)

F2000_h2.0_w2 の `finalize` の入力を書き出し、製品と同じ集合演算・簡略化・`collapse_float32_slivers` をかけて交差の組を調べた。

  表面は面 x = 17.5 に寄り添っていない(最寄りの頂点で 0.045 mm)。起票時の「平面に float32 の分解能より近く寄り添い、丸めで前後が入れ替わる」は外れで、
  集合演算の前に入力を float32 の座標へ寄せる案・寄り添う所をずらす案は、この原因に当たらない(問題の頂点は集合演算と簡略化が作る)。
- 同じメッシュ(128,778 三角形)に高さが丸め幅未満の三角形は17枚ある(反対側 x = −17.5 の同じ角にも1枚)。交差したのはそのうち1枚だけ。
- 最短辺を潰して比べた(体積変化は潰す前比):

| 潰す三角形 | 最短辺の上限 mm | 潰した辺 | float32 の交差 | 体積変化 mm³ |
|---|---:|---:|---|---:|
| 交差の組に現れる三角形だけ | 1e-3 | 1 | 0 | 6.8e-8 |
| 同上 | 1e-4 | 0 | cross 5 | 0 |
| 高さが丸め幅未満の全三角形 | 1e-4 | 11 | 0 | −2.2e-7 |
| 同上 | なし | 17 | 0 | (頂点が最大 0.32 mm 動く。全辺が長い三角形の頂点を辺へ寄せるため) |

  高さで先に潰す案は交差しない条件の結果も変えるので採らなかった。float64 で既に交差があるときは潰さず不合格にする(集合演算・簡略化の欠陥を隠さない)。
  潰した後も float64 で検査し直し、潰したことで float64 に交差ができたら不合格にする(float32 では消えて見えうる)。
  float64 の検査は交差の組があるときだけかけるので、交差の無い条件の時間は変わらない。
- 結果: F2000_h2.0_w2 は `recheck_failed_finalize.py` で `done`(三角形 128,776、安全率 4.8355)。

## ビューア表示とSTLエクスポートの同一性

三角形分割の経路は3つ: (1) ビューア表示(`DocumentView.geometry` が `kernel.tessellate_selective`。ズームも注視面の指定も無い土台の粗さは `kernel.tessellate(shape, Session.deviation, kernel.DEFAULT_ANGULAR_DEFLECTION)` と同じ)、
(2) 記録用STL `final.stl`(`trace.final_mesh` が、`finalize` が合格させた最終メッシュ(manifold3d の集合演算の結果)の三角形を書く。`kernel.tessellate` は通らない)、(3) `export_stl` MCPツール(`io_step.export_stl`)。
**(3)は全B-repで(1)の土台と同じ `kernel.tessellate` の三角形をそのまま書く**(本人判断: 適用範囲は最適化の結果に絞らず全B-rep)。OCCT純正の `StlAPI_Writer` で測り直す経路(`kernel.write_stl`)は削除した。
一致は `tests/test_stl_export.py` がビット単位で固定する(曲面を持つ形・複数Body。面積0の三角形だけは書き出しで除く)。ズーム中の画面の粗さには合わせない(書き出しの粗さはカメラで変わらない。`tests/test_adaptive_resolution.py`)。
**旧経路との差の実体は並列フラグではなく角度偏差だった**(旧0.5 rad、画面0.35 rad)。最適化の結果はマーチングキューブ由来の平面だけなので旧経路でも三角形は一致していた。
変わったのは曲面を持つB-repで、同じ偏差でも細かくなる(hanger のB-rep 12 Body・63面、偏差0.2 mmで 9,460枚 → 13,508枚)。書き出し時間は旧経路の1.4〜2.7倍(いずれも0.5秒未満)。
