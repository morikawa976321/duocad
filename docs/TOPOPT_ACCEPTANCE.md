# 最終形状の合格条件

現在の合格条件は、`models/hanger_bar_attachment.json` の最終出力の **水密性（自己干渉なし）・単一ソリッド** の2つ。
保持・除外は既定の合否判定から外し、平滑化後のメッシュ集合演算で反映する。

製品経路は `密度 → 島除去 → 1×1 の空隙(四方が材料で閉じた空セル)を埋めて6条件を取り直す(thin_voids) →
表面生成 → Taubin平滑化 → 平滑化後の表面の検査(接続6項目・向き・自己交差) →
保持・除外を線形偏差0.01 mm(`STL_DEVIATION` と同じ値)・角度偏差0.35 radで三角形分割して同じ検査 →
(表面 + 保持) − 除外(manifold3d、倍精度) → 入力面の由来を捨てて 1e-5 mm で簡略化 →
float32 で潰れる三角形の最短辺(1e-5 mm 未満)を潰す →
最終メッシュの検査(接続6項目・単一ソリッド・float32の縮退と頂点一致・自己交差) →
完成形の検査(探索の格子で解き直した安全率、つなぎ目の幅の診断。`duocad/topopt/final_check.py`) → 文書保存`
(`duocad/topopt/finalize.py`)。重複領域は除外が優先する。入力の不合格、空の結果、分断、自己交差を
成功扱いにしない。**小さいから通す判定は無い** —— 平滑化後の表面に自己交差があれば、それが4組でも
最終処理は入力検査で止まる(平滑化側の合格条件。[TOPOPT_SMOOTHING_INTERSECTIONS.md](TOPOPT_SMOOTHING_INTERSECTIONS.md))。
結果はメッシュボディとして三角形を操作ログに保存し、表示とSTLはその三角形をそのまま使う。
安全率は2つ返す: 探索時の値(`safety_factor`。平滑化前の形・探索の格子)と、**完成形を探索の格子の 1/3 へ占有化して解き直し、表面の最大応力で出した値**(`final_safety_factor`、2026-10-07〜。1/3 格子と表面の最大応力は 2026-10-09〜、[TOPOPT_STRESS_GATE_DILUTION.md](TOPOPT_STRESS_GATE_DILUTION.md) 10章)。完成形が本来の目標安全率を割ったときは、高応力部の肉盛り(#129)が入るまで警告を付けて結果を足す(`optimize_run.FINAL_UNSAFE_BLOCKS = False`。真にすると `final_unsafe` で足さない)。つなぎ目の幅は診断で、「幅不足の疑い / 未確定 / 疑いは観測されなかった」の3値(適合は出さない。[TOPOPT_NECK_RULE_120.md](TOPOPT_NECK_RULE_120.md) §3)。
入力・最終メッシュとも、閉殻の包含深さと面の向きを照合する。交差のない閉殻に対して代表頂点からの
立体角で包含を判定し、深さが偶数なら外向き、奇数なら内向きを要求する。外に離れた内向きの閉殻を
空洞として数えない。空洞内の材料は別ソリッドなので最終の単一ソリッド検査で不合格になる。
保持・除外の形は内接する三角形で近似される: 円柱では半径によらず約0.005 mmだけ除外の中に材料が残る
([TOPOPT_MESH_BOOLEAN_STUDY.md](TOPOPT_MESH_BOOLEAN_STUDY.md)「円柱の除外へのめり込み」。BSpline・トーラス面では
指定偏差を超えた標本がある)。

```powershell
.venv/Scripts/python.exe topopt_checks/check_final_shape.py --mesh result.stl --out output/acceptance.json
.venv/Scripts/python.exe topopt_checks/check_final_shape.py --model-dir output/optimization_runs/<run-id> --model document_after.json --mesh-body <body-id> --out output/acceptance.json
.venv/Scripts/python.exe topopt_checks/replay_finalization.py output/optimization_runs/<run-id>
```

判定器(`check_final_shape.py`)は既定で2条件だけを出力する。メッシュをOCCTのソリッドに縫合して
`BRepCheck`・自己干渉で判定する(hangerの最終メッシュで約89秒)。**製品経路はこの判定を呼ばず**、
`finalize.final_mesh_checks`(接続6項目・単一ソリッド・float32・自己交差。OCP非依存)で合否を決める
(2026-10-06。判定器はOCCTで独立に裏を取る道として残す)。旧保持・除外比較は調査用の `--check-constraints`。
`--solid-body` は2026-09-23より前の記録(`add_solid_body` で B-rep が入る)用。
`replay_finalization.py` はSIMPを再実行せず、保存済み平滑化後表面を製品と同じ最終処理に通し、
`output/finalization_checks/` に各段階の検査(`smoothed-mesh-checks` / `cad-meshes` / `mesh-boolean` /
`final-mesh-checks`)と、成功時の文書(メッシュボディ)/STLを保存する。
元の実行が finalize 失敗で mesh-world snapshot を残していない場合は finalize-input から
読み直すフォールバックになり、その回はgridが無いため成功しても最終STL(`final.stl`)は保存しない。

検証は `tests/test_finalization.py`、`tests/test_final_shape.py`、`tests/test_optimization_trace.py` と
`topopt_checks/check_trace.py`。後者は小型モデルで製品経路・文書再生・最終STLを確認する。

## 除外cutの警告の原因（hanger）

保存済みhanger実行 `20260921T185659-b6799e00457d` の finalize は、除外cutで
`BOPAlgo_AlertAcquiredSelfIntersection`・`BOPAlgo_AlertFaceBuilderUnusedEdges`・
`BOPAlgo_AlertSolidBuilderUnusedFaces`(9/8/1件)を出して不合格になった。保存済みB-repを読み、
`BOPAlgo_BOP`（cut・非破壊・fuzzy 0）を組み替えて切り分けた。

- **除外 `hanger_bar_attatchment_11` の単独 cut で再現**する。他の除外7個は単独では警告なし。
- **メッシュだけ（保持の和集合なし）の cut は警告なし**。保持のうち **`hanger_bar_attatchment_7` を足したときだけ**再現し、他の保持3個では出ない。
- 除外11は半径13.288 mmのロッド（軸 y=-200, z=60）で、中央 |x|<17.27 に浅いくびれ（トーラス R=352.8617, r=340）がある。
  保持7はそこにはまる厚さ5 mmの環で、**内面が除外11のくびれ面と同一のトーラス**（中心・軸・半径が一致、距離 1e-13 mm）。
  体積の重なりは0で、面だけが完全に一致して接する。
- `AcquiredSelfIntersection` 9件のうち7件は、この共有面の上。
- 除外11を軸まわりに ×0.999（面が約13 µm離れる）にすると警告0件で有効なソリッド。×1.001（13 µm重なる）では
  `AcquiredSelfIntersection`・`SolidBuilderUnusedFaces` が消え、`FaceBuilderUnusedEdges` が2件残る。
- メッシュ側は原因でない（最短辺 0.385 mm、最小高さ 0.307 mm、縮退・極小三角形なし）。

**保持と除外が同一の面を共有するモデルで、保持の和集合と除外の差集合が、その面上のメッシュとの交線をそれぞれ作る。
辺が二重になって OCCT が「引数の部品がツールを介してつながった」と見なす**、と読んでいる（辺が二重になる点は推定。
共有面の同一性と、面をずらすと警告が消えることは実測）。

### 試した回避策（同じ実行の保存済みB-repで実測。モデルは変えない）

正しい体積の目安は 3,169,814 mm³（除外を引いたメッシュ 3,169,421 ＋ 保持が足す 393）。

| 案 | 結果 |
|---|---|
| 除外のcutを先、保持のunionを後 | cutは警告なし。後のunionが 13/6/2 件で、体積が 3,153,136 に減って壊れる |
| 元の順序のcutに fuzzy 1e-4 / 1e-3 mm | 警告は 6件 / 5件に減るだけ（体積は正しい）。1e-2 は15分以上終わらない |
| メッシュから保持と除外を1回で同時に引き、除外で削った保持を後でunion | 同時cutは警告なし。後のunionが 1/1 件で、体積は正しい |
| `BOPAlgo_CellsBuilder` で (メッシュ ∪ 保持) − 除外 を1回の交差計算で作る | OCCTの警告は0件、体積 3,169,813.75、ソリッド1個で有効。**最終検査の自己干渉が1件残る**（頂点と辺） |
| 上の残りを形状修復（`ShapeFix_Shape`・`BRepLib.UpdateTolerances`） | 消えない。`ShapeFix_Shape` は体積が変わって無効な形になる |
| CellsBuilder に fuzzy 1e-4 / 1e-3 / 3e-2 mm | 体積0・警告多数で壊れる。1.5e-2 は30分以上終わらない |
| 除外11を軸まわりに ×0.999 / ×1.001 して cut | ×0.999 は警告0・有効。×1.001 は `FaceBuilderUnusedEdges` が2件残る。どちらも除外の実形状から約13 µmずれる |

許容差 0.011 mm の頂点は、保持と除外を同時に扱った時点（`cut(メッシュ, 保持＋除外)`）で既に現れる。
逐次の union では最大 1.5e-4 mm。保持7の内面のトーラスと除外11の肩のBSpline面が最大約0.01 mmずれて接するため、
OCCT が両者を同一面と見なして許容差を広げる、と読んでいる（推定）。
小さなモデル（くびれ付きロッドとはまる環）では、元の順序は10通り中8通りで警告が出て、CellsBuilder は10通りとも警告なし・有効だった。

## まとめてcut→保持だけ引き算→fuseへの置き換え（hanger実測）

前節の「メッシュから保持と除外を1回で同時に引き、除外で削った保持を後でunion」案を製品経路に採用した
（`duocad/topopt/finalize.py`）。手順: 1) メッシュから保持＋除外をまとめて1回のcutで引く
2) 保持ボディそれぞれについて単独で除外とのcutを計算する 3) 1の結果に2の「除外済みの保持」をfuseで足す。

同じ実行を新しい経路で再生すると、material-cut・保持0〜3個それぞれのcutは全て警告なしで通り、最後のfuseだけ
`BOPAlgo_AlertAcquiredSelfIntersection` 1件・`BOPAlgo_AlertFaceBuilderUnusedEdges` 1件が残る
（旧経路の9/8/1件から削減。`SolidBuilderUnusedFaces` は0件になった）。

残る1件は保持7・除外11の共有面（くびれ）ではなく別の干渉で、除外11の円筒面とBSpline遷移面（肩）の境目に出る。
メッシュの三角形近似で肩の位置が理想円筒からわずかにずれ、fuse時にその境目がAcquiredSelfIntersectionに
なると読んでいる（推定）。「警告が1件でもあればValueError」の判定は変えていないため、hangerはこの変更だけでは合格しない。

保持ボディが除外に全部覆われて `P_i - 除外` が空になる場合、fuse前にその保持を除外する
(`_boolean` の `allow_empty` 分岐。エラー・警告なしで0ソリッドを返すcutを「寄与ゼロ」として扱う。
旧経路ではこの場合エラーにならなかったため、この分岐が無いと退行する)。

## inspect_solid の面-面判定と `_boolean` の警告ゲート

`duocad/kernel_brep.py` の `inspect_solid` は、`BOPAlgo_CheckerSI` の干渉を種類を問わず数えていた。
頂点-頂点・頂点-辺・辺-辺・頂点-面のペアは許容差が触れているだけで無条件にカウントされる一方、
面-面のペアだけは実際に交差点・交差線があるかをOCCT自身が確認してから数える
（`BOPAlgo_CheckerSI::PostTreat`）。両端が `TopAbs_FACE` のペアだけをカウントするよう変更した
（数値のしきい値は導入していない）。`_count_face_interferences(ds, pairs)` として切り出し、
`tests/test_kernel_brep.py` がスタブの `ds`/ペアで検証する。

**この変更だけではhangerは合格しなかった**: `finalize.py` の `_boolean` は `BOPAlgo_BOP`(fuse演算そのもの)の
`HasWarnings()` を見て、警告が1件でもあれば `inspect_solid` を呼ぶ前に `ValueError` を投げていた
(`inspect_solid` の判定基準とは独立したゲート)。これを修正し、`has_errors` は従来どおり即座に不合格、
`has_warnings`(エラーなし)のときだけ `inspect_solid`(面-面の実交差だけを数える)に通し、`watertight` かつ
`single_solid` なら採用する形にした。

**実際にBOP自身が出した警告の中身**(`preserve-fuse` を実データで再実行し、`BOPAlgo_BOP.GetReport().GetAlerts()` で確認):

| 警告 | 含まれる形状 | 大きさ |
|---|---|---|
| `AcquiredSelfIntersection` | 面0・辺2・頂点4 | 0.03mm四方 |
| `FaceBuilderUnusedEdges` | 面1・辺3・頂点6 | モデルのほぼ全幅(1件目の巻き添えと見ている。未検証) |

修正後、`finalize()` 本体は成功するようになった(`final-solid-checks`: `watertight`・`single_solid` とも `True`、
`self_intersections=0`)。**ただし `finalize()` の直後に呼ぶ `solid_mesh()`(最終形状をSTL用に三角形分割する。
本番経路にも共通する)が新たに失敗する**: `ValueError('最終CADに三角形分割できない面がある')`。
失敗する面は面番号74485(全112,467面中1面)、平面、面積0.008235mm²の極小平面で、`BRepCheck_Analyzer` 上は有効。
原因・修正は次節「三角形分割に失敗する極小面」。

## 三角形分割に失敗する極小面（原因調査。2026-09-23 に修正、下記）

**面番号のずれに注意**: `kernel._face_map`(`TopExp.MapShapes_s`、1始まり)と `duocad/mesh_geometry.subshapes`
(`TopExp_Explorer`、0始まり)は同じ添字で別の面を指す。面番号を突き合わせるときは常に `kernel._face_map` と
`TopoDS.Face_s(face_map.FindKey(idx))` を使うこと(最初の調査でこれに気づかず、隣の無関係な面を数時間調べた)。

**面の実体**: 平面、面積0.00823511mm²、辺の長さ [0.00030774mm, 0.92402802mm, 0.91675163mm]
(剃刀のように細長い三角形。最短辺は模型の作業精度mmオーダーを3桁下回る)。**由来**: `material-cut`
(保持＋除外をまとめて引く最初のcut)の段階で既に存在する(`before-boolean` にはこの位置に通常の三角形3枚
しかなく、`material-cut` で初めて現れる。以降 `preserve-fuse`・`final-solid` まで無傷で通過する)。

**試して効かなかった手段**（すべて実測、この正しい面で再検証済み）:

| 手段 | 結果 |
|---|---|
| 単独でこの面だけメッシュ化（3回試行、並列あり/なし各5回） | **毎回、三角形0枚**。決定的に失敗する（非決定的ではない） |
| `ShapeUpgrade_UnifySameDomain`（既定許容差、1回・2回） | 面数112467→112221（246面統合、体積誤差41.46mm³も補正）だが、**この面だけは同一平面の隣が無く統合されない** |
| 同、角度・線形許容差を広げる（1e-3rad/1e-4mm） | `Standard_Failure: Courbes non jointives` で例外 |
| `ShapeFix_FixSmallFace`（precision 0.001〜0.5mmで掃引） | precision 0.001/0.01ではこの面に触れず。**0.05以上では形状が無効になり、別の面が新たに失敗し始める**（改善ではなく破壊） |

局所的な穴埋め・再分割・Defeaturingも同じ面あるいは別の面に問題を移すだけで解決しなかった
(境界点だけの穴埋めは接続検査は通っても幾何的な自己交差が残る。Defeaturingは有効なB-repになっても
別の面に欠落が移る)。全体を細かくする単純な変更も解決にならなかった(偏差0.01mmでは一時的に解消するが

## ビューア表示とSTLエクスポートの同一性（解決）

三角形分割の経路は3つある:

1. **ビューア表示** — `DocumentView.geometry` が `kernel.tessellate_selective` で測る。
   ズームも注視面の指定も来ていないとき（土台の粗さ）は `kernel.tessellate(shape,
   Session.deviation, kernel.DEFAULT_ANGULAR_DEFLECTION)` と同じ呼び出しになる。
   ズーム中は粗さがカメラに連動し、裏を向いた面は粗く測る。
2. **記録用STL** — `trace.final_mesh` が保存する `final.stl`。`finalize.solid_mesh()` が
   `kernel.tessellate(shape, 0.2)` で作った配列をそのまま書く。
3. **`export_stl` MCPツール** — `io_step.export_stl`。

**3は全B-repで、1の土台と同じ `kernel.tessellate` の三角形をそのまま書く**（本人判断:
適用範囲は最適化の結果に絞らず全B-rep）。OCCT純正の `StlAPI_Writer` で測り直す経路
（`kernel.write_stl`）は削除した。一致は `tests/test_stl_export.py` がビット単位で固定する
（曲面を持つ形・複数Body）。ズーム中の画面の粗さには合わせない（書き出しの粗さはカメラで
変わらない。`tests/test_adaptive_resolution.py`）。

**差の実体は並列フラグではなく角度偏差だった**（旧経路0.5rad、画面0.35rad。並列フラグの有無は
三角形を変えなかった）:

| 形 | 偏差 | 旧（0.5rad） | 新（=画面） |
|---|---|---|---|
| 最適化の最終ソリッド（`final-solid` の記録、1 Body） | 0.2mm | 4,004枚 | 4,004枚 ✓（`final.stl` とも ✓） |
| hanger_bar_attachment のB-rep（12 Body, 63面） | 0.2mm | 9,460枚 | 13,508枚 |
| 同 | 0.05mm | 16,496枚 | 20,424枚 |
| 40×30×10の箱にφ12の貫通穴 | 0.2 / 0.05 / 0.01mm | 120 / 156 / 324枚 | 160 / 160 / 324枚（0.01mmは ✓） |

最適化の結果はマーチングキューブ由来の平面だけなので、旧経路でも三角形は一致していた。
変わったのは曲面を持つB-repで、同じ偏差でも細かくなる。書き出し時間は旧経路の1.4〜2.7倍(いずれも0.5秒未満)。

以下は2026-09-14までの仕様。現在は `--check-constraints` を指定した調査時だけ適用する。

| 条件 | 判定方法 |
|---|---|
| 保持部分がすべて残る | 各保持CADソリッドから最終出力を引き、残存ソリッドがない |
| 除外部分に材料がない | 各除外CADソリッドと最終出力の共通部分にソリッドがない |
| 水密 | 穴・非多様体・重複面・縮退面・向きの矛盾・自己交差がなく、有効な閉じた境界を作る |
| 島がない | 材料領域のソリッド数が1。内部空洞は島として数えない |

保持・除外の条件はモデル文書の `optimize.preserve_bodies` と `optimize.exclude_bodies` から読み込む。
除外部分の境界面に触れるだけなら許容する。保持指定が空、入力不正、CAD演算の警告・失敗は合格にしない。

## 実行

リポジトリ直下から、ワールド座標・mm単位の最終STLを指定する。

```powershell
.venv/Scripts/python.exe topopt_checks/check_final_shape.py --model hanger_bar_attachment.json --mesh result.stl --out output/hanger_acceptance.json
```

`--model` の既定値は `hanger_bar_attachment.json`。
文書に保存済みの最終メッシュを検査する場合は、`--mesh result.stl` の代わりに
`--mesh-body <ボディID>` を指定する。

標準出力とJSONに4条件の `PASS / FAIL / UNKNOWN` を出す。
JSONには各保持・除外ボディの判定、残存体積、ソリッド数、入力のSHA-256も保存する。
終了コードは全条件合格なら0、判明した不合格があれば1、不合格が未確定で判定不能があれば2。
水密検査で止まった場合、保持・除外・単一ソリッドは判定不能になる。
スクリプトは最適化を実行せず、入力メッシュも修復しない。

## 「厳密」の範囲

ボクセル中心や表面のサンプル点の一致ではなく、元のCADと最終メッシュ全体の集合演算を使う。
残存体積の割合による合格許容値は設けない。微小でも残存ソリッドが検出されたら不合格になる。

ただし計算は有限精度のOCCTであり、数学的な完全厳密判定ではない。
縫合・包含判定にはOCCTの `Precision.Confusion`（現在1e-7 mm）を使い、
集合演算にはCADが持つトポロジーごとの公差も作用する。JSONの `tolerance_mm` は
検査で指定した基準値であり、全演算の誤差上限ではない。
STLの座標丸めや曲面の三角形近似も判定対象に含まれる。
曲面の保持部を内接する三角形だけで表すと、CADとの差が残り、不合格になりうる。
大規模メッシュでは面の縫合・自己交差検査・集合演算に時間がかかる。
