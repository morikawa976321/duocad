# 形状最適化 — 微小密度の要素を組み立てから外す(動的な active set)

**この文書の役割:** `simp.optimize(dynamic_active=True)` の**根拠と実測**。閾値がなぜ
`emin ** (1/penal)` という式であって定数ではないのか、**どこで効いてどこで効かないのか**、
そして**これを入れた目的だった「下端の崖」がなぜ埋まらないのか**を数字で置く。

| 何が | どこにあるか |
|---|---|
| 呼ぶ面・契約 | `duocad/topopt/simp.py` の `Model.dead_rho_threshold` / `Model._refresh_active` / `Model.reset_active` / `optimize(dynamic_active=)` の docstring |
| **生データ** | `duocad/topopt/output/active_set.json`(4ケースを `cases` へ積んだもの。計測は1ケース1ファイル `active_set_<tag>.json` に書き、`--merge` がこれへまとめる。**リポジトリに置くのはまとめたほうだけ**) |
| 反復1の ρ 分布だけ見たいとき | 同 JSON の `prepares[]`(`prepare` 1回につき1件。閾値・組み立てた要素数・固定自由度・ヒストグラム) |
| **計測スクリプト** | `topopt_checks/measure_active_set.py` |
| **回帰検査** | `topopt_checks/check_simp.py` の [11] |
| 崖そのものの表 | [TOPOPT.md](TOPOPT.md)「`p` を上げると SIMP が解けなくなる(下端の崖)」 |

**環境**: Windows 11 / 14コア(`simp.PARALLEL_THREADS` = 7)/ 31.7GB。
**題材**: `models/hanger_bar_attachment.json`・要素 2.412mm・材料 70,634.5mm^3・`update="oc"`。
塊は `PICK_RATIO` で振る。**塊は 2026-09-09 に作った参照 pickle
(`output/simp_convergence_hanger_2.4mm_ref.pkl`)から切り出している** —— 要素数は

## 結論(先に)

1. **入れた目的だった「下端の崖」は埋まらない。効果はゼロである(2026-09-12 実測)。**
   `PICK_RATIO=0.60`(充填率 0.77%)は**反復1の求解**で落ちる。そこの ρ は一様な初期値
   なので、**閾値 1e-3 を下回る要素が1つも無い**(設計空間の最小 ρ = 1.855e-3)。
   口を入れた前後で残差も max|u| も**1桁も動かない**(どちらも 2.963e-06 / 1.739e+06)。
   **最適化が作った死んだ領域を外す仕組みなので、最適化が動く前の崖には構造的に届かない。**
2. **崖の出所は `emin` ではない。保持ソリッド(ρ=1)と背景(ρ=初期の充填率)の
   コントラストである。** 充填率 0.77% の背景は `E = emin + 0.0077^3 = 4.58e-7` で、
   ρ=1 の保持ソリッドとの比は **2.2e6 倍**。`PICK_RATIO=0.08`(充填率 5.8%)なら
   `1.95e-4` で比は **5.1e3 倍**しかない。**`PICK_RATIO` を上げると背景が薄くなり、
   コントラストが 430倍に広がる** —— これが「下端の崖」の正体で、`emin` で支えられた
   軟モードの話ではない。
3. **CG は「収束した」と言って返ってくる。** 落ちた run の標準エラーに
   「CG が収束しませんでした」の警告が1行も無い —— `spla.cg` は再帰残差で `rtol=1e-9` に
   達したと判定しており、**真の残差 `||Ku-f||/||f||` はその約3000倍(2.96e-6)ある。**
   直交性が失われるほど条件数が悪い。**この崖を埋めるなら手を入れる先はここ**
   (真の残差での再スタート / K の対角スケーリング / 初期場を一様にしない)であって、
   active set ではない。
4. **既定(`PICK_RATIO=0.08`)では答えが変わらない。** 40反復でコンプライアンスの相対差
   **4.74e-06**、反力3枚は6桁一致、保持ソリッド4つの生死は完全一致。
5. **副産物として、解く系が 1/3 になり1反復が 24% 速くなる**(反復40で自由自由度
   299,625 → 90,105、49.8秒 → 37.6秒)。**速度は採否の判断材料ではない**が、
   「入れると遅くなる」ではないことは確かめてある。ただし**CG の反復数は 37% 増える**
   (`free` が箱型から細い構造へ変わって幾何マルチグリッドの効きが落ちる)。
6. **落ちる割合は充填率ではなく「どれだけ二値へ寄ったか」で決まる。** 反復1で 0%、
   反復4で 1.6%、反復40で 75%。充填率 30% の `PRESET` は 30反復で 33.6% —— **1題材の
   割合を一般化してはいけない。**

**既定はオフのままにしてある**(`dynamic_active=False`)。上の 1 のとおり、**入れる理由に
していた場面(求解の失敗)で効果が測れなかった**ため。5 の速度は既定を倒す理由にしない
—— それはこのタスクが判定に使うと決めた尺度ではない。

## 閾値 `emin ** (1/penal)` の導出

SIMP の補間は `E_e = emin + ρ_e^penal (E − emin)` である。`ρ^penal = emin` となる ρ、
すなわち

```
閾値 = emin ** (1 / penal)          # 既定 emin=1e-9 / penal=3 では 1e-3
```

でちょうど**SIMP 項が `emin` と同じ大きさ**になる。これを下回る要素は:

- **剛性寄与が `emin` と同じ桁**。組み立てから外しても K は O(emin) しか変わらない
- **感度も潰れている**。`dc ∝ penal · ρ^(penal−1) · ce` で、閾値では
  `ρ^(penal−1) = emin^((penal−1)/penal)` = **1e-6**(既定)—— ρ=1 の要素の 100万分の1。
  実測の集計はさらに小さく、**全体の 2.56e-12**(下の表。`ce` も小さいため)

つまり**すでに数値的に死んでいるものだけを外す**。`check_simp.py` [11] は
`thr**penal == emin` を4つの (emin, penal) の組で固定している。

### 上げてはいけない

| ρ | SIMP 項 `ρ^3` | `emin`(1e-9)との比 |
|---|---|---|
| 1e-3(**閾値**) | 1e-9 | **1倍** |
| 1e-2 | 1e-6 | **1000倍** |

ρ=1e-2 の要素は感度が生きている。外すと「まだ収束していない状態で位相を確定させる」
ことになり、**設計変数ごと外す案(2026-09-12 に本人が「やらない」と決めた領域)**に入る。

`check_simp.py` [11] はこれを**捨てる感度の割合**で測っている(合成題材 20x8x8、
死んだ塊 ρ=1e-6 と灰色の塊 ρ=5e-3 を置いた密度場):

| 閾値 | 外す要素 | 外す要素の \|dc\| が全体に占める割合 |
|---|---|---|
| `emin**(1/penal)` = 1e-3 | 216 / 1280 | **2.56e-12** |
| 1e-2 へ上げる | 432 / 1280 | **3.996e-05**(**1.56e7 倍**) |

**閾値を動かすなら、下の「戻れる/戻れない境目」も一緒に見直すこと。**

## 何をしているか(実装)

`Model.prepare` が毎回 ρ を受け取るので、そこで作り直す(`Model._refresh_active`):

1. `alive = ρ >= 閾値`(静的な `active_mask` を上限として AND を取る)
2. `alive` でない要素を**組み立てから外す**(`_iK`/`_jK` を作り直す)
3. `~alive` を void として `_floating_dofs` を引き、**外れた要素にしか接していない自由度を
   拘束へ回す**(`extra_fixed_dofs` と同じ void から作るという `Model.__init__` の契約を、
   動的な void で満たし直す)
4. `free` が変わるので、多重格子の移送作用素のキャッシュを捨てる

**active set が前の反復と同一なら 2〜4 を丸ごと飛ばす。** 実測: `PICK_RATIO=0.60` の反復1は
1要素も落ちないので 2〜4 を通らない。`prepare` の秒数は**同じ条件を2回測って
オフ 22.6 / 19.6秒・オン 17.6 / 17.9秒**(生データに残っているのは前者)——
**走ごとの振れのほうがオン/オフの差より大きい**。口を開けたぶんの費用は付いていない。

外した領域は `check_simp.py` [11] が固定している:

- 追加拘束された自由度の解は**きっかり 0.0**(同じ自由度は静的な系では max\|u\| = 2.297e+01
  の軟モードだった)
- 自由自由度は1つも孤立しない(K_ff に全零行が無い)
- 目的値は動かない(合成題材で相対 **5.13e-09**)
- `optimize` のループ上で active set が**反復の途中で段階的に縮む**(PRESET で反復10に
  158、反復30に 430 / 1,280要素)—— 終端だけを見ると「最後の1反復で落ちた」と区別が付かない

**既定オフが「1ビットも変わらない」ことの根拠は構造のほうにある**:
`prepare` は `if self.dynamic_active:` の中でしか `_refresh_active` を呼ばず、
`__init__` が足したのは属性2本の控え(`_base_active` / `_base_fixed`)だけである。
検査が押さえているのはその**一部**で、過大に読まないこと:

- `check_absolute_volume.py` [4] の**凍結指紋**(`rho_sha` と `c_last` を16進で固定)——
  この変更で動いていない。ただし**押さえているのは PRESET と void_mask の経路**で、
  hanger を `run_topopt` に通す経路の指紋は誰も固定していない
- [11](b) `prepare` が `active`/`fixed`/`free`/COO 添字を1つも触らない
- [11](f) オフの `optimize` が新しい経路へ1秒も入らない(`active_refresh_seconds == 0.0`)

## 完了条件の前後(`PICK_RATIO=0.60`・充填率 0.77%)

**通らなかった。落ちる場所も数字も変わらない。**

| | オフ(現状) | **オン(`dynamic_active=True`)** |
|---|---|---|
| 塊 | 658,136 要素 | 同じ |
| 設計空間の物理 ρ(反復1) | min 1.855e-03 / mean 8.277e-03 | 同じ |
| **閾値 1e-3 を下回る要素** | — | **0 個** |
| 組み立てた要素 | 658,136 | **658,136**(1つも外れない) |
| 固定自由度 | 1,555,329 / 3,623,730 | **1,555,329 / 3,623,730** |
| `prepare` の秒数(反復1) | 22.6(再走 19.6) | 17.6(再走 17.9) |
| 結果 | `SolveResidualError` 残差 **2.963e-06** / max\|u\| **1.739e+06** | **同じ**(2.963e-06 / 1.739e+06) |
| 落ちるまでの合計(塊の切り出しを含む) | 338.6秒(再走 327.0) | 334.6秒(再走 324.0) |

**同じ2ケースを2回測っている**(括弧の「再走」は `measure_active_set.py` をリポジトリへ
入れる前に同じ経路で回したぶんで、生データは残していない)。ρ・残差・max\|u\|・
固定自由度は**2回とも1桁も違わない**一方、秒数は 15% 振れる ——
**この題材の秒数でオン/オフを比べないこと。**

**TOPOPT.md の表の 2.701e-06 と食い違うのは、スレッド数と塊の切り出し元が違うため。**
あちらは `threads=1`、こちらは既定の7スレッドで、`_BlockedMatvec` の加算順序が変わると
CG の軌跡も変わる(答えの再現性はスレッド数ごとに保証されている。TOPOPT.md「CPU並列化」)。
拘束自由度も 1,554,498 対 1,555,329 とずれている —— 塊の**要素数**は
`PICK_RATIO × 案1の要素数` で決まるので一致するが、**どの要素を掴むかは参照 run の ρ 順位で
決まる**ので、参照が違えばアンカーも浮いた節点も変わる。**どちらの塊でも同じ場所で落ちる。**

### なぜ届かないか(この設計の構造的な限界)

初期の**設計変数**は一様で、その値は充填率そのものである:

```
初期 x = 材料量 ÷ (PICK_RATIO × 案1の容量) = 0.0077   （閾値 1e-3 の 7.7倍）
```

`prepare` が見るのは密度フィルタと保持/除外の上書きを通した**物理 ρ** なので一様ではないが、
それでも設計空間の最小値は **1.855e-03**(上の表)で、閾値 1e-3 の 1.9倍ある。
**フィルタが縁で薄めるぶんを足しても閾値に届かない。**

閾値は `emin`(1e-9)と `penal`(3)だけで決まる定数 1e-3 で、**充填率とは無関係**である。
したがって:

- **充填率 > 閾値 である限り、反復1では1要素も落ちない。** 崖が反復1にあるこの題材では、
  口を開けても開けなくても同じ行で落ちる
- 落とせるようになるのは**最適化が ρ を押し下げたあと**(この題材では反復2から)。
  つまりこの仕組みは「最適化が作った死んだ領域」を掃除するものであって、
  **最適化を始められるようにするものではない**

**充填率を閾値より下げれば反復1でも落ち始めるが、それは 0.0077 → 0.001 未満、
つまり `PICK_RATIO` をさらに 8倍(4.8 以上)にすることを意味する** —— `derive_from_reference`
は `0 <= pick_ratio <= 1` しか受けない(塊は案1より大きくできない)ので、**そもそも
到達できない領域**である。しかも仮に到達しても、そのとき落ちるのは「材料をまだ配って
いない一様場」であって、位相の情報を持たない要素を先に殺すことになる。

|---|---|---|

| 保持ソリッド | 4つとも `alive_ratio` 1.000 | **#1 と #4 が 0.000** |

**口を入れる前の状態で測っているので、これは本タスクの変更のせいではない。** 候補は2つで、
**どちらかを切り分けていない**:

1. **塊の切り出し元の参照 run が違う。** 本書は 2026-09-09 の pickle を使っている。
   要素数(87,752)は `PICK_RATIO × 案1の要素数` で決まるので一致するが、**どの要素を掴むかは
   参照の ρ 順位で決まる**。参照 run 自体はリポジトリに残っていない
2. **スレッド数が違う。** 本書は既定の7スレッド、`measure_simp_convergence.py` は

   (TOPOPT.md「40反復では収束していない」)ので差が育ちうる

**どちらであっても「保持ソリッドの生死が塊と実行条件で変わる」ことになる。**
TOPOPT.md の「構造の判定は40反復で安定している」は、**この再測では成り立っていない。**
オン/オフの比較そのものは同じ塊・同じスレッド数で並べているので影響を受けない。

## 1反復の費用の内訳

**速度は採否の判断材料ではない**(判定は「落ちていた題材が通るか」と「既定の答えが
変わらないか」)。ここに置くのは、**遅くなっていないことの確認**と、
**`_coo_index_arrays` の作り直しがいくらか**という着手時の未知数への答えである。

`PICK_RATIO=0.08` の 40反復(`simp.collect_solve_stats`。`solve` は `mg_setup` を内数に含む):

| | オフ | オン | 差 |
|---|---|---|---|
| 走り全体(塊の切り出しを含む) | 2,010.1秒 | **1,521.2秒** | **−24.3%** |
| 40反復の合計 | 1,991.9秒 | **1,503.1秒** | −24.5% |
| 1反復の平均 | 49.8秒 | **37.6秒** | −24.5% |
| `assemble`(K組立) | 32.41秒 | 13.20秒 | −59% |
| `slice`(自由DOF切出) | 7.60秒 | 3.39秒 | −55% |
| `mg_setup`(RAP+最粗LU) | 49.86秒 | 35.39秒 | −29% |
| `solve`(setup + CG) | 813.88秒 | 458.41秒 | −44% |
| **active set の作り直し** | 0 | **4.23秒**(0.106秒/反復) | — |
| **CG 反復数(合計)** | 12,721 | **17,386** | **+36.7%** |

**CG の反復数は増える。** 解く未知数が 1/3(299,625 → 90,105)になっているのに反復が 37%
増えた —— 幾何マルチグリッドの補間作用素は `free` から作るので、**箱型の設計空間から
細く枝分かれした構造へ変わると粗い格子の近似が悪くなる**。それでも解く時間は 44% 減った
(1反復あたりの費用の減りが反復数の増えを上回る)が、**枝がもっと細い題材では逆転しうる。**

### 作り直しの内訳(2026-09-12 実測・ndof 3,623,730)

着手時に未知数だった `_coo_index_arrays` は**問題ではなかった**。重かったのは自由度の
集合演算のほうで、**素直に書くと 8.0秒/反復**かかる:

| 手 | 秒 |
|---|---|
| `np.setdiff1d(np.arange(ndof), fixed)` | **6.32** |
| `np.union1d(base_fixed, floating)` | **1.66** |
| `_coo_index_arrays`(87,752 → 21,872要素) | **0.045** |
| `_floating_dofs` | 0.022 |
| `edof[active]` / `flatnonzero` | 0.003 |

`Model._split_dofs` は代わりに**真偽マスク1本**(`mask[base_fixed]=True; mask[extra]=True`
→ `flatnonzero(mask)` / `flatnonzero(~mask)`)で同じ2本(昇順・重複なし)を作る。
**8.0秒 → 0.013秒。** 出る答えは1ビットも変わらない(`rho` の SHA-256 が集合演算版と一致)。

**この差は口の採否をひっくり返す大きさだった**: 集合演算のままだと 40反復で 1,958.4秒
(オフ比 −2.6%。作り直しだけで 341.7秒)で、「入れても速くならない」に見えていた。

## 効く場と効かない場

**落とせる量を決めるのは充填率ではなく「密度場がどれだけ二値へ寄ったか」である。**
1題材の割合を持ち越さないこと。

### 効く場

- **反復が進んだ後**。`PICK_RATIO=0.08`(充填率 5.8%)で、反復20で 72%・反復40で **75%** が
  閾値未満になり、解く自由度が 299,625 → 90,105(**1/3**)になる。1反復は 24% 速くなる
- **`emin` だけで支えられた自由度を系から消したいとき**。合成題材では、外した領域の
  内部自由度が静的な系で max\|u\| = 2.297e+01 の軟モードになっていた(目的値には
  5.13e-09 しか効いていない)。**答えに効かないまま条件数だけ悪くしている部分空間**である

### 効かない場

- **反復の序盤。** 反復1で 0%、反復4で 1.6%。**一様な初期場には落とすものが無い。**
- **まさに `SolveResidualError` が出る場面。** `PICK_RATIO=0.60` の崖は反復1にあるので
  届かない(上の「完了条件の前後」)。**この口を「求解の失敗対策」として当てにしないこと。**
- **充填率が高い題材。** 片持ち梁の `PRESET`(volfrac 0.3・塊なし)は 30反復かけて
  **430 / 1,280 = 33.6%** しか落ちない —— 材料が残る場所が多いぶん、落とせる余地が小さい。
  **hanger(5.8%)の 75% より少ない。**
- **枝が細くて幾何マルチグリッドが効きにくい題材。** 上の費用表のとおり CG の反復数は
  **37% 増える**。いまの題材では未知数の減りが勝っているが、これは保証ではない

## 落とした要素が戻れる/戻れない境目

**戻れる。** 落とした要素の設計変数は生きたままで、`optimize` は
**設計変数を1つも減らしていない** —— 外すのは組み立てとその自由度だけである。したがって:

- **境界の落ちた要素**は、生きた要素と節点を共有するので `ce > 0` のまま。加えて感度は
  密度フィルタを通る(`dcn = filter(dc · live / hs)`)ので、**自分の `ce` が 0 でも
  近傍の生きた要素の感度が流れ込む**。OC はそこを持ち上げられる
- **落とした領域の深い内部**は、節点が全部拘束されるので `u = 0` → `ce = 0`、かつ
  近傍もすべて落ちているのでフィルタからも何も来ない。**`dcn = 0` になり 0 に張り付く**

`check_simp.py` [11] は「ρ が戻れば要素も自由度も戻る(片道ではない)」を固定している。

**この非対称が閾値の根拠そのものである。** 閾値を `emin**(1/penal)` にしておく限り、
戻れなくなるのは**既に数値的に死んでいた要素**だけになる(上の表の 2.56e-12)。
**閾値を上げるなら、ここを作り直すこと。**

## 併用できないもの

- **`update="mma"`。入口で `ValueError`。** MMA は感度の正規化 `_c0`(初回の
  コンプライアンス)・移動漸近線・直前2点を反復をまたいで持ち、組み立てる要素の集合が
  反復ごとに変わる前提になっていない。ペナルティ連続化(`penal_start`)と同じ扱いにした。
  **`reaction_min`(反力の下限)は MMA を要求するので、こちらも併用できない。**
  解くには「MMA の状態量が active set の変化にどれだけ動くか」を実物規模で測る必要がある
- **ペナルティ連続化(`penal_start`)とは併用できる。** 閾値は `penal` を追って動くので
  (penal=1 なら `emin` = 1e-9、penal=3 なら 1e-3)、低い penal の区間では何も落ちない
  —— PRESET で `penal_start=1.0` / `penal_iters=10` を回すと、落ち始めるのは penal が
  2.56 を超えてからだった。答えは変わらない(コンプライアンス相対 **2.05e-07** /
  \|Δρ\|max 2.96e-05。`check_simp.py` [11])。**実物規模では確かめていない**
- **`keep_model=True` と併せるときは静的な状態で返す**(`Model.reset_active`)。
  最後の反復の active を持ったまま返すと、応力評価(`stress.py`)が
  「どの ρ で作られたか分からない」拘束集合を引く。`stress.evaluate` は
  `model.solve(rho, ...)` を呼ぶので、そこで渡された ρ から作り直される
