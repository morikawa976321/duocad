# 穴口の微細隙間とメッシュ欠損の因果調査

「再現ファイル」までは製品コードを変更する前の調査、「案Aの設計」以降が修正の記録。
対象は保存済み最終形状 `20260922T075258-e20ae028100d`、入力は最適化run `20260921T185659-b6799e00457d`
(hangerの問題run)。面番号はkernel._face_mapの1始まり。

## 結論と適用範囲

フィレット付き保持穴と単純な除外円柱の間に残る細い領域は、正常な入力として扱う。
その領域を囲む曲線が、メッシュ用の折れ線に変換される際に交差することを元形状で確認した。
さらに、同じ局所条件から作った正常な閉じた3面ソリッドでもメッシュ破損を再現した。
単なる位置の相関ではなく、この局所形状と境界近似が破損を起こす十分条件になることを示している。
ただし、元の欠損6面のうち11842は別の円弧／直線の組合せであり、全てをこの隙間だけで説明しない。

OCCTの境界交差検査には小さい交差ループを無視する条件がある。
最小例で、同一の折れ線のまま検査のdeflectionだけを変えると判定が変わった。
形状を変えず標準メッシャーの面deflection設定を変更した実験でも最小例は改善した。
元モデル全体はその設定だけでは直らず、製品修正案の合格を意味しない。

## 元形状で見えた境界交差

deflection=0.2 mmで実際に作られたPolygonOnTriangulationのパラメータを取り出し、
元のpcurve上の点で面内の境界折れ線を復元した。三角形ゼロの面では共有辺の隣接面側から取得。
比較用に元のtrim済みpcurve同士をGeom2dAPI_InterCurveCurveで検査した。

| 面 | 場所 | 境界の種類 | 折れ線の内部交差数 |
|---|---|---|---:|
| 74485 | 下側穴口 | フィレットと平面の交線／円柱と平面の交線 | 2 |
| 74486 | 下側穴口 | 同上 | 3 |
| 74499 | 下側穴口 | 同上 | 1 |
| 7491 | 左上穴口 | 同上 | 1 |
| 8272 | 左上・反対側穴口 | 同上 | 1 |
| 11842 | 右上、y=-5の平面 | 円弧／直線2本 | 2 |

表は交点パラメータが端点に約1e-12まで近いヒットを除く(浮動小数点の端点判定による追加ヒットは
別にある)。8272では元の曲線にも端点から最大約3.4e-7 mmのヒットがあるが、辺の公差1e-6 mm以内。
全てのCAD境界が厳密数学的に交差ゼロと証明したわけではない。

面74485の対向境界は長さ約0.924/0.917 mm、離散化点数は7/6、曲線中点と弦中点の距離の最大値は
約0.00607/0.00477 mm。同じ共有辺を隣接面が別々に扱う問題ではなく、
**異なる対向辺の近似が互いを横切る問題**。

下側穴口はフィレットR=0.5 mm、除外円柱r=2.6 mm。
接する円から軸方向にt離れた位置の半径方向幅は
`w(t)=0.5-sqrt(0.25-t*t)`、小さいtでは `t*t/(2*0.5)` に近い。
t=0.07 mmで幅は0.004924 mm。上記の弦近似誤差と同程度以下になる。
幅は接線に近づくほど二次的にゼロへ近づくため、一定の距離誤差制限だけでは境界の順序を守れない。

![境界近似の実測](images/gap_mechanism.png)

左は元の曲線、中央は実際の折れ線、赤×は交点。横軸は弦方向の距離。
差を見せるため円柱側の元曲線を基準として縦方向を差し引き、µmで拡大した表示。

## 正常な3面ソリッドによる最小再現

元の面74485の平面で局所boxを切り、元の保持リングと解析円柱を差し引いた。
元の巨大な最終B-repや最適化ループを再実行せず、6面・2ソリッドの局所形状が得られる。
booleanのerror/warningはゼロ、BRepCheckはvalid。
分離した `minimal_solid_1.brep` は平面・トーラス・円柱面の3面のみ。
既存inspect_solidでvalid、closed、watertight、単一ソリッド、自己交差ゼロ。

| 同一の3面ソリッドに対する全体deflection | 三角形数 | 境界辺 | 非多様体辺 | 非多様体頂点 |
|---|---:|---:|---:|---:|
| 0.2 mm | 34 | 6 | 2 | 7 |
| 0.01 mm | 38 | 0 | 0 | 0 |
| 0.001 mm | 156 | 0 | 0 | 0 |

0.2でも三角形ゼロの面はなく、IsDone=true、GetStatusFlags=0だった。
従ってAPIの成功や「全ての面に三角形がある」だけでは破損を検出できない。
細かい2条件では向き不整合・縮退・重複もゼロ、接続成分は1。
ここでのメッシュ合否は接続の6項目であり、独立した三角形自己交差検査の合格までは主張しない。

対照実験では円柱半径を2.6から2.59に減らし、幅を0.01 mm増やすと、
元平面および法線方向±0.01 mm移動した平面の3条件とも0.2で接続6項目がゼロになった。
0.001 mmだけ広げた条件には破損が残る。入力の修正提案ではなく原因を切り分ける介入である。
平面位置の小さな変化でも狭い条件の破損は再現し、単一の偶然の座標だけの問題ではない。

## OCCTで見逃しが起きる機序

調べたソースはOCCT V7_9_3。
[BRepMesh_FaceChecker.cxx](https://github.com/Open-Cascade-SAS/OCCT/blob/V7_9_3/src/BRepMesh/BRepMesh_FaceChecker.cxx)
の137〜167行は、線分交差を見つけても、方向角が5度未満の場合や同一wire内の小ループの場合に無視する。
95〜96行、232行より小ループの面積閾値は `pi*(2*face_deflection)^2`。
対象平面のUVはmm座標なのでdeflection=0.2なら約0.503 mm²。
最小例の平面全体の面積約0.00824 mm²よりも大きい。

[BRepMesh_ModelHealer.cxx](https://github.com/Open-Cascade-SAS/OCCT/blob/V7_9_3/src/BRepMesh/BRepMesh_ModelHealer.cxx)
は検出した交差に対し辺のdeflectionを1/3にして再分割する処理を最大5回行う。
見逃した交差はその改善対象にならず、交差する境界が面分割へ渡る経路がある。
結果として面の欠落または部分的な欠損が生じる説明と、元形状・最小例の観測が一致する。
元の112467面全てについて内部の三角形採否の分岐までトレースしたわけではない。

最小例では標準と同じ処理部品を持つIMeshTools_Contextを作り、内部の離散化モデルを取得。
**折れ線は変更せず**対象平面のdeflectionだけ変更してFaceCheckerを再実行した。

| 検査時の面deflection | 交差なしとして受理 |
|---|---|
| 0.2 | true |
| 0.01 | false |
| 0.001 | false |
| 0.00001 | false |

方向角は変更していないので、少なくとも最小例の見逃しには面積閾値が関与する。
元形状全体の内部モデルで同じ直接検査を試みた処理はnative終了したため、その結果は得ていない。

## 案Aの設計(実装前に決めた契約)

OCCT本体は改造・再ビルドせず、Python/OCP から処理段階を制御する(独自の面三角形分割器・メッシュ
boolean・ボクセル化・穴埋め・頂点の距離による一括統合は導入しない)。**確実性の契約は「未解決の
境界交差・不正な最終メッシュを成功として返さない」**であって、任意の入力が有限回で必ずメッシュ化
できるという保証ではない。

採用理由と、実装後も残る不確実性:

- OCCT の FaceChecker は小ループや浅い方向角の交差を無視するので、独立した交差検査が要る。
- OCP には内部モデル・辺の離散化・3D/2D境界の再生成の API が公開されているが、**過去の内部モデル
  操作には native 終了の実績がある**。API が呼べることと、安全に段階制御できることは別。
- `ForceFaceDeflection` 等の設定変更は最小例を改善するが、元モデル全体は修復できない。
- 依存は `pyproject.toml` の `cadquery-ocp-novtk==7.9.3.1.1`。

### 処理の順序と保証点

```text
以前の三角形キャッシュを破棄
  → OCCT内部モデルを構築
  → 辺を通常精度で離散化
  → 必要な標準の境界整合処理
  → 独立した境界交差検査
  → 問題辺を再分割 → 全隣接面を再検査(解消するまで反復)
  → 面分割前の最終境界検査
  → OCCTの面分割・後処理
  → 出力された境界が検査済みの境界と整合することを確認
  → 面別payload、必要な成果物検査
```

**境界を変更する最後の標準処理の後、DiscretizeFaces の前**を独立検査の保証点にする(検査後に標準
処理が境界を変更するなら、もう一度検査する)。

### 不変条件

1. CADの曲線・曲面・位相接続は変更しない。変更するのは離散化とそのキャッシュだけ。
2. 同じCAD辺の3D点列は一元管理し、全ての利用面・pcurveへ更新を伝播する。
3. 一つの面だけを独立に再メッシュ化して差し戻さない。
4. 交差点を新しいCAD頂点として結合しない。元の曲線に沿って細分化する。
5. 全体の要求精度を緩めない。局所的に細かくすることだけを許す。
6. 汎用メッシュ化では開いた面・シェルも許す。閉鎖性・単一ソリッドは、その契約を持つ最終処理で検査する。

### 交差判定で禁じたこと

面積や角度が小さいことを理由に候補・交差を捨てない。deflection を交差判定の epsilon に流用しない。
固定 epsilon による近似判定は不可(符号が確定しない組だけ厳密演算へ進む)。円柱の seam は同じ辺が同じ面に
異なる pcurve として現れるので、辺そのものではなく**辺の利用箇所(wire内の位置・向き・pcurve)**を区別する。
UVの周期をまたぐ見かけの飛びや球の極の縮退は、そのまま通常の交差に数えない。

### 再分割の停止条件

問題辺は deflection を 1/3 にして元の曲線から再生成する(OCCT の EdgeAmplifier と同じ方針)。
**交差数が一時的に増えても失敗にしない**(細分化しても交差数が単調減少する保証はない)。止めるのは、
全面の境界交差・未分類接触が解消したとき、問題辺の全点列が変化しないか同じ状態へ循環したとき、
許容値の下限・最大反復回数(12巡)・最大点数に達したとき。**12巡以内に収束するという保証ではない。**
本当に交差する入力境界は再分割では直らないので、成功扱いにせず有界時間で失敗させる。

### 合格条件

- 元の問題形状と最小例で、面の欠落がなく、境界辺・非多様体辺・向き不整合・非多様体頂点・縮退・重複がゼロ。
- 最終成果物に不正な三角形自己交差がなく、元の最終ソリッドとして必要な接続条件を満たす(空洞を持つ一般
  ソリッドでは表面成分が複数でも正当なので、成分数1を汎用条件にしない)。
- 実際に面分割へ渡す境界の交差がゼロ。`GetStatusFlags` や三角形数だけでは合格にしない。
- BREP の曲面・曲線・位相構造を変更しない(メッシュキャッシュは変わるのでファイルのバイト一致は要求しない)。
- 正常形状を壊さず、未解決例は有界時間で診断付きの失敗になる。

## 案Aの実装と実測（2026-09-23）

上の設計どおり製品に入れた。
OCCT本体は改造していない。形状・フィレット・隙間・booleanの順序も変えていない。

- `duocad/kernel_meshing.py`: `BRepMesh_IncrementalMesh` の一括呼び出しを、標準と同じ6部品を
  `IMeshTools_Context` に組んだ段階制御に置き換えた（OCP に `BRepMesh_Context` は無い）。
  `initParameters` の補完（DeflectionInterior・MinSize・AngleInterior）まで揃えたので、
  交差の無い形状では三角形が一括呼び出しと完全一致する（`tests/test_kernel_meshing.py`）。
  検査の保証点は PreProcessModel の後・DiscretizeFaces の前。再分割のたびに PreProcessModel をかけ直す
  （円錐の seam に点を足すのがここで、再分割で2点に戻るため）。面分割後は全 pcurve の点数が検査時と
  一致することを確かめる。
- `duocad/boundary_check.py`（OCP非依存）: 正当な共有端点を (a) 同じ辺の隣接線分、(b) wire で連続する辺の
  接続端点（healer が厳密一致させる）、(c) 同じ面の別の wire で同じ CAD 頂点に着く辺の終端、で決め、
  線分の全対を外接矩形の掃引で絞って向き判定で分類する。向き判定は Shewchuk の誤差境界で確定しない組だけ
  整数演算へ落とす。固定εは使わない。(b) の端点が厳密一致せず CAD 頂点も共有しなければ `open` として報告する。
  座標が一致しない組（下記の落とし穴）は端点のずれに見合う範囲の接触だけを許容し、件数と最大のずれを診断に残す。
- 再分割は OCCT の EdgeAmplifier と同じ（`Clear(True)` で端点を保ち、偏差を 1/3、最小サイズは
  Precision::Confusion、点数は減らさない、3D を作り直して全 pcurve へ `Tessellate2d`）。
  停止条件は解消・上限12巡・点列の無変化・状態の循環・点数予算。解消できない面は Failure にして
  分割せず、`tessellate` の `untriangulated` と `boundary["unresolved"]` に残す。
- `duocad/mesh_intersections.py`（OCP非依存）: 三角形メッシュの自己交差を、正当な共有辺・共有頂点の
  接触を除いて向き判定だけで検出する。`finalize.solid_mesh` は接続6項目に加えてこれと、float32 に
  丸めた座標での頂点一致・縮退を検査し、不合格なら例外にする。`meshbody.write_stl` は書く前に
  float32 の縮退・非有限を検査し、既存ファイルに触れずに止める。

### 分かった落とし穴

- 内部モデルのハンドル（面・辺・pcurve）をモデルより長生きさせると解放時に 0xC0000005 で落ちる。
  製品では派生ハンドルを1オブジェクトに閉じ、pcurve→辺→面→モデル→context の順に手放す。
- OCCT の healer が再分割に使う最小サイズは Precision::Confusion で、context の既定 MinSize（0.1×偏差）
  ではない。既定のまま再分割すると細分できない。
- `IMeshData_Face.IsEqual` は状態フラグの比較で、面の同一性ではない。pcurve と wire の対応は
  `GetFace().GetFace().IsSame` と向きで取る。
- 純Pythonで面ごとに numpy を呼ぶと 112k 面で 42 秒かかった。全面を1本の配列に詰めて掃引すると 0.8 秒。
  折り返し検査の準備で `adjacent[legit][row]` を組ごとに評価する書き方も 39 秒かかった（O(n²)）。
- **スケッチの線が円の中で終わる領域**（`region.py` が splitter で作る面）では、内側の辺が外周の頂点に着くが
  OCCT の healer は同じ wire の連続する辺しか端点を揃えない。円弧の pcurve 端点は `(2, 2.4e-16)`、内側の辺は
  `(2, 0)` で、折れ線としては 2.4e-16 の本物の交差になり、再分割しても消えない（12 巡回って面が消え、
  `tests/test_move_verbs.py` の回転が落ちた）。CAD 頂点を共有する別 wire の終端どうし（規則 (c)）は
  接続として扱い、座標を動かさず端点付近の接触だけを許容する。同じ wire の連続しない辺の頂点共有は周期面の seam や
  u=0/2π の両端（ずれ 2π）なので (c) に含めない。

### 未検証・注意

- 有限回で必ず収束する保証はない。接する2曲線の最初の弦の角度が曲率比で決まる構図では、両辺を同じ比で
  細分しても交差が残りうる（解析的な推定で、実測はしていない）。上限12巡は今回7巡で足りた値で、
  超えた場合は未解決として分割せず報告する。
- 検査は OCCT の healer が端点を接続した後の点列を前提にする。接続されない wire（CAD で頂点を共有しない）は
  `open` として分割対象から外れる。INTERNAL の辺は接続の期待から外し、頂点共有 (c) だけで見る
  （スケッチ領域の内側の辺で確認。他の由来の INTERNAL 辺は試していない）。座標がずれた終端では、
  2端点の外接矩形を最大座標差だけ広げた範囲に交差・接触・重なり全体が収まる場合だけ許す。
  交点と範囲の比較はfloatの厳密な有理数表現で行い、浅い交差が線分の内部へ伸びた場合は検出する。
  許容域は端点評価ずれの扱いであり、元の曲線が厳密に交差していないことの証明ではない。
- 三角形の自己交差検査は float32 に丸めた座標でだけ行う（画面もSTLも float32 で消費するため）。
  float64 側は接続6項目のみ。
- 球の極では標準の OCCT が縮退三角形を出す（`test_kernel_meshing` の球で標準と一致するが接続検査は0でない）。
  汎用の `tessellate` は従来どおり通し、厳格な `solid_mesh` は不合格にする。
- 112k 面の形状では `tessellate` が約11秒遅くなり、画面のズームで再分割する経路も同じだけ遅くなる。
  取り出し 5.9 秒は pcurve 点ごとの OCP 呼び出しで、この版の OCP に一括取得の口は無い。

### 追加の制約

共有CAD頂点の端点差が1e-8 mmでも、浅い交差の交点は線分中央まで離れうる
(許容は端点付近だけに限定する。既存のスケッチ領域の2.4e-16 mmのずれは引き続き許容する)。
通常のB-repのSTL経路も`untriangulated`または`boundary.unresolved`があれば拒否する
(交差した面と正常な箱のcompoundで、欠落面を除いたSTLが成功する反例があった。
不合格時は出力ファイルの新規作成・上書きのどちらも起きない)。

元の112467面を既定0.2 mmで再検証しても同じ結果(未分割面ゼロ、接続6項目ゼロ、
float32自己交差5分類ゼロ)。関連248テストが合格。
