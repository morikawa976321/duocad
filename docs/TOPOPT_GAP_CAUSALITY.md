# 穴口の微細隙間とメッシュ欠損(OCCT のメッシャー)

フィレット付き保持穴と単純な除外円柱の間に残る細い領域で OCCT の面分割が壊れる因果と、その修正(案A: 境界交差の検出と再分割。`duocad/kernel_meshing.py`・`duocad/boundary_check.py`)の記録。
対象は保存済み最終形状 `20260922T075258-e20ae028100d`(最適化run `20260921T185659-b6799e00457d`、hangerの問題run)。面番号は kernel._face_map の1始まり。

## 結論と機序(外部の罠)

細い領域は正常な入力として扱う。その領域を囲む曲線がメッシュ用の折れ線に変換される際に**異なる対向辺の近似が互いを横切る**(同じ共有辺を隣接面が別々に扱う問題ではない)ことを元形状で確認し、
同じ局所条件から作った正常な閉じた3面ソリッドでもメッシュ破損を再現した。局所形状と境界近似が破損の十分条件になる。
ただし元の欠損6面のうち 11842 は別の円弧/直線の組合せ(右上、y=-5 の平面)で、全てをこの隙間だけでは説明しない。

- 元形状の折れ線の内部交差: 面 74485(下側穴口、フィレットと平面の交線/円柱と平面の交線)2・74486 3・74499 1・7491(左上穴口)1・8272 1・11842 2(deflection=0.2 mm の PolygonOnTriangulation から復元。端点に約1e-12まで近いヒットは除く)。
  全CAD境界が厳密に交差ゼロと証明したわけではない。
- 幅の近似: 下側穴口はフィレットR=0.5 mm・除外円柱r=2.6 mm。接する円から軸方向にt離れた位置の半径方向幅は `w(t)=0.5-sqrt(0.25-t²)`(小さいtで t²/(2·0.5))で、t=0.07 mm で 0.004924 mm。
  面74485の対向境界(長さ約0.924/0.917 mm、離散化点数7/6)の曲線中点と弦中点の距離の最大 約0.00607/0.00477 mm と同程度以下。
  幅は接線に近づくほど二次的に0へ近づくので、一定の距離誤差制限では境界の順序を守れない。図: ![境界近似の実測](images/gap_mechanism.png)
- **OCCT の見逃し**(V7_9_3): [BRepMesh_FaceChecker.cxx](https://github.com/Open-Cascade-SAS/OCCT/blob/V7_9_3/src/BRepMesh/BRepMesh_FaceChecker.cxx) 137〜167行は、線分交差を見つけても方向角が5度未満の場合や同一wire内の小ループを無視する。
  小ループの面積閾値は `pi*(2*face_deflection)²`(95〜96・232行)で、UVがmm座標なら deflection=0.2 で約0.503 mm²。最小例の平面全体(約0.00824 mm²)より大きい。
  [BRepMesh_ModelHealer.cxx](https://github.com/Open-Cascade-SAS/OCCT/blob/V7_9_3/src/BRepMesh/BRepMesh_ModelHealer.cxx) は検出した交差に対し辺のdeflectionを1/3にして最大5回再分割するが、見逃した交差はその対象にならず、
  交差する境界が面分割へ渡って面の欠落や部分的な欠損になる(元の112467面全てについて内部の三角形採否の分岐までトレースしたわけではない)。
  最小例で内部モデルの折れ線を変えず対象平面の deflection だけ変えて FaceChecker を再実行すると、0.2 は交差なしとして受理、0.01・0.001・0.00001 は拒否 —— 方向角は同じなので少なくとも最小例の見逃しには面積閾値が関与する。
  元形状全体の内部モデルでの同じ直接検査は native 終了して結果を得ていない。
- **API の成功では検出できない**: 破損した 0.2 でも三角形ゼロの面は無く、IsDone=true・GetStatusFlags=0。

## 最小再現

元の面74485の平面で局所boxを切り、元の保持リングと解析円柱を差し引いた6面・2ソリッド(boolean の error/warning は0、BRepCheck valid)から、
平面・トーラス・円柱面の3面ソリッド(`tests/fixtures/gap_minimal_solid.brep` ほか。`tests/test_kernel_meshing.py` が使う)を分離した。既存 `inspect_solid` で valid・closed・watertight・単一ソリッド・自己交差ゼロ。

|---|---:|---:|---:|---:|
| 0.2 mm | 34 | 6 | 2 | 7 |
| 0.01 mm | 38 | 0 | 0 | 0 |
| 0.001 mm | 156 | 0 | 0 | 0 |

- 円柱半径を 2.6 → 2.59(幅 +0.01 mm)にすると、元平面と法線方向±0.01 mm移動した平面の3条件とも 0.2 で接続6項目が0になる。0.001 mm だけ広げた条件には破損が残る。
  平面位置の小さな変化でも狭い条件の破損は再現し、単一の偶然の座標だけの問題ではない(入力の修正提案ではなく原因を切り分ける介入)。
- 形状を変えず標準パラメータ(`ForceFaceDeflection`・`DeflectionInterior`。辺の初期 0.2・角度0.35)を変える介入: 最小3面ソリッドは Force=true かつ Interior≤0.01 で接続6項目が0になる(三角形 76〜96)が、
  元の全形状は解決せず(三角形ゼロの面が 74485 または 7491、境界辺 38 → 17)。
  従って **全体の精度を上下させるだけ・入力の隙間を消すだけ・APIの成功だけを信頼する方法は根本対策にならない**。局所境界の交差を検出し、共有辺との整合を保って再分割する方向が根拠を持つ。
  メッシュ集合演算への全面変更が必要だとは、この調査からは結論できない。
- 接続6項目の合否は独立した三角形自己交差検査の合格までは主張しない。

## 案Aの設計(実装前に決めた契約)

OCCT本体は改造・再ビルドせず、Python/OCP から処理段階を制御する(独自の面三角形分割器・メッシュboolean・ボクセル化・穴埋め・頂点の距離による一括統合は導入しない)。
**確実性の契約は「未解決の境界交差・不正な最終メッシュを成功として返さない」**であって、任意の入力が有限回で必ずメッシュ化できるという保証ではない。
OCP には内部モデル・辺の離散化・3D/2D境界の再生成の API が公開されているが、過去の内部モデル操作には native 終了の実績があり、API が呼べることと安全に段階制御できることは別。

処理の順序(**境界を変更する最後の標準処理の後、DiscretizeFaces の前**を独立検査の保証点にする。検査後に標準処理が境界を変更するならもう一度検査する):

```text
以前の三角形キャッシュを破棄 → OCCT内部モデルを構築 → 辺を通常精度で離散化 → 必要な標準の境界整合処理
  → 独立した境界交差検査 → 問題辺を再分割 → 全隣接面を再検査(解消するまで反復)
  → 面分割前の最終境界検査 → OCCTの面分割・後処理 → 出力された境界が検査済みの境界と整合することを確認
  → 面別payload、必要な成果物検査
```

不変条件:
1. CADの曲線・曲面・位相接続は変更しない。変更するのは離散化とそのキャッシュだけ。
2. 同じCAD辺の3D点列は一元管理し、全ての利用面・pcurveへ更新を伝播する。
3. 一つの面だけを独立に再メッシュ化して差し戻さない。
4. 交差点を新しいCAD頂点として結合しない。元の曲線に沿って細分化する。
5. 全体の要求精度を緩めない。局所的に細かくすることだけを許す。
6. 汎用メッシュ化では開いた面・シェルも許す。閉鎖性・単一ソリッドは、その契約を持つ最終処理で検査する。

交差判定で禁じたこと: 面積や角度が小さいことを理由に候補・交差を捨てない。deflection を交差判定の epsilon に流用しない。固定 epsilon による近似判定は不可(符号が確定しない組だけ厳密演算へ進む)。
円柱の seam は同じ辺が同じ面に異なる pcurve として現れるので、辺そのものではなく**辺の利用箇所(wire内の位置・向き・pcurve)**を区別する。UVの周期をまたぐ見かけの飛びや球の極の縮退は通常の交差に数えない。

再分割の停止条件: 問題辺は deflection を 1/3 にして元の曲線から再生成する(OCCT の EdgeAmplifier と同じ方針)。**交差数が一時的に増えても失敗にしない**(細分化しても交差数が単調減少する保証はない)。
止めるのは、全面の境界交差・未分類接触が解消したとき、問題辺の全点列が変化しないか同じ状態へ循環したとき、許容値の下限・最大反復回数(12巡)・最大点数に達したとき。
本当に交差する入力境界は再分割では直らないので、成功扱いにせず有界時間で失敗させる。

合格条件: 元の問題形状と最小例で面の欠落がなく、境界辺・非多様体辺・向き不整合・非多様体頂点・縮退・重複がゼロ。最終成果物に不正な三角形自己交差がなく、必要な接続条件を満たす
(空洞を持つ一般ソリッドでは表面成分が複数でも正当なので、成分数1を汎用条件にしない)。面分割へ渡す境界の交差がゼロ(`GetStatusFlags` や三角形数だけでは合格にしない)。
BREP の曲面・曲線・位相構造は変更しない。正常形状を壊さず、未解決例は有界時間で診断付きの失敗になる。

## 案Aの実装と実測(2026-09-23)

- `duocad/kernel_meshing.py`: `BRepMesh_IncrementalMesh` の一括呼び出しを、標準と同じ6部品を `IMeshTools_Context` に組んだ段階制御に置き換えた(OCP に `BRepMesh_Context` は無い)。
  `initParameters` の補完(DeflectionInterior・MinSize・AngleInterior)まで揃えたので、交差の無い形状では三角形が一括呼び出しと完全一致する(`tests/test_kernel_meshing.py`)。
  検査の保証点は PreProcessModel の後・DiscretizeFaces の前。再分割のたびに PreProcessModel をかけ直す(円錐の seam に点を足すのがここで、再分割で2点に戻るため)。面分割後は全 pcurve の点数が検査時と一致することを確かめる。
- `duocad/boundary_check.py`(OCP非依存): 正当な共有端点を (a) 同じ辺の隣接線分、(b) wire で連続する辺の接続端点(healer が厳密一致させる)、(c) 同じ面の別の wire で同じ CAD 頂点に着く辺の終端、で決め、
  線分の全対を外接矩形の掃引で絞って向き判定で分類する。向き判定は Shewchuk の誤差境界で確定しない組だけ整数演算へ落とす。固定εは使わない。(b) の端点が厳密一致せず CAD 頂点も共有しなければ `open` として報告する。
  座標が一致しない組は端点のずれに見合う範囲の接触だけを許容し、件数と最大のずれを診断に残す。
- 再分割は OCCT の EdgeAmplifier と同じ(`Clear(True)` で端点を保ち、偏差を 1/3、最小サイズは Precision::Confusion、点数は減らさない、3D を作り直して全 pcurve へ `Tessellate2d`)。
  停止条件は解消・上限12巡・点列の無変化・状態の循環・点数予算。解消できない面は Failure にして分割せず、`tessellate` の `untriangulated` と `boundary["unresolved"]` に残す。
- `duocad/mesh_intersections.py`(OCP非依存): 三角形メッシュの自己交差を、正当な共有辺・共有頂点の接触を除いて向き判定だけで検出する。`finalize.final_mesh_checks` は接続6項目に加えてこれと、
  float32 に丸めた座標での頂点一致・縮退を検査し、`finalize` は不合格なら例外にする。`meshbody.write_stl` は書く前に float32 の縮退・非有限を検査し、既存ファイルに触れずに止める。
- 通常のB-repのSTL経路も `untriangulated` または `boundary.unresolved` があれば拒否する(交差した面と正常な箱のcompoundで、欠落面を除いたSTLが成功する反例があった。不合格時は出力ファイルの新規作成・上書きのどちらも起きない)。

実測(保存済み最終形状 112,467面・171,794辺、偏差0.2 mm、角度0.35 rad、InParallel。`topopt_checks/check_boundary_meshing.py --compare`):

| | 標準の一括メッシャー | 段階制御＋境界交差の修復 |
|---|---:|---:|
| 三角形ゼロの面 | 74485 | なし |
| 境界辺 / 非多様体辺 / 向き不整合 / 非多様体頂点 / 縮退 / 重複 | 38 / 0 / 0 / 37 / 0 / 0 | 0 / 0 / 0 / 0 / 0 / 0 |
| 三角形の自己交差(貫通/接触/共面/折り返し/重複) | 3 / 2 / 1 / 0 / 0 | 0 / 0 / 0 / 0 / 0(候補 1,091,753 対) |
| 三角形 / 頂点 | 136,284 / 68,149 | 136,564 / 68,276 |
| `tessellate` の秒 | 11.2 | 22.1 |

修復の経過は、初回の全面検査で交差10件、再分割した辺は13本(延べ37回)で7巡で解消。最も重いのは内部モデルからの pcurve 点列と CAD 頂点の取り出し(6.4秒、負荷のある環境で11秒。pcurve 点ごとの OCP 呼び出しで、この版の OCP に一括取得の口は無い)。
DiscretizeFaces は5.5秒、成果物検査(接続6項目・float32・自己交差)は5.1秒。112k 面の形状では `tessellate` が約11秒遅くなり、画面のズームで再分割する経路も同じだけ遅くなる。
最小例と局所形状(`tests/fixtures/gap_*.brep`。`tests/test_kernel_meshing.py` が固定)は、3面ソリッドが偏差0.2 で 1巡・2辺(点34→52、三角形70)、0.05 で 2巡・2辺(34→60、90)、0.01 は交差なしで一括と一致、
平面−0.01 mm・r2.6 と平面0・r2.599 も 1巡で接続6項目0。対照の r2.59 は交差なしで一括と三角形が一致する。
箱・円柱(seam・2辺wire)・球(極)・円錐(seam)・トーラス・穴あき板・開いた1面では交差を誤報せず、三角形が一括メッシャーと一致する。
蝶ネクタイ形の自己交差する wire は直線の辺なので再分割で点列が変わらず、1巡で `no_change` として止まり、その面だけ分割されずに報告される(他の面は分割する)。

### 落とし穴

- 内部モデルのハンドル(面・辺・pcurve)をモデルより長生きさせると解放時に 0xC0000005 で落ちる。製品では派生ハンドルを1オブジェクトに閉じ、pcurve→辺→面→モデル→context の順に手放す。
- OCCT の healer が再分割に使う最小サイズは Precision::Confusion で、context の既定 MinSize(0.1×偏差)ではない。既定のまま再分割すると細分できない。
- `IMeshData_Face.IsEqual` は状態フラグの比較で、面の同一性ではない。pcurve と wire の対応は `GetFace().GetFace().IsSame` と向きで取る。
- 純Pythonで面ごとに numpy を呼ぶと 112k 面で42秒かかった。全面を1本の配列に詰めて掃引すると0.8秒。折り返し検査の準備で `adjacent[legit][row]` を組ごとに評価する書き方も39秒かかった(O(n²))。
- **スケッチの線が円の中で終わる領域**(`region.py` が splitter で作る面)では、内側の辺が外周の頂点に着くが OCCT の healer は同じ wire の連続する辺しか端点を揃えない。円弧の pcurve 端点は `(2, 2.4e-16)`、
  内側の辺は `(2, 0)` で、折れ線としては 2.4e-16 の本物の交差になり、再分割しても消えない(12巡回って面が消え、`tests/test_move_verbs.py` の回転が落ちた)。
  CAD 頂点を共有する別 wire の終端どうし(規則 (c))は接続として扱い、座標を動かさず端点付近の接触だけを許容する。同じ wire の連続しない辺の頂点共有は周期面の seam や u=0/2π の両端(ずれ 2π)なので (c) に含めないが、**両方が INTERNAL の別の辺どうしは含める**
  (孤立線は1本の INTERNAL wire にまとまるので、L字・Y字・十字の枝は同じ wire で頂点を共有する。含めないと偽の touch で面が三角形にならない。2026-10-18 の再現で確認)。
- 共有CAD頂点の端点差が1e-8 mmでも、浅い交差の交点は線分中央まで離れうる。許容は端点付近だけに限定し(既存のスケッチ領域の2.4e-16 mmのずれは許容)、座標がずれた終端では、2端点の外接矩形を最大座標差だけ広げた範囲に
  交差・接触・重なり全体が収まる場合だけ許す(交点と範囲の比較は float の厳密な有理数表現。浅い交差が線分の内部へ伸びた場合は検出する)。許容域は端点評価ずれの扱いで、元の曲線が厳密に交差していないことの証明ではない。
  **ずれが評価誤差の大きさ(座標の 2^-40 倍以下)のときだけ、広げる幅を交差角で増やす**(2線の交点は端点から |ずれ|/sinθ まで離れる。整数座標でも、辺から 45 度未満で引いた孤立線は交点が最大座標差の外に出て偽の cross になった。上辺へ向かう整数座標の線 300 本のうち 10 本)。1e-8 のずれは評価誤差でなく、角度で広げない。

### 未検証・注意

- 有限回で必ず収束する保証はない。接する2曲線の最初の弦の角度が曲率比で決まる構図では、両辺を同じ比で細分しても交差が残りうる(解析的な推定で、実測はしていない)。
  上限12巡は今回7巡で足りた値で、超えた場合は未解決として分割せず報告する。
- 検査は OCCT の healer が端点を接続した後の点列を前提にする。接続されない wire(CAD で頂点を共有しない)は `open` として分割対象から外れる。
  INTERNAL の辺は接続の期待から外し、頂点共有 (c) だけで見る(スケッチ領域の内側の辺で確認。他の由来の INTERNAL 辺は試していない)。
- 三角形の自己交差検査は float32 に丸めた座標でだけ行う(画面もSTLも float32 で消費するため)。float64 側は接続6項目のみ。
- 球の極では標準の OCCT が縮退三角形を出す(`test_kernel_meshing` の球で標準と一致するが接続検査は0でない)。汎用の `tessellate` は従来どおり通し、
  `finalize` の入力検査(`input_mesh_checks`。縮退三角形は接続6項目の1つ)は不合格にする。
- 元の112467面を既定0.2 mmで再検証しても同じ結果(未分割面ゼロ、接続6項目ゼロ、float32自己交差5分類ゼロ)。依存は `pyproject.toml` の `cadquery-ocp-novtk==7.9.3.1.1`。
