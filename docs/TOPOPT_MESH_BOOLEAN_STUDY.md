# 最適化最終処理のメッシュ集合演算案（2026-09-22 実測）

**採用(2026-10-06、#95)**: 下記の中核処理を製品の最終処理にした(`duocad/topopt/finalize.py`。保持・除外の分割偏差
0.01 mm、`as_original().simplify(1e-5)`、入力と結果の検査)。採用の判断と現在の経路は [TOPOPT.md](TOPOPT.md)
「最終処理はメッシュ集合演算」、合格条件と採用後の実測は [TOPOPT_ACCEPTANCE.md](TOPOPT_ACCEPTANCE.md)。
以下は採用前の調査の記録(製品コードは変えていない時点のもの)。

## 結論と検証範囲

曲面を含む最終B-repを作ってから三角形化する代わりに、保持・除外CADを先に三角形化し、
平滑化後のメッシュと集合演算する案を調べた(製品コード・依存定義は変更していない)。

**hangerの問題runで、保存したバイナリSTLが既存の水密・単一ソリッド判定に合格した**
(接続検査6項目は全て0、OCCTの自己干渉0・ソリッド1、CGALの自己交差0)。別の小型run 2件でも
同じ処理が合格したが、これは3例での実測であり、任意モデルへの保証ではない。

一方、**元CADの保持・除外形状を厳密に再現する案ではない**。最終境界の標本点が元の除外CAD
内部に入る例を検出した。最終ボディをメッシュとして持ち、STEP書き出し・面単位の選択・CAD編集を
持たないことは製品仕様として確定している(2026-09-23 本人判断、2026-10-10 再確認。[TOPOPT.md](TOPOPT.md)
「結果は編集可能ソリッドとして持たない」)。

## 入力・環境・再現手順

主対象はhangerの問題run `20260921T185659-b6799e00457d`(121,412三角形・60,700頂点、
保持4個・除外8個)。平滑化入力の接続検査6項目は0、CGALの自己交差も0。
SIMP・表面生成・平滑化は再実行していない。

追加依存はWindows用wheelで導入できた(Manifold 3.5.3、CGAL Python bindings
6.0.1.post202410241521、PyMeshLab 2025.7.post1):

```powershell
uv pip install --no-deps --only-binary :all: manifold3d==3.5.3 cgal==6.0.1.post202410241521 pymeshlab==2025.7.post1
```

合格を再現する中核は次の処理。入力は倍精度の `Mesh64`。
`M` は平滑化済みメッシュ、`P` と `E` は三角形化した保持・除外のそれぞれの和集合。

```python
result = (M + P) - E
result = result.as_original().simplify(1e-5)
```

保持・除外の分割偏差は0.01 mm、角度偏差は製品既定の0.35 rad。
結果の配列を取り出し、座標完全一致で溶接してから検査・保存した。
近接頂点を許容差内でまとめる溶接や、不良面の単純削除はしていない。
`simplify(1e-5)` は形状変化の許容値を指定する処理で、欠陥を合格扱いにするしきい値ではない。
ただし、その指定値が全ケースで幾何誤差の上限になることを今回独立に証明したわけではない。

## 集合演算のみの結果

以下は簡略化前・倍精度。全4条件で接続検査6項目は全て0、境界成分1、ManifoldのstatusはNoError。

| CAD分割偏差 mm | 出力三角形 | 集合演算 秒 | CGAL自己交差ペア | バイナリSTL化後の縮退三角形 |
|---|---:|---:|---:|---:|
| 0.2 | 127,114 | 0.065 | 0 | 45 |
| 0.05 | 128,722 | 0.072 | 0 | 45 |
| 0.01 | 143,412 | 0.093 | 0 | 62 |
| 0.002 | 213,698 | 0.181 | 142 | 150 |

0.002では集合演算前の入力にCGALの交差検出が180ペアあった。入力メッシュの接続検査は
合格しているため、接続検査だけでは除けない。0.2・0.05・0.01の入力12ボディには
CGALで交差を検出しなかった(細かくするほど入力の健全性が改善するわけでもない)。

**検出器間で不一致がある**: PyMeshLabの自己交差フィルタは0.01の出力で200面を選択したが、
CGALでは0ペアだった(縮退三角形を自分自身とのペアとして報告するケースがあるため)。
PyMeshLabの面数を実交差の確定件数として使わない。簡略化後の最終候補はCGALと既存OCCT判定の
両方で確認した。

## 保存精度と簡略化

`meshbody.write_stl` は座標をfloat32で書く。ビューアのpositionも
`web/src/viewport.ts` の `Float32Array` に変換される。
倍精度の配列が正常でも、細い三角形が単精度では潰れる。

0.01の生出力に対して既存判定器を使うと、倍精度配列は
`RuntimeError: OCCTがソリッドを不正と判定した` でUNKNOWN（約48秒）、
バイナリSTLは縮退62枚のためFAILだった。

同じ倍精度結果を17桁ASCII STL（既存 `trace.final_mesh` と同じ数値表現）で書いて再読込すると、
座標と添字は完全一致・接続6項目0・CGAL交差0。この保存方法だけではビューアの単精度化や
OCCT判定は解決しない。

簡略化の比較では、保存配列から新しいManifoldを作って `simplify(1e-5)` すると
140,610三角形になり、バイナリSTLを含めて検査に合格した。
しかし集合演算結果に直接同じ簡略化を適用すると142,182三角形で、STLに縮退28枚が残った。
**`as_original()` で入力面の由来情報をリセットしてから簡略化すると、直接の処理でも
140,610三角形の合格結果を再現できた。**
元の面境界が簡略化を制限することはManifoldのAPI説明にも記載されている。
由来情報を使って入力CADの面へ戻る用途には、このリセットをそのまま適用できない。

再読込後に簡略化する比較実験では、許容値1e-4・1e-3 mmでも接続とCGAL検査は合格したが、
これらについて既存OCCT判定は実行していない。最終候補は1e-5 mm。

既存 `check_final_shape.evaluate` は変更せず、保持・除外比較は既定どおり無効。
両方の合格条件（水密・単一ソリッド）でPASSだった。

## 寸法と保持・除外への影響

比較対象CADは従来の最終形状(ネイティブB-rep)から書き出した。OCCTでの体積は3,169,813.784060525 mm³。

| 偏差 mm | 簡略化前の体積差 mm³（メッシュ−CAD） |
|---|---:|
| 0.2 | +97.349907 |
| 0.05 | +88.213448 |
| 0.01 | +19.052749 |
| 0.002 | +3.595203（自己交差があり不採用） |

最終候補は3,169,832.837426282 mm³で、差は+19.053366 mm³（約+0.000601%）。
小さい体積差は、局所のはめ合い精度を保証しない。

各入力CAD面の三角形を最大64枚選び、重心と3辺の中点から、
その元CAD面までの最短距離を `BRepExtrema_DistShapeShape` で測った。
以下は**標本で見つかった最大値**で、最終形状全体のHausdorff距離や誤差上限ではない。
偏差0.01の保持では指定偏差を超える距離も測定したため、パラメータ値をそのまま寸法保証に使えない。

| 偏差 mm | 保持の標本最大距離 mm | 除外の標本最大距離 mm |
|---|---:|---:|
| 0.2 | 0.071179 | 0.051901 |
| 0.05 | 0.163753 | 0.024243 |
| 0.01 | 0.018874 | 0.005336 |

さらに最終候補の三角形重心を、各除外CADのbbox内から最大300点選び、
`BRepClass3d_SolidClassifier`（公差1e-7 mm）で検査。
除外0〜6ではそれぞれ83・113・109・111・119・100・112点が厳密な内部状態 `IN`、
除外7は0点だった。
これは母集団の面積比・干渉体積の推定ではないが、境界が元の除外CAD内に入り込む反例になる。
内接した除外メッシュを引いても元の曲面まで引けないという近似の影響が、実物でも現れた。

Manifoldで結果とメッシュ化済み保持・除外を再演算する診断も行った。
体積は約1e-12 mm³前後だが、`is_empty()` はfalseで残存三角形があった。
**体積が小さいことを理由に保持・除外の厳密合格とはしていない。**
元CADに対する集合演算での保持・除外の完全検査は今回実施していない。

### 円柱の除外へのめり込み(製品既定の偏差。2026-09-25 実測)

`kernel.tessellate` の既定(線形 0.2 mm・角度 0.35 rad)で単独の円柱(長さ40 mm)を分割し、側面の三角形の
内部を細かく標本して、真の円柱面から内側へ入る最大距離を測った。頂点は円柱面上にあり、弦が内側を通るので、
`M − 三角形化した除外` の結果はこの距離だけ除外の中に材料を残す。

| 半径 mm | 周方向の分割数 | 最大弦角 | めり込み mm |
|---:|---:|---:|---:|
| 1 | 36 | 10.00° | 0.0038 |
| 4.35 | 36 | 10.00° | 0.0166 |
| 10 | 36 | 10.00° | 0.0381 |
| 13.288 | 36 | 10.00° | 0.0506 |
| 20 | 36 | 10.00° | 0.0761 |
| 30 | 39 | 9.23° | 0.0973 |
| 100 | 71 | 5.07° | 0.0979 |
| 340 | 130 | 2.77° | 0.0993 |

- OCCT は角度 0.35 rad(20°)に対して弦角を 10° に取り、線形 0.2 mm に対して最大の弦の垂れを約 0.1 mm に抑えた。
  どちらも指定値の半分で、半径約26 mm より小さい円柱は角度が、大きい円柱は線形が決める(めり込み ≒ r(1−cos 5°) = 0.0038 r、上限 約0.1 mm)。
- 今の B-rep 経路も、最終形状を同じ既定で分割して配るので、出力 STL の穴の内面は同じ量だけ除外に入っている。
- 単独の解析円柱での値。BSpline・トーラス面では指定偏差を超えた例がある(上の表「保持の標本最大距離」)。

## 採否に必要な判断

- 現在の水密・単一ソリッド条件を満たす実物は得られた。自作の穴埋め・局所再分割器を
  書くより、中核の実装は単純。ただし入力検査・保存後検査・失敗時の扱いは必要。
- 正本をメッシュにすると、現行のメッシュボディには面選択やCAD編集verbがない。
  有効な三角形B-repへ変換することは今回の既存判定内でもできたが、解析曲面は復元されない。
- 曲面の保持・除外を厳密に守る要件とは、そのままでは両立しない。
  近似精度をどう定めるか、必要なら除外側に安全な近似をどう作るかは別途検討が必要。
- 万能な「Manifoldに渡せば直る」処理ではない。0.002の入力自己交差が反例。
  不良を小さいから通す判定は導入せず、不合格なら原因を示して停止する必要がある。
- 製品の表示・保存・STLが同じ最終メッシュを使うよう統合する必要がある。
  記録用ASCII STLとexport用バイナリSTLでは座標精度が違うため、同じ入力配列だけで
  保存後の幾何まで同一とは限らない。
