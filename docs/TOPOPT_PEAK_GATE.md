# 完成形のピークが目標を割る問題 — 肉盛りに代わる案の検討と実測(2026-10-10、#129)

完成形の表面の最大応力が利用者目標を割る問題(#129。2026-10-11 に、目標を割ったら結果を足さない `final_unsafe` にして閉じた)に、
探索後の肉盛り以外の方法を探した記録。本人の依頼(原文):

> 肉盛りではなく、もっと抜本的でシンプルでスマートなアイデアをゼロベースで探してほしい。astra, fableと意見交換を交わしながら進め、ある程度意見が固まったら私に報告して。

> 局所解に陥らないように注意してね

係数 2.4 は変えない(2026-10-10 本人。[TOPOPT_TARGET_FACTOR.md](TOPOPT_TARGET_FACTOR.md) §1.1)。

## 1. 検討した案(astra〈gpt-6-astra〉・fable〈Fable 5.1〉との相談。採否は本人)

- **収束した案**: 探索の合否に**表面ピーク(部材域の露出面の面中心 von Mises)を却下専用の判定として足す**。Q_V は歩幅・1%停止・patience に残し、ピークは歩幅・停止に流さない。
  全材料ですでに上限を超えるセルだけ、そのセルの全材料の値 × (1+ε) まで許す。最終形が完成形検査を割ったら探索の途中の形へ戻る安全網を足す。
- ピークと Q_V の両方が要る根拠(既存ログの集計): dilution の旧研究版のピーク判定の却下 80 回は、ピークのみ 78・両方 2・Q_V のみ 0。path は却下 0 で Q_V が止めた。
- 最も強い反論: 完成形だけが満たせばよい条件を途中の形すべてに課して、よい形へ至る道を閉じうる。骨組み先行・丸い空隙を変数にする・材料量固定でピークを下げる、は二値マスクの探索という前提の外で、検討していない。

## 2. 「探索中にピークを見ると hanger で +87%」は実装の副作用だった

[TOPOPT_STRESS_GATE_DILUTION.md](TOPOPT_STRESS_GATE_DILUTION.md) 10-2 の hanger 1000N の `unified_peak`(+87%)は、ピーク比を代表応力に
合成して歩幅・停止規則に流していた(`topopt_checks/stress_gate/phase_b_search.py` の `value = max(value, target * peak / limit)`)。
上限 = max(8.33, 1.05 × 全材料 15.45) = 16.23 MPa で、第1評価から代表応力はピーク側の 7.94(安全率 5.04、目標 4.8)が支配し、
歩幅 r = 1 − (4.8/5.04)^0.5 ≈ 0.024 で這った。83 評価で却下 0、最後は安全率 4.844 ≤ 4.8 × 1.01 で 1% 停止
(`output/stress_gate_20261008/searches/hanger_unified_peak_c1_d2.4_e0.05_nodes_L1000_h2.4_w10_H1000.json`)。付け根の物理の証拠ではない。

## 3. 実装(既定は無効)

- `SearchConditions.peak_epsilon`(`None` は判定しない)。段階4の開始時に全材料で1回解き、セルごとの6面(内部の面も含む)の面中心の
  最大 B を測って、上限 `max(許容 ÷ 探索の目標, (1+ε)·B)` をセルごとに作る(`binary_search._attach_peak_limit`)。
- `acceptance.inspect(peak_limit_mpa=)` が6条件とは別の検査 `checks['peak']` を返す。探索はピークで落ちた候補を却下するだけで、
  歩幅・1%停止・安全率の poison には使わない。1セルの却下はその形の間だけ順位から外し、採用を挟まず patience(8)回続けば
  `peak_at_single_cell`。
- 高応力箇所の近くを順位から外す(`PEAK_HOT_RATIO = 0.9`・`PEAK_SKIP_RADIUS = 2`、暫定値): 採用形の露出面が上限の 0.9 を超える
  セルと、却下の最悪セルから 2 セル以内。入れる前の dilution 300N では却下 89 回中 73 回が同じ1か所で、止まった時点でも順位の上位
  30 手のうち 12 手は単独で通った(patience を同じ箇所で使い切っていた)。
- 診断は `diagnostics['reduction']['peak_gate']`(却下数、Q_V に 10% 以上の余裕があるのにピークで落ちた数、却下の場所)。

## 4. 実測(製品の入口 `optimize_run.run`、完成形検査は物差しを替える前(6章)の製品と同じ 1/3 格子・1面の最大。HEAD は各節に記す)

再現は `topopt_checks/stress_gate/run_peak_gate.py`(`--eps` でピーク判定、`--step` で段階4の1回に削る割合の上限)。

### 4-2. 1回に削る割合の上限と荷重(64e47c5、高応力箇所の除外あり。dilution の目標安全率 2.0)

(材料 mm³ / 完成形の安全率 / 評価)。今の製品(Q_V・上限 0.2)は 300N で 18,680 / **1.62** / 50、250N で 17,000 / **1.65** / 65 と目標を割り、200N は 15,840 / 2.21 / 33。
上限 0.05 にすると 300N 18,600 / 2.58 / 49、250N 17,896 / 2.36 / 45 で合格した(材料 −0.4%・+5%、評価ほぼ同じ。上限 0.1 の 300N も 20,272 / 2.38 で合格)。path は上限によらず 40,912 前後・5.33 前後。
ピーク判定は全条件で合格するが完成形の安全率が 2.7〜4.0 まで余り、材料は Q_V・0.05 より +7〜15%、評価回数は 2〜10 倍(300N・0.2 で 21,408 / 3.73 / 106)。高応力箇所の除外は 300N・0.2 で 23,912 → 21,408 mm³(評価 127 → 106)。

### 4-3. 完成形の表面最大の細分収束(junction_convergence.py。dilution 300N、分割数 2〜5、高応力箇所の除外なし)

保持との接合帯は細分でほぼ止まる(Q_V だけの形で k=2 の 10.76 → k=5 の 12.90 MPa)が、それより外は Q_V だけの形で k=3(製品)24.64 → k=5 **31.39** MPa まで上がる(荷重面の近く x ≈ 55 mm)。

### 4-4. 2セルの手(pair_moves.py。dilution 300N・ピーク判定・高応力箇所の除外なし)

止まった形で順位の上位 30 手: 単独で合格 12・ピークで不合格 18。ピークで落ちたセル A に別のセル B を足した 58 組のうち合格 10。
合格した 10 組はすべて B が単独でも合格する組で、**A も B も単独では落ちて組めば通る組は 0**(「組めば通る」という反論の機構は観測されなかった)。

### 4-5. hanger 1000N(64e47c5、h 2.4 mm・最小幅 10 mm、GPU、完成形検査は 1/2 格子)

Q_V・0.2(今の製品)は 582,693 mm³・97 評価で完成形の安全率 1.06、Q_V・0.05 は 427,275・223 評価で 0.83、Q_V + ピーク(ε 0.10)・0.2 は 1,108,472・1,000 評価(予算切れ)で 1.09。
3本とも完成形の最大は下側の保持リングの付け根((±3.6, −5.9, −61.4) mm)で目標 2.0 を割る。ピーク判定は却下 669 回(最初の 200 件の 181 件は上側リングの付け根付近)で材料を 1.9 倍にして予算を使い切っても付け根を割った
(探索格子でピークを抑えても、平滑化と保持ボディとの集合演算の後の付け根には効かない)。上限 0.05 は 27% 軽いが付け根のピークは上がり、dilution で効いた「上限を下げれば割らない」は付け根が支配する hanger 1000N には当たらない
(全材料でも付け根が目標を割る入力。[TOPOPT_STRESS_GATE_DILUTION.md](TOPOPT_STRESS_GATE_DILUTION.md) 10-3 (c))。

### 4-8. 付け根の最大は完成化のどの段で生まれるか(stage_peaks.py。hanger 1000N)

同じ確定マスク・細格子・確定表で stair(確定マスクを割っただけ)/ smooth(平滑化後 + 保持セル)/ final(製品の完成メッシュ)を解いた。分割数 1 では3段とも同じ。
分割数 2 では Q_V・0.2 の形で stair 52.20 → smooth 47.24 → final 37.83 MPa と**下がる**: 付け根のピークを作っているのは最終処理ではなく探索の形。
探索格子の付け根は Q_V・0.2 とピーク判定の形で全材料と同水準(25.5・24.0 対 24.4)、Q_V・0.05 は 1.57 倍(付け根を細らせた)。
hanger 1000N は全材料でも目標(20 MPa)を割る見込み(推定約 37 MPa。全材料の分割数 2 は約 19 GB でメモリが足りず未測定)。

### 4-9. 物理寸法の物差しは細分で収束するか(junction_convergence.py、7a9dbc2。dilution)

保持から離れた部材の表面。面積の上位値は「露出面の面中心の値を大きい順に並べ、面積の合計が A になる位置の値」、球平均は
材料だけで取った要素中心の von Mises の半径 r の平均の最大(MPa)。

| 形 | 最大 k3 → k5 | 面積 4 mm² k3 / k4 / k5 | 面積 9 mm² k3 / k5 | 球平均 r=1 mm k3 / k4 / k5 |
|---|---|---|---|---|
| 300N・0.2(今の製品) | 24.6 → 31.4 | 17.6 / 19.7 / 19.6 | 15.5 / 17.3 | 13.5 / 14.8 / 14.7 |
| 300N・0.05 | 15.5 → 20.2 | 13.9 / 14.8 / 15.0 | 12.7 / 13.8 | 9.6 / 10.1 / 9.8 |
| 250N・0.05 | 16.9 → 22.7 | 13.3 / 13.6 / 14.1 | 12.3 / 12.9 | 9.7 / 9.4 / 9.5 |
| 200N・0.05 | 18.7 → 21.0 | 16.0 / 16.9 / 17.1 | 14.3 / 15.2 | 12.4 / 13.6 / 13.1 |
| 300N・0.1 | 16.8 → 19.7 | 14.3 / 14.5 / 15.2 | 12.6 / 13.7 | 10.7 / 10.8 / 10.9 |

- 最大は k5/k3 = 1.12〜1.34。面積 4 mm² は 1.06〜1.11 で k4 → k5 はほぼ横ばい、球平均 r=1 mm は 0.98〜1.09。
- 球平均は表面の最大の 6 割前後の値になる(曲げの表面応力を平均で下に見る)。
- **物差しで合否が変わる**: 今の製品で目標を割った 300N・0.2 は、最大では 24.6(k3)だが面積 4 mm² の上位値では 17.6〜19.7。

### 4-13. 剛性行列を組み立てない解法の完成形検査(2026-10-11、`final_check_memory.py --solver matrix_free`)

## 5. 実測を見た後の相談の結論

astra・fable とも、次で一致した(相談役の提案。採否は本人)。

- ピーク判定・高応力近傍の除外・上限 0.05 は製品に入れない(研究用に残す)。
- 付け根のピークは最終処理ではなく探索の形が作るので(4-8)、接合部の形を最終処理で扱う案は取り下げる。
- 「1点の最大」は解像度の関数なので(4-7)、物理寸法で決めた物差しで探索と完成形検査を揃えるのを本線として検証する。
  astra は材料だけの球平均の最大、fable は露出面の面積の上位値(A = 2 mm 角 = 4 mm² を仮置き。fable が置いた値で材料の実測ではない)と、
  探索の Q_V の V を w³ から 1 セル程度へ小さくして付け根を見えるようにする案(代わりに入口で断る入力が増える。hanger 500N も
  断られる見込み)。
- #129 は今の判定のまま「目標を割ったら結果を足さない」で先に閉じ、物差しの変更は別件にする
  (今の最大は 4-9 のとおり上位値より大きいので、遮断は保守側に外れる)。→ 本人が採った(2026-10-11、`final_unsafe`)。

## 6. 本人の判断(2026-10-11)

- #129 は「目標を割ったら結果を足さない」で閉じる(5章の推奨の 1 に対して「1はそれでいい。早速実装して」)。
  `optimize_run` の `FINAL_UNSAFE_BLOCKS` と警告付きで足す経路を消し、`final_unsafe` を常に返す。
- 付け根を守る代わりに入口で断る入力が増えることは問題ない、とした。検証の荷重について(原文):

> 500Nって50kgだからPETGで受けられる重さでは到底ない。いままでそれだけの高荷重で検証をしてきたのがそもそも間違いだった。

- 入口で断るとき、探索を始められる荷重を示す(本人の指示「限界荷重をことわる修正をいれ」)。全材料が安全率だけで落ちたら、
  上限 = 今の荷重の大きさの合計 × 全材料の安全率 ÷ 探索の目標(応力は荷重に比例する)を文面と `full_material_limit_load` に返す
  (cb63622)。他の検査も落ちた全材料・計算失敗・荷重 0 では出さない。
- 完成形検査の物差しを替える。Claude が測る細かさの決め方の選択肢を示し(α: 測る間隔を物理寸法 0.67 mm に固定して
  面積 4 mm² の上位値で判定する、ほか)、本人は α を選んで次を足した(原文):

> αを選びつつ、大きな部品で測れなかった場合は、細かさを少し犠牲にして一応測りはする、というのはどう？

  Claude は条件として「粗く測った値は低く出るので、間隔の比の 0.41 乗を掛けてから目標と比べる」「要素数の上限を空きメモリから
  決める」を返し、本人は「実装開始。」と応じた。実装した値は 4-11 の割り増しの指数 0.42(Claude が示した 0.41 は実測の最大
  0.412 を丸めた値で、覆うには切り上げが要る)・面積 4 mm²・間隔 0.67 mm(`final_check.MEASURE_SPACING_MM` ほか)。
  0.67 mm で測った値を定義とする物差しで、さらに細かく測れば上がる(dilution 300N は 0.67 mm で 17.6 MPa、0.33 mm では
  目標の 20 MPa を超えた。4-11)。
- 完成形検査を割ったときの出し方。hanger 180N が割って何も足されなかった(4-12)のを受けて、本人(原文):

> 不合格のときになにも出てこないのは困るので、最後に合格だったステップを出す、とかにできないだろうか？合格がでるまで1つずつさかのぼるような感じで。あるいは割り増しを切ったことの警告付きで出した方がいい気がするな。

  Claude は前者(A: 合格するまでさかのぼる)を勧め、後者(B: 割り増し込みで割った形を警告付きで出す)には、割り増し前に
  合格していても安全とは言えないとして反対した。1つずつ戻る代わりに「完成形 ÷ 探索」の安全率の比で一気に戻り、だめなら
  二分で戻る形を提案し、本人は「Aを実装して」と応じた。実装は `topopt.complete.backtrack`(探索は合格形を
  `SearchResult.accepted` に1ビット詰めで持つ)。検査の回数の上限 `MAX_BACKTRACK_CHECKS = 5` は置いた値。
- hanger 180N で、さかのぼりは 49 手戻した形で合格したが、完成形検査が1回約 20 分で全体 2.8 時間かかった(4-14)。Claude が
  「A: 組み立てない解法を GPU でも動かす」「B: 通った後の二分を、得が小さければやめる(材料の差 3% 未満)」「C: 検査の上限を減らす」を挙げて
  A と B を勧め、本人は「A, Bをいれて」と応じた(4-15)。
- 残課題の整理(2026-10-12)。検証の荷重は本人が候補に挙げた 60・120・180N で、その選び直しを完了とした。Claude が推奨順の2に
  挙げた「粗く測ったときの割り増しを、間隔の比 2.5 より粗い所まで実測する」には、本人は「2はやらないことにする」とした
  (比 2.5 より粗い所は 4-11 の指数 0.42 の延長のまま)。
