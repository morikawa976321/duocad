# 形状最適化 — 反力の内訳と、各取付点に下限を課す制約

**この文書の役割:** 「全ての取付点(拘束面)が実際に荷重を受け持つ」を制約として入れた実装の
**根拠と実測**。ε(各取付点が受け持つ最低割合)がどこまで効くのか、効いたときの代償はいくらか、
**どこでは効かないのか**を数字で置く。

| 何が | どこにあるか |

| 随伴の式と、なぜ「グループ数−1本」で済まないか | `duocad/topopt/simp.py` の `reaction_sensitivity` docstring |
| 更新則 OC と MMA の比較(制約を足す前) | [TOPOPT_MMA_VS_OC.md](TOPOPT_MMA_VS_OC.md) |
| **生データ** | `duocad/topopt/output/reaction_constraint.json`(段ごとに `stages` へ積む) |
| **計測スクリプト** | `topopt_checks/measure_reaction_constraint.py`(`--model` で models/*.json を指定) |
| **回帰検査** | `topopt_checks/check_simp.py` の [7][8][9] |

## 結論(先に)

1. **反力の下限は「ε をいくつにするか」より「掛けるかどうか」が効く。** 制約が無いと
   荷重から遠い拘束面は反力が**厳密にゼロ**になる(合成題材で 4.5e-11)。ε を掛けると
   その面はきっかり ε だけ受け持つようになる(0.02→0.0200 / 0.10→0.1000 / 0.50→0.5000)。
   **どんなに小さい ε でも荷重経路は1本できる**ので、「保持ソリッドが残る最小の ε」は
   実質「0より大きければよい」である。
2. **代償は ε に強く効く。** 同じ合成題材で、コンプライアンスは ε=0.02 で +234%、
   ε=0.10 で +1116%、ε=0.50 で +20169%。**下限は「繋げる」ためのものであって、
   荷重を配り直すためのものではない。** ε を上げると材料を無駄に配る。
3. **hanger では制約が効かない(2026-09-11 実測)。** `hanger_test` は**本番の作業解像度
   2.412mm でも**3枚とも 0.98/0.98/1.92 を受け持ち、保持ソリッド4つは全要素が残る。
   `hanger_bar_attachment` も粗い格子で 0.84/0.84/1.67。**ε=0.10 を実際に掛けても
   出てくる形は同じ**(コンプライアンスの相対差 1.1e-10・反力6桁一致)。
   **ただしタダではない —— 同じ答えに 2.36倍の時間を払う**(実測3)。
4. **推奨する既定は ε=0.10。** 健全な設計が自然に出す最小の割合(実測 0.84)の 8分の1 で、
   健全な設計には触らない。かつ「荷重の1割も受け持たない取付点は飾り」と言える大きさである。
   **2 の代償が出るのは制約が効く場だけ**で、そこでは払わなければ取付点が結果から消える
   —— つまり払うのが正しい。**ε を上げてよい理由にはならない**(上げるほど無駄が増える)。
   **ただし「常に掛ける」は勧めない** —— 3 のとおり効かない題材でも 2.36倍を払う。
   反力の内訳は制約なしでも出るので、**先に内訳を見て 0 に近い取付点があるときに掛ける。**
   **この口はまだ既定で有効になっていない**(`reaction_min=None`)—— 既定を倒すのは
   taskbox `20260910-1315` の担当。

## なぜ反力か

「3点すべてで留まる」は**構造要求ではなく取付(インタフェース)要求**である。構造最適化は
定義上、荷重を運ばない材料を置かない。荷重の与え方を変えても表現できない。

反力を選ぶ利点は2つ:

- **新しい順問題が要らない。** 反力はいま解いている `K u = f` から直接出る
  (`R = (K u − f)|_fixed`)。仮想温度法のような架空の場を足さずに済む
- **物理的に意味のある量**なので、切れている取付点を「反力ゼロ」として名指しできる

## 大きさで測る。等式にはしない

反力はベクトルである。面の向きがばらばらだと、釣り合いを満たしたまま**大きさを揃えられる
保証がない** —— 実現不可能な制約は「妥協した設計」ではなく失敗を返すので、等式は採らない。
課すのは下限 `|R_i| >= ε |F|` だけである。

**`fraction` の合計は 1 にならない。** 全グループの反力**ベクトル**の和は荷重の合力の符号を
反転したものになる(剛体並進が K の零空間にあることから従う)が、**大きさの和はそれ以上に
なる** —— 取付点どうしが引き合っていれば打ち消し合うぶんが乗る。hanger では3枚の合計が
3.85〜3.88 になる(下の表)。**「合計が1になるはず」と思って読むと必ず間違える。**

## 費用 —— 随伴はグループ数ぶん要る

反力は自己随伴ではない。コンプライアンスが追加の線形解なしで感度を作れるのは
「目的が `f^T u` で、随伴の右辺が荷重そのもの」という特殊事情である。

**「全体の釣り合い Σ R = −F があるからグループ数−1本でよい」は、大きさには効かない。**
一定なのは合力**ベクトル**の和であって大きさの和ではないので、最後の1本の勾配を他から
作るには各グループの3成分ヤコビアン(3(n−1) 本)が要り、n 本より多くなる。**n 本解く。**

順問題と随伴は `Model.prepare` が返す同じ `PreparedSystem` を使うので、**多重格子の setup は
1反復に1回のまま**で、増えるのは CG の反復ぶんだけである。随伴は前の反復の解で
ウォームスタートする。**hanger_test 2.412mm の3グループで実測 2.36倍**(線形解は4倍、
CG反復の合計は2.88倍。実測3)。

## 実測1: 制約が効く場(合成題材)

**両端の壁を固定し、片方の壁のすぐそば(3要素)に荷重を載せた 40x8x8 の箱。** 遠いほうの壁は
構造上いらないので、制約が無ければ最適化はそこへ材料を1つも置かない。**hanger で保持
ソリッドが浮き島になって消えるのと同じ理屈を、秒で回せる大きさに落としたもの。**
材料は容量の 15%・40反復・`update="mma"`・`threads=1`。生データは JSON の
`far-wall-40x8x8` 段の過去の測定。比較用 `--far-wall` は削除済み。二つの壁のモデルは回帰検査に残す。

| ε | 遠い壁の受け持ち | コンプライアンス | 悪化率 |
|---|---|---|---|
| 制約なし | **4.5e-11** | 0.158193 | — |
| 0.02 | 0.0200 | 0.528602 | +234% |
| 0.05 | 0.0500 | 0.972543 | +515% |
| 0.10 | 0.1000 | 1.923474 | +1116% |
| 0.20 | 0.2001 | 7.676263 | +4752% |
| 0.35 | 0.3501 | 10.723757 | +6679% |
| 0.50 | 0.5000 | 32.064126 | +20169% |
| 0.70 | 0.7014 | 56.706145 | +35746% |

読み方:

- **制約は常に**きっかり境界に乗る(下振れは1件も無い)。超過は **`fraction/ε − 1` で
  4.6e-05〜2.1e-03**(絶対差 `fraction − ε` なら 1.4e-05〜1.4e-03。**割るか引くかで桁が
  1つずれるので、どちらの量かを書かずに引用しない**)。`REACTION_TOLERANCE` は
  `floor = ε(1 − TOL)` と**割る側で効く**ので、比べるべきは前者である。0.02 に対して
  4桁小さく、**制約を掛けた7件で1度も使われていない。**
- **悪化率が極端なのは題材が極端だから。** 遠い壁は 37 要素先にあり、材料は容量の 15% しか
  ない —— そこへ部材を1本通すこと自体が高い。**hanger のように取付点が全部使われている
  設計では、同じ ε が何の代償も生まない**(次節)。
- この題材は `check_simp.py` の [9] が回帰として固定している(制約なしで遠い壁の反力が
  0.01 未満 / ε=0.20 で 0.20 以上 / コンプライアンスが悪化する、の3点)。

## 実測2: hanger では制約が効かない

**制約なしで、3枚の拘束面が全部しっかり荷重を受け持っている。** 保持ソリッドも全部残る。
40反復・`threads=7`。生データは JSON の `hanger_test-5.3mm-0.3` などの段。

| 題材 | 要素サイズ | 塊 | 材料 | 更新則 | 面11 | 面3 | 面19 | 保持ソリッドの生存 |
|---|---|---|---|---|---|---|---|---|
| hanger_test | 5.319mm | 30,943 | 10% | oc | 0.993 | 0.993 | 1.895 | 4/4(全要素) |
| hanger_test | 5.319mm | 30,943 | 30% | oc | 0.973 | 0.973 | 1.903 | 4/4(全要素) |
| hanger_test | 3.989mm | 73,174 | 10% | oc | 0.978 | 0.978 | 1.908 | 4/4(全要素) |
| hanger_test | 3.989mm | 73,174 | 30% | oc | 0.984 | 0.984 | 1.927 | 4/4(全要素) |
| hanger_test | **2.412mm(本番の作業解像度)** | 322,384 | 30% | mma | **0.979** | **0.979** | **1.917** | **4/4(全要素)** |

**面11 と 面3 の値が一致しているのは題材が左右対称だから**で、丸めの偶然ではない。

### タスクの前提は `hanger_test` では成り立たない

このタスク(taskbox `20260910-1314`)は「制約なしでは1枚に集中し、残り2枚の保持ソリッドが
浮き島になって `mesh.remove_islands` に消える」を前提に立てられていた。**その前提は
`hanger_test` では成り立たない** —— 上の表のとおり、本番の作業解像度(2.412mm)でも
3枚とも 0.98/0.98/1.92 を受け持ち、保持ソリッド4つは**全要素が**結果メッシュに残る。
40反復・`threads=7` で 1331秒(`update="mma"`)。**既定の `update="oc"` でも同じ**で、
同じ条件で 1320秒 / C=0.608170 / 0.981・0.981・1.917 / 4つとも全要素だった
(**この1件だけ JSON に無い** —— 取り直すなら `--update oc --eps none`)
—— 病理の有無は更新則ではなく題材で決まる。

元の観測(2026-09-10)は **`hanger_bar_attachment` を 2.4mm で完走させたとき、保持 `_1`
(x -36.1〜-18.9)と `_2`(x 18.9〜36.1)が結果に入らなかった**というものである。
`hanger_test` は同じ部品・同じ条件構成のまま**部品を密集させて外接直方体を小さくした**
題材なので、取付点と荷重の距離関係が違う。**「同じ部品だから同じ病理が出る」とは限らない。**

したがって:

- **ε の下限(「3枚とも残る最小の ε」)は hanger_test では測れない。** 制約が1度も
  効かないので、どの ε でも同じ形が出る。上の合成題材で測ったのはそのためである。
- **反力の可視化(制約なしでも出る内訳)のほうが、この題材では価値がある。**
  `optimize_run.run` の応答に `"reactions"` が載るので、**病理が起きている題材では
  それが `fraction ≈ 0` として即座に見える。**

## 実測3: 本番解像度で ε=0.10 を掛けた費用(2026-09-11)

`hanger_test` 2.412mm・材料30%・40反復・`update="mma"`・`threads=7` を、制約なし / ε=0.10 で
同じ更新則のまま並べた(JSON の `hanger_test-2.4mm-0.3` 段)。

| | 秒 | 秒/反復(中央) | 線形解の本数 | CG反復の合計 | コンプライアンス | 面11 / 面3 / 面19 |
|---|---|---|---|---|---|---|
| 制約なし | 1331 | 28.59 | 40 | 5,147 | 0.608216967743 | 0.979384 / 0.979384 / 1.916906 |
| ε=0.10 | 3143 | 67.66 | 160 | 14,814 | 0.608216967678 | 0.979384 / 0.979384 / 1.916906 |

- **答えは同じ。** コンプライアンスの相対差は 1.1e-10、反力は6桁一致、保持ソリッド4つは
  どちらも全要素が残る、三角形数も 40,840 で同じ。**制約が最適点で不活性**(0.979 ≫ 0.10)
  なのだから当然そうなるべきで、そうならなければ実装が疑わしい。
- **費用は 2.36倍。** 線形解は 40 → 160(順問題1 + 随伴3 が毎反復)、CG の反復合計は 2.88倍。
  **多重格子の setup は反復あたり1回のままなので、4倍にはならない。**
- **峰メモリは 7.8GB**(制約なしと同じ。随伴は `PreparedSystem` を共有し、増えるのは
  グループ数ぶんのベクトルだけ)。
- **したがって「効くかどうか分からないから念のため掛ける」は 2.36倍を払う判断になる。**
  反力の内訳は制約なしでも出るので、**まず内訳を見て、0 に近い取付点があるときだけ掛ける**
  のが安い。既定を倒す判断(taskbox `20260910-1315`)はこの倍率の上でする。

## 満たせなかったときの落ち方

`simp.ReactionTargetError`(`ValueError` 派生)。属性に `required`(要求した ε)・
`reactions`(最後に測った内訳)・**`result`(そこまでで出た `Result`)**を持つ。
30分回した結果を見ずに捨てさせないために付けてある。

**支持配置によっては原理的に満たせない。** 静定な配置では反力の配り方が幾何だけで決まり、
構造をどう変えても動かせない(hanger は面ごとに多数の節点を固定するので不静定だが、
一般には成り立たない)。そこへ下限を課したときに返すべきなのは「妥協した設計」ではなく
**失敗**である。

判定は**最後に解いた密度場の実際の反力**で行う(近似した制約値ではない)。
MMA の部分問題は Svanberg の人工変数(`MMA_CONSTRAINT_PENALTY`)で常に解けるようにして
あるので、途中の反復では制約を破ってよい —— 破ったまま終わったかどうかだけを見る。
