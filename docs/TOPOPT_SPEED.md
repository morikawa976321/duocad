## 1回のFEM評価(assemble + multigrid CG)の内訳

**この節は `solver="mg"` での内訳(SIMP 時代の実測)。mg は 2026-09-21 に削除し、探索は cg で解く**
(`mg_setup` の段は今は無い。cg での反復数・秒・メモリは下「探索が解く形での cg と mg」)。

探索は候補ごとに1回、固定した格子上でFEM(`fem.py`)を解く。組立・
multigrid setup・CG/V-cycleの内訳は、SIMP時代に測った下記の実測が**アーキテクチャとして
今も同じ**(fem.pyの組立・CG・multigridの実装自体は段階6でも変えていない)。

**環境:** hanger(`hanger_bar_attachment.json`)・要素サイズ2.4mm・格子78×138×109 =
1,173,276箱要素(点群の外接箱+余白の外枠。固定凸包でも格子の外枠は同じ)・
`solver="mg"`・`cg_rtol=1e-9`。案1の全塊(active 1,096,894要素。2026-09-09実測)での
`collect_solve_stats`によるsolve 1回あたりの内訳:

| 項目 | 秒/solve | 比率(solve内) |
|---|---|---|
| `assemble`(K 組立) | 48.1 | 16% |
| `slice`(自由 DOF 切出) | 3.2 | 1% |
| **`mg_setup`(RAP + 最粗 LU)** | **24.3** | **8%** |
| **CG / V-cycle** | **242.0** | **75%** |
| CG 反復数 | 161〜306(平均 234) | 密度が二値に寄ると増える |

**塊(active要素)を7.6倍にすると1solveの秒数は2.7倍**(線形には伸びない)。理由は2つ:
格子サイズ(組立・フィルタの対象)は材料量と無関係に常に全箱要素で、密度フィルタ・組立は
塊が小さくても格子全体を走査する。加えて自由度の桁も縮まない(塊が小さくても`extra_fixed_dofs`
で拘束に回るだけで、自由DOFの桁は縮まらない)。**`mg_setup`は密度が変わるたびに毎回組み直しが
必要で、並列化できない。**

上記のうち、SIMP時代固有だった「体積制約OCの二分探索が`_physical()`を繰り返す」内訳
(反復あたり数秒〜数十秒)は、**現在の候補評価には無い**(1候補=1FEM解であって、
内側にOC/MMAの反復は無い)。したがって1候補あたりの費用は概ね上表のassemble+mg_setup+CGの
合計に近いはずだが、**未実測**。

## 保持・除外の判定を前計算にした(2026-09-19)

**何が遅かったか。** 候補ごとの保持・除外の判定(`acceptance.region_check`)は、材料マスクを直方体列へ融着して
CADソリッドとのブーリアンを毎回取っていた(`intersection_volume`)。hanger 2.4mm(格子69×129×100、設計空間
367,390セル)で、保持ソリッドの外接箱にかかるセル3,021個だけの細い形でも **15.6秒**、設計空間の全部で
**19.6秒**(保持4本+除外8本)。探索は同じ格子・同じソリッドを何百回も判定するので、この費用が候補の数だけ乗っていた。

**どうしたか。** 格子 × ソリッドの組ごとに「セルごとの重なり体積 [mm³]」を1回だけ求めて持ち、以後の判定を
`overlap[mask].sum()` の足し算にした(`acceptance.RegionOverlaps`)。重なり体積はセル中心近似ではなく、セルと
ソリッドの共通体積そのもの(境界のセルは部分的な重なりを持つ)。**候補1件あたりの判定は 0.13〜0.8ミリ秒**。

| 項目 | 置き場・寿命 |
|---|---|
| 持つ者 | `binary_search.SearchConditions.region_overlaps`(既定は新しい `RegionOverlaps`)。探索1回が1つ持ち、探索が終われば捨てる。`optimize_run._build_search_conditions` は何も足さない |
| 鍵 | ソリッドの同一性(`kernel.shape_key` = TShape・Location・Orientation)+ 格子の原点・間隔・形。**入力が変われば別の項目になるので、古い値は読まれない**。文書を編集するとソリッドは別物になるので探索をまたいで持ち越さない |
| 計算のタイミング | 遅延。材料マスクに現れたセルを含む8セル角の塊(`acceptance.TILE_CELLS`)だけ、その塊のセルをまとめて求める。設計空間に掛からない塊は一度も計算しない |
| メモリ | 外接箱と格子の共通部分のセル数 × 8 byte(ソリッドごと) |
| 使わない経路 | `bbox_cache=None` を明示した再検査(`inspect_kwargs(bbox_cache=None)`)は前計算も外し、旧経路のブーリアンで取り直す。過去記録を読む `inspect_document` も旧経路 |

**採用形状は旧経路で取り直す。** 段階4の評価は前計算から引く(段階3の最終再検査は今までどおりキャッシュ無しで、旧経路)。
段階4を出るとき、採用形状の保持・除外だけを旧経路のブーリアンで取り直し(`_recheck_regions_without_precompute`)、
通れば報告の保持・除外欄をその値へ差し替える。通らなければ段階3で再検査済みの形へ戻して `evaluation_error`。
1探索あたり旧経路の1回分(2.4mmで約16〜20秒、4.8mmで約5秒)が増える。キャンセル時も走る。

**前計算が作れない・途中で失敗したソリッドは、そのソリッドだけ旧経路へ戻す**(`RegionOverlaps.fallbacks` に理由)。
前計算は速さのためだけにあり、旧経路と同じ答えを返せないなら使わない。hanger の12本は4.8mm・2.4mmとも戻らなかった。

### セルごとにブーリアンを取ってはいけない(実測の罠)

最初の実装はセルごとに `BOPAlgo_BOP` の共通を取った。**hanger を4.8mmで切ると、格子の面(x=0)が円板ソリッド
(体積1048mm³)の継ぎ目に0.05µmまで近づき、セル単位のブーリアンが「共通部分が空」という誤った答えを
エラーも警告も出さずに返して、合計が1030.58mm³(17.4mm³ = 1.6%)しかなかった。** 面が形状に近づいたときの失敗は
1e-14の座標の違いで出たり消えたりする(再現が不安定)。旧経路は材料の連なり(x方向の連続部分)をまとめて取るので、
連なりの端がその面に来たときだけ同じ形で落とす(実測: 設計空間の無作為10%の候補で、この円板の
重なりを5.59mm³落とし、前計算のほうが正しかった)。

そこで前計算は「ソリッドを平面で切って、破片を重心のあるセルへ振り分ける」方式にした(`kernel.grid_cell_common_volumes`):
塊の6面で切って塊の中の破片を取り(空・全部の判定)、境界にかかる塊だけをセルの面で切り分ける。
曲面との交線をセルごとに計算し直さないので速い(曲面のソリッドの364セルの塊: セルごとのブーリアン約30秒 →
平面で切って約1秒)。ただし平面で切る方法も、塊の面が継ぎ目に近づくと体積を落とす(2セル角の塊で円板の1.4%。
塊をブーリアンで取る方法は20%)。**塊の中の体積を「切る方法」と「ブーリアン」の2通りで求めて突き合わせ、
食い違えば失敗(=そのソリッドを旧経路へ戻す)にした**。落とし方が違うので食い違いで見つかる。
もう1つ、破片の振り分けは重心で行うので、切る平面を形状の端まで届かせる必要がある(届かないと、塊の外の
残り全部が1つの破片につながり、その重心が塊の中に落ちて 2,960万mm³ 余計に数えた)。

### 実測(hanger、`topopt_checks/measure_region_overlaps.py`、2026-09-19)

| 要素サイズ | 格子 | 前計算(12本、設計空間を1回)| 前計算メモリ | 候補1件の判定 旧 → 新 |

| 4.8mm | 36×66×52 | **12.4秒**(塊55個) | 0.19MB | 4.3〜5.2秒 → **0.13ミリ秒**(中央値。最大1.0) |
| 2.4mm | 69×129×100 | **50.0秒**(塊161個。再測定で57.9秒) | 1.25MB | 15.6〜19.6秒 → **0.4ミリ秒**(中央値。最大は測るたびに0.5〜1.6) |

2.4mmの内訳(前計算50秒): 箱状の巨大な除外ソリッド(853×50×695mm)29.7秒、長さ500mmの円筒の除外10.3秒、曲がった保持バー6.3秒、他9本で3.7秒。
旧の範囲はマスクによる(保持だけの3,021セル 15.6秒、設計空間全部 19.6秒)。**旧経路の費用は保持ソリッドの外接箱にかかる
材料の連なりの数で決まり、材料が少なくても保持を残す限り下がらない**(3,021セルで15.6秒。依頼時の実測13.7秒と同じ水準)。新の判定はマスクの大きさに

**合否と体積の一致。** 3種の候補(保持だけ/保持+無作為10%/設計空間全部)× 保持・除外全12本で、`region_check` の
`status`・`rule` は全部一致。体積は、平面のソリッド(箱)では 1e-11〜1e-14 mm³ で一致するが、**曲面の保持ソリッドでは
最大 1.2e-4 mm³(相対 3.7e-8)ずれ、24行のうち8行で `region_check` の数値許容差(`max(1e-9, 1e-9×体積)`)を超える**
(4.8mm・2.4mmとも同じ8行。許容差の最大62倍)。**原因は前計算ではなくブーリアンの体積積分の桁**: 材料を無作為に2つに分けて
旧経路で足し合わせると、全体との差(体積は加法的なので0のはず)が旧経路自身で許容差の34倍(4.8mm)・282倍(2.4mm)

判定(`measured > tolerance`)は保持・除外とも1e3〜1e4 mm³ の量を許容差(1e-6〜3e-4)と比べるので、この差で合否は動かない。
これに合わせて新旧一致のテストは、平面と単純な曲面を許容差以内で、hanger は相対1e-6で比べる(`tests/test_region_overlaps.py`)。

**既知の残リスク。** 破片は重心でセルへ振り分けるので、平面がある破片を切り損ねた(複数セルにまたがったまま残った)とき、その体積がセルの体積を超えれば拒否(`_FULL_CELL_LIMIT`)、塊の合計と合わなければ拒否されるが、**セルの体積より小さい破片が切れずに残った場合は、合計が合うので通り、マスクが跨ぐセルの一部だけを含むときの値が旧経路とずれうる**。実測(hanger 12本×2格子)では起きていない。採用形状は旧経路で取り直すので、最終結果の合否には影響しないが、探索の途中の判定はずれうる。

## 自由度の集合演算をブール配列にした(2026-09-19)

**何が遅かったか。** `fem.Model` は候補ごとに作り直す。その `__init__` が
`np.union1d(拘束, 空要素の拘束)` と `np.setdiff1d(np.arange(ndof), 拘束)` で自由な自由度を出していた。
どちらも ndof 長の整列を伴うので、格子が細かいほど**材料の量と無関係に**高くつく。

**どうしたか。** ndof 長のブール配列で同じ配列(整列済み・重複なし)を作る。番号が `[0, ndof)` にあることは
既に検査しているので、そのまま添字に使える。**数値も挙動も変わらない**(`tests/test_fem_dofs.py` が
旧実装の集合演算と同じ配列であることを固定する)。

| 格子 | ndof | 候補1件あたり 旧 → 新 |
|---|---|---|
| hanger 4.8mm(36×66×52) | 394,161 | 283ミリ秒 → **1.9ミリ秒** |
| hanger 2.4mm(69×129×100) | 2,757,300 | 4,075ミリ秒 → **18.5ミリ秒** |

`fem.Model` の生成そのものは、hanger 2.4mm・材料3,535セルで **7.43秒 → 0.45秒**(残りは `_build_edof` 0.55秒
〈85.4MB〉などの格子比例の処理)。段階4は候補ごとにこれを通るので、2.4mm で35回解く探索なら約2.4分が消える。
**細かい格子ほど効く**: ndof は要素サイズの3乗に反比例するので、1mm 相当(ndof 約3,700万)では旧経路の
集合演算だけで候補1件あたり分の桁になる。

**残っている大きい費用は CG の反復そのもの**(hanger 2.4mm・材料3,535セル・自由DOF 21,825 で solve 8〜15秒。
組み立て0.05秒・自由DOFへの切り出し0.02秒なので、行列の作りではなく反復回数)。**ここは数値の話**(前処理・解法の
選び方)なので、上のような無害な置き換えでは減らない。

## 前の形の変位をCGの初期値にすると効くか(2026-09-19)

測定時の `peel` は内部のセルも抜けた(`surface_only=False`)。2026-09-20 に内部を抜く経路を削除したが、**この測定の値は変わらない**(旧コードで `surface_only` を True にしても全点が同一。1セルの 0.02 の理由は節「旧測定の1セル 0.02 が今と食い違う理由」)。**下の表と、その下の「効き方を決めるのは割合」という読みは旧 `peel` のもの。** 今の `peel` で測り直した値は末尾の小節「削るセル数 k ごとの効き(2026-09-21)」にあり、1セルの比は(大の親で)0.02 / 0.01 でなく 0.8〜0.9 に変わり、効きは割合では揃わず、親の形で大きく変わる。

段階4は合格形状から少しずつ削るので、前の形の変位は次の候補の初期値になりうる
(`Model.solve(u0=)` の口は前からあるが、探索は渡していない)。hanger で測った。

**測り方**: 初期形状は 4.8mm の採用形状(488セル)を各格子へ写し、条件節点に接する設計空間セルを
足したもの —— 写したままだと `fixed_face_23` の18節点中14個が支えられず `resolve_islands` が
全部落とす(粗い格子の形は細かい格子の条件節点を掴めない)。2.4mm で 4,173セル・2.0mm で
7,277セル(実測の採用形状は 2.4mm で 4,178セル)。そこから `peel` で削った形を、初期値0(cold)と
前の形の変位(warm)の両方で解く。`solver='cg'`(探索の既定)・`cg_rtol=1e-9`。
再現は `topopt_checks/measure_warm_start.py`。

| 格子(初期形状) | 削る幅 | 削ったセル | cold 反復 | cold 秒 | warm 反復 | warm 秒 | 反復比 |
|---|---|---|---|---|---|---|---|
| 4.8mm(588) | 1セル | 1 | 6,101 | 1.7 | 5,359 | 1.6 | 0.88 |
| | 20% | 117 | 6,417 | 1.9 | 6,547 | 1.9 | 1.02 |
| 2.4mm(4,173) | 1セル | 1 | 12,175 | 12.3 | **229** | **0.4** | **0.02** |
| | 1% | 41 | 12,083 | 15.2 | 9,935 | 11.7 | 0.82 |
| | 5% | 208 | 12,296 | 9.3 | 10,811 | 9.9 | 0.88 |
| | 20% | 834 | 13,623 | 14.4 | 13,708 | 13.2 | 1.01 |
| 2.0mm(7,277) | 1セル | 1 | 15,376 | 20.0 | **193** | **0.5** | **0.01** |
| | 1% | 72 | 15,127 | 24.2 | 12,483 | 18.4 | 0.83 |
| | 5% | 363 | 15,659 | 24.4 | 13,722 | 17.0 | 0.88 |
| | 20% | 1,455 | 15,464 | 21.7 | 14,843 | 15.2 | 0.96 |

1セルずつ連続して削り、そのつど前の解を渡しても比は保たれる(2.4mm: 0.02/0.02/0.02、
2.0mm: 0.01/0.01/0.01)。

**効き方を決めるのは「削ったセルが全体に占める割合」**。warm の反復数は格子にほぼ依らず
(2.4mm 229・2.0mm 193)、cold は格子が細かいほど増える(4.8mm 6,101 → 2.4mm 12,175 →
2.0mm 15,376)ので、細かい格子ほど比が下がる。4.8mm が 0.88 にとどまるのは初期形状が588セルで
1セルが全体の 0.17% を占めるため(2.4mm では 0.024%)。**細かい格子ほど効く。**
20%(`max_step_ratio` の上限)削ると効果は無い。

**答えは変わらない**: cold と warm の変位の最大相対差は1セルで 1.6e-11(2.4mm)・3.4e-12(2.0mm)、
20%削る場合でも 1e-9 台。CG の収束判定は右辺のノルム基準(`rtol`)なので、初期値を変えても
到達する精度は同じ。

秒は他の実行と競合した値(反復数は決定的)。

**段階4へ通した(2026-09-20、`0f1b0f0`)**: `u0` を `acceptance.inspect` → `safety_check` →
`stress.solve_displacement` → `Model.solve(u0=)` へ通し、解いた変位を `fields['displacement']`
(`element_energy` と同じ口)で返して `FeasibleModel.displacement` に1本だけ持たせる。
`find_best_feasible(..., warm_start=...)` で切り替える(**既定は False**。下の実測で cold と採用形状が一致しなかったため)。段階3には配線していない(上の表: ブロック単位の削除では効かない)。
`u0` は**格子全体の自由度(ndof)で渡す**(`PreparedSystem.solve` が `u0[model.free]` と読むので、
評価ごとに拘束が変わっても対応する)。形・型・非有限が合わない `u0` は例外にせず cold に落とし、
落ちた回数は `diagnostics['reduction']['warm_start_fallbacks']`(使えた回数は `warm_start_used`)。

### 旧測定の1セル 0.02 が今と食い違う理由(2026-09-21)

**結論: `peel` の変更が原因ではない。旧測定の親は、探索(エネルギー順の削減)を経ていない「写しただけの形」で、エネルギーがほぼ 0 のセルを少数持っていた。
それを1セルずつ削る最初の約8手だけ比が 0.02 になり、その在庫が尽きると比は約 0.8 に上がる。** 旧測定の連鎖は 3〜5 手で、0.02 の区間だけを見ていた。
以前の記録にあった「旧 `peel` が内部のセルも抜いたため」という推定は、旧コードで回し直して否定した。

**1. 旧測定は旧コードで再現し、`surface_only` を変えても値は変わらない。** 旧コード(`4cd9fdb` = `86a1e7b` の直前。`git archive` で展開)・旧マスク

### 実探索の軌道での初期残差 r0(2026-09-21、`topopt_checks/measure_warm_start_residual.py`)

上の小節の限界(「実際の探索が通る親での初期残差は未測定」)を測った。段階4の warm start を「r0 が小さい候補だけ」に絞る案(案b)を作る価値があるかの**材料であり、判断はしない**
(削減率がいくらなら十分かは本人が決める)。r0 = ‖f − K候補·u親‖ / ‖f‖(自由な自由度。cold の初期値 0 では 1)。

**測ったコードと方式**: 製品の既定(cold・目標 2.0・最小幅 m=1・`solver='cg'`)で `find_best_feasible` を hanger の 2.4mm・2.0mm で回し、**段階4の評価が 150 回に達したところで止めた**
(時間上限 2.4mm 150分・2.0mm 210分は、どちらも先に評価数の上限に達して当たっていない)。コードは develop の `0a9ddc7`(`git archive HEAD duocad topopt_checks` で展開し、測定スクリプトだけ重ねた。
`--head` は記録用で、実行したソースは検証しない)。スクリプトは実行時に `PreparedSystem.solve`・`peel`・`_evaluate_survivor`・`_geometry_rejection_trial`・`_reduce_volume` を包むだけで、`duocad/` は書き換えない。
r0 は候補の cold の solve の直前に出す。親の変位 = 直前に**採用された**評価の解(`_reduce_volume` と同じ条件)で、段階4の最初の評価は親の変位が無いので r0 なし。
**副測定**(軌道に影響させない): 候補が 50,000 セル以下の評価のうち、r0 < 0.1 は全部、それ以外は 5 回に 1 回(該当する評価を数えて最初の1回から)、同じ候補を u0 = 親の変位で解き直した(解は捨てる。cold の値は実際の solve のもの)。

### 判断の材料(判断はしない)

- `cg_rtol` を 1e-7 へ緩めて得られるのは、測った3つの形で反復の 1.7〜4.6%。合否が変わるほどの誤差は出ない(上の2つの表)が、
  探索の軌道は 1e-13 の差でも分かれるので(warm start の節)、緩めれば採用形状は今の記録と一致しなくなる。
- 6,000 セル未満の評価の solve を直接解法へ替えると、150 評価の記録に当てはめて段階4の秒の約 34%(2.4mm。1,126 秒 → 132 評価 × 約 0.3 秒)が消える**見込み**
  (推定。探索を直接解法で通した測定はしていない)。2.0mm の 6,000 セル未満の形(自由度は 2.4mm より多い)の直接解法の秒は測っていない。
  評価 150 の打ち切りより先まで探索を回すほど、細い形の評価の割合は増える。
- 直接解法は初期値を使わないので、直接解法で解く評価では warm start は働かない(`acceptance.safety_check` の `unused:direct`)。
  warm start が残るのは cg で解く序盤の太い形だけで、そこは抜くセルが多く r0 ≥ 1(warm の反復比 0.97)の区間にあたる。
- 序盤の太い形には、削除前の mg が秒で 0.56〜0.65 倍だった(前の節。メモリは +1.9GB)。直接解法が効く細い形とは効く場所が逆。
- 解法を自由度で切り替える場合に決めること: 切り替える自由度(上の表では 5万自由度で 0.11 倍・+0.27GB、10万で 0.6 倍・+1.2GB)、
  採用形状が今の記録と一致しなくなること(cg と direct の変位は 1e-10 台で一致するが、探索は 1e-13 の差で分かれる)。
