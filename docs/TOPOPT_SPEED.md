## 背景：1回の「形状最適化実行」で何に時間が掛かるか

画面で実行ボタンを1回押すと `optimize_run.run()` が走る。重い部分はほぼすべて
**安全率 → 材料量の探索**（`safety_loop`）である。

```
optimize_run.run()
  ├─ 事前チェック（案1 bbox 導出・条件面・保持/除外） … 数秒未満
  ├─ safety_loop
  │    ├─ 参照 run（1回・10反復）           … 全体の ~4%
  │    └─ 材料量探索（典型6評価 × 40反復）   … 全体の ~96%
  └─ メッシュ化 + add_mesh_body              … 数秒未満
```

`estimate_seconds()` のモデル（`optimize_run.py`）:

- 1評価 ≒ `DEFAULT_MAX_ITER`(40) × 格子要素数 × 係数
- 参照 run ≒ `REFERENCE_MAX_ITER`(10) × 格子要素数 × 係数
- 典型合計 ≒ 参照 + 6 × 1評価（`TYPICAL_EVALUATIONS = 6`）

実測。**題材と要素サイズを必ず添えて読むこと** —— 比率（参照 ~4% / 探索 ~96%）は解像度に
依らないが、**秒数は解像度で1桁変わる**。

`hanger_bar_attachment.json` / **要素サイズ 5.333mm**（98,606要素）:

| 内訳 | 秒（目安） | 比率 |
|---|---|---|
| 参照 run（10反復） | 91.5 | ~4% |
| 6評価 × 本番 SIMP（40反復） | ~1,940 | ~96% |
| **合計** | ~2,030（34分） | 100% |

**本番の作業解像度は 2.4mm であり、そこでは合計が時間単位になる**（2026-09-10 実測）:

| 題材 / 要素サイズ | 箱内要素 | 1反復 | 峰メモリ | 探索1回（参照+8〜10評価） |
|---|---|---|---|---|
| `hanger_test` / **2.4mm**（検証用） | 322,384 | 45.5秒 | 8.3GB | **3〜5時間** |
| `hanger_bar_attachment` / 2.4mm | 1,096,894 | 159.8秒 | 26.1GB | **8時間級** |

**検証は `hanger_test` の 2.4mm を使う**（本人決定 2026-09-10。同じ部品を密集させたもので、
条件の構成は同一・箱が3.4倍小さい）。

1評価の中身（[TOPOPT.md](TOPOPT.md)「端から端まで1回の内訳」）:

| 段 | 割合 |
|---|---|
| `simp.optimize` | **99.5%** |
| `build_anchors` | 0.5% |
| marching cubes + Taubin | 0.01% |

**結論:** 短縮の主戦場は **探索の評価回数を減らす** ことと、**各評価の SIMP 反復数を減らす**
こと。mesh/STL・derive 単体の削減は副次。

## 現状の探索アルゴリズム

入口: `safety_loop.solve_for_safety_factor`（`duocad/topopt/safety_loop.py`）。

### 探しているもの

利用者入力は**目標安全率**。内部では**材料量[mm³]** を動かす。

> **目標安全率以上を満たす最小の材料量**（「ぴったり目標」ではない）

数学的には `f(m) = safety_factor(m) − target` について、括り `[material_min, material_max]` 内で
`f(m) ≥ 0` となる**最小の m** を求める。上端は `f(hi) ≥ 0` が保証される。

### 手順（現状）

1. **参照 run を1回**（連続値保持の ρ。探索全体で使い回す）
2. **上端 `material_max` を評価** —— 届かなければ `SafetyTargetError`
3. **下端 `material_min` を評価** —— ここで既に目標を満たせば **探索本体はスキップ**
4. **二分探索本体** —— `mid = (lo + hi) / 2` を繰り返し
   - `ok` かつ `sf ≥ target` → `hi = mid`、best 更新
   - `ok` かつ `sf < target` → `lo = mid`
   - `too_little` → `lo = mid`
   - `too_much` → `hi = mid`
5. 停止: `(hi − lo) / hi ≤ rel_tol`（既定 **0.08**）または `max_evaluations`（既定 **15**）

### 現状のパラメータ（[TOPOPT.md](TOPOPT.md)「収束条件と回数上限」）

| パラメータ | 既定 | 備考 |
|---|---|---|
| `rel_tol` | 0.08 | **技術的根拠は無い**。評価回数を2回減らすために選んだ（9→7回の実測） |
| `max_evaluations` | 15 | 境界2 + 二分。8% までなら典型6回で足りる余裕 |
| `DEFAULT_MAX_ITER` | 40 | 各評価の SIMP 反復数 |
| `REFERENCE_MAX_ITER` | 10 | 参照 run のみ |

### 前提と罠

- **材料量 ↑ → 安全率 ↑** を前提（単調性）。合成題材では実測済みだが**理論保証はない**
  （plate の頭打ち、非連結など —— [TOPOPT.md](TOPOPT.md)「単調性を測る」）。
- 評価後の **`safety_factor` は次候補の決定に使っていない**（区間の中点だけ見る）。
- 塊は材料量で離散化される（連続値保持）。`rel_tol` より細かく詰めても意味が薄い、という
  議論も [TOPOPT.md](TOPOPT.md) にある。

## 改善案 A：探索アルゴリズム（二分 → 括り付き補間）

### 動機

上端の安全率が目標の数百〜数千倍（bracket 実測で 5529 vs 目標 2.0 など）のとき、
**中点評価はまだ sf ≫ target** になり、高材料量の SIMP を無駄に回す。

評価ごとに `report.safety_factor` は取れているのに、**捨てている**。

### 推奨: Regula Falsi + Illinois ハイブリッド

**Regula Falsi（割線法）:** 括り `[lo, hi]` と両端の `(sf_lo, sf_hi)` から、
sf が target になる材料量を線形補間する。

```
m_next = lo + (hi − lo) × (target − sf_lo) / (sf_hi − sf_lo)
```

- 目標から遠い → **lo 側に大きく寄る**（二分より早く「軽い側」を探せる）
- 近い → **小さく動く**（細かく詰める）

**Illinois:** Regula Falsi で同じ端点だけが更新され続けるとき、
その側の sf を半分にずらして二分に近い挙動へ落とす（粘り対策）。

**ハイブリッド（実装案）:**

1. 端点2回評価は現状どおり
2. 以降 `m_next = illinois_propose(lo, sf_lo, hi, sf_hi, target)`
3. 次のいずれかなら **1回だけ二分** `(lo+hi)/2` にフォールバック:
   - `sf_hi − sf_lo` が極小（除算不安定）
   - `m_next` が `lo`/`hi` と実質同じ（再評価）
   - 履歴で同じ材料量を2回踏んだ（振動）
   - **`too_little` / `too_much` の直後** —— 括りは `lo=mid` / `hi=mid` で更新されるが sf は計測不能。
     古い `sf_lo` / `sf_hi` をそのまま補間に使うと **括りの外に提案が飛ぶ**。
     このステップは必ず二分に落とす。
4. 補間提案は **`[lo + 0.15×(hi−lo), lo + 0.85×(hi−lo)]` にクリップ**（上端 sf が目標の数百〜数千倍のとき、
   `lo` 極近傍への張り付きを緩和）。比率 15/85 は経験値で実測調整。
5. **`too_little` / `too_much` に擬似 sf（例: 0）を返して補間に使わない** —— 非連結境界で sf が
   不連続ジャンプし、補間が非連結側に引きずられる。
6. 停止条件は **`rel_tol` on 材料量幅を主**とする。加えて **Dual Criteria**（下記 B0'）を入れると
   ラスト 1〜2 評価を削れる。

### 採用しない: `too_little` / `too_much` でも安全率を返す

FEA が解けない（`DesignSpaceDisconnectedError`）か、体積目標に届かない（`VolumeTargetError`）評価に
擬似 sf を載せても、**単調性と物理対応が壊れる**だけ。例外分類して括りだけ更新する現行契約を維持する。

### 使わない方がよいもの

| 手法 | 理由 |
|---|---|
| ニュートン法 | `f'(m)` が無い。1評価 = フル SIMP |
| 括りなし secant | 範囲外・`too_much` 処理が崩れる |
| Brent 法 | 堅牢だが評価回数削減より安定性優先。ここでは得が薄い |

### 期待効果

| 状況 | 二分（典型） | Illinois 等 |
|---|---|---|
| 上端 sf ≫ target | 中点が高材料側に偏り無駄が多い | 初手から lo 寄り |
| 典型 bracket | **6〜7 評価** | **4〜5 評価** の可能性 |
| 非単調・頭打ち | 現状と同程度 | 振動しうる → フォールバック必須 |

全体（参照+探索）に換算: **1〜2 評価分 ≒ 15〜30% 短縮**が現実的上限感。

### 実装箇所

- 変更: `safety_loop.py` の `mid = 0.5 * (lo + hi)` ブロック
- 端点・各 `ok` 評価で `sf_lo` / `sf_hi` を保持
- 受入: `check_safety_loop.py` に「評価回数が減る／採用材料量・安全率が従来と同程度」を
  bracket 題材で確認

### オプション: log(m) 軸での補間

材料量と安全率の関係が指数っぽい題材では `log(m)` 上で線形補間する手もある。
まずは線形 Regula Falsi で足りることが多い —— 効果が足りなければ実測後に検討。

## 改善案 B：その他の短縮（探索段全体）

いずれも **未実装**（2026-09-09 時点）。実装順は末尾の「推奨実装順」を参照。

### B0. 事前境界クランプ（Smart Bounding）

| 項目 | 内容 |
|---|---|
| 案 | 探索ループ前に `material_min` / `material_max` を参照 run の幾何からクランプ |
| 下限 | `max(keep_mm3×比率, reference.corridor × element_volume)` —— これより小さい材料量は
SIMP 前から非連結が確定 |
| 上限 | 塊容量 × 90〜95%（フィルタ目減り）—— `too_much` が確定する側 |
| 期待 | **異常系評価（数分の SIMP が例外で終わる試行）をゼロ化** |
| 備考 | 既定の `MATERIAL_MAX_RATIO=0.55` は既に保守的。主効果は**下限**とカスタム `material_max` 時。
`_material_bounds` との二重クランプに注意 |

### B0'. Dual Criteria（安全率側の早期終了）

| 項目 | 内容 |
|---|---|
| 案 | `ok` かつ `1.00 ≤ sf/target ≤ 1.02` なら **即採用して終了**（材料量 `rel_tol` 未達でも） |
| 期待 | ラスト **1〜2 評価**（数分）削減。plate 等の sf 頭打ち空回りも緩和 |
| トレードオフ | 契約は「以上で最小」—— 早期終了は **真の最小よりわずかに重い** 解を返しうる。
製品仕様として許容幅を明記すること |

### B1. 探索中だけ SIMP 反復数を減らし、採用候補だけ本番反復数

| 項目 | 内容 |
|---|---|
| 案 | 探索評価 `max_iter=15〜20`、採用材料量のみ `max_iter=40` |
| 期待 | 探索分 **40〜60%** 短縮 → 全体 **35〜55%** 程度 |
| 根拠 | 1評価の 99.5% が SIMP（[TOPOPT.md](TOPOPT.md) 内訳表） |
| リスク | 少反復の安全率順位が本番とずれる → 実測で単調性・順位一致が要る |
| **MMA 移行後** | **15〜20 は測り直し。** OC は収束が速く序盤から順位が出るが、MMA は漸近線が
落ち着くまで挙動が違い、収束に要る反復数も同等〜多い。**リスクの側が大きくなる案である** |
| 対策 | 探索時の目標 sf に **3〜5% マージン**、または本番でアンダーシュート時に材料量を1ステップ増やして
再実行 |
| 関連 | [TOPOPT.md](TOPOPT.md) は「粗い段で探索→最後に1回本番」の **2段構えは未実装**（案5型） |

### B5. `stress.evaluate` の solve をウォームスタート化

| 項目 | 内容 |
|---|---|
| 案 | SIMP 最終 `u` を `Result` に載せ、**最終 ρ で必ず solve** するが `u0=u` で CG/MG を加速 |
| 現状 | 評価ごとに SIMP 40 solve + stress 1 solve（`u` 未渡し） |
| 1反復ズレ | SIMP ループは「`x_phys` で solve → OC 更新 → `x_phys` 更新」。返却 `rho` は**最終更新後**だが、
ループ内の `u` は**その直前の密度**に対応する（`simp.py`）。`stress.evaluate(..., u=u)` で
solve を**完全省略**すると代表応力・安全率がずれる |
| 期待 | stress の solve 時間 **80〜90%** 削減（厳密性は維持） |
| リスク | 低。`solve_displacement` / `model.solve` に `u0` を渡す配線追加 |

### B6. 隣接候補間の ρ / u ウォームスタート

| 項目 | 内容 |
|---|---|
| 案 | 直前評価の `rho` または `u` を次 SIMP の初期値に |
| 現状 | 毎回 `x = volfrac` 一様、`u = 0`（`simp.optimize`） |
| 期待 | **20〜30%** / 評価 の可能性（MG ウォームは +6% 反復程度 —— [TOPOPT.md](TOPOPT.md)） |
| リスク | **連続値保持（既定）** では全評価が同一 `reference.base.grid` を共有し、塊マスクは材料量増加で
**単調に拡大**するため親和性が高い。案5（粗 run ごとに格子が変わる）とは状況が異なる |
| **MMA 移行後** | **この案は MMA だと不完全になる。** OC は `x` 以外の状態を持たないが、
**MMA は反復をまたいで状態を持つ** —— 移動漸近線 `low`/`upp` と直前2点 `xold1`/`xold2`。
`x` だけ引き継いで漸近線を初期状態（広い）に戻すと**最初の数反復が悪くスケールされ**、
別の材料量で育った漸近線をそのまま持ち込む根拠も無い。**「漸近線の状態をどう引き継ぐか」を
決めてからでないと実装できない**（本書が想定していない設計判断） |

### B7. 探索中の mesh/STL をスキップ

| 項目 | 内容 |
|---|---|
| 案 | 中間評価は `run_topopt` で SIMP+応力だけ、mesh は最終のみ |
| 期待 | ** negligible**（mesh **0.01%** —— [TOPOPT.md](TOPOPT.md)） |
| 備考 | 配線整理の価値はあるが速度目的では優先低 |

## 効果小・試済み・方針で採らない

| 案 | 理由 |
|---|---|
| 参照 run をさらに短縮 | 全体 **~4%**。10反復は被覆100%で既に最適（[TOPOPT.md](TOPOPT.md) 参照 run 表） |
| `cg_rtol` 緩和 | **~16%** 程度。[TOPOPT.md](TOPOPT.md) は「誤差の範囲」で未着手 |
| RAP / `splu` 並列 | **試して効かない**（[TOPOPT.md](TOPOPT.md) CPU並列化） |
| スレッド数を総コアまで | 半コア付近が最良（[TOPOPT.md](TOPOPT.md) スレッド数） |
| 塊固定（案c） | 導出 **0.4〜0.5秒/回** しか削れない。低材料で安全率 **4%ずれ** |
| 応力制約付き最適化（1回で解く） | **採らない**。ただし **MMA 移行後は根拠が1つ減る**（下記） |

**応力制約を採らない根拠の現状（2026-09-10 改訂）**: engine
`safety-factor-goes-outside-the-optimizer` が4点を挙げている。**MMA が消すのは①だけで、
結論は②③④で維持される。**

| | MMA 移行後 |
|---|---|
| ① 制約が1本から要素数ぶんに増える。OC は制約1本でしか成り立たない | **消える** |
| ② 特異最適（ρ→0 で応力が0に行かない）。ε緩和・qp緩和が要る | 残る |
| ③ 感度が自己随伴でなくなる（随伴解が1本増える） | 残る |
| ④ **ボクセルの階段状境界では応力が信用できない**（応力は最大値を見る量で階段に最も敏感） | 残る |

**「MMA が入ったから採れるのでは」と読まないこと。** ④はこの実装の根（ボクセル）に由来し、
更新則では手が届かない。

## 推奨実装順

リスク対効果順:

```
フェーズ 1: リスク極小・即効性
  1. [B0'] Dual Criteria              … 数行、1〜2評価削減（契約トレードオフ要明記）
  2. [B0]  Smart Bounding             … 異常系試行の排除
  3. [B5]  stress solve + u0 渡し     … 数十秒/評価、精度100%維持

フェーズ 2: 探索アルゴリズム
  4. [A]   Illinois（フォールバック・クリップ付き） … 2〜3評価削減
  5. [B6]  SIMP 間 ρ/u ウォーム       … 1評価あたり 20〜30%

  6. [B1]  探索 max_iter ↓（アンダーシュートマージン付き）
  7. [B2]  粗解像度探索（案5型2段構え）

  9. [B4]  並列評価
```

**第一弾（B0' + B0 + B5）** は探索本体の契約をほぼ変えず、異常系排除と stress 短縮で
**数分〜十数分** を狙える。**フェーズ 2（A + B6）** で探索段 **おおよそ 20〜40%** を狙う。

## 実装時の受入の考え方

1. **採用材料量・安全率** — bracket 等の固定題材で、旧二分と **同程度またはより軽い** 材料量
   （悪化しないこと）。完全一致はボクセル量子化で要求しない。
2. **評価回数** — `result.history` の長さが典型で **1〜2 減る** こと（題材依存と明記）。
3. **単調性が怪しい題材** — plate 等で `history` を見て安全率が逆行していないこと
   （[TOPOPT.md](TOPOPT.md) の留保どおり）。
4. **契約** — 探索目標は「以上で最小」のまま。`SafetyTargetError` / `too_little` / `too_much`
   の **3分類そのものは変えない**。Dual Criteria を入れる場合は **許容超過幅（例: 2%）** を
   仕様に明記。
   **※ MMA へ倒すときは「分類の作られ方」が変わる**（taskbox `20260910-1315`）——
   いまの `too_much` は `VolumeTargetError(side="above_capacity")`、すなわち **OC の
   ラグランジュ乗数の二分探索が退化したとき**に出る。MMA では体積が不等式制約になるので
   同じ出方をしない。**本書の案と 1315 はどちらも `safety_loop` の同じ場所を触るので、
   順序を決めてから着手すること**（分類の3値は保たれるので、本書の案そのものは生き残る）。
5. **B5** — 最終 ρ に対する solve が走ること。`u` の再利用は **`u0` 経由のみ**（完全省略禁止）。
6. **Illinois** — `too_little` / `too_much` 直後に割線法を使わないこと（二分フォールバック）。
