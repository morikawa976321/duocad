# duocad — 画面と操作の判断

**読むとき**: パネル・ツールバー・コマンドの振る舞い・スケッチ入力・見た目を変えるとき。
3Dビューの内側（カメラ・ピック・グリッド・深度）は [VIEWPORT.md](VIEWPORT.md)。
操作手順・キー割当・ボタン文言の正は各コンポーネントのコメント（docs/DEVELOPMENT.md §2）。ここに書くのは
**なぜそうしたか**と、コードから読めない判断だけ。個別の見た目の調整（色・寸法・文言）は書かない。

## 方針（docs/DEVELOPMENT.md §0 の設計原則の下にあるもの）

- **常設の指標を置かない**（本人）: 実物を見れば分かるものに札を作らない／人の判断に使わない数
  （操作数・ファイルの件数とサイズ）は出さない／札で補わないと伝わらない見え方は見え方の側を直す
  ／状態は常時光らせず、人の手が要る瞬間に言う（接続状態は送れなかったときにトースト）。
- **既定状態は「見ているだけ」**（本人判断）。既定コマンドを常時構えさせない。「通常モードにも『選ぶ』
  コマンドを新設して既定にする」案はボタンが増えるので却下。**確定に成功したら自動で無起動へ戻す**
  （連続作図の操作性を失うのを承知で全 verb 共通。`undo` / `redo` と、ファイルパネルが直接送る保存・開く・書き出し等は
  `CommandHost` を経由しないので対象外）。戻すのは**サーバが構えを畳んだ配信（`state.command` が null。issue #153）が返ってから** —— 楽観的発火と同時に
  落とすと、失敗応答で入力欄を復元しても欄自体が DOM から消えている（OCCT のフィレットは限界半径で失敗
  しうるので「打ち直す」が必須）。
- **現段階の duocad は複数パーツ運用を最適化しない**（本人）。パーツ一覧の pick 列と「選択したものだけ表示」は削除済み。
- **一度決めたら触らない設定は設定ダイアログ1枚に平らに並べる。** スキーマ駆動・カテゴリ・タブは作らない。
  作業中に切り替えるものはその場のパネル。見ながら決める設定（FOV）のために覆わない・暗くしない・即座に効く。
- **プレビュー（確定前の幽霊）はつけられる操作には基本的にすべてつける。** 方式は**ブラウザだけで描く
  ローカル**（`preview: 'local'`）。位置や図形しか変わらない verb は投機実行しても「形が変わった Body」が
  返らず応答が常に空になるので、サーバの投機実行は増やさない。
  要求の寿命は `web/src/previewController.ts` が持ち、ローカルは即時描画、サーバ方式は打ち終わり250ms待ち・
  打ち続けた場合は750ms以内に送る。引数や選択の指紋による重複抑止、形状配信後の250msの再送待ち、
  取消と応答の採否も同じ部品に置く。共有のコマンド・引数・モードの正は引き続きサーバの Workspace。
  入力が変わった後に届いた古い入力の応答は描かない。
- **モーダルを使わない。** 設定ダイアログは `show()`（非モーダル）。`showModal()` は背後を inert にして
  「見ながら回して確かめる」を殺す。フォーカストラップは戻さない。
- **既定の透視は30度、UIは正投影/透視の2値**（本人）。**「実用上の差が無い」は「弁別できない」ではない**
  （本人が明示的に訂正）—— 30と45には見た目の差がある。内部 API（`setFov` / `isSelectableFov`）は 0 または
  30〜90 を受け付けたまま。
- **その瞬間に要るものだけを出す**（本人）。**出し分けの主軸はモード**で、要らない側は無効化ではなく画面から消す。
  使うかもしれないものは認知負荷を上げない配置か開閉可能にする。

## パネルの配置

- **左サイドバー＝ファイルパネル（開閉可）、ビューポート左上に浮くブラウザ（モデル/スケッチ）、右サイドバー＝
  AI パネルだけ（開閉可）。** ブラウザは「モデル」「スケッチ」の2区分をフラットに並べる（入れ子のツリー化と
  コンストラクションを足すときに一覧を作り直さないため）。
- **ブラウザの行は、指したときだけ右端に ✎(名前を変える)と ✕(消す)を出す。** ✎ は行の中に入力欄を開く
  （ダブルクリックにしないのは、スケッチ行の1回目のクリックがスケッチに入ってしまうため）。✕ は確認を
  挟まない —— `delete_items` は1回の Ctrl+Z で戻る。確認が無いので、✕ は ✎ から 12px 離す（誤って押さないため。
  行の高さは変えない）。名前の既定はボディとスケッチで独立した通し番号
  （一度振った番号は再利用しない。`duocad/naming.py`）。**複製のボディだけは通し番号でなく「元の名前 + 半角空白 + 連番」**
  （番号は 2 から、既にある名前と重ならない最小。複製の複製は、番号を外した名前が文書にあるときだけ外して数え直す。
  名前が空の元は通し番号の名前）。
- **ブラウザの「モデル」「スケッチ」の見出しは、押すとその節を畳める**（▾ / ▸。初期は開く。畳んだ状態は再読み込みで開いた
  状態に戻る）。押せるのは見出しの名前側の全面で、右の表示数は押せない。畳むと全表示・全非表示のボタンも隠れる。
- **ファイルパネルは左サイドバーが正**（ツールバー統合は退けた）。**左サイドバーの既定は開いた状態**。
- **ファイル一覧の1行は「サムネイル・ファイル名・作成日時・更新日時」＋複製・削除。** サムネイルは画面が撮り
  （`web/src/thumbnail.ts`）、`models/.thumbnails/` の付随ファイルに置く。作成日時は文書のJSONの `created` が
  持つ —— 保存は一時ファイルの差し替えなので、ファイルシステムの作成時刻は毎回「最後に保存した時刻」に
  なる（Windows 11 / NTFS で実測）。`created` を持たない既存ファイルは「—」（更新日時で埋めない）。
  複製の欄には、複製のあとその文書を続けて開く確定（「複製して開く」）が「複製」と並ぶ。Enter は「複製」のまま。
  3つ目のボタンで名前の欄が約 50px に潰れるので、複製の行だけ「欄が1行、ボタンが次の行」に折り返す。
- **STEP 読み込みはツールバーの verb、STEP/STL 書き出しはファイルパネル。** 線は「文書を変えるか」。
  書き出し名の欄の既定は今の文書のファイル名（拡張子は書き出しの形式のもの）。触っていない欄だけが文書の改名
  （無題から名前が付くとき等）に追随し、打った名前は残る。同名のファイルへ書き出して上書きになったときは、
  知らせが「(N個・上書きした)」になる（サーバが `io_step.export` の応答に `overwrote` を載せる）。
- **常設パネルを足すときは画面に新しい帯を取らない。** 形状最適化の実行パネルをブラウザの右へ足したら
  その帯の下のボディが1面も指せなくなった。**モードのあいだ出しっぱなしの
  パネルは、モデルを覆う位置に置けない。** 一時的なダイアログは別の帯へ出してよい。
- **選択パネル・操作履歴パネルは削除済み。** 履歴の行クリックで一括 undo はコアの機能追加になるので見送り。
- **選択情報はビューポートの左下**（issue #140。`SelectionInfoPanel.svelte`）。**選択がちょうど1項目のときだけ**
  種別・参照名と寸法を出し、空・2項目以上では何も出さない（本人判断。2項目のあいだは「測定」コマンドが上中央に出す）。
  右下はトーストと重なるので避けた（本人）。置くのはブラウザの列の右（issue #281）: ブラウザは下端まで伸び、同じ列に置くと
  その下に隠れる（形状最適化の実行パネルも同じ列にいる）。札の高さをブラウザの下端の確保へ渡すと、選ぶたびにブラウザの高さが変わる。
  - 値は `measure` の1項目そのもの（WS の `inspect_selection`）で、画面で幾何を計算しない —— AI が読む値と同じ。
    足りなかった面の種類・円の辺の半径と中心・スケッチの線分の長さは `measure` 側に足した。
  - クリックを吸わない（`pointer-events: none`）。左下はモデルが来る位置なので、吸うと札の下の面が指せない。
  - 選択は人と AI で共有なので、AI が選択を変えても同じ道で追従する。取り直すのは選択か文書が変わったときだけ
    （状態はズームの粗さが変わっても届く）。
- **右サイドバーは AI 専用。** スケッチモードの操作はコマンドツールバー側。
- **断面はブラウザの「原点」の下の「断面」グループ。** チェックで入れ、入れている間だけ平面・位置・反転の
  操作子を出す。verb ではないのでツールバーにも AI（MCP）にも出さない。キー割当は無い。
  **代償は、切っていない間もブラウザが見出し1行ぶん縦に伸びること。** 実機検査のクリック・
  右ドラッグの始点がブラウザの下に入って落ちるので、押す前にブラウザを畳む（`browser.mjs` の `withoutBrowserPanel`）。
  - **平面（XY / XZ / YZ）はパネルのボタンで選ぶ。** docs/DEVELOPMENT.md §0 原則1とは緊張するが、基準平面のピックは
    スケッチの貼る先待ちの間だけ生きる経路で、大きいモデルでは原点が埋まって指せない。
  - **状態はその場限り**（文書にも localStorage にも載せない）。スケッチ・形状最適化のモードに入っても切ったまま。
  - 入れた瞬間・平面を替えた瞬間の位置は、表示中のボディ（幽霊を含む）の外接箱の中心。反転なしで消すのは
    **ホームビューのカメラ側**（`HOME_VIEW_OFFSET` の符号から導く）。
  - 平面は枠線だけで塗らず、クリックを吸わない。掴めるのは法線方向の矢印だけ（板全体を掴む形は、板の画素で
    モデルが指せなくなる）。切り口は1色（`SECTION_CAP_COLOR`）で、選択色には追従しない。
- **新規ボタン**（`new_document`）は確認ダイアログを挟まない —— 一覧のクリック1つで別の文書へ移れる
  のに空の文書へ移るときだけ確認すると挙動が割れる。**自動保存が書けず「未保存」のときは、開く・新規・閉じるの前に
  書き直し、それも書けなければ切り替えずに断る**（本人判断 2026-11-05、issue #279。`Session._save_before_leaving`）。**AI には開けない**（`mcp=False`）:
  今の文書を丸ごと捨てて undo でも戻せないので、捨てる判断は人がする。
- **何も開いていない状態（トップ画面）を持つ。** サーバはこの状態で起動し（`Session(opened=False)`）、
  ファイルパネルの「閉じる」（`close_document`）と開いている文書の削除でも戻る。
  - グリッド・原点・ビューキューブ・ツールバー・ブラウザは文書に属するものとして全部隠す（空の無題の文書と
    見た瞬間に区別できるため）。`StartScreen.svelte` が最近の文書8件のカードと「新規」だけを出す（左のファイルパネルが閉じていて文書が9件以上あるときだけ「すべてのファイル」も出る）。
  - 開いたとき、先頭（いちばん新しい）の文書のカードにフォーカスがあり、Enter 1回で開く。フォーカスはカードが最初に出たときの
    1回だけで、別の入力欄にフォーカスがあれば奪わない。
  - 閉じている間、文書を変える操作はどの口（画面・MCP・アプリ内AI）からもサーバが `NoDocument` で断る。
    素通しすると最初の変更で `untitled-<n>.json` が作られ、黙って無題の文書に変わる。AI は
    `describe_document` の `document_open` で知る。
  - 開いている文書の削除は、ファイルを消してから閉じる。中身を残して無題に戻すと、次の自動保存が消した
    はずの中身を別名で復活させる。
  - 「STEP/SVG から新規」は置かない（読み込みはサーバ側のパスを打つコマンドで、ファイルを落とす口が無い）。

## コマンド層

- **点から導ける寸法欄は how に数えない**（`fromPoints`。docs/DEVELOPMENT.md §0 原則3）。空欄なら集めた点から導き、打てば
  それが勝つ。確定に使う引数を `built ?? ghostBuilt` にして経路を一本化している。代償は**層をまたぐ契約が
  1本増える**こと —— プレースホルダの「いまマウスが指している値」は確定用の引数から名前で引くので、UI の
  欄名がサーバへ送る引数名と一致しない寸法（線分の長さ・角度は `p0`/`p1` へ畳む）は追従しない。
- **対象とは別に「既存の図形/面への参照」を引数で受ける verb**（`move_body.axis_edge` / `center_vertex`、
  `mirror_body.plane_face`、`mirror_sketch_entities.axis`）は `PickArgSpec`（`commands/command.ts`）に乗せる。
  必須のピックは対象の最小数が満たされた瞬間に構えられ素のクリックを全部吸うので、**修飾キー付きクリックは
  ピックへ行かせない**。ピックを `optional` にする案（必須が「(任意)」と出る）、対象の上限を1にする案
  （仕様を曲げる）は採らなかった。
- **持ち主ごとに効くコマンドの起動中は、光るものと効くものを揃える**（2026-11-04 本人指示「ボディではなく面が選択されてしまう」を
  全 verb へ広げた。`web/src/commands/grain.ts`）。コアが面・辺・頂点からボディを逆引きして効かせる verb（`move_body` /
  `mirror_body` / `split_body` / `boolean_body` / `delete` / `project_outline`。選択引数の `shapeKind: 'body'`）は、
  どこを押してもボディ全体を選び、ホバーもボディ全体を光らせる（辺・頂点は的から外す。ホバーは次の素のクリックで入るものに
  揃えるので、鏡映面・切る平面の「面を選ぶ」で面1枚を待つ間は面1枚、鏡映軸や切る平面のスケッチで線を待つ間は線まるごと）。スケッチの点から図形を逆引きして
  効かせる verb（`delete` / `mirror_sketch_entities` / 反復。`wholeEntities` と `entities` 引数）は、端点を押しても図形を選ぶ
  （点の図形はその点のまま）。起動前に選んであったもの（AI が選んだ面も）は起動の瞬間に同じ粒度へ畳む。点だけを動かせる
  `move_sketch_entities` は点のまま。ブーリアンのターゲットはボディを直接ピックし（`PickTarget` の `body`）、指したボディを
  全面強調する。照合は `tests/test_ui_command_wiring.py`（コアの入口を静的に読む）。**起動中に AI が選んだ面は畳まない**
  （AI の選択を画面が書き換え続けると取り合いになる）。
- **ボディ分割(`split_body`)は鏡映(`mirror_body`)の起動に揃えた**: 対象はボディ(上の粒度)、切る平面は「XY / XZ / YZ / 面を選ぶ / スケッチを選ぶ」の choice で、後ろの2つは別チャンネルのピック(共有選択に入れない)。**「スケッチを選ぶ」はスケッチの線を1本指す**(平面そのものを指す的が無いため。`sketchEntity` のピックは点を待たないので、線・円などの無いスケッチ(点だけ)は指せない)。「残す側」(両側 / 法線の側 / 反対側)は既定を持たない choice(作法どおり。両側なら1手増える)。鏡映と同じく**幽霊を出す**(`preview: 'server'`。切った後の形で本物を隠す)。決定の細目は [contracts/verbs.md](contracts/verbs.md)「split_body」。
- **モードは verb の上位次元**（[DESIGN_DECISIONS.md](DESIGN_DECISIONS.md)）。`App.svelte` のモードはタグ付き
  ユニオン1変数（`idle` / `sketch-pending` / `sketch` / `optimize`）だが**サーバの作業空間 `state.mode` からの派生**で、画面は
  持たない（issue #153）。入る・出るは `enter_sketch` / `leave_sketch` / `enter_optimize` / `leave_optimize` をサーバへ頼み、
  貼る先待ちはサーバでは「`sketch_create` を構えている」。**モードに紐づく状態の掃除は「出口」ではなく「入口」に置く** ——
  入口（再開・直接切り替え・undo での復帰・AI の切り替え）は後から増える。行き先で使えない選択はサーバが外す
  （`Session._apply_mode`）。
- **起動中の verb と引数も画面が持たず、サーバの作業空間 `state.command` に従う**（issue #153）。ツールバーのクリックは
  `begin_command`、入力欄は打ち終わり 250ms 後に `set_command_args`（欄を離れたら即）、Esc は `end_command`、Enter は従来の
  一発 verb（同じ verb の構えはサーバが確定として畳む）。打っている最中の欄は外からの値で奪わず札で知らせ、欄を離れれば
  自分の値が勝つ（サーバは後勝ち）。外（AI・別の画面）からの起動・引数・確定・モードの変更は画面に知らせない
  （人の打ちかけや選択が消えても同じ。本人判断 2026-11-05、issue #260。`note()` に積むだけ）。構える対象で
  ないもの（測定・ファイル操作・スケッチの「選ぶ」）だけは画面で起動する。確定の失敗で打った値を戻す仕組みは要らなくなった
  （サーバの構えが残る）。共有されるのは**サーバの引数名を持つ値**（半径・距離・選択肢・ピック・`corner` のような点。
  `COMMAND_PARAMS` で絞る）で、画面だけの補助欄（線分の長さ・角度、円弧の通過点のクリック）は共有されず、再読み込みで
  戻るのも共有された分だけ。実機の固定は `web/scripts/smoke-workspace.mjs`。
  入力表示と共有引数の調整は `web/src/sharedArgsController.ts` が所有し、送信済みの差分・未送信の値・受信時のフォーカス・
  外部から届いた値を分けて扱う。純粋な遷移は `transitionSharedArgs`、送信・入力表示・通知・タイマーの実行は
  `createSharedArgsController`。`CommandHost` は欄の値とイベントを渡し、App の引数変更通知も同じ部品で差分を作る。
- **構えたコマンドの引数のうち、ボディの面・辺・頂点を指す参照（`{body, index}`〈kind が無ければ面〉・`{body, kind, index}` とその配列）は、
  そのボディの形が変わったとき（undo・redo・別の verb の適用）サーバが `command.args` から外す。** 添字は形が変わると今の形の別の部分を指す。
  形が変わったかは、適用の前に控えたボディの形（`body.shape`・`body.mesh`）と後を同一性（`is`）で見比べる。外した引数名は応答の
  `dropped_args` に載り、画面は「形が変わったので「…」の指定を外した」を灰色で出す。欄の指定は、外した引数の配信を既存の共有引数の同期
  （`sharedArgsController`）が受けて消える。外から（MCP の undo など）の変更は応答が画面に届かないので、既存の「外から…の引数が変わった」の
  知らせに任せる。構えていた verb 自身が確定したときは構えごと畳むので外さない。
- **取り消したあとの新しい操作でやり直せる分が消えたとき、応答に `discarded_redo`（捨てた件数。適用の前後のやり直せる件数の差）が載り、
  画面は「やり直し N 件を捨てた」を灰色で出す。** 保存の形と再生は変えない。
- **ブーリアンの引数に、ツールを消すか残すかの選択がある**（`keep_tool`。既定は消す。選択肢の語は `commands/features.ts` が正）。残すを選ぶと
  送る引数に `keep_tool: true` が付き、ツールのボディが文書に残る。
- **距離欄の見出しに正の向きを書く**: スケッチの押し出しは「距離(正=スケッチの表側)」、面のオフセットは「距離(正=肉が増える/穴は細くなる)」。

  30px を実測）。式を打ったときのエコー「距離(…) = 〜」も見出しの文字なので長くなる。

  （`ghostLayer` の `removedByPreview`。置き換わるボディ、たとえばフィレットの元は指せる）。

- **`move_*` の空欄の軸は 0 として扱う（本人の判断。`web/src/commands/moveMode.ts` の `default: 0` で実装済み）。** 対象は**この2 verb の
  dx/dy/dz だけ** —— 半径・距離・個数のような「空欄＝まだ決めていない」引数に黙って 0 を埋めると壊れる。
- **数値欄は数式を受け付ける**（`web/src/expression.ts`）。三角関数の引数と逆三角の戻り値は**度**（本人選択）。
  関数セットは四則・単項マイナス・括弧・`^`・`sqrt`・`abs`・`pi`・`sin/cos/tan`・`asin/acos/atan/atan2` で、
  **`hypot` / `min` / `max` / `round` / `floor` / `ceil` は本人が明示的に除外**（`log` / `exp` / 剰余も無し）。
  文書パラメータの参照は入れていない（`set_parameter` は公開面から外してあり UI にもパラメータ欄が無い）。
- **次に打つ欄へは自動でフォーカスを入れる**（issue #18）。起動・点のクリック・選択肢・直接ピック・基準平面・
  **この画面のクリックによる選択変更**の後に `focusFirstNumber()` が走る。選択・ピック・選択肢を待つ間は奪わない。
  面や辺を選んだ直後は欄にフォーカスがあるので、**数値欄が空のとき Ctrl+Z / Ctrl+Y は欄でなく文書の取り消し・やり直しに回す**
  （奪っても失う文字が無い。判定は `CommandHost.isEmptyArgField` で、引数の行の中の空の入力欄だけ。AI の会話欄・名前変更の欄は空でも欄のもの）。
  文字がある欄は欄の取り消しのまま（入力欄の Ctrl+Z は文書を戻さない。[WEB_PITFALLS.md](WEB_PITFALLS.md)）。

## スケッチ入力（本人判断、Fusion に揃える）

- **寸法はもう1つの点で決まる**（長方形＝対角、円＝円周の1点）。数値欄は残し、空欄ならマウス追従・
  打てばそれが勝つ。長方形・円は2クリック、円弧・楕円は3クリックで確定（Enter を押さない）。
- **円と楕円は直径で入れる**（2026-10-17 本人判断。Fusion と同じ）。楕円は「中心 → 1本目の軸の端 → 2本目の軸の長さ」の3クリック。verb の契約は変えず UI 層で閉じる。
- **円弧は「始点 → 終点 → 円弧上の1点」の3クリック（中心は入力しない）。** 中心から始める形は「円と線分で
  代用できる」ので採らない。3点目を中心にしないのは、中心は弦の垂直二等分線上にしか置けず、「膨らむ向き」と
  「劣弧/優弧」を同時にマウスで選べないため。
- **線分には長さ・角度の数値欄**（角度は度・反時計回り・X軸から）。
- **長方形は幅と高さを両方打つと、打った符号が向きを決める**（正は +u / +v 側、負は逆側。マウスの位置は見ない）。片方だけ打ったときは
  マウス側へ伸び、負は「両方を打ったときだけ逆向きにできる」と理由を言って断る。
- **スナップ3段**（描く verb が点を待っている間）: 既存の点マーカー → 既存の図形の線 → **1mm グリッドの
  交点へ丸める**（点と線の段にはボディ由来の吸着先も並ぶ。下の「スケッチの平面と交わる…」）。原点の軸への吸着は、
  軸に沿って原点から 1mm 刻みに丸める（軸は格子線と重なるので、丸めないと軸の上の格子点が置けない。2026-11-05 本人判断。
  ピックの規則は [VIEWPORT.md](VIEWPORT.md)「ピック」）。1mm は `gridScale.ts` の `TIERS` の最小段で絶対値固定。**マウスだけでは非整数の座標が
  置けないのは意図した挙動**（端数は寸法を打つ）。**スナップを切る修飾キーも、ズームで刻みを変える仕組みも
  作らない**（視点に依存すると同じ操作が違う結果になる）。スナップは拘束ではない。
- **スケッチの図形・点にはホバー強調を出し、描く verb が点を待っている間も出す**（「既存の選択ゲートに従う」の例外）。
  スナップが入ると強調の意味が「クリックすればここに乗る」に変わり、どちらでも予告として正しい。
- **長方形の残り3隅・楕円の軸の端4点と、図形をまたぐ交点（線分・円・円弧の組と、楕円と線分。ベジエと「楕円と曲線」は対象外）は本物の点と同格に吸着する。**
  交点は `SketchEntityHit.snapAt`（厳密座標）で運ぶ —— 片方の図形への射影に任せると連続的な最近傍点になり
  交点からずれる。
- **スケッチの平面と交わる・接するボディの点と線にも吸着する**（2026-11-05 本人判断）。点は平面上の頂点と平面を貫く辺の
  通る点、線は平面上の辺と面と平面の交線で、面そのものは吸着先にせず交線として扱う。
  - **面に貼ったスケッチに限らず全部のスケッチで効く**（基準平面・オフセット平面が立体を横切れば断面の輪郭に吸着する）。
  - **顔ぶれはスケッチの図形の吸着と同じ**: 端点・直線の中点・円/円弧/楕円の中心・楕円の軸の端・ボディの線とスケッチの図形の交点。
    段（点 → 中点 → 線 → グリッド）も同じで、同じ段の中はスケッチの図形と画面の距離で競う（同着は図形）。
  - **線は吸着したときだけ明るく描く**（常時の参照線は出さない。「普段描かない辺はホバー中だけ現れる」と同じ線）。
  - **立体に隠れていても吸着する**（編集中のスケッチの線と同じく立体の上に描く）。
  - 対象は見えている B-rep のボディだけ（隠したボディ・メッシュのボディは外す）。吸着は座標だけで、拘束にも参照にもならない
    （後でボディを変えても描いた図形は追従しない。投影と同じ）。点を待っていない間は当たらず、選択・軸や中心の指定にも使わない。
- **pointKey が1個しかない種別（rectangle / circle / ellipse / arc）は点マーカーを選択中・ホバー中だけ出す。**
  「その点だけ動かす」と「図形全体を動かす」が同じ処理（`_moved_params`）なため。線分・ベジエは常時出す。
- **スケッチ開始は「ボタン → 貼る先をクリック」の2手**（基準平面も任意の面も同じ。Enter を挟まない）。
- **視線がスケッチ平面と 2 度未満の角で見ているとき、点を置くクリックは受けず、視点を平面に向けてから置くよう知らせる**
  （`planeSight.ts` の `MIN_PLANE_SIGHT_DEG`。2 度は置いた値で実測ではない。見積もり: 画角 45 度・縦 800px で、2 度のとき 1px の動きは
  カメラの平面からの高さの約 0.8 倍の移動になり、1mm に丸めても置いた点は狙いからずれる）。止めるのは点を置くクリックだけで、
  既存の図形・ガイドに当たっているクリックは対象外。
- **SVG を取り込んだあとは、取り込んだ図形（既存の図形は含めない）が収まるまで、今の向きのまま寄る**（`frameSketchEntities`。選択はしない）。
- **スケッチを抜けたら入る前の視点へ戻す**（本人）。**再フレーミングを通常編集（押し出し・フィレット）へは
  広げない。** `open_document` は再フレームする、`new_document` はしない。
- **選択の修飾キー: Shift も Ctrl も「トグル」に統一**（除外専用は無意味）。無修飾は置き換え。
- **コマンド起動中は素クリックもトグル、終わったら選択を全解除。選択に出所の区別は無い。** 決定は
  [DESIGN_DECISIONS.md](DESIGN_DECISIONS.md)「隠したボディ・選択・可視性」。実装: 素クリックは `toggle_selection` を送る。
  終わりは Esc・中断ボタン・確定成功・別 verb への乗り換え（`App.svelte` の `onCommandEnd` / `onCommandStart`）。
  `PickArgSpec` の素クリックは従来どおりピック引数が食う。ドラッグ選択（矩形）は共有の `toggleOnlyMode` を通る。
- **ブーリアンのターゲットに指したボディは、ツールの選択から外す**（`PickArgSpec.excludesFrom`。issue #263）。先に2つ選んでから
  起動すると両方がツールに数えられ、コアが「ターゲットはツールになれない」と断っていた。
- **食える面の種類が決まっている引数は、起動中のクリックで絞る**（`SelectionArgSpec.surfaceKinds`。ねじは全周の円筒面だけ）。
  ほかの種類の面のクリックは選ばずに知らせる。起動前・ドラッグで選ばれた食えない面は、残っている間は確定させず外すよう言う
  （コアは選択にある面を全部数える。外すクリックは通す）。種類は届いた形の
  `FaceGeometry.kind`（コアの `classify_face`。ねじのコアの判定と同じ）を `web/src/faceKinds.ts` が控える。
- **個数の上限がある選択引数（ねじ・測定）は、上限を超えるクリックで最古の選択を外して置き換える**（`command.ts` の `evictionsForClick`。
  クリックだけで枠選択は対象外。選択の追加と最古の除外は1回の `modify_selection` で送る）。
- **ボディを隠すと、そのボディのボディ・面・辺・頂点の選択項目は選択から外れ、表示に戻しても選択は戻らない。** 隠れた項目が残ると
  移動・ブーリアン・削除が、隠れていることを理由に残りを含めて断られる。決定は [DESIGN_DECISIONS.md](DESIGN_DECISIONS.md)「隠したボディ・選択・可視性」。
- **Esc は、文字を打つ欄（AI の欄・ファイル名・干渉の隙間など）と開いている設定ダイアログの中ではその欄のもので、コマンドを
  中断しない**（`keys.ts` の `ownsEscapeKey`。issue #271）。コマンド自身の引数の欄の Esc は中断。**Delete / Backspace は
  「削除する」**（点を順に打つコマンドで打ちかけの点があるときの Backspace は、最後の1点を戻す方が先）: 消せるものが選ばれていれば無起動から起動して確定し、「削除する」の起動中は確定する。文字を打つ欄では
  効かせず、別のコマンドの最中も何もしない。
- **待ちの1行は、起動中は引数の行（overlay）の末尾に置いて折り返す**（issue #269）。コマンド行は in-flow で、伸びると
  ビューポートの実寸が変わる。無起動（スケッチの「選ぶ」の案内）はコマンド行の右端のまま。起動中も、無起動のときの待ちの1行と
  同じ文字・同じ CSS の見えない場所取り（`.prompt-space`）をコマンド行に残し、引数の行が開いてもツールバーとビューポートの
  高さを変えない（スケッチで線分を開いて実測: ツールバーのコマンド行 80.5px・ビューポート 688.5px のまま）。
- **サーバのプレビューが断ったら、理由を待ちの1行に出し、「Enterで確定」を出さない**（トーストにはしない。issue #259）。
  サーバの断りは `preview_id` を持ち、画面は最後に送った要求の断りだけを、その要求の入力の印と一緒に控える（後から送った要求が
  あれば古い断りは捨てる）。入力が変われば出さなくなり、プレビューが通れば消える。文言はコアの例外文のまま。
- **スケッチモードの「選ぶ」ボタンは人向けの画面から外す**。コマンド定義・既定コマンド・Esc/確定後に戻る
  挙動は AI 用に残す（`CommandDef.hidden`）。

## 測定（issue #10）

**verb ではない**（文書もログも変えない）が、verb→target の枠（`CommandHost`）に乗せた。

- **起動の形は「測定」ボタン。** 「選択がちょうど2つになったら常に距離を出す」案は「状態を常時光らせない」に
  反するので退けた。既に2つ選んであれば押した瞬間に測る（**読み取り専用だけの例外**。他の verb は起動時に
  揃っていても発火しない —— AIが選んだ面のまま押し出しを押しただけで形が変わるのを防ぐため）。
- **サーバ側の口は既存の `measure` を拡張**して WebSocket にも開いた（`ws="special"`、応答は要求した接続へだけ
  `{type:'measure'}`）。計算は `duocad/measure.py` の1箇所で、画面とAIが同じ答えを読む。
- **対象はソリッドの頂点・直線の辺・平らな面と、スケッチの点・線分・領域**（issue #201）。スケッチの点は点の図形・
  線分の端点・円/円弧/楕円の中心・長方形の角・ベジエの制御点で、線分は辺と同じく無限直線、領域はそのスケッチの平面
  として測る。基準平面・面上の任意点・ソリッドの円い辺の中心は未対応。直線でない辺・平面でない面・線分以外の
  スケッチの図形まるごとはコアが `between_error` で断り、画面はトーストで見せる。断られたときは測れない項目
  （`between_error_items`）だけを選択から外し、測れた側は残す。起動中は曲面と円い辺を光らせない・指せない
  （`SelectionArgSpec.shapes`）。待ちの1行に測れる種類を出す。
  画面からはボディそのものを測定に入れられない（`body` 参照を2つ置くと `between_error`）。メッシュボディを指すと、
  選択に入れずにその場で「測れない」と出す。
- **直線と平面は無限に延ばして測る**（有限の辺・面どうしの最短距離ではない）。**平行でなければ距離の代わりに
  角度**（0〜90度）。点と点は距離に加えて Δx/Δy/Δz。**読み札は点と点以外の組の名前に「(無限に延長)」を添える**
  （角度の表示にも付く。3Dの札には付けない）。平行判定は sin θ < 1e-6 で、述語 `parallel_to` の許容
  `PARALLEL_TOLERANCE`（内積で 1e-6 ≈ 0.08度。[MCP.md](../MCP.md)「実装のメモ」）とは別に持つ。
- **結果はビューポート上に浮く読み札（`#measure-result`）と、3Dの線+札**（角度のときは線は無い）。`.stage` の
  position:absolute なので新しい帯を取らない。**測った選択が変わるまで残り**、Esc・次のコマンドの起動・
  モード切替で消える。
- **Enter 規則**: `needsEnter` の「対象を複数取りうる」は「上限が無い、または上限が下限より大きい」。
  下限＝上限（ちょうど2つ）は何個で終わりかが機械に分かるので Enter 不要（`tests/test_ui_command_wiring.py`）。
- **測定中は素のクリックで対象を足す**（`toggleOnlyMode`）。置き換えのままだと2つ目のクリックが1つ目を
  消して永久に揃わない。
- **面・辺・頂点を全ボディで、点・線・領域を見えている全スケッチで指せる**（起動中は測定が受け付ける種類だけ。
  docs/VIEWPORT.md「ピック」）。頂点は普段描かず、
  ホバー中と選択中だけ印を出す（全ボディの頂点を出すと27部品では数千の的が画面を覆う）。

## 干渉チェック（issue #186）

**verb ではない**（文書もログも変えない・undo の対象にならない）。方式・定義・許容差は [INTERFERENCE.md](INTERFERENCE.md)。

- **起動は「干渉チェック」ボタン**（測定と同じ `query`）。引数なしでその場で走り、確定の待ち（`pendingOp`）にも待ちバーにもしない
  （数秒〜最大2分かかりうる。走っている間も他の操作ができる）。選択は**残す**（隙間を変えて再検査できる）。
- **対象はコアの選択と可視性で決まる**（本人判断カード2）: 選択なし＝見えているボディ全部の総当たり／1つ＝その1つ対ほかの見えている全ボディ／

- **行を選ぶとその組の重なりの立体（半透明の赤）・接触面（橙）・最短距離の線と札を出す**。もう一度押すと外れる。何も選んでいなければ

  **モード（スケッチ・形状最適化）へ移ると畳む**（文書の版は変わらないので版の見張りでは消えない。検査中なら返事も捨てる）。
  **検査の途中で接続が切れたら、前の結果も消して理由を出す**（前の結果は今回の検査の結果ではない）。

## 待ちの表示（issue #112）

- **出すのは「人が頼み、結果がビューポートに出るまで待たせている」操作だけ**（本人判断 2026-10-13。
  どれもビューポートに出るまで人を待たせる）。verb の確定・取り込み・文書を開く/新規/閉じる・
  サーバで計算するゴースト・選択・表示切替・undo/redo・辺と頂点の取り寄せ・測定・最適化のステップ表示が入る。
  ファイル一覧・保存・書き出し・サムネイル・選択1件の寸法・AI・最適化の実行は入らない（どれを待たせるかは
  `web/src/session.ts` の送る口ごとに決めてある）。
- **確定の応答待ちが 3 秒を超えたら、コマンドの待ちの1行（`#command-prompt`）に「計算中 N 秒」を出す**（新しい部品は足さない）。250ms ごとに
  数え直し、表示は 1 秒単位。応答・失敗・再接続で消える。3 秒は置いた値で実測ではない（重いフィレットは最長 20 秒で断られる）。
  出すのは共有のコマンド（構えた verb）の確定だけで、ローカルのコマンド（測定・ファイル操作）には出さない。
- **ズーム後の作り直し（`set_view_resolution`）は入れない。** 人が頼んだものではなく、古いメッシュは見えたまま
  使える。作り直しの後ろに並んだ選択クリックは、クリックした時点から数えるのでそちらで出る。
- **見せ方はビューポート上端の流れるバー**（本人選択）。待ちカーソル・画面を暗くする・枠を光らせる案と比べた。
  暗くする案はゴーストを数値で調整している間にも暗くなり、「操作できない」と言ってしまう（回転やズームはできる）。
- **数え方**: 待たせる下りに `ack_id` を付け、サーバは処理し終えた後（失敗でも）に `done` を返す。いちばん古い
  待ちが 0.5 秒を超えたら出し、一度出したら最低 0.3 秒は残す。どちらも本人の「0.5秒以上待つ場面」と、
  ちらつかせないための調整値で、測った値ではない。`pendingOp`（Enter の二重確定を断る印）とは別に持つ ——
  `pendingOp` はファイルを開く・undo などでは立たない。
- **`pendingOp` を解くのは、待っている操作そのものの応答か失敗だけ。** エラーの返事は失敗した要求の `client_op` を
  持ち、画面は一致したときだけ解く。確定の直前に送ったプレビューは確定より先に失敗が返るので、
  どの失敗でも解くと、確定がまだサーバで走っている間に次の Enter が通る。
- **応答が返らないときの専用の表示は作らない**（本人判断）。サーバの例外はエラートースト（`done` も来るので
  バーは消える）、待っている間の切断もエラートーストにする。接続が生きたままサーバが固まった場合は
  バーが出続ける（タイムアウトは置いていない。経過秒は新しい部品でなく、上の待ちの1行に出す）。
