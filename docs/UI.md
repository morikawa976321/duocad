# duocad — 画面と操作の判断

**読むとき**: パネル・ツールバー・コマンドの振る舞い・スケッチ入力・見た目を変えるとき。
3Dビューの内側（カメラ・ピック・グリッド・深度）は [VIEWPORT.md](VIEWPORT.md)。
操作手順・キー割当・ボタン文言の正は各コンポーネントのコメント（README §2）。ここに書くのは
**なぜそうしたか**と、コードから読めない判断だけ。個別の見た目の調整（色・寸法・文言）は書かない。

## 方針（README §0 の設計原則の下にあるもの）

- **常設の指標を置かない**（本人）: 実物を見れば分かるものに札を作らない／人の判断に使わない数
  （操作数・ファイルの件数とサイズ）は出さない／札で補わないと伝わらない見え方は見え方の側を直す
  ／状態は常時光らせず、人の手が要る瞬間に言う（接続状態は送れなかったときにトースト）。
- **既定状態は「見ているだけ」**（本人判断）。既定コマンドを常時構えさせない。「通常モードにも『選ぶ』
  コマンドを新設して既定にする」案はボタンが増えるので却下。**確定に成功したら自動で無起動へ戻す**
  （連続作図の操作性を失うのを承知で全 verb 共通。`import_step` / `undo` / `redo` は `CommandHost` を
  経由しないので対象外）。戻すのは**サーバの確認（`client_op` の一致）が返ってから** —— 楽観的発火と同時に
  落とすと、失敗応答で入力欄を復元しても欄自体が DOM から消えている（OCCT のフィレットは限界半径で失敗
  しうるので「打ち直す」が必須）。
- **現段階の duocad は複数パーツ運用を最適化しない**（本人）。パーツ一覧の pick 列と「選択したものだけ表示」は削除済み。
- **一度決めたら触らない設定は設定ダイアログ1枚に平らに並べる。** スキーマ駆動・カテゴリ・タブは作らない。
  作業中に切り替えるものはその場のパネル。見ながら決める設定（FOV）のために覆わない・暗くしない・即座に効く。
- **プレビュー（確定前の幽霊）はつけられる操作には基本的にすべてつける。** 方式は**ブラウザだけで描く
  ローカル**（`preview: 'local'`）。位置や図形しか変わらない verb は投機実行しても「形が変わった Body」が
  返らず応答が常に空になるので、サーバの投機実行は増やさない。
- **モーダルを使わない。** 設定ダイアログは `show()`（非モーダル）。`showModal()` は背後を inert にして
  「見ながら回して確かめる」を殺す。フォーカストラップは戻さない。
- **既定の透視は30度、UIは正投影/透視の2値**（本人）。**「実用上の差が無い」は「弁別できない」ではない**
  （本人が明示的に訂正）—— 30と45には見た目の差がある。内部 API（`setFov` / `isSelectableFov`）は 0 または
  30〜90 を受け付けたまま。
- **その瞬間に要るものだけを出す**（本人）。**出し分けの主軸はモード**で、要らない側は無効化ではなく画面から消す。
  使うかもしれないものは認知負荷を上げない配置か開閉可能にする。

## パネルの配置

- **左サイドバー＝ファイルパネル（開閉可）、ビューポート左上に浮くブラウザ（モデル/スケッチ）、右サイドバー＝
  AI パネルだけ（開閉可）。** ブラウザは「モデル」「スケッチ」の2区分をフラットに並べる（入れ子のツリー化と
  コンストラクションを足すときに一覧を作り直さないため）。
- **ブラウザの行は、指したときだけ右端に ✎(名前を変える)と ✕(消す)を出す。** ✎ は行の中に入力欄を開く
  （ダブルクリックにしないのは、スケッチ行の1回目のクリックがスケッチに入ってしまうため）。✕ は確認を
  挟まない —— `delete_items` は1回の Ctrl+Z で戻る。名前の既定はボディとスケッチで独立した通し番号
  （一度振った番号は再利用しない。`duocad/naming.py`）。
- **ファイルパネルは左サイドバーが正**（ツールバー統合は退けた）。**左サイドバーの既定は開いた状態**。
- **ファイル一覧の1行は「サムネイル・ファイル名・作成日時・更新日時」＋複製・削除。** サムネイルは画面が撮り
  （`web/src/thumbnail.ts`）、`models/.thumbnails/` の付随ファイルに置く。作成日時は文書のJSONの `created` が
  持つ —— 保存は一時ファイルの差し替えなので、ファイルシステムの作成時刻は毎回「最後に保存した時刻」に
  なる（Windows 11 / NTFS で実測）。`created` を持たない既存ファイルは「—」（更新日時で埋めない）。
- **STEP 読み込みはツールバーの verb、STEP/STL 書き出しはファイルパネル。** 線は「文書を変えるか」。
- **常設パネルを足すときは画面に新しい帯を取らない。** 形状最適化の実行パネルをブラウザの右へ足したら
  その帯の下のボディが1面も指せなくなった。**モードのあいだ出しっぱなしの
  パネルは、モデルを覆う位置に置けない。** 一時的なダイアログは別の帯へ出してよい。
- **選択パネル・操作履歴パネルは削除済み。** 履歴の行クリックで一括 undo はコアの機能追加になるので見送り。
- **選択情報はビューポートの左下**（issue #140。`SelectionInfoPanel.svelte`）。**選択がちょうど1項目のときだけ**
  種別・参照名と寸法を出し、空・2項目以上では何も出さない（本人判断。2項目のあいだは「測定」コマンドが上中央に出す）。
  右下はトーストと重なるので避けた（本人）。形状最適化のあいだは同じ左下の実行パネルの右へずれる。
  - 値は `measure` の1項目そのもの（WS の `inspect_selection`）で、画面で幾何を計算しない —— AI が読む値と同じ。
    足りなかった面の種類・円の辺の半径と中心・スケッチの線分の長さは `measure` 側に足した。
  - クリックを吸わない（`pointer-events: none`）。左下はモデルが来る位置なので、吸うと札の下の面が指せない。
  - 選択は人と AI で共有なので、AI が選択を変えても同じ道で追従する。取り直すのは選択か文書が変わったときだけ
    （状態はズームの粗さが変わっても届く）。
- **右サイドバーは AI 専用。** スケッチモードの操作はコマンドツールバー側。
- **断面はブラウザの「原点」の下の「断面」グループ。** チェックで入れ、入れている間だけ平面・位置・反転の
  操作子を出す。verb ではないのでツールバーにも AI（MCP）にも出さない。キー割当は無い。
  **代償は、切っていない間もブラウザが見出し1行ぶん縦に伸びること。** 実機検査のクリック・
  右ドラッグの始点がブラウザの下に入って落ちるので、押す前にブラウザを畳む（`browser.mjs` の `withoutBrowserPanel`）。
  - **平面（XY / XZ / YZ）はパネルのボタンで選ぶ。** README §0 原則1とは緊張するが、基準平面のピックは
    スケッチの貼る先待ちの間だけ生きる経路で、大きいモデルでは原点が埋まって指せない。
  - **状態はその場限り**（文書にも localStorage にも載せない）。スケッチ・形状最適化のモードに入っても切ったまま。
  - 入れた瞬間・平面を替えた瞬間の位置は、表示中のボディ（幽霊を含む）の外接箱の中心。反転なしで消すのは
    **ホームビューのカメラ側**（`HOME_VIEW_OFFSET` の符号から導く）。
  - 平面は枠線だけで塗らず、クリックを吸わない。掴めるのは法線方向の矢印だけ（板全体を掴む形は、板の画素で
    モデルが指せなくなる）。切り口は1色（`SECTION_CAP_COLOR`）で、選択色には追従しない。
- **新規ボタン**（`new_document`）は確認ダイアログを挟まない —— 一覧のクリック1つで別の文書へ移れる
  （未保存の編集が消える）のに空の文書へ移るときだけ確認すると挙動が割れる。**AI には開けない**（`mcp=False`）:
  今の文書を丸ごと捨てて undo でも戻せないので、捨てる判断は人がする。
- **何も開いていない状態（トップ画面）を持つ。** サーバはこの状態で起動し（`Session(opened=False)`）、
  ファイルパネルの「閉じる」（`close_document`）と開いている文書の削除でも戻る。
  - グリッド・原点・ビューキューブ・ツールバー・ブラウザは文書に属するものとして全部隠す（空の無題の文書と
    見た瞬間に区別できるため）。`StartScreen.svelte` が最近の文書8件のカードと「新規」だけを出す。
  - 閉じている間、文書を変える操作はどの口（画面・MCP・アプリ内AI）からもサーバが `NoDocument` で断る。
    素通しすると最初の変更で `untitled-<n>.json` が作られ、黙って無題の文書に変わる。AI は
    `describe_document` の `document_open` で知る。
  - 開いている文書の削除は、ファイルを消してから閉じる。中身を残して無題に戻すと、次の自動保存が消した
    はずの中身を別名で復活させる。
  - 「STEP/SVG から新規」は置かない（読み込みはサーバ側のパスを打つコマンドで、ファイルを落とす口が無い）。

## コマンド層

- **点から導ける寸法欄は how に数えない**（`fromPoints`。README §0 原則3）。空欄なら集めた点から導き、打てば
  それが勝つ。確定に使う引数を `built ?? ghostBuilt` にして経路を一本化している。代償は**層をまたぐ契約が
  1本増える**こと —— プレースホルダの「いまマウスが指している値」は確定用の引数から名前で引くので、UI の
  欄名がサーバへ送る引数名と一致しない寸法（線分の長さ・角度は `p0`/`p1` へ畳む）は追従しない。
- **対象とは別に「既存の図形/面への参照」を引数で受ける verb**（`move_body.axis_edge` / `center_vertex`、
  `mirror_body.plane_face`、`mirror_sketch_entities.axis`）は `PickArgSpec`（`commands/command.ts`）に乗せる。
  必須のピックは対象の最小数が満たされた瞬間に構えられ素のクリックを全部吸うので、**修飾キー付きクリックは
  ピックへ行かせない**。ピックを `optional` にする案（必須が「(任意)」と出る）、対象の上限を1にする案
  （仕様を曲げる）は採らなかった。
- **モードは verb の上位次元**（[DESIGN_DECISIONS.md](DESIGN_DECISIONS.md)）。`App.svelte` のモードはタグ付き
  ユニオン1変数（`idle` / `sketch-pending` / `sketch` / `optimize`）。**モードに紐づく状態の掃除は
  「出口」ではなく「入口」に置く** —— 入口（再開・直接切り替え・undo での復帰）は後から増える。
- **確定前の幽霊が無関係な再配信で消えたまま戻らない（未解決）。** カメラを動かすと可変解像度が
  `set_view_resolution` を送り、形が変わっていなくても状態が配信し直され（[VIEWPORT.md](VIEWPORT.md)）、
  `viewport.update()` が幽霊を消す。幽霊は引数が変わらないと描き直されない（`CommandHost` の `previewedKey`）。
  塞ぐなら「最後のローカルプレビュー要求を控えて `viewport.update()` の後に描き直す」形だが、
  `preview: 'local'` の全 verb の挙動が変わる。実機検査は「状態配信が止まるまで待ってから打つ」で避けている。
- **`move_*` の空欄の軸を 0 として扱う判断（本人）はコードに入っていない。** 入れるなら**この2 verb の
  dx/dy/dz だけに絞る** —— 半径・距離・個数のような「空欄＝まだ決めていない」引数に黙って 0 を埋めると壊れる。
- **数値欄は数式を受け付ける**（`web/src/expression.ts`）。三角関数の引数と逆三角の戻り値は**度**（本人選択）。
  関数セットは四則・単項マイナス・括弧・`^`・`sqrt`・`abs`・`pi`・`sin/cos/tan`・`asin/acos/atan/atan2` で、
  **`hypot` / `min` / `max` / `round` / `floor` / `ceil` は本人が明示的に除外**（`log` / `exp` / 剰余も無し）。
  文書パラメータの参照は入れていない（`set_parameter` は公開面から外してあり UI にもパラメータ欄が無い）。

## スケッチ入力（本人判断、Fusion に揃える）

- **寸法はもう1つの点で決まる**（長方形＝対角、円＝円周の1点）。数値欄は残し、空欄ならマウス追従・
  打てばそれが勝つ。長方形・円は2クリック、円弧は3クリックで確定（Enter を押さない）。verb の契約は変えず UI 層で閉じる。
- **円弧は「始点 → 終点 → 円弧上の1点」の3クリック（中心は入力しない）。** 中心から始める形は「円と線分で
  代用できる」ので採らない。3点目を中心にしないのは、中心は弦の垂直二等分線上にしか置けず、「膨らむ向き」と
  「劣弧/優弧」を同時にマウスで選べないため。
- **線分には長さ・角度の数値欄**（角度は度・反時計回り・X軸から）。
- **スナップ3段**（描く verb が点を待っている間）: 既存の点マーカー → 既存の図形の線 → **1mm グリッドの
  交点へ丸める**。1mm は `gridScale.ts` の `TIERS` の最小段で絶対値固定。**マウスだけでは非整数の座標が
  置けないのは意図した挙動**（端数は寸法を打つ）。**スナップを切る修飾キーも、ズームで刻みを変える仕組みも
  作らない**（視点に依存すると同じ操作が違う結果になる）。スナップは拘束ではない。
- **スケッチの図形・点にはホバー強調を出し、描く verb が点を待っている間も出す**（「既存の選択ゲートに従う」の例外）。
  スナップが入ると強調の意味が「クリックすればここに乗る」に変わり、どちらでも予告として正しい。
- **長方形の残り3隅と図形をまたぐ交点（線分・円・円弧。ベジエは対象外）は本物の点と同格に吸着する。**
  交点は `SketchEntityHit.snapAt`（厳密座標）で運ぶ —— 片方の図形への射影に任せると連続的な最近傍点になり
  交点からずれる。
- **pointKey が1個しかない種別（rectangle / circle / arc）は点マーカーを選択中・ホバー中だけ出す。**
  「その点だけ動かす」と「図形全体を動かす」が同じ処理（`_moved_params`）なため。線分・ベジエは常時出す。
- **スケッチ開始は「ボタン → 貼る先をクリック」の2手**（基準平面も任意の面も同じ。Enter を挟まない）。
- **スケッチを抜けたら入る前の視点へ戻す**（本人）。**再フレーミングを通常編集（押し出し・フィレット）へは
  広げない。** `open_document` は再フレームする、`new_document` はしない。
- **選択の修飾キー: Shift も Ctrl も「トグル」に統一**（除外専用は無意味）。無修飾は置き換え。
- **コマンド起動中は素クリックもトグル、終わったら選択を全解除。選択に出所の区別は無い。** 決定と本人の原文は
  [DESIGN_DECISIONS.md](DESIGN_DECISIONS.md)「隠したボディ・選択・可視性」。実装: 素クリックは `toggle_selection` を送る。
  終わりは Esc・中断ボタン・確定成功・別 verb への乗り換え（`App.svelte` の `onCommandEnd` / `onCommandStart`）。
  `PickArgSpec` の素クリックは従来どおりピック引数が食う。ドラッグ選択（矩形）は共有の `toggleOnlyMode` を通る。
- **スケッチモードの「選ぶ」ボタンは人向けの画面から外す**。コマンド定義・既定コマンド・Esc/確定後に戻る
  挙動は AI 用に残す（`CommandDef.hidden`）。

## 見た目

- **文字の大きさは2段だけ**（`--fs` 本文と操作子、`--fs-meta` 添える情報）。**ラベルであることは色（`--dim`）で
  言い、大きさでは言わない。**
- **操作子は線ではなく面で見せる。** `--line` は区画境界専用、打ち込む欄は凹み（`--input-bg`）、押すものは
  出っぱり（`--control-bg`）。**枠は常に 1px ぶん確保して色だけ変える** —— 太らせたり消したりすると行高が動き、
  ビューポートの実寸（＝カメラのアスペクト）が動く。
- **border の無い flex 帯の中の区切り線は `position:absolute` の疑似要素で足す**（`.toolbar` は `flex:0 0 auto`
  なので border/padding で高さを増やすとビューポートの実寸を圧迫する）。
- **ホバー強調は新しい色を足さず明度を上げる**（選択済みにも同じ）。色相が「選択されているか」（橙）、明度が
  「今カーソルの下にあるか」。頂点は対象外・カーソル下の1つだけ・基準平面は半透明の板1枚。
- **フォントは PlemolJP Console を同梱・固定**（本人「いったんこれで」＝暫定）。
- **原点ギズモ**（issue #8）: 原点の点・XYZ 軸・3平面の7項目はブラウザの「原点」1行でまとめて表示切替。
  文書の状態ではなく画面設定（`viewSettings.ts`）。
- **エラーはすべてトースト**（右下 —— 右上だとAIパネルとかぶる）。クライアント側で先回り判定はしない —— 判定は
  コアの1箇所、UI は結果を見せるだけ。接続の切断自体はトーストにしない（自動再接続）。開けなかった試行は
  初回待ちが3回（`CONNECT_FAILURE_NOTICE_AT`）、一度繋がったあとの再接続失敗は1回目
  （`RECONNECT_FAILURE_NOTICE_AT`）。時間で切らないのは、繋がらないソケットの `onclose` に約2秒かかり再接続の
  実周期が 5〜26 秒まで伸びるため。

## 測定（issue #10）

**verb ではない**（文書もログも変えない）が、verb→target の枠（`CommandHost`）に乗せた。

- **起動の形は「測定」ボタン。** 「選択がちょうど2つになったら常に距離を出す」案は「状態を常時光らせない」に
  反するので退けた。既に2つ選んであれば押した瞬間に測る（**読み取り専用だけの例外**。他の verb は起動時に
  揃っていても発火しない —— AIが選んだ面のまま押し出しを押しただけで形が変わるのを防ぐため）。
- **サーバ側の口は既存の `measure` を拡張**して WebSocket にも開いた（`ws="special"`、応答は要求した接続へだけ
  `{type:'measure'}`）。計算は `duocad/measure.py` の1箇所で、画面とAIが同じ答えを読む。
- **対象は v1 ではソリッドの頂点・直線の辺・平らな面だけ。** スケッチの点と線・基準平面・面上の任意点・円の
  中心は v2。直線でない辺・平面でない面はコアが `between_error` で断り、画面はトーストで見せる。
  画面からはボディそのものを測定に入れられない（`body` 参照を2つ置くと `between_error`）。
- **直線と平面は無限に延ばして測る**（有限の辺・面どうしの最短距離ではない）。**平行でなければ距離の代わりに
  角度**（0〜90度）。点と点は距離に加えて Δx/Δy/Δz。平行判定は sin θ < 1e-6 で、述語の
  `PARALLEL_TOLERANCE`（1e-3 ≈ 2.6度）とは別に持つ —— あれで「平行」にすると2度傾いた面どうしに距離が出る。
- **結果はビューポート上に浮く読み札（`#measure-result`）と、3Dの線+札**（角度のときは線は無い）。`.stage` の
  position:absolute なので新しい帯を取らない。**測った選択が変わるまで残り**、Esc・次のコマンドの起動・
  モード切替で消える。
- **Enter 規則**: `needsEnter` の「対象を複数取りうる」は「上限が無い、または上限が下限より大きい」。
  下限＝上限（ちょうど2つ）は何個で終わりかが機械に分かるので Enter 不要（`tests/test_ui_command_wiring.py`）。
- **測定中は素のクリックで対象を足す**（`toggleOnlyMode`）。置き換えのままだと2つ目のクリックが1つ目を
  消して永久に揃わない。
- **辺・頂点を指せるのは対象ボディ1つぶん**（`edgeTargetBody`）。全ボディの頂点を出すと27部品では数千の的が
  画面を覆う。面は全ボディを指せる。別ボディの辺・頂点どうしは v2。
