# duocad — 3Dビューポート（カメラ・ピック・グリッド・深度）

**読むとき**: `web/src/viewport.ts` とその兄弟（`planeGrid.ts` / `gridScale.ts` / `viewCube*.ts` /
`faceCulling.ts` / `screenPick.ts` / `sectionView.ts`）を変えるとき。当たり判定は screen 半径[px]で揃える
（正は `web/src/screenPick.ts` と `tests/eval_screen_pick.mjs`）。
実装の詳細はコードのコメントが正で、ここは**判断の理由と実測**。

## 不変条件「見えるもの＝指せるもの」と深度の規約

three.js の線のレイキャストは面による遮蔽を見ないので、見た目だけ隠すと「見えない辺が選ばれる」になる。
本当の不変条件は深度ではなく**見えるもの＝指せるもの**で、z-fighting が起きないのはその副産物。
判定は「そのオブジェクトはピック対象か」の一問:

- **A群（ピック対象）** — 辺・領域・スケッチの線と点。`depthTest:false` ＋ `depthWrite:false` ＋ renderOrder の階段。
  実体を透過するのは仕様。
- **B群（装飾。ピック対象でない）** — 床グリッド・面グリッド・原点ギズモ。深度検査あり・書き込みなし ＋
  **クリップ空間の深度バイアス**でカメラ側へ寄せる（`planeGrid.ts`）。
- **C群（実体）** — 何も指定しない。

基準平面のグリッドはスケッチ対象待ちのときだけピック対象になるが**表示は常に B群**（ピックは別経路のレイ検査）。
**使わないと決めたもの**: 法線方向へのワールドオフセット（ズームで破綻し、描画とレイ検査がずれる）。
`polygonOffset`（WebGL は `POLYGON_OFFSET_FILL` しか持たず線に効かない）。`renderer.reversedDepthBuffer`
（three 0.185.1 に実体はあるが `@types/three` の型に無く、B群の自前 `gl_FragDepth` が黙って壊れる）。
ビューキューブは同一 canvas の第2パスで `clearDepth()` してから描くのでこの規約の外側。

## カメラ

- **Z-up 右手系**（X右/Y奥/Z上。Fusion・Blender・Cura と同じ）。直したのはカメラの up だけで、ジオメトリに
  回転や軸入替は無い。
- **near/far は初回フレーミングから分離して常時引き直す**（`updateClipPlanes`）。一発フラグに相乗りさせると、
  後から入れた大きな STEP（対角約640mm）が**平面で削られて**見えた。「初回だけでよいもの（姿勢）」と
  「常時追随すべきもの（視錐台）」を同じ一発フラグに乗せない。
- **カメラを動かすと、見ているボディ自身が配り直される。** 版の鍵 `body_recipe` に目標精度と面単位の `focus`
  （視錐台に入り正面を向く面の集合）が入っているので、**形が変わっていなくても版が上がって再テセレーションが
  配信される**（右ドラッグ後、約500msで revision が上がる）。**「この配信で形が変わったか」をブラウザ側から
  判定する口は無い** —— `applied === null` も使えない（MCP 起点の変更と形状最適化の完了配信がどちらも
  `applied=None` で本物の形を配る）。
- **減衰つきのカメラは正確には止まらない。** `enableDamping` は指数で近づくので位置も四元数も下位桁が動き続け、
  姿勢の一致を「止まった」の条件にすると可変解像度が採り直されなくなる。閾値で見る。
  **閾値は画面の画素で決める**（位置は `worldPerPixel * 0.5`、向きは四元数内積 `1-1e-7`、倍率は相対差）。
- **`fitDistance` を経由しない距離の決め打ちを残さない。** 起動時カメラ位置が `diagonal * 1.2` を独自に持ち、
  既定 FOV を 45→30 に変えたとき `fitDistance` と 55% ずれて実機検査が原因を名指ししない形で落ちた。
  既定値を変える前に `grep -rn "diagonal \* [0-9]"` で独自再計算を確認する。
- **球にちょうど収まる距離 `R / sin(fov/2)` は、球でない凸体を対角からずれた向きで見ると FOV が大きいほど縮む**
  （ビューキューブで対角±22°ずれ、FOV 30→90 で一辺が約18%縮む）。UI の FOV が 2値になり 90 が選べなくなって
  実用上は解消。

## ボディの描き方(issue #171)

- **1ボディ = 三角形メッシュ1つ + 境界線1つ**(`web/src/bodyMesh.ts`)。面は頂点の範囲で区別し、色は頂点色で塗る
  (材質は滑らか・平らの2つだけ)。面ごとに Mesh を持つと PC ケースで 5,670 オブジェクトになり、静止中も主スレッドが
  12 ms/フレーム埋まっていた。three.js の材質配列 + groups は group ごとに描画項目になるので使わない。
- **境界線は面ごとに `EdgesGeometry`(閾値 20 度)を取って繋ぐ**。ボディ全体に掛けると、接線で続く面の境目が
  面の内側と同じ扱いで消える(面ごとのときは隣の面と頂点を共有しないので、面の縁はどれも線になっていた)。
- **面ごとの外接球と境界線は、面の頂点の配列ごとに覚える**(`bodyMesh.ts` の WeakMap)。カメラで測り直した面だけが新しい
  配列で届き、残りの面は前回と同じ配列が使い回される(配信は前回送った面を省く: `web/src/wire.ts`)ので、ボディを作り直しても
  変わらない面の計算を繰り返さない。
- **ピックは面ごとの外接球で絞ってから三角形に当てる**(`Mesh.raycast` の差し替え)。当たりの三角形番号から面の
  添字へは三角形ごとの表で戻す。BVH は入れていない(面ごとに Mesh だったときと同じ絞り方で足りている)。
- **必要なときだけ描く**: 公開口の呼び出し・ポインタ・ホバーの変化・カメラの移動があったフレームだけ描く
  (`viewport.ts` の「必要なときだけ描く」)。カメラは 1e-6 の許容で比べる(真上から見る極の近くでは `OrbitControls` が
  毎フレーム行列を 1e-8 ほど揺らし続ける)。ビューキューブは本描画の上に色を消さずに重ねるので、本描画と同じフレームでだけ描く。

## ピック

- **面と基準平面はレイ距離で競わせない。面に当たる画素では面が勝ち、基準平面は面の無い画素でだけ取れる**
  （#109、本人判断 2026-10-07）。距離で競わせると壊れる:
  - 基準平面の当たり範囲はモデルに追随して覆うので、ホームビューのカメラから原点をはさんだ反対側の面への
    レイは必ず先に座標平面をくぐり、面が見えているのに指せなかった。
  - 基準平面に描いて押し出した面は基準平面と厳密に同一平面で、素の `<` では勝敗が浮動小数の最後の桁で決まった
    （カメラ位置が 7e-14 ずれただけで面が XZ 平面に化けた）。
  代償として、部品のシルエットに重なる部分の基準平面は指せない。断面の切り口（`faceHitAt` の `ref: null`）も
  面と同じく基準平面を塞ぐ。
- **固定の優先順位の下では、上位の的に常に乗っている下位の的は一生指せない**（頂点は必ず辺の端点にあり、辺が先。
  `move_body` 起動中は回転中心の頂点が 100% 辺に取られ、症状は「クリックしても何も起きない」だけ）。解き方は
  「外したときに何が起きるか」で選ぶ: 要求している間だけ順序を入れ替えるゲート（`preferVertices`。外しても
  何も起きないならこれ）／要求している間だけ上位の的を画面から引っ込める（外すと共有選択が書き換わる種類の
  衝突ではこちら）。
- **`clickable(x,y)` が単一の choke point。** 浮かせた DOM パネルは `elementFromPoint` で判定できる
  （`pointer-events:none` のトーストは自動的にすり抜ける）が、**同一 canvas の第2パス（ビューキューブ）は
  `elementFromPoint` が canvas を返し続ける**ので矩形の明示的な除外を足した。新しい「吸うオーバーレイ」が
  増えたらここへ条件を足せば、ピック・矩形選択開始・ホバー予告の全部に波及する。
- **ホバーのキャッシュは「ポインタ＋カメラ」の鍵では不足。** 当たるものはポインタも視点も動かないまま変わる
  （ゲートの開閉・選択によるマーカーの増減・プレビュー・寸法変更）。「何が指せるか」を変える側が増やす
  **世代番号**を鍵に混ぜる。無効化は参照を捨てるだけでなく材質を戻すところまで。
- **辺の screen pick は全走査で足りる**（27部品の最大ボディ 233面・辺645本、1280×860 で p95 0.7ms。基準
  「16ms の p95 超過なら二段階化」に20倍以上の余裕）。効いているのは「1回に走査するのは1ボディぶんだけ」。
- **`projectRegion` は三角形あたり4点（重心＋各頂点へ寄せた3点）を試し、実際のクリックと同じ判定を通す。**
  ベジエの制御点が重心の5画素以内に来て候補が尽きた。「その画素で本当にそれが取れるか」を答えるヘルパは、
  ピックの優先順位を1つ足すたびに検算の条件も足さないと嘘をつき始める。

## グリッド（本人判断）

- **刻みは 1mm / 10mm / 100mm の3段固定。** 内容から刻みを導く方式は画面から縮尺が失われた。段の不透明度は
  画面上の線間隔[px]だけから決まる1本の規則（目安 1.5px で 0・6px で 1）で、**連続フェードにすればヒステリシスは
  要らない**。判定は必ず投影後の px（FOV は 0 もあるのでカメラ距離では正投影で破綻）。
- **無限グリッドは「指せる範囲」で切る。** 基準3平面を同時に出すとビューポートが白い線で埋まった。その平面が
  指せるときだけピック範囲（±extent）で切り、装飾だけのときは無限でよい。
- **ピック範囲の枠はワールド原点を含める**（本人「普通は原点付近にモデリングするので問題ない」）。代償: 原点から
  400mm 離れた 60mm 角の箱で枠が 600mm 角。面グリッドは `includeOrigin:false` で面自身の範囲が正
  （`extentFor()` は `BASE_EXTENT`=100mm を下限に持つので面のスケールで再利用すると 40×20mm の面に 100mm が
  返る。`snap125()` を直接呼ぶ）。
- **スケッチ中のグリッドは、スケッチ自身のframeに出す。** 基準平面からのオフセット（`sketch_create_offset`）は原点が法線方向に
  ずれているので、原点を通る基準平面のframeで描くと、XZ・YZ のオフセットではスケッチ平面に正対したとき床が真横になって
  グリッドが出ない（`tests/eval_grid_planes.mjs`）。向きが基準平面と一致するときだけ軸の色と面外の軸を出し、面からの
  オフセット（向きが合わない）は軸なしでそのframeのグリッドだけを出す。
- **格子の u=0 / v=0 の線は無条件に抜く。** 3平面を同時に出すと格子の v=0 線が軸と完全に一致し、後から描いた
  灰色が色付きの軸を上書きする。描く順序では「どれかの軸が必ず負ける」。

## 可変解像度と面カリング（RTX 5060 Ti・headless Chrome・1280×860・PCケース 27部品2835面の実測）

文書全体で1つの目標精度（画面誤差 0.35 画素から導く）は深いズームで破綻する。全体 65,707 三角形・測り直し
2.8秒に対し、30段ズームインで 1,180,763 三角形・14.5秒（サーバは単一イベントループなので、この間セッション
全体が応答しない）。画面に出ていない部品まで同じ細かさで測るのが効いている。**相対下限
`DEVIATION_MIN_RELATIVE` を上げて誤魔化さない**（大きなモデルの小さな造作へ寄ったとき角が見え、可変解像度の
目的を壊す）。

対処は **face 単位の視錐台＋バックフェイス**（オクルージョンは実装しないと本人決定）。30段ズームで
三角形 1,180,763→205,534、細かく測った面 2835→231、往復 16.3→4.0秒（全体視点は 2.1→1.8秒）。
効いている仕掛けは3つで、どれか1つ欠けると効果が消える: (1) 粗い側の精度をズームに依存させない（画面外の Body の
「測り方」が変わると版が上がり全部配り直す）(2) 版とキャッシュの鍵を「実効レシピ」にする（全面を粗く測る Body
の鍵に細かい側の値を入れない）(3) 判定は画面側（カメラを持つのはブラウザだけ。プロトコルは `set_view_resolution`
に `focus` を1つ足しただけ）。**バックフェイスは閉じた立体の平面 face にだけ使う**（開いたシェルは裏が本当に
見える。曲面は「中央の法線」が面を代表しない）。残る代償: 細かい面と粗い面が曲線の辺を共有すると境目に隙間が
開きうる（画面の縁とシルエットなので塞がずに置いてある）。

**面単位のキャッシュ（issue #166）**: サーバは面の三角形を測り方 `(偏差, 角度偏差)` ごとに覚え、測り方の変わった面だけを
測る（`view._FaceTessellations`。形はボディごとに3つ、測り方は4通りまで）。目標偏差は `2^(k/4)` の段へ細かい側に丸める
（画素の長さは同じ視点へ戻しても最後の桁が変わり、丸めないとキャッシュの鍵が毎回外れる）。代償: 別々の回に測った面どうしは、
同じ細かさでも境目の折れ線の分割が揃わず、小さな隙間が残りうる（上限は偏差の2倍程度。偏差が画素から決まっている間は
0.35 画素以下なので 1 画素未満で、面の境目には境界線を描くので見えない）。**偏差が下限に張り付く深いズームでは画素に対して
大きくなりうるので、細かく測る面の組は同じ回に測ったものだけで組む**（足りなければ組ごと測り直す。画面は下限に張り付いた・
離れたことを、偏差の比が作り直しの閾値に届かなくても知らせる: `resolutionTracker.ts`）。従来から細かい面と粗い面の
境目には粗い側の偏差ぶんの隙間を許している。判断の記録は [decisions.md](decisions.md)。

## ビューキューブ（本人採用）

- 方向認識の問題への対策は**ビューキューブ1つで打ち止め**（本人「それ一つでほとんどの問題が片付くから」）。
  26領域（6面+12辺+8角。14領域案は退けた）。表示 ON/OFF は作らない。ドラッグ自由回転は Pointer Lock
  （本編の右ドラッグには効かせない）。
- 見送った3件: スケッチのタグに面名・法線／正対時の `camera.up` を人間規則で固定／照明をワールド固定のキー＋フィル。
  **照明だけはキューブと守備範囲が重ならない**（ヘッドライトでは平行な面・浅い段差・面取りとフィレットの区別は
  視点の手当てでは原理的に良くならない）。本人は承知で「実際に使って困るかを見る」順序を採った。
- **投影は本編の FOV に追従**。透視の距離は `R / sin(fov/2)`（R=√3）。素朴に「半幅 1.8 を画角で割る」と
  FOV 90 で手前の角が near に食われて消える。near/far はカメラ距離から導いて引き直す。
- **スケッチ中にキューブが天地逆になった原因**は `lookAtSketch` が `camera.up` にスケッチ平面の v 軸を焼いて
  いたこと。`OrbitControls` は生成時の up を一度だけ焼き込むので、回転軸（常に Z）と食い違う。
  `upForDirection`（真上・真下付近だけ ±Y）を `lookAtSketch` にも使う。

## 断面（issue #6、2026-09-16）

- **切るのは材質の `clippingPlanes`**（`renderer.localClippingEnabled`）。`renderer.clippingPlanes` は全材質に効き、
  グリッド・スケッチ・原点ギズモ・キューブまで切れる。切るのはボディの面・境界線・選べる辺・頂点マーカー・幽霊で、
  どれも `sectionView.ts` の共有配列を持つ（OFF のあいだ空）。スケッチ・領域・グリッド・原点ギズモ・形状最適化の注記・測定の線と札は切らない。
- **切り口はステンシルの偶奇で塗る。** ボディの全三角形を色も深度も書かずに `InvertStencilOp` で描くと、平面上の点が
  そのボディの内側にある画素だけ反転が奇数回残る。そこへ `NotEqual 0` の板を描く。巻き順を見ないので面の向きが
  揃っていなくてよい代わりに、**閉じた立体でしか正しくない**。反転するビットはボディごとに分ける（同じビットだと
  重なった2つのボディの断面が打ち消し合う）。判定メッシュは ON の間だけボディごとに1本へ結合して作り、形が配り直される
  たびに作り直す。レンダラの `stencil: true` が要る（[WEB_PITFALLS.md](WEB_PITFALLS.md)）。
- **「見えるもの＝指せるもの」はピック側で保つ**（レイキャストはクリップ平面を見ない）。面は `faceHitAt` がレイの
  平面をよぎる距離で当たりを捨て、切られた側から入るレイは「そのボディの表面を平面の手前で奇数回またいだか」で
  切り口に当たったと見なす（描画の偶奇と同じ規則）。切り口は指せないが奥の面と基準平面を隠す。辺は折れ線を平面で
  切り詰めてから画面距離を測る（端点ごとに落とすだけだと切り口の手前の見えている部分が指せなくなる）。
  頂点マーカーと矩形選択は切られた点を数えない。
- **ハンドル（法線方向の矢印）は A群**で、`clickable()` がその画素を外す。押下はキューブと同じく
  `setPointerCapture` で引き取る。ドラッグ量はポインタのレイと法線軸の最近点で決め、視線と軸が約6度以内だと
  発散するので動かさない。大きさは画面の画素で一定（点ごとに1画素の世界長さを測る。注視点の `worldPerPixel` では
  ハンドルの奥行きでずれる）。**平面の枠は B群** —— 原点を通る断面では床のグリッド・原点ギズモの平面と同じ平面に
  乗るので深度バイアス層 `sectionFrame` を持つ。

## 調査の順序

**ビューポートの見た目異常（グリッド・軸線が変なところで切れる等）は、グリッドやカメラのロジックを疑う前に、
クライアント（dev サーバ・ブラウザタブ）が複数同時に立っていないかを先に確認する**（実際に原因だった）。
