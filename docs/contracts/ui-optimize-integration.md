# メッシュ body 種別・最適化の配線と実行 UI の契約

形状最適化の結果を文書に入れるための「メッシュボディ」種別、最適化バックエンド（二値探索 `binary_search.find_best_feasible`）を `Session`/WebSocket/画面へつなぐ配線（`duocad/optimize_run.py`）、
実行パネル（`OptimizePanel.svelte`）について、ソースを読んでも分からない不変条件・依存禁止・罠を、元の作業タスクの契約から分野別に蒸留した文書。
**いまの挙動の正はコードとテスト**。最適化アルゴリズム本体は [../TOPOPT.md](../TOPOPT.md) と `TOPOPT_*.md`、画面は [../UI.md](../UI.md)。デバッグビュー（`?debug=` `?voxel=1`）は ui-selection-viewport.md。

出典は項目末尾の括弧 `(タスクID, YYYY-MM-DD)`。日付はタスクIDの先頭8桁。

## メッシュ body 種別（`duocad/document.py` / `meshbody.py` / `verbs/add_mesh.py`）

- **ボディ種別は `document.MESH_KIND`（`"mesh"`）**。`SOLID_KIND` と合わせて `_VALID_KINDS` は2つ。種別の綴りを文字列で書かず定数を import する。形は `Body.mesh`（frozen dataclass `Mesh`: `positions` を x,y,z 平坦、`indices` は**0始まり**で3つずつ。`vertex_count`/`triangle_count`）。**`Body.shape` は常に None**（両方持つ Body は `__post_init__` が弾く）。素の並びから作るのは `document.make_mesh`。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- **メッシュボディを作る唯一の口は verb `add_mesh_body`**（コア `verbs.add_mesh_body(doc, positions, indices, name=None)`、`Session.add_mesh_body`、MCP ツール `add_mesh_body`）。**WebSocket には開けない**（`catalog` の `ws="none"`）。画面は三角形を作らず、結果は `run_optimization` がサーバ内で入れる——1703 の「1705 が `ws` を開ける」は必要になればという条件付きで、必要にならなかった（2026-09-05 の判断）。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04; 20260904-1705-duocad-optimize-run-ui, 2026-09-04)`
- verb を1本足すと `tests/test_mcp_verbs.py` の `test_tool_names_match_the_verb_names_in_the_operation_log` が落ちる。**ログに載る verb には `catalog` に同じ綴りの宣言が必須**（両方向で突き合わせる）。WS コマンド（`ws`）や MCP（`mcp`）は開けない宣言にできる（`add_mesh_body` は WS を開けない）。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- `duocad/meshbody.py`: `triangles/bbox/volume/geometry/write_stl/from_tessellation/reject`。**断り文の実体は `reject()` の1箇所**で「次に何ができるか」を必ず含む（`tests/test_mesh_body.py` の `EXPECTED_HINT` が固定）。形状最適化の結果を入れるときは `from_tessellation` ではなく `duocad.topopt.mesh` の `verts`/`faces` をそのまま平らにして渡す（`verts.ravel().tolist()`/`faces.ravel().tolist()`。巻き順は `topopt.mesh` が外向きに揃えてあるので入れ替えない）。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- **`add_mesh_body` の args に「元の B-rep の ID」を入れない**。三角形そのものを積む（元を指すと、元ボディをその後に編集した文書の再生で別の形が復元される）。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- **`meshbody.py` に OCP / build123d を import しない**（`tests/test_boundaries.py` が落とす）。numpy/scipy も pytest 起動費用に乗る層なので関数内 lazy import に留める（現行は `validate_float32` 内で numpy を lazy import している。モジュール直下で import しない）。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- 画面への配りものは `meshbody.geometry(mesh)`: `kernel.tessellate_selective` と同じキー構成で `faces` は**要素1つだけ**（`index:1`/`kind:"mesh"`/`detail:"fine"`/`deviation:0.0`）。`web/` は1行も変えずに描画・投影できる。`App.svelte` の `partBodies` 付近のコメントが「`model.bodies` は常に編集用ボディ(kind が solid)だけ」と書いてあっても実体は `model?.bodies ?? []` で濾していない（コメントが古いだけ。信じて画面側を直しに行かない）。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`

### 編集 verb を効かせない（断りの門）

- **メッシュボディに編集 verb を効かせない。断りの門は2つだけ**: `duocad/verbs/_common.py` の `editable_body()` と `duocad/verbs/extrude.py` の `_resolve_target()`（領域の押し出し専用の解決関数）。**新しい編集 verb は必ず `editable_body()` を通す**（通さないと断り漏れが1本できる）。`delete` だけは種別を問わず消せるよう `_common.deletable_body()` を使う（**`delete` の do 側 `_do_delete` にも同じ呼び出しがある**ので2箇所）。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- **選択の粒度はボディ単位だけ**。`selection.select_face/edge/vertex` はメッシュを断り（一括経路 `_coerce_refs` にも同じ門）、メッシュを指すのは `select_body`（`kind="body"`/`index=None`）。AI 側から編集 verb が断りへ届く外からの唯一の経路は `move_body`（`extrude_face`/`fillet`/`chamfer` は面・辺の確定選択を要求し、メッシュは面も辺も選べない）。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- **通す／断る／外すは1本の線で決める: 「名指ししたら断る／導出した集合からは黙って外す」**。名指し（`select_face(mesh, 3)`、`predicates` の `body` 明示、面の指紋、貼る先の面）は「このボディには面がある」という誤った主張なので断る。導出（`predicates` の `body` 省略＝可視 Body 全部、`export_stl` の対象集合）は主張ではないので外しても矛盾しない——ここで断ると最適化結果のメッシュが1つあるだけで述語による選択が丸ごと使えなくなる。`predicates` では**メッシュを外してから** `on_boundary_of_face` の単一 Body 検査に掛ける（逆順だと可視のメッシュ1つで「複数の Body が見えている」と断られる）。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- **`body.shape` が非 None であることに依存しない**。ボディ全体を舐める新コードは `kernel.face_count`/`query.volume`/`kernel.bounding_box`/`query.describe_shape`/`describe_faces`/`describe_edges` を**無条件に呼ばない**。当時塞いだ12箇所: `view.body_meta/_body_volume/geometry`（メッシュ用の値）、`view.edges/vertices`（断る）、`mcp_server.describe_document/describe_shape`（メッシュ用の値、後者は `triangle_count` を足す）、`io_step._export_candidates`（含める）、`io_step.export_step`（断る）、`selection.select_face/edge/vertex`＋`_coerce_refs`（断る）、`predicates._target_bodies`（明示なら断る／省略なら外す）、`optimize.face_fingerprint`（断る）、`sketch.resolve_plane`（面に貼るスケッチ。断る）。`optimize._body_state`/`session._revision_snapshot` 周辺/`set_parameter` の前後比較（`id(shape)` を鍵にするだけ）、`session.preview`（`body.shape is None` で `continue` 済み）、`verbs/*`、`view` のキャッシュ刈り取りは安全と確認済み。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- `body_meta`/`describe_document` の `face_count` は**メッシュでは常に1**（配りものが「面1枚」なのに合わせた）。三角形数は `describe_shape` の `triangle_count`（メッシュのときだけ載る）か、配りものの `faces[0].indices.length / 3`。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- **`Body` に持たせるフィールドを増やしたら `duocad/speculative.py` の `_snapshot`/`_restore` のタプルにも足す**（`mesh` を含めて6要素）。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- **`body_revision`（`duocad/view.py`）の鍵に `id(body.mesh)` を入れる**（入れ忘れると、メッシュは `shape` が常に None で `id(None)` が不変なので**版が二度と上がらず**差分配信が「変わっていない」と判断し続ける）。`meshbody.geometry` は毎回 positions/indices をリストへ写すので、`view.geometry` に**メッシュの同一性を鍵にしたキャッシュ**がある（消さない。`body_state()` は接続・状態配信のたびに呼ばれる）。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- 罠: `session.document = doc` で文書を差し替えても `session.view` は古い文書を握ったまま——検査で `Session` にメッシュを持たせるときは `Session.add_mesh_body()` 越しに作る（view を作り直す口は `_replace_document` のみ）。`parameters.rebuild()` は `OpLog.replay` とは別の再生経路（`doc.bodies` を空にしてログを頭から流し直す）で、`set_parameter` を1回打つだけで踏む——メッシュボディが復元されることを別検査で固定してある。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- 罠（網羅の取り方）: `grep "\.shape"` だけでは、`query.describe_edges(body.shape)` のように関数呼び出しの引数の中にあるものを数え落とす。`doc.bodies` を舐める場所（`grep "\.bodies"`）からも辿って**両方向**で潰す（QA が実測で `predicates.evaluate()` を9箇所目に発見、洗い直しで `face_fingerprint` と `sketch.resolve_plane` も出た）。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`

## 最適化の配線（`duocad/optimize_run.py` / `session.py` / `net/ws.py`）

- 配線の本体は `duocad/optimize_run.py`。**verb は1本も足していない**（結果を文書に入れる口は既存の `add_mesh_body` だけ）。`Session` の4つ: `optimize_conditions()`（4条件がそろって走らせられるか。`{ready, problems, preserve_bodies, exclude_bodies, fixtures, loads, load}`、**`problems` はそのまま人に見せる文**）/ `optimize_resolution()`（要素サイズの上限・下限・既定。軽い）/ `run_optimization(...)`（重い。成功時だけ戻り値に `"applied"` を足す）/ `cancel_optimization()`（旗を立てるだけ。実際に降りるのは次に進捗が出た時点）。コア側は `conditions_report(doc)`/`build_conditions(doc)`/`resolution_limits(doc)`/`run(doc, options, *, progress, should_cancel, debug, debug_kinds)`、摘みは `OptimizeOptions`。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
- **`run()` の戻り値は `state` で分岐し、`"done"` 以外では文書は1ビットも変わらない**（`body_id` は None）。`state` は `"done"`（`body_id/name/triangle_count/vertex_count/safety_factor/...`）のほか、`"empty_condition_faces"`（条件面に格子節点が付かない。`empty_condition_faces` に診断、`warning` に `anchor.format_condition_face_warning` の1文）／`"unrepresented_regions"`（保持/除外がこの解像度で表現できていない事後検出。`format_region_warning`）／`boundary_mapping_failed`／`no_feasible_found`／`input_contradiction`／`resolution_insufficient`／`fill_infeasible`／`final_unsafe` など。全一覧は `_run` の docstring。どの状態でも `resolution/element_size_mm/grid/design_elements/allowable/anchor_check/seconds/warning` が入る。**戻り値は素の値だけ**（`json.dumps` が通る＝`DesignSpace`/`AnchorTable` を外へ出さない。`space`/`table` が入っていることに依存しない）。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
- **進捗は `progress(event)`**。`event` は必ず `{"phase","message","evaluation"}` を持つ（phase は `prepare/derive/search/fill/mesh/finalize/final_check/insert`）。例外はどれも文面に「次に何をすればよいか」を含み**握り潰さない**: `OptimizeInputError`(`ValueError`)/`FaceMappingError`(**`RuntimeError`**)/`OptimizeCancelled`(**`RuntimeError`**) ほか。**`OptimizeCancelled` を `ValueError` にしない**——探索内の `acceptance.inspect` の例外処理が入力の不備と分類して**探索が続く**（現行 docstring に同じ理由）。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
- **元のボディを消さない・形を差し替えない**。最適化は編集ではなく「条件から新しい形を1つ作る」操作（2026-09-04 本人決定）。結果は `optimized`（2回目は `optimized-2`）という名前のメッシュボディとして**足されるだけ**（積み上がる。要らないものは選んで `delete`）。`shape` の同一性（`is`）で固定。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04; 20260904-1705-duocad-optimize-run-ui, 2026-09-04)`
- **面の対応の網を2枚とも外さない**。面添字がずれても例外は出ず、**荷重が別の面に入ったまま最適化がもっともらしく収束する**。(1) `_verify_face_mapping`: まとめた形（`kernel.make_compound`）側で測り直した指紋がボディ単体の指紋と一致するか。**面積・法線・重心の3つを見る**（重心を外すと同じ形のボディを2つ並べた文書で取り違えを通す）。(2) `_check_anchor_centroids`: 実際にできた面アンカーの節点の重心が条件面の重心から3要素以内か。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
- **結果メッシュの座標変換は1箇所**（`_mesh_to_world`）。`mesh.build_surface` が返す頂点は**要素添字空間**（`spacing=(1,1,1)`・セル中心規約）で、ワールド mm は `grid.origin + verts * grid.spacing`。忘れると原点付近に縮んだメッシュが黙って入るので `_check_mesh_placement` が毎回格子の箱に収まっているかを見る。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
- **要素サイズの上限は2つの要求の min**: 固定値 `MAX_ELEMENT_SIZE_MM` と `min(sqrt(条件面の CAD 面積))`（後者は `anchor.empty_face_diagnosis` の `suggested_max_spacing_mm` と同じ式で `optimize_run._face_max_spacing_mm` に1箇所化。近似であって保証ではない）。**既定は上限側（いちばん粗くて安い）**、**時間は制約にしない**。要素サイズの下限は設計空間の要素数の上限 `MAX_DESIGN_ELEMENTS` から割り戻す。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
- **事後検出は保持/除外を1つずつ数える**（まとめて数えると大きい保持ソリッド1つで小さいほうが1要素も掴めていないことが隠れる。`anchor._require_nodes` が「合計で見てはならない」とするのと同じ）。0要素なら最適化本体を呼ばずに戻る。格子の列が1本もその形状を貫かない場合は異常ではなく「この解像度では表現できていない」そのもの（要素4mm の格子に1mm 角の保持ソリッドを置くと必ずこうなる）なので、`vx.occupancy(..., allow_empty=True)` で0要素として扱う。`MIN_REGION_ELEMENTS = 8` は根拠のある閾値ではない（確かな線は「0は必ず止める」だけ。0より多く8未満は警告して続ける）。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
- **メッシュボディは保持・除外に指定できない**。断りの門は2つ: `verbs/optimize_setup.py` の `_assign_bodies`（新規割り当て）と `optimize_run.conditions_report`（過去のログを再生した文書に入っている場合）。**`_apply_bodies` には門を置かない**（redo/replay も通る関数で、置くと過去に受け付けたログの再生が落ちて文書が開けなくなる）。断り文は `meshbody.reject` の1箇所。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
- **`duocad.topopt` は関数の中で import する**。`session.py` が `optimize_run` をモジュール直下で import するので、ここが崩れると pytest が毎回 skimage と `duocad.topopt` の起動費用を払う。`scipy` の有無では検出できない（`duocad/view.py` が既に読んでいる）。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
- 粗い段の中では中断できない（進捗が出るのは探索の反復・候補ごと。進捗の口が無い段はその粒度で止まる）。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
- 罠（中断の検査）: **`Session.cancel_optimization()` を実行前に呼んでも効かない**（旗を畳むのは `begin_optimization`＝実行の入口。中断の直後に立て直された旗を次の実行が拾わないよう、`cancel_optimization` では畳まない）。中断の検査は「進捗の途中で旗を立てる」形で書く。`should_cancel` を直に渡す `optimize_run.run` なら1件も進捗を出さずに降りる。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04; 20260904-1705-duocad-optimize-run-ui, 2026-09-04)`
- 罠（面添字の変異検査）: 面添字を **+1** ずらす変異は「範囲外」で落ちて取り違えを見ていない（最後の面をまたぐ）。**−1 側でずらす**。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`

## 実行 UI（`OptimizePanel.svelte` / `session.ts` / `net/ws.py`）

- WebSocket に4つ（`catalog` の `category="protocol"`＝verb ではない、`ws="special"`/`mcp=False`/`changes_document=False`、実体は `duocad/net/ws.py` の `_dispatch`）: `optimize_conditions`（要求した接続にだけ返す）／`optimize_resolution`（`OptimizeInputError` は `type:"error"` にせず `{"error": 文}` に畳む——条件面がまだ無いのは「設定の途中」であって事故ではない）／`run_optimization`（**待たずに返り**、`optimize_status`→`optimize_progress`(多数)→`optimize_result` か `optimize_error`→`optimize_status` の順で**全接続へ**配る）／`cancel_optimization`（`optimize_status {running, cancelling}`）。**`optimize_error` には `cancelled: bool` が載り**、中断は失敗ではないので画面はトーストを出さない。`problems` は条件が足りないときだけ入る。`Server` の配信ヘルパは `_emit_event`/`_spawn_broadcast`/`_broadcast`（旧 `_*_ai`＝AI 専用でなくなったため改名）。`(20260904-1705-duocad-optimize-run-ui, 2026-09-04)`
- **重い処理は `run_in_executor` で回す**。`_dispatch` の中で待つと `handle()` が1接続を直列処理する以上、同じ接続から届く `cancel_optimization` が読めなくなる（止める手段がゼロ）。`_ai_start` と同じ形。`(20260904-1705-duocad-optimize-run-ui, 2026-09-04)`
- **解像度の目盛りは粗い側へ動かさない**。粗い側の端は「正しさ」の境界（割ると条件面から節点が消え最小部材幅が表現できず、しかも silent）、細かい側の端は「都合」の境界（遅い・落ちるだけ）。**時間を入力にしない**（時間から解像度を逆算すると最小部材幅と条件面の要求を黙って割る）。段（`resolution_limits()["steps"]`、`optimize_run.RESOLUTION_STEPS`=6の等比、添字0が最粗＝既定、最後の段は下限そのもの、上限が下限を下回るときは空）は**サーバが作る**（`_resolution_steps`。要素数の数え方——余白比率0.25と `voxelize.DEFAULT_PAD`——を画面が持つと必ずずれる）。同じ要素数になる段は畳むので `steps.length` が `RESOLUTION_STEPS` と一致することに依存しない。`(20260904-1705-duocad-optimize-run-ui, 2026-09-04)`
