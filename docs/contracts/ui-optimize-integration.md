# メッシュ body 種別・最適化の配線と実行 UI の契約

形状最適化の結果を文書に入れるための「メッシュボディ」種別、最適化バックエンドを `Session`/WebSocket/画面へつなぐ配線（`duocad/optimize_run.py`）、
実行パネル（`OptimizePanel.svelte`）について、ソースを読んでも分からない不変条件・依存禁止・罠を、元の作業タスクの契約から分野別に蒸留した文書。
**いまの挙動の正はコードとテスト**。最適化アルゴリズム本体は [../TOPOPT.md](../TOPOPT.md) と `TOPOPT_*.md`、画面は [../UI.md](../UI.md)。デバッグビュー（`?debug=` `?voxel=1`）は ui-selection-viewport.md。

出典は項目末尾の括弧 `(タスクID, YYYY-MM-DD)`。日付はタスクIDの先頭8桁。`(対象コード不在・要確認)` は契約が名指した関数・ファイルを見つけられなかった印。

**重要な注意（古くなった契約）**: 契約が書かれた2026-09-04 時点の最適化は SIMP（密度フィルタ半径 `rmin_mm`・設計反復・材料量探索 `safety_loop`）だった。
現行コードは二値探索（`binary_search.find_best_feasible`）に置き換わっており、`rmin_mm`/`max_iter`/`material_*_mm3` は渡されると `OptimizeInputError` で断る。
下の「SIMP 時代の契約」節に分けた項目は、現行コードにそのまま対応しない。現行の仕様は `optimize_run.py` の docstring と [../TOPOPT.md](../TOPOPT.md) が正。

## メッシュ body 種別（`duocad/document.py` / `meshbody.py` / `verbs/add_mesh.py`）

- **ボディ種別は `document.MESH_KIND`（`"mesh"`）**。`SOLID_KIND` と合わせて `_VALID_KINDS` は2つ。種別の綴りを文字列で書かず定数を import する。形は `Body.mesh`（frozen dataclass `Mesh`: `positions` を x,y,z 平坦、`indices` は**0始まり**で3つずつ。`vertex_count`/`triangle_count`）。**`Body.shape` は常に None**（両方持つ Body は `__post_init__` が弾く）。素の並びから作るのは `document.make_mesh`。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- **メッシュボディを作る唯一の口は verb `add_mesh_body`**（コア `verbs.add_mesh_body(doc, positions, indices, name=None)`、`Session.add_mesh_body`、MCP ツール `add_mesh_body`）。**WebSocket には開けない**（`catalog` の `ws="none"`）。画面は三角形を作らず、結果は `run_optimization` がサーバ内で入れる——1703 の「1705 が `ws` を開ける」は必要になればという条件付きで、必要にならなかった（2026-09-05 の判断）。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04; 20260904-1705-duocad-optimize-run-ui, 2026-09-04)`
- verb を1本足すと `tests/test_mcp_verbs.py` の `registered_verbs() == LOGGING_TOOLS` が落ちる。**ログに載る verb には同じ綴りの MCP ツールが必須**（`VERB_TOOLS` と `ARGUMENTS` の2箇所）。WS コマンド（`catalog` の `ws`）は `"none"` にできるが MCP は外せない。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- `duocad/meshbody.py`: `triangles/bbox/volume/geometry/write_stl/from_tessellation/reject`。**断り文の実体は `reject()` の1箇所**で「次に何ができるか」を必ず含む（`tests/test_mesh_body.py` の `EXPECTED_HINT` が固定）。形状最適化の結果を入れるときは `from_tessellation` ではなく `duocad.topopt.mesh` の `verts`/`faces` をそのまま平らにして渡す（`verts.ravel().tolist()`/`faces.ravel().tolist()`。巻き順は `topopt.mesh` が外向きに揃えてあるので入れ替えない）。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- **`add_mesh_body` の args に「元の B-rep の ID」を入れない**。三角形そのものを積む（元を指すと、元ボディをその後に編集した文書の再生で別の形が復元される）。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- **`meshbody.py` に OCP / build123d を import しない**（`tests/test_boundaries.py` が落とす）。numpy/scipy も pytest 起動費用に乗る層なので関数内 lazy import に留める（現行は `validate_float32` 内で numpy を lazy import している。モジュール直下で import しない）。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- 画面への配りものは `meshbody.geometry(mesh)`: `kernel.tessellate_selective` と同じキー構成で `faces` は**要素1つだけ**（`index:1`/`kind:"mesh"`/`detail:"fine"`/`deviation:0.0`）。`web/` は1行も変えずに描画・投影できる。`App.svelte` の `parts` のコメントが「常に kind==="solid" だけ」と書いてあっても実体は `model?.bodies ?? ### 編集 verb を効かせない（断りの門）

- **メッシュボディに編集 verb を効かせない。断りの門は2つだけ**: `duocad/verbs/_common.py` の `editable_body()` と `duocad/verbs/extrude.py` の `_resolve_target()`（領域の押し出し専用の解決関数）。**新しい編集 verb は必ず `editable_body()` を通す**（通さないと断り漏れが1本できる）。`delete` だけは種別を問わず消せるよう `_common.deletable_body()` を使う（**`delete` の do 側 `_do_delete` にも同じ呼び出しがある**ので2箇所）。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- **選択の粒度はボディ単位だけ**。`selection.select_face/edge/vertex` はメッシュを断り（一括経路 `_coerce_refs` にも同じ門）、メッシュを指すのは `select_body`（`kind="body"`/`index=None`）。AI 側から編集 verb が断りへ届く外からの唯一の経路は `move_body`（`extrude_face`/`fillet`/`chamfer` は面・辺の確定選択を要求し、メッシュは面も辺も選べない）。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`
- **通す／断る／外すは1本の線で決める: 「名指ししたら断る／導出した集合からは黙って外す」**。名指し（`select_face(mesh, 3)`、`predicates` の `body` 明示、面の指紋、貼る先の面）は「このボディには面がある」という誤った主張なので断る。導出（`predicates` の `body` 省略＝可視 Body 全部、`export_stl` の対象集合）は主張ではないので外しても矛盾しない——ここで断ると最適化結果のメッシュが1つあるだけで述語による選択が丸ごと使えなくなる。`predicates` では**メッシュを外してから** `on_boundary_of_face` の単一 Body 検査に掛ける（逆順だと可視のメッシュ1つで「複数の Body が見えている」と断られる）。`(20260904-1703-duocad-mesh-body-kind, 2026-09-04)`

## 最適化の配線（`duocad/optimize_run.py` / `session.py` / `net/ws.py`）

- 配線の本体は `duocad/optimize_run.py`。**verb は1本も足していない**（結果を文書に入れる口は既存の `add_mesh_body` だけ）。`Session` の4つ: `optimize_conditions()`（4条件がそろって走らせられるか。`{ready, problems, preserve_bodies, exclude_bodies, fixtures, loads, load}`、**`problems` はそのまま人に見せる文**）/ `optimize_resolution()`（要素サイズの上限・下限・既定。軽い）/ `run_optimization(...)`（重い。成功時だけ戻り値に `"applied"` を足す）/ `cancel_optimization()`（旗を立てるだけ。実際に降りるのは次に進捗が出た時点）。コア側は `conditions_report(doc)`/`build_conditions(doc)`/`resolution_limits(doc)`/`run(doc, options, *, progress, should_cancel, debug, debug_kinds)`、摘みは `OptimizeOptions`。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
- **`run()` の戻り値は `state` で3分岐し、`"done"` 以外では文書は1ビットも変わらない**: `"done"`（`body_id/name/triangle_count/vertex_count/safety_factor/...`）／`"empty_condition_faces"`（条件面に格子節点が付かない。`empty_condition_faces` に診断、`warning` に `anchor.format_condition_face_warning` の1文）／`"unrepresented_regions"`（保持/除外がこの解像度で表現できていない事後検出。`format_region_warning`）。どの状態でも `resolution/element_size_mm/grid/design_elements/allowable/target_safety_factor/anchor_check/seconds/warning` が入る。**戻り値は素の値だけ**（`json.dumps` が通る＝`DesignSpace`/`AnchorTable` を外へ出さない。`space`/`table` が入っていることに依存しない）。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
- **進捗は `progress(event)`**。`event` は必ず `{"phase","message","evaluation"}` を持つ。契約時の phase は `prepare/derive/insert/search/optimize`、現行コードの phase には `fill/mesh/finalize/final_check` が増えている。例外はどれも文面に「次に何をすればよいか」を含み**握り潰さない**: `OptimizeInputError`(`ValueError`)/`FaceMappingError`(**`RuntimeError`**)/`OptimizeCancelled`(**`RuntimeError`**) ほか。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
- **元のボディを消さない・形を差し替えない**。最適化は編集ではなく「条件から新しい形を1つ作る」操作（2026-09-04 本人決定）。結果は `optimized`（2回目は `optimized-2`）という名前のメッシュボディとして**足されるだけ**（積み上がる。要らないものは選んで `delete`）。`shape` の同一性（`is`）で固定。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04; 20260904-1705-duocad-optimize-run-ui, 2026-09-04)`
- **面の対応の網を2枚とも外さない**。面添字がずれても例外は出ず、**荷重が別の面に入ったまま最適化がもっともらしく収束する**。(1) `_verify_face_mapping`: まとめた形（`kernel.make_compound`）側で測り直した指紋がボディ単体の指紋と一致するか。**面積・法線・重心の3つを見る**（重心を外すと同じ形のボディを2つ並べた文書で取り違えを通す）。(2) `_check_anchor_centroids`: 実際にできた面アンカーの節点の重心が条件面の重心から3要素以内か。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
- **結果メッシュの座標変換は1箇所**（`_mesh_to_world`）。`mesh.build_surface` が返す頂点は**要素添字空間**（`spacing=(1,1,1)`・セル中心規約）で、ワールド mm は `grid.origin + verts * grid.spacing`。忘れると原点付近に縮んだメッシュが黙って入るので `_check_mesh_placement` が毎回格子の箱に収まっているかを見る。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
- **要素サイズの上限は2つの要求の min**: `rmin_mm / simp.DEFAULT_RMIN` と `min(sqrt(条件面の CAD 面積))`（後者は `anchor.empty_face_diagnosis` の `suggested_max_spacing_mm` と同じ式で `optimize_run._face_max_spacing_mm` に1箇所化。近似であって保証ではない）。**既定は上限側（いちばん粗くて安い）**、**時間は制約にしない**（予想時間は帰結として出るだけ）。要素サイズの下限は設計空間の要素数の上限（契約時 `MAX_ELEMENTS=120,000` の暫定固定値→現行は `MAX_DESIGN_ELEMENTS = 1,300,000`）から割り戻す。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)` `(対象コード不在・要確認: `MAX_ELEMENTS`・`simp.DEFAULT_RMIN` は無く `MAX_DESIGN_ELEMENTS` に変わった。matrix-free 化で桁が動く旨の契約どおり)`
- **事後検出は保持/除外を1つずつ数える**（まとめて数えると大きい保持ソリッド1つで小さいほうが1要素も掴めていないことが隠れる。`anchor._require_nodes` が「合計で見てはならない」とするのと同じ）。0要素なら最適化本体を呼ばずに戻る。**`vx.occupancy` は格子の列が1本もその形状を貫かないと `ValueError`（「レイのずらしを6通り試したがすべて縮退した」）**——事後検出ではこれが「0要素」そのものなので捕まえて0として扱う（要素4mm の格子に1mm 角の保持ソリッドを置くと必ずこうなる）。`MIN_REGION_ELEMENTS = 8` は根拠のある閾値ではない（確かな線は「0は必ず止める」だけ。0より多く8未満は警告して続ける）。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
- **メッシュボディは保持・除外に指定できない**。断りの門は2つ: `verbs/optimize_setup.py` の `_assign_bodies`（新規割り当て）と `optimize_run.conditions_report`（過去のログを再生した文書に入っている場合）。**`_apply_bodies` には門を置かない**（redo/replay も通る関数で、置くと過去に受け付けたログの再生が落ちて文書が開けなくなる）。断り文は `meshbody.reject` の1箇所。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
- **`duocad.topopt` は関数の中で import する**。`session.py` が `optimize_run` をモジュール直下で import するので、ここが崩れると pytest が毎回 skimage と `duocad.topopt` の起動費用を払う（pytest が subprocess で固定）。`scipy` の有無では検出できない（`duocad/view.py` が既に読んでいる）。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
- **拘束面・荷重面は1枚ずつだけ**（依存禁止）: `design_space.Conditions` の `fixed_face`/`load_face` が面添字を int 1つしか持たず `DesignSpace.fixed_face` が `int()` を掛けるので並びを渡すと落ちる。下の層（`AnchorTable.node_ids/fixed_dofs/load_vector/element_mask`）は Iterable を受ける。広げるなら `Conditions`/`DesignSpace.fixed_face`/`assert_faces_connected`/`condition_face_diagnoses`/`run_pipeline` の5箇所と受入検査をセットで直す。2枚以上は `conditions_report` が理由つきで断る。保持ソリッドが無くても走ることにも依存しない（塊は保持ソリッドと条件面から起こす。`Conditions.keep` 必須）。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
- 粗い段の中では中断できない（進捗が出るのは探索の反復・候補ごと。進捗の口が無い段はその粒度で止まる）。`(20260904-1704-duocad-wire-optimize-backend, 2026-09-04)`
