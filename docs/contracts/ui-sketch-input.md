# スケッチ入力・コマンド引数・ゴースト・グリッドの契約

スケッチを描く入力（クリックと打鍵の両対応）、コマンドの引数仕様（ピック引数・条件付き必須・`fromPoints`）、ホバー強調とスナップ、
ローカル幽霊（ゴースト）、スケッチ中のグリッド追従、長方形の角度について、ソースを読んでも分からない不変条件・依存禁止・罠を、
元の作業タスクの契約から分野別に蒸留した文書。**いまの挙動の正はコードとテスト**。画面と操作の判断は [../UI.md](../UI.md)、グリッドは [../VIEWPORT.md](../VIEWPORT.md)。
画面ピックの当たり判定（半径・tie-break）は ui-selection-viewport.md。

出典は項目末尾の括弧 `(タスクID, YYYY-MM-DD)`。日付はタスクIDの先頭8桁。`(対象コード不在・要確認)` は契約が名指した関数・ファイルを見つけられなかった印（移動先が分かれば併記）。

## コマンド引数仕様（`web/src/commands/command.ts` / `CommandHost.svelte`）

- **`ArgSpecCommon.when?: (values) => boolean`**（条件付き必須）と、**`PickArgSpec`**（`kind:'pick'`, `target: 'edge'|'vertex'|'sketchPoint'`, `buttonId`, `optional?`）。値は `SelectionRef` 1つ（edge/vertex は `{body, kind, index}`、sketchPoint は `{sketch, entity, point}`）。`argApplies` / `pickedRefOf` / `pickedLabel` は `command.ts` の1箇所。ボタンの id は `buttonId`、指した中身は `<buttonId>-value`、外すボタンは `<buttonId>-clear`。`(20260906-0916-duocad-move-verb-ui-rotation-picking, 2026-09-06)`
  - **`when` は肯定形で書く**（`values.mode === 'rotate'`）。`values` は「いま集まっている値」で確定値ではないので、`!== 'translate'` と書くとモード選択前から回転側の引数を要求し始める。`(20260906-0916-duocad-move-verb-ui-rotation-picking, 2026-09-06)`
  - **`ArgSpecCommon` に足した種別は必ず `argSatisfied` / `promptFor` / `liveArgs` の3箇所を通る**。呼び出し側で `spec.when?.(values)` を書き直さない（`argApplies` を使う）。`(20260906-0916-duocad-move-verb-ui-rotation-picking, 2026-09-06)`
  - 省略できるピックは `firstMissingArg` が指さない。人が「指す」ボタンで構える（`armedPick`）のが唯一の入口で、外すボタンが既定へ戻す手。`(20260906-0916-duocad-move-verb-ui-rotation-picking, 2026-09-06)`
  - **`needsEnter` は `pick` を「即適用の側」に数える**（対象を1つだけ指すので終わりが機械に分かる）。ピックだけのコマンドを作ると即適用になる——意図しないなら how（数値・選択肢）を足す。対応表は `tests/test_ui_command_wiring.py::ENTER_REQUIRED`。`(20260906-0916-duocad-move-verb-ui-rotation-picking, 2026-09-06)`
  - `MOVE_BODY.args` の**並びが動線**（ピックを角度より前に置くのは「回転を選んだ瞬間に辺が指せる」ため。`firstMissingArg` の順序＝何を先に問うか）。引数を足すときは並びを意識する。`(20260906-0916-duocad-move-verb-ui-rotation-picking, 2026-09-06)`
- `CommandHost` のチャンネル: `wantsPick(): PickTarget|null` / `setPick(ref): boolean` / prop `onWantsPick`、App 側 `wantedPick`（`__duocad.wantedPick` は検査用の穴）。`web/src/commands/moveMode.ts` の `MOVE_MODE_OPTIONS`/`isTranslateMode`/`isRotateMode`/`rejectAngle` は `features.ts` と `sketch.ts` の両方から使う（片方をもう片方から import しない）。`move_body`/`move_sketch_entities` は `catalog` の `ws="special"` で `duocad/net/ws.py` の `_dispatch` が個別に捌く。`(20260906-0916-duocad-move-verb-ui-rotation-picking, 2026-09-06)`
- **ピックした参照を共有選択集合へ入れない**。コアの `require_bodies` は選択の面/辺/頂点からボディを逆引きするので、軸に使った辺を入れると**その部品まで一緒に回る**。`onPick`/`onSketchPick` では `host.wantsPick()` の分岐を `event.edge`/`event.vertex`/`event.sketchEntity` の分岐より**前**に置く。`(20260906-0916-duocad-move-verb-ui-rotation-picking, 2026-09-06)`
- **サーバへは参照のまま送り、幽霊の側は数値へ解決する**（非対称が設計の中心）。辺が乗る直線を厳密に出せるのはコアだけで、まっすぐでない辺の拒否（`kernel.edge_axis`）もコア規則がそのまま効く。`showLocalGhost` は**解決済みの数値しか読まない層**のままで、ピックした参照は `App.svelte` の `resolvePicksForGhost(verb, args)` が渡す前に数値へ解決する（辺→`axis_point`/`axis_dir`、頂点→`axis_point`、スケッチの点→`center`）。**省略時の既定（ソリッド＝体積重心／スケッチ＝代表点の平均）は画面側へ写さない**——指されなければ幽霊を描かない。`(20260906-0916-duocad-move-verb-ui-rotation-picking, 2026-09-06)`
- **`kernel.edge_axis` の向きと、配られた折れ線の「始点→終点」の向きは一致する**（同じ `BRepAdaptor_Curve` の媒介変数順。立方体・穴あき・フィレット・合体・L字の直線辺83本で実測）。辺の解決を書き換えるときは測り直す（逆だと幽霊だけ逆回りに見える）。`(20260906-0916-duocad-move-verb-ui-rotation-picking, 2026-09-06)`
- 曲線の辺を軸に指したときは「幽霊が出ず、確定でコアのエラーが札に出る」。UI 側で先回りして断る判定は入れていない。軸の数値直接入力（数値6欄）は本人判断でスコープ外（MCP の `axis_point`/`axis_dir` は生きている）。`(20260906-0916-duocad-move-verb-ui-rotation-picking, 2026-09-06)`
- 罠: `tests/test_ui_command_wiring.py::_local_ghost_routes` は `showLocalGhost` から `requestPreview` までの本文を切り出して走査するので、その間に関数を挟まず新しい関数は `showLocalGhost` より前に置く `(対象コード不在・要確認: `_local_ghost_routes` はリポジトリ内に見つからない。同ファイルの `test_every_hand_dispatched_command_has_a_branch` は現存)`。`SKETCH_COMMANDS` の顔ぶれを固定する検査は `ws="special"` へ移すとその表から消えるので期待値も直す（コードが正）`(対象コード不在・要確認: 契約が挙げる `tests/test_sketch_ui.py` は存在しない)`。`(20260906-0916-duocad-move-verb-ui-rotation-picking, 2026-09-06)`

## スケッチ入力（クリック・打鍵の両立）（`commands/sketch.ts` / `sketchGeometry.ts`）

- 描く4 verb（`add_line` / `add_rectangle` / `add_circle` / `add_arc`）は**クリックだけでも打鍵だけでも**置ける。寸法欄は `NumberArgSpec.fromPoints?: true`（空欄なら集めた点から導く寸法。値は作らず `build` が点から計算する）で、`commitsGhost(command)`（`fromPoints` 寸法を1つ以上持つか）が「見えている幽霊をそのまま確定してよい」を決める。`CommandHost` は `commitSource`（`built ?? ghostBuilt`）/ `canCommit` を見て、Enter・ボタン押し直しは `ready` ではなく `canCommit` を見る。**サーバの verb 契約は変えていない**。`(20260906-1000-duocad-fusion-style-sketch-input, 2026-09-06)`
  - 対応: `add_line` = 点 `p0/p1`、寸法 `length`(`sketch-line-length`)/`angle_deg`(`sketch-line-angle`)。`add_rectangle` = `corner/opposite`、`width`/`height`。`add_circle` = `center/rim`、`radius`。`add_arc` = `p0/p1/via`、`radius`(`sketch-arc-radius`)。**`#sketch-arc-start`/`#sketch-arc-end` は無くなった**（角度は始点・終点のクリックで決まる）。`(20260906-1000-duocad-fusion-style-sketch-input, 2026-09-06)`
- 幾何は `sketchGeometry.ts`（純関数のみ・`import type` しか持たない）: `lineFromPoints` / `rectFromPoints` / `circleFromPoints` / `arcFromPoints` / `lineLength` / `lineAngleDeg`（規約 [0,360)）。**`sketch.ts` は `node` から直接読めない**（拡張子なしの実行時 import）ので、幾何を `sketchGeometry.ts` に置き `tests/eval_sketch_geometry.mjs` が直に読む。`sketch.ts` へ幾何を戻すと検査が死ぬ。`(20260906-1000-duocad-fusion-style-sketch-input, 2026-09-06; 20260906-1405-duocad-line-dimension-placeholder, 2026-09-06)`
- **`fromPoints` の `name` は `build` が出す引数のキーと同じにする**。`placeholderFor` がその名前で `ghostBuilt.args` を引いて「いまマウスが指す値」を薄字に出す。ずれても型検査は通り、**プレースホルダが黙って静的に戻るだけ**。`(20260906-1000-duocad-fusion-style-sketch-input, 2026-09-06)`
- **円弧の `build` は常に `start_deg <= end_deg` を出す**。`duocad/kernel.py` は `(end_deg - start_deg) % 360` で必ず反時計回りに掃くが `entityKinds.ts` の `arcPoints` は差の符号どおりに描く。負の掃引を送ると**幽霊と確定結果が別の弧になる**。`end_deg` が360超は正常（差だけを見る）。`(20260906-1000-duocad-fusion-style-sketch-input, 2026-09-06)`
- **円弧の向きは「弧の中点が `via` と同じ側か」で決める**（優弧/劣弧の大小比較で決めると**ちょうど半円のとき破れる**）。回帰検査の円弧の節はどちらも意図的にちょうど半円の配置。`(20260906-1000-duocad-fusion-style-sketch-input, 2026-09-06)`
- **`fromPoints` の数値は `isHowInput` に数えない**（数えると4 verb が Enter 必須へ戻り `ENTER_REQUIRED` が落ちる）。**`argSatisfied` は `fromPoints` の空欄を「揃っている」側に倒す**（判定は `command.ts` の1箇所。呼び出し側で `spec.fromPoints` を書き直さない）。`ENTER_REQUIRED` の即適用側はスケッチの描く4 verb ＋ `sketch_create` の5つ。`(20260906-1000-duocad-fusion-style-sketch-input, 2026-09-06)`
- **`hover`（`App.svelte` の `hoverPoint`）はポインタが canvas から出ても消えない**（`viewport.ts` の `onPointerLeave` は `planeMoveListener` を呼ばない）。「角をクリック→寸法を打つ→Enter」はこの性質に乗っている——`onPointerLeave` で `hoverPoint` を `null` にするとその経路が全部落ちる。`(20260906-1000-duocad-fusion-style-sketch-input, 2026-09-06)`
- **長方形の入力に角度欄は無い**（マウスで置く長方形は軸平行。コアは 1442 で `angle` を持つようになったが WS/画面は送らない `ws=False`）。`(20260906-1000-duocad-fusion-style-sketch-input, 2026-09-06; 20260906-1442-duocad-rectangle-gets-an-angle, 2026-09-06)`
- **線分の長さ・角度欄のマウス追従薄字**: `NumberArgSpec.live?(args): number | null`（名前で `build` の結果を引けない寸法だけが持つ。`ADD_LINE` の `length`/`angle_deg`、`args.p0/p1`＝`ghostBuilt.args` から作る）。`placeholderFor` の優先順位は「`spec.name` で `build` の結果を引く→引けなければ `spec.live`」。**`live` は表示だけに使い、サーバへ送る引数を1つも増やさない**（`add_line` の `build` 出力は `{p0, p1}` のまま）。`live` が受けるのは `ghostBuilt.args`（打った寸法を織り込んだ点）で生の入力値ではない（打った側の欄は `numberText[spec.name] !== ''` のガードで薄字ではなく実入力になる）。`live` は `fromPoints` を持つ数値 spec にしか意味がない（`placeholderFor` が `spec.fromPoints !== true` を先に弾く）。`(20260906-1405-duocad-line-dimension-placeholder, 2026-09-06)`  
  （1000 の「`add_line` の長さ・角度欄は薄字がマウス追従にならない」は 1405 で解消済み。）
- 罠: タスク本文の手計算値のうち「半径5の優弧: start=281.55 / end=618.45」は丸めがずれている（厳密には 281.537 / 618.463、中心 v=√24=4.89898）。検査には厳密値を入れる。puppeteer の `page.evaluate` から `window.__duocad.sketches` の要素を素のオブジェクトで返すと Svelte 5 の `$state` プロキシで `{}` に潰れる——ブラウザ側で `JSON.stringify` するか数値を向こうで計算して返す（既存 `sketchState()` が `JSON.stringify` している理由）。`(20260906-1000-duocad-fusion-style-sketch-input, 2026-09-06; 20260906-1420-duocad-sketch-hover-highlight, 2026-09-06)`

## ホバー強調とスナップ（`entityKinds.ts` / `App.svelte`）

- **クリック（`addPoint`）と幽霊（`hoverPoint`）は必ず `snappedPlanePoint` → `snapToSketchEntity` を通る**。片方だけ直すと「吸い付いて見える位置と確定結果がずれる」。`snappedPlanePoint(u, v, hit)` は `App.svelte` の唯一の入口（`onSketchPick` の `addPoint` 直前と、`onMount` の `viewport.onPlaneMove` コールバックの両方）。`snapToSketchEntity(entity, point, u, v)` は `point !== null`（点マーカーに当たり）なら射影せず `entityHandles` の値をそのまま返し、`point === null`（線に当たり）なら `snapToEntity(kind, params, u, v)`（種別ごとの表 `EntityKindSpec.snap`）へ落とす。`onPlaneMove(listener)` は第2引数 `sketchEntity: SketchEntityHit | null` を持ち、`planePointAt` と同じ `offsetX/offsetY` で `sketchEntityAt` も呼ぶ（`resolveHit` と同一の当たり判定を共有）。`hoveredRef()` の戻り値の `sketchEntity` は実機検査の穴。`(20260906-1420-duocad-sketch-hover-highlight, 2026-09-06)`
- 当たり判定（`resolveHit`/`sketchEntityAt`）の優先順位は点→線→（領域は図形が当たっていれば抑制）。`entityKinds.ts` の `projectToSegment`/`projectToPolyline`/`clampAngleToArc` は非 export（外から呼ばない）。`viewport.ts` の `hoverSketchEntity`/`hoverSketchKey` は内部 state で `hoveredRef().sketchEntity` 経由でしか読めない。`(20260906-1420-duocad-sketch-hover-highlight, 2026-09-06)`
- **スナップの段の優先順位は (1)点マーカー→(2)図形の線→(3)1mm グリッド**。(3) は `hit === null` のときだけ（図形に当たっているときは丸めない）。**丸めの門は `host?.wantsPoint()` の1箇所だけ**——点を待っていない選択クリック等では `hoverPoint` も生の座標のまま（丸めは強調ではなく実際に置く座標を変えるので、前タスクの「ゲートで出し分けない」裁定は (1)(2) の強調にだけ適用）。丸めの刻みは1mm固定（`gridScale.ts` の `TIERS` の最小段と一致。**自動追随しない**ので `TIERS[0]` を変えるなら丸め側も手で直す。可変・ズーム連動にしない）。`(20260906-1452-duocad-grid-snap-1mm, 2026-09-06)`  
  `(対象コード不在・要確認: 契約が名指す `App.svelte` の `snappedToGrid1mm` は無い。現行は `entityKinds.ts` の `snapSketchPoint` の3段目 `fallback`（`roundGrid ? [Math.round(u), Math.round(v)] : [u,v]`）。1mm 刻みの検査は `tests/eval_sketch_snap.mjs`）`
- **罠（実機 smoke の空き地）**: 検証に使う「何にも当たっていない」座標は、**後続の検証が新しく引く線の終点を含めて除外**する。使い回すと既存線の当たり判定を拾い、`Math.round` を経由しない浮動小数の射影誤差（例 `15.000000000000002`）が返る（原因は距離ではなく実行順序）。`(20260906-1452-duocad-grid-snap-1mm, 2026-09-06)`
- **罠（近接配置の fixture）**: スナップ導入後、新しい図形を近接配置する検査は既存図形の輪郭から**余裕を持って**（目安10mm以上、または実測で確認して）離す。旧 `DISC_B`（輪郭から2mm）はスナップの当たり判定に入り、クリック点が `DISC` の輪郭へ吸い付いて中心間距離が意図の7mmでなく5mmになり、「縮めても領域が3→2に戻らない」と表面化した。製品は正しく、**検査の前提が壊れていた**——切り分けは (a) 実際に送られた `entities[].params` をダンプ、(b) クリック前に同じ画素へマウスを動かして `hoveredRef()` を見る（人間が見るのと同じホバー状態）、(c) 輪郭からの距離を振って閾値を実測。当時のカメラ距離では gap=4mm までスナップ・5mm でしないが**この閾値はそのカメラ距離・フレーミング固有の実測**で一般化できない。サーバ（領域計算）から疑うと遠回り。`(20260906-1620-duocad-fix-smoke-regions-broken-by-hover-highlight, 2026-09-06)`  
  （当時の判定半径は `EDGE_PICK_PIXELS`=6、`SKETCH_HANDLE_PIXELS`=5。現在コードは 6／7。）
- 罠（検査）: 既存スケッチへ再入場した直後、`activeSketch` は同期的に更新されるが `lookAtSketch()` のカメラ再フレームは数フレーム遅れる——`activeSketch` 一致の直後に `projectSketchPoint` を呼ぶと稀に `null`。数フレーム `settle()` で待つ。`modify_selection` の add/remove は1操作として原子的に検証されるので、**隠した Body の古い選択参照が remove に混じると新しい選択を足す側ごと拒否される**——Body を隠す前に選択を空にする。`(20260906-1420-duocad-sketch-hover-highlight, 2026-09-06)`

## 長方形の角度（`duocad/kernel_sketch.py` / `sketch.py` / `entityKinds.ts`）

- `rectangle_corners(params) -> [P0=基準の角, P1=P0+width方向, P2=対角, P3=P0+height方向]`（反時計回り）と `rectangle_angle(params)=params.get("angle",0.0)`。**長方形の形を読む処理は全部これを通す**（自分で `x+width` を書かない）。`Entity.params["rectangle"]` は `x, y, width, height, angle` の5個で **`angle` は必ず最後**（度・反時計・基準の角まわり）。`EntityKindOps.rotate`/`.mirror` は `Dict[str,float]` を1つ返す（種別は変わらない。旧 `_rectangle_as_rotated_lines` 等は削除済み。「長方形はまるごと回せない」「この軸では鏡映できない」の ValueError も出ない）。`add_rectangle(doc, sketch_id, corner, width, height, angle=0.0)`。`(20260906-1442-duocad-rectangle-gets-an-angle, 2026-09-06)`  
  `(対象コード不在・要確認: 契約は `duocad/kernel.py` に置くとするが、現行は `duocad/kernel_sketch.py`（`kernel.py` は import 境界の最下層として他の duocad を import しない、という理由は維持）)`
- **4隅の規則はコア（`kernel.rectangle_corners`）と TS（`entityKinds.ts` の `rectangleCorners`）の2箇所にある。片方だけ変えない**（幽霊と確定結果が別の向きになる）。実機の突き合わせは円形反復の幽霊 vs 確定結果、回した幽霊の4隅の三角関数照合。`(20260906-1442-duocad-rectangle-gets-an-angle, 2026-09-06)`
- **`rectangle.snap()` は `rectangleCorners` の4辺へ射影するので回転に追随する**（1420 で書かれた「`rectangle.snap()` は軸平行前提」は 1442 が解消）。スナップ計算は `entityKinds.ts` の `snap()` 1箇所。`(20260906-1442-duocad-rectangle-gets-an-angle, 2026-09-06)`
- **`angle` の値そのものを期待値にしない**（同じ4隅を張る `angle` と基準の角の組は複数ある。鏡映は基準の角を `P3` の像へ移すので軸平行の鏡映でも `angle=180` が出る）。検算は**4隅の集合**で行う。`(20260906-1442-duocad-rectangle-gets-an-angle, 2026-09-06)`

## ローカル幽霊（`viewport.update()` / `ghostLayer.ts`）

- **`viewport.update(bodies)` の事後条件**: 呼ぶ前に出ていたローカル幽霊（`showBodyGhosts` で置いたもの＝`move_body`）は、呼んだ後も出ている。中身は**届いたばかりの `rawGeometry` から組み直した**メッシュで、`ghostInfo().bodies` の `offset`/`rotate`/`matrix` は不変。**サーバ投機実行のプレビュー（`showPreview`）は従来どおり落ちる**。幽霊が乗っていたボディがこの更新で消えた（`entry.geometry === null`）ぶんは落ちる。`clearPreview()` 自体は変えていない（`prune()`・Esc・App の中断はローカル幽霊も一緒に消す）。`(20260906-1426-duocad-fix-local-ghost-dies-on-unrelated-update, 2026-09-06)`
- **組み直しは `update()` の末尾**に置く（`refreshContentDiagonal()` の `contentBoxForGrid()` と `frameToContent()` の `Box3.setFromObject(root)` は幽霊も `root` に入るので、前へ動かすと初回フレーミングとグリッド倍率に幽霊が混ざる）。`(20260906-1426-duocad-fix-local-ghost-dies-on-unrelated-update, 2026-09-06)`
- **控えるのは `bodyGhostInfo`（指示）であってメッシュではない**。`clearPreview()`→`clearBodyGhosts()` は `bodyGhostInfo` を**新しい配列へ差し替える**（`bodyGhostInfo = []`）ので先に掴んだ参照が生き残る。`length = 0` や `splice` へ変えると救済が**エラーなしに空振りする**。`bodyGhostInfo` はもう検査専用の穴ではなく製品の分岐が読む入力（`ghostInfo()` の戻りは検査用のまま）。いまは `ghostLayer.ts` にある。`showLocalGhost`/`previewedKey` は触っていない（投げ直す側のデデュープは元のまま、救済は受け側 `viewport` に閉じる）。`(20260906-1426-duocad-fix-local-ghost-dies-on-unrelated-update, 2026-09-06)`
- **罠（案が成立しない）**: 「幽霊の対象ボディ集合と `entries` の交差で消さない」判定は成立しない——`duocad/view.py::body_revision` の鍵に `body_recipe()`（目標精度＋face単位 `focus`）が入っており、**カメラを回すと幽霊が乗っているボディ自身の版が上がる**（実測: 右ドラッグ1回で 2→3）。「`applied === null` なら形は変わっていない」も成立しない（`_spawn_push()` の MCP/AI 経路と最適化完了配信が `applied=None` で本物の形を配る）。着手前にここを実測しないと、緑のテストで直っていない実装を納品することになる。`(20260906-1426-duocad-fix-local-ghost-dies-on-unrelated-update, 2026-09-06)`
