## Issue の粒度(AIの判断 2026-10-16)

- 前提(記録済みの本人の基準。docs/DESIGN_DECISIONS.md「開発の進め方」): 不満は issue にせず、issue は「1件ずつでは直せない構造的な作業」にだけ使う。
- 決めた: 今回は本人が「適切な粒度で Issue 化」と明示したので Issue を立てる。粒度は**層とデータ経路の単位**(例: 「面ごとの Mesh を1ボディ1 Mesh にまとめる」「テセレーションをイベントループから外す」)にし、1 Issue が1回の対話で終わる見込みのもの(数値1つの変更など)は Issue にせず、まとめ Issue の箇条書きに入れる。
- 各 Issue に「実測(今の数値)」「原因の場所(file:line)」「方針」「効いたかを測る物差し(再現コマンド)」を書く。
