# 点から導ける寸法欄は how に数えない

CADの描画ツールは「クリックで大きさを決める」と「数値を打って決める」の両方を持つ。duocadのコマンド層は **Enterの要否を引数の並びから導出**していて、規則は「対象を複数取りうる」か「how(どうするか)の入力がある」なら Enter が要る、だった([[duocad-ui-interaction-principles]])。このまま寸法欄を足すと**寸法欄を持つverbは全部Enter必須**になり、2クリックで長方形を置く道が塞がる。

**解いた形(2026-09-06、[[duocad-sketch-dimensions-follow-the-mouse]] の実装)**: 数値引数に「**空欄なら集めた点から導く**」印(`fromPoints`)を1つ足し、その印が付いた数値だけを**howに数えない**。howがEnterを要求するのは「打ち終わりが機械に分からない」からであり、空欄でも点から値が決まる欄にはその問題が無い。結果:

- 引数を完成させる最後のクリックで即適用される(線分2・長方形2・円2・円弧3クリック)。
- 打ちたい人は打ってEnterを押す。Enterは「打ち終わった」という宣言として残る。

**もう1つ要るのが「見えている幽霊をそのまま確定する」口**。点をあと1つ待っている状態でもマウスの位置で形は決まっている(ゴムひも) —— 確定に使う引数を `built ?? ghostBuilt` にすると、①始点だけ置いて寸法を打ってEnter ②角をクリックして寸法を打ってEnter の両方が同じ1本の経路で通る。「見えているものが確定される」は人から見て最も予測しやすい規則で、逆に塞ぐと「打鍵だけで置く」が原理的に作れない。

副産物として、空欄のプレースホルダに「いまマウスが指している値」を薄字で出せる(Fusionのカーソル脇の寸法ボックスに相当)。ただし**その値は確定用の引数から名前で引く**ので、UIの欄名がサーバへ送る引数名と一致しない寸法(線分の長さ・角度は `p0`/`p1` へ畳んで送る)は追従しない。**層をまたぐ契約が1本増える**のがこの設計の代償。
