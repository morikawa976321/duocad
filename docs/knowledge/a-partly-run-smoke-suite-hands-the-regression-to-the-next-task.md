# 部分的にしか回さなかったスイートは、回帰を次のタスクへ渡す

無人runnerは「自分が触った層の周辺」を検証範囲に選ぶ。それ自体は合理的に見えるが、**選ばなかったスイートが壊れていても誰も気づかないまま完了報告が出る**。次に全体を回したタスクがそれを踏み、**自分が壊したのか前任が壊したのかの切り分け**から始めることになる。

## 実例(duocad, 2026-09-06)

`63a30a7`(スケッチの図形・点にホバー強調を出し、そこへ吸い付いて点を置く)のrunは `smoke-hover` / `smoke` / `smoke-vertex` / `acceptance` を回して緑と報告した。**スケッチのクリック経路を変えたのに `smoke-regions.mjs` を回していなかった。**

翌タスク(幽霊のrace修正)が実機smoke19本を全部回して `smoke-regions: FAIL 2つめの円を縮めても領域が2つに戻らない` を踏んだ([[smoke-fixture-points-must-clear-snap-targets]] の距離型)。そこから**自分の修正を1行無効化して同じ所で落ちることを確認 → 使い捨てworktreeを立てて `329993e` PASS / `63a30a7` FAIL と二分**するまでが、本来の作業とは別に必要になった。

## 効く形

- **検証範囲は「触ったファイル」ではなく「スイート」で選ぶ。** 部分実行にするなら、**回さなかったスイート名を完了報告に書く**(緑の範囲を偽らない)。
- 壊れているのを見つけた側は、**二分して犯人のコミットを名指してから**次へ渡す。「落ちている」だけを引き継ぐと、次の実行者がまた同じ切り分けをやる。
- 実機smokeはCPU時間は食うが人間の時間は食わない。**削る対象として最初に選ばない。**
