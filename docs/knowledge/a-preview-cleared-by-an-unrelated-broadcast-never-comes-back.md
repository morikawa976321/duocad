# 無関係な再配信で消えたプレビューは、引数が変わるまで戻らない

確定前のプレビューを「**引数が前回と違うときだけ**投げ直す」(印を持って重複送信を避ける)実装と、「**本物の形が届いたらプレビューを消す**」実装を組み合わせると、**プレビューを消したのが本物の変更でなかった場合に、二度と描き直されない**。「消す側の条件」と「描き直す側の条件」を別々に書くと、消す条件のほうが広いときに必ずこの窓が開く。

duocadで踏んだ形(2026-09-06):

- カメラを動かすと可変解像度が約180ms後に `set_view_resolution` を送る。サーバは粗さを版の鍵に入れているので、**形が1ミリも変わっていなくても状態を配信し直す**([[duocad-camera-move-redelivers-the-body-you-are-looking-at]])。
- その配信で `viewport.update()` が走り、表示中の幽霊(ローカルプレビュー)が消える。
- 幽霊は引数が変わらないと描き直されない(`CommandHost` の `previewedKey`)ので、**消えたまま戻らない**。人から見ると「打った数値のプレビューが勝手に消える」。

実機検査ではこれが**偽の失敗**として出た(「幽霊が出ない」で60秒タイムアウト)。実際には出ていて直後に消されていた —— 時系列で複数回サンプルするまで分からなかった。検査側は「状態配信が止まるまで待ってから打つ」ヘルパで避けた。

**根本は塞いでいない**(2026-09-06時点)。塞ぐなら「最後のローカルプレビュー要求を控えて、`viewport.update()` の後に描き直す」形になるが、`preview: 'local'` の全verb([[preview-belongs-on-every-verb-that-can-have-one]])の挙動が変わる。
