# 固定の優先順位の下では、上位の的に常に隠れる下位の的は一生指せない

3Dビューのピック解決を「辺 → 領域 → 頂点 → 面」のような**固定の優先順位**で書くと、下位の的が上位の的の上に**幾何的に必ず乗っている**場合、その的は一生指せない。

duocadで踏んだ形(2026-09-06):

- 頂点は必ず辺の端点に乗っている。優先順位は「辺が先」だった(フィレット中に辺の端を掴めるようにするための、それ自体は正しい判断)。
- `move_body` は対象を面/辺/頂点のどれでも指せるので、起動している間は**辺が常に出ている**。
- したがって「回転中心の頂点をクリックする」は**100%辺に取られる**。
- **症状は「クリックしても何も起きない」だけ**で、例外もエラーも警告も出ない。マーカーは描かれているので、画面を見ているかぎり原因の手がかりが無い。

新しい的を指させる機能を足すときは、その的が既存のどれかの部分集合的な位置(端点・縁・中心)にいないかを先に確かめる。いるなら順序そのものをゲートにする。

## 解き方は2つ。「外したときに何が起きるか」で選ぶ

1. **要求している間だけ順序を入れ替えるゲート**(`viewport.preferVertices(on)`)。既存の「その対象を要求しているコマンドを起動している間だけ指せる」規律の延長で、閉じている間の挙動は1ビットも変わらない。外しても**何も起きない**(頂点を狙って辺を掴んだが、その辺は捨てられる)ならこれでよい。
2. **要求している間だけ上位の的を画面から引っ込める**。「面を1つ指させる」引数を足したとき、辺は面より先に拾われるので、辺の配信そのものを要求中だけ止めて解いた。外すと**共有選択が書き換わる**(素のクリックは選択の置き換えなので、選び直したつもりのない対象がその場で入れ替わる)種類の衝突ではこちらが安全。副作用として「待ち受けに入った瞬間に辺が画面から消える」が起きるが、これは**いま何が指せるかの表示**として読めるので許容した。
