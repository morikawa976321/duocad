**「途中で止めない」検査ハーネスは、走り終わったあとに合否を終了コードへ落とす処理を
明示的に書かないと、❌ が何個並んでも `exit 0` で終わる。**

duocadの `web/scripts/acceptance.mjs` が実際にそうなっていた。このスクリプトは意図的に
「各操作は独立して試し、落ちても止めずに ❌ と理由を残す」設計で、各セクションが例外を
catchして `ok: false` を記録して次へ進む。**その catch が最後の1つでもあると、
プロセスは正常終了する。** 結果、`fitDistance` や `setFov` をわざと壊しても
終了コードは0のままで、**呼び出し側(人・cron・無人drain)からは全緑と区別が付かなかった。**
画面のログには `NG` が出ているので、人が目で読む限りは気づける ——
**気づけないのは自動化した側だけ**である。

一般形: **「止めない」と「合格を出さない」は別の設計判断**であり、前者を選んだ時点で
後者が自動的に付いてくるわけではない。止めない設計を選ぶなら、走り終わりに
**記録を1回走査して終了コードを決める処理**を必ず対にすること
(duocadでは `failedLabels()` を足し、未実行のセクションも失敗として数えるようにした)。
出力を減らす必要は無い —— 変えるのは終了コードだけでよい。

この欠陥は**新機能の検査を足そうとして初めて表面化した**(足した検査をわざと壊して
赤を見ようとしたら、終了コードが0のままだった)。**「わざと壊して赤を見る」を
終了コードで確かめる習慣が無ければ、この穴は見つからない。**
