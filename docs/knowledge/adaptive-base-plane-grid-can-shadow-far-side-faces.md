duocadの基準平面(XY/XZ/YZ)は、面とのピック優先順位を**レイ距離が近い方**で決める(同着は面が勝つ。[[duocad-coplanar-base-plane-pick-is-decided-by-the-last-bits]])。この判定は解析的な平面(見た目は透明な線)に対しても行われるので、**平面の当たり範囲が固定の小さい値(±100mm等)だった間は、実物のモデルがその範囲の外に出ている限り問題にならなかった**。

2026-08-30〜31、基準平面の当たり範囲をモデルの大きさへ追随させる変更(半幅・刻みを内容から導く)を入れたところ、当たり範囲がモデル全体を覆うようになった結果、**カメラから見て原点をまたいだ向こう側にある面が、実際にクリックできなくなる**現象を実測した: duocadのホームビューはカメラが原点から見て特定の象限(`HOME_VIEW_OFFSET`の符号が決める。例えば−Y側)にあり、モデルの一部がその反対側(+Y側)にある場合、カメラからその部分の面へ向かうレイは**必ず先に原点を通る座標平面(例: XZ平面=Y0)をくぐる**。当たり範囲がそこまで広がっていると、レイ距離ではその平面のほうが面より手前になり、**解析的には正しいオクルージョン判定**として平面が勝つ(見た目には透明な線でしかないので、人には「面が見えているのに指せない」と映る)。

実測した具体例: PC_case STEPモデル(Y=-290.5〜+110.5)で、Y=0を超えた側(Y>0寄り)にある部品の非平面面をクリックすると、狙った面ではなく基準平面(グリッド)が指された。**部品を1つに絞って隔離しても、その部品自体がY=0を超えた側にあれば同じ現象が起きる** — 母数が足りないのではなく、幾何学的に常にそうなる。

**対処**: この現象自体はバグではなく、当たり範囲を広げた設計の正しい帰結。実機smokeでクリック対象の面を選ぶときは、**カメラの原点に対する象限(`HOME_VIEW_OFFSET`の符号)と同じ側にある部品・面を優先して選ぶ**(bboxを見て、原点をまたいだ反対側にある部品は避ける)。duocadの`web/scripts/smoke.mjs`の「平面でない面は札で断られる」検査がこれで実際に壊れ、Y座標で危険な部品を除外してから候補を探す形に直した(`20260830-1535-duocad-grid-scales-with-model`タスク)。
