# 図形のparamsにキーを足すと、旧ログから再生した個体が壊れる

duocadの文書は操作ログ(verbと引数の列)で、再生は `_do_add_entity` が**ログに書いてある `params` をそのまま** `register_value` して entity を作る。したがって図形の `params` にキーを1つ足すと、**そのキーを持つentityと持たないentityが同じ文書に混在する**(新しく描いたものは持ち、旧ログから再生したものは持たない)。

**再生時に既定値で埋めてはいけない。** `parameters.register_value` は「その時点で空いている最小の `d<n>`」を振るので、再生でキーを1つ増やすと**以後のパラメータ名が全部ずれ**、古いログの `set_parameter`(名前で指す)が別の値を指す。`models/keyboard_36_case.json` は38個の長方形で `d1`〜`d152` を使っており、1個ずらすだけで壊れる。

結果、読む側が `params.get(key, 既定値)` で受けるしかなくなり、次の箇所が**例外もログも出さずに**壊れる(2026-09-06に長方形へ `angle` を足したとき全部踏んだ):

1. **書き戻し** — `move_sketch._write_params` は `entity.params[key]` で名前を引くので、新しいキーで `KeyError`。図形がまだ持たないキーは**書き戻す側で `register_value` する**(その操作の再生でも同じ順序で起きるので `d<n>` の割り当ては決定的なまま)。
2. **辞書の等値比較** — `mirror_sketch` の「元と完全に重なる複製は作らない」検査が `values == current` で、キーの数が違うだけで常に不一致になり、**重なった複製を素通しする**(領域検出が同じ辺を2本見る)。**元が持っているキーだけで比べる**。
3. **無関係に見える実機検査** — 形状最適化モードの実機検査(`web/scripts/smoke-optimize-mode.mjs`)が「板を1枚足したら新規パラメータは4個(角x/y・幅・高さ)」を固定していて落ちた。`d#` の連番をハードコードしない工夫(前後の差集合)まではしていたが、差集合の**要素数**は 4 に固定されていた。図形が持つ値の個数を変える変更は、**その語で全文検索しても見つからない**(検査は「4」としか書いていない)。実機smokeを全部回すのが唯一の検出手段になる。

「古い個体はキーが少ない」を `get` の1箇所で吸収したつもりになりやすいが、書き戻し・等値比較・個数を固定した検査が別々に壊れる。旧データを再生した状態からの検査を1本ずつ足すこと。
