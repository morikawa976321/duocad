# 自動で構えられたピックが、対象を選ぶクリックを食う

対象集合を共有選択から取り、**基準(軸・鏡映面)だけを別チャンネルの1ピックで受ける**コマンドは、引数を「対象 → 基準」の順に集める。収集は「まだ揃っていない最初の引数」を待つので、**対象の最小数(たいてい1)が満たされた瞬間に基準のピックが構えられる**。以後の素のクリックはすべてピックへ吸われ、**2つ目の対象を足す手が無くなる**。

見た目は壊れない: 選択は消えないし、エラーも出ない。人は「2つ目をクリックしたのに選択に入らない」とだけ感じる。

解き方は3案あり、duocadでは3を採った(2026-09-06):

1. **ピックを `optional` にして「指す」ボタン専用にする** — 必須の引数が画面に「(任意)」と出て収集の案内も指さないので、初めて使う人に基準が要ることが伝わらない。
2. **対象の上限を1にする** — 仕様を曲げる(鏡映は何個でも対象に取れる)。
3. **修飾キー(Shift/Ctrl)付きのクリックはピックへ行かせない** — 修飾キーは既に「選択のトグル」の意味を持っているので規則が増えない。素のクリック=基準を指す / 修飾キー付き=対象を直す、と読める。

3は既存のピック(回転軸・回転中心)にも同じ分岐でそのまま効く。**この逃げ道が無いと、「基準を待っている間は対象を直せない」という制約が全ピック引数に暗黙に付く。**
