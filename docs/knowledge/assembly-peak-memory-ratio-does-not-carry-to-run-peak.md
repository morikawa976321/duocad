duocad の SIMP で、疎パターンを固定する案(`pos` を持つ)と void 除去だけの案の
**メモリ比は、どこを測るかで別物になる**:

- **組み立てのピークだけ**で測ると 1.34倍(2026-09-08 以前の実測。`pos` と構築の一時領域が
  そのまま比に出る)。
- **実行全体のピークRSS**(導出 → 40反復の solve → メッシュ化)で測ると **1.035〜1.063倍**
  (5測定点。hanger 3解像度 + bracket + tilted)。

理由は solve 側のほうが大きいから。マルチグリッドの `_BlockedMatvec` は行列の約2倍を持ち、
各段の作用素と `splu` も乗る。`pos`(21〜80MB)はそこに埋もれる。

**したがって「案Aは案Bよりメモリを食う」を組み立てのピークだけで言わないこと。**
逆に、実行全体のピークには **385MB 前後の固定の床**(Python・OCCT・条件の三角形分割・
塊の導出まで)があるので、**ピークRSSのスケーリング指数も1を大きく下回る**(N^0.60〜0.76)。
床を引いた増分で取り直すと **N^1.00〜1.10** になり、行列の非零数の伸び(ほぼ線形)と揃う。
