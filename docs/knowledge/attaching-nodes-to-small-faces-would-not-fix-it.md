# 小さい面に節点を付けても解決しない(だから当面は通知だけ)

[[face-to-node-anchoring-loses-faces-smaller-than-the-cell]] の続き。2026-09-04に
「どうやって小さい面を節点に紐づけるのか」を検討し、**紐づけない**という結論になった。

## なぜ空になるのか(機序)

面 → 節点の表は3段で作られている(`probe_topopt/anchor.py`):

1. 面を細分して標本点を作る(面積は保存)
2. 各標本点から半径 `radius_ratio × 要素サイズ`(既定1.0)の球に入る節点へ、テント重みで
   面積を配る
3. **1節点は高々1面**。持ち主は「**最も多く面積を配った面**」(同点は面添字の小さい方)

**小さい面も節点に面積は配っている。** 負けるのは3段目の**多数決**で、隣の大きい面が勝つ。
だから「付ける」こと自体は、多数決の規則を曲げるか排他をやめるかで技術的には可能である。

## それでもやらない理由2つ

1. **排他には理由がある。** 稜線を共有すると同じ節点が「拘束されていて、かつ荷重を受ける」
   状態になり、**その荷重は黙って消える**(拘束された自由度に載せた荷重は解に効かない)。
   排他は「黙って消える」を防ぐために置かれた規則である。壊すなら代わりの守りが要る。
2. **付けても解決しない。** 節点1つに荷重を載せるのは**点荷重＝特異点**である。
   `20260904-0143` の実測で、プリセットの素の最大応力は「ρ=1 の荷重直下(点荷重の特異点)」に
   出ている。無理やり節点を付けた小さい面は、そこに応力が集中して**安全率が信用できない値に
   なる** —— しかもそれは silent である。

**つまり「付ける」努力は、黙って間違える方向への努力になる。** 正しいのは「この面は要素より
小さいので条件を置けない」と言って、別の面を選ばせるか解像度を上げさせること。

## 当面の措置(2026-09-04本人判断)

**例外にせず、メッセージを出すだけ。** 当初は実行経路の入口で落とす案だったが、本人が
通知に留めると判断した。「**いずれ解きたい問題ではある**」とのことなので、上の2点は
そのときの出発点として残す。

なお**道具は既にある**(`AnchorTable.empty_faces()`)し、受入検査も見ている。
`design_space.assert_faces_connected` は空の条件面を見つけると**意図的に判定を降りる**
(そこで落とすと原因が別の例外に化けるため)。**足りないのは実行経路の入口だけ**だった。
