# 面の添字はフィレットで壊れる（散発的に、が最悪）

トポロジカルネーミング問題の実測。build123d 0.11.1 / OCCT の `get_faces()` 列挙順序について、
**同一の面（箱の右側面・+X向き・x=30）を追跡**しながら形状を変え、添字が動くかを見た。

| 変更 | 追跡面の添字 | 判定 |
|---|---|---|
| 基準形状（箱＋穴1つ、7面） | i=5 | — |
| 既存の穴を半径 8→5 に縮小 | i=5 | 保持 |
| 穴をもう1つ追加（8面に） | i=5 | 保持 |
| ポケットを穴より前に追加（12面に） | i=5 | 保持 |
| 上面の外周に面取り（11面に） | i=5 | 保持 |
| **縦エッジにフィレット（11面に）** | **i=9** | **ずれた** |

- **面が増えるだけなら添字は末尾に付き、既存の添字は動かない**ことが多い。
- **フィレットのように既存面を作り直す操作では動く。**
- **この「たいてい壊れないが時々壊れる」性質が一番危険**。素朴に生の添字を保存すると、
  エラーにならず**静かに違う面を指す**。壊れるなら毎回壊れてくれた方がまだ扱いやすい。

**How to apply**: クリックで得た面の添字を、そのまま保存・再利用してはいけない。
その場（同一トポロジのうち）で使い切るか、意味的セレクタ式（例 `faces().sort_by(Axis.Z)[-1]`）へ
逆合成してから保存する。関連: [[ocp-vscode-selection-channel-discovery]] / [[cad-migration-deixis-layer]]
