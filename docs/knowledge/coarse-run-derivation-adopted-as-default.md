# 案5(粗く1回回して膨らませる)を既定に採用(2026-09-04本人決定)

**案5は 2026-09-10 に duocad から削除した(`derive_from_coarse_run` も専用定数も受入検査[11]も残っていない)。以下は当時の記録。** 既定は 2026-09-09 に連続値保持([[topopt-continuous-rho-at-production-resolution]])へ移り、その翌日に「製品から1行も呼ばれず、hanger の作業解像度では導出自体が失敗する」ことを理由に本人が削除を指示した。**この節の数値を現在の挙動として引かないこと。**

`probe_topopt/design_space.py` に案5(`derive_from_coarse_run`。粗い格子で1回 SIMP を回し、出た材料を
膨らませて塊にする)を入れ、案1(条件の外接直方体+余白。[[margin-box-design-space-cannot-guarantee-containment]])と
比べた。要素サイズ固定 3.635mm / 本番60反復 / 材料 107,616 mm³ で揃えた実測:

| 姿勢 | 導出 | 塊[要素] | 合計[秒] | コンプライアンス | 壁接触(材料比) |
|---|---|---|---|---|---|
| 0° | 案1 | 6,988 | 31.10 | 3.1796 | 8.8% |
| 0° | **案5** | **5,896** | **26.49** | **3.1791** | 9.1% |
| 30° | 案1 | 9,652 | 48.26 | 2.9353 | 7.9% |
| 30° | **案5** | **5,949** | **33.49** | **2.9249** | **7.8%** |

- **姿勢依存がほぼ消える。** 案1の塊は z軸30°回転で **1.38倍**に膨らむが、案5は **1.01倍**。
  軸整列の箱ではなく材料の居場所に沿うため。**案5の一番大きな効果はこれ。** 利用者は塊を見ない
  ([[topopt-needs-no-design-space-input]])ので、姿勢で結果が変わることは説明のしようがない欠陥だった。
- **塊は材料の量に追従して縮む**(材料を 50,000 mm³ に落とすと 5,896 → 4,406 要素。このとき全項目で案5が勝つ)。
  案1の塊は材料の量を知らないので 6,988 のまま動かない。
- **コンプライアンスは同等**。案5が答えを削っている証拠は出ていない。逆に塊を案1の半分まで絞っても
  コンプライアンスは動かない —— **この題材では塊の大きさは答えの質を決めていない。**
- 勝ち負けは壁への接触だけで割れる(0°で負け・30°で勝ち)。決定的な差ではない。
- **測ったのは1題材(`demo_conditions`)・2姿勢だけ。** 条件の配置は振っていない。

## なぜ速いのか(誤読しやすい)

**格子は案1と同じ**である(案5は案1の箱の中で塊を削るだけで `nelx*nely*nelz` は不変。30°で [28,24,19])。
[[enlarging-the-box-does-not-get-cheaper-in-simp]] のとおり ρ=0 の要素も系から消えないのに
48.24秒 → 31.94秒(0.66倍)になるのは、**空要素が増えて CG の収束が速くなる**ためで、自由度が減ったからではない。
**秒数の改善を「自由度が減った」と説明しないこと。**

## 判定規則が粗かった(採用の経緯)

タスクには「比較表の**全項目**で案1以上なら既定を倒してよい」と書いてあったため、runner は壁接触が 0° で
8.8%→9.1% と負けたことを理由に据え置いた。実行は正しく、規則が粗かった。**壁接触は代理指標**
(「塊の壁が答えを切っている疑い」を測るもの)で、**コンプライアンスが本命の指標**。案5の塊は材料の
居場所に沿うぶん接触率が上がるのは当然で、切られている直接の証拠(コンプライアンス)は出ていない。
本人が採用を決めた。**代理指標と本命の指標を同じ重みで並べた合否規則を書かない。**

## 新旧を比べるときの注意2つ(どちらも実際に誤読しかけた)

1. **「案5は速い」は反復数に依存する。** 粗い段は 1.3〜4.0秒の固定費(反復数に依らない)で、
   1設計反復は 0.77〜0.97倍に軽くなるが CG反復数はほとんど動かない(0.90〜1.00倍)。
   したがって `perf.py`(**8設計反復**)の基準線では合計 0.93〜1.25倍で n=30 の4行はすべて案1より遅く、
   60反復では 0.85倍 / 0.69倍で速い。**前段を足す最適化の速さは、反復数を言わずに主張しない。**
   ベンチの反復数と実運用の反復数が違うときは実運用側でも1回測ってから「速くなった」と書く。
2. **相対体積制約のまま導出を変えると、新旧のコンプライアンスは比べられない。** `perf.py` は
   `volfrac=0.3`(相対)で回すので、塊が 0.67〜0.91倍に縮めば材料も同じ比率で減る(実測 0.71〜0.91倍)。
   案5へ倒した直後の基準線は4題材×2解像度の8行とも「悪化」して見えた(bracket n=30 3.677→4.059、
   plate n=30 266.7→411.4)が、少ない材料で解いた結果を並べているだけ。機序は
   [[larger-design-space-gave-worse-compliance]] と同じ(向きが逆)。**塊の大きさを動かす変更の
   新旧比較は体積目標を絶対量(mm³)で固定してから測る。** 相対のまま測った表を残すなら
   「コンプライアンスの列は比べられない」と表のそばに書く。

## 後続への影響

案5の塊は材料量に追従するので、安全率の外側ループ(材料量を二分探索する)の各段で塊を作り直すか固定するかを
決める必要が生じた → 各段で導出し直す(a)を採った([[safety-loop-refreshes-chunk-per-bisection-step]])。
膨張量の刻みは [[dilation-in-mm-quantizes-to-the-grid-it-is-applied-on]]、膨張を絞りすぎたときの OC の退化は
[[oc-degeneracy-is-filter-loss-at-the-design-space-edge]]、粗い段へ渡す材料量の決め方は
[[coarse-stage-voxel-volume-is-several-times-the-true-volume]]。
