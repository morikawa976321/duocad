# 比較スクショは既定値を動かした瞬間に再現不能になる

duocadの形状最適化は、本番の最適化の前に**粗い格子で1回解いて塊を決める段**を持つ([[coarse-run-derivation-adopted-as-default]])。この粗い段は**その時点の `simp.DEFAULT_RMIN`** で回る。

`docs/topopt-smooth-compare/` の16枚(撮影当時は `probe_topopt/screenshots/smooth_compare/`。実験場は2026-09-05に削除し画像だけ `docs/` へ退避)は、2026-09-05の午前(`DEFAULT_RMIN` が1.5だったとき)に撮られている。同日午後に既定を2.5へ動かしたので、**同じコマンドで撮り直しても同じ絵は出ない** —— 変えたのは本番の `rmin` だけのつもりでも、比較の土俵である塊そのものが別物になっている。

さらに `probe_topopt/` を `git rm -r` したあと作業ツリーに残った72ファイル・9.3MB(`output/`・`screenshots/smooth_compare/_data/` の頂点・面JSONと面ごとのPNG・`__pycache__`)は全て `.gitignore` 対象で、**gitは一度も持っていない**。削除済みで復元手段は無い。「gitに入っているから安全」はディレクトリ単位では成り立たない —— `git rm -r` のあとは `find <dir> -type f` で残りを数え、消す前に一覧を記録し、中間ファイルが本当に再生成できるかを確かめる。

## 効かなかった対策と効く対策

「撮り直す道具を使い捨てにせずコミットする」では救えない。道具は「同じ手順」を再現するが「同じ入力」は再現しない。道具の中に既定へ追随する呼び出しが1つでもあれば、既定が動いた時点で出力が変わる。

1. **撮影時の既定値を画像と一緒に記録する**(同ディレクトリの `README.md` は実際にそうしていて、だから「もう一致しない」ことを後から言える)。
2. 本当に再現したいなら、道具側で**その段も含めて全部の値を明示して渡す口**を用意する(既定に追随しうる引数を1つも省かない。同じ罠は指紋を採る回帰検査でも起きた: [[a-check-that-asserts-the-default-has-not-changed-blocks-changing-it]])。
3. どちらもやらないなら、**その画像は撮り直せない一次資料**として扱い、消さずに残す。

## 隠す処理が入った設定の前後比較は3面が要る

「1要素幅の筋」を消す既定値を選び直したとき、旧既定 対 新既定の2面を並べた比較画像は**どちらも滑らかで差が分からない**ものになった。旧既定にはガウシアン平滑化([[gaussian-density-smoothing-fixes-mid-frequency-mesh-waviness]])が入っており、それが筋を溶かして隠していたからである。**「旧既定(出荷されていたもの)」「旧既定から隠す処理だけを外したもの」「新既定」の3面**にすると、2面目に問題が見え、3面目で隠さずに消えていることが見える。

撮影台の検査が1面の真っ黒を見逃した件は [[summed-render-check-hides-a-black-panel]]。
