疎パターンを固定して `data` だけ更新する組み立て(有限要素の COO → CSC)では、
**COO の各項が CSC の `data` のどこへ行くか**の表 `pos` を1回だけ作る。その作り方で
一時領域が大きく変わる(duocad・hanger の剛性行列で実測):

| 作り方 | 8.19mm(項 5.28M / 非零 2.37M) | 5.37mm(項 20.1M / 非零 8.84M) |
|---|---|---|
| `np.lexsort((rows, cols))`(従来) | 0.430 s / **+196.5 MB** | 1.262 s / **+834.6 MB** |
| `searchsorted`(分割なし) | 0.625 s / +101.9 MB | 2.164 s / +414.6 MB |
| **`searchsorted`(COO 側を分割)** | 0.600 s / **+77.2 MB** | 2.034 s / **+296.0 MB** |

**鍵**: CSC の (列, 行) は全体として昇順に並んでいるので、**`列 * ndof + 行` を鍵にすれば
1本の `np.searchsorted` で引ける**(列ごとに切り出す必要が無い)。一時領域が
「項数 × 8バイト」から「**非零数 × 8バイト**」へ落ちる —— 比は Z/E(非零数÷項数)で、
3次元8節点要素の連続した塊なら **0.44** 前後。さらに COO 側をチャンクに切ると、
探索の一時が「分割幅 × 8バイト」に固定される。

**代償は構築時間 1.4〜1.6倍。** 設計反復40回に対して構築は1回なので、全体に対しては
0.3〜0.6% でしかない。**一時領域を取るほうが得**。

なお `pos` は int32 で持てる(非零数が 2^31 未満なら)。実測で `pos` 自体は 21.1MB / 80.4MB。
足し込みは `np.bincount(pos, weights=vals, minlength=nnz)` の1パスが速い
(整列した並びへ `vals[order]` で並べ替えてから `np.add.reduceat` する書き方は、
double をランダムアクセスでコピーするぶん遅い)。
