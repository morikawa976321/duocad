# デバッグ表示は「切り分けたい対象を扱える場所」に置く

本人の発端(2026-09-05): 「デバッグ表示3点を開発フラグを使って本体に組み込んだ方が全体としてスマートになる気がする」。

## 決めたこと

duocadのデバッグ表示3つを `probe_topopt/`(実験場)から**本体へ移す**。

| フラグ | 出るもの |
|---|---|
| `?debug=space` | 塊(設計空間)のボクセルを薄く重ねる |
| `?debug=anchors` | 拘束/荷重に割り当たった格子節点を色分けした球で |
| `?voxel=1` | 平滑化する前のボクセル(結果メッシュは表示だけ隠す) |

- **ビルドで落とさない**(本人指示)。落とすと利用者の環境で起きた問題を調べられなくなる。
- 代わりに**フラグが無いときの画面は1ピクセルも変わらない**ことを不変条件にする。
- **移植先ではデモ題材に固定しない**(本人の完了条件)。

## 根拠

**probeは合成題材しか表示できなかった。** ところが `?debug=space` が欲しくなるのは**実物の部品で変な答えが出たとき**である。そのときprobeは役に立たず、同じ現象を合成題材で再現するところから始めることになる。切り分けの道具が、切り分けたい対象を扱えない場所にあった。

したがって「移す」ときに満たすべき条件は「同じ絵が出ること」ではなく**「元の道具が持っていた制限を持ってこないこと」**。probeの制限をそのまま移植したら、移す意味そのものが消える。
