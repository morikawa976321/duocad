# 膨張を mm で持っても、効く刻みは「どの格子でかけたか」で決まる

2026-09-04、`probe_topopt` の案5(粗い格子で1回 SIMP を回し、出た材料を膨らませて塊にする)で
実測。膨張は `scipy.ndimage.distance_transform_edt(sampling=spacing)` で mm 指定にしていたが、

- **粗い格子(要素 6.75mm)でかけると、0mm / 2mm / 4mm がすべて同じ塊**(2,414 要素)になった。
  距離場の値が要素サイズの倍数付近にしか出ないため、mm 指定なのに実質2〜3段階しか取れない。
- **本番の格子(要素 3.635mm)でかけ直すと** 0 / 4 / 8 / 12mm が 2,414 / 3,504 / 4,518 / 5,896 と
  分かれた。

**mm で持つこと自体は正しい**(格子は箱に合わせて切り直されるので、層数で持つと同じ設定が
姿勢ごとに別の物理距離になる)。ただし **mm の解像度は「かける格子」の要素サイズが上限**で、
それより細かい指定は黙って丸められる。**粗い側でかけるか細かい側でかけるかは、mm を選んだ
時点では決まっていない別の判断である。**

## 最近傍アップサンプルは 6近傍の連結性を壊さない

粗い格子の bool マスクを細かい格子へ**最近傍で再サンプル**すると、粗いセル1つは細かいセルの連続した直方体ブロックへ写り、
隣り合う粗いセルのブロックどうしは面で接する。だから 6近傍の連結成分の構造はそのまま保たれる。
実際の効き目(2026-09-04・案5): 「膨張を0にすれば塊が切れて連結性ガードが落ちるだろう」という想定は外れた。
膨張0でも塊は1成分のままで、落ちたのは体積目標が容量の端に張り付いて OC が退化したため
([[oc-degeneracy-is-filter-loss-at-the-design-space-edge]])。**再サンプルの粗さを連結性ガードで検出できると当てにしないこと。**
