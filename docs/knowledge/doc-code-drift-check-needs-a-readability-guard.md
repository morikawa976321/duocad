# 文書↔コードの一致検査は、走査が効いていることを先に落とす

文書に残した列挙が古くならないよう機械検査を付けるとき、いちばん書きやすい形は**「コード側の値が文書のどこかに文字列として在るか」を `in` で見る**ものである(duocad `topopt_checks/check_design_space.py` の `[12-6]` がこの形だった)。これには2つ穴がある。

1. **文書側に余計な行が残っていても検出できない**(片方向しか見ていない)。廃止した項目が一覧に居座り続け、それを読んだ人が存在しないものを呼ぶ。
2. **節ごと消えても、同じ文字列が文書のどこかにあれば緑**になる。掛かり先が無くなったことに気づけない。

## 代わりに置く形

- **掛かり先を見出し名で決め、見出しが無ければ落とす。** 見出しから次の同レベル以上の見出しまでを切り出し、見出しが見つからない時点で「改名したなら検査側の参照も直せ」と落とす。文書全体を対象にしない。
- **走査が効いていることを見る検査を対で置く**(「拾えた件数がN未満なら落ちる」)。文書の書き方が変わって0件になったとき、集合比較だけだと**0件 vs 0件で一致**して緑になる。
- 比較は**必ず両方向**(足りない側と余計な側)。
- **期待値を検査側に書かない。** 「7語彙」のような数や名前の一覧を定数で置くと、その検査自身が新しい手動同期先になる([[drift-check-must-run-what-it-excluded]] 後半と同じ)。数も顔ぶれもコード側から導出し、**落ちたときに直すのは文書の行**であると失敗文に書く —— そう書かないと次の人は検査の期待値を書き換えて緑にする。

## 節を切る関数はコードフェンスの内側を読み飛ばす

素直に**行頭が `#` なら見出し**と判定すると、` ```powershell ` ブロック内の `# SIMP側の数値の正しさ` のようなシェルコメントを「レベル1の見出し」と読み、**節はその1行前で終わる**。切り出した節は実質空になり、そこから拾う一覧は0件になる。duocadで2026-09-06に実際に踏んだが、上記「走査が効いていることを見る」検査を対にして書いていたので**その場で赤くなって気づけた**(集合比較だけなら静かに緑だった)。節を切る関数は ` ``` ` の出現でフェンスの内外を反転させ、内側の行は見出し判定から外す。シェル・PowerShell・Pythonの手順ブロックを含む文書ほど確実に踏む。
