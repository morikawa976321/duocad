# duocadの肥大は「在庫の掃除」では止まらない(実測)

2026-09-05に本人が再び「コメントが多すぎる」と述べたのを機に、git上のツリーを測り直した4件の実測。規律そのものは [[comment-discipline-four-kinds-only]]。

## 1. コメント減量は流入率を変えなければ戻る

`git show <rev>:<path>` で各時点の全ファイルを取り、Pythonの `tokenize`+`ast` でコメント行とdocstringだけを数えた:

| 時点 | 非空行 | コメント行 | 率 |
|---|---|---|---|
| 減量の直前 `807fca9` (2026-08-23) | 29,556 | 9,718 | 32.9% |
| 減量の直後 `2b8c49e` (2026-08-23) | 28,308 | 8,289 | 29.3% |
| 13日後 (2026-09-05) | 70,967 | 22,036 | 31.1% |

**5コミットの減量が稼いだのは3.6ポイント、13日で1.8ポイント戻った。** `2b8c49e..HEAD` で追加された42,431非空行に対しコメント約9,892行で、**新しく書かれるコードのコメント密度は減量前と変わっていない**。規律の文書化(README §0 原則5)だけでは足りなかった。

ファイルサイズも同じ片道: `web/src/viewport.ts` 388行(2026-08-13)→5,155行(2026-09-05)、`web/src/App.svelte` 950→2,461、`duocad/kernel.py` 298→2,052。**一度も減っていない。** 無人実行は足す仕事しか積まれないので、減らす力を別に用意しない限りどの指標も片道になる([[handover-cleanup-unowned]] の「基準の定義と執行主体の割当は別」)。

## 2. 文書は「行」でなく「節」の単位で増える

`docs/TOPOPT.md` の縮小タスクが2026-09-05に走った前後:

| 時刻 | 行数 | 出来事 |
|---|---|---|
| 08:15 | 3,426 | 削減タスク開始 |
| 08:18 | 3,253 | 4コミット12分で−173行 |
| 17:45 | 3,640 | 密度フィルタ半径の既定変更(1コミットで**+397行**) |
| 20:37 | 3,662 | probe_topopt削除の反映 |

**削った量の2.3倍が同日のうちに戻った。** 機序は「機能タスク1本＝日付付きの新規節1つ」。見出し32節の大半が `## ○○(2026-09-04)` の形で、実測の表・比較・判断が丸ごと入る。削減タスク自身は「消してはいけないものの線引きが広く、現存する記述の大半が現行の実測・既定値の根拠・留保のいずれかに該当した」と報告しており(目標3,239→1,500行に対し−170行)、**在庫側は既に絞ってあり、残っているのは構造の問題**である。効く形は同じ文書内に実証があった: 変異検査の記録9節を1つの表に畳み「今後は新見出しを立てず表の末尾に行を足す」と契約に書いた。反復する節(実測値・基準線・案N)に同じ形を当てれば増分が節ではなく行になる。TOPOPT.mdを畳む際の注意は [[doc-restructure-fold-vs-preserve-structural-sections]]。

## 3. 「どちらが正か」を宣言しても再掲コピーは腐る

`README.md` は冒頭の文書地図でどの文書が何の正かを宣言している(`docs/IMPLEMENTATION_PLAN.md`=設計、`MCP.md`=MCP仕様など)。それでもREADMEが内容を再掲している箇所が2026-09-05の全文監査で4組あり、**2組がコピー側だけ、あるいはコピーの連鎖ごと誤り**になっていた(第三分類「省略できる付帯入力」に実例が無いという記述は正の側も含め誤り — `add_mesh_body` の `name` が実例。失敗封筒の語彙数は正の側2つが「7語彙」で正しく、READMEと `mcp_server.py` のdocstringが「6語彙」のまま)。宣言が守るのは「直すときどちらを直すか」だけで、コピーが自動で追随するわけではない。重複を見つけたら正を選ぶだけでなく**コピーを消して参照に置き換える**。関連: [[consolidating-markdown-headings-breaks-named-cross-references-silently]]。

## 4. 一括掃除の削減率は「定常の発生率」ではない

コメント減量5タスク(2026-09-06)の効果を、対話側AIが2026-08-23の実績「コメント行の14.7%を削った」を現在の22,156行に掛けて**−3,000行**と見積もり、実績は**−232行**(13倍の過大)。文書側も−800行の見積もりに対し**+269行**。2026-08-23は規律が無かった時代のコードへの初回の掃除で、削れたのは「規律が無かったから積もった在庫」。以後のコードは規律がある状態で書かれ、経緯の語りの密度が最初から低かった。実際に消えた1,341行のうち546行(41%)が日付スタンプを含む行で、919行は書き戻し(消さずに書き換え)。

タスク本文には「数値目標を置くな」「疑わしければ残せ」と書いてあり、−3,000行を達成していたらそれはタスク違反だった。**実質の完了条件は全て満たされた**(文書の失効9件が全部ゼロ、TOPOPT.mdに「現在の正」節ができて実コードと一致、機械検査が変異で落ちることを確認)。**行数を成果の指標にしていたら「失敗」と誤判定していた。**
