同じ `PC_case_20251122.step`(27部品)を、完全に別々の2回のサーバ起動でそれぞれ読み込み、
矩形選択(`collectInBox`)の結果を比べたところ、選ばれた面の**総数は一致**(2835件・27ボディ)
したが、`bodyId` の文字列そのもの(`body-01a54896757b` / `body-10e70d05ba20` など)は
**2回の起動で1件も一致しなかった**。ファイルの内容(部品の形状・並び順)が同じでも、
`bodyId` はインポートごとにその場で振られる値であり、STEPの内容から決定的に導かれる
ハッシュではない。

**影響**: 「同じ矩形で選択結果が変わらないこと」のような回帰確認を、**別々のサーバ起動を
またいで**bodyId込みで完全一致させようとすると必ず偽の差分になる。突き合わせるには
bodyIdを無視し、ボディごとの面インデックス集合(ソート済み配列など)をキーにして
グルーピングし、集合同士が一致するかで比べる必要がある(bodyId自体は無視してよい)。

**同一サーバ起動内**(1回importして前後で比べる)であればbodyIdは変わらないので、
このグルーピングは不要 —— 起動をまたぐ比較のときだけ気をつければよい。
