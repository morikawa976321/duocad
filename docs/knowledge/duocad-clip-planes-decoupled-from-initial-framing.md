# near/farは初回フレーミングから分離して常時引き直す

## 症状と機序（2026-08-30実測）

duocadに500×366×142mm（対角約640mm）のSTEPをインポートしたら**モデルの端が消えた**。コンソールから `window.__duocad.frameAll()` を叩いたら直り、原因が確定した。

`web/src/viewport.ts` の `frameToContent()` が**2つの仕事を兼ねていた** — (1) カメラをコンテンツに合わせる、(2) `camera.near` / `camera.far` をコンテンツの外接対角から作る。そしてこれは `framed` フラグで**ページ読み込みごとに1回しか走らない**。新規・開く・インポートのどれもフラグを戻さないので、**最初に届いた形の大きさで視錐台が固定される**:

- 遠クリップは `対角 × 20`。最初が小さな部品ならfarが数百mmになり、後から入れた大きなモデルは**画面の外に出るのではなく、幾何が平面で切られる**（「見切れた」ではなく「削られた」に見える）。
- 通常のズーム・オービットではfarは**一切広がらない**。つまり**引けば引くほど切れる** — 「大きすぎて扱えない」という誤診を招く。

## 判断: 責務ごとに別の更新条件を持たせて分離

near/farの決定を `updateClipPlanes()` として姿勢決定から切り出し、(1) 内容が変わるたび（`refreshContentDiagonal()` の全呼び出し元）、(2) カメラが意味のある幅で動くたび（既存の画素基準の `cameraMoved()` 判定に相乗り）の両方で呼ぶようにした。姿勢（カメラ位置・向き）は据え置き — 勝手に動かすと操作の邪魔になるので初回だけでよい。

一般化できる教訓: **「初回だけでよいもの（姿勢）」と「常時追随すべきもの（視錐台）」を同じ一発フラグに相乗りさせると、後者が壊れる。** ビューポート系で「このパラメータは何が変わったら引き直すべきか」を決めるときは、他のパラメータの更新条件をそのまま流用しない。

副次の注意: `frameToContent()` は箱が空のとき早期returnするが、呼び出し側は**戻り値を見ずに `framed = true` にする**ので、geometryがnullのBodyだけが届く最初の1通で「1回きりの機会」が空振りのまま焼き切れる経路がある。
