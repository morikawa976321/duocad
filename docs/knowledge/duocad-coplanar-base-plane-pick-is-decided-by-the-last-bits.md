duocadの `resolveHit` は面と基準平面を**レイ距離が近い方**で決める。ところが
**基準平面に描いて押し出すと、その面は基準平面とぴったり同一平面になる**ので、
2つの距離が同着になる。素の `<` では**勝敗が浮動小数の最後の桁で決まっていた**。

2026-08-28に実地で踏んだ: `fitDistance` を**数学的に同値な式へ書き換えただけ**
(`radius / tan(min(vHalf, hHalf))` → `fitHalfHeight(radius) / tan(vHalf)`)で、
カメラ位置が **7e-14 ずれ**、`smoke-files` の(b)が面ではなくXZ基準平面を取って赤くなった。

**決着済み(2026-08-28)**: `resolveHit` は**画面で1画素にも満たない差を「手前」と
見なさない**(しきい値は `worldPerPixel()`。シーンの寸法に依らない)。見分けが付かない
ところに実体のある面があるなら、それが狙いだからである。基準平面が本当に1画素より手前に
あるときの挙動は変えていない。これにより据え置いていた `fitDistance` / `worldPerPixel` も
`fitHalfHeight` / `viewHalfHeight` へ寄せてある。

**再発の検査は `smoke-files.mjs` の(d)**。**1回クリックして面が取れても検出力は無い** ——
同着はどちらに転んでもおかしくないので、たまたま勝てば緑になる。**画角を45〜55で振って
カメラを視線上で動かし**、丸め方の違う6通りすべてで面が勝つことを見る形にしてある
(決着前の実測では51度と55度が平面を取った。**同じ画角でもクリックごとに転ぶ** ——
(b)は画角45で平面、(d)の45度は面だった)。

**切り分けの決め手は「HEADと自分の版でカメラ姿勢を並べて出す」こと。** 姿勢が最後の桁まで
同じなら自分の変更は無関係、最後の桁だけ違うならこの種の同着を踏んでいる。見た目・画面座標は
どちらも同じ(`projectFace` は同じ画素を返す)ので、そこを見ても差が出ない。
