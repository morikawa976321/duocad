# duocad: 削除verb `delete` の契約

2026-09-03に本人が決めた、`delete` verb(`duocad/verbs/delete.py`)についての一連の判断。

## 1本を新設する / キー割当は後回し

**確定選択に入っているボディとスケッチ図形をまとめて削除するverbを1つ新設する。** それまでduocadには「間違えて作った/要らなくなったものを消す手段」がundoしか無かった。

**キーボードのDelete/Backspaceへの割り当ては今回やらない**(本人明言)。理由も明言されている: **他のverbにキー割当が無い中でdeleteだけがキーを持つのは一貫性を欠く**ため、キー割当まわりは**全verbが完成してからまとめて決める**。呼べる口はUIのボタン(通常モード=ボディ、スケッチモード=図形)とMCPだけでよい。

## 領域(region)が混ざっていても拒否せず無視する

同日朝の新設時は「確定選択に領域が混ざっていたら `SelectionKindMismatch` で削除自体を拒否する(残りだけを黙って消さない)」と決めていたが、「スケッチで選択範囲に領域があると削除が失敗する」というバグ報告を受け、**同日中に本人が覆した**: 領域は無視して残り(ボディ/スケッチ図形)を削除する。

**選択が領域だけ**(削除できる対象が実際に0件)の場合は従来どおり拒否する — 「何もしないのに成功したように見える」ことは避けている。

この変更で、当初delete専用に追加した `SelectionKindMismatch.hint`(食える種別が複数あるverbで既定のエラー文が嘘になる問題への対処)の呼び出し元が消え、機構自体を撤去した。

## 反復(pattern)の元図形を消しても反復は消えない

**判断(本人・選択のみ。理由の明言なし)**: `delete` で反復(`Pattern`)の元になっている図形を消したとき、**反復そのものは消えず、その元だけ展開されなくなる**(領域0個・元図形が実在しない状態のまま文書に残る)という挙動を、そのままでよいと確定した。図形どうしの依存グラフ(元図形が消えたら反復も一緒に消す、等)は作らない。`duocad/verbs/delete.py` のモジュールdocstring「やらないこと」節に同じ判断が実装コメントとして書かれている。
