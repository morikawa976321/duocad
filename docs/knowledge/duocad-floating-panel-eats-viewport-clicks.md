# 3Dビューポートに浮かせたパネルは、レイ検査には見えない

## 何が起きたか

duocadのビューポート左上に浮かせたブラウザ(`BrowserPanel.svelte`)を入れたら、
その下の画素を狙ったクリックがパネルに吸われた。にもかかわらず
`viewport.ts` の `project*`(「その画素が本当にその面/辺/領域を取れる」ことを
確かめてから返す約束の関数群)は**取れると答え続けた** —— three.jsのレイ検査は
canvasの中しか見ないので、canvasの**上に載っているDOM**は視野の外にある。

結果として実機検査は「クリックしたのに反応しない」ではなく、**別の場所を押した後の
遠い症状**(全く違うverbのエラー)で落ちる。原因に辿り着くのに時間がかかった。

## 正しい判定

`document.elementFromPoint(x, y)` が canvas を返すかで見る。要点は、これが
「覆っているか」ではなく**「クリックを吸うか」を直接答える**こと ——
`pointer-events: none` の要素(duocadのトースト)は覆っていても吸わないので、
この判定は自動的にすり抜ける。覆いの矩形を自分で計算する方式だと、
浮かせるものが増えるたびに嘘が増える。

## 候補が複数あるかどうかで結果が割れる

覆われた画素を候補から落とすと、**候補を複数持つ射影は勝手に別の画素へ逃げる**
(面・辺・領域は三角形や折れ線を順に試し、基準平面は複数の探り点を持つ)。
逃げ場が無いのは**スケッチ平面の (u,v) だけ** —— それは画面の1画素しかない。
だから自動検査でパネルを畳む必要があるのはその1箇所に絞れた。

## 続報(2026-09-05): 常設パネルを1枚足すと、その帯の下のボディは1面も指せなくなりうる

`viewport.project(bodyId, faceIndex)` は面の三角形を1枚ずつ画面へ射影しながら **`clickable(x, y)`(上の判定)**と
`pickAt(x, y)` を見て、指せる画素だけを返す。つまり浮かせるパネルを1枚足すと、その帯の下のボディは
「クリックできる画素がゼロ」になりうる。実機検査(`web/scripts/smoke-*.mjs`)の `pickAnyFace` はこの関数を使うので、
**パネルを足しただけで既存のsmokeが落ちる**。落ち方は「ボディ X に画面から指せる面が無い」で、原因(パネル)を名指ししない。

実測: 形状最適化の実行パネル(幅320px)を左のブラウザパネルの**右**へ足したら、`smoke-optimize-mode.mjs` の左のボディが
1面も指せなくなった。**ブラウザパネルと同じ列(左端・同じ幅)の下端へ移して解決** —— 画面に**新しい帯を取らない**のが
位置の決め手である。一時的なダイアログ(`SettingsDialog`)は別の帯へ出してよい(開いている時間が短い。
[[duocad-settings-dialog-moves-next-to-the-browser]])。**モードのあいだ出しっぱなしのパネルは、モデルを覆う位置に置けない** ——
そのモードの仕事が「モデルの面をクリックすること」ならなおさら。
