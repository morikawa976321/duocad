duocadのFOVは[[duocad-fov-adjustable-from-ui]]で「0(完全正投影)または30〜90度のスライダー、既定45」に
していたが、**UIをスライダーから正投影/透視30度の2値へ縮める**と本人が決めた(2026-09-04)。

**理由(本人の実使用による観察)**: 30/40/50のあいだには**実用上の差が無く**、FOV 90はビューポート・
ビューキューブのいずれでも使う角度ではなかった。さらに**既定の45度は歪みすぎる**と判定し、既定を
30度へ下げた(同日)。

見かけの大きさを保つ距離補正が効いているため、体感するパースの強さは度数ではなく `tan(fov/2)` で
動く(30→0.268 / 45→0.414 / 70→0.700 / 90→1.0)。30 vs 50 が弁別できない＝1.74×が閾値を下回るという
ことで、使える帯(30〜70)の全幅2.6×には刻みが1つ半しか入らない。**意味のあるパース設定は実質1つ**
であり、観察は「刻みを粗くせよ」ではなく「選択肢は正投影と透視の2つでよい」を意味する。
Fusion 360もFOVの数値を露出していない。

**「実用上の差が無い」は「弁別できない」ではない**(2026-09-04に本人が明示的に訂正)。
30と45には見た目の差がある。刻んで選ばせるだけの**作業上の理由**が無い、という意味であり、
そう読み違えると「30まで下げても体感が変わらないはずだから20度まで下げる」という誤った
設計判断に繋がる(実際に一度そう判断しかけた)。**観察の言葉を弁別閾の主張として読まないこと。**

透視の値は**30度**(現行 `FOV_MIN` そのもの)。`FOV_DEFAULT` を1つ書き換えるだけで、選べる値の
範囲・`isSelectableFov`・既存の検査には触らない。

**副作用**: 既定FOVが下がるとカメラが1.55倍遠くなるため、`fitDistance` のドキュメントコメント
(45度で評価した数値と「既定のFOVでの見え方は実質変わらない」という主張)が嘘になる。

**UIだけを2値にし、`setFov`/`isSelectableFov` は 0 または 30〜90 を受け付けたまま残す。**
`web/scripts/smoke-files.mjs` が45/47/49/51/53/55度を掃いており、これはFOV機能の検査ではなく
[[duocad-coplanar-base-plane-pick-is-decided-by-the-last-bits]]の回帰検査(わずかに違うカメラ行列を
安く作る道具としてFOVを使っている)。内部APIを絞るとこの検査が巻き添えで死ぬ。

**副産物**: 正投影がスライダーとは別のチェックボックスだったために必要だった「正投影を解いたときに
戻る角度」の記憶(`App.svelte` の `fovAngle`、`SettingsDialog` の `angle` prop)が丸ごと消える。
また、FOV 90でビューキューブが約18%縮む既知の件([[duocad-view-cube-adopted]]。機序は
[[sphere-fit-perspective-distance-distorts-off-diagonal-views]])は、
90が選べなくなることで実用上解消し、視点依存の係数を入れる後続タスクが不要になった。
