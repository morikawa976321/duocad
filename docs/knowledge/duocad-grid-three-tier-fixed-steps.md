# duocadのグリッド: 3段固定・指せる範囲で切る・原点を含む

## 刻みは3段固定(本人判断)

それまでのグリッドは分割数を10に固定し、刻みを内容の大きさから導いていた。**モデルが大きかろうと小さかろうと同じ見え方になり、画面から縮尺の情報が失われていた**ため、本人が刻みを**絶対値で固定**すると決めた(2026-09-03)。線の太さがそのまま寸法の意味になる。

- 刻みは **1mm(細線) / 10mm(中線) / 100mm(太線)** の3段。内容の大きさでも視点でも変わらない。
- 段の不透明度は**画面上の線間隔[px]**という1つの量から決まる1本の規則で、段ごとの特例を置かない(100mm段も引き切れば消える)。目安は線間隔1.5pxで0・6pxで1。
- **ON/OFFの瞬間切替にせず連続的なフェードにする。** 閾値を跨ぐたびの点滅を原理的に無くすためで、**フェードにすればヒステリシスは要らなくなる**(旧実装のヒステリシスは同じ問題への対処だった)。
- 判定は必ず**投影後のpx**で行う。FOVは0(完全正投影)〜90で可変なので([[duocad-fov-adjustable-from-ui]])、カメラ距離だけで判定すると正投影で破綻する。
- 表示する平面は状態で決まる: 通常はXY平面+Z軸 / スケッチの対象待ちは3平面すべて / 基準平面へのスケッチ中はその平面+直交する軸。

内容の大きさへの追随そのものは捨てていない — **描画からは切り離し、基準平面のピック範囲とnear/farの下限にだけ残した**([[duocad-base-planes-lose-to-solids-by-depth]] と [[viewport-resize-silently-changes-what-a-click-grabs]] が同時に悪化するため)。

## 無限グリッドは「指せる範囲」で切る(実測)

シェーダーの無限グリッドに置き換えた直後、スケッチの対象待ち(基準3平面を同時に出す状態)で**ビューポート全体が白い線のノイズで埋まり、平面が3枚あることすら読めなくなった**(スクリーンショットで確認)。1枚(XY床だけ)のときは無限のほうが縮尺が読めて良いので、無限そのものが悪いのではない。

直し方は**その平面が指せるときだけ、ピック範囲(±extent)で切る**。根拠は不変条件**「見えるもの＝指せるもの」**([[duocad-depth-overlay-rule]])で、指せる範囲の外まで無限に描くと「見えているのに指せない」面積が生まれる。装飾として出しているだけのとき(スケッチ外の床・スケッチ中のスケッチ平面)は指せないので無限でよい。

## ピック範囲の枠はワールド原点を含める(本人判断)

基準平面の枠(`contentBoundsForPlane` の `includeOrigin`)にワールド原点を含めるかが論点になり、**本人の選択: 含める**。理由の明言は「**普通は原点付近にモデリングするので、原点を含めるのは問題ない**」。

代償として提示した実測: 原点から400mm離れた60mm角の箱では枠が **600mm角**(モデルの10倍)になる。含める側の利点は、**原点がどこかが常に画面から読めること**。

面グリッド(任意面へのスケッチ)は `includeOrigin: false` のままで、面自身の範囲が正である([[extent-for-floor-leaks-document-scale-into-face-scale]] — 文書スケールの前提を面スケールへ漏らさない)。

## 格子の u=0 / v=0 の線は無条件に抜く(実測)

基準3平面を同時に出したとき、**X軸(赤)とY軸(緑)が画面から消えた**。格子が `u=0`・`v=0` にも線を引くため、X軸(y=0,z=0)はXZ平面のv=0の線と、Y軸はYZ平面のv=0の線と、Z軸はYZ/XZ平面のu=0と完全に一致し、後から描いた平面の灰色の線が先の色付き軸を上書きする。描く順序を入れ替えても「どれかの軸が必ず負ける」。

**直し方は順序ではなく、格子側で `u=0`/`v=0` の1本を無条件に抜くこと。** 軸はその1本を担当する平面だけが色付きで描く。旧実装(線ジオメトリ)の `if (t === 0) continue` はこの問題への対処で、シェーダーへ移しても同じ規則が要る。
