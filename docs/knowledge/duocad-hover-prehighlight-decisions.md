duocadに「マウスホバー時、そのままクリックすれば選択されるものを事前に強調する」機能を
入れると決定。第一段の裁定7件(本人、2026-08-27):

1. **頂点は暫定的に対象外**。対象は面と辺のみ(基準平面は下記5で別途対象)。
2. **カーソル下の1つだけ**を強調する。修飾キー(Shift=追加/Ctrl=除去)を織り込んだ
   「クリック後の選択集合」の予告はしない。
3. 色の扱いは [[duocad-hover-uses-brightness-not-a-third-color]]。
4. **領域は3Dで色分けせず、スケッチ側の強調に揃える**(既存の「領域は3Dでは色分けしない」を
   ホバーでも維持する)。
5. **基準平面(XY/XZ/YZ)は半透明の板を1枚出して示す**。グリッド線を3本の
   BufferGeometry へ分割する案は採らない。
6. **既存の選択ゲートに従う**(その対象を要求しているコマンドを起動している間だけ指せる、
   という規律)。結果としてコマンド起動前は面しかハイライトされない。
7. **性能は測らずまず入れる**。ホバーの解決は1フレームに1回まで。

先送りと決めたもの: クリックの意味づけ(面クリックが選択でなくスケッチ平面の指定になる
`wantsPlane` のような場合)をホバーで区別して見せることは、必要になるまでやらない。

頂点を対象にするには「選択済みの頂点しかマーカーが出ていない」現状を変えて全頂点を
候補として出す必要があり、それは [[duocad-files-panel-selection-panel-verdict]] の
「頂点を引数に取るコマンドが無いので候補を全部見せる場面は存在しない」を覆す。
ホバーの話ではなく頂点を取るverbの話として別に立てる。

**2026-09-06の拡張**: スケッチの図形・点にはホバー強調を出し、描くverbが点を待っている間も出す(裁定6の例外。
「クリックすればここに乗る」というスナップの予告に意味が変わるため) → [[duocad-sketch-hover-snaps-to-existing-geometry]]。
ソリッドの頂点は対象外のまま。
