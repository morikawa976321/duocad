# duocadのLLM待ち時間の分散は、ほぼ全部が思考

2026-08-23、Ornith-1.5-9B(Q4_K_M・RTX 5060 Ti・62 t/s)で、同一の4手目相当の呼び出しを
seedを変えて8回ずつ実行した。

| 条件 | 中央値 | 最悪 | 生成トークン | 誤り |
|---|---|---|---|---|
| 現状(思考ON) | 3.25s | **8.09s** | **86〜518** | 1/8 |
| 思考OFF | 1.56s | 1.66s | **98〜105** | 1/8 |
| 思考OFF + `tool_choice:required` | 1.53s | 1.64s | 98〜105 | 1/8 |

- **思考を切ると出力長がほぼ決定的になる**(8回中7回が98トークンぴったり)。
  分散の出どころは思考であって、ツール呼び出しそのものではない。
- **精度は3条件とも誤り1/8で差が出なかった。** 単発の観測では思考OFFが
  verb選択を誤ったように見えたが、8試行では有意差にならない。
  **思考OFFに判断品質の代償がある、とは言えない**(このタスクでは)。

## 120秒の回はこの分布では説明できない

思考ONでも最悪518トークンであり、事故時の**7,468トークンは観測レンジの14倍**。
つまり通常のばらつきの裾ではなく、**質的に別の事象(縮退ループ)**である。
現在のサンプラは `repeat_penalty=1.0` `dry_multiplier=0.0` で
**反復抑制が1つも入っていない**(llama-serverの既定のまま)。
