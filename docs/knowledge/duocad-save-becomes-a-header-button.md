# duocadの保存は編集中のファイル1つに閉じ、ヘッダのボタン1個になる

duocadが編集中のファイル以外も上書き保存できてしまう件について、本人が以下を決めた。

**サーバ側の契約**: `Session` が「いま開いているファイル」を持ち（open/save成功で設定、new でクリア）、
`save_document()` 引数なしは現在のファイルへ上書き、`save_document(name)` は新しい名前でのみ保存し
既存名は拒否する。拒否は既存のエラー経路（`{"type":"error"}` → `onError` → トースト）で返る。

**UI**: 一覧各行の「上書き」ボタン（`FilesPanel.svelte` の `.files-overwrite`）を廃止し、
ヘッダ最上段（`#current-file` / `#save-state` と同じ行）に保存ボタンを1個置く。
「名前を付けて保存」はファイルパネルの名前欄のまま残す。

**本人が述べた理由**: 「ある瞬間、サイドバーの上書きボタンのうち意味がある（押して怒られない）のは
1つだけ」。行ごとに置く意味が無い。

検討の過程で採らなかった案: UIだけで塞ぐ案（防御がブラウザ側だけになり、リロードで現在名を失うと
保存手段が消える）、確認ダイアログを挟む案（「開くのに確認を挟まない」という既存の設計判断と衝突）、
上書きを可逆にする案（`models/.trash` への退避。予防を入れた上の保険として保留）。
