# 同じ規則がコアとUIの2箇所に実装されていた

2026-08-23、「明示的な承認は不要」という本人裁定を実装したときの実測。

`origin == "proposed"` の選択をverbに使わせない門は、**設計上は
`duocad/selection.py` の `confirmed_items` 1箇所**であり、コード中のコメントも
「ここが提案と確定の区別を実際に効かせている唯一の場所」と書いていた。

ところが `web/src/commands/CommandHost.svelte` に `needsCommit` という**独立した同じ
判定**があり、提案が載っている間は Enter を受け付けずコマンド行に
「AIの提案を承認するか、クリックして直してください(下の選択パネル)」と出していた。
理由は「往復してサーバに同じことを言われるより手前で出す」という善意の先回りである。

**サーバ側の自動commitだけを入れて実機で叩いたら、verbが1回も飛ばなかった** ——
サーバは正しく直っているのに、画面が送る前に止めていた。pytestは全部緑のまま
(pytestはWebSocketの層までしか見ない)、`npm run check` も緑。**実ブラウザで
押して初めて出た。**

再利用可能な形にすると:

- **「唯一の場所」と書いてあるコメントは、その層の中でだけ真**である。UI側が
  ユーザー体験のために同じ判定を先回りで持つのは普通に起きる。
- 規則を変えるときは、**その規則の文言(ここでは「承認」「proposed」)でリポジトリ全体を
  grepしてから**着手する。実装ファイルだけ見ても見つからない(UI側は別の語彙で書く)。
- **層をまたぐ規則の変更は、pytestと型検査では検出できない。** 実機で1回押すのが
  唯一の確認手段だった。
