**判断（本人・選択＋理由）**: duocadの2つ目の起動コマンド `python -m duocad.server` を**廃止**した。
同日の [[single-launch-path-over-options]]（手順書は上位互換の経路1本に寄せる）を、
**手順書だけでなくコード側にも適用した**もの。理由は同じで、`mcp_server` が機能的な上位互換
（MCP+WebSocket+静的配信を1プロセス）であり、**AIに何も頼まなければ手だけの操作と同じ**だから。
起動経路が2つあると「AIが変えた文書」と「人が見ている文書」が別物になりうる。

**実装で効いた3点**（再利用できる形）:

1. **モジュールは残し、`main()` だけ消す。** `duocad/server.py` は `Session` / `Server` /
   静的配信の実体で、543件のテストと `mcp_server` がimportしている。**廃止するのはコマンドであって
   モジュールではない**、という切り分けが要る。
2. **廃止したコマンドは黙って成功させない。** `__main__` を消すだけだと
   `python -m duocad.server` が何もせず終了コード0で終わる。行き先を1行出して**終了コード2**で
   止める（古い手順を読んでいる人・過去の自分に届く唯一の場所）。
3. **「下位の経路を消す」の本体は、それに依存していた側の付け替えだった。** smokeスクリプト3本が
   `duocad.server` を別窓で立てる前提だったので、**スクリプトが自分で立てて止める**形へ移した。
   副産物として「文書は接続より長生きするので毎回サーバを立て直す」という手順が不要になった
   —— **依存を消すと、その依存が要求していた手順も一緒に消える**。
