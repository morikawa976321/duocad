# duocadのスケッチ入力: 寸法はマウスで決め、数値欄は上書き

duocadの長方形・円・円弧は「位置はクリック / サイズは数値欄」、線分は「2点クリック専用で数値では引けない」という入力だった。**Fusionに揃える**ため、次の形にすると本人が決めた(2026-09-06)。

## 採る形

- 寸法は**もう1つの点**で決まる(長方形=対角、円=円周の1点、円弧=下記)。
- 数値欄は残し、**空欄ならマウス追従・打てばそれが勝つ**上書きとして働く。
- 結果、長方形・円は2クリック、円弧は3クリックで確定する(Enterを押さない)。
- サーバのverb契約(`add_rectangle` / `add_circle` / `add_arc` / `add_line` の引数)は変えず、UI層だけで閉じる。
- 設計原則「howの入力があればEnterが要る」(README §0 原則3)に**例外が1つ増える** —— 点から導ける寸法欄はhowに数えない。仕組みは [[a-dimension-derivable-from-points-is-not-a-how-input]]。

## 円弧は「始点 → 終点 → 円弧上の1点」の3クリック(中心は入力しない)

本人が述べた理由:

- **中心から始める形は採らない** ——「中心から始める円弧は円と線分で代用できる」から。
- 3点目を中心にする案を一度出したが、**Fusionを再確認したら円弧上の点になっていた**のでそちらへ変えた。

3点目を中心にできない技術的な理由: 中心は `|C-始点| = |C-終点|` を満たす必要があり**弦の垂直二等分線という1本の線の上にしか置けない**。自由度が1つしか残らないので「膨らむ向き」と「劣弧/優弧」の両方をマウスで選べない。3点目が円弧上の点なら2次元のまま自由に動けるので両方が同時に決まる。サーバは中心・半径・開始角・終了角で持つままで、3点からの変換はUI側で行う(掃引方向の罠は [[duocad-arc-sweep-is-ccw-in-kernel-but-signed-in-the-ghost]])。

## 線分には長さ・角度の数値欄を足す

長方形・円・円弧が「数値でしか寸法を決められない」側だったのに対し、線分は**逆向きの同じ非対称**(クリックでしか引けない)だった、という捉え方。同じ `fromPoints` の仕組みに載るので、4verbが「クリックでも打鍵でも置ける」に揃う。欄は**長さ・角度**(dx/dyではない)。Fusionの線ツールに合わせた。角度は度・反時計回り・X軸から(`add_arc` の角度と同じ規約)。

点を置く際のスナップは [[duocad-sketch-hover-snaps-to-existing-geometry]]。
