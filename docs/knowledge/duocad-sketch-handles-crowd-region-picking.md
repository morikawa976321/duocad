# スケッチの点マーカーは領域のクリック可能な画素を食う

## 事実(2026-08-30実測)

duocadでスケッチの点・辺を選べるようにしたとき、ピックの優先順位を
**点 → 辺 → 領域**にした(点は必ず辺の上に乗っているので、後に見ると端点を掴めない)。

その結果、`viewport.ts` の `projectRegion`(実機検査が「その領域を本当に押せる画素」を得る穴)が
SVG取り込みのスケッチで null を返すようになった。**ベジエの制御点は曲線から離れた位置 ——
つまり領域の内側 —— にも立つ**ので、領域メッシュの三角形の重心がその5画素以内に来る。
候補が三角形あたり1点(重心)しか無いと、そこで候補が尽きる。

## 解消

三角形あたり4点(重心 + 各頂点へ寄せた3点)を試す形にした。あわせて `projectRegion` は
**実際のクリックと同じ判定**(点・辺が勝つ画素は返さない)を通すようにした ——
`regionAt` だけで確かめると「領域に当たるが、押すと線が選ばれる」画素を返し、
`project*` の約束(その画素で本当にそれが取れる)が破れる。

## 一般化

**「その画素で本当にそれが取れるか」を答えるヘルパは、ピックの優先順位を1つ足すたびに
検算の条件も足さないと嘘をつき始める。** 嘘をついても実機検査は「クリックしたのに別の
ものが選ばれた」という遠い症状でしか落ちない。
