duocadは同じ「STEPを読む」が起動時とアプリ内で違う意味になっていた:

- 起動時 `--step`（`Session.load_step`）… ソリッドごとに参照ボディ＋編集用コピー＋参照を隠す。**読んだ直後から触れる**
- アプリ内「STEP読み込み」（`io_step.import_step`）… **参照ボディ（読み取り専用）だけ**。編集するには `make_editable_copy` が1ボディずつ要る（PCケースは27ソリッドなので27回）

**判断（本人・選択＋理由）**: **`--step` を廃止し、毎回空で起動してアプリ内でインポートする形にする。**
理由は「起動時にしかできないことがあるのがおかしい」であって、CLI引数を減らしたいのではない。

**この判断が効く一般則**: **起動時にしかできない操作を作ると、それは起動オプションとして永久に残る。**
duocadでは `--step` を消せない理由が「アプリ内importが半分しかやらない」ことだったので、
**オプションを消すには機能の非対称を先に消すしかない**。オプションの数はこの手の非対称の指標になる。

実装は taskbox `20260815-0325-duocad-import-step-editable` へ積んだ（2026-08-15）。
設計上の要点は、import＋編集用コピー＋参照を隠すを**1つのverb（ログ1行・undo1回）**にすること
——コマンド層からN回発行すると、27部品を読んだ後のCtrl+Zが最後の1個だけ戻す挙動になり、
duocadのverb粒度規則（[[cad-verb-granularity-rule]]）に反する。
