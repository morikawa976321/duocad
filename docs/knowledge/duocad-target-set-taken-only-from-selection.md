# duocadの対象集合はコアの確定選択からしか取らない

**本人の決定(2026-08-20)**: verbが食う面・辺・領域を引数で渡す経路を、WebSocket側からも廃止する。
MCPは最初から「引数で受けない。確定した選択から取る」だったので、これで指定方法が2つから1つになった。

**理由**: 選択集合はコア(Python)が持ち、UIのクリックもAIの述語も同じ集合を編集する。にもかかわらず
WS側だけは、Enter確定時にブラウザ(`web/src/commands/features.ts` の `edgesOf`/`regionsOf`)が
**コアの選択を添字へ変換して送り返して**いた。同じ変換が2言語に2つある状態で、片方だけ緩んでも
誰も気づかない(実際、過去に「辺の参照の `body` を捨ててアクティブBodyを丸める」事故が出ている)。
統一はMCP側の明文原則「面・辺・領域は引数で受けない」(README §5)およびREQUIREMENTS §2
「分業の境界は対象集合の指定方法で決まる」と一貫する。

**併せて過去の設計判断を明示的に撤回した**: `tests/test_ui_command_wiring.py` 冒頭は
「3層(MCP/WS/UI)は引数の形が違うので1つの表から生成しない」と統合を却下していた。
本人がこの却下を覆した —— 却下の前提だった「引数の形の差」を、この変更が消したため。
矛盾ではなく前提の解消である。ただし3つの表の統合そのものは今回もしていない
(3つの表は目的が違う: MCPはAIに見せるスキーマ、WSは許可リスト、TSは引数の集め方)。

`body_id` は残る。**Bodyは選択集合の項目ではない**ので、「どのBodyへ足す/から引くか」
「隠すBody」「複製元」は名前であって対象集合ではない。
