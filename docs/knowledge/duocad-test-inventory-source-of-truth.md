# duocadの検査一覧の正は `--collect-only`

**「いま何を検査しているか」を知りたいときは `tests/README.md` を読まず、次を走らせる**:

```
.\.venv\Scripts\python.exe -m pytest -q --collect-only
```

理由は2026-09-06に変わった。**`tests/README.md` は在庫表ではなくなったのではなく、
最初から在庫表ではない**が、根拠が入れ替わっている:

- **2026-08-28時点**: この文書は「当時の記録として凍結する」規約で運用されており（3053行）、
  すでに削除されたテスト（`test_incremental_update.py`、2026-08-22削除）を名指す記述が
  残ったままだった。**古いから在庫表にならない**、という理由だった。
- **2026-09-06時点**: 文書は「テストが定義するAPI契約」として書き直されている（974行 →
  同日の網羅追加で1199行）。冒頭が「各節は**いま何が真か**だけを書く（経緯・変更の理由・
  日付はここに置かない — それらは `git log` で辿れる）」と宣言しており、**凍結規約は失効**。
  代わりに**個々のテスト関数を意図的に列挙しない**方針になった（列挙すると手動同期になるため）。
  **新しいから在庫表になる、ではない** —— 書いてあるのは「実装が守っている契約」であって
  テストの目録ではない。

**どちらの時点でも結論は同じ**: 在庫は `--collect-only`、契約は `tests/README.md`、
なぜその検査をその形で書いたかは各テストのモジュールdocstring。3つは別物で、
**片方を読んでもう片方の代わりにしない**。

なお2026-09-06時点でも**全テストファイルに節があるわけではない**（`test_delete.py` /
`test_move_verbs.py` / `test_svg_import.py` など十数本は未収載）。
`tests/README.md` の目次を数えて「これで全部」と思わないこと。
