本人の指摘「duocadのUIがごちゃごちゃしすぎている / フォントサイズも統一感がない」を受け、
方針をAIが決めて実装した(本人委任)。

**文字の大きさは2段だけ**にする: `--fs`(13px)=本文とすべての操作子、
`--fs-meta`(11px)=本文に添える情報だけ(件数・バイト数・入力欄の注意書き・「無い」の知らせ)。
コンポーネントは生のpxでfont-sizeを書かない(`grep "font-size: [0-9]"` が空であることで守る)。
**ラベルであることは色(`--dim`)で言い、大きさでは言わない。**

直す前は 11/12/13px が混在しており、決めていたのは役割ではなく**そのファイルで誰かが
font-sizeを書いたかどうか**だった(実測: 同じボタンがヘッダ13px/ファイル一覧11px/ブラウザ11px、
一覧の1行が名前12px+メタ11px、232pxのブラウザの中だけで13/12/11pxが揃い踏み)。
**差が8%では階層は伝わらず、不揃いだけが見える。**

**操作子は線ではなく面で見せる。** `--line` を区画境界(header/.toolbar/サイドバー)と
ボタン・入力欄の枠で共用していたのをやめ、打ち込む欄は凹み(`--input-bg`)・押すものは
出っぱり(`--control-bg`)で見分け、線は区画に譲る。これは
[[duocad-boundary-color-tokens-raised]] の「枠が一緒に強くなるのは意図どおり
(枠だけ弱くしたい理由が無い限りトークンを分けない)」の**前提を覆す**もので、
その理由が見つかった形になる ——12個のボタンの枠と区画の境界線が同じ濃さで並ぶと、
線が「どこが区画で、どこが押せるものか」を答えられない。

**読み札と押せる札も分けた**: `span.tag`(未保存・編集中など)は琥珀の文字だけ、
`button.tag`(保存・設定など)だけが面を持つ。以前はヘッダで「保存済み」と「保存」が
同じ箱で隣り合っており、押せるかどうかは押してみるまで分からなかった。

**枠は常に1pxぶん確保して色だけ変える。** 太らせたり消したりすると高さが動き、
ヘッダとツールバーの行高、ひいてはビューポートの実寸が動く(実際この改修は
header 37.9 / toolbar 73 / viewport 900x789.1 を1pxも動かさずに済んでいる)。
