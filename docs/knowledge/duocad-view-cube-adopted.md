# duocad: 方向認識の対策はビューキューブで打ち止め

## 申告(2026-09-03)

本人からduocadの使用上の問題として「**軸と面の識別が難しい**」「**特にスケッチ中に、どの面をどの向きで見ているのかが分からない**」が挙がった。Z-up右手系への統一([[duocad-viewport-switches-to-z-up]])・スケッチ開始のポインティング統一([[duocad-sketch-start-is-two-steps-by-pointing]])・スケッチ退出時の視点復帰([[sketch-exit-restores-pre-sketch-view]])を済ませた後の時点で、方向の手がかりは原点を通る3色の軸線(X赤/Y緑/Z青)と3面グリッドだけだった。

## 採用(2026-09-03・本人)

**ビューキューブの追加を選び、いったんそれのみを実装する。**

- **理由(本人明言)**: 「それ一つでほとんどの問題が片付くから」。
- **領域は6面+12辺+8角の26領域**(AIが出した「辺12を省いて14領域にする」簡素化案は本人が退けた)。
- 他の対策(照明をワールド固定のキー+フィルへ／スケッチ中のタグに面名と法線を出す／正対時の `camera.up` を人間規則で固定／グリッド改修／軸線へのX/Y/Zラベル)は**見送り**。キューブが片付けるのは大域の姿勢であって、スケッチ平面の同定と正対時の向きは残る、とAIは指摘したが、本人はまずキューブ単体で様子を見る側を採った。
- 常設UIを増やさない方針([[duocad-no-standing-indicators]])との衝突は、本人がキューブを入れる側で決着させた。表示ON/OFFのトグルは作らない。
- **ドラッグでの自由回転**を持つ。ドラッグ中はPointer Lockでカーソルを消し、画面端で頭打ちにならず何回転でもでき、離すとドラッグ開始位置にカーソルが戻る。**本編の右ドラッグ軌道回転(`OrbitControls`)にPointer Lockを効かせるかは「効かさなくていい・現状維持」**(理由の明言は無い)。

実装はtaskbox `20260903-0309-duocad-view-cube` で行った。同一canvasへ第2パスで描くため、クリック判定の落とし穴が1つ出た([[same-canvas-second-pass-also-eats-clicks]])。深度は独立した空間になる([[duocad-depth-overlay-rule]])。

## 打ち止め(2026-09-03・本人)

実装が入った後、**方向認識の改修をここで止める**と本人が決めた。本人の見立ては「ビューキューブでそれなりに解決したのでは」。見送った残りは3件 — スケッチのタグへの面名・法線の表示／正対時の `camera.up` を人間規則で固定／照明をワールド固定のキー+フィルへ。このうち**照明だけはキューブと守備範囲が重ならない**(ヘッドライトはどの向きの面もカメラを向いた分だけ明るくするので、平行な面・浅い段差・面取りとフィレットの区別は視点の手当てでは原理的に良くならない)。本人はこれも承知のうえで見送った。新しい機構を足す前に**実際に使って困るかを見る**という順序。

## 投影は本編のFOVに追従(2026-09-04・本人)

キューブは当初、本編とは独立した `OrthographicCamera`(`CUBE_ORTHO_HALF`=1.8 / `CUBE_CAMERA_DISTANCE`=4)で描き、向きだけを追従させていた。本編のFOVは [[duocad-fov-adjustable-from-ui]] で可変(0=完全正投影、または30〜90度)なので、**本編がパースなのにキューブだけ正投影**という状態が生じていた。**キューブの投影も本編のFOVに追従させ、同じ画角でひずませる**と本人が決めた。本編が正投影のときはキューブも正投影。パースを本編より弱める案は採らない。

見かけの大きさはFOVによらず一定に保つため、透視のときのカメラ距離は外接球が視錐台に収まる距離 `R / sin(fov/2)`(R=sqrt(3))で出す(本編の `fitDistance` と同じ考え方。fov→0で距離→∞＝正投影へ連続的に近づく)。**落とし穴**: 素朴に「半幅1.8を画角で割る」とFOV 90でカメラ距離が1.8になり、角視点で手前の角が `1.8 - sqrt(3) = 0.068` に来てnear(0.1)に食われて消える。near/farはカメラ距離から導いて引き直す。

`R / sin(fov/2)` は球以外を対角からずれた向きで見ると FOV が大きいほど見かけが縮む(FOV 90 で約18%。
[[sphere-fit-perspective-distance-distorts-off-diagonal-views]])。UIのFOVが正投影/30度の2値になった
([[duocad-fov-ui-reduced-to-binary]])ことで90が選べなくなり、この縮みは実用上解消した。

## スケッチ中の挙動不正とその原因(2026-09-03修正)

「スケッチ中はビューキューブが通常モードと違う動きになる」(本人報告)の原因は `viewport.ts` の `lookAtSketch` が `camera.up.set(...frame.v)` でスケッチ平面のv軸を `camera.up` に焼いていたこと。`OrbitControls` は生成時のupを `_quat` へ一度だけ焼き込み以後再計算しないため、実際の回転軸(常にZ)と、`camera.up` を写すキューブの見た目が食い違っていた。実在ボディの側面(法線 `[0,-1,0]`)に貼ると `frame.v=[0,0,-1]`(真下向き)で、そのスケッチだけ天地逆のキューブが出ていた。

修正は `upForDirection`(`viewCube.ts`。ほぼ全方向でWORLD_UP(Z)を返し、視線が真上・真下に近いときだけ±Yへ切り替える)を `lookAtSketch` にも使う形。基準平面XZ/YZ(元々 `frame.v=Z`)とXY(上面図分岐が同じ+Yを返す)は無変化で、**挙動が変わるのは任意面にスケッチしたときだけ**。
