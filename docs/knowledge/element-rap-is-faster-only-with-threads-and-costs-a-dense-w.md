マルチグリッドの粗格子作用素 `A1 = P^T A P` を、`A` を作らずに要素から直接
(`A1 = Σ_e E_e W_e^T ke W_e`、`W_e = Q_e P`)組む道を測った
(duocad・hanger 5.37mm・active 34,910・粗自由度 14,412・nnz(A1) 1,016,566):

| | 秒 | 疎の三重積との比 |
|---|---|---|
| `(P^T A P)`(scipy の疎行列三重積。**本番。並列化されていない**) | 133.6 ms | 1.00 |
| 要素から直接 1スレッド | 262.2 ms | 1.96 |
| 要素から直接 4スレッド | 93.4 ms | 0.70 |
| **要素から直接 7スレッド** | **88.7 ms** | **0.66** |
| 要素から直接 12スレッド | 94.7 ms | 0.71 |

内訳(1スレッド): 24×24 のバッチ行列積 189.2ms / `np.bincount` の足し戻し 64.8ms /
CSR への詰め替え 8.2ms。**行列積が律速**で、そこはスレッドで 5.4倍(189→35ms)まで落ちる。
足し戻しは `np.bincount` が GIL を握るので 1.4倍しか落ちない(64.8→45.5ms)。

**構造の事実**: 2:1 の粗視化では細要素の8節点が必ず1つの粗要素に入るので、`W_e` の列は
ちょうど粗の8節点=24自由度に収まる(実測: 支持の**最大24・平均22.6**)。つまり `W_e` は
24×24 の密行列で、`A1` の組み立ては元の COO と**同じ 576×active 項**になる。
数値は疎の三重積と機械精度で一致(相対差 5.0e-16〜5.8e-16。nnz も完全一致)。

**代償**: 要素ごとの 24×24 密ブロック `W` が **161MB** 要る(同じ点の `K_ff` 106MB より
**大きい**)。構築の一回きりの費用 2.5秒。したがって **「K を作らずメモリで勝つ」は
matvec では成立するが RAP では成立しない**([[matrix-free-matvec-needs-element-blocks-and-dof-bands]])。

`W` は原理的には粗要素の中での細要素の位置(8通り)で決まるので、8枚の正準行列 + 要素ごとの
添字に畳めば 161MB は消えるはず。**未測定**(格子の端では支持が24未満になるので、
そのまま8種類には落ちない)。
