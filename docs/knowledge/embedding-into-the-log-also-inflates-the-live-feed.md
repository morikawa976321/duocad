# ログへの埋め込みは、保存だけでなく配信も太らせる

duocadで読み込んだSTEPの本文を操作ログの `args` へ埋め込んだ
（[[duocad-oplog-embeds-imported-step]]）ときに踏んだ。

**保存形式を変えたつもりが、配信形式も変わっていた。** duocadの `Session.state_meta()` は
「27部品でも数KB」を前提にログのエントリを丸ごと（`args` ごと）WebSocketで配っており、
**操作のたびに全量が流れる**。埋め込みを入れた時点で、PCケース（4.6MBのSTEP）を読むと
1操作あたり **4.83MB** が流れる状態になっていた。実測して伏せたあとは **10.5KB**。

**埋め込みの設計判断（サイズ・圧縮・可読性）は保存ファイルの話として検討されるが、
同じ `args` を読む経路は他にもある** —— 配信、一覧、履歴パネルの表示、MCPの応答。
どれか1つでも全量を通していると、保存側の判断が実用性を壊す形で波及する。

**直し方は「保存は本文、配信は射影」**。ログ本体は本文を持ち、配る側だけが伏せた写しを作る
（duocadでは値を「N文字は配信しない」に置き換えた）。保存（`to_json`）は本文を書くので、
自己完結性は変わらない。

**確認の仕方**: 埋め込みを入れたら、`json.dumps(配信ペイロード)` の長さを実測して比べる。
テストは通る（機能は正しい）ので、測らないと気づかない。
