# 空の並びは `None` 検証を素通りして制約を黙って無効化する(2026-09-11)

duocadの反力下限制約(`simp.optimize(reactions=..., reaction_min=ε)`)のQAで出た欠陥(`composer-2.5` が指摘)。

`reaction_min` を渡すときは `reactions` も要る、という検証が **`reactions is None` だけ**を見ていた。`reactions=[]` は通り、以後:

- グループが空なので契約検査(`_check_reaction_groups`)は `if groups:` で呼ばれない
- 反復の中でも `if groups:` が偽なので制約が1本も作られない
- 終端の検査は「下限を満たさない取付点」を数えるので、**0件 → 合格**

結果、**`reaction_min=0.2` を持ったまま無制約の `Result` が正常終了として返って**いた。同型の穴が `max_iter=0`(反復が1回も回らず測定が0件)にもあった。

**教訓は2つ:**

1. **「無い」の検証は `None` と空を両方見る。** 制約・検証・フィルタのように「0件だと何もしないのが自然」な機能では、0件が黙って無効化になる。
2. **終端の合格判定を「違反件数 == 0」で書かない。** 母集団が0件のときに真になる。「**何件検証したか**」を先に見る(`if not measured: raise`)。

検出できたのは、**指摘を受けて門を外した版で再現を試した**からである。修正したうえで「門を外すと新しい検査が落ちる」ことまで確認しないと、検査が欠陥を固定できていない可能性が残る。
