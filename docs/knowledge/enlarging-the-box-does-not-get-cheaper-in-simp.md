# 「でかい箱にしても最初の反復で勝手に削れる」は費用の話としては成り立たない

**答えについては概ね正しい。** 体積制約が絶対量なら材料の総量が固定されるので、余分な空間は
ただの空間で、出てくる形はほとんど変わらない。

**費用は下がらない。** SIMP が下げるのは密度だけで、要素は格子に残る。毎反復すべての要素が
剛性行列に入り、すべての自由度が線形方程式に入る。「削れた」のは設計上の話であって、
1反復目と60反復目の計算量は同じ。要素を実際に系から外す仕組み(アクティブセット)は
duocad `probe_topopt/simp.py` に無い。

**むしろ悪化する。** `simp.py` は「空要素にしか接していない節点は剛性 emin でしか繋がっていない
浮いた自由度で、残すと K がほぼ特異になって CG が収束しない」として `_floating_dofs` で系から
外しているが、**これは `void_mask` から反復に入る前に一度だけ計算される**。最適化の途中で
ρ が 0 になった領域はこの網にかからない。でかい箱は、このコードが守っている当の病理を
守れない形で大量に作る。

## 費用の外挿(部品 60.1×154.0×100.6mm、60反復)

| 箱 | 要素サイズ | 要素数 | 60反復 |
|---|---|---|---|
| 部品ぴったり | 1.54mm | 254k | 1.8時間 |
| 2倍 | 1.54mm | 2.04M | 29時間 |
| 3倍 | 1.54mm | 6.88M | 147時間 |
| 2倍 | 6.16mm | 33k | **7分** |
| 3倍 | 6.16mm | 107k | **34分** |

メモリも壁になる。264k自由度で1.57GB の実測があるので、2倍の箱・同じ要素サイズは
600万自由度で30GB級(このPCのRAM 31.7GB)。

**結論: でかい箱は要素が粗いときだけ払える。**「大部分は勝手に削れるだろう」が成り立つ条件は
「削れることが安い解像度でやる」ことで、それは粗い格子で1回回してから細かく仕上げる
多重解像度の1段目そのもの([[simp-cost-scales-with-fourth-power-of-resolution]] の対策③)。
つまり多重解像度は「でかい箱案」の対案ではなく、それを払える形にしたもの。

未検証のリスク: 絶対量とでかい箱を組み合わせると初期密度が極端に低くなる(箱が100倍なら
初期 ρ は 1/100)。SIMP は ρ を一様に置いて始めるので penal=3 で剛性が emin 近くまで落ち、
荷重経路が最初から存在しない状態からのスタートになる。局所解に落ちる恐れがあるが**未実測**。

逆向きの実測: 同じ格子のまま塊だけ縮めると自由度は減らないのに 0.66倍に速くなる(空要素が増えて CG の収束が速くなるため。
[[coarse-run-derivation-adopted-as-default]])。
