duocadの `web/src/gridScale.ts` の `extentFor()` は「原点中心の基準平面が内容を覆う半幅」を返すが、**`BASE_EXTENT`(100mm)を下限として強制する**(空の文書でも±100mmは確保する、という文書スケールの前提)。

任意面へのスケッチ平面グリッド(`viewport.ts` の `faceUvExtent`)の実装で、この `extentFor()` をそのまま流用したところ、40×20mmの面に対して**extent=100mmが返り**、面の何倍もの大きさでグリッドが描かれて画面の大半が線で埋まった。数値上は「関数が正しく丸めた結果」なので静的検査・型検査は何も検出せず、**実機のスクリーンショットで初めて気づいた**。

直し方は `extentFor()` を使わず、`snap125()`(丸めだけを担う下位関数)を直接呼んで、対象のスケール(面の実測サイズ)に応じた下限で丸める。

**一般化**: ある関数の内部に埋め込まれた定数(この場合 `BASE_EXTENT`)が「呼び出し元のスケール」を前提にしている場合、**その関数を別スケールの文脈で再利用すると、丸め・下限・上限のロジックだけ正しく動いて、結果の値が文脈違いのまま返る**。型は通り、テストが無ければ気づけない。再利用するなら「その関数が前提にしているスケールは何か」を先に確認する。
