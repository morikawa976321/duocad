カメラが対象を「画面に収める」ことの実機検査を、**「対象を1つでも画面へ射影できたか」**で
書くと、ほとんど何も検出しない。duocadでFOVを可変にした際、`frameToContent` の距離式を
わざと画角非依存(`diagonal * 1.2` 固定)へ戻して確かめたところ、**画角90度でシーンが本来の
0.4倍の大きさにしか写らない状態でも検査は緑のまま**だった —— 中央付近のものはどのみち
画面に残るためである。

効いたのは**射影された広がり(画面上の大きさ)を画角ごとに比べる**形。収める距離が画角に
追随していれば広がりは画角によらずほぼ一定になり、追随していなければ数倍ずれる。
このとき**測る対象の集合を揃えること**が要る —— 射影できる面の顔ぶれは画角で増減するので、
全部を使うと「拾えた面が違う」ぶんの揺れが混ざり、正しい実装でも0.73倍などになって
判定の幅が取れない。3つの画角すべてで射影できた面だけで測ると0.97〜1.10倍に収まり、
壊れた実装の0.41倍との間に十分な幅ができた。

一般化: **「収まっているか」は在否ではなく寸法の問題**であり、在否で書いた検査は
在否しか答えない。閾値は実測してから決め、決めた後に一度わざと壊して赤を見ること。
