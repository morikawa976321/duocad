`overflow-y: auto` を持つ**縦のflex容器**の中で、区分(セクション)を並べたときの罠。区分に `min-height: 0` を置くと、既定の `flex-shrink: 1` に下限が無くなり、**区分は中身より低く潰れる**。ところが潰れても中身は隠れない(`overflow: visible` のまま)ので、**リストが枠の外へ溢れて次の区分の見出しに重なる**。見出しに背景色があると、見出しが行の上に浮いて見える。

duocadのブラウザパネル(モデル29件＋スケッチの2区分)で実測した値: 区分1は中身740pxなのに**444pxまで潰れ**、リストは区分の底(678px)を突き抜けて**974pxまで伸びて**いた。「スケッチ」の見出しは679–706pxにあり、そこを通る行と重なる。スクロールバーは出る(スクロール可能領域は子の溢れを含む)ので、**一見スクロールできているように見えるのが厄介**。

- **見分け方**: 各区分の `getBoundingClientRect().height` と `scrollHeight` を並べる。**食い違っていれば潰れている**。重なりの有無は行の矩形と見出しの矩形の交差で直接数えられる(`elementFromPoint` を使うまでもない)。
- **直し方**: 区分を `flex: 0 0 auto` にして中身なりの高さを保たせ、**スクロールは容器が1つだけ持つ**。区分ごとに独立スクロールさせる形(区分に `min-height:0`＋リストに `overflow-y:auto`)も成立はするが、flexの縮小は基準サイズに比例するので**小さい区分まで一緒に潰れる**(実測で「スケッチ」区分は見出し28px＋2pxまで潰れた)。
