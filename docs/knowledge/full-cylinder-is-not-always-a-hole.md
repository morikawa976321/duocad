# 全周円筒は「穴」とは限らない（面の種類だけで意味を判定しない）

duocad の受入テストを本人の実物から決めるため、STEPファイルの面の種類を数えて
「どのverbが要るか」を逆算した。その過程で誤った判定をした実例。

## 何を間違えたか

`shelf_attachment_GD.step` を **56面 = 平面34 + 全周円筒22 → 「板に22個の穴」** と読んだ。
実際は **17個の独立したソリッド**で、体積を見れば正体が分かる:

```
4面・体積 1767.1 = π·5²·22.5    → 円柱（スペーサー/ネジ軸）
3面・体積  117.8 = π·2.5²·6     → 小さい円柱
```

**ネジ・スペーサー類の集まりであって、ブラケットの設計データではなかった。**
`_GD` が与件（参照部品）、`_result.stl` が本人の成果物、という命名だったとみられる。

## 誤りの構造

- **全周円筒は「穴の内壁」でも「ピンの外側」でもありうる。** 面の種類は向きを持たない
- **ソリッド数を見ていなかった。** 1ソリッドか17ソリッドかで意味が正反対になるのに、
  面の総数だけで「1つの板」と決めつけた
- 影響: **v1の受入テストの定義が丸ごと誤っていた**（実物でない物を受入対象にしていた）

## How to apply

B-repから設計意図を逆算するときは、**面の種類の前にまずソリッド数と体積を見る**。

- ソリッド数 → 1部品かアセンブリか（意味が正反対になる）
- 体積を既知の式（π·r²·h 等）と突き合わせる → 面の種類だけでは分からない正体が出る
- 面の法線の向き（内向き/外向き）を見れば穴とピンは区別できるが、**ソリッド数の方が先に安い**

**そもそも、他人（メーカー）の配布データが混在しているフォルダで
「本人の設計」を面の統計から推定するのが危うい。** ファイル名の規則（`_GD` / `_result`）を先に確かめるべきだった。
