# モデルが守れない規律は、文章で頼まずコードで止める

duocadの `agent_instructions()` には「曖昧・探索的な依頼なら propose_selection で止めて
尋ねる」「迷ったら止める側に倒す」と明記してある。**Ornith-1.5-9Bはこれを守れなかった** ——
「角が尖ってて危ないから、いい感じに処理しといて」に対し、止まらず R1.5mm を自分で決めて
fillet まで適用した。

観察された非対称: **このモデルは「能力の限界」では止まれるが「権限の限界」では止まれない。**
述語が無くて選べないときは正しく停止して報告したのに、「やっていいか分からない」は
認識できずに進んだ。9Bクラスに「やらない判断」を期待するのは分が悪い。

そこで2026-08-23、規律を実装へ移した(`Param.dimension` の印 + ループ側のガード)。
実機で、曖昧な依頼3回のうち1回はガードが fillet を阻止し、残り2回は合計時間の打ち切りで、
**適用0/3**。寸法を明示した依頼は3/3で完走し誤発火なし。

**線引きの原則**: プロンプトで頼んでよいのは「間違えても直せること」だけ。
**undoでしか戻せない副作用**が絡む規律は実装で止める。文章は守られたかどうかを
後から検証できないが、コードは検査で固定できる。

設計上の留意(実装して分かったこと):
- ガードは**例外にせず失敗の封筒で返す**。モデルはそれを読んで提案側へ回れる。往復が
  1つ増えるだけで、適用してしまった形をundoで戻すより安い。
- 判定は**厳密な照合にしない**。「直径8mm」から `radius: 4` を導くのは正しい導出であり、
  値がそのまま本文にあることを求めると普通の依頼が通らなくなる。見るのは
  「人が量を与えたか」だけでよい。
