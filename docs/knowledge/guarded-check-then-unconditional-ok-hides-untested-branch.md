実機smokeで `if (条件が成立するときだけ検査する) { ...fail()... }` の直後に無条件で `ok('...')` を書くと、条件が成立しなかった回でも「検査した・通った」と表示される。duocad `smoke-clip-planes.mjs` で実際に踏んだ: `if (nearEdge > 0 && !(near <= nearEdge)) fail(...)` のガード自体は正しい(カメラが外接球の内側にいるときは近側クリップを判定できないので、判定しないこと自体は正しい設計)。しかし直後の `ok('外接球の近端はnearより奥')` が無条件だったため、`nearEdge` が負(検査対象外)の実行でも同じ「OK」が出て、この検査が一度もその分岐を通っていないことに誰も気づけなかった(QAが実際に走らせてログの数値を読むまで発覚しなかった)。

**教訓**: ガードで守られた検査には、`ok()` もガードの中に入れ、ガードの外側(スキップ時)には別の文言(「検査対象外」等、スキップした理由を書く)を出す。**検査の合否と「検査したこと自体」を同じ1行のok()で済ませない** — 実行はしたが判定は素通りした、という状態を緑色の1行が覆い隠せてしまう。

**副次的な教訓(同タスクで実際に確認した設計上の事実)**: near/farの「外接球containment」検査は、near側とfar側が**互いに鏡像で、同じカメラ姿勢では片方しか検査できない**。文書全体がカメラの外側にある(nearEdge>0)姿勢を作るには、i) 内容がその後**縮む**(大きな形で初回フレーミング→undoで消して小さな形だけ残す)、ii) 実カメラがその小さな形の外側・近くまで**実際に寄る**(`frameAll()`等の明示的な再フレーミングは、検査したい「自動追随の欠落」そのものを迂回してしまうので使えない)、の両方が要る。詳細と実装はduocad `3101173`(`web/scripts/smoke-clip-planes.mjs`)。
