成果物は `duocad/models/`(**`.gitignore` 対象なのでコミットされない**)。

## 4.4mm —— 製品の経路(`Session.run_optimization`)

`state="done"` / `converged=True` / **9評価** / `rel_tol=0.08` / 40反復。

- 安全率 **156.758**(目標2.0)/ 収束材料量 **1,315,866.508 mm^3** / 三角形 **14,580**
- 格子 43x76x60 = 196,080箱(実spacing 4.4247mm)、最大の評価で塊 137,683
- 全体 **2,107秒**(35.1分)。組立 112.93 / solve 861.68 / mg_setup 166.18
  (うち splu 8.00・RAP+平滑化 158.18)/ slice 27.25秒。CG 19,394反復 / 366 solve
  (平均53.0・最大144)。ピーク +3,767MB・スワップ無し
- `models/hanger-4.4mm-void.stl`(729,084バイト)
- **面アンカーの門は余裕 0.15mm で通っている**(実測 13.120mm / 許容 13.274mm)。
  [[anchor-centroid-gate-false-positive-on-curved-condition-faces]] のとおり、
  距離はほぼ一定で許容だけが要素サイズで動くので、**この解像度は崖っぷちである**。
- 探索の途中で `too_little` を3回踏んだ。うち2回は
  `DesignSpaceDisconnectedError`(拘束と荷重が繋がらない)で、材料 1,186,138mm^3 と
  1,056,410mm^3。**収束値 1,315,867 のすぐ下に不連結の崖がある。**

## 2.4mm —— **製品の経路ではない**(単発)

2.4mm は製品の経路を通らない([[hanger-product-path-passes-only-at-4400um-and-4800um]])ので、
`design_space.run_topopt` を直接呼び、**材料量を 4.4mm の収束値に固定して40反復1回**回した。
**安全率探索ではない。**

- 格子 78x138x109 = **1,173,276箱**(実spacing 2.4076mm)/ 塊 **172,310** / 自由度
  3,623,730(自由 567,246・拘束 3,056,484)/ nnz **43,235,469** / `_iK`+`_jK` 794.0MB
- 全体 2,484秒(41.4分)。組立 60.57 / solve 1,035.88 / mg_setup 84.95 / slice 14.53秒。
  CG 7,763反復 / 40 solve(平均194.1)。ピーク **+4,970MB**・**スワップ無し**
- 安全率 **154.701**(4.4mm の 156.758 と 1.3% 差)/ 三角形 **50,244**
- `models/hanger-2.4mm-void.stl`(2,512,284バイト)

**自由度の 84% が拘束側に回っている**(3,056,484 / 3,623,730)。`_floating_dofs` が
「空要素にしか接していない節点」を外すためで、2.4mm のように塊が箱の15%しかない構成では
これが効く。
