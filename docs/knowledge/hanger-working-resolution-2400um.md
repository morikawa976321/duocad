`models/hanger_bar_attachment.json` が製品の経路を一度も通っていなかった問題
([[hanger-product-path-passes-only-at-4400um-and-4800um]])への対応。**2つ決めて、1つは
意図的に決めなかった。**

## 決めたこと

1. **`optimize_run.MAX_ELEMENTS` を 120,000 → 2,000,000**(`duocad` の `4b9d2e2`)。
   これで 2.4mm が `[下限 2.065mm, 上限 13.264mm]` に入り、指定できるようになった。
2. **hanger の作業解像度は 2.4mm**(箱 1,173,276 / 塊 610,384)。**コードは変えず**、
   回すときに `element_size_mm=2.4` を明示的に渡す。
   **2026-09-09に製品の経路(`optimize_run.run`)で完走した。** 当初は面アンカーの門に
   落ちて SIMP を1回も呼べなかったが、比べる相手を面積重心に直して通るようになった
   ([[anchor-centroid-gate-false-positive-on-curved-condition-faces]]・duocad `d3b1229`)。

## 決めなかったこと ——「既定の決め方」は当面そのまま

既定は文書ごとに導出され、**いちばん粗い(=条件面が許す上限)** を採る。hanger では
13.264mm。これを 2.4mm 固定に変える案は**採らなかった**:

- **2.4mm は hanger 固有の事情(薄い部品が5.00mm)から出た数字**で、他の部品へ持ち出す
  根拠が無い。絶対値の固定は部品の大きさに追随しない(10mm角の部品なら4要素、
  500mmの部品なら200要素跨ぐ)。
- 原因に直接対応するなら「保持・除外の最小辺が N 要素跨ぐ大きさ」のような規則
  (hanger だと自動で約1.7mmが選ばれる)だが、**実測が溜まる前に規則を決めない**。

## 代償(承知のうえ)

- **完走の実測(2026-09-09・void除去済み・既定は連続値保持)**: 箱 1,096,894要素 /
  採用材料 70,634.5mm^3(容量の 0.46%)/ 最小安全率 2.024(目標2.0)/ 最終の塊 11,368要素 /
  三角形 10,236枚。**評価5回で 3.57時間・峰 25.9GB。** ただしこれは材料量の範囲を
  `[54233, 87036]` へ絞った再開分で、範囲を絞らない初回は評価10回目で落ちるまでに
  5.7時間かかっている([[safety-search-dies-on-residual-failure-at-low-material]])。
  **範囲を絞らない完走は8時間級**と見ておくこと。1反復あたりの費用と安全率の曲線は
  [[hanger-2400um-measured-cost-and-safety-curve]]。
- **`MAX_ELEMENTS` はもうメモリの安全域ではない。** 上限いっぱいの200万要素は
  現行実装で約46GBとなり、この機械では走らない。**「実物が通るための政策上の上限」**
  として読むこと(定数のコメントに同じことを書いた)。実用の目安は120万要素前後。
