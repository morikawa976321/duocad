# 実機確認スクリプトは、ポートが埋まっていると古いサーバを撮って緑になる

duocad `probe_topopt/shot.mjs`(headless Chromeで実機確認して `screenshots/` に撮る)は、
`server.py` を子プロセスで起動してからブラウザを向ける。**ポートが既に埋まっていると
子プロセスは bind に失敗して死ぬが、ブラウザは既に走っていた方のサーバに繋がる。**

そのサーバは**古いコードを読み込んだままのプロセス**である(Pythonは起動時に import した
モジュールを保持するので、後からソースを直しても反映されない)。それでもスクリプトの
成功条件 —— `state === 'done'` / `surface === 'smooth'` / 反復数 / `renderer.info.render.
triangles > 0` —— は**全部満たされる**ので「OK: 実機確認に合格」と表示される。

実測: メッシュの巻き順を直した**後**に撮った `result_smooth.png` が、直す**前**の画像と
**md5まで一致**した(`fca3b7e2…`)。ログには `OSError: [Errno 10048] bind on ('127.0.0.1',
8776)` が出ていたが、スクリプトはそれを終了条件にしていない。

回避: `PROBE_HTTP_PORT` / `PROBE_WS_PORT` に空きポートを渡して走らせる
(`shot.mjs` は両方を尊重し、画面URLにも `?ws=` を付ける)。**動いている方を落として
ポートを空けるのではなく、こちらがずれる** —— 落とす相手は人が開いているサーバかもしれない。

一般化: **子プロセスとして立てたサーバの起動失敗を、クライアント側の成功条件だけで
判定してはいけない。**既に同じポートで何かが動いていると、そちらへ繋がって偽の緑になる。
実機確認スクリプトは「自分が立てたプロセスが生きているか」を独立に確かめるべき。
