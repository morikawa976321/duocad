duocadのAIパネルで、プロバイダを llama-server(openai_compat) から Claude(anthropic) へ切り替えて適用すると必ずエラーになった。エンドポイント入力欄は `{#if providerDraft === 'openai_compat'}` で**表示だけを止めていた**ので、`baseUrlDraft` は llama-server のURLを保持したまま送信され、サーバの「anthropicに `base_url` は渡せない(実キーが外部ホストへ出る)」という防御に当たっていた。

**詰みになった理由は、防御が正しかったこと**。サーバは `openai_compat` のとき `base_url` に既定値を必ず埋めて返すので、設定を開き直すたび同じURLが入り直す。つまり**画面操作だけではClaudeへ戻れない**。エラーメッセージはサーバ側の正しい説明を出しているので、画面を見ている限り原因(隠れた欄)には辿り着けない。

**一般形**: 条件付きレンダリングは**DOMを消すが状態は消さない**。フォームの一部を出し分けるなら、隠す判断と送る判断を同じ場所で持つこと。隠れている値を送信時に落とすだけでは、モデル名のように「別プロバイダの値が残ったまま設定は通り、実行時に落ちる」形が残る。

**採った対処(2026-08-27・ユーザー判断)**: 送信時に落とすのではなく、**プロバイダを切り替えた時点でモデルとエンドポイントの打ちかけを捨てる**。あわせて `bind:value` をやめ、切り替えの処理を1つの関数に集約した(束縛の更新と `onchange` の実行順に依存させないため)。
