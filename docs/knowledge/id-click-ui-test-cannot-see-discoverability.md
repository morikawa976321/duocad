# IDクリック方式の実機UI検査は発見可能性を検査していない

duocadの実機UI検査(`web/scripts/*.mjs`, puppeteer)は `page.click('#sketch-new-XY')` の形で
IDを直接指定してクリックする。これは緑になるが、示しているのは

- **そのIDの要素が存在して押せる**

だけであり、次のどれも検査していない:

- ボタンが**主要な操作面(ツールバー)に居るか**、それとも別の場所(サイドバー最下部)か
- ラベルが**操作を表す語**か(duocadのスケッチ開始は `XY` `XZ` `YZ` という平面名のみで、
  「スケッチ」「新規」という語がボタン側に無い)
- 空の文書のような**初期状態で、次にやるべき操作へ視線が向くか**
- `page.click` は要素を**自動でスクロールして可視域に入れる**ので、画面外にあっても緑になる

duocad v1の完成条件「全verbを人間とAIの両方が満足に使える状態」が19/19で満たされたと
判定されたのに、本人が「スケッチを開始するUIが無い気がする」と言う状態が両立したのはこのため。
検査が測っていたのは**到達可能性**で、本人が欠けていると感じたのは**発見可能性**だった。

再利用可能な教訓: UIの検査をIDクリックで書く場合、「押せる」の緑は
**その操作をユーザーが見つけられる保証を一切含まない**。発見可能性は自動検査の外側に残る。
