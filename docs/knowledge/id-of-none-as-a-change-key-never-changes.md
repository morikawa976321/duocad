# `id(常にNoneの値)` を変更検出の鍵にすると、版が二度と上がらない

duocad の `DocumentView.body_revision()` は
`key = (id(body.shape), body.visible, レシピ)` の変化で版を上げ、差分配信が
「版が同じ = 変わっていない」と判断する。形状は差し替えであって書き換えではないので、
`id()` を控えるのは正しい設計である。

ここに **`shape` が常に `None` である種別**(三角形メッシュのボディ。形は別フィールド
`Body.mesh` が持つ)を足すと、`id(None)` は常に同じ値なので**その種別の版が二度と
上がらなくなる**。可視性が鍵に入っていたおかげで表示切替だけは動き、
**「形が変わったのに画面が更新されない」だけが残る**という気づきにくい壊れ方をする。

## 一般化

- **「同一性で変更を測る」鍵は、その値が入る**すべての**経路で非Noneであることに
  依存している。** 形の持ち方を1つ増やしたら、鍵にもそのフィールドを足す
  (duocadでは `id(body.mesh)` を追加した)。
- 同じ形の依存が**キャッシュの当たり判定**にもある(`cached[0] is body.shape`)。
  片方だけ直すと、版は上がるのに古いキャッシュが返る/その逆になる。**版とキャッシュは
  必ず同時に見ること。**
- 検査は「表示を切り替えたら版が変わる」ではなく、**新しい種別のボディで版が動くこと**を
  直接見る(可視性が鍵に入っていると前者は通ってしまう)。
