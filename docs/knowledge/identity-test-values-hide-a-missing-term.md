# 恒等になる特殊値でテストを書くと、その項の欠落を検出できない

duocadで「軸上の点まわりの回転」を `T(p)·R·T(-p)` で組んだ。実機検査は軸を**原点を通るZ軸**にして「(10,0,0) が (0,10,0) へ移る」を当てていた。テストは緑で、変異検査(角度の符号を反転)も赤くなったので噛んでいるように見えた。

しかしQA(cursor composer-2.5)の指摘どおり、**`p = 原点` では前後の平行移動が恒等**である。`T(p)` と `T(-p)` を丸ごと消す変異を入れても通った。「軸の位置」というこの機能の中身がまるごと未検証だった。

軸を非原点(`x=10` を通るZ軸)にして、軸上の点・軸から離れた点・軸方向へずれた点の3点を当てる形に変えたら、同じ変異で赤くなった。さらに「Z軸・正の角度・単位ベクトル」だけだと**軸の取り違え・符号の反転・正規化の忘れ**が全部素通りするので、Y軸・負の角度・長さ2の向きベクトルのケースも足した(`.normalize()` を消す変異で実際に赤くなる)。

テストの入力に選びがちな「きれいな値」(原点・単位行列・0・1・軸に平行)は、**式の一部を恒等にする値**でもある。恒等になった項は実装から消えていても結果に現れない。

- 変換のテストは**関わる項が全部効く値**を選ぶ(原点を通さない・軸に平行でない・角度は正負両方・ベクトルは非単位)。
- 「変異を入れたら赤くなった」は**その変異についてしか語らない**。落としたい欠陥の種類ごとに変異を作る(符号・項の欠落・正規化の忘れは別々の変異)。
- **不動点(軸上)と動く点**を両方当てると、恒等変換に潰れた実装も捕まる。
