# LLMエージェントは矛盾した指示で思考が暴走する(文脈枯渇と紛らわしい)

2026-08-20、duocadのツール呼び出し検証で遭遇。

**症状**: 「いま確定している選択の**辺**にフィレット」と指示したが、確定していたのは**面**3枚だった。
モデルは `get_selection` / `describe_document` / `describe_shape` / `describe_predicates` / `measure` と
**確認ツールを5回繰り返して手が止まり**、次の1リクエストが600秒経っても返らなかった。

**誤診しかけた原因**: 「文脈が伸びたせい」と考えたが**違った**。矛盾を除いた同条件の再実行では
プロンプトは4,005→5,789トークンまでしか伸びず(`-c 16384` に対し余裕)、全7ターン170秒で完遂した。
**伸びるのは思考(reasoning_content)の側**で、難所のターンだけ1,986字・85秒に膨らむ。
矛盾があると、この膨らみに天井が無くなる。

**対策**: エージェントループには (a) `max_tokens` の上限、(b) 1リクエストの短いタイムアウト、
(c) 打ち切ったときに「何が矛盾していたか」を返して再指示させる経路、が要る。
指示の一貫性はUI側で担保する(確定済み選択の種別と、これから呼ぶverbが要求する種別を突き合わせる)。

**教訓の一般形**: エージェントが遅いとき、真っ先に疑うべきは文脈長ではなく**指示の矛盾**である。
文脈長は測れば一瞬で否定できるので、先に測る。
