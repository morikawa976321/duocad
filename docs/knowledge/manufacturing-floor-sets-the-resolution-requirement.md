# 「解像度をどこまで上げるべきか」は製造下限が決めている

`probe_topopt` の密度フィルタ半径 `rmin` は**要素単位**である(既定 1.5要素)。しかも
`anchor.run_pipeline` / `design_space.run_topopt` から**渡す口が無い**。
つまり**解像度を変えると物理的な平滑化スケールが変わり、別の設計問題を解いている**。

これは [[topopt-needs-no-design-space-input]] の系列で 0142 が直したもの
(体積分率が塊の大きさで材料量を変える)と**まったく同じ型**である ——
**格子単位で持っている量は、格子が変わった瞬間に物理を変える。**

実物部品(最長辺154mm)で並べるとこうなる:

| 分割数 | 要素サイズ | `rmin`=1.5要素 | 相当する最小部材幅 |
|---|---|---|---|
| 40 | 3.85mm | **5.8mm** | 6〜12mm |
| 60 | 2.57mm | 3.9mm | 4〜8mm |
| 100 | 1.54mm | 2.3mm | 2〜5mm |
| 128 | 1.20mm | 1.8mm | 2〜4mm |

## 2つの下限が挟み撃ちにする

- **製造側**: PETG / 0.4mmノズル。壁2本の 0.8mm は「形はできるが構造ではない」。設計値が出る
  最小部材幅はおおむね **2〜3mm**。密度フィルタは最小寸法を厳密には保証しない(保証には
  ロバスト定式化＋投影が要る)が、目安として部材幅は `rmin` 〜 2×`rmin`。
  → **狙うなら `rmin` ≈ 1.5〜2mm**。
- **数値側**: `rmin` が1要素を下回るとフィルタが効かずチェッカーボードが出る。
  → **`rmin` ≥ 1.5要素、つまり要素サイズ ≤ `rmin` / 1.5**。

**いまの分割40はフィルタが製造下限よりはるかに粗い。** 2mm の部材が作れるプリンタに対して、
最適化は6mmより細い部材を出せない —— **製造能力を使い切っていない。**

## ここが効く

**`rmin` 2.0mm を満たすには要素サイズ ≤ 1.33mm が要り、154mm の部品なら116分割以上。**
現状で1.8時間を超える領域である。つまり [[four-thirds-cost-law-is-the-jacobi-preconditioner]]
の速度の話は、**製造要求から逆算された必要条件**であって、単なる快適さの問題ではない。

以前「待ち時間と解像度の折り合いが未決」と整理していたが、**その折り合いの答えは製造下限が
持っていた**。感覚で決める問題ではない。

## 採った形(2026-09-04本人了承)

値を1つ固定するのではなく、**両方の下限を明示して、破ったら数字で教える**:

- `rmin` を mm で指定する口を作る(要素単位の口は残す・排他)
- **既定は要素単位 1.5 のまま。2.0mm を既定にしない** —— そうすると現状のデモが全部落ちる
  (デモは最長軸22分割で、要素サイズが 1.33mm に遠く及ばない)。2.0mm は README の**目標値**。
- 下限を破ったら例外にし、**逃げ道を2つとも数値で言う**(要素サイズをいくつ以下にするか /
  この解像度で指定できる `rmin` の下限はいくつか)
