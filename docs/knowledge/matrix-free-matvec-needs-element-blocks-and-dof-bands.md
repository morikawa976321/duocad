duocad の SIMP で `K` を作らずに `K_ff · v` を計算する実装を4通り測った
(hanger 5.37mm・active 34,910・自由度 118,083・nnz 8.83M。最小値):

| 実装 | 1スレッド | 7スレッド | 12スレッド |
|---|---|---|---|
| 選択行列1本 + 行ブロック並列 | 4.328 ms | 4.603 ms(**遅くなる**) | — |
| `np.take(out=)` + 選択行列(直列) | 4.172 ms | — | — |
| 要素ブロック(自由度ベクトルをスレッド数だけ作って足す) | 3.485 ms | 3.091 ms | 3.923 ms |
| **要素ブロック + 触る自由度の帯だけ返す** | 3.740 ms | **1.567 ms** | **1.406 ms** |
| 疎(本番の `_BlockedMatvec`) | 5.706 ms | 2.210 ms | 1.879 ms |

**3つとも要る。1つ欠けると本番より遅い:**

1. **gather も scatter も選択行列(疎行列 × 密ベクトル)で書く。** `ve[idx]` も `np.bincount` も
   numpy のインデクシングで **GIL を握ったまま**なので、スレッドで割っても速くならない。
   scipy の CSR 行列ベクトル積は C 実装で GIL を解放する —— **並列化の唯一の入口**。
2. **要素ブロックへ割る。** 行列を持たないので行ブロック分割(`_BlockedMatvec`)は使えない。
3. **各ブロックが返すのは「そのブロックが触る自由度の帯」だけにする。** 自由度数ぶんの
   ベクトルをスレッド数だけ作って足し合わせると、**集約そのものが律速になる**
   (12スレッドで 3.92ms 対 1.41ms)。要素の並びが格子の x 優先なら、要素ブロックが触る
   自由度はほぼ連続した帯になる。

密度は scatter 側の値へ畳み込む(別立ての `fe *= ee[:, None]` は出力の確保ぶんだけ高い)。
その代わり**密度が変わるたびに作り直す**必要がある。

CSR 行列ベクトル積が GIL を解放する性質そのものは [[scipy-csr-matvec-releases-gil-sparse-sparse-does-not]]。
`P^T A P` のほうは要素から直接組んでもメモリで勝てない([[element-rap-is-faster-only-with-threads-and-costs-a-dense-w]])。
なお本番へ採ったのは void 除去だけで matrix-free は入れていない([[duocad-void-removal-adopted]])。

4測定点での最終比(matrix-free / 疎、それぞれ最良スレッド数): **0.67〜0.92** ——
**matrix-free のほうが速い。** メモリは選択行列2本 11.3MB 対 疎 56.9MB(`kf` 28.5MB +
`_BlockedMatvec` の行ブロックの写し 28.4MB)で **5.0倍少ない**(hanger 8.19mm)。
数値は疎との相対差 5.6e-16〜1.0e-15。
