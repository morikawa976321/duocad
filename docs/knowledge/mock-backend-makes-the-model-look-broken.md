# 模擬バックエンドで測った「モデルの欠陥」は、模擬の欠陥だった

2026-08-22、Ornith-1.5-9Bがduocadの29ツールを扱えるかを、**固定応答の模擬バックエンド**で
測った。そこで2つの「欠陥」を観測し、あやうく誤った改修を実装しかけた。

- 「**存在しない図形IDを捏造する**」 — モデルは「ID形式を推測して試します」と述べて
  `entities: ["c1"]` を渡した。原因は模擬の `describe_document` が
  `sketches[].entities[]` を返していなかったこと。**実物は最初から全図形の
  `entity_id` を返している**(`mcp_server.py` の `sketches_out`)。
- 「**6手を超える複合操作で破綻する**」 — 模擬では14手かけて未完了だった。
  **実duocadに繋いだら同じ課題を5手で完走した**(捏造ゼロ・エラーゼロ)。
  模擬が状態変化を返さないので、モデルは正しく「まだ反映されていない」と読んで
  確認ループに入っていた。**空回りはモデルの判断としてはむしろ正しい。**

教訓: **能力の測定に模擬を使ってよいのは、模擬が実物と同じ情報を返すときだけ。**
省略した項目はそのままモデルの失点として現れる。エージェントの評価では、
遅くても実物に繋ぐ方を選ぶこと。模擬で出た失敗は、実物で再現するまで
モデルの欠陥として記録しない。
