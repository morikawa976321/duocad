# 定義の変異検査は「その1件だけが落ちる」ことで示す

2026-09-04、probe_topopt の連結性ガード(taskbox `20260903-2235`)で得た作法。
「連結性は6近傍で判定する」という**定義**を明文化したとき、その定義が実装と一致していることを
検査で示すには、**定義を変異させたときに落ちる検査が実在すること**を見る必要がある。

実際に当てた変異は3つで、落ち方が3通りに分かれた:

| 変異 | 落ちた検査 | 何を示すか |
|---|---|---|
| 呼び出し自体を外す | 正常系 + 断ち切り配置 | ガードが経路に繋がっている |
| 判定の本体を外す | 断ち切り + 直接入力3件 | 判定そのものが効いている |
| **定義を 6近傍 → 26近傍に変える** | **角1点で接する2島の1件だけ** | **定義が実装と一致している** |

**要点は3つ目。** 壁で断ち切った配置も、隙間を空けた2島も、6近傍でも26近傍でも同じく
「切れている」と判定される —— つまり**定義の変異を検出できない**。角1点だけで接する2島という
**定義を分離する題材**を1件用意して初めて、変異が検査に映る。

一般化: **「AとBのどちらの定義を採ったか」を検査で固定したいなら、AとBで答えが変わる入力を
題材にしなければならない。** ふつうの正常系・異常系をいくら増やしても、両方の定義で同じ答えに
なる入力ばかりなら、定義は検査に守られていない。変異検査は「何個落ちたか」ではなく
**「狙った1件だけが落ちたか」**で読む。

## 同型: 変異は「狙った落ち方」をする側へずらす(2026-09-05)

複数ボディを compound にまとめたときの面添字の対応(オフセット = 先行ボディの `face_count` の累積)を検査するとき、
わざとオフセットをずらす変異を `+1` で入れたところ、compound の最後の面をまたいで
`face index out of range: 13 (1..12)` になり、**「別の面を掴んだ」ではなく「添字が無い」で落ちた**。後者は範囲検査が
働いただけで、取り違えの検出力を1件も見ていない。**-1 側でずらすこと** —— 添字1は必ず存在するので範囲内に留まり、
かつ確実に別の面になる。「壊したら落ちる」を見せる変異検査は、**落ち方まで指定して**(例外の型・文面の一部)確かめないと、
意図と違う安全網に助けられて緑になる。
