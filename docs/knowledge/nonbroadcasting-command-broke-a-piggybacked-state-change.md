# 状態変更の配信を他コマンドに相乗りさせない

2026-08-23、duocadでQAが見つけた欠陥。**自分では気づけなかった種類の穴**なので残す。

verbの実行直前に選択集合を自動確定する処理を入れ、「確定そのものは配信しなくてよい ——
直後のverbが状態を配るのでそこに乗る」と設計した。docstringにもそう書いた。

**`preview` だけがその前提に乗っていなかった。** プレビューは「文書を変えないので
状態を配らない」と決めてあるコマンドで、応答は要求元へ結果を返すだけである。結果、
プレビューを投げるとサーバ側の選択だけが確定へ変わり、**どのクライアントにも届かない**。
プレビューして中断すると食い違いがそのまま残った。

一般化すると:

- **状態を変えたなら、その場で配信する。** 「直後に別の配信があるはずだ」という前提は、
  配信しない種類のコマンドが1つでも同じ入口を通った瞬間に破れる。相乗りは
  **入口を共有するコマンド全部の配信の有無に依存する**ので、コマンドが増えるたびに
  前提が壊れうる(そして壊れても例外は出ない)。
- 検査は**2接続**で書く。1接続だと「要求元には結果が返っている」ので緑に見えることがある。
- **自動で起こした変更に、人の操作IDを載せない。** duocadでは載せると
  アプリ層が「この画面の人が選択を触った」と数え、クリック即適用の引き金になっていた。
