**解いた系と目的値の総和範囲は必ず揃える。** duocad の void除去
([[duocad-void-removal-adopted]])で `Model.assemble` を active 要素だけにしたとき、
`Model.compliance` は全要素で足したままだった。結果:

- 変更前は K が空要素を emin で含んでいたので **`c == F・U` が厳密に成り立っていた**。
- 除去後は `c = F・U + (解いた系に無い emin 媒質のひずみエネルギー)` になった
  (実測の相対差 2.5e-07 / 1.3e-06。題材による)。

## なぜ検査で捕まらなかったか

**`check_simp.py` [2] は `c == F・U` を `1e-8` 相対で assert している。**
にもかかわらず全件緑だった —— [2] が使うのは `void_mask` を渡さない片持ち梁で、
そこでは `active_mask` が `None` なので**等式が今も厳密に成り立つ**。
**検査は存在したのに、壊れた経路にだけ届いていなかった。**

**「同じ不変条件を assert している検査があるか」ではなく「その検査は自分が変えた経路を
通るか」を見ること。** 新しい経路を足したら、既存の不変条件の検査も新しい経路ぶん足す。

## 直し方の選択

**目的値の側を active に揃えた**(`c` だけ active で足し、`ce` は感度に使うので全要素ぶん
返す)。逆に「ずれることを docstring に書いて残す」案は採らなかった:

- ずれは 2.5e-07 で許容の内側だが、**目的値は解いた系のものであるべき**で、放置すると
  以後の全ての利用者(随伴の検算・matrix-free・エネルギーを使う収束判定)がこの項を継ぐ。
- **費用が測れて小さいことを先に確かめた** —— `c` は `history` にしか入らず、OC更新は
  `ce` から作る `dc` を使う(空要素は `x_phys**(penal-1)` と `live` で消える)ので、
  **ρ は1ビットも動かないと予測でき、実際にビット一致した**(SHA-256・体積とも)。
  動いたのは `c_first`/`c_last` だけ。判定表の「コンプライアンス 相対1e-3以内」に対して
  1.2e-06 で、しかも**除去前との差は 2.4e-06 → 1.2e-06 へ縮んだ**(余分な項を落としたので当然)。

**「念のため直す」と「直す費用を測ってから直す」は別物である。** 基準値の取り直しを伴う
変更は、先に「何が動かないか」を予測して確かめてから入れると、判定が事後の追認にならない。
