# OC の退化は「密度フィルタが塊の縁で目減りさせること」で起きる

`probe_topopt/simp.py` の OC 二分探索(`while (l2 - l1) / (l1 + l2) > 1e-9`)は、体積目標が
「フィルタ後に到達できる最大」を超えると退化する。2026-09-04に3段階で判明した。

## 症状(区間の端)

片持ち梁の小格子で実効分率を振った実測:

| 実効分率 | 起きること |
|---|---|
| 1.501 / 1.0 | `ZeroDivisionError: float division by zero`(`l1 = l2 = 0` へ落ちる) |
| 0.999 | 正常(目標どおりの体積が出る) |
| 0.0 / -0.001 / -0.1 | `ValueError: K U = F が解けていない(残差 …)`。**「拘束不足を疑え」と言ってくる** |

「達成できない体積目標は黙って端に張り付く」という予想は外れていた —— 落ちはする。問題は**どちらの文面にも
体積の話が1文字も出ない**ことで、原因から遠い場所を名指ししてくる。上端ちょうど(容量と等しい指定)は数学的には
達成可能だが解けない。絶対量の口が入る前からある性質で `volfrac=1.0` でも同じ。

## 症状(区間の内側でも起きる)

案5(膨張0の塊 2,414要素・うち固定208要素)に 2,241要素ぶんの材料(容量の **92.8%**)を要求したところ
同じ `ZeroDivisionError` で落ちた。姿勢を変えても、材料を 50,000 mm³ に落としても(塊も 1,132 要素に縮み
比率はやはり 92%)同じ。目標は容量より小さいので体積の口のガード(`simp.VolumeTargetError`)は通り、
その先の OC 二分探索が退化する。**「区間の内側なら通る」「99.9% は通る」を一般化してはいけない。**

## 機序

OC は各設計反復で目標体積をちょうど当てる λ を二分探索する。密度フィルタ(`_physical`)は塊の縁で密度を
にじませ、にじんだぶんは塊の外で 0 に上書きされる。したがって**動かせる要素を全部 ρ=1 にしても、
フィルタ後の体積は要素数より小さい**。目標がその「フィルタ後の最大」を超えると、λ→0 まで下げても届かず
`l2` が 0 へ潰れて `(l2-l1)/(l1+l2)` が 0除算になる。**空要素(塊の外)が多い形ほど早く踏む。**

**実測の境目は形で決まる**(定数として持ち出さないこと):

- 塊の外に空要素がある配置(8x4x4 の周りに1層 + 上1層を void): **容量の 98% は落ち、95% は通る**
  (フィルタ後に到達できる最大は容量の 96.8%)。
- 空要素が無い配置: 容量の 99.9% でも通る(上の「区間の端」の観測はこちら)。
  2つの観測は矛盾していなかった —— 塊の縁がどれだけあるかの差である。

## 対処

`simp.optimize` の二分探索に、退化を拾って `VolumeTargetError(side="above_capacity")` を投げるガードを入れた。
文面に「目標 / この反復で到達できる最大 / 塊の容量 / その割合」が出る。**健全な経路の計算は1ビットも変えない**
(退化していないとき `l1+l2>0` はつねに真なので、条件を1つ足しても同じ枝を通る。rho 場の SHA-256 の回帰基準は
取り直していない)。実用上は容量未満を渡す。

## 塊を材料から自動導出する設計では構造的に踏む

塊が「その材料がちょうど入る大きさ」になるので、目標が必ず容量の端へ寄る。膨張(`dilate_mm`)を絞りすぎたとき
に出る —— **膨張が守っているのは答えの質ではなく「要求した材料が塊に入ること」だった。**
なお「膨張を0にすれば塊が切れて連結性ガードが落ちるだろう」という想定も外れた(最近傍アップサンプルは
6近傍連結性を壊さない。[[dilation-in-mm-quantizes-to-the-grid-it-is-applied-on]])。落ちたのはこの退化のほう。
