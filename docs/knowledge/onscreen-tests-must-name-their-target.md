実機検査で操作の対象(面・辺)を**「その視点でたまたま最初に射影できたもの」**として選ぶと、
検査は視点に暗黙で依存する。カメラを触った瞬間に別の対象が選ばれ、**そこから先の文書の形が
丸ごと変わる**ので、離れた場所の検査が原因不明で落ちる。

2026-08-28、duocadのビューポートを Z-up の front-top-right へ変えたとき、`acceptance.mjs` の
`human/extrude_face` は「平面のうち最初に射影できた面」を押していた。それまで当たっていた
`+Y` の壁が裏向きになり、代わりに `+X` の壁(40×10、以前は 60×10)が選ばれた。その操作自体は
成功して緑のままだったが、**3セクション先のAI側の `fillet` / `chamfer` が
`IsDone is false` / `no suitable edges` で落ちた** —— 押し出した壁の位置が変わって、後から
`join` で融合する円筒との交わり方が変わったためである。原因が「視点」にあることは、落ちた
検査の側からは全く見えない。

直し方は**対象を法線や寸法で名指しする**こと(例: `normal[1] < -0.9` の手前の壁)。
「指せること」自体を見たいなら、名指しした対象が射影できなければ失敗にする —— そうすれば
「別のものに逃げて緑のまま」という最悪の挙動が消える。

同じ回に、AI側の `chamfer` が**述語で集めた円い辺の先頭**を黙って使っていたのも同種で、
直前の `fillet` が作る長さ1.57mm(半径1の四半円)の角の円弧を掴んで OCCT に断られた。
`measure` で長さを確かめて一番長い辺を選ぶ形に直した(提案を確定前に検算する経路そのもの)。

[[viewport-resize-silently-changes-what-a-click-grabs]]。射影とクリックの時間差の側は
[[project-after-arming-not-before]]。
