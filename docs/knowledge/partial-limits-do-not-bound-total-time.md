# 部分の上限をいくつ置いても、合計時間は決まらない

2026-08-23、duocadのエージェントループで実測した教訓。

出力上限(`max_tokens`)・1リクエストの待ち(`request_timeout`)・往復数(`max_turns`)の
3つを締めても、**人が待つ時間は決まらなかった**。前2つは1リクエストしか縛らず、
`max_turns` は回数しか縛らない。**待ち時間はその掛け算**だからである。

実際、1リクエストを1024トークン(最悪16.5秒)に抑えた状態で、曖昧な依頼のときに
query ツールを堂々巡りして12往復を使い切り、**合計88秒**かかった。
待っている人から見れば、1回の暴走か12回の空回りかは区別がつかない。

**合計時間そのものに上限を置くしかない。** duocadでは `Limits.max_total_seconds` を足した。

**判定を往復の境目だけに置くと、実効上限は「合計 + 1リクエスト」になる**(実測: 上限30秒に
対して35.2秒)。進行中のリクエストへ渡すタイムアウトも残り時間で頭を押さえて、
ようやく30.0秒ちょうどに収まった。

併せて、**予算切れによる接続タイムアウトを「プロバイダの障害」として報告しない**こと。
原因はこちら側の予算であって相手ではないので、直す場所を見誤らせる。
