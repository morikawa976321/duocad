# 個別判定ではスイートは半減しない

2026-08-22、duocadのテストを半分以下にする試みで判明した。

**やったこと**: 全35ファイルをsonnetサブエージェント4本に分担させ、「検出力はあっても維持コストに
見合わなければ切る」という**旧回より厳しい基準**で削減候補を出させた。

**結果**: 4本の合計は **470件中45件（9.6%）**。内訳はコア幾何12・選択/状態12・MCP/agent5・UI配線16。
どのグループも「各テストは違う失敗モードを塞いでいるので切れない」と報告した。

**なぜそうなるか**: 一度整理されたスイートでは、**1本ずつ見ると全部が「要る」に見える**。
個別判定は「このテストに検出力があるか」を問うが、その答えはほぼ常にYesであり、
「この**種類**の検査をこのプロジェクトで続けるか」という問いに置き換えないと大きな数は動かない。
削減の単位はテストではなく**層**（UI配線層・AIエージェント層・MCP封筒層…）である。

**さらに厳しく問い直しても増えなかった**: 判断を排し「実装の**同じ分岐**しか通らないことを
`duocad/xxx.py:行番号` で証明せよ」と条件を付けて3本追加調査させたところ、出たのは
**429件中7件**だった。**規律の高いスイートには、証明できる冗長はほとんど残っていない。**
「まだ削れるはずだ」という直感は、たいてい間違っている。

**副次の発見**: 大きく効いたのは判定ではなく**依存の切断**だった。私物STEP依存の削除だけで
622→470件（-24%）、実行時間180.6秒→14.2秒、万年赤1本も消えた
（[[duocad-drops-private-step-test-dependency]]）。**「どれを消すか」より「何に依存しているか」
を先に見る方が、桁の違う効果が出る。**
