# plan-then-write は同じオブジェクトへの複数の計画を併合しないと最後だけが勝つ

## 事実(2026-08-30・duocad `move_sketch_entities` で実測)

「途中で落ちても半分だけ適用された状態を残さない」ために、**全対象の結果を先に作って
検査してから書き込む**形にした。ところが各対象の計画が

    現在の値を読む → 自分の分だけ変える → **全鍵ぶんの完全な辞書**を返す

だったので、**同じオブジェクトに複数の対象が掛かると、後の書き込みが前の書き込みを
丸ごと打ち消した**。線分の両端(`p0` と `p1`)を選んで動かすと片方しか動かない ——
`p1` の計画が持つ `x0, y0` は「動かす前の値」なので、先に書いた `p0` の移動が消える。

**例外もログも出ない。** ウィンドウ選択で図形をまるごと囲えば普通に踏む経路だった。

## 一般化

plan-then-write を採るなら、**計画の単位は「書き込みの単位(オブジェクト)」であって
「入力の単位(対象)」ではない**。同じオブジェクトに掛かる入力は、書く前に1つの計画へ
積み上げること(前の計画を土台にして次を重ねる)。

## 検査の書き方

「2つ動かして両方動く」テストが要る。**1つだけ動かすテストは何本あっても通る**し、
座標を比べるテストでも、片方が偶然同じ値になる配置を選ぶと素通りする(実際、
「辺と点を同時に選ぶ」ケースは両方の計画が同じ値を書くので、この不具合を検出できなかった)。
