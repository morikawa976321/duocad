Puppeteerベースの実機検査で「WebGL描画がAとBで有意に違うか」を機械的に確かめたいとき、
`pixelmatch`/`pngjs`等の画像diffライブラリを新規に足さなくても、`page.screenshot({clip,
encoding:'binary'})` が返すPNGバイト列を**単純に1バイトずつ比較した不一致数**で近似できる。

**やり方**: ①同一カメラ・同一設定で2回連続スクリーンショットを撮り「制御群」の差分バイト数を
測る(Chrome headlessの描画+PNGエンコードは同一入力に対して決定論的なので、理論値は0)。
②比較したい条件(例: FOV違い)のスクリーンショットの差分バイト数を測る。③制御群の数倍
(実測ではdocadで0バイト対2995バイトと歴然差が出た)を閾値にする。

**利点**: 依存を増やさない・実装が数行で済む・「変わったか」の有無を検出するだけなら画素単位の
精密diffは不要。**欠点**: 「どれだけ・どこが」変わったかは分からない(全体か一部かの区別が
つかない)ので、「変化量の大小を比較する」検査には向かない(その場合は素直に画素decodeが要る)。
duocadの `web/scripts/acceptance.mjs`(ビューキューブがFOVに追従する検査)で採用。
