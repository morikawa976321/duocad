# 点-三角形の最短距離は「領域分けの優先順位」ではなく「候補の最小値」で書く

Ericson "Real-Time Collision Detection" の最近傍点は、頂点3・辺3・面内の**7つの領域**を
順に判定して最初に当たったものを返す形で書かれている。この分岐は**三角形が退化していない
ことを前提**にしていて、2頂点が重なった三角形では複数の領域判定が同時に真になる。
numpy でベクトル化するときは「分岐」ではなく `np.where` の**上書き**になるので、
後から上書きしたほうが勝ち、誤った距離が返る。

反例(実測): `a = b = (0,0,0)`, `c = (5,4,4)`, `p = (10,4,-8)`。

- 領域分けの上書き実装: **13.416407865**(= `|p - a|`。辺 `ab` が長さ0で射影パラメータが
  0/0 になり、`a` を返す枝が辺 `ac` の正しい射影を上書きした)
- 正解(線分 `a`-`c` への距離): **12.638010059**

対処は**候補の最小値**。最近傍点は必ず「3頂点 / 3辺への射影(端で打ち切る) / 面への射影
(重心座標が三角形の内側のときだけ)」のどれかなので、距離の2乗を7つとも出して最小を取れば
優先順位が要らず、退化しても正しい。ベクトル化した実装では中間配列が `(点,三角形,3)` から
`(点,三角形)` に減るので**速度も落ちない**。

**退化三角形は理論上の話ではない。** OCCTの `BRepMesh_IncrementalMesh` は円錐の頂点まわりで
実際に出す(`Cone(10,0,20)` の三角形分割841枚のうち1枚が退化。ただし
`shelf_attachment_7.step`(231面・62,318三角形)では0枚)。**入力で弾く方針は取れない。**
