# 3D座標の射影は「UIを触った後」に取る

2026-08-22、duocadのsmoke検査で実測。**射影 → ボタンを押す → クリック** の順で書いた
検査が、意図した面ではなく**別の部品の面**を押していた。

原因は2つあり、どちらも「射影した時刻とクリックした時刻の間に画面が動く」ことである:

1. **UIの文言が変わるとレイアウトが動く** —— コマンドを起動すると「何を待っているか」の
   1行が入れ替わる。長さが変わって行が折り返すと**3Dビューの高さが変わり、投影行列ごと
   ずれる**(duocadがサイドパネルの高さを固定してあるのと同じ事情)。
2. **カメラのダンピングが効いている間は数十msかけて動き続ける**(OrbitControlsの
   `enableDamping`)。視点を変える操作の直後に射影すると、クリックの頃には数画素ずれている。

**対処**:

- **状態を変える操作を全部済ませてから射影する**(順序を逆にしない)。
- 視点を動かした直後は、**2回続けて同じ画素に射影できるまで待つ**(止まった判定)。

「クリックの直前に射影し直す」という規律だけでは足りない —— *直前* の定義に、
これから押すボタンが引き起こすレイアウト変化が入っていないため。

## 視点を変えると、隠れていた同じ罠が再発する(2026-08-28追加)

この時間差は、**指している面がたまたま境界から遠ければ隠れる** —— 数画素ずれても同じ面が
取れるからである。2026-08-28にduocadのビューポートを Z-up の front-top-right へ変えて
**指せる面が別の面に変わった途端**、それまで何年も緑だった `smoke.mjs` の「全解除のあと
面を選び直す」手が**6回に2回**落ちるようになった(射影の前に往復を1つ挟むだけで4回連続で
通ったので、原因が時間差であることは確認済み)。**「今まで緑だった」はこの罠に対して何の
保証にもならない。** 視点・レイアウトを触ったら、射影してクリックする手は全部「止まった
判定」を通す。
