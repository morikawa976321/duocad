# 散文の規則は、検査を厚くせず「人が守る領域」に切り分ける

2026-08-22のdrain(duocad T4、AIの行動規範プロンプトの改訂)での決着。

**状況**: duocadのAIの行動規範は `duocad/catalog.py` の `agent_instructions()` が単一の正で、
MCPの `initialize.instructions` とアプリ内AIパネルのシステムプロンプトが同じ文を読む
(同一性はテストが固定している)。この散文が骨抜きにされていないことを文字列検査で守ろうとした。

**起きたこと**: QAが2ラウンド続けて素通りの経路を見つけた。1回目は「重要句の有無しか見ていない」、
2回目は「区間を切り出したが終端句より後ろを見ていない」。区画を4つに割り、
「止まれと読める語は第2段の中にしか置けない」という不変条件へ作り直して13通りの変異を落としたが、
**列挙していない言い回しの矛盾は常に書き足せる**ことが実測で残った
(素通り例: 「ユーザーへ問い合わせてから進むこと。」「実行の前にユーザーに聞くこと。」)。

**判断**: 語を追い足すのをやめた。**原本のdocstringに「この文を書き換える人への注意書き」を置き、
検査ではなく人が守る領域として切り分けた。**

**なぜ危険側に倒れないか、を先に確かめること**: この件で怖いのは、
**規範を骨抜きにする変更をしてもコアが何も止めないので実行時に異常が出ない**点だった。
散文を検査から外すときは、外した先に別の防具(コア側の門)があるかを必ず確認する。

**一般則**: 散文の意味は文字列検査で固定できない。検査は「重要句が消えた」までしか見られず、
「意味を打ち消す1文が足された」は原理的に追い切れない。パターンを増やす方向は
[[mutation-tests-inherit-the-checkers-blind-spot]] の盲点を厚くするだけで、投資対効果が反転する。
