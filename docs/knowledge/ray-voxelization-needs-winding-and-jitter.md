# レイ走査のボクセル化は巻き数とレイのずらしの両方が要る

三角形メッシュへ +z のレイを飛ばして内外を決めるとき、縮退(レイが三角形の辺や頂点を
**厳密に**通る)は例外的な事故ではなく**系統的に起きる**。格子を bbox から起こすと、
軸に整列した形状では面や辺が列の中心と厳密に一致するため。守りは2つ要る:

1. **偶奇ではなく巻き数で数える。** 共有辺をレイが通ると2枚の三角形が同じ z に交点を返す。
   偶奇だとその上の全域で内外が反転し、**列がまるごと壊れる**。巻き数なら
   「入る(+1)/出る(−1)」が相殺する。符号は三角形の xy 投影の符号付き面積(=外向き法線の
   z成分)の符号から取る。実測: 40×40×10 の箱で上面の対角線が列の中心を通り、
   偶奇 15,200 mm³ / 巻き数 16,000 mm³(正解16,000)。
2. **レイの (x,y) をセル中心から要素サイズの 1e-4 ほど決定的にずらす**(乱数ではない)。
   巻き数でも守れないのは**頂点に三角形が集まる点**で、円錐の頂点をレイが貫くと
   「出る」ばかりが数十回数えられて巻き数が0に戻らない。実測: `Cone(10,0,20)+Box(30,30,4)` は
   ずらし無しだと n=6〜40 の**全解像度**で破綻した(ずらし有りでは全解像度で正常)。

**「巻き数が0に戻らない列」の数を必ず数え、0でなければ落とす。** 閉じた表面ならこれは
0でなければならない量で、非水密な入力・重なった三角形・貫いた頂点をまとめて検出できる
最後の砦になる。黙って返すと「レイが1回しか交差しない列は全部内部」というもっともらしい
ゴミが出る。
