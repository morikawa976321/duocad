# 4xxで断るときも、リクエスト本文は読み切ってから返す

duocadの `/mcp`(MCPのHTTPトランスポート)で実測。`Origin` ヘッダを見て403を返す検査を、
**本文を読まずに** `send_error` して接続を閉じる形で書いたところ、まだ本文を書いている
クライアント側で `ConnectionAbortedError` になった(Windows。受信バッファに未読が残ったまま
閉じるとRSTが飛ぶ)。

**症状がややこしいのは、拒否そのものは効いているのに、クライアントからは「通信が壊れた」に
見える**こと。防御が働いた結果なのか、サーバが落ちたのかを呼び出し側が区別できない。

対処は「検査より先に本文を読み切る」。上限で頭打ちにしてあれば読み切って安全である。
上限超過だけは読み捨てずに接続を閉じる(読み捨てること自体が的になるため)。

## 併せて得た検査の教訓

このバグは**1回目のpytestで緑・2回目で赤**という形で出た。競合なので当然だが、
「散発的に赤い＝テストの作りが悪い」と早合点していたら実バグを見逃していた。
**散発的な赤はまず実装の競合を疑う**([[perf-test-left-red-with-a-caution-line]] のように
マシン負荷で振れるものとは別物)。
