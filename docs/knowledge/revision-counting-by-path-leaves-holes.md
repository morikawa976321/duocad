# 版は「経路」ではなく「状態」から導く

2026-08-11、duocad M3.5（部品ごとの差分送信）の契約を書いたとき、**同じ形の穴が経路を変えて
3ラウンド続けてQAに指摘された**。設計を直すまで、こちらが「直した」と思うたびに次の経路が出た。

出た順:

1. **非表示が届かない** — 「版は形状が変わったときだけ増える」と決めていたため、
   `set_visible(False)` したBodyは差分で `unchanged` に入り、消したことがクライアントへ
   一度も届かない
2. **再表示が届かない** — 1を「可視性でも版を上げる」と直したが、テストが非表示方向しか
   縛っておらず、「隠したときだけ版を上げる」実装でも全部緑になる
3. **undo/redo が届かない** — 2を直しても、版を verb の適用時だけ上げる実装だと
   `_undo_set_visible` の経路で版が動かず、undoしても画面から消えたまま

3つとも**別のバグではなく同じ設計の帰結**である。「押し出したら上げる」「隠したら上げる」と
**イベントを数え上げる**形にしている限り、undo・redo・再生・将来増えるverbのぶんを必ず
取りこぼす。穴を1つ塞ぐたびに、まだ数え上げていない経路が残る。

**対処**: 版を状態から導く。duocadでは `(形状オブジェクトの同一性, visible)` の組が変わったら
版が変わる、という形にした。経路が増えても自動的に追随し、テストで経路を1つずつ列挙する
必要も無くなる。

**一般化**: 「変更を通知する」種類の仕組み（差分送信・キャッシュ無効化・再描画のトリガ）は、
**変更イベントを列挙する設計と、現在の状態から導出する設計の2択**であり、前者を選ぶと
列挙漏れが恒常的な不具合源になる。列挙が正しいことを保証する手段が無いため、
テストは「今思いつく経路」しか守れない。
