# 材料量を動かす外側ループは、塊も毎回作り直す

`probe_topopt` の塊の導出(案5 `derive_from_coarse_run`)は材料の居場所から塊を作るため、
材料量が変われば塊も変わる([[topopt-needs-no-design-space-input]] の下敷き)。安全率を
入力に材料量を二分探索する外側ループ(`safety_loop.py`)を組むとき、塊の扱いに3案あった:

- (a) 二分探索の各段で塊を導出し直す —— 塊と材料量が常に噛み合うが、塊が段ごとに
  変わるので「安全率の変化が材料のせいか塊のせいか」を厳密には切り分けられない
- (b) 一度だけ導出して固定 —— 安いが、塊と材料量が噛み合わない(探索の反対側の端で
  塊が締め付ける/緩すぎる)
- (c) 探索範囲の上端で一度導出して固定 —— (b)よりはまし(塊が最大なので少ない材料も
  含む見込みがある)が、包含は保証されない

**(a)を選んだ**。理由: check-scale解像度(数百〜千要素)での実測コストが
1点あたり導出0.4〜0.5秒+最適化1.8〜2.8秒と無視できる大きさで、切り分けの明快さより
噛み合わせの正しさを優先できた。(a)と(c)を同じ題材(bracket)で比較実測すると、
材料量が(c)の固定点に近いほど安全率が一致し(差0.01〜0.13%)、遠いほどずれる
(最大4.23%)—— (c)の塊は固定点向けに膨らませてあるので、それより少ない材料では
塊が「緩すぎる」側に振れるため。

## 一般化できる部分

**「材料量(や他の設計変数)に追従して形状/離散化そのものが変わる系で、その変数を
外側ループが振るとき」は、内側の離散化・領域決定を候補値ごとに作り直すコストが
実際にどれだけ無視できるかを測ってから決めること。** 「切り分けの明快さ」と
「値の噛み合い」はトレードオフで、コストが安ければ後者を優先してよい。逆にコストが
高い(本番解像度など)場合は別の判断になりうる —— 本タスクの検証は check-scale
解像度でのみ行っており、**本番解像度(elements_long_axis=40)でのコスト比較はしていない**。

詳細・実測数値は `probe_topopt/README.md`「塊が材料量に追従する問題」節、実装は
`probe_topopt/safety_loop.py`。
