# 辺の screen pick は全走査で足りる(実測)

duocad の当たり判定を world threshold から画面上のCSS px距離へ移すとき、
「ソリッドの辺は本数が多いので Raycaster を粗い絞り込みに残すか」が未決だった。実測して不要と判断:

- 対象: 27部品の mATX PC ケースの**面数最大のボディ**(233面・**辺645本 / 折れ線の点1,768**)、
  1280×860。
- 測ったのは `projectEdge`(内部で `edgeAt` を1〜7回呼ぶので `edgeAt` 1回の**上界**)。
  見えている辺1本を300回で **p50 0.2ms / p95 0.7ms / 最大 1.4ms**。645本を1周して
  **p50 0.2ms / p95 0.3ms / 最大 1.6ms**。
- 判定基準は「1フレーム16msの p95 超過なら二段階化」。20倍以上の余裕がある。

**効いているのは「1回に走査するのは1ボディぶんだけ」という設計**(辺は選択中のボディのものしか
画面に出さない)。部品数が増えても走査量は増えない —— 増えるのは1部品の辺の本数そのもの。
