# サーバへは参照、幽霊へは解決した数値

画面で既存の図形(辺・頂点・スケッチの点)を指してそれを引数にするUIを作るとき、**参照のまま送るか座標へ潰して送るか**という分岐が出る。duocadの `move_body(mode="rotate")` の回転軸で採ったのは**非対称**の形(2026-09-06):

- **サーバへは参照のまま送る**(`axis_edge = {body, index}`)。辺が乗る直線を厳密に出せるのはB-repを持つコアだけで、まっすぐでない辺の拒否のような既存の規則もコア側にそのまま効く。座標へ潰すと同じ解決規則がブラウザにもう1つ増える。
- **確定前のプレビュー(幽霊)には数値へ解決してから渡す**。プレビューの層は「解決済みの数値でしか描かない」を不変条件にしてある。そこへ参照を渡すと「省略時の既定」もその層で解決したくなり、既定(重心・代表点の平均)はコアにしか無い規則なので、写した瞬間に**幽霊と確定結果が別の場所に出る**壊れ方の芽になる。

**解決に使ってよいのは「コアが既に配った数値」だけ**(テセレーションの折れ線・配信済みの頂点座標・解決済みの `params`)。近似(メッシュからの体積重心など)は使わない —— 使わずに**描かない**ほうが正しい。

この形は「向きの符号が両者で一致しているか」を測る責任を生む。`kernel.edge_axis` の向きと配られた折れ線の始点→終点が一致することを、立方体・穴あき・フィレット・合体・L字の直線辺83本で実測した(どちらも同じ `BRepAdaptor_Curve` の媒介変数の順に並ぶため)。**ここが逆だと幽霊だけが逆回りに見える。**
