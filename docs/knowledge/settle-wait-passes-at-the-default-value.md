実機検査に「画面が落ち着くまで待つ」処理を書き、条件を
**「ビューポートが採った目標偏差 == サーバから届いたメッシュの偏差」**にした。

これは**ズーム前でも即座に真**になる。まだ一度も解像度を採っていない画面の既定値(0.2mm)と、
サーバが最初に配ったメッシュの偏差が**同じ既定値**だからである。結果、ホイールを回した直後に
待機が0msで抜け、まだ減衰中のカメラの値を読み、「寄ったのに何も変わらない」で落ちた
(このときは幸い落ちたが、**閾値の向きが逆なら緑で通っていた**)。

**待機条件には「まだ何も起きていない状態」を必ず弾く項を入れる。** ここでは
`worldPerPixel > 0`(＝解像度を一度は採った)を足し、さらに**その値が複数回続けて同じ**である
ことを見る形にした(減衰つきのカメラ操作はイベントが止まった後も数十フレーム動く)。

一般化: **「AとBが一致したら準備完了」は、AとBの初期値が同じなら準備完了の判定にならない。**
一致の検査には「初期値ではないこと」を別の項で足す。
