# SIMPの所要は線形解像度の4乗で伸びる(Jacobi前処理のとき)

**この4/3乗は前処理の性質であって、SIMPの性質ではない(2026-09-04)。** 同じ実装に幾何
マルチグリッド前処理を入れて4題材で測り直したところ、**秒/設計反復の指数は 1.26〜1.93乗 →
0.97〜1.53乗**、CG反復数は 7〜13倍減った(295.8→28.6 など)。下の表と式は
**`solver="cg"`(Jacobi前処理)のときの値**として読むこと。**新しい既定は `solver="mg"`。**
ただし**秒が倍以上速くなったのは大きい題材だけ**で、小さい題材(自由度1.4万の薄板)は
むしろ 1.37倍遅くなった —— V-cycle 1回が行列ベクトル積6〜8回ぶんあり、密度が変わるたびに
粗格子作用素を組み直すため。**反復数の比はそのまま費用の比にならない。**
数字の正は duocad `probe_topopt/README.md`「幾何マルチグリッド前処理」節。
**4/3 の出どころ(Jacobi前処理で CG反復数 ∝ N^(1/3))と、指数が題材の形ごとに散る実測(4題材で 1.05〜2.03乗)は
[[four-thirds-cost-law-is-the-jacobi-preconditioner]]。マルチグリッドの当たり取りを一様密度でやってはいけない件は
[[multigrid-tuning-on-uniform-density-is-meaningless]]。**

duocadの `probe_topopt`（3D SIMP・8節点hex・Jacobi前処理CG＋前反復の解でウォームスタート・rtol=1e-9）を格子サイズを変えて実測した（1反復あたり、3反復目以降の平均。duocad .venv / numpy 2.4.6 / scipy 1.17.1）:

| 格子 | 要素 | 自由度 | 秒/反復 | CG反復/回 |
|---|---|---|---|---|
| 40×16×16 | 10,240 | 35,547 | 1.48 | 435 |
| 50×20×20 | 20,000 | 67,473 | 3.49 | 553 |
| 60×24×24 | 34,560 | 114,375 | 6.64 | 666 |
| 80×32×32 | 81,920 | 264,627 | 24.03 | 902 |

線形解像度の倍率を s とすると:

- **CG反復数は s に正比例**（435→902 が s=2 でちょうど2.07倍）。Jacobi前処理では条件数が h^-2 で悪化するという教科書どおりの挙動。
- **所要時間は s^4**（s=2 で実測16.2倍・理論16倍）。1反復あたりの費用が「要素数(s^3) × CG反復数(s)」だから。**要素数比(s^3)で見積もると外す。**
- メモリは自由度に比例。264k DOF でピーク Working Set **1,569MB**（組み立て済みCSRを持つ方式）。線形解像度をさらに2倍（約2.06M DOF）にすると **12GB級**になり、このPC（RAM 31.7GB・空き9GB程度）では組み立て方式のまま素直には回らない。

**格子の縦横比が上の表と違うときは s^4 を使わない(2026-09-03追加)。** 上の s は「同じ形の格子を
一律に細かくする」倍率なので、実物のように縦横比が違う格子へ当てはめると外す(実際に外した:
41×102×68 を長辺比の4乗で見て1.1時間と見積もったが、下式では1.8時間)。一般形は
**秒/反復 ≈ 24.03 × (要素数 / 81,920)^(4/3)**(要素数 N に対し CG反復数が N^(1/3) に比例するため)。
上の実測4点に対し 1.50/3.67/7.60/24.03 秒(実測 1.48/3.49/6.64/24.03)で±15%以内。
**この式は要素サイズを細かくしても設計空間を広げても同じように効く** —— 費用を決めるのは
要素数であって、それが解像度から来たか領域の大きさから来たかは問わない
([[enlarging-the-box-does-not-get-cheaper-in-simp]])。

60反復の総時間に直すと 40×16×16 で約1.5分、80×32×32 で**約24分**、160×64×64 で**約6.4時間**（かつメモリ壁）。

**効く手を効く順に**: ①**マルチグリッド前処理** — CG反復数を s 比例から実質定数へ落とすので、この表の支配項が消える。単独で最大の効き。**2026-09-04に実装済み**(pyamgは要らなかった。均一ボクセル格子なので粗格子が自明で、numpy/scipyだけで幾何マルチグリッドが書ける)。②**行列を組み立てない matrix-free CG** — メモリ壁を外す。③粗い格子で回してから射影して仕上げる多重解像度（新規依存なし）。④cupyでGPU（Windows対応・RTX 5060 Tiで動く）。
