# 規約の定数は1箇所に畳み、口どうしの一致を検査する

同じ規約(例: 「要素の値はセルの**中心**のもの」= 添字に +0.5)を、複数の関数がそれぞれ
リテラルで書いていると、**1箇所だけ壊しても受入検査が緑のまま通る**。使われていない口の
規約がずれたまま残り、後からその口を使ったコード(別の段・別のタスク)が半セルずれる。

実例(duocad `probe_topopt/voxelize.py` stage1、2026-08-31): `Grid.centers_1d` /
`Grid.centers_of` / 占有判定のレイ生成が、それぞれ `+ 0.5` を書いていた。変異検査で
`centers_1d` の +0.5 だけを +1.0 に壊したところ、**8項目の受入検査が全部緑のまま通った**
(検査が使っていたのは別の口だった)。

対処は2つセットで:

1. 規約を**1つの名前付き定数**にして、すべての口がそれを参照する
   (`CELL_CENTER_OFFSET = 0.5`)。占有判定のレイも自前で座標を作らず `Grid` 経由にする。
2. **口どうしが同じ値を返すことを受入検査で照合する**(`centers_1d` と `centers_of` と
   `center_of` の3つを突き合わせる)。定数を1つにしても、参照箇所を1つ壊す変異は残るため。

一般に、**受入検査が全部緑で1発で通ったときは変異を当ててみる**。この欠陥は「1発で緑」を
疑って変異検査を回したから見つかった。
