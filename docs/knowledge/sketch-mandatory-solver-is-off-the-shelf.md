# スケッチは必須。ただし拘束ソルバは書かなくてよい

## 判断（本人）

> スケッチは必須。スケッチは厳密で複雑なモデリングをするための必須機能。

AI側が出した「最小セットではスケッチを持たずフィーチャ級verbで代替する」案
（[[cad-verb-granularity-rule]]）は**退けられた**。理由は任意の輪郭が要ること。
ただし**フィーチャ級verbは併存させる価値がある** — 穴のような決まった形はスケッチ経由より
手数が半分で済むため。最終形は「スケッチが要るものはスケッチで、要らないものはフィーチャ級verbで」。

## 事実（2026-08-07実測）

スケッチ部分系の最大の未知だった**拘束ソルバは既製品で埋まる**:

```
python-solvespace 3.0.8 (SolveSpaceの slvs ソルバのPythonバインディング)
雑に置いた4点の矩形 (0,0)(31.7,2.4)(29.1,18.6)(-1.2,21.3) に
horizontal×2 / vertical×2 / distance×2 を与えて solve
  → (0,0)(60,0)(60,40)(0,40) に厳密収束。約20行
寸法だけ 25×80 に変えて再解決 → (25,80)。パラメトリック駆動も成立
```

- **ライセンスは GPLv3+**。個人利用なら問題ないが配布・販売時に効く。
  代替は FreeCAD の `planegcs`（同じくGPL系）。回避したいなら自作が必要。
- **`dof()` の値が手計算と合わない**（完全定義なら0のはずが6を返した）。
  Fusionの「完全定義（青→黒）」に相当する表示を作るならDOF判定の意味は要調査。
- **残るコストはソルバ以外**: 閉領域の検出／2Dエディタのコマンド層／
  描画中の自動拘束推定／入れ子の選択とundo。**未知の塊ではなくなったが依然として最大の部分系。**

## 実装状況（2026-08-30実測）: ソルバ統合はまだ手つかず

現行の `duocad/duocad/sketch.py` を含むコードを "solvespace" "constraint" "solver" で検索しても拘束ソルバの実装は一切無い。スケッチのEntityは線=`{x0,y0,x1,y1}`、円=`{cx,cy,radius}` のように**座標を直接パラメータとして持つだけ**で、ソルバによる導出値ではない。つまり上記の決定は「技術的に実現可能と確認した」という検証結果であって「実装に組み込んだ」ではない。統合自体は手つかずのタスクとして残っている。

副次的に、直接パラメータのままなので**座標を直接ドラッグ/verbで書き換えても拘束ソルバと衝突する心配は無い**（[[duocad-move-verb-split-sketch-and-body]] の実装はこの前提の上に成り立つ）。

## 波及

- **スケッチは面に貼り付く。「この面にスケッチする」はモデル変更時に最初に壊れる種類の参照**であり、
  スケッチ必須化により [[occt-provenance-enables-persistent-naming]] の
  「day 1で由来スロットを用意する」の価値が上がった。
- **スケッチ編集セッションは同じアーキテクチャの入れ子インスタンス**
  （独自の文書・選択・verb・undoスコープ）。特別扱いではなく再帰なので層の設計を再利用できる。
