# 実機検査: 片方の点だけ動かした後のクリック座標は、動かす前の値と混ぜない

`web/scripts/smoke-move.mjs` の「線分そのもの(辺)をクリックで選べない」flakeを調べたら、
テスト自身の座標計算バグだった(製品コードの回帰ではない)。

## 機序

`move_sketch_entities` で線分の片方の端点(x1,y1)だけをdy=10動かすと、線分は
`(60,0)-(80,0)` から `(60,0)-(80,10)` へ**傾く**。この後「図形全体(辺)をクリックで
選び直す」ためのクリック座標を

```js
const mid = await planeAt((LINE.x0 + LINE.x1) / 2, moved.params.y0)
```

のように、**動かす前の定数(`LINE.x0/x1`)と動かした後のy0を混ぜて**作っていた。
`moved.params.y0` は不変(0のまま)なので、これは (70, 0) を指す。だが傾いた線分の
実際の中点は ((60+80)/2, (0+10)/2) = (70, 5) であり、垂直距離で約4.5mmずれる。
これはクリックの当たり半径(`EDGE_PICK_PIXELS`)の外になり、
`waitFor(..., '線分そのもの(辺)をクリックで選べない')` がタイムアウトする。

同じ関数`smoke-move.mjs`内に、この形の中点計算が計4箇所あり、全部同じ理由で踏んでいた
(検証6・6c「図形まるごと回す」・6d「回転をUIから起動する」・6b「スケッチ切り替え」)。

## 教訓

エンティティを部分的に変形した**後**にそのエンティティへ向けてクリックを打つときは、
中点・端点などの狙い座標を**必ずその時点の実パラメータ(`moved.params.x0/y0/x1/y1`等)
から計算し直す**。呼び出し元で最初に定義した定数(`LINE.x0` 等)と、後で読んだ実測値の
一部だけを混ぜて式を作ると、コンパイルも型検査もpytestも通るのに実機だけがタイムアウトで
落ちる ——「動かしていないはずの座標」を使ったつもりが、実は動いた形状の一部と噛み合って
いないことに気づきにくい。

画面外に出る、別種のクリック座標の落とし穴)。
