# 「空き地」のつもりの座標がスナップに吸われる(距離型と順序型)

[[duocad-sketch-hover-snaps-to-existing-geometry]] の導入後(duocad `63a30a7`)、新しい点を置くクリックは既存図形の輪郭に近いとその輪郭上へ吸い付く。**製品バグではなく仕様どおり**の動作だが、機能導入前に「近いが重ならない」間隔で図形を置いていた実機smokeのfixtureは、そのfixtureだけがサイレントに壊れる(検査の失敗メッセージは「見た目には無関係な後続の症状」として出る)。

## (a) 距離型

当たり判定は画面ピクセルベース(`EDGE_PICK_PIXELS`=6px)を世界座標に換算した距離。`smoke-regions.mjs` 修正時の典型的なフレーミングで**輪郭から4mmはスナップし、5mmはスナップしない**。閾値はカメラ距離に依存するので絶対値としては使い回せないが、「数mmは危険域」という桁感は再利用できる。fixtureは**既存図形の輪郭から余裕を持って(目安10mm以上、または `window.__duocad.hoveredRef()` で実測して)離す**。ぴったり数mmで設計すると、当たり判定を伴う機能が入るたびに同じ形で壊れる。

## (b) 順序型

`smoke-hover.mjs` に1mmグリッドスナップの検査を足したとき、「何にも当たっていない場所」として、既存の検査(点スナップ・円スナップ)が線分の**終点**として使っていた座標 `(45,15)`/`(45,25)` に近い `(45.4, 15.35)` を選んだ。単独では離れているつもりだったが、**前段の検査がその座標へ実際に線分の端点を置いていた**ため、後段の時点ではもう空き地ではなかった。クリックが端点(点マーカー)へスナップし、`Math.round` を経由しない射影誤差(例 `15.000000000000002`)が返って、「丸めが効いていない」ように見える誤検出になった。**距離を離しても直らない**。

新しい検査を足すときの「空き地」は、スクリプト冒頭でMCPが作った初期図形からだけでなく、**同じスクリプトの前段が実行時に追加する図形・端点からも**離す。疑わしければ新しい実体が増える前(早い段)に挿入するか、既存のどの端点とも共有しない専用の空き地(2つの図形のbounding boxの隙間)を割り当てる。

## 切り分け手順(再利用可能)

1. `page.evaluate` で実際に送られたentity paramsをダンプし、意図した座標とズレていないか確認する。
2. ズレていたら、クリック前のマウス移動だけで `window.__duocad.hoveredRef()` を呼び、同じ当たり判定が実際のホバー機構からも得られるか確認する(人間が同じ画素にカーソルを置いても同じことが起きるか)。
3. 両方が一致すれば「検査の側が前提にしていた当たり判定が変わった」と判断してよい。丸め後の値が整数から浮動小数点誤差ぶんだけズレているのは、`Math.round` 経路ではなく別の当たり判定(スナップ先の線への射影)を通った証拠。
