# エラーコードを分ける基準は「名前が嘘をつくか」

2026-08-20、duocadの選択エラーで本人が決定。

**状況**: フィレット(辺を食う)を呼んだのに確定選択が面3枚、という種別の食い違いを、
既存の `selection_empty` で返すか専用コードを足すか。同日の実装は「どちらも次の一手が
『辺を選び直す』で同じ。区別の材料は `selection.count` で足りる」として**分けなかった**
(文面だけ強化)。

**本人の判断**: 分ける(`selection_kind_mismatch` を7語彙目として新設)。
**理由は語彙の数ではなく、名前が嘘をつくこと** —— 面3枚が入っている選択に対して
`selection_empty`(選択が空)と名乗ると、後で読む人を必ず一度混乱させる。
副次的な利点として、アプリ層が種別違いにだけ反応する余地(「この面の辺を選ぶ」等)を
コードで分岐できる。

**一般化**: 「次の一手が同じだから同じコードでよい」は**消費者がLLMだけなら**成り立つが、
コードは人も画面も読む。**名前が状態を正しく述べているか**を先に見る。

**実装の型**: 新しい例外を既存例外の**派生**にすると、既存の `pytest.raises(既存型)` を
壊さずにコードだけ増やせる。ただし判定順を入れ替えると派生が基底に吸われて新コードが
死ぬので、**両方向をテストの対で固定する**(片方だけだと順序の退行が緑で通る)。
