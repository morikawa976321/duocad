# STEP往復の体積は実対象ファイルではbit-exactに一致しない

`duocad/docs/IMPLEMENTATION_PLAN.md` §7は「STEP往復は厳密（26面・体積23340.849375、
差0.00e+00を確認済み）」と書いているが、これは**別の（より単純な）形状での実測**だった。

minicad M0のテスト設計中に、v1の受入対象そのものである `shelf_attachment_GD.step`
（56面 = 平面34 + 全周円筒22、体積91018.2223598035mm³）で同じ検証を行ったところ、
**`export_step` → 再読込の体積差は約7.3e-11（相対 約8e-16、IEEE double の1ULP級）で、
`==` によるbit-exact比較は成立しなかった**。

## 再現性の確認

同じ入力に対して2回exportし直しても同じ値・同じ差になった（`91018.2223598035` →
`91018.22235980343` を安定して再現）。ランダムなノイズではなく、**形状を再度読み込むことで
面のパラメトリック表現や走査順が変わり、`GProp_GProps` の数値積分（Gauss求積）の
浮動小数点演算順序が変わることに由来する**と判断した（`BRepGProp.VolumeProperties_s` に
明示的な収束epsilonを渡すとさらに値そのものが動くことも確認しており、既定の積分が
厳密解ではなく近似であることの傍証）。

面数（`face_count`）は往復後も厳密一致（`==`、56→56）した。ずれるのは体積のような
数値積分結果のみで、トポロジ（面の数）は保たれる。

## How to apply

STEP往復の体積検証を書くときは、**`==` ではなく `math.isclose(rel_tol=1e-6)` 程度の
緩やかな相対誤差**で比較すること。実測誤差（8e-16）の10億倍のマージンがあるので、
面の欠落・重複など実際のジオメトリ破損（体積差は通常オーダーが変わる）は確実に検出できる。
**「実装計画書に書かれた数値」を無条件に信じず、受入対象の実物ファイルで測り直す**判断が
効いた実例（`minicad` M0テストタスクの完了条件「数値の期待値を推測で書かない」を実践した結果）。
