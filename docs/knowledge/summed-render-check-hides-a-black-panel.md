# 「合計 > 0」は、1つだけ空の部分を隠す

duocadの比較スクリーンショット撮影台は、設定違いのN面を1枚のcanvasに並べて描く。「真っ黒の合格」を防ぐためにGPUへ行った三角形数を見ていたが、**全面を合算して `> 0` を見ていた** —— 1面のデータ読み込みが失敗して真っ黒になっても、他の面が描けていれば合格する。QAレビュー(cursor composer-2.5)が指摘して直した。面ごとに見て、空の面の添字を名指しで落とす。

**集計値は、集計した単位でしか異常を検出しない。** 検査が守りたい主張が「**どれも**〜である」なら、数える単位を主張の単位(面ごと・ボディごと・色ごと)まで割る。合計・平均・最大は、1つだけ壊れた要素をほぼ確実に隠す。同種: 画素の集計だけを見る色の検査は「描かれていない色」を見逃す(1色ずつ隠して落ちることを確かめる変異検査で塞いだ)。深度検査の見張りを2つある材質の片方でしか読んでいなかったのも同じ形。

## 副産物: 土俵をずらせない構造にする

同じ撮影台で、**カメラ・光源・背景・画角を面ごとに持てないようにする**ために「面ごとにレンダラを作る」のをやめ、**1枚のcanvasに `setScissor` で並べて描く**形にした。比較の土俵がずれた画像は無価値なので、規律で守るのではなく構造として書けなくする。
