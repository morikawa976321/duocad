# Svelte 5: `{#key}` の作り直しは、子の「中断」を親へ伝えない

`{#key mode.kind}` のように、状態が変わったら子コンポーネントを丸ごと作り直す書き方をすると、**子は破棄されるだけで、子が普段「もうやめる」を伝えている経路(`onCancelPreview` のようなコールバックprop)は一度も呼ばれない**。

duocadで実際に起きた形: コマンド層(子)が「確定前の姿」を描かせている最中にモードを切り替えると、子は作り直されるが**描かせた半透明の形はビューポートに残り続ける**。`$effect` の依存が変わったときの再実行と混同しやすいが、**破棄はコールバックを走らせない**。

**対処**: 作り直しの引き金を持っている側(親の `setMode` のような関数)で明示的に消す。**子の `$effect` のクリーンアップに任せない** —— そちらに書いても、消す相手が親の持ち物(ビューポート)なら結局親のAPIを呼ぶことになり、破棄の順序に依存する。

**症状が静かなのが厄介**: 型検査も既存の検査も通り、残った表示物はピックの対象でもないので操作は普通にできる。画面に見覚えのない半透明の形が1つ増えるだけである。
