# 絶対量の体積目標は保持領域を含む「材料の総体積」

2026-09-04に `simp.optimize` へ入れた `material_mm3` の意味を、**保持領域(`solid_mask` で
ρ=1 に固定された要素)を含む材料の総体積**と定義した。したがって達成可能なのは
**`[solid の体積, (solid + 動かせる要素) の体積]`** の閉区間だけで、その外は
`simp.VolumeTargetError`。

- 質量(グラム)は内部表現にしない —— 密度を掛けるのは表示の仕事(本人の決定)。持ち込むと
  「材料をどう定義するか」という別の問題が入る。
- 分率(`volfrac`)の口は残し、**排他**(両方渡すと例外)。
- 要素体積(`mm^3 → 要素数` の換算)は、**格子を知っている層**(`anchor.run_pipeline` /
  `design_space.run_topopt`)が自分で決めて渡す。呼び出し側に換算を書かせると、格子の
  作り方が変わったときに黙ってずれる。

塊を自動導出する経路では分率が使えない理由の実測: 同じ条件を余白比率 0.10 と 0.40 で導出
すると塊が 2,050 → 10,595 要素になり、**分率 0.3 のままだと材料が 4.56倍**(47,914 →
218,309 mm^3)になる。絶対量なら相対 1.1e-10 で一致する(**要素体積が 62.99 → 66.43 mm^3 と
変わっても** —— `derive(spacing=...)` を渡しても格子は箱に合わせて切り直される)。
