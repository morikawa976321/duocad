# 設計空間はユーザー入力にしない・見せもしない

## 入力にしない(2026-08-31)

Fusion 360のGenerative Designは設計空間(材料を置いてよい領域)を明示的に入力させるが、**duocadでは作らない**と本人が決めた。

理由(本人明言): **拘束からも荷重からも離れたところに体積を置く意味がない**ので、設計空間は条件から自動で決まる。計算の入力として必要なだけなら機械的に適当な値を入れればよい。

囲いたい場合(ケースの中に収める等)は**除外ソリッドで表現する**。したがって条件の入力は「保持ソリッド/除外ソリッド/拘束面/荷重面」の4つで足りる。

## 見せもしない(2026-09-03)

本人がさらに一段強くした: **利用者が入れるのは保持ソリッド・除外ソリッド・拘束面・荷重面の4つだけで、あとは最適化ボタンを押すだけ。** 設計空間(削る前の塊)は**見ることも知ることもなく、一切意識しなくてよい**。本人の言葉: 「それでも最適な形状が勝手に出てくるような塊を作るロジックを選ぶ」。

含意(AI側の整理・本人の理由ではない):

- 塊の大きさを決める摘みを利用者に出せない。摘みを隠すということは、外したときに誰も気づけないということ。膨らませ量のような自由パラメータを持つ導出ロジック(外接直方体・凸包・経路カプセル)は、値が小さすぎると**答えの居場所を黙って削る**([[margin-box-design-space-cannot-guarantee-containment]] で実測)。
- 解像度も同じ理由でアプリが決めることになる。要素サイズより小さい面は拘束・荷重に指定できない([[face-to-node-anchoring-loses-faces-smaller-than-the-cell]])ので、「この面は指定できません」と言う責任もアプリ側に来る。
- 塊を安全側(大きめ)に倒せる前提として、体積制約を絶対量へ倒す必要がある → 下記で決着。

「見せない」のは本体のUXであり、開発用の可視化には切り替えで残す。**2026-09-05にその
可視化は probe_topopt から本体へ移った** —— 本体で `?debug=space` を付けたときだけ塊が出る
([[debug-views-belong-where-the-real-part-is]])。既定の画面が塊を見せないことは変わっていない。

## 材料量の指定(2026-09-04決着)

体積の指定を「設計空間に対する分率」でやると、自動導出した領域の大きさが答えを変える(分率30%は領域が倍なら材料も倍になる。[[larger-design-space-gave-worse-compliance]] で実測)ので、**分率は採らない**。**内部表現は絶対量(mm³)、利用者の入力は安全率**の2層にし、安全率は最適化器の外側のループが絶対量へ翻訳する。応力制約の定式化を採らない理由は [[safety-factor-goes-outside-the-optimizer]]。
