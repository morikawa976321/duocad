# UIのrestyleは、決め打ち座標の実ブラウザ検査を黙って壊す

duocadで実測(2026-08-20)。`web/scripts/smoke-features.mjs` と `acceptance.mjs` が
「平面上の点 (u,v) が画面の中に無い」で赤になっていた。`web/src` を巻き戻して二分探索した結果、
**`478b660`「UIをリボン+右サイドバー構成へ restyle」で入った**(その1つ前 `5d9606e` では緑)。

機序: 検査スクリプトはモデル座標 `(u,v)` を毎回その場で画面座標へ射影してクリックする。
射影(`viewport.ts` の `toScreen`)は**ビューポート矩形の外なら `null`** を返す。
サイドバーを足して3Dビューが狭くなると、モデルの端に置いた点(円柱を離して立てる `(80,0)` など)が
画面から外れ、スクリプトはクリックする場所を失う。

**素通りした検査**: `npm run check`(tsc + svelte-check)も pytest も、この壊れ方を一切見ない。
restyle のコミット以降、実ブラウザ検査は一度も回っていなかったと見られる。

教訓: **見た目だけの変更でも、実ブラウザ検査は回す**。とくにレイアウトの面積が変わる変更は、
「決め打ち座標をクリックする」自動検査の前提を静かに壊す。
なお「カメラの余白を広げる(製品側)」か「スクリプトの座標を寄せる(検査側)」かは別問題で、
duocad では本人判断待ちとして README §7 の留保3に置いてある。
