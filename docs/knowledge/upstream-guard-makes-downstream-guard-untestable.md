# 上流の防具があると、下流の防具はテストできない

2026-08-23にduocadで実測。「消えた領域を押し出させない」防具が3枚重なっていた:

1. **コア**が形を変えるverbの後に選択を空にする(`resets_selection`)
2. **UI**が「選んだ領域が今のスケッチに無い」と判定して送らない(`regionsStillExist`)
3. **サーバ**が範囲外の添字を拒む

実際に効いているのは1だけで、**2の枝には到達しない**(1が先に選択を空にするので、
確定の引数がそもそも揃わない)。つまり2は「書いてあるが一度も走らないコード」である。

**変異検査で層を1枚ずつ剥がすと、どれが効いているかが測れる**: 1を外すと2が働き、
1と2を両方外すと3だけが残る。このとき**外から見える結果(文書が変わらない)は3通りとも同じ**で、
変わるのは画面に出る理由だけだった —— 2が守っているのは文書ではなく**理由の見え方**である。

再利用できる作法:

- 「この防具にテストを書け」と言われたら、**まず上流に別の防具が無いかを疑う**。
  上流が先に効くなら、その防具単独に歯を立てる緑のテストは書けない(書けたと思ったら、
  それは別の層を検査している)。
- テストは**外から見える性質**(結果)に対して書き、どの層が効いたかは
  変異検査で測って文書に残す。
- 到達しない防具を消すかどうかは設計判断であり、テストが書けないことは削除の理由にならない
  (上流の契約が変わった瞬間に必要になる)。
