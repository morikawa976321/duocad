有限要素の `K U = F` を CG で解き、`info != 0` なら直接解法へフォールバックする構成
(duocad probe_topopt の `simp.py`)に、**拘束不足の系**(`fixed_dofs=[0]` のように
剛体運動が止まっていない)を渡した実測:

- 「拘束が非空で範囲内」という入口の検査は**通る**。
- CG は収束しない(`info` は打ち切り反復数)。
- フォールバック先の直接解法が **NaN でも例外でもなく、有限の巨大な解**を返す
  (max|u| = 1.2e16〜4.7e16)。
- 最適化はその値を信じて進み、**まったく別の場所**(OC 更新)で `ZeroDivisionError` に
  なって落ちる。原因から遠い場所で落ちるので、追うのに時間がかかる。

**直し方: 解いた後に `||K u - f|| / ||f||` を測り、閾値(1e-6 など)を超えたら
「拘束不足の可能性」を名指しした例外で落とす。** ソルバの成功/失敗フラグは
「収束したか」しか言わず、**フォールバック先が黙って garbage を返す経路を覆えない**。
残差はどの解法を通っても同じ意味で測れるので、フラグより上位の検算になる。
剛体運動の完全な検出(ヌル空間の次元を数える等)は要らない —— 残差で足りる。

コストは1反復あたり疎行列ベクトル積1回で、CG 数百反復に対して無視できる。
