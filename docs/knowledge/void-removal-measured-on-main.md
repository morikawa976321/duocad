[[duocad-void-removal-adopted]] の適用後、`duocad` の `e86f0f8` で測った実測。
題材は `models/hanger_bar_attachment.json`、要素サイズ 5.368mm(箱 113,400 / 塊 34,910)、
40反復、7スレッド。**経路は `design_space.run_topopt` の単発**(材料量を固定して1回)で、
`optimize_run.run`(製品の経路)ではない —— 比較のブランチと同じ測り方に揃えてある。

| | 変更前 | 変更後 | 比 |
|---|---|---|---|
| 全体 | 159.1秒 | **120.8秒** | 75.9% |
| 組立 | 40.49秒 | **12.07秒** | 29.8% |
| ピークRSS | +2,590MB | **+1,287MB** | 49.7% |
| nnz(全体) | 28,144,890 | **8,844,813** | 31.4% |
| `_iK`+`_jK` | 522.5MB | **160.9MB** | 30.8% |
| CG反復(合計) | 1,401 | 1,458 | +4.1% |

- **自由自由度は1つも減らない。** `model.free` の SHA-256 が変更前と一致
  (`3e4a0b2fb445d708`)。
- ρ>=0.5 の一致率 **100.0000%** / 材料量の相対差 **6.9e-12** /
  コンプライアンスの相対差 4.7e-6 / 安全率の相対差 1.6e-6。三角形数は 13,808 で同一。

## 移植が正しいことの一番強い証拠

**main の実装とブランチ `topopt-assembly-comparison` の条件2実装で、ρ 場の SHA-256 が
ビット一致した**(`099fa60aac55ec3c`)。コンプライアンス・安全率・達成体積分率も最後の桁まで
同じ。**「同じ数字が出た」ではなく「同じビットが出た」**なので、移植で条件2以外のものが
混ざっていないことをこれ一本で言える。**大きい実装を別の場所へ写したときは、まず
成果物のダイジェストを突き合わせる**のが安い。
