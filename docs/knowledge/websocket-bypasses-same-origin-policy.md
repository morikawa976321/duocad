# ローカルWebSocketは「127.0.0.1にbind」では守れない

**機序**: WebSocketは**同一オリジンポリシーの対象外**である。普通のHTTPなら悪意あるページが
`127.0.0.1` を叩いても応答を読めないが、WebSocketにはその制限が無く、**任意のWebページが
`ws://127.0.0.1:<port>` へ繋いで読み書きできる**。攻撃側のコードは利用者のブラウザの中で動くので、
ローカルアドレスへのbindは防御にならない。**踏むのに狙い撃ちは要らない** —— ローカルサーバを
立てっぱなしにする運用と、普通のWeb閲覧が重なるだけで成立する。

duocadの実例: 検査が無い間、duocadを立てたまま別のサイトを開いているだけで、そのページが
文書を読み・壊し・`export_step` で任意のパスへ書き・`ai_chat` でAnthropicの課金を消費できた。

**本人の判断(2026-08-20)**: Origin許可リストを入れる。許可はduocad自身が配るページだけ
(静的配信と Vite dev を `127.0.0.1`/`localhost` の両綴りで)。**`Origin` ヘッダ無しは意図的に許可する** ——
ブラウザは必ずOriginを送りJSから偽装できないのでブラウザ経由の攻撃は塞がり、一方で
ヘッダを送らない検査スクリプト(素のWSクライアント)は壊れない。素のWSを立てられる相手は
既にそのPCでコードを実行できており、この防御線の外側にいる。

**実装上の罠**: 「ヘッダ無し(`None`)の許可」と「文字列 `"null"` の許可」を取り違えると、
sandboxed iframe や `file://` のページ(`Origin: null` を名乗る)が通り、**穴が空いたまま緑になる**。
