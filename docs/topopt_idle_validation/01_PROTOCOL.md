## 3. 旧セル幅指定 vs 新mm固定: 比較単位の切り分け

- **旧64条件(`output/smoothing_corpus/`)はセル数指定の比較として凍結する**。`min_width`は`cells`(例: w5=5セル)
  で指定され、実mmは要素サイズが変わるたびに動く(例: w5は1.8mmで9.0mm、2.4mmで12.0mm — `manifest.json`の
  `min_width.guaranteed_mm`を参照)。**このデータへ新しい実験条件を追加しない**(2-1〜2-3節の登録済みデータの
  ままとし、格子×荷重×幅の新規全探索はしない。「小型題材を主にする変更」節の指示どおり)。
- **新規に追加するhanger実験はmm固定**(`optimize_run.OptimizeOptions(min_width_mm=...)`)で指定する。
  `_resolve_min_width(spacing, min_width_mm, max_cells)`が返す`cells`が要素サイズごとに変わりうるので、
  **実現セル数・保証mm(`guaranteed_mm`)を必ず記録**する(task00契約②と同じ理由。`--cells`指定は格子依存の
  「同条件」の崩れを生む)。
- **共通実幅と挟み込み比較の使い分け**: 複数解像度を比較する実験は、まず`min_width_mm`の候補値のうち
  **全解像度で有効な最小値**(`_resolve_min_width`が要求する`max(2×要素サイズ, 1mm)`の下限を、最も粗い解像度が
  決める)を「共通実幅」として使う(task00のpath_smallが6.0mmを選んだのと同じ理由)。共通実幅では格子が細かい
  ほど実際の保証mmが要求値に近づく(丸めが小さくなる)。**格子差と幅差を分離したい実験は、共通実幅1点に加えて
  「要求値を挟み込む2点」(例: 目標9.5mmに対し実現8.9mm相当と10.2mm相当の2条件)を追加し、材料・安全率を線形
  補間して目標mmでの値を推定する**(挟み込み比較)。どちらを使うかは各実験が明記すること(7節の対応表に記載欄を
  持つ)。
- 丸めの記録: `min_width_cells_resolved`・`min_width_guaranteed_mm`・`element_size_resolved_mm`(`_snap_to_grid`後の
  実spacing)を全条件の記録に必須フィールドとする(9節のスキーマ)。

## 5. 合成題材5種の定義

`topopt_checks/_fixtures.py`の`demo_conditions`/`severed_conditions`(build123d + `ds.Conditions`、
`roles=("keep","fixed"/"load")`)と同じ構築規約に従う。**保持部/接続部/一般部の境界は物理座標(mm)で定義し、
評価距離の感度(境界を±1mm動かすと判定が変わるか)を各題材の検証項目に含める。**

| ID | 名前 | 幾何(概要) | 境界条件 | 解析解 | 保持部/接続部/一般部の定義(mm) |
|---|---|---|---|---|---|
| S-T | 引張 | 一様断面の角柱(例: 20×20×200mm) | 一端固定・他端に軸方向の面荷重 | **解析解あり**(σ=F/A、一様応力。有限要素との差は拘束端の局所効果のみ) | 保持部=両端から1要素分(拘束の局所効果域)、一般部=それ以外 |
| S-B | 曲げ | 片持ち梁(例: 10×20×150mm) | 一端固定・自由端上面に集中荷重(下向き) | **解析解あり**(材料力学の片持ち梁公式。σ=My/I、たわみは公式) | 保持部=固定端近傍(応力集中)、一般部=中央、接続部なし(単純形状のため) |
| S-TB | ねじり+曲げ | 円形または角形断面の片持ち軸(例: 直径20×200mm)、自由端に偏心荷重(軸線から10mmオフセット) | 一端固定・自由端にオフセット荷重(曲げ+ねじりの合成) | **部分解析**(円形断面ならτ=Tr/J・σ=My/Iの重ね合わせとvon Misesは解析可能。応力集中源〈フィレット等〉が無ければ全域解析解、フィレットを入れると数値参照のみ) | 保持部=固定端、一般部=軸中央、接続部=断面変化がある版でのみ定義 |
| S-L | L字 | 2つの直方体腕を直角に接続(例: 各腕20×20×100mm、内側フィレット半径5mm) | 一方の腕の端面を固定・他方の腕の端面に荷重 | **数値参照のみ**(コーナー部の応力集中に単純な閉形式が無い。各腕の中央部はBernoulli梁理論で近似解析可能、コーナー近傍は数値専用) | 保持部=固定端、接続部=コーナー(フィレット中心から半径×2の球状領域)、一般部=各腕の中央 |
| S-MS | 複数支持(荷重分担が変わる) | 3点で支持された板または梁(両端固定+中央可変位置の第3支持)、中央付近に荷重 | 2〜3面を固定、1面に荷重。**第3支持の有無/位置を実験変数にする**(支持数が変わると静定/不静定が切り替わり、荷重分担が変わる) | **支持2点(静定)は解析解あり、支持3点(不静定)は数値参照のみ**(不静定梁は数値解法またはたわみ整合法が必要で、本検証では数値参照に留める) | 保持部=各支持面近傍、接続部=支持間の中間(荷重分担の変化が現れる領域)、一般部=支持から離れた両端 |

- **調整用/未使用検証用の区別**: S-T・S-B は探索方式のパラメータ調整(歩幅・評価式の閾値決め)に使ってよい
  「調整用」題材、S-TB・S-L・S-MS は**探索方式が確定するまで一度も使わない「未使用検証用」**題材とする
  (8章「調整と検証を分ける」原則)。task5(合成題材の比較)が両者を混同しないよう、7節の対応表で用途を明記する。
- 各題材の具体的な寸法・荷重は、hangerと同じ許容応力40MPa・目標安全率2.0(探索目標4.8)を使い、全材料での
  安全率が3〜10程度になるよう調整する(task00の300N/3000N選定と同じ考え方 — 全材料で余裕があり、かつ希釈・
  局所解の余地が測れる範囲)。**具体的な数値は幾何を実装するtask(2または5)が実測して決める**(本書は形状と
  境界条件の設計、解析解の有無、ゾーン定義までを確定する)。

### 6-1. 半セル原点移動

`design_space.derive`は原点を明示的に受け取らない(外接箱+余白から内部で計算する)。**原点移動は製品の
第一級パラメータではない** —— 実験するには「凸包の外接箱を計算した直後、格子の原点を±0.5×spacingだけ
指定軸へ平行移動してから`grid_for_bbox`相当のラスタ化を続ける」パッチが要る(`output/idle_study/counterfactual.py`が
`stress.representative_stress`を差し替えるのと同じ、プロセス内一時パッチの手口)。**達成した実シフトが
0.5セルちょうどにならない場合があることを記録すること**(格子は整数セルの外枠を再計算するため)。

台帳: 基準(シフト無し)+ 各軸単独 +0.5セル/−0.5セル(x/y/z × 2 = 6件)+ 全軸同時+0.5セル(1件) = 計8条件。
対象は task00 の小型2題材(`topopt_idle_dilution_small.json`・`topopt_idle_path_small.json`)を主とし
(「小型題材を主にする変更」)、hangerは4節のH1/H2代表条件でのみ確認する。

### 6-2. 初期形状

| 初期形状 | 説明 | 目的 |
|---|---|---|
| 全材料(製品既定) | 設計空間を全て材料で開始 | 基準 |
| 移植トラス | 別解像度/別探索の採用マスクを初期形状として投入 | 2-4節の移植トラスが「初期形状として与えれば探索がそこから改悪せずに留まるか」を確認(2-4節の限界=最小幅未達を補う経路の1つ) |
| 粗い探索から写す形 | 粗い格子(例: 3.0mm)の採用マスクを細かい格子(例: 2.0mm)へ写し、そこから探索を再開 | ウォームスタートが原因2(局所解)を避けられるかを確認。`docs/TOPOPT_STOP_RULE.md`の既存warm-start測定と重複しないよう、対象条件はそちらで未測定のものを選ぶ(task4が確認) |

いずれも「移植先の格子で最小幅・保持・除外を満たすか」を**投入前に**別途検査すること(2-4節で踏んだ罠と同じ)。

### 6-3. フィルタ実幅

`binary_search.ENERGY_FILTER_SIZE = 3`(セル)固定。物理幅は`3 × spacing`で格子ごとに変わる(2.0mm格子で6.0mm、
1.5mm格子で4.5mm等)。**比較条件として明示する**(8章の指示どおり)。台帳: (a) セル数固定(現行、比較すると物理幅が
動く)、(b) 物理mm固定(格子ごとにセル数を丸めて揃える、`uniform_filter`の`size`は整数のみ受け付けるため
最近整数セルに丸める。丸め差を記録)の2条件を、6-1と同じ対象題材で比較する。

### 6-4. 複数荷重

単一の集中荷重だけでなく、以下を台帳に登録する: (a) 同時載荷(2箇所に同時に荷重、力の合成が単純化されない
条件)、(b) 択一載荷(複数の荷重ケースのうち各評価で最も厳しいものを判定に使う、製品が現状サポートしない
場合はどこまでの改修が要るかを記録するだけに留める)。対象は S-MS(複数支持、5節)と、task00の2題材に
追加荷重点を設けた変種(要新規生成、task5が担当)。

## 9. 共通基盤

`topopt_checks/idle_validation/_common.py`(新規)。既存の`topopt_checks/sweep_smoothing_corpus.py`の
git状態取得・アトミック書き込み・ピークメモリ計測・OS排他ロック(`msvcrt.locking`。**プロセスが異常終了しても
OSがロックを放すので死んだ錠の回収ロジックが要らない**)をタスク非依存の形へ切り出した。task2〜10は**この
モジュールをコピーせず直接importする**(コピーすると単一実行制御の穴・記録形式の食い違いが再発する)。

| 関数/クラス | 役割 |
|---|---|
| `git_state(paths=("duocad",))` | HEADコミットと指定パス配下の未コミット差分有無。**`output/idle_study/`のような`.gitignore`対象の使い捨てスクリプトはコミットで版を特定できないため、`sha256_file`をその代わりに使う**(2節で実施済み) |
| `sha256_file(path)` / `sha256_json(obj)` | 入出力ファイル・条件辞書のハッシュ(改ざん・取り違えの検出) |
| `write_atomic(path, data)` | `os.replace`によるアトミック書き込み(実行中断で壊れた途中ファイルを残さない) |
| `peak_memory_mb()` / `available_memory_mb()` | `psutil`によるプロセスピークメモリ・空きメモリ(「計算の継続と資源」節の監視に使う) |
| `ExecutionLock(lock_path, tag)` | OS排他ロック。**同じ`lock_path`をタスク横断で指定すれば「重いFEMは1実行ずつ」をタスクをまたいで強制できる**。タスクごとに別ファイルにすればタスク内だけの多重起動防止になる(粒度は呼び出し側が選ぶ) |
| `condition_id(**fields)` | 条件を人間可読な短いIDへ正規化(台帳の重複排除キー) |
| `load_ledger(path)` / `upsert_case(ledger, case_id, record)` / `is_case_done(ledger, case_id)` | 条件台帳の読み込み・重複排除つき追記・**再開時のスキップ判定**(記録だけ残ってファイルが消えている状態を「済み」と誤認しない — 参照ファイルの実在まで見る) |
| `SingleFemRun()` | 1回のFEM/最適化実行の所要時間・ピークメモリ計測を`with`で1箇所にまとめる |

**検証結果の捏造・基準の事後調整・未実行のpass化の検出**は、各タスクの記録が次を必須フィールドとして持つことで
機械的に照合可能にする(`inventory_stage1_shapes.py`・`reproduce_stage1_transplant.py`が実装済みの形):
`code_version`(製品コードのgit状態 or 使い捨てスクリプトのsha256)、`files`(出力ファイルパス+sha256)、
`doc_cross_check`(既存文書の報告値との突合。`matches`がfalseなら`mismatches`配列に載る)。**未実行の条件は
`status`を`missing`のまま記録し、`ok`や`pass`へ書き換えない**(`_record_for`の`missing`分岐)。
