# probe_topopt — 形状最適化の実験場

**ここは実験場である。壊してよい。** 最適化のコード(`simp` / `voxelize` / `anchor` /
`mesh` / `design_space` / `stress` / `safety_loop` / `bench` / `perf`)と受入検査は
2026-09-05 に **`duocad/topopt/` と `topopt_checks/`(リポジトリ直下)へ移した**。ここに残っているのは
**画面(`server.py` / `web/`)と実機確認(`shot*.mjs` / `screenshots/`)だけ**である。

**依存は probe → 本体の一方向。** ここは `duocad.topopt` を import して動く。
**本体からこのフォルダへの参照は1つも無い**(作った瞬間に、製品が実験場に依存する形へ
逆戻りする)。だから**ここが壊れても本体は無事**で、本体の pytest / smoke を
巻き込まずに画面の実験ができる。

| 探しているもの | どこにあるか |
|---|---|
| **実測の記録**(費用の表・余白比率・案5の比較・応力・面アンカー・変異検査) | [docs/TOPOPT.md](../docs/TOPOPT.md) |
| **契約・不変条件** | `duocad/topopt/*.py` の docstring |
| **受入検査の走らせ方** | `readme.md` §3「形状最適化の受入検査」 |

## 起動(これ1本)

```powershell
& C:\Users\tm976\mf\duocad\.venv\Scripts\python.exe C:\Users\tm976\mf\duocad\probe_topopt\server.py
```

**ブラウザは自動で開く。** 開くと**ボタンを押す前から**4条件(保持・除外・拘束・荷重)が
duocad 本体と同じ色分けで描かれている(下記「起動直後の既定表示」)。左上のボタン
「最適化を実行」を押すと**その4条件を導出した塊(設計空間)で** SIMP が走り、反復ごとに
**ボクセルの立方体**が更新される。終わるとボタンが完了表示になり、
**同時にボクセルが滑らかな三角形メッシュへ差し替わる**(marching cubes + Taubin平滑化。
下記「メッシュ化」)。止めるのはターミナルで Ctrl-C。

- ブラウザが開かなければ手で <http://127.0.0.1:8775/> を開く。
- **ポートは 8775 / 8776**。duocad 本体(8765 = WS / 8766 = 静的配信)と**ぶつからないように
  ずらしてある**ので、本体を動かしたままこのプローブを立ててよい。
- ポートを変えるときは `PROBE_HTTP_PORT` / `PROBE_WS_PORT`。
  **WSポートを変えたら URL に `?ws=<番号>` を付ける**(画面側の既定は8776)。
- **`?voxel=1` を付けると、完了時も平滑化した面へ差し替わらず、従来のボクセル表示のまま
  終わる**(デバッグ用。marching cubes導入前の見え方を確認したいときに使う)。
- **`?debug=space` を付けると、塊(設計空間)のボクセルを既定表示に薄く重ねる**
  (本体は塊を利用者に見せない設計 —— engine `topopt-design-space-never-shown-to-the-user` —
  なのでこれは開発用の切り替え。答えがおかしいときに「塊が悪いのか最適化が悪いのか」を
  切り分ける手段として残してある)。
- **`?debug=anchors` を付けると最適化を回さず、合成ブラケットの面アンカーを描く**
  (`design_space.demo_conditions()` とは別の、面アンカーそのものの検証用デモ形状)——
  設計空間のボクセルの上に、**固定に割り当てた節点(緑シアン)と荷重に割り当てた節点(橙赤)**
  を別々の色の球で出す。ボタンは「面アンカーを表示」になり、押すと数秒で出る。
  節点は深度テストを切って最前面に描くので、形状の裏側にある節点も見える。**面アンカーが
  効いていることの唯一の目視確認**なので、既定表示を4条件に切り替えたあとも消していない。
- マウスドラッグで回転、ホイールでズーム(OrbitControls)。

## 起動直後の既定表示: 4条件を duocad 本体と同じ色分けで描く(2026-09-04)

**フラグ不要 —— ページを開いた時点で、ボタンを押す前から**4条件(保持ソリッド・除外ソリッド・
拘束面・荷重面)を duocad 本体の形状最適化モード(`web/src/viewport.ts`)と同じ色で描く。
本体側の色分けの見た目をここで先に詰められるようにするのが狙い(2026-08-31の引継ぎ)。

| 役割 | 色 | 描き方 |
|---|---|---|
| 保持 | `#3f9b58` | `conditions.keep` の三角形を塗る(拘束面ぶんは除く) |
| 除外 | `#c75448` | `conditions.obstacle` の三角形を塗る |
| 拘束 | `#3f7fc2` | `soup.triangles_of_face(fixed_face)` の三角形を塗る + 固定記号(四角錐 `#1c3550`) |
| 荷重 | `#ffc857` | `ArrowHelper` + 大きさのラベル(canvasテクスチャのSprite)。**面の色は変えない**(duocadと同じく、荷重面は保持の色のまま矢印だけを重ねる) |

**入口**(表示と計算が同じ `DesignSpace` オブジェクトを使う。完了条件3):

```
conditions = design_space.demo_conditions()
# **導出は名指ししない**(既定の入口。2026-09-04〜は案5が返る)
space      = design_space.derive_default(conditions, elements_long_axis=22, coarse_volfrac=0.3)
# 既定表示はこの space から材料(三角形・重心・法線)を作って送るだけ(最適化は回さない)
# ボタンを押すと同じ space を design_space.run_topopt() に渡す
```

- **`server.py` の `_get_demo_space()`** がこのキャッシュ。起動後最初のリクエストで1回
  導出し、以後はプロセスが生きている間使い回す。**表示用と計算用で2回導出しない** ——
  呼ぶと余白や格子が独立に決まり、見せている問題と解いている問題が別物になりうる。
- **粗い段には本番と同じ体積目標(`DEMO_VOLFRAC`)を渡す。** 別の量で解くと「別の形の周り」を
  膨らませた塊になる(`derive_from_coarse_run` の docstring)。
- 除外ソリッドは面アンカーの対象(`space.soup`)に含まれないので、`server.py` 側で
  別途三角形分割する。**`space.model.obstacle`(ボクセルのマスク)は使わない** ——
  どちらの導出も除外を塊から引き切っているので常に全 False(`design_space.py` の設計判断)。
- 荷重の矢印は**面法線ではなく、実際に最適化へ渡す力の向き**(`server.py` の `DEMO_FORCE
  = (0, 0, -1)`)を描く。見た目と計算の入力がずれると、画面が正しく見えるのに別の問題を
  解いている、という事故になる。

### カメラの向き(踏み抜いた罠)

**`demo_conditions()` の拘束面(固定側パッドの x 最小面、法線 `(-1,0,0)`)は軸整列の平面**
なので、カメラの向きが十分 `-x` を向いていないと、隣接する面(同じパッドの側面)の陰に
隠れてほぼ画面に出ない。**旧来の視点(`(0.72, 0.45, 0.86)`)では拘束面の画素がほぼ0だった**
(実測: どの `?debug=anchors` 用の視点でも拘束面ぶんの画素が変化しなかった)。
`web/index.html` の `fitCamera()` の向きを `(-0.75, 0.5, 0.6)` へ変えて解決した。
**`MeshLambertMaterial` を両面描画(`side: THREE.DoubleSide`)にしただけでは直らない** ——
これはバックフェースカリングの問題ではなく、**同じ塊(パッド)の他の面に幾何学的に
遮られている**ことが原因(オブジェクトの奥にある面は、カリング設定に関係なくそもそも
視線が届かない)。塊を利用者に回転させて見る前提の以上、少なくとも既定視点では
4色とも一定の画素数が出る向きを選ぶ必要がある。

### 画素判定の閾値(実測。`web/index.html` の `pixelCensus`)

`MeshLambertMaterial` は陰影で暗くなるので、**元の16進色そのものでは画素にほぼ出ない**。
拘束面 `#3f7fc2` は環境光だけになる向きのため実測で `(16,40,72)` 前後まで暗くなる。
そのため判定は絶対値ではなく**チャンネル比**で作った:

| 役割 | 判定式 | 既定視点での画素数(表示時→非表示時) |
|---|---|---|
| 保持 | `g>40 && g>1.6r && g>1.3b` | 7135 → 0 |
| 除外 | `r>40 && r>1.8g && r>1.8b` | 7518 → 0 |
| 拘束 | `b>45 && b>1.8r && b>1.6g` | 10020 → 0 |
| 荷重(矢印/ラベル) | `r>140 && g>100 && r>1.9b && r<1.6g` | 252 → 0 |

**`boundsHelper`(半透明の境界線、`#5577aa` が背景と混ざった `(48,56,88)` 前後)が
拘束の閾値に紛れ込みやすい** —— `b>1.6g` を要求して弾く(境界線ブレンドは `b/g≈1.2` 止まり、
実際の拘束面は `b/g≈1.8` 前後)。**検出力は`probe.setVisible(role, false)` で1色ずつ実際に
隠して確認した**(`shot_anchors.mjs` が毎回この変異検査を回す。集計だけの検査は
「描かれていない色を見逃す」ことがある。2026-09-02の実例)。

### 制約(2026-09-04本人指示)

**画面は、その時点で最新の最適化経路を可視化する。** 計算側の入口が変わったら画面もそこへ
追随させる —— 古い入口(片持ち梁プリセット)を回したまま新しい条件を描く状態を残さない。
見た目が正しいのに解いている問題が別、という食い違いは画面からは観測できないため。

## 実機確認(`shot*.mjs`)

`server.py` を子プロセスで起動して撮り、終わったら落とす(**先に自分で起動しておく必要は
ない**)。

```powershell
Set-Location C:\Users\tm976\mf\duocad\probe_topopt

# ボタンを押して平滑化された面を screenshots/result_smooth.png に撮る
node shot.mjs

# 既定表示(4条件)が起動直後に出ることを screenshots/result_anchors.png に撮る
node shot_anchors.mjs
```

**ポートが空いていることを確かめてから回すこと。** 別のサーバが 8775/8776 を掴んでいると、
**headless Chrome は古いサーバを撮って「合格」と出す**
(engine `headless-shot-photographs-a-stale-server-when-the-port-is-taken`)。
空きを渡すときは `PROBE_HTTP_PORT` / `PROBE_WS_PORT` を環境変数で与える(例: 8875/8876)。
